# プロファイル

基準・要領・社内標準を、コードとは別の、版のあるデータとして持ちます。照合は、API の `check` の op に `profile.json` を `zm_push` で渡して行います。

| id | 版 | 対象 |
| --- | --- | --- |
| `mlit-cad` | [2025-12](mlit-cad/2025-12/profile.toml) | CAD製図基準（土木、令和 7 年 12 月） |
| `mlit-earthwork` | [2026-03](mlit-earthwork/2026-03/profile.toml) | 土木工事施工管理基準及び規格値（案）の土工の面管理（令和 8 年 3 月） |
| `mlit-delivery-const` | [2026-02](mlit-delivery-const/2026-02/profile.toml) | 工事完成図書の電子納品等要領（令和 8 年 2 月、`delivery_check` の op） |
| `mlit-delivery-design` | [2026-02](mlit-delivery-design/2026-02/profile.toml) | 土木設計業務等の電子納品要領（令和 8 年 2 月、`delivery_check` の op） |
| `mlit-bim-drawing` | [2026-03](mlit-bim-drawing/2026-03/profile.toml) | BIM 図面審査の申請前のチェックと面積の測り方（Rust の `zumen_profile::building`） |
| `mlit-cad-building-drawing` | [2025-12](mlit-cad-building-drawing/2025-12/README.md) | CAD製図基準（2025-12）に合わせる建物の切り出しと図面チェック（`mlit-cad` を継承） |
| `zumen-building-drawing` | [2026-11](zumen-building-drawing/2026-11/README.md) | 建物の線・模様・建具と通り芯の記号・階名・切断高さ（Rust の `zumen_profile::building_drawing`） |

電子納品の工事・業務の `link` 規則は、要領の管理項目と DTD にある実ファイル名を使います。説明用の日本語名に拡張子があっても、別のファイルを要求しません。[公式作成例を使った正しい組・欠落の照合](../xtask/verify/dtd/README.md#公開-api-で要領の規則と参照先を照らす)

## 直し方

- 元は `<id>/<edition>/profile.toml` です。直したら `cargo xtask codegen` で `profile.json` を作り直し、両方をコミットします。
- 値には出典の文書・節・項を書きます。出典が列挙しない値は `basis = "chosen"` にします。
- 基準の新しい版は、新しいフォルダーにします。同じ版のデータを直したら `revision` を上げます。
- 値には、出典の文書・節・表の番号を書きます。

## 建物の作図プロファイル

`zumen-profile` の `building-drawing` feature で `DrawingProfile::load` を使います。`cut` は切る面・許容差・弦の誤差と任意の用紙を受け取り、建具の記号を選んで切り出し、線の見た目と模様・通り芯の記号を足します。すでに切り出した未編集の結果には `apply` で見た目を当てられます。階の基点から既定の高さで切る面は `default_plan`、2 点と見る側から既定の深さで切る断面は `default_section`、元の階名から種類への対応は `level_kind` で得ます。

`Drawing` は元の線の対応を `output.lines` に保ち、追加した図形の対応を `decorations` に持ちます。図面にはプロファイルの ID・版・revision の鎖とハッシュ、追加した図形の元要素を拡張として残します。値と制限、出典の条件は[初版の記録](zumen-building-drawing/2026-11/README.md)と[CAD製図基準向けの記録](mlit-cad-building-drawing/2025-12/README.md)を参照してください。

## 確認申請のプロファイル

`mlit-bim-drawing` の初版は `edition = "2026-03"` です。BIM 図面審査のガイドライン・入出力基準・表現標準の項とページ、施行令を出典とします。規則に文や表を転載せず、表現標準が第三者から引用した部分は出典にしません。申請前に IFC のデータで確認できる項目だけを扱います。

| 規則 | 種類 | 出典 | 確かめること |
| --- | --- | --- | --- |
| `ifc-schema` | IFC のバージョン | 入出力基準 2-2-2 | ファイルの `FILE_SCHEMA` が `IFC2X3` であること。違えば warning |
| `models-aligned` | ファイルの重なり | 入出力基準 2-2-2、ガイドライン 6-3 | 複数の IFC の長さの単位と、建物の配置の原点と軸がそろうこと |
| `representation-present` | 形の有無 | ガイドライン 6-3 | 形を持つはずの要素（壁・柱・梁・床・屋根・扉・窓・空間）が、形状表現を持つこと |
| `room-use` | 属性の有無 | 入出力基準 意-012① | 空間の要素に、用途の属性があること |
| `area-region-code` | 属性の有無 | 入出力基準 意-013①の 2、意-014①の 2 | 面積の領域の要素に、符号の属性があること |
| `floor-area-ratio` | 属性の有無 | 入出力基準 意-014② | 床面積の領域の要素に、容積率の対象内外の別の属性があること |
| `fire-compartment` | 属性の有無 | 入出力基準 意-015① | 壁・柱・床・扉・窓の要素に、防火区画等の種別の属性があること |

型への対応は下位の型を含め、プロファイルの語彙に `basis = "chosen"` で記録します。属性の名前と面積領域の型は基準が定めていないので、初版で空にし、利用者が `extends` で指定します。空なら規則ごとに確認できなかったことを返します。PDF の図書との一致や設計者の判断を要する法令適合は判定しません。

面積は領域の形のまま m² で求め、丸める前の値も返します。階別は区分の合計後、用途別は用途ごとの合計後に、10 進で小数点以下 2 桁に切り捨てます。丸めは表現標準の記載例に基づく選択です。建築面積の地階や軒の除外を検証していないことも結果に残します。BIM データ審査の基準が公表されたときは別の ID で扱います。

`zumen-profile` の `building` feature を有効にして `BuildingProfile::load` で JSON の継承を解き、`check` に建物モデルの列を渡します。`Report` は図面の照合と同じ規則の集計と指摘を持ちます。指摘の `model` は入力の 1 始まりの番号で、0 は規則の設定を指します。要素の指摘には元の ID とレコードの場所も付きます。共通 API の図面向けの `check` では建物を照合しません。

配置の照合は、各モデルで建物が 1 つであることと、その配置、長さの単位、所有する形の 3D 文脈から工学座標の原点と軸を求めます。複数の文脈が異なる場合、配置を解けない場合、地図への対応が異なる場合は確認できないと返します。原点の許容差は m、軸の成分の許容差は無次元で、プロファイルの選んだ値です。1 モデルだけならモデル間の比較はありません。形の有無は形状表現の項目で調べ、メッシュが評価できることまでは判定しません。

属性は要素の値、次に型の値を調べます。要素に明示された欠値を型の値で補いません。同じ名前の値が複数ある場合や、不明な論理値・非有限数・不正な参照は確認できないと返します。0 と false は値があると扱います。`extends` では同じ ID の規則全体を置き換えるため、利用者は `check`・`level`・`classes`・`property-set`・`property` をまとめて指定します。`classes` は語彙の名前の列です。

`areas` には同じ高さで測る領域の列を、`AreaGroup` の階別・用途別・建築面積の区分と、文書単位の切断原点で渡します。各区分の水平断面を元の形のまま測り、別の階や用途の結果は足しません。区分への割り当てと切断高さは利用側が決め、属性から推測しません。同じ種類の区分どうしで要素が重なれば要求を拒みます。各結果は選んだ ID・版と、継承後の規則・語彙・識別の BLAKE3 を保ちます。面積の算定対象を選んだ設計者の判断や法令への適合は判定しません。

# SAF 付き P2Z・SFZ の実機確認（#494）

このキットの入力は `fixtures.py` で自作しました。Autodesk などの製品に付属する資源は含みません。`manifest.json` に生成器・照合器のハッシュと検査の結果があります。

## 比べる値

SFZ（SFC）と P2Z（P21）、SAF の名前の 2 通り、ZIP の無圧縮と deflate を組み合わせた 8 組です。各フォルダーの `input` と `edited` の図面を開き、次の値を比べます。

| 項目 | 入力 | 編集後 |
| --- | --- | --- |
| 線分 | 始点 (0, 0)、終点 (100, 0)、画層 L | 同じ |
| 円 | 中心 (50, 25)、半径 10、画層 L | 中心 (55, 22)、半径 10、画層 L |
| 属性の対象 | 図形識別番号 10、名前「検証線分」の線分 | 同じ |
| 属性セット | 検証セット、版 1.0、作成者 zumen | 同じ |
| 属性グループ | 測点 | 同じ |
| 測点名 | 型 STR、値 No.1 | 同じ |
| 現地盤高 | 型 LEN、単位 m、値 102.0400 | 同じ |

電子納品の照合では、図面と同じ幹名の `DRAWING.SAF` を使います。図面の拡張子を残す `DRAWING.SFC.SAF` と `DRAWING.P21.SAF` は、zumen の互換読み込みを確かめる組です。[農林水産省「測量成果電子納品要領（案）」付属資料 4](https://www.maff.go.jp/j/nousin/seko/nouhin_youryou/pdf/survey_youryob_h2603.pdf)。属性 XML・非対象の線分と表・`control.txt` は変更しません。

## 利用者が行う実機の操作

許可した SXF ブラウザで、各フォルダーの `input.sfz`/`input.p2z` と `edited.sfz`/`edited.p2z` を開きます。属性を開けるソフトの名前と版を `report-template.json` に記録し、形、画層、属性の値と結び先を上の表と照らします。アーカイブを直接開けない場合は、同じフォルダーに展開済みの `input/` と `edited/` を使い、その制約を結果に記録します。

開けた項目だけを確認済みにします。見られない属性や未実行の組は `not_run` として残します。製品のメッセージ全文、画面、利用者名を含むパス、非公開図面は報告に入れません。保存し直す場合は Git の外に置きます。

自作の SFC と同名幹の SAF を Jw_cad 10.3.6.0 で開き、P21 に保存すると、線分・円・画層 L は残りました。図形識別番号 10 と SAF への参照は出力から失われ、SAF も生成されませんでした。P2Z の編集前後を実機で比べるには、表の属性を付けたまま保存できるソフトで自作した原本を使います。DynaCAD ビューアー 9.00.00 で確認した国総研の配布原本と、キットの SFZ の結果は[形式文書](https://github.com/zumen-jp/zumen/blob/main/docs/formats/sxf.md)にあります。

### P21 の用紙に属性付きの線分を置く照合

2026-11-21 に DynaCAD ビューアー 9.00.00 のファイル形式で P21/P2Z を選びました。用紙と部分図を修正したキットの `p2z-stem-0/input.p2z`（SHA-256 の先頭 `aa36f655bfda5789`）は、編集前に読み込みのエラーになりました。

同じ線分と円を Jw_cad が保存した P21 に、キットの同名幹の SAF を置いて比較しました。

| P21 の変更 | ビューアーで開けたか |
| --- | --- |
| 保存時のまま。SAF は置かない | 開けた |
| 同じ P21 に SAF を添える | 開けた |
| 線分を持つ作図グループの定義名だけに図形識別番号 10 を付ける | 開けた |
| グループの配置と専用画層を追加し、用紙の要素一覧には配置を含めない | 開けた |
| 直前の P21 の用紙（`DRAWING_SHEET_REVISION`）の要素一覧に、その配置への参照を 1 個加える | 読み込みのエラー |

最後の 2 件は同じ SAF を使い、P21 の違いは用紙からの参照 1 個です。配置を外した図面は線分と属性の実機照合用の原本には使えません。次は、属性を持つ線分を用紙に配置した状態で開ける自作原本を用意し、P2Z の編集前後を期待値表と照らします。[属性の配置を追う issue](https://github.com/zumen-jp/zumen/issues/902)

この実測後に、P21 の作図グループの定義原点と配置の軸を分けました。定義原点を (0, 0) とし、参照方向を省きます。配置は (0, 0)、回転 0 度、等倍です。配置と線分の画層を、同じキットの SFC が指定する L にそろえました。編集前後とも、用紙から配置、グループ定義、線分までの参照と図形識別番号 10 を ezsxf で照合します。[国土交通省 SXF Ver.3.1 第 2 版、STEP AP202 サブセット編 2-1-20・2-1-21・2-2-31](https://www.cals-ed.go.jp/sxf_ver3-1_specification_draft/)

### 修正版を DynaCAD で開いた結果

2026-11-21 に DynaCAD ビューアー 9.00.00 のファイル形式で P21/P2Z を選び、[作図グループの定義原点と画層を修正したキット](https://github.com/zumen-jp/zumen/commit/805aa195)の編集前後を開きました。

| 開いたファイル | 内訳 | 読み込み結果 |
| --- | --- | --- |
| 修正版の P2Z | SAF 名 2 通り × 圧縮方式 2 通り × 編集前後の 8 件 | 全件でエラー |
| 修正版から展開した P21 と SAF | SAF 名 2 通り × 編集前後の 4 件。圧縮方式だけが違う組は、P21 と SAF がバイト単位で一致 | 全件でエラー |
| SAF 名を省いた対照 | 同名幹・無圧縮の組を基にした P2Z と、そこから展開した P21 の編集前後の 4 件 | 全件でエラー |

対照では、作図グループの定義名と配置名の両方から末尾の `$$DRAWING.SAF` を取り除き、図形識別番号 10 と、同梱した `DRAWING.SAF` を保ちました。
同名幹・無圧縮の修正版 P2Z の SHA-256 の先頭は、編集前が `7368c7e2c335968a`、編集後が `69c38d13bd1eb191` です。省略形では順に `9ae38fcfc90f2631`、`fd309bff766af74c` です。

16 件とも図形を表示する前に止まり、線分・円・画層 L と、線分に付く測点名・現地盤高は実機で確認できませんでした。次は、属性付きの線分を用紙に配置したままビューアーで開ける P21 と SAF を用意し、作図グループの定義・配置から用紙までの参照を比較します。

## 自動で確かめた範囲

Python の ZIP 実装でメンバー・CRC・非対象のバイト列、ElementTree で XML の構造・属性値、ezsxf 0.3.7 で図形・画層と変更の期待値を照合しました。コアの `lift` の結果から取り出した属性を XML と照らし、同じ線分への結び付けと属性の有効性を確かめました。同じ入力と変更を 2 回実行し、出力のバイト列の一致も確認しました。

キットの生成にはネイティブ CLI を使います。生成後に `xtask/verify/saf/compare_wasm.mjs` を実行すると、8 組の応答・図面モデル・編集出力を wasm と比較できます。`application` は `not_run` から始め、実機で確かめた項目ごとに記録します。キットの生成時は DTD を読み込みません。

# ジオイドの格子の補間を国土地理院の計算と照らす

`zumen-crs` のジオイドの格子の読み取り（`Grid::read`）と双一次の補間（`Grid::interpolate`）を、国土地理院の[ジオイド高計算サービス](https://vldb.gsi.go.jp/sokuchi/surveycalc/geoid/calcgh/calcframe.html)か、モデルと一緒に配られる内挿計算プログラム（geoidcalc）の結果と照らす検証キットです（#438）。国土地理院のモデル（ISG 形式のファイル）は、利用者が入手し、リポジトリの外に置きます。モデルとその値、サービスとプログラムが返した値は、Git・パッケージ・テストに入れません（[決定 0019](../../../docs/decisions/0019-coordinate-systems-and-gsi-data.md)）。

| ファイル・コマンド | 中身 |
| --- | --- |
| `points.txt` | 照らす点の一覧（23 点）。格子点の上・東西と南北の格子の線の上・格子の中・範囲の縁と外の点と、基準面補正量のある離島の点 |
| `cargo xtask geoid points` | 点の一覧に、渡した格子の無効の領域の際の点を足し、サービスと内挿計算プログラムの入力をフォルダーに書く（`xtask/src/geoid.rs`） |
| `cargo xtask geoid compare` | サービスか内挿計算プログラムの結果を、zumen の補間の値と比べ、点の数と差の最大を示す |

サービスへの入力と内挿計算プログラムの実行は、利用者が行います。エージェントが行うのは、そのセッションで利用者がブラウザーかアプリの利用を許したときだけです（#438 の 2026-11-09 の判断、`docs/work.md`）。

## 国土地理院の側（2026-11-09 に確かめた）

### モデル

- 「ジオイド2024日本とその周辺」と「基準面補正パラメータ」の[説明書](https://www.gsi.go.jp/common/000277542.pdf)（2026 年 4 月）の 2 章によれば、ISG 形式の zip（`JPGEO2024_isg`）に、次のファイルが入っている。
  - `JPGEO2024.isg`（ジオイド高）・`Hrefconv2024.isg`（基準面補正量）・`JPGEO2024+Hrefconv2024.isg`（同じ地点の 2 つを足した値。説明書は「統合したファイル」と呼ぶ）
  - 内挿計算プログラムの `geoidcalc_win64.exe`（Windows）・`geoidcalc_linux_x86_64.tar.gz`（Linux）と、その入力の例 `input.txt`
- 格子は北緯 15〜50 度・東経 120〜160 度で、間隔は緯度 1 分・経度 1.5 分（2101 行 × 1601 列）。`JPGEO2024.isg` は範囲の全域に値を持つ。`Hrefconv2024.isg` は、日本水準原点の範囲で 0、ほかの原点の範囲（吐噶喇列島以南・八丈島以南の離島）で基準面補正量、標高の原点の定まっていない範囲で無効（`-9999.0000`）を持つ。統合したファイルも、同じ所が無効になっている。
- 国土地理院の[ジオイド・モデルの頁](https://www.gsi.go.jp/buturisokuchi/grageo_reference.html)は、「ジオイド2024日本とその周辺」を 2025-04-01 から使うモデルとして挙げ、版の番号を書いていない。説明書の改訂は、2025-04-01 の初版と、2026-04-01 の商標の追記だけである。
- 入手は、基盤地図情報のサイトから。測量に使わない研究・調査なら、出典を示せば申請は要らない（[利用手続](https://www.gsi.go.jp/buturisokuchi/grageo_geoidprocedure.html)）。

### ジオイド高計算サービス

- 測量計算サイトの[トップ](https://vldb.gsi.go.jp/sokuchi/surveycalc/main.html)は、「ジオイド高計算（ジオイド2024日本とその周辺）」が、ジオイド高にこのモデルを使い、参考として基準面補正量も示すと書く。海域と一部の離島には、基準面補正量のない無効の領域がある。モデルの版の番号は書いていない。
- 1 点ずつの計算（緯度・経度を度分秒か十進の度で入れる）と、ファイルの一括計算がある。
  - 一括計算の入力は、拡張子が `.in` のテキストで、名前は英数字・`_`・`.` だけにする。1 行に緯度と経度を半角の空白で区切り、度分秒を区切らずに書く（`dddmmss.ssss`）。`#` で始まる行はヘッダーで、文字コードは Shift_JIS か、BOM のない UTF-8 にする。
  - ジオイド高計算の一括計算は、100 点まで（トップの注意事項）。
  - 一括計算の結果は、拡張子が `.out` のテキストで、`#` で始まる注記の後に、1 行に緯度・経度・ジオイド高を書く（「入力値を出力する」を選んだとき）。範囲の外は `-9999.` になる。
- 表示する値の小数の桁は、公式の頁（トップ・[API の使用方法](https://vldb.gsi.go.jp/sokuchi/surveycalc/api_help.html)・入出力ファイル形式・入出力機能説明）に書かれていない。入出力ファイル形式の頁の結果の例は、メートルの小数 3 桁だが、頁は「数字は実際の計算結果とは異なります」とし、注記も古いモデルのファイル（`gsigeo2011_ver1.asc`）の名前のままである。そこで `compare` は、結果の値の小数の桁を数え、4 桁（0.1 mm）より少なければ、0.1 mm の照合にしない。
- 同じ IP アドレスからの計算は、10 秒に 3 回まで（トップの注意事項）。

### 内挿計算プログラム

- 説明書の 3 章。ISG format 2.0 のファイルを読み、求める点を囲む四隅の格子点で双一次に補間する。四隅のどれかが無効なら `NaN` を書く。格子点の上と格子の線の上では、その格子点か、線の両端の格子点だけを見る（注 6）。範囲の外も `NaN` を書く。
- 入力は、1 行目に `Unit:DMS` と書き、続けて 1 行に緯度と経度を半角の空白で区切り、度分秒を区切らずに書く（秒の小数は 4 桁まで）。`-g` で格子のファイル、`-i` で入力、`-o` で出力を選ぶ。
- 出力は、`#` で始まる注記（格子のファイルとプログラムの版）の後に、1 行に緯度・経度・値（メートル）を書く。説明書の例の値は、小数 4 桁である。
- 説明書は、ジオイド高と基準面補正量を別々に求めて足した値と、統合したファイルから求めた値は、0.1 mm ほど違うことがあると書く。キットは、ファイルごとに、同じファイルを使った結果と比べる。

## 点

`points.txt` の点は、説明書の格子の形から選んだ（23 点）。どの点がどこにあるかは、`cargo test -p xtask geoid` が、説明書の格子の形（値は持たない）で確かめる。

| 場所 | 点 |
| --- | --- |
| 格子点の上 | P01〜P05（P03 は那覇付近、P04・P05 は範囲の隅） |
| 東西の格子の線の上 | P06・P08（P08 は範囲の北の縁） |
| 南北の格子の線の上 | P07・P09（P09 は範囲の東の縁） |
| 格子の中 | P10〜P19（P14〜P17 は基準面補正量のある離島、P18 は海域、P19 は日本の外の陸） |
| 範囲の外 | P20〜P23（範囲から 0.0001 秒外） |

`JPGEO2024.isg` は無効の格子点を持たないので、無効の領域の際の点は、`cargo xtask geoid points` が、渡した `Hrefconv2024.isg` と統合したファイルから選んで足す（E01 から）。際の位置はモデルから決まるので、キットの `points.txt` には書かず、利用者のフォルダーにだけ書く。形は次の 6 つで、形ごとに、北の行から探し、使う有効の格子点の値がどれも 0 でない際（離島の際）を先に選ぶ。

| 形 | zumen の値 |
| --- | --- |
| 東・南・南東の隣に無効の格子点がある格子点 | あり |
| 両端が有効で、南の隣に無効の格子点がある、東西の線の上 | あり（重みが 0 の格子点は見ない。説明書の注 6） |
| 両端が有効で、東の隣に無効の格子点がある、南北の線の上 | あり（同じ） |
| 片方の端が無効の、東西の線の上 | なし |
| 片方の端が無効の、南北の線の上 | なし |
| 隅に無効の格子点を持つ格子の中 | なし |

`Grid::interpolate` は、格子点と格子の線の上で、南と東の隣の格子点を重み 0 で持つので、その側に無効の格子点がある際を選ぶ。線の上の点は、西か北の格子点から間隔の 3 分の 1 の所に置く（片方の端が無効の線では、有効の端から 3 分の 1）。格子の中の点は、北西の格子点から南と東へ 3 分の 1 ずつの所に置く。`points` は、それぞれの点で、zumen の値のあるなしが表のとおりかも確かめる。

## 手順

1. 基盤地図情報のサイトから、ISG 形式の「ジオイド2024日本とその周辺」（`JPGEO2024_isg` の zip）を入手し、リポジトリの外のフォルダー（下の例では `../geoid`）に展開する。
2. 点と入力を作る。書く先のフォルダー（下の例では `../geoid-check`）も、リポジトリの外にする。

   ```bash
   cargo xtask geoid points ../geoid-check ../geoid/JPGEO2024.isg ../geoid/Hrefconv2024.isg "../geoid/JPGEO2024+Hrefconv2024.isg"
   ```

   どれかのファイルを `Grid::read` で読めなければ、診断の code と一緒に止まる（#438 の完了の条件の 1 つめ）。読めれば、フォルダーに `points.txt`（点の一覧）・`geoid.in`（サービスの一括計算の入力）・`input.txt`（内挿計算プログラムの入力）を書き、点ごとに、ファイルごとの場所と zumen の値のあるなしを表示する。値は表示しない。

3. 結果を作る。次のどちらか、または両方を使う。
   - 内挿計算プログラム: zip を展開したフォルダーで、3 つのファイルそれぞれについて実行する。Linux では `geoidcalc_linux_x86_64` を使う。

     ```bash
     geoidcalc_win64.exe -g JPGEO2024.isg -i ../geoid-check/input.txt -o ../geoid-check/JPGEO2024.out
     ```

     ```bash
     geoidcalc_win64.exe -g Hrefconv2024.isg -i ../geoid-check/input.txt -o ../geoid-check/Hrefconv2024.out
     ```

     ```bash
     geoidcalc_win64.exe -g JPGEO2024+Hrefconv2024.isg -i ../geoid-check/input.txt -o ../geoid-check/combined.out
     ```

   - ジオイド高計算サービス: サービスの頁で「一括計算」を選び、`geoid.in` を選んで、「入力値を出力する」を選んだまま計算し、結果を `../geoid-check/service.out` に保存する。サービスの値は、ジオイド高（`JPGEO2024.isg`）と比べる。1 点ずつ入れたときは、`geoid.in` の各行の後ろに、表示された値を空白で区切って足し（値がなければ `NaN`）、同じ形のファイルにする。

4. 結果のファイルごとに、使った格子のファイルを渡して比べる。

   ```bash
   cargo xtask geoid compare ../geoid-check ../geoid/JPGEO2024.isg ../geoid-check/JPGEO2024.out
   ```

   `compare` は、数字で始まる行を値の行とし、ほかの行（`#` で始まる注記や見出し）は注記として表示する。値の行を `points.txt` の順に結び、行の数と、緯度・経度が点と同じかを確かめてから、値を比べる。値の後ろの列（コメント）は読まない。サービスの結果が、ジオイド高の後ろの列に基準面補正量も書くなら、`--column 4` を足して `Hrefconv2024.isg` と比べる。

## 期待する結果

- `points`: 3 つのファイルを読める。`JPGEO2024.isg` は無効の格子点がないと表示し、`Hrefconv2024.isg` と統合したファイルからは、無効の領域の際の点を 6 つずつ選ぶ（同じ点は 1 つにする）。
- `compare`: どの結果でも「合った」で終わる。値のある点は差が 0.1 mm 以内で、zumen が値を返さない点では、結果も値なし（`NaN`・`-9999.`）。
  - `JPGEO2024.isg`: 範囲の外の P20〜P23 だけが値なし。
  - `Hrefconv2024.isg`・統合したファイル: 加えて、無効の領域の中の点と、際の点のうち上の表で「なし」の形の点が値なし。
- 結果の値の小数が 4 桁より少なければ、`compare` は「0.1 mm の照合になりません」で終わる。表示の丸めの中で合ったことは示すが、#438 の照合には数えない。
- 合わなければ、`compare` は、点の ID・場所・差（値は書かない）を示して止まる。仕様と結果を比べて、違いを調べる。

## 記録

- `docs/formats/crs.md` の検証の記録と #438 には、照らしたファイル・照らした相手・点の数・差の最大だけを書く。モデルの値、サービスとプログラムが返した値、無効の領域の際の点の位置は書かない（決定 0019）。
- 照らした相手の版（サービスなら照らした日、内挿計算プログラムなら結果の注記の版）と、ファイルの `model name`・`model year`（`compare` が表示する）も書く。
- 出典として、国土地理院の「ジオイド2024日本とその周辺」と「基準面補正パラメータ」を示す。
- 書く先のフォルダーとモデルのファイルは、Git に入れない。`points` と `compare` は、リポジトリの中のフォルダーとファイルを断る。

## テスト

`cargo test -p xtask geoid` は、テストの中で作る小さな ISG で、度分秒の読み書き、点の一覧の場所、無効の領域の際の選び方、結果の読み方と比べ方、リポジトリの中のフォルダーとファイルを断ることを確かめる。国土地理院のモデルとその値は使わない。

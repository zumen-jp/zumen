# ジオイドの格子の補間を国土地理院の計算と照らす

`zumen-crs` のジオイドの格子の読み取り（`Grid::read`）と双一次の補間（`Grid::interpolate`）を、国土地理院の[ジオイド高計算サービス](https://vldb.gsi.go.jp/sokuchi/surveycalc/geoid/calcgh/calcframe.html)か、モデルと一緒に配られる内挿計算プログラム（geoidcalc）の結果と照らす検証キットです（#438）。国土地理院のモデル（ISG 形式のファイル）は、利用者が入手し、リポジトリの外に置きます。モデルとその値、サービスとプログラムが返した値は、Git・パッケージ・テストに入れません（[座標系の扱い](../../../docs/formats/crs.md)）。

| ファイル・コマンド | 中身 |
| --- | --- |
| `points.txt` | 照らす点の一覧（27 点）。格子点の上・東西と南北の格子の線の上・格子の中・範囲の外の点。範囲の隅と縁の点、縁から 0.0001 秒内側と外側の点、基準面補正量のある離島の点を含む |
| `cargo xtask geoid points` | 点の一覧に、渡した格子の無効の領域の際の点を足し、サービスと内挿計算プログラムの入力と、zumen の値をフォルダーに書く（`xtask/src/geoid.rs`） |
| `cargo xtask geoid compare` | サービスか内挿計算プログラムの結果を、zumen の補間の値と比べ、点の数と差の最大を示す |

サービスへの入力と内挿計算プログラムの実行は、利用者が行います。エージェントが行うのは、そのセッションで利用者がブラウザーかアプリの利用を許したときだけです（#438 の 2026-11-09 の判断、`docs/work.md`）。

## 国土地理院の側（2026-11-09 に確かめた）

### モデル

- 「ジオイド2024日本とその周辺」と「基準面補正パラメータ」の[説明書](https://www.gsi.go.jp/common/000277542.pdf)（2026 年 4 月）の 2 章 (1)① によれば、公開しているのは `JPGEO2024_isg` フォルダーを zip にしたもので、フォルダーに次のファイルが入っている。
  - `JPGEO2024.isg`（ジオイド高）・`Hrefconv2024.isg`（基準面補正量）・`JPGEO2024+Hrefconv2024.isg`（同じ地点の 2 つを足した値。説明書は「統合したファイル」と呼ぶ）
  - 内挿計算プログラムの `geoidcalc_win64.exe`（Windows）・`geoidcalc_linux_x86_64.tar.gz`（Linux）と、その入力の例 `input.txt`
- 格子は北緯 15〜50 度・東経 120〜160 度で、間隔は緯度 1 分・経度 1.5 分（2101 行 × 1601 列）。`JPGEO2024.isg` は範囲の全域に値を持つ。`Hrefconv2024.isg` は、日本水準原点の範囲で 0、ほかの原点の範囲（吐噶喇列島以南・八丈島以南の離島）で基準面補正量、標高の原点の定まっていない範囲で無効（`-9999.0000`）を持つ。統合したファイルも、同じ所が無効になっている。
- 国土地理院の[ジオイド・モデルの頁](https://www.gsi.go.jp/buturisokuchi/grageo_reference.html)は、「ジオイド2024日本とその周辺」を 2025-04-01 から使うモデルとして挙げ、モデルのバージョンの番号を書いていない。説明書の改訂は、2025-04-01 の初版と、2026-04-01 の商標の追記だけである。
- 入手は、基盤地図情報のサイトから。測量に使わない研究・調査なら、出典を示せば申請は要らない（[利用手続](https://www.gsi.go.jp/buturisokuchi/grageo_geoidprocedure.html)）。

### ジオイド高計算サービス

- 測量計算サイトの[トップ](https://vldb.gsi.go.jp/sokuchi/surveycalc/main.html)には、「ジオイド高計算（ジオイド2024日本とその周辺）」と、経過措置の「日本のジオイド2011（Ver2.2）」の計算がある。キットは前者と照らす。前者は、ジオイド高に「ジオイド2024日本とその周辺」を使い、参考として基準面補正量も示す。海域と一部の離島には、基準面補正量のない無効の領域がある。モデルのバージョンの番号は書いていない。
- 1 点ずつの計算（緯度・経度を度分秒か十進の度で入れる）と、ファイルの一括計算がある。どちらも、結果の画面に、計算に使ったパラメーター（「ジオイド2024日本とその周辺」と「基準面補正パラメータ」）を示す（入出力機能説明の画面の例）。
- 1 点ずつの計算の画面は、ジオイド高・基準面補正量・ジオイド高+基準面補正量の 3 つを、メートルの小数 4 桁で示す（入出力機能説明の画面の例）。
- 一括計算の入力は、拡張子が `.in` のテキストで、名前は英数字・`_`・`.` だけにする。1 行に緯度と経度を半角の空白で区切り、度分秒を区切らずに書く（`dddmmss.ssss`）。`#` で始まる行はヘッダーで、文字コードは Shift_JIS か、BOM のない UTF-8 にする。ジオイド高計算の一括計算は、100 点まで（トップの注意事項）。
- 一括計算の結果は、拡張子が `.out` のテキストである。入出力ファイル形式の頁の例は、`#` で始まるコメントの行の後に、1 行に緯度・経度・ジオイド高を小数 3 桁で書き（「入力値を出力する」を選んだとき）、範囲の外を `-9999.` とする。ただし、その頁は「数字は実際の計算結果とは異なります」とし、コメントの行も古いモデルのファイル（`gsigeo2011_ver1.asc`）の名前のままである。今のサービスの一括計算の結果の列と小数の桁は、公式の頁に書かれていない。
- 同じ IP アドレスからの計算は、10 秒に 3 回まで（トップの注意事項）。

`compare` は、結果の値の小数の桁を数え、4 桁（0.1 mm）より少なければ、0.1 mm の照合にしません。

### 内挿計算プログラム

- 説明書の 3 章。ISG format 2.0 のファイルを読み、求める点を囲む四隅の格子点で双一次に補間する。四隅のどれかが無効なら `NaN` を書く。格子点の上と格子の線の上では、その格子点か、線の両端の格子点だけを見る（注 6）。3 章 (2) の式は、どちらの側の格子を使うかを書いていない。
- 入力は、1 行目に `Unit:DMS` と書き、続けて 1 行に緯度と経度を半角の空白で区切り、度分秒を区切らずに書く（秒の小数は 4 桁まで）。`-g` で格子のファイル、`-i` で入力、`-o` で出力を選ぶ。`log.txt` だけは、実行ファイルと同じフォルダーに書く（3 章 (3)④）。
- 出力は、`#` で始まるコメントの行（格子のファイルと、プログラムの名前とバージョン）の後に、1 行に緯度・経度・値（メートル）を書く。説明書の例の値は、小数 4 桁である。
- 3 章 (4)① は、範囲の外を 2 通りに書く。ISG のファイルの lat min・lat max・lon min・lon max から外側を範囲の外とし、`JPGEO2024.isg` については、北緯 15 度の「以南」と 50 度の「以北」、東経 120 度の「以西」と 160 度の「以東」を範囲の外とする。後の書き方は、範囲の縁の線の上も範囲の外と読める（下の「範囲の縁」）。
- 3 章 (4) は、ジオイド高と基準面補正量を別々に求めて足した値と、統合したファイルから求めた値は、0.1 mm ほど違うことがあると書く。キットは、ファイルごとに、同じファイルを使った結果と比べる。

## 点

`points.txt` の点は、説明書の格子の形から選びました（27 点）。どの点がどこにあるかは、`cargo test -p xtask geoid` が、説明書の格子の形（値は持たない）で確かめます。

| 場所 | 点 |
| --- | --- |
| 格子点の上 | P01〜P05（P03 は那覇付近、P04・P05 は範囲の隅） |
| 東西の格子の線の上 | P06・P08・P26・P27（P08 は範囲の北の縁、P26・P27 は東と西の縁から 0.0001 秒内側） |
| 南北の格子の線の上 | P07・P09・P24・P25（P09 は範囲の東の縁、P24・P25 は北と南の縁から 0.0001 秒内側） |
| 格子の中 | P10〜P19（P10 はサービスの入力の例の点、P14〜P17 は基準面補正量のある離島、P18 は海域、P19 は日本の外の陸） |
| 範囲の外 | P20〜P23（範囲の縁から 0.0001 秒外側） |

範囲の縁の線の上の点（P04・P05・P08・P09）と、その内側と外側の点（P24〜P27・P20〜P23）で、範囲の境の規則と、補間そのものを分けて確かめます（下の「範囲の縁」）。

`JPGEO2024.isg` は無効の格子点を持たないので、無効の領域の際の点は、`cargo xtask geoid points` が、渡した `Hrefconv2024.isg` と統合したファイルから選んで足します（E01 から）。際の位置はモデルから決まるので、キットの `points.txt` には書かず、利用者のフォルダーにだけ書きます。形は次の 8 つで、形ごとに、北の行から探し、使う有効の格子点の値がどれも 0 でない際（離島の際）を先に選びます。範囲の縁の線の上の点は、境の規則の違いと注 6 の扱いの違いを分けられないので選びません（下の「範囲の縁」）。

| 形 | zumen の値 |
| --- | --- |
| 東・南・南東の隣に無効の格子点がある格子点 | あり（重みが 0 の格子点は見ない。説明書の注 6） |
| 北・北東の隣に無効の格子点がある格子点 | あり（同じ） |
| 両端が有効で、南の隣に無効の格子点がある、東西の線の上 | あり（同じ） |
| 両端が有効で、北の隣に無効の格子点がある、東西の線の上 | あり（同じ） |
| 両端が有効で、東の隣に無効の格子点がある、南北の線の上 | あり（同じ） |
| 片方の端が無効の、東西の線の上 | なし |
| 片方の端が無効の、南北の線の上 | なし |
| 隅に無効の格子点を持つ格子の中 | なし |

`Grid::interpolate` は、格子点と格子の線の上で、南と東の隣の格子点を重み 0 で持ちます。説明書の式で (i, j) を南西の格子点にとると、重み 0 になるのは北と東の隣の格子点です。どちらの側でも注 6 のとおりかを確かめるため、両方の側の際を選びます。線の上の点は、西か北の格子点から間隔の 3 分の 1 の所に置きます（片方の端が無効の線では、有効の端から 3 分の 1）。格子の中の点は、北西の格子点から南と東へ 3 分の 1 ずつの所に置きます。`points` は、それぞれの点で、zumen の値のあるなしが表のとおりかも確かめます。

## 手順

コマンドは、リポジトリの根で流します。下の例のパスは、リポジトリの根から書いています。`points` と `compare` は、リポジトリの中と、ほかの Git の作業ツリーの中のフォルダーとファイルを断ります。作業ツリーがほかの checkout の中にあるとき（`.claude/worktrees/` の下など）は、`..` がその checkout の中を指すので、リポジトリの外の絶対パスを使ってください。

1. 基盤地図情報のサイトから、ISG 形式の「ジオイド2024日本とその周辺」（`JPGEO2024_isg` フォルダーの zip）を入手し、リポジトリの外のフォルダー（下の例では `../geoid`）に展開する。ファイルは `../geoid/JPGEO2024_isg/` に入る。違う所に入ったら、下のパスを合わせる。
2. 点と入力を作る。書く先のフォルダー（下の例では `../geoid-check`）も、リポジトリの外にする。

   ```bash
   cargo xtask geoid points ../geoid-check ../geoid/JPGEO2024_isg/JPGEO2024.isg ../geoid/JPGEO2024_isg/Hrefconv2024.isg "../geoid/JPGEO2024_isg/JPGEO2024+Hrefconv2024.isg"
   ```

   どれかのファイルを `Grid::read` で読めなければ、診断の code と一緒に止まる（#438 の完了の条件の 1 つめ）。読めれば、フォルダーに `points.txt`（点の一覧）・`geoid.in`（サービスの一括計算の入力）・`input.txt`（内挿計算プログラムの入力）と、格子ごとの zumen の値（`zumen-JPGEO2024.txt` など）を書き、点ごとに、ファイルごとの場所と zumen の値のあるなしを表示する。値は画面に出さない。zumen の値のファイルは、内挿計算プログラムの結果と同じ形（緯度・経度・値）で、モデルから求めた値なので、Git・issue・PR に書かない。

3. 結果を作る。次のどれか、またはいくつかを使う。
   - 内挿計算プログラム（Windows の PowerShell）: 3 つのファイルそれぞれについて流す。`log.txt` は、実行ファイルと同じフォルダー（`../geoid/JPGEO2024_isg/`）に書かれる。

     ```powershell
     ..\geoid\JPGEO2024_isg\geoidcalc_win64.exe -g ..\geoid\JPGEO2024_isg\JPGEO2024.isg -i ..\geoid-check\input.txt -o ..\geoid-check\JPGEO2024.out
     ```

     ```powershell
     ..\geoid\JPGEO2024_isg\geoidcalc_win64.exe -g ..\geoid\JPGEO2024_isg\Hrefconv2024.isg -i ..\geoid-check\input.txt -o ..\geoid-check\Hrefconv2024.out
     ```

     ```powershell
     ..\geoid\JPGEO2024_isg\geoidcalc_win64.exe -g "..\geoid\JPGEO2024_isg\JPGEO2024+Hrefconv2024.isg" -i ..\geoid-check\input.txt -o ..\geoid-check\combined.out
     ```

   - 内挿計算プログラム（Linux）: tar.gz を展開し、実行の権限を付けてから流す（説明書の 3 章 (3)②）。`Hrefconv2024.isg` と統合したファイルも、`-g` と `-o` を変えて流す。

     ```bash
     tar -xzf ../geoid/JPGEO2024_isg/geoidcalc_linux_x86_64.tar.gz -C ../geoid/JPGEO2024_isg
     ```

     ```bash
     chmod +x ../geoid/JPGEO2024_isg/geoidcalc_linux_x86_64
     ```

     ```bash
     ../geoid/JPGEO2024_isg/geoidcalc_linux_x86_64 -g ../geoid/JPGEO2024_isg/JPGEO2024.isg -i ../geoid-check/input.txt -o ../geoid-check/JPGEO2024.out
     ```

   - ジオイド高計算サービスの一括計算: 測量計算サイトの「ジオイド高計算（ジオイド2024日本とその周辺）」の頁で「一括計算」を選び、`geoid.in` を選んで、「入力値を出力する」を選んだまま計算し、結果を `../geoid-check/service.out` に保存する。結果の画面の、計算に使ったパラメーターを控える。
   - ジオイド高計算サービスの 1 点ずつの計算: 点ごとに、`geoid.in` の緯度・経度を度分秒で入れ、画面のジオイド高・基準面補正量・ジオイド高+基準面補正量を、`geoid.in` の各行の後ろに、この順に空白で区切って足す。値がなければ `NaN` と書く。できたファイル（例: `../geoid-check/single.out`）は、3 列目がジオイド高、4 列目が基準面補正量、5 列目が 2 つの和になる。

4. 結果のファイルごとに、使った格子のファイルと列を渡して比べる。列は、緯度を 1 列目、経度を 2 列目として数え、既定は 3 列目。

   ```bash
   cargo xtask geoid compare ../geoid-check ../geoid/JPGEO2024_isg/JPGEO2024.isg ../geoid-check/JPGEO2024.out
   ```

   | 結果 | 格子のファイル | 列 |
   | --- | --- | --- |
   | 内挿計算プログラム（`JPGEO2024.out`・`Hrefconv2024.out`・`combined.out`） | `-g` で渡したファイル | 3（既定） |
   | サービスの 1 点ずつの計算のジオイド高 | `JPGEO2024.isg` | 3（既定） |
   | サービスの 1 点ずつの計算の基準面補正量 | `Hrefconv2024.isg` | `--column 4` |
   | サービスの一括計算 | 結果の列の見出しに合わせる（ジオイド高は `JPGEO2024.isg`、基準面補正量は `Hrefconv2024.isg`） | 見出しの列 |

   サービスの和（ジオイド高+基準面補正量）は、照合に数えない。説明書の 3 章 (4) のとおり、別々に求めて足した値と、統合したファイルの値は 0.1 mm ほど違い得るうえ、サービスがどちらで求めたかは書かれていない。統合したファイルは、内挿計算プログラムの結果と照らす。参考に比べるなら、`--column 5` で統合したファイルと比べる。

   `compare` は、数字で始まる行を値の行とし、ほかの行（`#` で始まるコメントの行や見出し）は、そのまま表示する。値の行を `points.txt` の順に結び、行の数と、緯度・経度が点と同じかを確かめてから、値を比べる。選んだ列より後ろの列は読まない。

## 範囲の縁

zumen は、範囲の縁の線の上（緯度が lat min か lat max、経度が lon min か lon max の所）を範囲の中とし、値を返します。説明書の 3 章 (4)① の「以南」「以北」などの書き方のとおりに、相手が縁の線の上を範囲の外とすれば、P04・P05・P08・P09 で、結果だけが値なしになります。無効の領域の際の点は、縁の線の上には選びません。

`compare` は、その点を「範囲の縁」として分けて示し、失敗にしません。そのときは、次のように扱います。

- 境の規則の違いとして、点の ID と照らした相手を #438 に書く（値は書かない）。
- 縁から 0.0001 秒内側の P24〜P27 が 0.1 mm 以内で合えば、補間そのものは合ったとみる。
- zumen の境の規則を相手に合わせるかは、#438 で決める。
- 結果だけが値なしの範囲の縁の点は、値を比べた点に数えない（#438 の「10 点以上」にも数えない）。

相手が縁の線の上で値を返せば、ほかの点と同じく、0.1 mm 以内で合うことを確かめます。縁から 0.0001 秒外側の P20〜P23 は、どちらの書き方でも範囲の外なので、結果も値なしになるはずです。

## 期待する結果

- `points`: 3 つのファイルを読める。`JPGEO2024.isg` は無効の格子点がないと表示し、`Hrefconv2024.isg` と統合したファイルからは、無効の領域の際の点を 8 つまで選ぶ（同じ点は 1 つにする）。
- `compare`: どの結果でも「合った」の行を示して通る（終了コードは 0）。値のある点は差が 0.1 mm 以内で、zumen が値を返さない点では、結果も値なし（`NaN`・`-9999.`）。「合った」の行に、値を比べた点の数と、両方とも値なしの点の数を分けて示す。範囲の縁の点と、値を比べた点が 10 点より少ないことは、その後の行に示す。
  - `JPGEO2024.isg`: 範囲の外の P20〜P23 だけが値なし。
  - `Hrefconv2024.isg`・統合したファイル: 加えて、無効の領域の中の点と、際の点のうち上の表で「なし」の形の点が値なし。
  - 範囲の縁の点で、結果だけが値なしなら、「範囲の縁」として分けて示す（上の「範囲の縁」）。
- 結果の値の小数が 4 桁より少なければ、`compare` は「0.1 mm の照合になりません」で終わる。表示の丸めの中で合ったことは示すが、#438 の照合には数えない。
- 合わなければ、`compare` は、点の ID・場所・差（値は書かない）を示して止まる。仕様と結果を比べて、違いを調べる。

## 記録

- `docs/formats/crs.md` の検証の記録と #438 には、照らしたファイル・照らした相手・点の数（値を比べた点と、両方とも値なしの点）・差の最大だけを書く。モデルの値、サービスとプログラムが返した値、zumen の値、無効の領域の際の点の位置は書かない（[座標系の扱い](../../../docs/formats/crs.md)）。
- 照らした相手を特定できるよう、サービスなら照らした日と、結果の画面の計算に使ったパラメーターを書く。内挿計算プログラムなら、結果のコメントの行のプログラムのバージョンを書く。モデルのバージョンの番号は公開されていないので、ファイルの `model name`・`model year`（`compare` が示す）を書く。
- 範囲の縁で結果だけが値なしだった点は、その ID と照らした相手を書く（上の「範囲の縁」）。
- 出典として、国土地理院の「ジオイド2024日本とその周辺」と「基準面補正パラメータ」を示す。
- 書く先のフォルダーとモデルのファイルは、Git に入れない。誤ってリポジトリの中に展開しても、`JPGEO2024_isg` のフォルダー、`.isg` のファイル、内挿計算プログラム（`geoidcalc_*`）は、`.gitignore` で Git から外れる。

## テスト

`cargo test -p xtask geoid` は、テストの中で作る小さな ISG で、度分秒の読み書き、点の一覧の場所、無効の領域の際の選び方（範囲の隅と、秒の小数 4 桁で表せない格子を含む）、点の数の上限、結果の読み方と比べ方（範囲の縁の扱いを含む）、リポジトリと Git の作業ツリーの中のフォルダーとファイルを断ることを確かめます。国土地理院のモデルとその値は使いません。

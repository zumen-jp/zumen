# 文書エンジンの試作

[文書エンジン](../../docs/live.md)を、DXF で縦に 1 本通した試作です。図面を開いたままメモリに置き、要素を動かす・足す・除く・属性を変える変更と、取り消し・やり直し・全体の保存・範囲で選ぶことを、変えた要素の分だけの手間で行います。今の実装（要求のたびに図面の全体を作り直す、今のコアの動かし方）に同じ変更を 1 つずつ当てて、保存したバイト列を比べ、同じ操作の時間とメモリを測ります。作業は [#878](https://github.com/zumen-jp/zumen/issues/878) で追います。

コアのワークスペースには入れていません。`crates/` と公開の API には、何も足していません。依存は、このリポジトリの `zumen`・`zumen-acad`・`zumen-drawing` と、`libm` です。`Cargo.lock` は、ワークスペースの `Cargo.lock` から同じバージョンを引き継いでいます。CI はこのフォルダーのコードを組み立てないので、下の結果は、書いた日付に手元で流したものです。

## 範囲

扱うものは、次のとおりです。

- 入力は ASCII の DXF です。行の終わりは、LF と CR LF のどちらも読みます。
- 要素は、ENTITIES セクションの、モデル空間の LINE・CIRCLE・ARC・LWPOLYLINE・TEXT・INSERT です。INSERT は、続く ATTRIB と SEQEND を付けて、1 つの要素として持ちます。要素になる条件と ID（`space/0/h2D9` など）は、今の実装と同じにしています。
- ブロックの定義は、開くときに 1 回読みます。名前・基点・中身の図形と、属性の定義（ATTDEF）を持つかどうかを持ちます。
- 変更は、要素を動かす・除く・属性を変える・足すの 4 種類です。今の実装の `apply` の `transform`・`remove`・`restyle`・`add` に当たります。属性を変える変更は、画層・色・線種・線種の尺度・線の太さを変えます。足す変更は、線・円・円弧・折れ線・文字と、属性のない記号（ブロックの挿入。格子に並べるものを含みます）を、モデル空間に足します。
- 1 回の変更は、種類の違う変更をいくつでも並べられて、すべて受け付けるか、すべて受け付けないかのどちらかになります。
- ほかの操作は、取り消し・やり直し・全体の保存・範囲で選ぶことです。
- 開くときは、ファイルを区間に分けて、複数のスレッドで読みます。

扱わないものは、次のとおりです。

- 寸法・ハッチング・MTEXT・点など、ほかの種類の図形と、ペーパー空間の図形。ペーパー空間にある 6 種類の図形は、数だけを数えます。
- 要素を置き換える変更（`replace`）と、画層・線種・文字スタイル・寸法スタイルなどの表の変更。
- 属性（ATTRIB）を持つ記号を足す変更。
- DWG と、バイナリ DXF。バイナリ DXF は、開くときに断ります。4 GiB 以上のファイルも、位置を 32 bit で持つので断ります。
- 診断・予算・中断・要素と文書のハッシュ・文書が古くなっていないかの確かめ・JSON のメッセージ。
- Shift_JIS（`$DWGCODEPAGE` が `ANSI_932`）の図面にある、ASCII でない文字を持つ図形。数だけを数えます。
- ハンドルのない図形を指す変更。図形は持ちますが、ID がないので指せません。
- 後ろに足す保存、変更の記録をファイルに足すこと、版。
- wasm での組み立てと測定。

今の実装は受け付けるが、この試作は範囲の外として断る変更があります。`compare` は、これを違いに数えず、理由ごとの件数を出します。理由は次の 6 つで、それぞれの見立ては[書き戻しに要るもの](#書き戻しに要るもの)に書きます。

| 理由 | 断る変更 |
| --- | --- |
| 付き方 | ATTRIB と SEQEND の付く先が、レコードの並びだけで決まらない図面で、要素を足す・除く変更 |
| 名前 | 画層・線種の名前が、表のレコード 1 つで決まらないときに、その名前を指す変更。表にない名前、同じ名前のレコードがいくつかある名前、綴りの大文字と小文字が表と違う名前が当たります。Shift_JIS の図面で、表の名前に ASCII でない文字があるときは、名前を指す変更をすべて断ります |
| 定義 | 記号の定義が、名前で 1 つに決まらないか、属性の定義を持つときに、その定義の記号を足す変更 |
| 文字コード | Shift_JIS の図面に、ASCII でない文字を書く変更と、ASCII でない文字の属性が付いた INSERT を動かす・属性を変える変更 |
| セクション | ENTITIES セクションがちょうど 1 つでない図面に、要素を足す変更 |
| 読み直し | 足したレコードを、この試作が要素として読み直せない変更。照らした中では、1 回もありませんでした |

## 持ち方

- 元のファイルのバイト列を、そのまま持ち続けます。レコード（グループ・コード 0 のタグから、次の 0 の前まで）の先頭の位置を覚えます。
- 要素は、列ごとの配列で持ちます。行（ハンドル・レコードの番号・種類・画層・色）と、種類ごとの形の表、頂点・文字・記号の属性の置き場に分けます。行の番号は、32 bit の整数です。
- 除いた要素の行は、場所を残して、生きていない印を付けます。足した要素の行は、終わりに足します。行の番号とレコードの番号は、変更で変わりません。
- INSERT の行は、定義の番号・置く点・尺度・回転・格子と、付いた属性の範囲を持ちます。ATTRIB と SEQEND の付く先は、開くときに 1 回、今の実装と同じ規則（所有者と、レコードの並び）で決めます。
- 変えたレコードと足したレコードだけを、タグの列として別に持ちます。変えていないレコードは、保存のときに元のバイト列を写します。足したレコードは、ENTITIES セクションを閉じる ENDSEC の前に書き、除いたレコードは書きません。
- 表示のバッファー、要素を囲む箱、ハンドルから行を引く表、範囲の索引を持ち続け、変更のたびに、変えた行の分だけを直します。表示のバッファーは、線分・円弧・文字を、要素ごとの値のまま並べたものです。除いた行は、表示のバッファーの場所を残して持ち主を外し、箱を空にして、索引から外します。範囲の索引は、段ごとにセルの大きさが 2 倍になる格子です。
- INSERT の表示は、定義の番号と置き方（置く点・尺度・回転・格子）を持つ 1 つの挿入と、表示する属性の文字です。定義の中身は、開くときに 1 回だけ、別の表示のバッファーにします。定義の中身を挿入ごとに置くことは、描く側の仕事として、この試作では行いません。INSERT の箱は、置く点・属性を置く点と、定義の中身の箱を格子の四隅に写したものを囲みます。
- 開くときに 1 回読んで、持ち続けるものがあります。名前の表（画層・線種・文字スタイル・ブロックの、綴りと、同じ名前のレコードの数）、ブロックの定義、ほかのオブジェクトからの参照の逆引き、ハンドルの最大、ヘッダーの変数（`$HANDSEED`・`$EXTMIN`・`$EXTMAX`）、版（`$ACADVER`）、文字コード、モデル空間の持ち主、ENTITIES セクションの終わりの位置です。
- 変更は、文書を変える前にすべて決めてから当てます。当てた操作（タグの置き換え・追加・削除と、行を足す・除くこと）を記録し、取り消しは、記録にある前の値を戻します。逆の変換は当てません。
- ハッシュの表は使いません。名前は順序のある表、ハンドルは値で引く配列（飛び飛びのときは、ハンドルの順に並べた列の二分探索）で引きます。

## 今の実装と同じにした規則

要素になる条件、変更の後のレコードの値、タグの差し替え方は、今の実装のコードと同じ規則を、この試作の中に書いています。変換の計算は `zumen-drawing` の `transform`、値の型は `zumen-acad` の型を、そのまま呼びます。今の実装の列は、`crates/zumen-acad/src/` からの位置です。

| 試作 | 今の実装 | 規則 |
| --- | --- | --- |
| `src/scan.rs`・`src/value.rs` | `dxf.rs`・`dxf/objects.rs` | 行とタグの切り方、値の型と書式 |
| `src/lift.rs` | `drawing.rs`・`drawing/geometry.rs`・`drawing/style.rs` | 図形が要素になる条件と、形の読み方 |
| `src/store.rs` | `drawing.rs`・`drawing/block.rs` | ATTRIB と SEQEND の付く先、ブロックの定義の読み方 |
| `src/edit.rs` | `drawing/apply.rs`・`drawing/apply/replace.rs`・`drawing/apply/transform.rs`・`db.rs`・`dxf/write_back.rs` | 動かした後と属性を変えた後のレコードの値、タグの差し替え方、除く要素への参照の外し方、図面の範囲（`$EXTMIN`・`$EXTMAX`）の広げ方、`$HANDSEED` の直し方 |
| `src/born.rs` | `drawing/apply/add.rs`・`drawing/apply/transform.rs`・`drawing/style.rs` | 足すレコードのタグ、画層・線種・文字スタイル・定義の名前の決め方、色・線種・線の太さの書き方 |
| `src/save.rs` | `dxf.rs` | 書き出し |

規則が 2 か所にあるので、今の実装の規則を変えると、この試作は合わなくなります。そのときは `compare` が違いを出します。この試作のコードは、試験を含めて 12,600 行ほどで、そのうち今の実装の規則を写したファイル（`lift.rs`・`edit.rs`・`born.rs`）が 4,200 行ほどです。

## 流し方

リポジトリのルートで流します。図面は、[bench/editor](../editor/README.md) の `prepare.mjs` が作る `target/bench-editor/dxf-*.dxf` と、公開サンプルを使います。受け取った図面は使いません。

```bash
cargo build --release --locked --manifest-path bench/live/Cargo.toml --target-dir target
mkdir -p target/bench-live
target/release/live compare target/bench-editor/dxf-1k.dxf samples/dxf/text_alignments.dxf --hashes
target/release/live measure target/bench-editor/dxf-100k.dxf --current
target/release/live grow target/bench-editor/dxf-100k.dxf target/bench-live/dxf-1m.dxf 10
target/release/live grow samples/dwg/zumen-minsert-r2018_ascii.dxf target/bench-live/insert-100k.dxf 25000
target/release/live cases samples/dxf/text_alignments.dxf target/bench-live/cases.dxf 400 --seed 1 --variant loose
target/release/live open target/bench-live/dxf-1m.dxf --hold 3000
```

- `compare` は、文書エンジンと今の実装に同じ変更を流して比べます（[照らし方](#照らし方)）。違いがなければ 0、あれば 1、引数や入力を読めなければ 2 で終わります。`--steps` は変更の数、`--seed` は乱数の種（指定しなければ 1）、`--threads` は開くときのスレッドの数（指定しなければ論理 CPU の数）です。`--hashes` を付けると、今の実装の要素のハッシュを変更のたびに取り直して、変更が指していない要素のハッシュが変わっていないかを見ます。`--show` を付けると、違いの前後のバイト列を出します。図面の中身が出るので、公開できる入力だけで使います。
- `measure` は、文書エンジンの時間を測ります。`--current` を付けると、今の実装の同じ操作も、同じプロセスで測ります。`--runs` は、開くこと・保存・今の実装の操作を繰り返す回数（指定しなければ 7 回）です。範囲で選ぶ小さい範囲は、bench/editor の図面では決まった範囲を使い、ほかの図面では `--region` で渡すか、要素の 1 つの周りを選びます。
- `grow` は、モデル空間の要素を、ずらしながら写して増やします。属性の続く INSERT は、続く ATTRIB と SEQEND も写します。上の例は、10 万要素の図面を 10 枚並べて 100 万要素にするものと、INSERT を 4 つ持つ公開サンプルを 25,000 枚並べて 10 万要素にするものです。
- `cases` は、書き方を変えた図形を足した入力を作ります（[書き方を変えた図面](#書き方を変えた図面)）。`--variant` は、図面の作りの変種です。
- `open` は、開いたまま `--hold` のミリ秒だけ待ちます。プロセスのメモリを、外から測るために使います。`--current` を付けると、今の実装で開いて `scene` を 1 回作ってから待ちます。
- `--budget` は、今の実装の要求に付ける予算の JSON です。下の結果は、付けずに流しました。
- `grow` と `cases` が作るファイルは、測ることと照らすことのための入力です。写した図形の拡張ディクショナリやリアクターは元の図形と同じものを指し、`cases` はわざと読めない値も書くので、ほかのアプリケーションに渡す図面にはなりません。

## 照らし方

`compare` は、入力ごとに次を行います。

1. 両方で開き、今の実装の `entities` が返す要素の ID と、文書エンジンが持つ要素の ID を比べる。文書エンジンだけが持つ要素は、違いに数える。今の実装だけが持つ要素（この試作が扱わない種類と、ペーパー空間の要素）は、種類ごとの数を出す。
2. ファイルを 1・2・3・7・16 個の区間に分けて開いた結果が、ふつうに開いた結果と同じことを確かめる。
3. 種を決めた乱数で変更を作り、両方に 1 つずつ当てる。変更の作り方は、下に書く。
4. 1 つ当てるごとに、受け付けるかどうかが両方で同じことと、文書エンジンが保存したバイト列が、今の実装が書き戻したバイト列と同じことを確かめる。足す変更では、今の実装が返した新しい要素の ID と、文書エンジンが振ったハンドルが同じことも確かめる。
5. 受け付けた変更ごとに、取り消して保存したバイト列が変更の前と同じことと、やり直して保存したバイト列が変更の後と同じことを確かめる。
6. 決まった間隔（変更の数の 16 分の 1 ごと）で、文書エンジンが持つ列・表示のバッファー・箱が、保存したバイト列から開き直したものと同じことと、範囲で選ぶ結果が、総当たりと、開き直した文書と同じことを確かめる。表示のバッファーは、生きている行の値を比べ、あわせて、並びまで同じかどうかを数える。
7. 最後に、すべて取り消したバイト列が始まりと同じことと、変えたレコードと除いた行が残っていないこと、すべてやり直したバイト列が今と同じことを確かめる。

今の実装だけが受け付けて、文書エンジンが範囲の外として断った変更は、理由ごとに数えます。そのあと、文書エンジンを今の実装のバイト列から開き直して、続けます。文書エンジンだけが受け付けた変更と、理由が範囲の外でないのに文書エンジンだけが断った変更は、違いです。

変更の数は、指定しなければ、要素の数から 80〜4,000 回の間で決めます。変更は、次の割合で作ります。

| 変更 | 割合 | 1 回に指す数 | 混ぜるもの |
| --- | ---: | --- | --- |
| 動かす | 52% | 1 件が 78%、2〜8 件が 15%、9〜100 件が 7% | ない ID、同じ要素を 2 度。変換は、平行移動・回転・拡大と縮小・鏡映・相似・縦横で違う拡大・せん断・恒等・逆のない変換 |
| 足す | 16% | 1 件が 78%、2〜6 件が 22% | 表にない名前、綴りの違う名前、ない定義、受け付けない値（半径が 0 以下の円、頂点が 1 つの折れ線など） |
| 属性を変える | 14% | 1 件が 75%、2〜8 件が 25% | ない ID、同じ要素を 2 度、表にない名前 |
| 除く | 12% | 1 件が 72%、2〜5 件が 23%、6 件以上が 5% | ない ID、同じ要素を 2 度 |
| 種類を混ぜる | 6% | 2〜6 個の変更 | すでに指した要素を、別の種類の変更でもう 1 度指す |

指せる要素がなくなれば、足す変更だけを作ります。ASCII でない文字を足す変更は、終わりの 5% の回だけで作ります。

今の実装と比べているのは、要素の ID の集まりと、受け付けるかどうかと、保存したバイト列と、足した要素の ID です。バイト列が同じなので、読み直した図面モデル・ID・ハッシュ・診断も同じになります。文書エンジンが中に持つ形・表示のバッファー・範囲で選ぶ結果は、文書エンジンどうし（開き直したものや総当たり）で比べていて、今の実装のシーンや `entities` の結果とは照らしていません。

### 書き方を変えた図面

合成の図面は `apply` の `add` が書いた図形で、公開サンプルは 6 種類の要素が少ないので、書き方の幅が足りません。`cases` は、土台の図面の ENTITIES セクションの終わりに、6 種類の図形を、乱数で書き方を変えながら足します。変えるのは、次のものです。

- 実数の書式（小数の桁、指数、前後の空白、正の符号、先頭の 0 を省いた小数、小数点のない値、`-0.0`）、整数の桁寄せ、ハンドルの大文字と小文字。
- 座標の大きさ（0、負の値、桁の多い値、とても大きい値と小さい値）。
- 省けるタグの有無と値（持ち主・サブクラスマーカー・線種・色・RGB の色・透明度・線の太さ・線種の尺度・表示しない印・厚さ・押し出しの向き・Z の値）。
- CIRCLE と ARC の、0 と負の半径、0〜360 度の外の角。
- LWPOLYLINE の、0 個と 1 個の頂点、頂点の数と合わない 90、閉じる印と線種の生成、一定の幅、頂点ごとの幅、膨らみ、頂点の ID、高さ。
- TEXT の、高さ（0 と負の値を含む）、回転、幅の係数（0 と負の値を含む）、傾き、文字スタイル、反転、位置合わせと第 2 の点、`%%d` などの書き方を含む中身。
- INSERT の、定義の名前（下に書く定義と、ない定義）、尺度（0 と負の値を含む）、回転、列と行の数（0 と負の値を含む）と間隔、属性が続く印（続かないのに書くもの、0 を書くものを含む）、続く ATTRIB の数（0〜3 個）、SEQEND の有無。
- ATTRIB の、所有者の有無、画層、色、高さ、中身、回転、幅の係数、傾き、文字スタイル、反転、位置合わせと第 2 の点、タグ、表示しない印などのフラグ。
- XDATA（文字・制御・整数・実数・距離・倍率・点・変位・向きなど。Y と Z の値が続かない点を含む）。
- 読めない値（数でない文字、空の値、範囲を超える数など）と、ペーパー空間の印。

図形のほかに、次のものも足します。

- 表のレコード。画層は、大文字と小文字の違う 2 つの綴りを同じ名前で持つものを含みます。線種と文字スタイルも 1 つずつ足します。図形は、表にない画層も指します。
- ブロックの定義と BLOCK_RECORD。基点のある定義、属性の定義を持つ定義、空の定義、ほかの定義を中に置く定義、同じ名前の定義が 2 つあるもの、小文字の名前で BLOCK_RECORD のないものです。
- 足した図形を指すオブジェクト。DICTIONARY の項目、リアクターの組（`{ACAD_REACTORS`）の中の参照、組の外の所有者と参照です。図形の先頭にも、前の図形を指す組を書きます。除く変更で、参照の外し方を確かめるためです。

`--variant` で、図面の作りを変えます。

| 変種 | 図面の作り |
| --- | --- |
| `plain` | ATTRIB と SEQEND の付き方がそろった図面 |
| `loose` | 付き方のそろわない図面。所有者がほかを指す ATTRIB、印のない INSERT に続く ATTRIB、親のない ATTRIB と SEQEND を混ぜます |
| `no-seed` | `$HANDSEED` のない図面 |
| `low-seed` | `$HANDSEED` が、ハンドルの最大より小さい図面 |
| `two-sections` | ENTITIES セクションが 2 つある図面 |
| `no-tables` | TABLES セクションのない図面 |
| `empty` | ENTITIES セクションが空の図面。図形は足さず、定義と表のレコードだけを足します |

## 書き戻しに要るもの

[採らない条件](../../docs/live.md#進め方)は、書き戻しに図面の全体の解釈が要ることです。変更の種類ごとに、そのレコードのタグのほかに何を使ったかを書きます。

| 変更 | そのレコードのタグのほかに使ったもの |
| --- | --- |
| 動かす | INSERT では、付いた ATTRIB のレコード。文字コード。図面の範囲（`$EXTMIN`・`$EXTMAX`） |
| 属性を変える | 画層と線種の名前の表。版（RGB の色と線の太さを書けるか） |
| 除く | ほかのオブジェクトからの参照の逆引き。ハンドルの最大。ATTRIB と SEQEND の付き方がそろっていること |
| 足す | 次のハンドル（ハンドルの最大と `$HANDSEED`）。画層・線種・文字スタイルの名前の表。ブロックの定義。ENTITIES セクションの終わりの位置。モデル空間の持ち主。版と文字コード。図面の範囲 |

- この範囲では、どの変更も、図面の全体を解釈し直さずに書き戻せました。使ったものは、開くときに 1 回読んで、変更のたびに、変えた分だけを直します。
- 動かす変更と属性を変える変更は、そのレコード（INSERT では、付いた ATTRIB も）のタグを直すだけです。ほかのレコードは変えません。
- 除く変更は、除く要素を指すオブジェクトから、参照を外します。今の実装は、除く要素ごとに、すべてのオブジェクトのタグを見て外します。この試作は、開くときに逆引き（指されるハンドルと、指しているレコードの組）を 1 回作り、指しているレコードだけを直します。外すのは、今の実装と同じく、102 の組の中のハンドルと、DICTIONARY の項目です。組の外の所有者や参照は、残します。除いた要素が持つ拡張ディクショナリのオブジェクトも、今の実装と同じく、残します。
- 足す変更は、ほかのオブジェクトを指す参照を、組の中に書きません。所有者（モデル空間）は組の外です。逆引きは、開くときに作ったものを、変更で直さずに使い続けられました。
- 足す要素のハンドルは、ハンドルの最大の次と `$HANDSEED` の大きいほうから、足す順に振ります。ハンドルの最大は、開くときに 1 回数え、足す・除く変更で直します。最大のハンドルを持つ行を除いたときは、次に大きいハンドルを、ハンドルから行を引く表を下へたどって探します。
- 属性の続く INSERT を除く変更は、今の実装も受け付けないので、付いた ATTRIB と SEQEND を除く規則は要りませんでした。

範囲の外にした理由ごとの見立てです。どれも、この試作で試していないことで、見立てにとどまります。

- 付き方: 付き方のそろった図面では、属性の続く INSERT のすぐ後ろに ATTRIB と SEQEND が並ぶので、ほかの要素を除いても、終わりに足しても、付く先は変わりません。そろわない図面では、間の図形を除くと、続く ATTRIB の付く先が変わりえます。付く先を決め直す範囲を、並びの前後に限れるかどうかは、確かめていません。
- 名前: 今の実装は、表にない名前や、綴りの違う定義がいくつかある名前も、図面の全体の解釈（図形が指すだけの画層を含む一覧）から決めます。開くときに、図形が指す名前を数えておき、変更のたびに数を直せば足りるかもしれません。
- 定義: 属性を持つ記号を足す規則（変更が持つ属性から、ATTRIB と SEQEND を書く）を、入れていません。同じ名前の定義がいくつかある図面での、今の実装の選び方も、写していません。
- 文字コード: Shift_JIS の変換を、入れていません。
- セクション: ENTITIES セクションが 2 つ以上ある図面での、足す場所の規則を、入れていません。

## 要る判断

次の 3 つは、利用者がまだ決めていません。この試作は、どれも決めたことにしていません。

- 差分で直した表示のバッファーを、決定性の契約の対象から外すか。足す・除く変更のあと、表示のバッファーは、開き直して作ったものと並びが変わります。生きている行の値は同じです。契約の対象に残すなら、並びを詰め直す仕事が要ります。
- 後ろに足す保存のバイト列を、どう扱うか。この試作は、全体を書く保存だけを行い、今の実装と同じバイト列にしています。
- crate の置き場所と名前。この試作は、コアのワークスペースの外の `bench/live` にあります。

## 分かったこと

- 取り消しは、タグと行の前の値を戻すので、保存したバイト列が変更の前と同じになりました。足す・除く変更でも同じです。今の実装で逆の変換を当てて戻すときの、丸めの違い（[`apply` で直すときの性質](../../docs/editor.md#apply-で直すときの性質)）は起きません。
- 足す・除く変更のあとは、差分で直した表示のバッファーが、開き直して作ったものと、並びが変わります。除いた行は場所を残し、足した行は終わりに足すためです。開き直すと、除いた行の場所が詰まり、足した行はレコードの順に並びます。動かす変更と属性を変える変更だけなら、並びまで同じです。
- 今の実装の要素のハッシュは、そのレコードの外に依ることがあります。今の実装は、画層の ID を、表のレコードの順と、表にない画層が図形に現れた順で振り、要素のハッシュに画層の ID を入れます（`crates/zumen-acad/src/drawing/style.rs` と `crates/zumen-drawing/src/hash.rs`）。TABLES セクションのない図面で、ある画層を最初に指す図形を除くと、後ろの画層の ID がずれて、指していない要素のハッシュが変わります。`no-tables` の変種の 457 件は、この仕組みで説明できますが、1 件ずつは確かめていません。文書エンジンが要素のハッシュを差分で保つなら、こうした、そのレコードの外に依る値をどう扱うかを決める必要があります。
- 今の実装の除く変更は、除く要素ごとに、すべてのオブジェクトを見ます。逆引きを持ち続ければ、指しているレコードだけで済みました。
- `$HANDSEED` のない図面では、ハンドルの最大の次から振るので、最大のハンドルを持つ要素を除いたあとに足すと、除いた要素と同じハンドルになります。今の実装も同じです。取り消しの記録には、同じハンドルの、除いた行と足した行が並びます。ハンドルから行を引く表は、生きている行だけを引きます。
- 最大のハンドルを持つ行を除くと、次に大きいハンドルを探し直します。ハンドルから行を引く表を、大きいほうから下へたどるので、除いた行のハンドルが下へ続いていると、その数だけ進みます。表を配列で持つ図面では、行のないハンドルも通ります。下の 124〜1,999 件を除いたあとで測ると、0.7〜2.2 マイクロ秒でした。取り消しは、控えた値を戻すので、探しません。
- 今の実装は、変更のたびに `$HANDSEED` と図面の範囲を確かめて直します。文書エンジンでは、ヘッダーの変数を開くときに 1 回読み、変更で値が変わるときだけ、ヘッダーのレコードを直します。
- 分けて読んだ結果を入力の順に集めれば、開いた結果は、区間の数にもスレッドの数にも依りませんでした。
- 今の実装と同じバイト列を書くには、今の実装の規則を、数の書式やタグの順まで同じにする必要がありました。足す変更では、名前の決め方と、版ごとの書き分けも写しました。規則を写して 2 か所に持つ形は、続けられません。採るときは、1 つのオブジェクトのタグを受け取って直す 1 つの実装にまとめ、今の実装と文書エンジンの両方から呼ぶ形がよいと見ています。
- 変えたレコードと足したレコードをタグの列で持ち、除いた行も場所を残すので、変更の多い文書では、メモリが増えます。測った場合では、変えたレコードのタグと取り消しの記録が、10〜38 MiB でした（[測った値](#測った値)）。
- 開いた直後に足す最初の 1 回は、図面の大きさに比例して長くなりました（100 万要素で 19 ms）。行ごとの配列を、開いたときの大きさちょうどで持っていて、足すときに広げて写すためと見ています。配列に空きを持たせて開くか、配列を区切って持てば、避けられると見ていますが、試していません。
- 元のファイルのバイト列を持ち続けるので、メモリは、ファイルの大きさより小さくなりません。INSERT の多い図面は、1 要素あたり 490 バイトほどあり、100 万要素では、元のファイルだけで 468 MiB と、目標の値（500 MiB）に近い大きさです。
- INSERT の多い図面を開く時間の大半は、ATTRIB と SEQEND の付く先を決めて、付いた ATTRIB を読む段でした。この段は、1 つのスレッドで流しています。分けて流せるかどうかは、試していません。

## 確かめていないこと

- コアの lint（添字・`unwrap`・`panic` などを禁じる）には、合わせていません。テストでないコードに、添字で読む所が 30 か所あります。`unsafe`・`unwrap`・`expect`・`panic!` はありません。入力でパニックしないことは、確かめていません（fuzz を流していません）。
- 公開サンプルにある 6 種類の要素は 98 件で、ほかのアプリケーションが書いた図面での幅は狭いままです。属性の付いた INSERT は、公開サンプルの 3 個（`zumen-minsert-*`）に、2 つずつあるだけです。
- 文書エンジンが中に持つ形・表示のバッファー・範囲で選ぶ結果を、今の実装のシーンや `entities` の結果と照らすこと。INSERT は、定義の中身を挿入ごとに置いた結果を作っていないので、描いた結果は確かめていません。
- 要素を置き換える変更、表の変更、属性を持つ記号を足す変更、ペーパー空間の要素。範囲の外にした 5 つの理由の変更も、通していません。
- DWG。
- 診断・予算・中断・ハッシュを入れたときの時間と、wasm での結果と時間。
- 測ったときに、同じ端末でほかの仕事が動いていなかったことは、確かめていません。マイクロ秒の値は、端末の様子で変わります。

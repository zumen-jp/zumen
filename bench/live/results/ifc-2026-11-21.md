# IFC の壁の属性編集と依存先の測定（2026-11-21）

公開 IFC 3 件と各階 100 枚の壁を持つ自作 IFC4 で、建物の属性を持ち続ける `IfcLive` を検証しました。壁 1 枚の説明を変え、従来の `zumen_ifc::apply` と変更件数・診断・保存した全バイトを比較しています。編集・取り消し・やり直しの各段で、保持する属性モデル全体と変換診断（種類・値・件数・場所・順序）を、保存した SPF の再読と照合しました。建物を起点とする影響先の順序も、編集・やり直しでは再読した文書エンジン、取り消しでは初期状態と一致しました。

## 時間

Windows x64、Ryzen 5 3600XT、Rust 1.99.1 の release ビルドを使いました。Rust から直接呼び、各条件で 3 回、新しいプロセスを起動した中央値です。単位はミリ秒です。「スレッド」は開くときにページの圧縮へ渡した本数です。「逐次」は事前に読み込んだファイルモデルに同じ変更を当て、書き戻したバイト列を返すまでを含みます。「常駐」は確定のみで、変更後の全バイト列を得る時間は「保存」に示します。「依存先」は建物から影響先を列挙する時間です。各操作の計時から結果の照合を除いています。

通常の `IfcLive::building` が保持するのは属性の建物モデルです。形状と表示を含む取得、構造を置き直す変更、GPU 表示はこの表の計測範囲外です。自作 IFC の壁には階への所属、個別の配置と形状表現があり、押し出し形状の定義は共有します。

## 形状と表示を保持する場合

同じ 5 入力を `IfcLive::open_with_geometry` で開き、属性だけの計測と同じ壁に形状があることを確かめて説明を変えました。編集・取り消し・やり直しの各段階で、形状と表示を含む建物モデル全体、診断の順序と場所、保存した全バイトを逐次の読み書きに照らしました。建物を起点とする影響先の件数は上表と同じで、列挙順も開き直した結果と一致しました。

## 再現

リポジトリの直下で次を実行します。生成先とビルド先は手元の作業用フォルダーに変更できます。

```sh
python bench/live/ifc-walls.py target/ifc-live-inputs
cargo build --release --locked --manifest-path bench/live/Cargo.toml --bin ifc-live --target-dir target/bench-live-ifc
target/bench-live-ifc/release/ifc-live samples/ifc/bim-whale/LargeBuilding.ifc 1
target/bench-live-ifc/release/ifc-live target/ifc-live-inputs/10000-wall.ifc 4
target/bench-live-ifc/release/ifc-live target/ifc-live-inputs/10000-wall.ifc 4 --geometry
```

各入力に 1 と 4 を指定し、属性だけの表は各 3 回、形状を保持する表は `--geometry` を付けて各 1 回測ります。各プロセスは既定の予算で実行し、すべての照合に通ると件数・時間（ナノ秒）・予算の使用量（バイト）を TSV で出力します。

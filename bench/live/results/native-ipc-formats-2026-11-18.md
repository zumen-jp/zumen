# 常駐 IPC の往復を JWW・SFC・DWG・P21 で測る（2026-11-18）

[2026-11-16 の測定](native-ipc-2026-11-16.md)は合成 DXF だけでした。同じ `zumen live --stdio` と Node.js 接続で、JWW・SFC・DWG・P21 を開いて測りました。移動と差分反映の中央値は 102.2〜186.7 µs で、1 ms を超えたのは全 18,000 回のうち 4 回です。

## 対象と手順

- 実行入口: [`60bcc12c`](https://github.com/zumen-jp/zumen/commit/60bcc12caab6841c26a0f77d97d9f419a177ae52)。測定器は [`native-ipc.mjs`](../native-ipc.mjs) で、要素数の代わりに入力のファイルを渡しました。
- Windows x64、AMD Ryzen 5 3600XT、Rust 1.99.1 MSVC、ワークスペースの release ビルド、Node.js 24.22.2。開くときのスレッド数は 1 です。
- 入力は `bench/editor/prepare.mjs` で作りました。公開 DWG と適合テストの合成 JWW・SFC・P21 に、`apply` の `add` で要素を足した図面です。出所は[今の実装の測り](../../editor/README.md)と同じです。
- 描く順（`order`）の行を固定の整数列で混ぜた順に試し、移動を受けた行を 1,000 行まで対象にしました。今回の入力では、断られた行はありません。
- 各入力で 100 回の慣らし後、1,000 回ずつ、行の ID とハッシュの取得、1 要素の移動、取り消しを直列に行いました。時間に含めるものは 2026-11-16 と同じです。

```sh
cargo build -p zumen-abi --release --target wasm32-unknown-unknown --locked --no-default-features --features drawing
node bench/editor/prepare.mjs target/wasm32-unknown-unknown/release/zumen_abi1.wasm target/bench-editor
cargo build -p zumen-cli --release --locked
node --expose-gc bench/live/native-ipc.mjs target/release/zumen target/bench-editor/jww-100k.jww 1000 1
```

## 等価の確認と残件

慣らしを含む全移動をそれぞれ取り消した後の全体保存を、開いた直後の保存と全バイトで照合しました。開いた直後の保存は、6 入力とも入力と同じバイト列でした。受信側の全 13 列も、初期パケットの全バイトと照合しました。6 入力すべてで一致しています。

この測定は 1 スレッドだけで、移動以外の編集、空間索引での選択、Electron の描画を含みません。SFC・P21 の常駐メモリの内訳は調べていません。全回 1 ms 以内という条件は、どの入力でも満たしていません。超えた回は散発で、中央値・p99 からは離れています。

# 2D シーンの塊の測定

同じ図面モデルに塊の設定を変えて渡し、シーン生成の時間・大きさ・線分の座標精度を比較します。計測器はコアの workspace と公開パッケージの外に置いています。

## 2D シーンの既定値

描くものの件数上限に 4,096 個、塊の幅・高さの目安に表示の許容差の 65,536 倍を採用しました。測定表の `provisional` がこの設定です。次の図形を加えるとどちらかの上限を超えるとき、次の塊に移ります。単独で範囲を超える図形も 1 個の塊に収めます。

- 件数上限を 1,024・4,096・16,384 にすると、密な線分 1 万本では順に 10・3・1 塊になります。静岡市の DXF では、2 図郭のシーンが 3 設定で全バイト一致し、残る図郭でも 1,024 に下げたときに 1 塊増えました。4,096 なら密な入力で 1 塊に集める件数を抑えながら、これらの実図面に余分な塊を作らずに済みます。[合成入力](RESULTS.md)・[DXF の生成と範囲選択](WEBGPU-RESULTS.md)
- 範囲の倍率を 16,384 に下げると、神戸市の JWW 4 枚で塊の数が約 7〜11 倍になり、松浦市の SFC 図郭 2 では 45 から 1,242 に増えました。262,144 に上げると、ストラスブールの DWG で 1,756,216 バイト減る一方、実線の端点を復元したときの最大誤差は 0.03043 mm から 0.12203 mm に増えました。65,536 を維持し、用紙での細分化と広域図での座標誤差を抑えます。[JWW](JWW-RESULTS.md)・[SFC](SFC-RESULTS.md)・[DWG](DWG-RESULTS.md)

GeForce RTX 4070 で松浦市の 2 図郭を用紙・実寸の全図で描き、各 2 回の画素を照合しました。GPU プロセスの専用メモリの標本最大は 322〜956 MiB です。別機種の描画時間・メモリは未測定です。[GPU メモリと再現手順](SFC-RESULTS.md)

## 再現する手順

リポジトリのルートで、固定した Rust と Node.js 22 以降を使います。`wasm32-unknown-unknown` が必要です。

```powershell
cargo run --manifest-path bench/chunks/Cargo.toml --bin measure --release --locked -- bench/chunks/out 7
cargo build --manifest-path bench/chunks/Cargo.toml --lib --target wasm32-unknown-unknown --release --locked
node bench/chunks/run.mjs bench/chunks/out bench/chunks/target/wasm32-unknown-unknown/release/zumen_bench_chunks.wasm 7
```

`out/results.json` に機械とツールのバージョン、入力のサイズ・SHA-256、各設定の中央値と検査結果を書きます。入力はコードに名指しした公開サンプルか、実行時に生成した DXF だけです。外部のファイルや環境変数から図面を探しません。公開入力のハッシュとサイズは `samples/ledger.toml` と照合します。出所・再配布の条件はその台帳にあります。生成したシーンのバイト列も `out/` に置き、ネイティブと wasm で全バイトを比較します。`out/` は Git に入れません。

末尾の反復回数は両方とも省略時に 7 回で、3〜99 の奇数だけを受け付けます。ネイティブの `out/native.json` に反復回数とウォームアップ回数を保存し、wasm 側の指定と違えば測る前に停止します。結果の `native_repeats` と `wasm_repeats` に両方の回数を残します。

release のネイティブを作ったあと、`node bench/chunks/test.mjs` で入口の回帰を検査できます。偶数を両入口が断ること、ネイティブが指定した 3 回を記録すること、wasm 側に 7 回を指定すると食い違いとして断ることを確認します。

## 測るもの

- L1 の読み取り、図面モデルへの lift、比較元の線分の収集は準備段階です。時間に含めません。
- 許容差は実寸の空間の 0.01 単位、起点は実寸の空間、表示用の設定です。フォントは渡さず、範囲では絞りません。許容差の単位は各図面の実寸の単位です。
- 1 回ウォームアップし、7 回のシーン生成の中央値を取ります。ネイティブは `Instant`、wasm は Node.js の `performance.now()` を使います。予算・診断は各回で作り直します。シーン生成と診断の code・件数の集計を時間に含め、入力の準備、結果の比較、ファイルの読み書きは含めません。
- 描くもの 4,096 個・許容差の 65,536 倍を基準に、件数だけを 1,024・16,384 個、範囲だけを 16,384・262,144 倍に変えて比較します。各設定を測定用の `Options` に渡します。
- 合成入力は線分 1 万本と 10 万本です。メートルを宣言し、原点 (100000, 50000) の近くに、小数の端点を持つ線分を格子状に並べます。1 万本は幅が約 1 m の狭い範囲に置いて件数上限を、10 万本は約 1 km 四方に置いて範囲上限を比較します。実物の図面の代わりには数えません。

## 結果の検査

`walked` は部品を含めて配置をたどった数、`entities` はシーンの要素の行数です。塊・線・頂点などの数と、シーン全体のバイト数を記録します。

設定を変えても、要素の ID・種類・配置の道筋、描く単位の表、文字列、種類ごとの描く単位の順が同じことを列の全バイトで比較します。塊の順と、塊内の描く単位の順を組み合わせた順序も比較します。すべてのシーンの ID が入力の走査にあることも検査します。`identity_order_fnv1a` は比較対象の要約です。設定が違えば塊の数や座標の量子化が変わるため、シーン全体のバイト列は同じとは限りません。同じ設定の繰り返しとネイティブ・wasm の間では、シーン全体のバイト列と検査結果が一致することを確かめます。

座標精度は、表示する実線の線分を対象にします。線の ID と配置の道筋から元の f64 の端点を引き、配置のアフィン変換を当てた点と比較します。塊の f64 の原点に f32 の相対座標を戻した点との差を軸ごとに記録します。対象の線がすべて出力にあること、最大誤差が許容差を超えないことも検査します。`checked_lines` に対象の本数を示し、対象がない場合の誤差は `null` にします。曲線の分割、破線への展開、文字と字形の精度は、この値には含めません。

## 実図面の測定

静岡市の公開 DXF 3 図郭では、既定の許容差と 0.01 m のシーンを比較し、Windows の CLI が図面を開いてからシーンを作るまでの最大ワーキングセットを測りました。[図郭別の結果と手順](WORKING-SET.md)

ブラウザーの描画・範囲選択・転送・保持メモリは[消費側の手順](CONSUMERS.md)と [WebGPU での実測](WEBGPU-RESULTS.md)にあります。松浦市の実 SFC 2 図郭では[用紙ビューと実寸の空間](SFC-RESULTS.md)を照合しました。[神戸市の実 JWW](JWW-RESULTS.md) は 4 枚の用紙と実寸空間、[ストラスブールの DWG](DWG-RESULTS.md) は R2000 で別名保存したモデル空間を照合しました。

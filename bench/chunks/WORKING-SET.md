# 静岡市の都市計画基本図で測った許容差とメモリ

静岡市の公開 DXF の 3 図郭を、Windows のネイティブ CLI で開きました。各図郭について、`scene` の許容差を省いた場合と 0.01 m を指定した場合を各 3 回、新しいプロセスで測りました。全 18 回で、シーンが返るまでの最大ワーキングセットに達したのは図面モデルの変換と要約（`drawing`）でした。続くシーン生成（`scene`）はその最大値を更新しませんでした。[反復ごとのバイト数・診断・SHA-256](working-set-2026-11-21.json)

## 許容差とシーン

実寸の空間 `space/0`、フォント指定なし、表示用の仮設定（件数上限 4,096、範囲上限は許容差の 65,536 倍）を使いました。実寸の空間で許容差を省くと、コアは描画範囲の対角線を 50,000 で割ります。表の既定値は `scene` の応答を丸めたものです。

| 図郭 | 許容差（メートル） | 塊 | 頂点 | シーン（バイト） |
| --- | ---: | ---: | ---: | ---: |
| 最小 | 既定 0.0500061 | 5 | 123,745 | 2,172,144 |
| 最小 | 0.01 | 2,661 | 147,082 | 2,496,952 |
| 元の頂点数最多 | 既定 0.0500043 | 4 | 128,483 | 1,888,280 |
| 元の頂点数最多 | 0.01 | 1,205 | 136,443 | 2,014,432 |
| 最大 | 既定 0.0500184 | 6 | 122,439 | 2,503,656 |
| 最大 | 0.01 | 1,567 | 146,446 | 2,776,904 |

各条件の 3 回でシーンの SHA-256 が一致しました。既定時は以前の Node.js Worker の wasm 出力、0.01 m のときは以前の仮設定の生成結果とも一致しました。図郭ごとの非平面要素などの診断件数は結果の JSON にあります。[既存の比較値](webgpu-results-2026-11-21.json)

## ネイティブプロセスの最大メモリ

単位は MiB、値は同じ図郭・許容差を使った 3 回の中央値です。`open`・`drawing`・`scene` の累積最大は、Windows がその要求の応答までに記録した `PeakWorkingSet64` です。右端は `scene` を送る直前から応答まで `WorkingSet64` を繰り返し読んだ観測最大です。応答を待つ間は 5 ms ごとに調べます。スケジューリングと計測間隔の間に生じた短いピークは右端に現れないことがあります。

| 図郭 | 許容差（メートル） | open までの累積最大 | drawing までの累積最大 | scene までの累積最大 | scene 区間の観測最大 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 最小 | 既定 | 55.3 | 98.1 | 98.1 | 77.7 |
| 最小 | 0.01 | 55.4 | 98.0 | 98.0 | 77.2 |
| 元の頂点数最多 | 既定 | 139.0 | 204.9 | 204.9 | 158.2 |
| 元の頂点数最多 | 0.01 | 138.2 | 204.1 | 204.1 | 152.3 |
| 最大 | 既定 | 315.1 | 510.8 | 510.8 | 354.8 |
| 最大 | 0.01 | 315.2 | 510.7 | 510.7 | 354.8 |

CLI は同じセッションで、パスを渡す `push`、DXF を読む `open`、初めて図面モデルを必要とする `drawing`、モデルからシーンを作る `scene` を順に実行しました。シーンのバイト列を取り出す `take` は、メモリを記録したあとで実行しました。数値には CLI 本体と保持中の入力・モデルが含まれます。モデル単体のヒープ、GPU・ブラウザー・wasm の最大メモリはこの表の対象外です。[別に測ったモデルのヒープ](https://github.com/zumen-jp/zumen/issues/559#issuecomment-6982336747)

## 再現手順

2026-11-21、Windows 10.0.26300 x64、AMD Ryzen 5 3600XT（6 コア・12 論理 CPU）、PowerShell 7.6.9、Rust 1.99.1 で、`e339b28e` の release ビルドを使いました。計測用 PowerShell のメモリは計上しません。単一環境での観測です。

1. 静岡市の都市計画基本図（1/2,500、ND68-1〜ND79-2）の ZIP をリポジトリ外に取得します。ZIP の SHA-256 は `70471ce945a05a1fe53f5e56383a11e9cb96c33946e7d23c966b867650b4d24b` です。[原本の配布記録](https://data.e-gov.go.jp/data/ja/dataset/3fd092fb-a5da-431f-92e7-e4a0e0bce776/resource/7451e919-ec65-48a0-9c50-2e34c086734b)・[利用上の注意](https://www.city.shizuoka.lg.jp/documents/51396/tyuuizikou.pdf)
2. ZIP 内の DXF を格納順に 0 から数え、7・8・19 番目をリポジトリ外に展開します。以下の例では `sheet-07.dxf`・`sheet-08.dxf`・`sheet-19.dxf` と呼びます。計測スクリプトは既存の結果にある SHA-256 で原本を識別します。
3. リポジトリのルートで次を実行します。各回のメモリ使用量は実行環境によって変わります。

```powershell
cargo build --locked -p zumen-cli --release
$files = @('C:/samples/sheet-07.dxf', 'C:/samples/sheet-08.dxf', 'C:/samples/sheet-19.dxf')
./bench/chunks/measure-working-set.ps1 -Executable target/release/zumen.exe -Inputs $files -Repeats 3
```

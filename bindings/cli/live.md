# 文書エンジンの子プロセス IPC

`zumen live --stdio` は、1 つの文書エンジン（DXF・DWG は `AcadLive`、JWW は `JwwLive`、SXF の SFC・P21 は `SxfLive`）を子プロセス内に保持します。形式は Open のバイト列の署名で選びます。入力、表示の列、表示の画層の表、描く順、矩形による選択、行を指定する移動・削除・複写・スタイルの変更、取り消し・やり直し、全体保存、現在の ID とハッシュ、診断を運びます。64 bit ネイティブの実行ファイルを Electron の main から使う入口です。Node.js の接続は `@zumen-jp/zumen/node` の `openLiveProcess` です。

この入口は既存の `Session` の JSON op を追加・変更しません。IFC、文字列・記号の定義の同期、線種の変更・置き換え・追加などの編集、Electron の表示への組み込みは残件です。13 列だけで全図形を表示できるとはしていません。性能目標も測定結果と分けて扱います（[文書エンジン](../../docs/live.md)）。WASI は実行入口の対象外です。状態処理と符号化の単体検査は WASI でも流します。

## 通信と上限

数値はすべて little endian です。要求は通常 1 つずつ送り、応答をすべて読んでから次を送ります。要求番号は 0 以外の `u64` で、通常要求ごとに増やします。中断だけは、実行中の要求と同じ番号で送れます。入力の終端、枠の破損、通常要求の重複、出力の切断では接続を終了します。

受信バッファーはコマンド別の通信上限で、操作の `Cx` とは別に制限します。ヘッダーを検査してから確保し、枠を最後まで受信した後に文書を処理します。入力ファイルは最大 256 MiB、移動は最大 65,536 行です。入力は複製せずコアへ貸します。呼び出し元は通信にも期限を設けます。

文書の処理は、要求に指定された 7 種の予算と中断を持つ 1 つの `Cx` を共有します。入れ子の処理で予算を作り直しません。入口の作業量 1、要求ヘッダーと本文の入力バイト数、固定の作業領域 256 バイトも計上します。開くときのファイル本体はコアで入力バイト数へ計上し、入口と二重に数えません。操作が予算で停止しても、常駐文書と接続を保持して応答します。

応答の本文は最大 1 GiB + 136 バイトです。表示パケットと反映後の表示全列にはそれぞれ 1 GiB、診断の符号化前の見積もりには 16 MiB の上限を設けます。コアの確保にも要求の予算を適用します。Node.js は本文の通信上限を既定で 256 MiB + 136 バイトにし、`maxMessageBytes` で変えられます。応答のヘッダーを検査してから本文を確保します。

Node.js の要求期限は既定 30 秒です。`cancel()` は実行中の要求へ中断を送り、1 秒以内に応答がなければ子を終了します。期限切れや通信の故障で `broken` になった接続は再利用しません。`close()` は処理中の要求を失敗にし、子の終了を待ちます。実行ファイルの道筋は利用者が渡し、シェルを介さず、子の標準エラーを接続のログへ出しません。

## 枠とコマンド

要求のヘッダーは 24 バイトです。応答は magic を `ZLIR` に替え、コマンド・要求番号・フラグをそのまま返します。長さはヘッダーを含みません。

| 位置 | 型 | 内容 |
| --- | --- | --- |
| 0 | 4 バイト | 要求は `ZLIP`、応答は `ZLIR` |
| 4 | u16 | 版 1 |
| 6 | u16 | コマンド |
| 8 | u64 | 要求番号 |
| 16 | u32 | 本文のバイト数 |
| 20 | u32 | フラグ。bit 0 は表示を付ける、bit 1 は全体表示 |

全体表示には bit 0 も必要です。フラグを指定できるのは Open・Display・Transform・Remove・Restyle・SetText・Undo・Redo です。予約ビットと予約値は 0 でなければなりません。

Cancel・Close を除く本文は、次の 72 バイトで始まります。

| 位置 | 型 | 内容 |
| --- | --- | --- |
| 0 | u64 × 7 | inputBytes・decodedBytes・records・elements・depth・segments・work の上限 |
| 56 | u64 | 要求が前提にする文書の版 |
| 64 | u64 | 適用済みの表示の版 |

`u64::MAX` は、予算では明示した上限なし、版では指定なしを表します。通常の数値としては使いません。Node.js で予算の単位を省略するとコアの既定値、`null` を渡すと上限なしです。u64 の値は `bigint` で返し、入力には安全な整数の `number` も受けます。

| 番号 | コマンド | 72 バイトの後の内容 |
| --- | --- | --- |
| 0 | Cancel | 本文なし。対象の要求番号を使い、応答は返さない |
| 1 | Open | スレッド数 u32（1〜64）、予約 u32、ファイルのバイト列 |
| 2 | Display | なし。フラグが 0 でも表示を返す |
| 3 | Transform | 行数 u32、予約 u32、変換行列 f64 × 6、行番号 u32 × 行数 |
| 4 | Undo | なし |
| 5 | Redo | なし |
| 6 | Save | なし |
| 7 | Target | 行番号 u32 |
| 8 | Diagnostics | 診断の元の要求番号 u64 |
| 9 | Close | 本文なし。応答して終了する |
| 10 | Select | モデル空間の矩形 `[min_x,min_y,max_x,max_y]`、f64 × 4 |
| 11 | Layers | なし |
| 12 | Order | なし |
| 13 | Remove | 行数 u32、予約 u32、行番号 u32 × 行数 |
| 14 | Copy | 行数 u32、予約 u32、変換行列 f64 × 6、行番号 u32 × 行数 |
| 15 | Restyle | 行数 u32、スタイル 44 バイト（線種を変えれば 52 バイト）、行番号 u32 × 行数 |
| 16 | LineTypes | なし |
| 17 | Texts | 行数 u32、予約 u32、行番号 u32 × 行数 |
| 18 | SetText | 行数 u32、内容のバイト数 u32（1 MiB まで）、4 バイト境界まで 0 で埋めた UTF-8 の内容、行番号 u32 × 行数 |
| 19 | Symbols | 定義の数 u32（65,536 まで）、予約 u32、定義の番号 u32 × 定義の数 |
| 20 | Draw | 雛形の行番号 u32、形の種類 u32、値 f64 × 5 |

Open の前提の版・表示の確認は指定なしにします。一度文書を開いた子は別の文書を開きません。開く処理自体が失敗した場合は再試行できます。Diagnostics の表示の確認は指定なしにし、前提の版は使いません。

Transform の `[a,b,c,d,e,f]` は、既存の `apply` と同じく `(x,y)` を `(a*x+b*y+c,d*x+e*y+f)` に写します。すべての行から現在の `Seen` を取得して、既存の `Changes` の 1 トランザクションとして適用します。範囲外や削除済みの行、前提の版が違う要求は、編集を始めずに断ります。表示と選択の座標は、DXF・DWG ではモデル空間、JWW・SXF では用紙の座標です。JWW・SXF の行列は表示の座標で受け、行ごとに空間の座標から用紙への変換 `S` で `S⁻¹·T·S` に直してから当てます。SXF の実寸の空間の要素で、空間を置いたビューがないか 2 つ以上あるものは、用紙の座標が 1 つに決まらないので、`change.edit.unsupported` を診断して rejected を返し、何も変えません。Remove は行を除き、Copy は行を写して写しを変換で動かします。どちらも Transform と同じく、すべての行から現在の `Seen` を取得して 1 トランザクションで当て、範囲外や削除済みの行、前提の版が違う要求は編集を始めずに断ります。Copy の行列も表示の座標で受けます。Copy は写しの行を、当てる前の表の末尾から対象の順に、データの種類 5 で返します。表示のフラグは受けないので、表示は Display で取り直します。写せる要素と値は既存の `apply` の `copy` と同じで、JWW・SXF の文書エンジンは `change.edit.unsupported` を診断して rejected を返します。Restyle は行の画層・色・線幅・線種・線種の倍率のうち、指定したものだけを変えます。スタイルは、変える項目 u32（bit 0 画層、bit 1 色、bit 2 線幅、bit 3 線種の倍率、bit 4 線種）、画層 u32、色の種類 u32・色のフラグ u32・色番号 u32・RGB u32、線幅の種類 u32、線幅 f64、線種の倍率 f64 の順です。bit 4 を立てたときだけ、続けて線種の種類 u32・線種 u32 を置きます。画層は Layers の表の値で指し、表にない値は invalid です。色の種類は 0 画層・1 ブロック・2 自分の値で、自分の値はフラグの bit 0 で色番号、bit 1 で RGB を持ちます。色番号と RGB の符号化は Layers の表と同じです。線幅の種類は 0 画層・1 ブロック・2 用紙の上の幅（mm）・3 文書の既定です。線種の倍率は正の数です。線種の種類は 0 画層・1 ブロック・2 自分の値で、自分の値は LineTypes の表の値で指し、表にない値は invalid です。変えない項目の値と予約ビットは 0 にし、変える項目がない本文は invalid です。形式に書けない値（R2004 より前の DXF の RGB など）は既存の `apply` の `restyle` と同じ診断で rejected です。版と行の意味を守るため、Node.js の `transform`・`restyle`・`remove`・`copy`・`target`・`select`・`layers`・`lineTypes`・`texts`・`setText`・`symbols`・`draw`・`undo`・`redo` には版を明示します。

Select は、モデル空間の最上位要素の囲む箱と矩形が接触・交差する生存行を昇順で返します。形状そのものとの交差や画層の表示状態による除外は行いません。無限大は全域指定に使え、NaN・逆転した矩形は空の結果です。空間索引の走査・結果の確保・整列・生存判定・通信へのコピーを同じ予算で検査します。停止時に部分結果は返さず、文書の版・内容を保ちます。受領確認はほかの通常要求と同じく独立して処理します。

## 応答

本文は 136 バイトの固定フィールドと、その後のデータです。

| 位置 | 型 | 内容 |
| --- | --- | --- |
| 0・4 | u32 | 操作の状態・表示取得の状態 |
| 8・16 | u64 | 現在の版・履歴の状態番号。文書がなければ指定なし |
| 24 | u64 | 操作の結果 |
| 32 | u64 | 差分が前提にする確認済みの版。全体表示・表示なしは指定なし |
| 40・44 | u32 | データの種類・通常の要求で報告した診断数。Diagnostics 成功時は取得元の件数 |
| 48・52 | u32 | データのバイト数・予約 |
| 56 | u64 × 7 | 7 種の予算使用量 |
| 112 | u32 | 停止なし 0、予算の種類 1〜7、中断 8、期限 9 |
| 116・124 | u64 | 超えた予算の上限・要求量。予算超過以外は 0 |
| 132 | u32 | 予約 |

状態は順に、0 ok・1 invalid・2 unsupported・3 stale・4 missing・5 rejected・6 exceeded・7 cancelled・8 timedOut・9 noDocument・10 alreadyOpen・11 noDiagnostics です。Node.js ではこれらの名前を返します。コアの失敗は例外にせず状態で返し、通信の失敗は `ProcessError`、通常要求の重複は `ZumenError` の `busy` にします。

Diagnostics の取得に失敗した場合、応答の診断数は 0 です。保持元の診断は変更せず、取得を再試行できます。

結果は Open では生存行数、Transform・Remove・Copy・Restyle・SetText では適用件数、Undo・Redo では変更したか（0 または 1）、Save ではバイト数、Target と missing では行番号、Diagnostics では元の要求番号、Select では選択行数、Layers では画層の数、Order では行の数、LineTypes では線種の数、Texts では行の数です。それ以外は 0 です。

データの種類は、0 なし、1 [ZLDP](../../docs/live.md#表示差分の通信)、2 保存バイト列、3 編集対象、4 診断、5 選択行（Copy では写しの行）、6 画層の表、7 描く順、8 線種の表、9 行の文字、10 記号の定義です。編集対象は ID のバイト数 u32、ハッシュの 16 バイト、UTF-8 の ID の順です。ハッシュは既存の `v2:` の 16 進表記に対応します。診断は UTF-8 の JSON 配列で、code・severity・fidelity・count・params・places・spec を元の順序と値で返します。Node.js は診断を自動で JSON の数値へ変換せず、元のバイト列を返します。

選択行のデータは、件数 u32、行番号 u32 × 件数です。件数は結果フィールドと同じで、行番号は重複のない昇順、仮想ノードを除く `0..0x80000000` です。空でも件数の 4 バイトを返します。Node.js は長さ・件数・全行の順序を検査してから、`reply.selection.length` と `reply.selection.rows()` を公開します。行は応答バイト列を借り、追加の配列を作りません。編集には応答の `revision` とともに渡します。

Layers は、表示の列のスタイル `[画層, 色]` の 1 つ目の値を、画層の名前・状態・色に引く表を返します。値は、DXF・DWG では画層の表の位置、JWW・SXF では図面モデルの画層の ID です。並びは図面モデルの `layers` と同じで、値は重複しません。表示の行が使う画層の値は、どれも表に載ります。前提の版が違えば stale を返し、表を返しません。データは件数 u32 と、画層ごとの値・フラグ・RGB・色番号・名前のバイト数（各 u32）、UTF-8 の名前を 4 バイト境界まで 0 で埋めたものです。フラグは、bit 0 が状態あり、bit 1〜4 が表示・印刷・編集・凍結、bit 5 が RGB あり、bit 6 が色番号あり、bit 7 が配置に従う画層です。RGB は `0x00RRGGBB`、色番号は上位 8 bit に体系（1 ACI・2 SXF・3 JWW）、下位 24 bit に番号です。持たない値は 0 にします。作る前に、名前と説明のバイト数と画層の数を要求の予算で数えます。Node.js は全件の長さ・フラグ・埋め草・UTF-8 を検査してから、凍結した `reply.layers` を公開します。

Order は、表示に出る生きた行を、先に描くものから並べて返します。規則は図面モデルの描く順と同じです。DXF・DWG はモデル空間の SORTENTSTABLE のキー（なければハンドル）の昇順で、同じキーは行の順です。ハンドルのない行があれば行の順にします。JWW は記録の順（追加した行は元の記録の後ろ、定義の空間の前）を画層グループの順に安定に並べ、ブロックの定義の中の行は返しません。SXF は用紙の順に従い、用紙の要素はその位置で、ビューはその空間のモデル要素を最初に置いた位置で返し、追加した行は元の挿入位置に置きます。データは件数 u32 と行 u32 の並びで、行は重複しません。前提の版が違えば stale を返し、並びを返しません。作る前に、行の走査・並べ替えの作業と並べる領域を要求の予算で数えます。Node.js は件数・長さ・重複・仮想ノードの混入を検査してから、凍結した `reply.order` を公開します。

LineTypes は、Restyle の線種で指せる線種の表を返します。値は図面モデルの `LineTypeId` で、重複しません。DXF・DWG は図面モデルの `line_types` と同じ順・同じ値です。JWW は実線と破線（1〜9）、ランダム線と倍長線（11〜19）、SXF の線種を持つ版では定義のある SXF の線種（30〜62）の番号です。SXF は既定の線種（1〜15）と、文書が定義する利用者定義の線種です。前提の版が違えば stale を返し、表を返しません。データは件数 u32 と、線種ごとの値・フラグ・名前のバイト数・説明のバイト数・列の数（各 u32）、4 バイト境界まで 0 で埋めた UTF-8 の名前と説明、f64 の線と間の列です。フラグは、bit 0 が定義あり、bit 1 が用紙の mm の列（なければ要素の空間の長さ）、bit 2 が形か文字の添え物ありです。定義がなければフラグ・説明・列は 0 です。添え物の中身は運びません。作る前に、線種の数と、名前・説明・列のバイト数を要求の予算で数えます。Node.js は全件の長さ・フラグ・埋め草・UTF-8 を検査してから、凍結した `reply.lineTypes` を公開します。

Texts は、行の文字を要求の順に返します。種類は 0 が文字でない行、1 が文字（DXF・DWG の TEXT、JWW の文字、SXF の文字要素など図面モデルの `Shape::Text`）、2 が書式つきの文字（MTEXT など `Shape::Formatted`）です。内容は図面モデルの `content` を、制御文字や書式の符号を含めて元のまま返します。文字でない行の内容は空です。属性・寸法・表の中の文字は返しません。範囲外や削除済みの行があれば missing と行番号を、前提の版が違えば stale を返し、文字を返しません。データは件数 u32 と、行ごとの種類 u32・内容のバイト数 u32・4 バイト境界まで 0 で埋めた UTF-8 の内容です。行ごとの作業と内容のバイト数を要求の予算で数えます。Node.js は全件の種類・長さ・埋め草・UTF-8 を検査してから、凍結した `reply.texts` を公開します。

Symbols は、記号の定義の表示を要求の順に返します。表示の挿入の定義の値（ZLDP の列 10 の 1 語目）は、この定義の番号です。データは、文書の定義の数 u32、要求した定義の数 u32、定義ごとの先頭の行 u32 と行の数 u32、続けて全量の ZLDP です。ZLDP には、要求した定義の要素を、要求の順に 1 要素 1 行で、定義の座標のまま並べます。各定義の行は、前の定義の行に隙間なく続きます。行のスタイルは文書の表示と同じ画層の値と色で、入れ子の挿入は挿入のまま書くので、その定義はもう一度 Symbols で引きます。定義を求めない要求は、定義の数だけを返します。範囲外の番号があれば invalid です。DXF・DWG はブロックの定義を、JWW は記号の定義を、SXF は複合図形の定義を返します。JWW の定義の座標は、用紙の縮尺を掛けない定義の空間の座標です。定義の版は文書の版と同じで、表示の差分には定義の変更を含めません。Node.js は全件の行の並びとパケットを検査してから、凍結した `reply.symbols` を公開します。

SetText は、文字の行の内容を同じ 1 つの内容に替えます。各行の要素を、内容だけを替えた値で既存の `apply` の `replace` と同じく置き換え、すべての行を 1 トランザクションで当てます。替えられるのは `Shape::Text` の行と、区間が文字列 1 つだけの `Shape::Formatted` の行（区間の中身も替えます）です。ほかの行（文字でない行や、区間が書式・段落の区切りを持つ MTEXT など）を含めば、`change.edit.unsupported`（`edit` は `text`）を診断して rejected を返し、何も変えません。内容は解釈せずにそのまま書くので、形式の符号（MTEXT の書式など）は形式の規則に従います。形式の文字コードで書けない文字は、既存の `replace` と同じ診断で rejected です。範囲外や削除済みの行、前提の版が違う要求は、編集を始めずに断ります。JWW は、公開サンプルに文字がないので、試験で組み立てた文字を持つ JWW で確かめています。

Draw は、雛形の行と同じ空間か用紙に、その画層とスタイルで線分・円・円弧を 1 つ足します。形の種類は 1 が線分 `[x0,y0,x1,y1,0]`、2 が円 `[x,y,r,0,0]`、3 が反時計回りの円弧 `[x,y,r,始まりの角度,終わりの角度]`（度）です。値はどれも有限で、使わない値は 0、半径は正です。ほかは invalid です。値は表示の座標で受け、Transform と同じく行の空間の座標から用紙への変換 `S` の逆で行の座標に写します。円・円弧は、`S` が軸に沿った正の一様な拡大縮小と平行移動のときだけ受け、半径を同じ比で直します。写せなければ `change.edit.unsupported`（`edit` は `add`、`kind` は `view`）を診断して rejected です。記号の定義の中の行は雛形にならず、`kind` が `place` の同じ診断で rejected です。足す要素は既存の `apply` の `add` と同じく 1 トランザクションで当て、足した行を当てる前の表の末尾から、データの種類 5 で返します。表示のフラグは受けないので、表示は Display で取り直します。範囲外や削除済みの行、前提の版が違う要求は、編集を始めずに断ります。

表示のスタイルの 2 つ目の値（色）は、どの形式も同じ読み方です。上位 8 bit が 0 で画層の色（または指定なし）、1 でブロックの色、2 で色番号、3 で下位 24 bit の RGB（`0xRRGGBB`）です。色番号は、bit 16〜23 に体系（1 ACI・2 SXF・3 JWW。Layers の表と同じ値）、下位 16 bit に番号を置きます。RGB も持つ色（JWW のペンなど）は RGB を運びます。番号が 16 bit に収まらない色は、画層の色として運びます。定義は `zumen-live` の `display::color` です。

編集確定と表示取得は別の成否です。編集が成功した後で表示生成が予算停止した場合、操作は ok、新しい版と表示の停止理由を返します。編集は取り消しません。表示を別要求で取得するか、返った版を指定して undo します。

## 差分の受領確認と診断の寿命

送信しただけでは表示の変更フラグを消しません。受信側はパケット全体を検証し、全列の長さと塊を反映してから、その版を確認します。Node.js では `acknowledge(reply.revision)` で記録し、次の要求に確認を付けます。差分を反映できるのは、手元の表示の版が応答の `base` と同じ場合です。違う場合は `display({ full: true })` で全体を取り直します。

子プロセスは、最後に表示を送った版と現在の版がどちらも確認の版と同じ場合だけ、表示の変更フラグを消します。古い確認で後の編集を消すことはありません。確認がない間は、前の確認済みの版からの差分を繰り返して取得できます。一度も確認していない場合は全体表示です。

受領確認は、すでに適用した表示への独立した操作です。前提の版を確かめた後、編集前に処理するため、編集が後で失敗しても有効な確認は保持します。文書の編集の原子性は、それぞれの文書エンジンの `apply` に従います。

診断は最後の通常要求の分を保持し、`diagnostics(requestId, { budget })` で別の明示した予算を使って取得します。取得が停止しても元の診断は保持します。次の通常要求を送ると置き換わるため、必要な診断はその前に取得します。新しい既定予算を使う自動取得はしません。

## 検査

```sh
cargo test -p zumen-cli
cargo build -p zumen-cli
node bindings/js/test/live.mjs target/debug/zumen
```

合成 DXF の移動を既存の Session の逐次 `apply` と比較し、保存バイト列、現在の ID・ハッシュ、1・4 スレッドの表示と予算使用量を照合します。自作・CC0 の公開 DWG（R2000・R2018）の点の移動も同じ入口で比較します。64 行の差分、版の不一致、古い確認、取り消し・やり直し、診断の寿命、予算停止後の再試行も検査します。実プロセスの中断に加え、独立した応答器で枠の分割・破損、通信上限、期限、処理中の終了を検査します。JWW・SFC の公開サンプルでは、用紙の座標で選んだ行を遠くへ動かすとその行だけが移動先で選ばれること、取り消すと元の選択に戻ること、ビューに置いていない実寸の空間の要素を断って保存のバイト列を変えないことを確かめます。全形式・全編集と製品の表示は、この検査の対象ではありません。

矩形選択は移動・取り消し・やり直し後の追従、予算上限の直前・一致、中断、古い版の拒否と空の結果を検査します。1・4 スレッドの実プロセスと、ネイティブ・WASI の状態処理で行・使用量・停止の記録を照合します。独立した応答器でも、件数・長さ・順序・仮想ノードの混入を拒否し、次の要求後も借用した結果を保持することを確かめます。

画層の表は、DXF・JWW・SFC の公開サンプルで各エンジンの `display_layers` と全項目を照らし、古い版では stale と空のデータを返すことを確かめます。独立した応答器では、値の重複・未定義のフラグ・状態なしの状態ビット・RGB の範囲・色の体系・埋め草・UTF-8・件数・長さ・結果の不一致を拒否します。

スタイルの変更は、2 つの画層を持つ R2000 の DXF・JWW・SFC で、画層の表の値で画層を変えると要素のハッシュと保存が変わり、取り消すと保存が戻ること、形式の色番号で色を変えられること、R2000 の DXF の RGB は断って版が進まないことを確かめます。形の合わない本文（項目なし・予約ビット・使わない値・色の種類とフラグ・色の体系・RGB の範囲・負や NaN の線幅・正でない線種の倍率）と表にない画層の値は、invalid で版と保存を変えないことを確かめます。

行の削除は、DXF・JWW・SFC で、除いた行が選ばれず・対象を引けず・もう一度は除けないこと、取り消すと元の行に戻ることを確かめます。写しは、最小の DXF と、記号を含む DXF・DWG の公開サンプルの行を 1 つずつ写して、写しの行が `Applied` の ID・ハッシュと対象の順に一致すること（断ったときは行が増えないこと）、移動先で選ばれ、取り消すと消えること、JWW・SFC では断って版が進まないことを確かめます。実プロセスでは、写した行を除き、取り消すと保存のバイト列が戻ることを確かめます。

描く順は、DXF・JWW・SFC の公開サンプルで各エンジンの `display_order` と照らし、古い版では stale と空のデータを返すことを確かめます。各エンジンでは、図面モデルの `order` と同じ順になること（DXF は SORTENTSTABLE で並べ替えた最小入力でも、JWW・SXF は編集を挟んでも）と、予算の停止を記録することを確かめます。独立した応答器では、重複・仮想ノード・長さ・結果の不一致を拒否します。

線種の表は、DXF・JWW・SFC の公開サンプルで各エンジンの `display_line_types` と全項目を照らし、古い版では stale と空のデータを返すことを確かめます。各エンジンでは、DXF・DWG は図面モデルの線種と一致し、JWW・SXF は図面モデルの書ける線種を同じ値で含むこと、予算の停止を記録することを確かめます。線種の変更は、R2004 の DXF・JWW・SFC で、表の値で線種を変えると要素のハッシュと保存が変わり、取り消すと保存が戻ることを確かめます。値の続かない本文、継承に値のある指定、未知の種類と表にない値は invalid です。独立した応答器では、値の重複・未定義のフラグ・定義のない項目の値・埋め草・UTF-8・件数・列の長さ・結果の不一致を拒否します。

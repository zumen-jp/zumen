# 2D の閉領域

`zumen-geom2d::topology` の整数格子・交点・編集の共通契約は[アーキテクチャ](architecture.md#幾何と許容差)を参照してください。閉領域の入力も同じ原点・間隔の `Point` にそろえます。曲線を折れ線にした場合は、その近似の誤差と出所を呼び出し側が保ちます。

## 入力と結果

`boolean_regions` は左右の輪郭と塗り規則を受け、和・積・左から右を引く差・排他的論理和を返します。輪郭は暗黙に閉じ、末尾に始点を重ねても受け付けます。奇偶規則と、周回数が 0 でない部分を塗る規則を使えます。自己交差にも同じ規則を使い、符号付きの面積が 0 という理由だけでは輪郭を捨てません。点や線だけの接触は面積を持つ結果に含めません。

`detect_regions` は線分の集合が囲む有限の面をすべて返します。向きと重複に依存せず、入れ子の境界では外周と穴の間の面に加え、穴の内側の面も別に返します。境界の間の橋や開いた枝は面を作りません。入力の外側の固定の枠で平面を分け、枠を含む面だけを取り除きます。枠の座標は `±2^40` で、すべての入力点の外側です。

結果は外周が反時計回り、穴が時計回りです。輪郭の始点を X、Y の辞書順で最小にし、同じ点が複数ある場合は続く点列で決めます。穴と領域も点列の辞書順に並べます。境界上の同一直線上の点を保ちます。点で接する面の表し方には外周の分割と外周・穴による表現があるため、別の実装との照合では表現の件数だけを比較しません。

入力の位置は `RegionLocation` で返し、図面の ID と出所への対応は呼び出し側が保ちます。`adjustments` は交点を格子へ丸めた元の辺と点を重複なく返します。`discarded` は、点か一直線に縮んだ輪郭・長さ 0 の辺と、検出した境界に使わなかった線分の部分を区別します。元の線分の一部だけが使われなかった場合も、その区間を返します。呼び出し側は種類・件数・場所をカタログ診断へ結び付けます。集合演算で指定どおり除いた領域は、欠落の診断にはしません。カーネルは元の図面と ID を変更しません。

## 分割と予算

入力点・輪郭・線分をそれぞれ 4,096 まで、交点で分割した辺も 4,096 までに制限します。各組の交点を整数式で判定し、格子へ丸めた点で両方の辺を分割します。重なる区間も端点で分割します。点を元の辺へ投影した順序を保ち、元の端点間に収め、元の辺からの垂線距離を格子の 1 間隔以内に制限します。これは利用側の許容差の 1/4 です。分割を 8 回まで行い、最後にもう一度交点を検査します。個数超過は `Range`、順序・移動量を保てない場合や分割が収束しない場合は `Precision` とし、部分結果を返しません。

全組の走査、分割点の検索・挿入、再構築、結果の正規化と、使われなかった部分の探索に必要な量を、先に `Work` へ数えます。各組や輪郭でも中断を確認します。作った分割点、丸めの記録、出力の点と使われなかった区間の両端を `Points` へ数えます。自前の配列は確保前に `Bytes` を検査し、失敗を返す確保を使います。辺は 128、分割点と丸めの記録は 64、破棄の記録は 80 バイトを 1 件の予約量とし、32 bit と 64 bit で検査列をそろえます。

依存へ渡す時点では、交点が既存の格子点の端点になっています。整数の List 走査、絶対精度、単一スレッドに固定し、依存の内部で丸めを反復させません。同一直線の折り返しを整理しても、新しい格子外の交点は生じません。分割した辺の数に枠の 4 辺を足した数を `n` として、走査・抽出・穴の所属判定には `64 * n * n` の作業量、配列には `4,096 * n` バイトを先に予約します。依存の処理中は中断を確認できないので、呼び出し前の辺数制限と予約、直後の中断検査を使います。環境のメモリ不足は、明示した予算での停止とは区別します。

## 依存を選んだ理由

[iOverlay 9.2.0](https://docs.rs/i_overlay/9.2.0/i_overlay/) は、i64 の整数座標で穴・接触・自己交差を含む集合演算と、線分による面の分割を扱えるため採用しました。[MIT または Apache-2.0](https://github.com/iShape-Rust/iOverlay) で、推移依存の iFloat 5.0.0・iShape 5.0.0・iKeySort 0.12.0・iTree 0.20.0 は MIT です。既存の libm とともに crates.io から取得し、既定の機能と並列処理の機能は有効にしません。浮動小数の描画・オフセットの API は使いません。

採用前にリポジトリ外でネイティブと wasm の整数 API の結果を照合しました。版は `=9.2.0` に固定します。更新時には交点分割・内部の反復・確保と作業量の上限を再監査し、ライセンス検査とネイティブ・wasm の全バイトの照合を通します。

## 検査の範囲

`tests/regions.rs` は、矩形の和・積・差・排他的論理和の面積、穴と周回数、点での接触、自己交差、橋と枝、入力の逆向き、丸めの記録、最大座標、入力・分割数の上限、予算の各停止点を検査します。`examples/topology_contract/regions.rs` は値と予算の記録を既存の契約記録へ追加し、ネイティブ各環境と wasm の全バイトを同じハッシュに照らします。

環境間の一致とは別に、リポジトリ外で [Pyclipper 1.4.0 / Clipper 6.4.2](https://github.com/fonttools/pyclipper/blob/main/README.rst) と、矩形・45 度の三角形・入れ子・自己交差・座標上限付近の 3,392 条件を照合しました。MIT のラッパーと BSL-1.0 の Clipper を別に導入し、成果物には含めません。356 条件では外周と穴への分け方が異なりましたが、向き付き境界を同一直線の区間へ分けた結果はすべて一致しました。この照合は格子上に交点がある入力が対象であり、格子へ丸める場合の一致を保証するものではありません。

公開の [`intersect`](../schema/README.md#モデル空間の交わり) は、環境間の一致とは別に、リポジトリ外で [ezdxf 1.4.5](https://ezdxf.readthedocs.io/en/stable/math/construct2d.html) の `ezdxf.math` と照合しました。ezdxf で作った座標 ±50・半径 1〜40 の乱数の線分 40・円 30・円弧 30 本の DXF を CLI で開き、6 種類の組を 300 組ずつ、計 1,800 組と期待 622 点を許容差 0.001 で比べました。点の数はすべて一致しました。4 組では点が ezdxf の交点から許容差を超えて最大 0.0019 離れましたが、どれも円か円弧どうしが浅い角度で交わる組でした。返した全点は両方の元の曲線から 0.00038 以内でした。照合は乱数の入力で、重なりと接点の比較を含みません。

公開の [`regions`](../schema/README.md#モデル空間の閉領域) は、環境間の一致とは別に、リポジトリ外で [Shapely 2.2.0 / GEOS 3.14.1](https://shapely.readthedocs.io/en/stable/manual.html) と照合しました。ezdxf で作った座標 ±50 の乱数の単純な多角形 59 個と、20 四方の乱数の線分の組 60 個の DXF を CLI で開き、交わる多角形の 150 組の和・積・差・排他的論理和の 600 件と、線分の組の面の検出 60 件（面 114 個）を許容差 0.001 で比べました。領域・面の数はすべて一致し、面積の差は最大 0.0053 で、どれも周長と格子の間隔の積以下でした。照合は弦に分けない直線だけの入力で、穴の向きと点の並びの比較を含みません。

公開の [`construct`](../schema/README.md#モデル空間の作図) は、環境間の一致とは別に、リポジトリ外で Shapely 2.2.0（GEOS 3.14.1）と解析式に照合しました。ezdxf で作った座標 ±50 の乱数の線分 80・円 40・円弧 40 本と、端点を共有する線分の組 52 個の DXF を CLI で開き、許容差 0.001 で比べました。線分のオフセット 80 件は Shapely の `offset_curve`、トリム 117 件と延長 200 件（交点がない 148 件を含む）は Shapely の交点、円と円弧のオフセット 80 件・面取り 52 件・フィレット 52 件は解析式を期待値にし、食い違いは 0 件でした。差は最大で、円弧のオフセットの端点が 0.00050、トリムと延長の切断点が 0.00016 で、ほかは 1e-13 以下でした。照合は線分の境界だけで、円・円弧を対象や境界にするトリムと延長、楕円などの近似の比較を含みません。

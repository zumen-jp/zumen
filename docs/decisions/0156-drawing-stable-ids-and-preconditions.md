# 0156: 図面モデルの ID は形式が持つ変わらない鍵で作り、変更は読んだときの要素のハッシュを前提条件に持つ

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-29 |
| 状態 | 提案 |

## 背景

`entities` の op（[決定 0117](0117-entities-op.md)）は、要素の ID を、空間か用紙と出所で作る。出所は、DXF ではレコードの番号、DWG ではバイトの位置である。用紙と記号の定義の空間とレイヤの ID は、読んだ順の番号である（[決定 0145](0145-drawing-sheets-per-layout.md)）。図面モデルの変更（[決定 0139](0139-drawing-apply.md)）は、要素を出所で指す。

この作り方には、次の問題がある。

- レコードの番号とバイトの位置は、前の図形を 1 つ足すか除くとずれる。書き戻し（apply）の後は、読み直すまで、使い手が持つ ID が別の要素を指す。用紙を足すと、用紙の番号もずれる。
- 同じ図面でも、DXF と DWG では ID が違う。
- 変更は、使い手が読んだときと要素が同じかを確かめない。読んだ後に別の変更が当たっていても、そのまま上書きする。[決定 0008](0008-model-layers-and-codecs.md) は、中水準の変更セットが元のハッシュを前提条件に持つとした。
- 形式固有の情報（[決定 0115](0115-drawing-format-extensions.md)）は、付く先を要素の添字で指し、読んだときの付く先の値を写して持つ。要素を並べ替えると別の要素を指し、値の写しは拡張の数だけ増える。

AutoCAD の系統の図形・表のレコード・オブジェクトは、ハンドルを持つ。ハンドルは図面の中で重ならず、AutoCAD は保存し直しても変えない。DXF ではグループ・コード 5（寸法スタイルは 105）に書く。試料の `jp-yokosuka-minami-survey-plan` は、同じ図面の DXF と DWG である。DWG でハンドルを持つ 9400 個のオブジェクトは、すべて DXF でも同じハンドルと同じ種類を持つ。SXF の SFC と P21 のインスタンスは、番号（`#n`）を持つ。JWW の要素は、鍵を持たない。

## 選択肢

1. 形式が持つ鍵（ハンドル・インスタンスの番号）で ID を作る。変更は、ID と、読んだときの要素のハッシュを持つ。
2. 今の ID のままにし、apply の後に、古い ID から新しい ID への対応を返す。
3. zumen が要素ごとに番号を振り、L1 に書き込んで（XDATA など）保つ。

2 は、使い手が対応を毎回たどる必要があり、ほかのソフトで変わった図面には使えない。3 は、元の図面に zumen の値を書き足し、ほかのソフトで編集すると失われる。

## 決定

選択肢 1 を提案する。

- **要素の鍵。** 出所（`Ref`）に、形式が持つ鍵を足す。AutoCAD の系統はハンドル、SXF はインスタンスの番号とする。
- **要素の ID。** 決定 0117 の出所の部分を、鍵があれば鍵で作る。ハンドルは `h` と大文字の 16 進（`space/0/h2F`）、インスタンスの番号は `i` と 10 進（`space/0/i120`）で書く。鍵のない要素（JWW、ハンドルを持たない R12 の DXF）は、決定 0117 のまま `r`・`b`・`e` で作る。1 つのレコードから作った 2 つ目からの要素に `/1`・`/2` を足すことも変えない。
- **空間・用紙・表の項目の ID。** 用紙、記号の定義の空間、レイヤ、線種などの表の項目の ID も、鍵で作る。
  - AutoCAD の系統では、用紙は LAYOUT の、記号の定義の空間はブロックの表のレコード（BLOCK_RECORD）の、表の項目はその表のレコードのハンドルとする。用紙の ID の文字列は `sheet/h22`、記号の定義の空間は `space/h1F` になる。
  - 実寸の空間は、どの形式でも `space/0` とする。LAYOUT を持たない版（R14 まで）の用紙と、鍵のない形式は、今の番号のままにする。
  - ハンドルは 64 ビットまであるので、`SpaceId`・`SheetId`・`LayerId`・`LineTypeId` は、64 ビットの値と、ハンドルから作ったかどうかを持つ。ID は並びの位置ではないので、添字に使わない。
- **ID を作る所。** ID を作る規則と、ID から要素を引く関数を `zumen_drawing` に置く。`entities` の op と apply は、同じ関数を使う。apply は、ID から要素への索引を 1 回だけ作る。
- **要素のハッシュ。** 要素のレイヤ・スタイル・形（意味の値を含む）を、決まった並びのバイト列にし、BLAKE3 の先頭の 128 ビットを取る。
  - 出所の位置（レコードの番号・バイト範囲）は入れない。前の要素が増えても、ハッシュは変わらない。
  - 実数はビットの並びで書き、-0 は 0 に、NaN は 1 つの値にそろえる。
  - 並びの版を前に付け、`v1:` と 32 桁の 16 進で書く。並びを変えるときは、版を上げる。
  - Rust の `DefaultHasher` は、Rust の版でアルゴリズムが変わりうるので使わない。
  - レイヤ・線種などの表の項目も、同じ規則でハッシュを持つ。
- **文書のハッシュ。** 元のバイト列の BLAKE3 の先頭の 128 ビットを、文書のハッシュとする。
- **前提条件。** 変更は、要素の ID と、読んだときの要素のハッシュを持つ。apply は、すべての変更を当てる前に確かめる。ID の要素がなければ `change.element.missing`、ハッシュが違えば `change.element.stale` を返し、何も反映しない。変更の一覧は、文書のハッシュを持ってもよい。持てば、今の文書のハッシュと同じときだけ当てる。診断の出来事の語に、`stale`（読んだ後に変わっていた）を足す。
- **apply の結果。** 当てた変更ごとに、要素の新しい ID とハッシュを返す。使い手は、読み直さずに次の変更を作れる。鍵のない形式で、ほかの要素の ID がずれうるときは、そのことを結果に示す（`ids_shifted`）。
- **境界。** `entities` の項目に `hash` を、`drawing` の要約の空間と用紙に `id`（`space/0`・`sheet/h22`）を、文書に `hash` を足す（[決定 0015](0015-add-only-boundary-and-version-floors.md) の足すだけの変更）。
- **形式固有の情報。** `Target` は、要素と表の項目を ID で指す。`Basis` は、読んだときの付く先のハッシュにする。`is_current` は、付く先の今のハッシュと比べる。付く先の値の写しは持たない。

## 影響

- 決定 0117 の ID と、決定 0145・[決定 0153](0153-drawing-empty-layout-sheets.md) の用紙の番号が変わる。適合試験の ID は作り直す。
- ハッシュのために BLAKE3 の crate（CC0-1.0 か Apache-2.0）を足す。WebAssembly で動くことと決定性（[決定 0007](0007-single-rust-implementation.md)）を、足す PR で確かめて記録する。
  - 足した版は `blake3` 1.8.7 で、C と asm を使わない `pure` の機能だけを使う。wasm32-unknown-unknown でも組める。適合試験（`open_dwg` の手順 8）が、要素のハッシュの値を固定し、どの結合でも同じ値になることを確かめる。
- 最初の PR は、AutoCAD の系統の要素の ID をハンドルで作り（ID の規則の版を 2 に上げる）、`entities` に `hash` の欄と、出所の `handle` を足す。用紙は、出所に LAYOUT を持ち、ID の文字列を LAYOUT のハンドルで作る（`sheet/h22`）。`drawing` の要約は、空間と用紙の `id` と、文書の `hash` を返す。試料の同じ図面の DXF と DWG の組は、どれも同じ要素と用紙の ID になる。
  - 用紙の ID の文字列は、`SheetId` の値でなく用紙の出所の鍵から作る。`SheetId` などは、図面モデルの中で点と用紙を合わせるための値として、読んだ順の番号のまま残す。64 ビットにするかは、記号の定義の空間と表の項目を ID で指す変更の一覧を作るときに決める。
  - 記号の定義の空間・表の項目の ID、SXF のインスタンスの番号は、続く PR で作る。
- ハンドルが重複する入力では、用紙の ID の 2 つ目から `/1`・`/2` を付ける。重複した用紙の並びが変わると番号も変わるが、`drawing` と `entities` は同じ ID を返す。
- 記号の定義の空間とレイヤ・線種の ID は、3 つ目の PR で作った。`zumen_drawing::id` の `definition`・`layer`・`line_type` が、`space/h1F`・`layer/h10`・`line-type/h14` を作る。ハンドルがなければ、読んだ順の番号で作る（`space/3`・`layer/2`）。apply は、記号の定義の中の要素も ID で引く。
  - 記号の定義の空間は、BLOCK_RECORD でなく BLOCK のハンドルで作る。R12 の DXF は BLOCK_RECORD を持たないが、BLOCK はハンドルを持つので、版をまたいで同じ規則で作れる。同じ図面の DXF と DWG では、BLOCK のハンドルも同じになる。
  - 試料で、名前のない定義（`*U25` など）と、注釈尺度を分けて書いたレイヤ（`0 @ 1` など）は、同じ図面の DXF と DWG でハンドルが違った。CAD が保存するたびに作り直すものなので、ID は保存をまたいで変わりうる。ハッシュの前提条件が、別の要素を変えることを防ぐ。
  - `SpaceId`・`LayerId`・`LineTypeId` は、読んだ順の番号のまま残す。ID の文字列は出所の鍵から作るので、64 ビットにしなくても鍵で指せる。境界で表の項目を ID で指すことは、変更を境界の op で受ける PR で作る。
- 次の PR は、DXF と DWG の apply に前提条件（`change.element.missing`・`change.element.stale`・`change.document.stale`）を足し、変更ごとの新しい ID とハッシュを返す。文書のハッシュは、今のファイルを書いたバイト列で比べる。変えていないファイルは元のバイトのまま書くので、読んだバイト列のハッシュ（境界の `drawing` が返すもの）と同じになる。
- 要素と文書のハッシュは、可変長の内容を処理するときも予算と中断を確かめる（[決定 0010](0010-budget-by-work.md)）。文書は 1024 バイトごとに work を 1 使う。
- JWW と、ハンドルを持たない R12 の DXF は、apply の後に ID がずれうる。ずれた ID で別の要素を変えることは、ハッシュの前提条件が防ぐ。
- SXF の apply は、インスタンスの番号を保って書き戻すことを条件にする。
- 足す要素の ID は、AutoCAD の系統では `$HANDSEED` から振ったハンドルで作る。足し方は 0139 で決める。
- AutoCAD の系統では、同じ図面の DXF と DWG が同じ ID になる。ただし、実数を文字で書く DXF と、ビットの並びで書く DWG では、同じ要素のハッシュが違いうる。
- 採用するときに、0115 と 0117 からこの決定へリンクする。

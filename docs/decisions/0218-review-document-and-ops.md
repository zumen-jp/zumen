# 0218: レビューの文書の JSON のキーを決め、引き継ぐ op と照合の指摘を取り込む op を API に足し、取り込んだ指摘の ID を入力から決める

## 背景

[決定 0214](0214-review-model-and-bcf.md) は、レビューの文書の中身（対象・指摘・図形）と、新しいバージョンへ移す規則を決めた（#428）。作るにあたり、次の 4 つが決まっていなかった。

- JSON のキーの名と、2D と 3D の場所の分け方。
- API で、レビューの文書をどう受け、どう返すか。API のメッセージのスキーマは、どんな JSON でも受ける型を持たない。
- 照合の結果から作る指摘の ID（UUID）を、乱数で作るか、入力から決めるか。
- API で、建物モデルを対象にできるか。今の wasm の図面のモジュールは、建物モデルを持たない。

## 選択肢

API での文書の受け渡しは、2 つある。

1. 文書をメッセージの中の JSON の値として受け、返す。
2. 文書を入力の名（`zm_push`）で受け、結果の blob で返す。

選択肢 1 は、メッセージのスキーマに文書の全体を書くことになり、知らないキーを保つ規則（0214）とスキーマの `additionalProperties` が合わない。

指摘の ID は、2 つある。

1. 乱数の UUID（バージョン 4）。
2. 対象のハッシュ・規則の id・診断から決める UUID（バージョン 8）。

選択肢 1 は、同じ結果を 2 回取り込むと指摘が重なり、テストの結果が実行ごとに変わる。

## 決定

API では選択肢 2 を、指摘の ID では選択肢 2 を採る。

### JSON の文書

- 最上位は `format`・`version`・`targets`・`topics`・`markups` にする。空の列は書かず、読むときに空の列と同じに扱う。
- キーは、0214 の名を英語の snake_case にする（`status_label`・`modified_by` など）。
- 場所は `kind` が `"2d"` か `"3d"` にする。2D は `view`・`pin`（`[x, y]`）・`extent`（`[x0, y0, x1, y1]`）・`elements`、3D は `camera`・`selected`・`visible`・`exceptions`・`colored`（`color` と `elements`）・`clips`（`point` と `normal`）を持つ。カメラは `projection` が `"perspective"` なら `field_of_view`、`"orthographic"` なら `width` を持つ。
- 要素の参照は `{ "id", "hash" }`、移した記録は `carried: { "from", "state" }`、照合の出所は `origin: { "rule", "diagnostic" }` にする。`diagnostic` は API の診断の形（決定 0012 の `code`・`severity`・`params` など）のオブジェクトをそのまま持つ。
- 知らないキーは、文書・対象・指摘・コメント・場所・図形で保ち、知っているキーの後に読んだ順で書き戻す。参照・カメラ・切断面・色・移した記録・出所は、決めた形だけにし、知らないキーを断る。
- 読むときに、種類ごとに ID が重ならないこと（対象・指摘・場所・コメント・図形）と、参照の先（場所と図形の対象、図形の指摘、コメントの場所、関係する指摘）が文書にあることを確かめる。合わなければ `review.id.exists`・`review.reference.missing` を出して断る。

### 新しいバージョンへ移す

- 0214 の規則に、次を足す。場所を作ったときのハッシュがない参照は、変わっていないと言えないので `changed` にする。`removed` の参照は、新しいバージョンにハッシュがないので、元のハッシュのまま残す。参照を持たない場所と図形は `unchanged` にする。
- 移すのは、ID で選んだ 1 つの対象を指す場所と図形だけにする。対象の文書のハッシュを新しいバージョンのハッシュに書き換える。対象が文書になければ `review.target.missing` を出して断る。

### 照合の指摘を取り込む

- 取り込むのは、利用者が選んだ指摘だけにする（0214）。指摘ごとに、開いた指摘を 1 つ作り、2D の場所を 1 つ（ID は指摘の ID に `/l1` を足したもの）と出所を持たせる。題は規則の id と診断の code にする。
- 指摘の ID は、対象のハッシュ・規則の id・診断の JSON のバイト列・同じ組の何番目かを、長さを前に置いて BLAKE3 にかけ、先頭の 16 バイトを UUID のバージョン 8（RFC 9562）にする。同じ ID の指摘が文書にあれば、取り込み済みとして足さない。
- 対象が文書になければ足す。同じ ID の対象の形式かハッシュが違えば、`review.target.stale` を出して断る。古いバージョンの指摘と新しいバージョンの照合の結果を混ぜないため、先に移す。
- ライブラリの取り込みは、規則の id と診断と要素の参照の組を受けるので、IDS の照合（[決定 0217](0217-ids-check.md)）の結果も同じ関数で取り込める。

### API

- `review_carry` は、文書の番号・入力の名（レビューの文書）・対象の ID を受け、その文書を新しいバージョンとして移す。参照ごとの状態をページで返し、移した文書を blob で返す。
- `review_adopt` は、文書の番号・プロファイル・入力の名（なければ空の文書）・対象の ID・照合の指摘の番号の列を受け、照合（決定 0179）をし直して、選んだ指摘を取り込んだ文書を blob で返す。
- どちらも、図面の文書だけを対象にする。図面の要素の ID とハッシュは 0156 のものを使う。建物モデルを対象にする API は、建物モデルが API に出たとき（#415）に足す。
- 新しい診断の code と op を足すので、API のマイナーバージョンを 43 にする。

## 影響

- #428 は、`zumen-review` と 2 つの op を作る。#429 の BCF は、この文書に写す。
- 図面の要素の位置のずれで 2D の点を動かすことは、0214 のとおり、バージョンの比較の op ができてから足す。

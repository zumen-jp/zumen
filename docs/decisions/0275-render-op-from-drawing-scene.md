# 0275: render は scene と同じ図面の指定から画像を返す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-06 |
| 状態 | 採用 |

## 背景

決定 0272 の `zumen-render` はシーンから SVG を書ける。サーバーや各言語から使う入口と、画像の設定・予算・診断の契約が残っている。

## 選択肢

- `drawing`・`convert`・`scene` の結果を画像に切り替える。これらは図面の要約・図面形式の変換・シーンの blob を返す契約で、画像を返すと名前と意味が変わる。scene と画像の両方を返す追加も考えられるが、画像だけを使うときにも大きいシーンを結果として保持する。
- `svg` のような形式別の op を足す。設定とシーン生成の契約が、PNG を足すときにも分かれる。
- 汎用の `render` に、開いた図面とシーンの指定・画像の形式を渡す。既存のシーン生成を共有し、1 回の呼び出しで画像まで作れる。
- `render` に、`zm_push` した ZMSC だけを渡す。描画部品としては足りるが、API の利用者がシーンを取り出して再び渡す必要があり、フォントの指定も別の呼び出しになる。

## 決定

汎用の `render` op を図面のモジュールに足す。`doc`・`from`・`view`・`tolerance`・`print`・`palette`・`fonts`・`heights` は `scene` と同じ意味にし、内部で借用した指定と生成経路を共有する。公開済みの `SceneRequest` の型と JSON の形は変えない。L1 の形式や描く順を API 側で読み替えない。

- `format` は当面 `svg` だけにする。SVG 専用の op と境界関数は足さない。PNG は #604 でツールと契約を決め、値を追加する。画像の形式は `render_format` で表し、L1 の読み書きの形式を示す `capabilities.formats` には足さない。
- `width`・`height` は正の u32 の範囲のピクセル数、`region` は起点の座標で正の有限の幅・高さになる 4 値、`dpi` は正の有限値とし、すべて必須にする。`background`・`foreground` も sRGB と alpha の 0〜255 の 4 値を必須にする。決定 0272 の中央への配置・余白・範囲外の切り抜き・線幅の規則を使う。
- フォントは `scene_font` と、入力として明示したバイト列だけを使う。字形のない文字などの未描画は、描画部品の診断と元の ID・unit をそのまま返す。unit は同じ設定の `scene` の列から配置へたどれる。
- 結果は形式・ピクセル数・起点・ビュー・座標の単位・使った許容差・blob の番号を返す。blob は既存の `image` にし、SVG の UTF-8 のバイト列を `zm_take` で取り出す。シーンは内部の一時的な結果にし、別の blob として登録しない。
- サイズ・色・表示範囲の誤りは図面の変換前に、`call.value.invalid` と JSON Pointer で返す。シーンと描画の診断はそのまま集約する。画像は全体ができてから登録し、失敗した呼び出しは途中の画像を返さない。元の文書を変更・閉鎖しない。
- 文書の lift・シーン生成・描画で、1 つの `Cx` の予算と中断の合図を使う。描画部品が読む内部の ZMSC も `input_bytes` に数える。描画の索引・出力・診断は決定 0272 の予算を使い、API 側で予算を初期化しない。
- スキーマのマイナーバージョンを 64 に上げる。既存の op・関数・blob の種類の意味は変えない。内部の依存は採用済みの `zumen-render` だけを足し、新しい外部の依存は入れない。

## 影響

各言語は既存の `call` と `take` で SVG を使える。SVG のバイト列と診断・停止は、共通の適合入力を使い、ネイティブ・wasm・各言語で比べる。`capabilities` のスキーマのバージョンと op の一覧は変わるが、既存の描画シーンと ID は変えない。

シーンだけを再描画する API と、OS のフォント・外部画像の探索は足さない。独立したシーンのバイト列を持つ Rust の利用者は `zumen_render::svg` を直接使える。#603 で SVG の API を完了し、親 #534 の PNG は #604 に残す。

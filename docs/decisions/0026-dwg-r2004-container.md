# 0026: DWG の R2004 以降は、コンテナーのセクションを展開したバイト列にしてから読む

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-26 |
| 状態 | 採用 |

## 背景

DWG のコーデックは R2000（AC1015）だけを読み、ほかのバージョンには `dwg.version.unsupported` を返す。[#64](https://github.com/zumen-jp/zumen/issues/64) は、R2000 のほかのバージョンも読むことを求めている。

- R2000 は、ヘッダー・クラス・オブジェクトのマップ・オブジェクトをファイルにそのまま並べる。レコードの位置は、ファイルの先頭からのバイトの位置で表せる。
- R2004（AC1018）は、ファイルのヘッダーの後ろに暗号化したヘッダーを置き、セクション（`AcDb:Header`・`AcDb:Classes`・`AcDb:Handles`・`AcDb:AcDbObjects` など）を圧縮したページに分けて置く（ODS 5.4.1 の 4）。セクションの中身は、ページを展開してつなげるまで読めない。
- R2010（AC1024）から後のバージョンも、同じコンテナーを使う。R2007（AC1021）は別のコンテナーを使う。

## 選択肢

1. セクションごとに、ページを展開してつなげたバイト列を作り、R2000 と同じ読み方をそのバイト列に当てる。
2. ページを展開せず、読むたびにページをたどる。
3. コンテナーを読まずに、R2004 を R2000 と別のコーデックにする。

2 は、展開のたびに同じ計算をし、ビットのリーダーがページの境目を知らなければならない。3 は、ヘッダーの変数・クラス・オブジェクトの読み方が R2000 とほとんど同じなのに、2 つに分かれる。

## 決定

選択肢 1 を採る。

- `dwg::r2004` が、暗号化したヘッダーを戻し、ページのマップとセクションのマップを読み、セクションの名前ごとに展開したバイト列を作る。
- 暗号化したヘッダーの CRC と、マップのページの検査の値が合わないときは、`dwg.crc.invalid` を返して読み続ける。初めのマーカー・ページの型・展開が合わないときは、`dwg.file.invalid` で止める。データのページの検査の値は、まだ確かめない。
- 暗号化したセクション（パスワードで守った図面）は読まない。
- この PR ではコンテナーだけを確かめ、要る 4 つのセクションがあれば `dwg.version.unsupported` を返す。ヘッダー・クラス・オブジェクトは、後の PR で展開したバイト列から読む。そのときのレコードの位置は、`AcDb:AcDbObjects` の展開したバイト列の中の位置とする。
- 書くときは、R2000 と同じく元のバイトをそのまま並べる。

## 影響

- 展開した大きさは、予算の展開・復号のバイト数で数える。セクションとページの数は、レコードで数える。
- 合成したコンテナーと、R2004 の 2 つの図面で、コンテナーを読めることをテストで確かめた。

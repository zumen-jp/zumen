# 0113: 図面モデルの表をセルの格子で持ち、表題欄を属性を持つ記号のまま持つ

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

[決定 0022](0022-drawing2d-semantics-and-format-mapping.md) は、表を行・列・結合範囲とセルの内容・書式・枠で持ち、値と表示文字の違いを残すと決めた。表題欄は、項目のキーと値、元の項目名、対応する表示要素を持ち、単なる罫線の表とは区別する。線と文字から、表題欄や表の意味を推定して作らない。対応表の E10 は、結合セルのある 2×2 の表と、項目名と表示文字が異なる表題欄を試す。

## 選択肢

1. 表を新しい要素にし、行の高さ・列の幅と、セルの格子（結合して広げる数・覆われるか・内容）を持つ。表を線と文字で描いた部品は、表示のための構成要素として指す。表題欄は、役割を明示する形式の読み手を足すときに要素を足す。DXF では、属性を持つ記号のまま持つ。
2. 表を、描いた部品（DXF の名前のないブロック）の配置として持つ。
3. 表題欄の要素を今足し、DXF の属性を持つ記号から推定して作る。

## 決定

選択肢 1 を採る。描いた部品は線と文字だけで、行・列・結合の意味を持たない。DXF は表題欄の役割を持たない。属性を持つ記号を表題欄とみなすことは、決定 0022 の禁じる推定になる。DXF の表題欄の項目と表示は、属性の定義（タグと値を尋ねる文）と、配置の属性（タグと値）として、すでに分けて持てる。

- `Shape::Table` は `Table` を持つ。挿入点・行の向き・行の高さ・列の幅・セル・元の表のスタイル・描いた記号の定義（`drawn`）を持つ。
- `Cell` は、内容（`CellContent`: 空・書式つきの文字の元の内容と区間・記号の定義）と、結合して広げる列と行の数、ほかのセルに覆われるかを持つ。セルは、上の行から行ごとに左の列から並べる。
- DXF の ACAD_TABLE を移す。行と列の数・大きさの数・セルの数が合わないものは、`dxf.lift.invalid` を返す。
- 2007 からのセルの値（301〜304）は、文字（1・2）がなければ、その文字（302）を内容とする。この扱いは推定で、試料の図面で確かめていない。
- 表題欄の要素は、まだ足さない。SXF の表題欄の属性（附属書 2）を読むときに足す。

## 影響

- 次のものは、まだ移さない。
  - セルの書式・枠・色・回転と、セルの値の種類と表示の書式。そのため、値と表示文字の違いは、まだ持たない。
  - 表のスタイルの中身。
  - セルの中の属性の値（179・331・300）。
- DWG の読み手は ACAD_TABLE の型ごとの欄を表に置かないので、DWG の表は移らず、`dxf.lift.invalid` を返す。
- 境界（`drawing` の op）の要約は、表を数えず、範囲にも入れない。

# 0142: DXF・DWG の厚さ・線種の生成・スプラインの許容差は、図面モデルの拡張 `dxf.entity` に控える

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-28 |
| 状態 | 採用 |

## 背景

DXF・DWG から図面モデル（Drawing2D）へ移すとき、図形の厚さ（39）と、LWPOLYLINE・POLYLINE の線種の生成（70 の 128）と、SPLINE の許容差（42・43・44）は「まだ移さない」としていた（#174）。診断も出さないので、黙って落としていた。

- **厚さ**: 平面の図形を Z の向きに押し出す長さである。上から見た形は変わらないので、平面の図面モデルの形には要らない。3D の見え方や、元の形式へ戻すときには要る。
- **線種の生成**: 線種の模様を頂点ごとに切らずに、ポリライン全体で続ける印である。表示の結果を変える。日本の測量図の試料（横須賀市の 3 つの図面）では、線種の生成を立てたポリラインが合わせて 137 本あった。
- **スプラインの許容差**: SPLINE の節点・制御点・当てはめの許容差（42・43・44）は、スプラインを作り直すときの精度である。節点と制御点で決まる形は変えない。日本の測量図の試料の SPLINE も、3 つの許容差を持っていた。

形式固有の情報は、[決定 0115](0115-drawing-format-extensions.md) の拡張（`Extension`）に、付く先の要素とその値（`Basis`）と組にして置ける。SXF の文字の幅と間隔（`sxf.text`、[決定 0122](0122-sxf-text-to-formatted-text.md)）も同じ形で残している。

## 選択肢

1. 名前空間 `dxf.entity` の拡張に、要素ごとに控える。
2. 図面モデルの `Polyline` に線種の生成の印を、`Spline` に許容差を、要素に厚さを足す。
3. 移さず、診断を出す。

## 決定

選択肢 1 を採る。

- 厚さと許容差は、平面の形を変えないので、モデルの値にする理由がない。
- 線種の生成は表示を変えるが、線種の模様をどう描くかは、まだ図面モデルの値にしていない（線種の形と文字も #174 の残りにある）。模様の描き方を決めるときに、モデルの値へ移すかをあらためて決める。後に[決定 0157](0157-drawing-model-fields-and-extensions.md) で、線種の生成を `Polyline` の値に、当てはめの許容差（44）と節点の取り方を `Spline` の値に移すことにした。
- 診断だけ（選択肢 3）では、値が失われる。

内容は次のとおり。

- 名前空間は `dxf.entity`、値の型の契約の版は 1。付く先は図形の要素で、名前は空、版は `$ACADVER`。
- 欄は次のとおり。どの欄もない図形は、この拡張を持たない。
  - `thickness`（実数）: LINE・CIRCLE・ARC・TEXT・LWPOLYLINE・POLYLINE・SOLID・TRACE・POINT・SHAPE の 39。0 でなければ置く。
  - `line_type_generation`（整数の 1）: LWPOLYLINE・POLYLINE の 70 の 128 が立っていれば置く。
  - `knot_tolerance`・`control_tolerance`・`fit_tolerance`（実数）: SPLINE の 42・43・44。あれば置く。
- DWG は、表の値が DXF と同じなので、同じ扱いになる。試料の同じ図面の DWG と DXF の組（sample_AC10xx）は、厚さと線種の生成を持たない。持っているスプラインの許容差（42・43）が、どの組でも一致することを確かめた。

## 影響

- 拡張を読む使い手は、`dxf.entity` を見れば厚さ・線種の生成・スプラインの許容差を得られる。要素を変えると、拡張の `Basis` が合わなくなり、`is_current` が偽になる。
- 図面モデルから DXF・DWG への書き戻し（[決定 0139](0139-drawing-apply.md)）は、元の表の値を残すので、この拡張を読まない。
- 欄を足すときは、版を上げずに `dxf.entity` に足してよい。意味を変えるときは版を上げる。

# 0193: DWG のヘッダーのセクションの大きさを変えて点の表し方を書き、API で点の表し方を読み、P21 の見え方の割り当てを写す

## 背景

[決定 0190](0190-drawing-apply-p21-markers-and-point-styles.md) で文書の点の表し方の書き戻しを足したが、3 つを残した（#348）。

- DWG のヘッダーの変数は、セクションの大きさを変えずにその場で書き直す（[決定 0069](0069-dwg-write-back-header-variables.md)・[決定 0084](0084-dwg-r2010-header-variables.md)）。そのため、BS・BD で書く幅が変わる `$PDMODE`（0 とほかの値の間）と `$PDSIZE`（0・1 とほかの値の間）を書けず、既定の図面（`$PDMODE` 0・`$PDSIZE` 0）の点の表し方を変えられなかった。
- API には、今の文書の点の表し方を読むフィールドがなかった（シーンの `point_style` のセクションだけが返す）。
- P21 の点マーカーの色の変更は、記号の見え方の割り当てがほかの見え方も持つと断っていた。

## 選択肢

DWG のヘッダーのセクションの大きさを変える書き方は、次のどれかにする。

1. 断ったままにし、サンプルで確かめてから決める。
2. 後ろのビットをずらしてセクションを作り直す。置き場所は、R2000 はファイルの後ろに置いてセクションの記録を直し、R2004 からは展開したセクションの中で置き換える。
3. R2000 でも元の位置でセクションを広げ、後ろのクラスのセクション・オブジェクト・マップの位置をすべてずらす。

API で点の表し方を読むフィールドは、次のどれかに置く。

1. `drawing` の結果（文書の要約）に、任意のフィールドを足す。
2. `tables` の結果に足す。
3. 新しい op を足す。

P21 の色の変更は、次のどちらかにする。

1. 断ったままにする。
2. 元の割り当ての見え方の並びを写し、記号の見え方だけを新しいものに付け替えた割り当てを足す。

## 決定

DWG は選択肢 2、API は選択肢 1、P21 は選択肢 2 を採る。

- **DWG のセクションの作り直し。** セクションの大きさ・CRC・後ろのセクションの位置は、どれも今の部品で扱いが決まっている。
  - セクションの中: PDMODE・PDSIZE を新しい幅で書き、その後ろのビットはそのまま写す。大きさ（RL）を新しいデータのバイトの数にし、CRC を大きさからデータの終わりまで計算し直す（HANDSEED・INSUNITS の書き直しと同じ計算）。R2010 からの上位の RL は元のまま写す。
  - R2010 からのストリーム: 文字列のストリームの大きさと有無のフラグは、データの初めの RL（文字列のストリームの終わりの位置）から前へ数え、ハンドルのストリームはその位置から始まる。後ろをまとめてずらし、この RL に同じビットの数を足せば、どちらのストリームも元のまま読める。オブジェクトの文字列のストリームを組み直す書き方（[決定 0092](0092-dwg-r2010-write-back-entity-addition.md) など）と同じ形である。[決定 0084](0084-dwg-r2010-header-variables.md) がサンプルで確かめていないとして採らなかった形を、この理由で採る。
  - R2000 の置き場所: オブジェクトのマップをファイルの後ろに置いてセクションの記録を直す書き方（[決定 0028](0028-dwg-object-data-edit.md)）と同じく、作り直したセクションをファイルの後ろに足し、セクションの記録（番号 0）の位置と大きさと、ファイルのヘッダーの CRC を直す。元のセクションのバイトは残る。選択肢 3 は、オブジェクトのマップのすべての位置と、ほかのセクションの記録を書き直すことになり、使わないバイトを残す今の書き方より変える所が多い。
  - R2004 からの置き場所: 展開した `AcDb:Header` の中でセクションを置き換え、コンテナーは書くときに組み直す（[決定 0070](0070-dwg-r2004-container-write.md)）。セクションの大きさが変わっても、オブジェクトのセクションと同じく扱える。
  - 大きさが変わらない変更は、これまでどおりその場で書き直す。INSUNITS の幅が変わる値は、依頼がないので今までどおり断る。
- **API。** `drawing` の結果に `point_style`（`point_style_summary`: 形 `mark`・囲み `circle`・`square`・大きさ `size`・大きさの意味 `size_kind`）を足す。フィールドの意味は `point_style_edit` と同じにし、列挙 `point_mark`・`point_size_kind` を使い回す。文書が点の表し方を持たない（JWW・SXF）ときはフィールドを持たない。文書の要約なので `drawing` に置く。`tables` は表の項目を返す op で、文書の設定とは別にする。マイナーバージョンを 39 に上げる。
- **P21 の割り当ての写し。** 元の割り当て（`PRESENTATION_STYLE_ASSIGNMENT`）の見え方の並びを同じ順に写し、`SYMBOL_STYLE` だけを新しい記号の見え方に付け替えた割り当てを足して、表記の実体の参照を指し替える。元の割り当ては書き換えない（ほかの要素と共有しうる）。指されなくなった元の割り当てと記号の見え方は、ほかの幾何と同じく除き、写したほかの見え方は残る。

## 影響

- `DwgTxn::set_point_mode`・`set_point_size` と、表からの書き戻しの `$PDMODE`・`$PDSIZE` は、幅が変わる値も受け付ける。有限でない大きさは、これまでどおり断る。
- 手組みの R2000 の図面で、幅の同じ値・違う値を書き戻し、読み直した表が変えた表と同じになり、セクションの記録が後ろを指すことを確かめた。書いたファイルをもう一度書き戻せることも確かめた。手組みの R2004・R2010・R2013・R2018 のコンテナーでも、幅の変わる値を書いて読み直し、ほかの変数が元のままで CRC の診断が出なかった。セクションの単体のテストで、R2010 からの文字列のストリームとハンドルのストリーム（2 つの空間のハンドル）が元のまま読めることを確かめた。
- サンプルの DWG では、ここで確かめていない（`ZUMEN_SAMPLES` の図面がない）。書いた図面を AutoCAD で開いて確かめてもいない。R2000 で、ファイルの後ろに置いたヘッダーのセクションを AutoCAD が受け付けるかは、オブジェクトのマップと同じく分からない。
- API の `drawing` の応答が、点の表し方を持つ文書で変わる。適合テストのハッシュを作り直した。
- P21 の曲線の見え方（線の要素）の割り当てがほかの見え方も持つときの変更は、これまでどおり断る。

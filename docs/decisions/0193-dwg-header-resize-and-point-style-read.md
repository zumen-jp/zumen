# 0193: DWG の見出しの区切りの大きさを変えて点の表し方を書き、境界で点の表し方を読み、P21 の見え方の割り当てを写す

| --- | --- |
| 日付 | 2026-10-31 |
| 状態 | 採用 |

## 背景

[決定 0190](0190-drawing-apply-p21-markers-and-point-styles.md) で文書の点の表し方の書き戻しを足したが、3 つを残した（#348）。

- DWG の見出しの変数は、区切りの大きさを変えずにその場で書き直す（[決定 0069](0069-dwg-write-back-header-variables.md)・[決定 0084](0084-dwg-r2010-header-variables.md)）。そのため、BS・BD で書く幅が変わる `$PDMODE`（0 とほかの値の間）と `$PDSIZE`（0・1 とほかの値の間）を書けず、既定の図面（`$PDMODE` 0・`$PDSIZE` 0）の点の表し方を変えられなかった。
- 境界には、今の文書の点の表し方を読む欄がなかった（シーンの `point_style` の区画だけが返す）。
- P21 の点マーカーの色の変更は、記号の見え方の割り当てがほかの見え方も持つと断っていた。

## 選択肢

DWG の見出しの区切りの大きさを変える書き方は、次のどれかにする。

1. 断ったままにし、試料で確かめてから決める。
2. 後ろのビットをずらして区切りを作り直す。置き場所は、R2000 はファイルの後ろに置いて区切りの記録を直し、R2004 からは展開した区切りの中で置き換える。
3. R2000 でも元の位置で区切りを広げ、後ろのクラスの区切り・オブジェクト・地図の位置をすべてずらす。

境界で点の表し方を読む欄は、次のどれかに置く。

1. `drawing` の結果（文書の要約）に、任意の欄を足す。
2. `tables` の結果に足す。
3. 新しい op を足す。

P21 の色の変更は、次のどちらかにする。

1. 断ったままにする。
2. 元の割り当ての見え方の並びを写し、記号の見え方だけを新しいものに付け替えた割り当てを足す。

## 決定

DWG は選択肢 2、境界は選択肢 1、P21 は選択肢 2 を採る。

- **DWG の区切りの作り直し。** 区切りの大きさ・CRC・後ろの区切りの位置は、どれも今の部品で扱いが決まっている。
  - 区切りの中: PDMODE・PDSIZE を新しい幅で書き、その後ろのビットはそのまま写す。大きさ（RL）を新しいデータのバイトの数にし、CRC を大きさからデータの終わりまで計算し直す（HANDSEED・INSUNITS の書き直しと同じ計算）。R2010 からの上位の RL は元のまま写す。
  - R2010 からの流れ: 文字列の流れの大きさと有無の印は、データの初めの RL（文字列の流れの終わりの位置）から前へ数え、ハンドルの流れはその位置から始まる。後ろをまとめてずらし、この RL に同じビットの数を足せば、どちらの流れも元のまま読める。オブジェクトの文字列の流れを組み直す書き方（[決定 0092](0092-dwg-r2010-write-back-entity-addition.md) など）と同じ形である。[決定 0084](0084-dwg-r2010-header-variables.md) が試料で確かめていないとして採らなかった形を、この理由で採る。
  - R2000 の置き場所: オブジェクトの地図をファイルの後ろに置いて区切りの記録を直す書き方（[決定 0028](0028-dwg-object-data-edit.md)）と同じく、作り直した区切りをファイルの後ろに足し、区切りの記録（番号 0）の位置と大きさと、ファイルの見出しの CRC を直す。元の区切りのバイトは残る。選択肢 3 は、オブジェクトの地図のすべての位置と、ほかの区切りの記録を書き直すことになり、使わないバイトを残す今の書き方より変える所が多い。
  - R2004 からの置き場所: 展開した `AcDb:Header` の中で区切りを置き換え、入れ物は書くときに組み直す（[決定 0070](0070-dwg-r2004-container-write.md)）。区切りの大きさが変わっても、オブジェクトの区切りと同じく扱える。
  - 大きさが変わらない変更は、これまでどおりその場で書き直す。INSUNITS の幅が変わる値は、依頼がないので今までどおり断る。
- **境界。** `drawing` の結果に `point_style`（`point_style_summary`: 形 `mark`・囲み `circle`・`square`・大きさ `size`・大きさの意味 `size_kind`）を足す。欄の意味は `point_style_edit` と同じにし、列挙 `point_mark`・`point_size_kind` を使い回す。文書が点の表し方を持たない（JWW・SXF）ときは欄を持たない。文書の要約なので `drawing` に置く。`tables` は表の項目を返す op で、文書の設定とは別にする。小版を 39 に上げる。
- **P21 の割り当ての写し。** 元の割り当て（`PRESENTATION_STYLE_ASSIGNMENT`）の見え方の並びを同じ順に写し、`SYMBOL_STYLE` だけを新しい記号の見え方に付け替えた割り当てを足して、表記の実体の参照を指し替える。元の割り当ては書き換えない（ほかの要素と共有しうる）。指されなくなった元の割り当てと記号の見え方は、ほかの幾何と同じく除き、写したほかの見え方は残る。

## 影響

- `DwgTxn::set_point_mode`・`set_point_size` と、表からの書き戻しの `$PDMODE`・`$PDSIZE` は、幅が変わる値も受け付ける。有限でない大きさは、これまでどおり断る。
- 手組みの R2000 の図面で、幅の同じ値・違う値を書き戻し、読み直した表が変えた表と同じになり、区切りの記録が後ろを指すことを確かめた。書いたファイルをもう一度書き戻せることも確かめた。手組みの R2004・R2010・R2013・R2018 の入れ物でも、幅の変わる値を書いて読み直し、ほかの変数が元のままで CRC の診断が出なかった。区切りの単体の試験で、R2010 からの文字列の流れとハンドルの流れ（2 つの空間のハンドル）が元のまま読めることを確かめた。
- 試料の DWG では、ここで確かめていない（`ZUMEN_SAMPLES` の図面がない）。書いた図面を AutoCAD で開いて確かめてもいない。R2000 で、ファイルの後ろに置いた見出しの区切りを AutoCAD が受け付けるかは、オブジェクトの地図と同じく分からない。
- 境界の `drawing` の応答が、点の表し方を持つ文書で変わる。適合試験のハッシュを作り直した。
- P21 の曲線の見え方（線の要素）の割り当てがほかの見え方も持つときの変更は、これまでどおり断る。

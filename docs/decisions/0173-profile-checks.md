# 0173: プロファイルの照合は `zumen-profile` に置き、`check` の op で、配置をたどって解いた図面モデルの値と語彙を比べる

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-30 |
| 状態 | 採用 |

## 背景

[決定 0138](0138-profiles-as-versioned-data.md) は、基準・要領・社内標準を版のあるデータ（プロファイル）にした。最初のプロファイル `mlit-cad` の 2025-12 版は、レイヤ名・色・線種・線幅・文字の高さ・使えない文字・用紙の大きさ・向き・尺度の 9 つの規則を持つ。照合そのものは、まだない（#220）。

決めることは次のとおり。

- 照合の置き場所（crate）と呼び方（op と引数）
- 照合の種類ごとに、図面モデルのどの値と比べるか（色は、ACI と SXF の色の対応を含む）
- `extends` の解き方
- 照合の結果と、[決定 0009](0009-diagnostics-and-catalog.md) の診断との関係。0009 は重要度を code ごとに決めるが、プロファイルの規則は自分の重要度（`level`）を持つ

関わる事実は、次のとおり。

- コアは、色の符号表を持たない（[決定 0106](0106-drawing-color-line-type-weight.md)）。プロファイルの色の語彙は、SXF の既定義色の番号と参考の RGB を持ち、ACI の列を持たない。
- コアは、ファイルを自分で開かない。入力は `zm_push` で渡す（`describe` のカタログと同じ）。
- 配置をたどって、要素ごとの解いた色・線種・線幅・実効のレイヤ・表示の可否と変換を返す関数を、図面モデルに置く（[決定 0159](0159-drawing-walk-placements.md)）。0159 は、プロファイルの照合もこの関数を使うとした。
- 図面モデルの文字の高さは、長さの型（用紙か実寸）と意味（SXF の文字枠・形式の宣言値など）を持つ（[決定 0022](0022-drawing2d-semantics-and-format-mapping.md)）。
- 用紙は大きさを持つが、向きの欄を持たない。ビューは、実寸の空間から用紙への変換（`Affine`）を持ち、尺度の欄を持たない。

## 選択肢

1. 新しい crate `zumen-profile` に照合を置き、境界の `check` の op で呼ぶ。0159 の関数でたどった値と、語彙を比べる。
2. 照合を図面モデルの crate（`zumen-drawing`）に置く。
3. 照合をコアに置かず、`entities` と `tables` の結果を使って、各言語の側で行う。

2 は、図面モデルがプロファイルの JSON の読み取りと、照合の種類ごとの知識を持つことになる。図面モデルは形式にも基準にも依らない型にしておきたい。3 は、照合を言語ごとに書くことになり、どこでも同じ結果という約束（[決定 0007](0007-single-rust-implementation.md)）を外れる。

## 決定

選択肢 1 を選ぶ。

### 置き場所と呼び方

- **crate。** `zumen-profile` を足す。プロファイルの JSON（`profile.json`）を `zumen-json` で読み、`extends` を解き、図面モデル（`zumen-drawing`）の値と比べる。境界の `zumen-abi` が呼ぶ。`xtask` のプロファイルの検査も、照合の種類と欄の一覧をこの crate から引く。
- **op。** `check` を足す。引数は次のとおり。
  - `doc`: 文書の名前
  - `profiles`: プロファイルの入力の名前の列。`zm_push` で渡したもの。`extends` で指す先も、すべて渡す
  - `profile`: 照合に使うプロファイルの `id` と `edition`。列の中から選ぶ
  - `from`: たどる起点（0159 の用紙・ビュー・空間の ID）。書かなければ、すべての用紙から、用紙がなければ実寸の空間からたどる
  - `offset`・`limit`: 返す指摘の範囲（`entities` と同じ。上限は 10000）
  - `palette`: 色の表の入力の名前（[決定 0172](0172-scene-sections-and-op.md) の `scene` と同じ形）
- **結果。** 次を返す。
  - 照合に使ったプロファイルの鎖。基から順に、`id`・`edition`・`revision`
  - 規則ごとの、指摘の数と、照合できなかった数
  - 指摘の列。規則の id・重要度・code・場所（要素・レイヤ・用紙・ビューの ID）・見つけた値・比べた語彙の名前を持つ
  - 続きの位置（`next_offset`）

### 指摘と診断

- 指摘は、診断ではなく、`check` の結果として返す。重要度は、規則の `level` とする。
- 指摘の code は、照合の種類ごとに `profile.<種類>.invalid` とし、カタログに日本語と英語の文を置く。指摘は診断と同じ形の値を持つので、`describe` で文にできる。カタログの重要度は使わない。
- 照合できない値（RGB の分からない色、尺度の分からないビューなど）は、`profile.<種類>.unsupported` の指摘にし、重要度を `info` とする。黙って通さない。
- プロファイルを読めない、`extends` の先がない、`extends` が輪になるなど、照合を始められないときは、診断（`profile.format.unsupported`・`profile.extends.missing`・`profile.extends.invalid`）を返して、何も照合しない。

### `extends` の解き方

- `extends` の先から順に重ねる。同じ id の規則は、子が置き換える。新しい id の規則は、後ろに足す。
- 語彙も、同じ名前のものは、子が全体を置き換える。
- 鎖の深さは、予算の `depth` で数える（[決定 0010](0010-budget-by-work.md)）。

### 照合の種類ごとに比べる値

どれも、0159 の関数でたどった要素のうち、表示する要素を比べる。

| 種類 | 比べる値 | 語彙との比べ方 |
| --- | --- | --- |
| `layer-name` | 表示する要素の実効のレイヤの名前。要素のないレイヤは比べない | `separator` で区切り、`parts` の語彙の `code` と順に比べる。`user-part` が真なら、残りを自由な部分とする。名前の幅（半角を 1、全角を 2）が `max-width` を超えれば指摘する |
| `color` | 要素の解いた色 | 下の「色」のとおり |
| `line-type` | 要素の解いた線種の名前 | 語彙の形式の列（`sxf` など）の名前と比べる。図面の形式の列がない語彙なら、照合できない |
| `line-width` | 要素の解いた線幅（用紙の mm）。文書の既定は、文書の既定の値で解く。読まなかった線幅は照合できない | 語彙の値と、`tolerance` の内で一致するか |
| `text-height` | 文字・書式つきの文字・属性の高さを、用紙の mm にしたもの。実寸の高さは、ビューの変換の尺度を掛ける。縦横の尺度が違うビューと、用紙を通さない実寸の文字は照合できない | 語彙の値と、`tolerance` の内で一致するか。指摘に高さの意味（文字枠・宣言値など）を書く。意味の違う高さを換算しない（0022） |
| `characters` | 文字・書式つきの文字・属性・表のセル・寸法の文字の内容 | 語彙の範囲の文字を含めば指摘する |
| `sheet-size` | 用紙の大きさ。向きは問わない | 語彙の幅と高さと、縦横を入れ替えたものの、どちらかと `tolerance` の内で一致するか。大きさのない用紙は照合できない |
| `orientation` | 用紙の大きさの、幅と高さの大小 | 幅が高さ以上なら横、ほかは縦として、`orientation` と比べる |
| `scale` | ビューの変換の尺度と、実寸の空間の単位から求めた縮尺の分母 | 分母を仮数（1 以上 10 未満）と 10 の累乗に分け、仮数が語彙にあるか。単位が分からないビューと、縦横の尺度が違うビューは照合できない |

- `tolerance` を書かなければ、1e-6 mm までの差を同じとみなす。

### 色

- 図面の色の系統の列が語彙にあれば、符号で比べる。SXF の図面なら、既定義色の番号を語彙の `sxf` の列と比べる。
- 系統の列がなければ、RGB で比べる。RGB は、ファイルが持つ RGB か、`palette` から引いたものとする。語彙の RGB と一致すれば通す。
- どちらでも決まらなければ、照合できない指摘にする。
- ACI と SXF の色の対応は、コアに持たない（0106）。プロファイルは、語彙に `aci`・`jww` などの列を足して、対応を持てる。出典が対応を決めていなければ、`basis = "chosen"` にする。

## 影響

- 照合は、0159 の関数ができてから作る。照合だけのために、配置のたどり方を別に書かない。
- `xtask` が持つ照合の種類と欄の一覧（`xtask/src/profiles.rs`）は、`zumen-profile` から引く形に移す。
- プロファイルの JSON を読む側は、0138 のとおり、知らない欄を読み飛ばす。`xtask` の検査は、書く側の検査として、知らない欄を拒むままにする。
- `mlit-cad` の ACI の列は、ACI と SXF の色の対応を決めてから、プロファイルの新しい `revision` で足す。それまで、DXF・DWG の図面の色は、RGB が分かるものだけを照合する。
- 線種は名前で比べるので、DXF・DWG の線種の名前が SXF の名前と違えば、照合できない。模様で比べることは、別に決める。
- 新しい診断と指摘の code（`profile.*`）と、`check` の op を足すので、境界の小版を上げる。
- ほかの基準（電子納品要領・SXF の実装規約・J-LandXML など）のプロファイルは、文書の版と出典を確かめてから足す（#220）。

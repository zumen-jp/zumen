# 0290: JWW の追加で、レイヤに従う線幅をペンの線幅で書き、レイヤに従う色と線種は理由の分かる診断で断る

| 日付 | 2026-11-10 |
| 状態 | 採用 |

## 背景

[決定 0168](0168-jww-apply.md) は、JWW への追加で「線幅を書かなければ 0 とし、ペンの印刷の幅に従う」とし、「レイヤに従う値、ブロックに従う値は、JWW の図形が持たないので書けない」「断るものは `change.edit.unsupported` で断る」とした。

API の `apply` の `add`（`add_edit`）は、書かない色・線種・線幅をレイヤに従う値（`Inherit::Layer`）として渡す（[決定 0139](0139-drawing-apply.md)）。そのため、API から JWW に線・円・円弧を足すと、線幅を書かなくてもレイヤに従う線幅として渡り、0168 の「書けない」に当たって、どの線幅でも断っていた（#702）。色か線種を書かないときも、足す図形のクラスを `kind` にした `change.edit.unsupported` で断るので、利用者には何を書けばよいかが分からなかった。

## 選択肢

1. 線幅: API の側で、JWW への追加だけ、書かない線幅を「持たない」（`None`）として渡す。
2. 線幅: JWW の側で、レイヤに従う線幅を、0168 の「書かなければ 0」と同じに扱う。
3. 色と線種: 書かなければ、既定の値（ペン 1・実線）で書く。
4. 色と線種: 書かなければ断り、どのフィールドが要るかを持つ新しい診断で返す。

## 決定

2 と 4 を採る。

- **線幅。** JWW の追加で、線幅を持たない（`None`）か、レイヤに従う（`Inherit::Layer`）ものは、0 で書く。JWW のレイヤは線幅を持たず、図形の線幅の 0 が「ペンの印刷の線幅に従う」ことを表す。JWW で「自分で決めない線幅」に当たるのはこれだけなので、0168 の「書かなければ 0」をレイヤに従う線幅にも当てる。読み直した線幅は、ペンの印刷の線幅（`Inherit::Own`）になる。ブロックに従う線幅と、文書の既定の線幅（`LineWeight::Default`）は、今までどおり断る。
- **色と線種。** JWW の追加で、色（点と線・円・円弧）か線種（線・円・円弧）がレイヤに従うものは、新しい診断 `change.style.unsupported` で断り、何も変えない。値は `field`（`color` か `line_type`）と `format` を持つ。ほかの断り方（書いた値を受けられないとき、ブロックに従う値など）は、今までどおり `change.edit.unsupported` で断る。

1 は、API の変更の組み立て（`zumen-abi`）に JWW の都合を入れ、同じ要求でも形式で渡す値が変わる。DXF・DWG では、書かない線幅はレイヤに従う線幅（ByLayer）のまま書くので、形式ごとの読み替えは形式の crate に置く。3 は、JWW にはレイヤに従う色と線種がないので、利用者が頼んでいない値を黙って決めることになる。

## 影響

- API から JWW に線・円・円弧を足せる。色と線種は書く必要がある。点は色だけを書く。
- 「レイヤに従う」と頼んだ線幅は、読み直すとペンの印刷の線幅になる。`schema/messages.json` の `add_edit` の説明と、`docs/formats/jww.md` に書く。
- `change.style.unsupported` は、形式によらない名前にする。SXF もレイヤに従う色を持たず、今は `change.edit.unsupported` で断る。同じ診断にそろえるかは、別に決める。

# 0112: 図面モデルの記号の定義を、定義ごとの空間に持つ

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

[決定 0022](0022-drawing2d-semantics-and-format-mapping.md) は、再利用する要素の定義と、基点・変換・属性値を持つ配置を分けた。空間・グループ・再利用定義は区別する。部品の配置から定義まで辿れるようにする。[決定 0108](0108-drawing-symbols-hatches-arrowheads.md) は、配置（`Symbol`）が定義をキー（`SymbolKey`）で指すことにした。ただし、定義の中身（DXF の BLOCKS）は移さなかった。対応表の E8 は、同じ部品の 2 つの配置で、配置ごとの出所と定義の出所を残すことを試す。

## 選択肢

1. 記号の定義を図面の一覧に置く。中身は、図面の実寸の空間とは別の ID を持つ、定義ごとの空間（`ModelSpace`）に置く。
2. 中身の点に、用紙でも実寸でもない第 3 の点と長さの型を足す。
3. 配置ごとに中身を写して展開し、配置の要素として持つ。

## 決定

選択肢 1 を採る。定義の中身は、配置されるまで用紙にも図面の実寸の空間にも属さない。定義ごとの座標系を持つ。空間の ID を分ければ、点と長さの型を増やさずに、定義の点を図面の点と混ぜて計測することを防げる。配置で写すことは、ビューで空間を用紙に置くことと同じ形になる。展開すると、配置の数だけ中身が増え、定義と配置の区別がなくなる。循環する定義や展開の上限の扱いも要る。

- `Drawing2D` は `symbols` に `SymbolDefinition` の一覧を持ち、`Drawing2D::symbol` でキーから引く。
- `SymbolDefinition` は、次を持つ。
  - キー。
  - 中身の空間。ID は図面の実寸の空間とも、ほかの定義とも重ならない。単位は文書の単位。
  - 基点。分からなければ `None`。
  - 属性の定義（`AttributeDefinition`: 配置の属性と同じ欄と、値を尋ねる文、値が決まっている・確かめる・尋ねないの印）。
  - 名前のない定義か、外部参照のパス、出所。
- DXF・DWG の BLOCKS の BLOCK を移す。
  - 中身は、所有者をたどって着くブロックのレコードの BLOCK のものとする。所有者が分からなければ、並びの中で前の BLOCK から ENDBLK までのものとする。
  - 空間のブロック（`*Model_Space`・`*Paper_Space`）は移さない。
  - どの定義のものか分からない図形と、名前のない BLOCK は `dxf.lift.invalid` を返す。
- 配置は展開しない。外部参照のファイルも読まない。

## 影響

- DWG の読み手は、ブロックの基点（ブロックのレコードの欄）と BLOCK の印を表に置かない。そのため DWG の定義は基点を持たず、名前のない定義は名前の `*` から推定する。
- ブロックのレコードの単位（70）は、まだ移さない。中身の描く順は、モデル空間と同じく、ブロックのレコードを指す SORTENTSTABLE で決め（[決定 0105](0105-drawing-layers-and-order.md)）、なければ入力の順とする（#174 で足した）。
- 定義の中の要素の色・線種で、ブロックから継承するもの（BYBLOCK）は、継承のまま持つ。配置で解く処理は、まだない。
- ほかのレイアウトの用紙空間のブロック（`*Paper_Space0` など）の図形は、まだ移さない。
- 寸法やハッチングが作った名前のない定義も移る。寸法の部品の展開とのつながりは、まだ持たない。

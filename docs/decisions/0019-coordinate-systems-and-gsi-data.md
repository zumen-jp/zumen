## 背景

- 旧版は、用紙の mm（Y が上）と、図面の実寸（部分図とレイヤグループの縮尺）だけを扱い、地図の座標系を持たなかった。SXF の測地座標系の部分図（X が北、Y が東）は、X と Y を入れ替えて表示の向きにした。
- 形式は、それぞれの書き方で座標系を持つ。
  - SXF: 部分図ごとに、数学座標系か測地座標系か
  - IFC: `IfcMapConversion`（`Eastings`・`Northings`・`OrthogonalHeight`・X 軸の向き・縮尺）と、地図の座標系の名前
  - J-LandXML・CityGML: 座標系の名前と、その軸の順の座標
- 平面直角座標系は、平成 14 年国土交通省告示第 9 号（最終改正は平成 22 年国土交通省告示第 289 号）で決まる。
  - 19 の系があり、ガウスの等角投影法による。
  - X 軸は原点で子午線に一致し、北を正とする。Y 軸は東を正とする。数学の向きと逆になる。
  - X 軸上の縮尺係数は 0.9999。楕円体の長半径と扁平率は、測量法施行令第 3 条が決める（GRS80）。
- 国土地理院の測量計算サイトは、経緯度と平面直角座標の換算に、河瀬（2011）の式（国土地理院時報 第 121 号）を使う。
- 2025-04-01 に、国土地理院は全国の標高成果を改定した（2026-10-24 に、国土地理院の頁と Q&A で確かめた）。
  - 改定後の成果は「測地成果2024」。緯度・経度と平面直角座標は変わらず、標高と楕円体高が変わった。三角点の標高の改定量は、最大で +57 cm と −67 cm。
  - 標高は、衛星測位の楕円体高からジオイド高を引いて求める。ジオイド・モデルは「ジオイド2024日本とその周辺」（JPGEO2024）。吐噶喇列島以南と八丈島以南の離島では、基準面補正量も引く。
  - 測地系の名前は、「日本測地系2011（JGD2011）」から「日本測地系2024（JGD2024）」に変わった。定義は変わらない。
- EPSG の登録簿（2026-10-24 に、EPSG の API で確かめた）
  - JGD2011 の名前を JGD2024 に変えた。定義と座標の値は変わらず、コードも同じ（地理座標は EPSG:6668、平面直角座標系 I〜XIX は EPSG:6669〜6687）。JGD2011 の名前は別名に残る。
  - 平面直角座標系の軸は、northing・easting（X・Y）の順。
  - 標高の CRS は、新しい JGD2024 (vertical) height が EPSG:11317、それまでの JGD2011 (vertical) height が EPSG:6695。平面直角座標系と標高を組んだ複合の CRS もあり、番号は連続しない。
  - 古い測地系の平面直角座標系は、JGD2000 が EPSG:2443〜2461、日本測地系（Tokyo）が EPSG:30161〜30179。
- 座標の換算の部品（2026-10-24 に、crates.io とソースで確かめた）

| crate | 版 | ライセンス | 中身 | [0007](0007-single-rust-implementation.md) の規則との関係 |
| --- | --- | --- | --- | --- |
| proj | 0.31.0 | MIT OR Apache-2.0 | C の PROJ の結合 | C の PROJ と SQLite が要り、浮動小数の関数も C のものになる |
| proj4rs | 0.2.1 | MIT OR Apache-2.0 | proj4js の Rust への移植 | std の三角関数を使う |
| geographiclib-rs | 0.2.7 | MIT | 測地線の計算。投影は持たない | std の三角関数を使う |
| jgdtrans | 0.3.1 | MIT OR Apache-2.0 | TKY2JGD・PatchJGD・SemiDyna のパラメータによる変換 | std の `hypot` と HashMap を使う |

- 平面直角座標は、原点から 10^5 m 級の値になる。f32 の隣り合う値の間隔は、65,536〜131,072 m で約 7.8 mm、262,144〜524,288 m で約 3.1 cm になる。

## 選択肢

### 座標の型

1. **1 つの点の型に、座標系の名前を値で付ける。** 取り違えは実行時にしか見つからない。
2. **空間ごとに型を分け、空間の間の変換も型で表す。** 取り違えをコンパイルの時に見つける。

### 換算の実装

1. **C の PROJ を結合する。** 座標系の対応は広い。ただし C の道具とデータベースが要り、wasm32-unknown-unknown に向かない。データベースの分だけ、配るものも大きくなる。結果も C の数学関数に頼る（[0007](0007-single-rust-implementation.md)）。
2. **純 Rust の crate（proj4rs など）を使う。** std の三角関数を使うので、0007 の規則に合わない。
3. **日本で要る換算だけを自前で持つ。** 告示と国土地理院が公開する式から書き、libm を使う。

### 国土地理院のデータ

1. **同梱する。** 利用者はすぐ使える。ただし測量法の承認が要り、版の更新も追いかける。
2. **同梱せず、利用者が入手して渡す。**

## 決定

座標の型は 2、換算は 3、国土地理院のデータは 2 を選ぶ。

### 座標の空間

| 空間 | 単位 | 軸 | 例 |
| --- | --- | --- | --- |
| 用紙 | mm | X が右、Y が上。原点は用紙の左下 | 文字高、矢印の大きさ |
| 図面の実寸 | 文書の長さの単位 | 部分図・ビューポート・レイヤグループの中の座標 | 実寸の図形 |
| プロジェクト | 文書の長さの単位 | X・Y・Z（Z が上） | IFC の配置 |
| 地図 | m | 北（northing）・東（easting） | 平面直角座標 |
| 地理 | 度 | 緯度・経度 | JGD2024 の経緯度 |
| 高さ | m | 上 | 標高、楕円体高 |

- 空間ごとに型を分ける。幾何の型（[0018](0018-geometry-layers-and-tolerances.md)）は、空間を型の引数に持つ。
- 空間の間の変換も型で表す。実寸から用紙への配置（部分図・ビューポート）、プロジェクトから地図への変換（IFC の `IfcMapConversion`）、地理と地図の間の投影。変換を通さずに、別の空間の点を混ぜられない。
- 地図の座標の成分は、`x`・`y` と呼ばず、`northing`・`easting` と呼ぶ（EPSG の軸の名前）。境界のメッセージ（[0012](0012-boundary-functions-and-messages.md)）と表の列も、同じ名前にする。
- 軸の順は、読み書きの所で型に直す。コーデックと lift・lower が、形式ごとの順（SXF の測地座標系の部分図、IFC の `Eastings`・`Northings` など）を読み、型に入れる。L2 から先は、軸の順を気にしない。

### 座標系の名前

- 地図と高さの座標系は、EPSG のコードで名指す。
- JGD2011 と JGD2024 は、同じ定義の名前として扱う。読むときはどちらも受け付ける。書くときの名前は、出力先の形式とプロファイル（[#9](https://github.com/zumen-jp/zumen/issues/9)）が決める。
- EPSG のコードは識別子として使い、定義（原点と縮尺係数）は告示から書く。EPSG Dataset の定義を写すときは、その利用条件に従い、IOGP の持ち物であることを書く。

### 標高

- 標高は、高さの基準と成果を持つ。
  - 基準: 東京湾平均海面（T.P.）、離島の独自の平均海面、楕円体（GRS80。楕円体高のとき）
  - 成果: 測地成果2011（2025-03-31 まで）、測地成果2024（2025-04-01 から）
- 成果の違う標高は、同じ地点でも数十 cm 違うことがある。黙って比べたり、足したりしない。違う成果の値を一緒に使うときは、診断を返す。
- 形式が成果を書いていなければ、仮定して `assumed` の診断にする（[0009](0009-diagnostics-and-catalog.md)）。

### 換算を自前で持つ

- crate `zumen-crs`（[#1](https://github.com/zumen-jp/zumen/issues/1) の crs）に、次を持つ。
  - 経緯度と平面直角座標の換算。河瀬（2011）の式で、三角関数は libm を使う（[0007](0007-single-rust-implementation.md)）
  - 19 の系の原点と、EPSG のコードとの対応
  - ジオイド高と基準面補正量の補間。国土地理院の説明書の方法（ISG 形式の格子の、双一次の補間）で、格子は利用者が渡す
- 測地系の間の変換（日本測地系から JGD2000 への TKY2JGD、地震の後の PatchJGD）は、その座標を持つ形式を読むときに足す。パラメータの格子は、利用者が渡す。
- ほかの座標系（UTM など）は、需要が出たら記録を書いて足す。それまでは、ホストの側の道具で変換してもらう。
- 換算の試験の期待値は、告示と式から書く。国土地理院の測量計算サイトの結果との照合は、検証の記録に残す。

### 国土地理院のデータ（2026-10-24 に確かめた結果）

| データ | 入手 | 条件 |
| --- | --- | --- |
| ジオイド2024日本とその周辺（JPGEO2024）と基準面補正パラメータ | 基盤地図情報のサイト。ISG 形式（ISG format 2.0）と GML 形式。格子は緯度 1 分・経度 1.5 分で、北緯 15〜50 度・東経 120〜160 度 | 基本測量の測量成果で、測量法第 29 条（複製）・第 30 条（使用）の承認が要る場合がある。要る場合として、測量に使う、不特定多数が入手できる状態に置く、ジオイド・モデルを組み込んだソフトウェアを開発する、配布のために形式を変える、が挙がっている。研究・調査に使うだけなら、出典を示せばよい。名前（「ジオイド2024日本とその周辺」「JPGEO2024」「基準面補正パラメータ」）は国土地理院の登録商標 |
| 日本のジオイド2011（Ver.2.2 まで） | 国土地理院のジオイド・モデルの頁 | 基本測量の測量成果で、上と同じ。2025-03-31 まで使われた |
| TKY2JGD のパラメータ（Ver.2.1.2） | TKY2JGD の頁 | 頁に申請の要否の記載はない。ソースコードは国土地理院コンテンツ利用規約に従う |
| PatchJGD のパラメータ | 座標補正パラメータファイルの頁 | 頁に申請の要否の記載はない |
| 国土地理院コンテンツ利用規約 | — | 公共データ利用規約（第 1.0 版）（PDL1.0）を適用する（2025-11-20 改正）。使うときは出典を書く。基本測量の測量成果の複製と使用には、測量法の申請が要る |

- zumen は、これらのデータも、形式を変えたものも、パッケージ・リポジトリ・試験に入れない。
- 利用者が国土地理院から入手し、ほかの入力と同じく `zm_push` で渡す（[0012](0012-boundary-functions-and-messages.md)）。
  - 測量に使う利用者は、国土地理院に承認を申請する。
  - zumen を使うアプリがジオイド・モデルを同梱して配るなら、そのアプリが承認を得る。
  - 文書に、入手先と、承認が要る場合があることを書く。
- 渡されたモデルの版（JPGEO2024 か、ジオイド2011 か）を判別し、計算に使った版を結果に記録する。
- 試験は、合成の格子で行う。
- 同梱したくなったら（ブラウザの利用者のためなど）、先に国土地理院に問い合わせ、承認を得てから、記録を書く。

### 大きな座標を GPU へ渡す

- L2 と L3 の計算は、f64 の座標で行う。
- 表示用のシーン（[#6](https://github.com/zumen-jp/zumen/issues/6) のバイナリ）は、塊ごとに f64 の原点と、そこからの f32 の相対座標で持つ。塊の大きさは、相対座標が表示の許容差（[0018](0018-geometry-layers-and-tolerances.md)）を表せる範囲にする。
- 表示エンジンは、カメラの位置を塊の原点から引いてから f32 にする。
- 原点の選び方と、バイナリの中の配置は、#6 で測って決める。

## 影響

- 旧版の SXF の測地座標系の扱い（X と Y の入れ替え）は、空間の型の変換に置き換わる。
- `zumen-crs` は、段階 0（[#1](https://github.com/zumen-jp/zumen/issues/1)）で、平面直角座標系の換算から作る。ジオイドの補間は、楕円体高を持つデータ（衛星測位で測った点群など）を標高と合わせるときに使う。
- ジオイド・モデルがないと、楕円体高と標高の換算はできない。その操作は、何が足りないかを診断で返す。
- 標高の成果を持つことは、設計の値と測った値の照合（出来形など）で効く。
- 地図の座標と標高を持つ形式を足す PR は、軸の順と成果の扱いを、形式の文書に書く。
- [#12](https://github.com/zumen-jp/zumen/issues/12) は、この記録で完了する。

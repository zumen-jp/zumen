# 0249: SXF の属性ファイル（SAF）を読み、属性ファイル用の属性付加機構の要素に属性ごとの拡張で結ぶ

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-03 |
| 状態 | 採用 |

## 背景

SXF の属性付加機構のうち、属性ファイル用（ATRF）は、作図グループの名前に `$$ATRF$$図形識別番号$$属性ファイル名` と書き、属性は図面とは別の属性ファイル（SAF）に書く（SXF Ver.3.1 仕様書・同解説の附属書の属性付加機構編の 2-3・2-4-1）。属性ファイルは XML で、図形識別番号ごとの図形（`Figure`）に、属性セット（`AttrSetRef`）ごとの属性（`Attr`）と属性のグループ（`AttrGroup`）を書く（同 3 章）。P2Z・SFZ は、図面と属性ファイル・画像を 1 つの書庫に入れる。

[決定 0131](0131-sxf-attribute-mechanism.md) は、作図グループの名前の記述を要素の `sxf.attribute` の拡張に残し、関連ファイル（属性ファイル）は読まないとした。[決定 0204](0204-profile-sheet-line-widths-and-file-names.md) は、SAF を読み書きしないので、SAF のファイルの名前の規則（CAD製図基準の図 1-7）をプロファイルに足さなかった。属性ファイルの属性は、横断図の測点・地盤高や土量の計算方法のような、図面の利用に要る値を持つ（#386）。

## 選択肢

### 属性の持ち方

1. 属性ごとに、`sxf.saf` の拡張を、`$$ATRF$$` の作図グループを置いた要素に付ける。拡張の名前を属性名にし、値は図形・属性セット・グループ・属性タイプ・単位・属性値の欄にする。
2. 図形ごとに 1 つの拡張にし、属性を欄の並びで持つ。
3. 属性を図面モデルの共通の欄（要素の属性の値）にする。

### 属性ファイルの渡し方

1. P2Z・SFZ の中の、図面と同じ名前の SAF を使い、別の入力も `open` で名指せるようにする。
2. P2Z・SFZ の中の SAF だけを使う。
3. 属性ファイルを別の文書として開き、図面と組にする op を足す。

## 決定

どちらも選択肢 1 を採る。拡張は要素ごとの追加の情報で、要素の形と共通の欄を変えない（[決定 0115](0115-drawing-format-extensions.md)）。属性ごとに分けると、属性名で引け、ほかの拡張と同じ形で読める。属性の意味（既定義属性の役割や `$$$`）は運用ごとに違うので、値は解かずに文字のまま持つ（決定 0131 と同じ）。

### 読み方

- 属性ファイルは `zumen-sxf` の `saf` で、XML（`zumen-xml`）として読む。根は `SxfAttributeXML`。仕様の DTD は解決せず、文書型宣言の診断（`xml.dtd.dropped`）は返さない。
- 省略できないタグ属性がないものと、重なる図形識別番号（3-4 の (3)）は、`sxf.saf-value.invalid` を返す。重なる図形は初めのものだけを使う。知らない要素は `sxf.saf-element.unsupported` を返す。
- 属性のグループは、仕様は 2 階層までとするが、8 階層までは読む。

### 結び方

- 図面モデルへの変換で、`sxf.attribute` の拡張の値が `ATRF` で始まる要素（作図グループを置いた要素）に、同じ図形識別番号の図形の属性を、属性ごとに `sxf.saf` の拡張で付ける。拡張の名前は属性名、版は属性ファイルの `version`。欄は次の順にする。
  - `figure`（図形識別番号）・`figure_name`（図形名称）・`set`（属性セット識別番号）
  - 属性セットが属性ファイルにあれば `set_name`・`set_version`・`designed_by`
  - グループの中なら `group`（外からのグループの名前を `/` でつなぐ）
  - 書いてあれば `type`（属性タイプ）・`unit`（単位）
  - `value`（属性値。`$$$` もそのまま）
- 図面の `$$ATRF$$` の図形識別番号の図形が属性ファイルになければ `sxf.saf-figure.missing` を、属性ファイルの図形の番号を持つ要素が図面になければ `sxf.saf-figure.dropped` を返す。
- 属性ファイルがなければ、今までどおり `sxf.attribute` だけを付ける。

### 渡し方

- `open` に `saf`（属性ファイルを入れた入力の名前）を足す（小版 63）。SXF（P2Z・SFZ を含む）でない入力に書けば `call.value.invalid` にする。
- `saf` がなければ、P2Z・SFZ の中の、図面と同じ名前の SAF を使う。名前は、拡張子を `.SAF` にしたもの（CAD製図基準の図 1-7）か、図面の項目の名前に `.SAF` を足したもの（附属書の 2-3 の「図面ファイル名.SAF」）で、大文字と小文字を区別しない。ほかの名前の SAF は結ばず、今までどおり `entries` に名前を返す。
- 属性ファイルが読めなければ、その診断を返し、属性ファイルなしで図面を開く。

### 書き出し

- 属性ファイルは書き直さない。P2Z・SFZ への `apply` は、今までどおり SAF の項目を展開したバイト列のまま写すので、図面の `$$ATRF$$` の名前と属性ファイルの図形識別番号の対応は保たれる。別の入力で渡した SAF は、呼び出し側が持つ。
- 別の形式に書き出すとき、`sxf.saf` は、ほかの形式固有の拡張と同じく、書き出さない（決定 0115）。

### プロファイル

- `mlit-cad` の `file-name` の規則の拡張子に `SAF` を足す（revision 4）。SAF のファイルの名前は、元図の CAD データの名前と同じ規則（図 1-7）なので、規則を分けない。

## 影響

- メッセージのスキーマの小版を 63 に上げた。`open` の要求に `saf` が増えた。
- 診断の code に `sxf.saf-element.unsupported`・`sxf.saf-value.invalid`・`sxf.saf-figure.missing`・`sxf.saf-figure.dropped` を足した。
- 属性ファイルを持つ P2Z・SFZ を開くと、図面モデルに `sxf.saf` の拡張が増える。
- 属性の追加・変更（属性ファイルの書き直し）は、まだしない。要るときは、`sxf.saf` の拡張の変更から属性ファイルを書く道を、別に決める。

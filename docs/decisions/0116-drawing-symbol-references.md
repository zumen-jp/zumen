# 0116: 図面モデルの記号の配置は展開せず、定義のない配置と輪になる定義を診断する

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

対応表の E9 は、循環する部品・欠けた定義・非有限の倍率・展開上限を超える配置を置き、パニックせず診断し、上限で止めることを試す。[決定 0112](0112-drawing-symbol-definitions.md) で、記号の定義は配置と別の空間に持ち、配置は展開しないことにした。いまの変換は、配置が指す定義があるかも、定義が自分を配置するかも確かめていない。

## 選択肢

1. 変換の最後に、配置が指す定義と、定義から定義への配置の輪を確かめて診断する。配置と定義は移したまま持つ。
2. 定義のない配置と、輪になる定義を移さない。
3. 確かめず、展開する側に任せる。

## 決定

選択肢 1 を採る。配置は展開しないので、定義がなくても輪になっても、配置の位置や属性は意味を持つ。移さないと、その情報を落とす。展開する側だけに任せると、変換の結果を使う側が、輪を見つけるまで展開を進めてしまう。

- 実寸の空間・用紙・記号の定義の空間の配置（`Shape::Symbol`）が指す定義がなければ、`dxf.block.missing` を返す。
- 定義の中の配置をたどり、自分に戻る定義ごとに `dxf.block-cycle.invalid` を返す。輪の中にない定義が輪の定義を配置しても、診断しない。
- 確かめる手間は、配置 1 つと、たどる辺 1 つごとに 1 と数える。格子の配置は展開しないので、行と列の数で手間は増えない。

## 影響

- 表のセルと表を描いたブロック、寸法・引出線・寸法スタイルが指すブロックは、まだ確かめない。
- 外部参照の定義は、中身を読まないので、輪を見つけられない。
- 展開する op を作るときは、この診断を前提にせず、展開の深さと数を予算で止める。

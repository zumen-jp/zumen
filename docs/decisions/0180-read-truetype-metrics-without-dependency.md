# 0180: TrueType のフォントの寸法は、依存を足さずに要る表だけを zumen-drawing で読む

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-30 |
| 状態 | 採用 |

## 背景

文字の配置（[決定 0176](0176-text-layout-with-glyph-metrics.md)）は、フォントの寸法を trait `Glyphs` で受け取る。呼び出し側が渡したフォントのファイルから、その値（em・アセンダー・ディセンダー・大文字の高さ・文字ごとの送りと外形）を読む方法を決める（#328）。フォントは受け取ったファイルなので、パニックせず、作業量に上限を持ち、ネイティブと wasm32 で同じ結果を返す必要がある（[決定 0007](0007-single-rust-implementation.md)・[決定 0010](0010-budget-by-work.md)）。

## 選択肢

1. `ttf-parser`（MIT OR Apache-2.0、unsafe なし、no_std）を足す。
2. `read-fonts`・`skrifa` を足す。
3. 要る表（`head`・`hhea`・`maxp`・`OS/2`・`cmap`・`hmtx`・`loca`・`glyf`）だけを自前で読む。

選択肢 1 を試した。ライセンスと wasm32 は満たすが、次の点で規則に合わなかった。

- 壊れた `cmap` の形式 12（群の数が大きいもの）で、`debug_assert` が働き、デバッグの組み立てでパニックした。合成のフォントのバイトを変える試験で見つけた。
- 長さと位置の計算を `usize` で行う所があり、溢れたときの結果が 32 ビット（wasm32）と 64 ビットで変わりうる。
- 字形の外形を輪郭をたどって求める。複合の字形が自分を何度も参照すると、作業量が入れ子の深さ（32）の指数で増える。CFF のサブルーチンも同じである。

選択肢 2 は、表の種類が多く依存が大きい。要るのは数個の表の数個の値だけである。

## 決定

選択肢 3 を採り、`zumen_drawing::font` に置く。配置と同じ crate に置き、新しい crate は作らない。

- **読むもの。** OpenType の仕様に従い、em は `head` の unitsPerEm、アセンダー・ディセンダーは `OS/2`（版 4 以降）の USE_TYPO_METRICS が立てば sTypo の値、立たなければ `hhea` の値を読む。大文字の高さは `OS/2`（版 2 以降）の sCapHeight で、なければ `H` の字形の外形の上、それもなければアセンダーにする。送りは `hmtx`、外形は `loca` で引いた `glyf` の字形の見出しの値で、輪郭はたどらない。
- **文字から字形。** `cmap` の Unicode の副表の形式 12 を使い、なければ形式 4 を使う。どちらもなければ読まずに理由を返す。字形 0 に当たる文字・字形の数を超える番号に当たる文字・区間の壊れた字形は、フォントにない文字とし、字形 0 で置く。
- **受け取ったファイル。** 位置と長さをすべて確かめ、足し算と掛け算は `u64` か溢れを確かめて行う。整数だけで読み、浮動小数の計算をしない。表がない・壊れているときは、読まずに表の名前を返す。
- **予算。** 読むときの作業は表の数（最大 65535）で抑えられ、文字ごとの作業は副表の二分探索で抑えられる。入れ子をたどらないので、予算（決定 0010）は数えない。
- **扱わないもの。** CFF・CFF2 の外形のフォントは、まだ読まずに理由を返す。可変フォントの変化・縦書きの寸法・カーニングは読まない。
- **SHX。** AutoCAD の形のファイル（SHX）は読まない。Autodesk が公開しているのは形の定義の書き方（SHP の文）で、組み立てた SHX の並びは公開されていない。読むなら公開された資料と推定によることになり、先に `formats/ledger.toml` と同じ扱いで入手先と根拠を確かめる。TrueType と違い、SHX のフォントは利用者の手元にも少ない。

## 影響

- 依存を足さないので、Cargo.toml と cargo-deny の設定は変わらない。
- 試験はフォントを同梱せず、試験の中で最小の TrueType のバイト列を組み立てる。バイト列を切り詰めたり 1 バイトずつ変えたりしても、パニックしないことを確かめる。
- 境界（zumen-abi・schema/）でフォントを受け取ることは、別の issue で決める。
- 残る作業は、CFF の外形（字形の命令を解釈し、作業量を予算で数える）、SHX を読むかの判断、表示と比べた寸法の選び方（アセンダーの選び方など）の確認で、それぞれ issue で追う。

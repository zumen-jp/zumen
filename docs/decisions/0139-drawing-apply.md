# 0139: 図面モデルの変更は、ID と前提条件で要素を指す変更の一覧にし、共有の表を通して元の形式へ書き戻す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-28 |
| 状態 | 提案 |

## 背景

[#170](https://github.com/zumen-jp/zumen/issues/170) で、図面モデル（Drawing2D）の変更を、元の系統の L1 へ書き戻す（apply）。これまでの決定は次のとおり。

- L2 から L1 への向きは `lower`（別の形式への変換と新規作成）と `apply`（その場の編集）に分け、形は AutoCAD の系統の試作で決める（[決定 0008](0008-model-layers-and-codecs.md)）。中水準の変更セットは、元のハッシュを前提条件に持つ。
- 図面モデルの要素は、元のレコードを指す出所（`Ref`）を持つ（[決定 0022](0022-drawing2d-semantics-and-format-mapping.md)）。
- DXF と DWG は、共有のオブジェクトの表 `AcadDb` を持つ。表の変更は `write_back` が元のレコードと比べて、違うレコードだけを 1 つのトランザクションで書き戻す。書き戻せない変更が 1 つでもあれば、何も反映しない（[決定 0024](0024-acad-table-write-back.md)・[決定 0025](0025-acad-object-add-remove-write-back.md)）。

この決定の最初の案は、要素を出所で指す置き換えと除去の一覧だった。main には、実寸の空間と用紙の LINE・CIRCLE・ARC・ELLIPSE・LWPOLYLINE・TEXT・MTEXT・INSERT の形の置き換えと、続くレコードを持たない図形の除去と、図形とともに動く XDATA の扱い（[決定 0154](0154-drawing-apply-keeps-format-data.md)、提案）と、要素の追加（`Edit::Add`・`Edit::AddOnSheet`。[決定 0155](0155-drawing-apply-additions.md)、提案）がある。作ってみて、次のことが分かった。

- 出所（レコードの番号・バイトの位置）は、書き戻すとずれる。使い手は、変更のたびに読み直す必要がある。
- 変更は、使い手が読んだときと要素が同じかを確かめない。
- 置き換えは、レイヤとスタイルが同じことを求める。レイヤや色だけを変える変更を表せない。
- 図形を動かす変更は、形の置き換えとして渡すので、図形とともに動く XDATA の変換を一意に決められない（0154）。
- 用紙の要素の置き換えと追加に、別の種類の変更（`ReplaceOnSheet`・`AddOnSheet`）が要った。記号の定義の中の要素は指せない。
- 足した要素の出所は、書き戻したファイルを読み直すまで決まらない（0155）。足した直後の要素を、同じ変更の一覧で直せない。
- 記号（INSERT）を置き換えても、続く属性（ATTRIB）は動かない。
- 指せない変更の診断が、形式ごと（`dxf.*`・`dwg.*`）に分かれている。変更そのものは形式によらない。

## 選択肢

1. 変更の一覧。要素を ID（[決定 0156](0156-drawing-stable-ids-and-preconditions.md)）と読んだときのハッシュで指し、置き換え・スタイルの変更・移動・追加・除去を並べる。apply は一覧の変更だけを書き戻し、足した要素の ID を返す。
2. 編集した図面モデル全体を渡し、apply が元の図面モデルと比べて変更を見つける。
3. 図面モデルの型ごとに、L1 を直接変える関数（線の端点を動かす、など）を置く。

2 は、比べる手間が図面の大きさに比例し、要素の順の入れ替えや、移せなかった要素との区別が難しい。3 は、関数が形式の系統と要素の種類の組ごとに増え、境界のメッセージにも写しにくい。

## 決定

選択肢 1 を提案する。

- **trait。** `zumen_sdk::Apply<C>` を置く。`apply(&mut self, changes: &C, cx)` は、すべての変更を確かめてから反映する。1 つでも当てられなければ何も反映せず、当てられない変更ごとの診断と一緒に `Error::Rejected` を返す。最初の 1 つで止めない。当てたときは、変更ごとの新しい ID とハッシュ（0156）を返す。0008 の素案の `Lower` は、別の形式への変換を作るときに足す。
- **変更の一覧。** `zumen_drawing::Changes` は、`Edit` の一覧と、あれば読んだときの文書のハッシュを持つ。どの変更も、指す要素の ID と、読んだときの要素のハッシュを持つ。
- **変更の種類。**
  - `Replace`: 要素の値（レイヤ・スタイル・形）を置き換える。形の種類は変えない。種類を変えるときは、除去と追加にする。
  - `Restyle`: 要素の並びの、レイヤ・色・線種・線幅・文字スタイル（[決定 0158](0158-drawing-text-styles.md)）のうち、指したものだけを変える。形は変えない。
  - `Transform`: 要素の並びを、使い手が渡す変換（`Affine`）で動かす。AutoCAD の系統では、図形とともに動く XDATA を、AutoCAD と同じ規則で直す。位置（1011）は移動・尺度・回転・鏡映、変位（1012）は尺度・回転・鏡映、向き（1013）は回転・鏡映、距離（1041）と倍率（1042）は尺度で直す。記号の属性も一緒に動かす。変換が渡されるので、0154 の選択肢 4 の「変換を一意に決められない」はなくなる。変換した形を元の種類で表せないもの（円の非一様な尺度など）と、非一様な尺度で 1041・1042 を持つものは、当てない。
  - `Add`: 空間・用紙・記号の定義の空間に要素を足す。足す先は、空間か用紙の ID で指す。AutoCAD の系統では、`$HANDSEED` から振ったハンドルを ID にし、空間のブロックのレコードを所有者にする。ハンドルは apply が決めるので、読み直さずに足した要素の ID を返す。書き方と足せる形は、0155 に従う。
  - `Remove`: 要素を除く。続くレコード（VERTEX・ATTRIB・SEQEND）も一緒に除く。
- **指せるもの。** 実寸の空間・用紙・記号の定義の空間の要素を、同じ変更の種類で指す。ID が空間か用紙かを表すので、用紙のための別の種類を置かない。レイヤ・線種などの表の項目の変更は、のちに足す。
- **形式の系統。** DXF と DWG は、今のファイルから表を作り、変更を表のオブジェクトに当ててから `write_back` で書く。どちらの符号化でも同じ当て方を使う。JWW と SXF も、同じ `Changes` を受け取る apply を、それぞれの L1 の上に作る。
- **確かめること。** 当てる前に、すべての変更を次の順で確かめる。
  - 文書のハッシュがあれば、今の文書と同じか（`change.document.stale`）。
  - ID の要素があるか（`change.element.missing`）と、ハッシュが同じか（`change.element.stale`）。
  - 変更を元の形式のレコードで表せるか（`change.edit.unsupported`。変更の種類・要素の種類・形式を値に持つ）。
  - 形を変える `Replace` で、元の図形が図形とともに動く XDATA を持たないか（0154 の規則。`change.xdata.unsupported`）。形を動かすときは `Transform` を使う。
- **診断の名前空間。** 変更の診断は、形式によらない名前空間 `change` にする。`dxf.element.missing`・`dxf.change.unsupported`・`dwg.change.unsupported` は、台帳で廃止にする（[決定 0009](0009-diagnostics-and-catalog.md)）。0154 の `dxf.xdata.unsupported` も、`change.xdata.unsupported` に移して廃止にする。
- **手間。** apply は、ID から要素への索引を 1 回だけ作る。図面モデルへの変換も、1 回の apply で 1 回にする。手間は、文書の大きさと変更の数の和に比例する。
- **今の範囲。** 変更の一覧は、ID と読んだときのハッシュで要素を指し、文書のハッシュを持てる。DXF と DWG は、実寸の空間と用紙の LINE・CIRCLE・ARC・ELLIPSE・LWPOLYLINE・TEXT・MTEXT・INSERT と、制御点で決まる SPLINE の形の置き換えと、続くレコードを持たない図形の除去と、同じ形の追加（足す先を空間か用紙の ID で指す。0155）と、`Restyle`（DWG は色と線種の倍率だけ）と、`Transform`（線と、膨らみと幅を持たない折れ線はどのアフィン変換でも。円・弧・楕円・ほかの折れ線・文字・記号は相似、書式つきの文字と、書式つきの属性を持つ記号は鏡映を含まない相似でだけ。記号の鏡映は Y の尺度の符号を変え、文字の鏡映は上下の反転の印を入れ替えて表す。格子の間隔には尺度を掛け、鏡映では行の間隔の符号を変える。図形とともに動く XDATA と属性も同じ変換で直す）を当て、変更ごとに新しい ID とハッシュを返す。記号の定義の中の要素も、置き換え・`Restyle`・`Transform`・除去で指せる（決定 0156 の定義の空間の ID）。記号の定義の空間への追加・続くレコードの除去・文字スタイルの変更（0158）は、まだない。書式つきの文字（MTEXT）の鏡映は、まだないものではなく、形式の限界とする。MTEXT は TEXT と違い、字形を左右・上下に反転させる印を持たないので、鏡映した形を正しく表せない。`Transform` は、鏡映を含む変換を書式つきの文字に当てず、`change.edit.unsupported` にする。

## 影響

- 今の `Edit::ReplaceOnSheet`・`Edit::Add`・`Edit::AddOnSheet` は、ID で指す `Replace` と、足す先を ID で指す `Add` にまとめる。0155 の「出所は読み直して決める」は、ID を返す形に替わる。書き方・足せる形・名前で指す定義の扱いは、0155 のまま使う。
- 境界の op として変更を受けるときは、`Changes` の形をメッセージのスキーマに写す。ID とハッシュは、`entities` の op が返す文字列をそのまま使う。
  - 境界の `apply` の op を作った（メッセージのスキーマの小版 7）。要求は文書の名前・あれば文書のハッシュ・変更の並びを持ち、変更は `kind` で `restyle`・`transform`・`remove` を選ぶ。結果は、変更ごとの書き戻した後の ID とハッシュと、書き戻した文書のハッシュを返し、書き戻したファイルを `blobs` の `file` で返す。文書は書き戻したものに替わるので、続けて `entities` と `apply` を呼べる。
  - `restyle` のレイヤと線種は、元の名前で指し、図面の中で名前が 1 つに決まるものだけを受ける。`entities` がレイヤを名前で返すため。
  - 続く PR で、レイヤと線種の表の項目を ID・名前・ハッシュで返す `tables` の op を足し、`restyle` の `layer_id` と線種の `id` で、表の項目を ID でも指せるようにした（小版 8）。DXF は名前で書くため、同じ名前の表の項目が複数あるときは ID でも書き戻さない。表の項目そのものの変更（名前・色の変更、追加、除去）は、まだない。寸法スタイルも `tables` で ID・名前・ハッシュを返すようにした（小版 9）。
  - 続く PR で、形の値（`geometry`）で形を置き換える `replace` と、空間か用紙に要素を足す `add` を境界に足した（小版 10）。形の値は `shape` で線分・円・円弧・折れ線・文字を選び、点は要素の空間か用紙の座標、角度は度で持つ。`entities` も、`fields` に `geometry` を入れると同じ形の値を返す（決定 0118 で後に回した欄）。
    - `replace` は、形の種類を変えず、レイヤとスタイルも変えない。折れ線は元の幅を保ち、頂点ごとの幅を持つものは置き換えない。文字は、元の文字の位置合わせ・高さの意味・文字スタイルを保ち、内容・位置・高さ・回転を替える。1 点に置かない文字（2 点の間に合わせるもの）と、改行を含む内容は受けない。
    - `add` は、足す先を空間か用紙の ID で指し、レイヤを `layer` か `layer_id` で選ぶ。どちらもなければ、レイヤ「0」に置く。色・線種・線幅はレイヤに従い、線種の倍率は 1 にする。
    - 続く PR で、楕円と楕円の弧も形の値にした（小版 11）。中心・長軸の端の点・短軸の長軸に対する比と、楕円を円に引き延ばしたときの角度（度）で持つ。時計回りの弧は、同じ点をたどる反時計回りの弧として返す。R12 の DXF は ELLIPSE を持たないので、足すと `change.edit.unsupported` になる。
    - 続く PR で、文字も足せるようにした（小版 12）。足す文字は、左・基線に合わせ、幅の係数を 1、斜体の角度を 0 とし、反転を持たず、高さは DXF の TEXT の高さ（コード 40）の意味で持つ。文字の形の値に `style` を足した。`entities` は文字スタイルの名前を返し、`add` は図面にある文字スタイルの名前を受ける（省けば `Standard`）。DXF に文字スタイルの定義がないときは `Standard` だけを受ける。`replace` は文字スタイルを変えないので、元と同じ名前だけを受ける。DXF の 2007 より前の版は ASCII の文字しか書けないので、それ以外の内容を足すと `change.edit.unsupported` になる。レイヤ「0」を持たない図面（Jw_cad が書いた R12 の DXF など）では、`layer` か `layer_id` でレイヤを指す必要がある。
    - 続く PR で、書式つきの文字（MTEXT）も形の値にした（小版 13）。内容は書式の符号（`\P` の改行など）を含めた元の形式のまま持ち、基点・高さ・回転（度）・枠の位置合わせ（9 つ）・折り返す枠の幅・文字スタイルの名前を持つ。図面モデルの書式の区間は、読むときと同じ解釈で内容から作る。
      - `replace` は、枠の高さ・書き進める向き・行送り・背景・高さの意味・文字スタイルを元の値のままにする。位置合わせを書かなければ元のまま、枠の幅を書かなければ折り返さない。向きは元と同じ形（角度か X 軸の向き）で書く。
      - `add` は、左上に合わせ、枠の高さなし・左から右・行送り 1 倍・背景なしで足す。0 でない回転は、DWG にも書けるよう X 軸の向きとして書くので、読み直した角度は末の桁で違うことがある。
      - 生の改行（`\n`）を含む内容は受けない。用紙では、内容の中の絶対の高さなどを mm に直す倍率を書き戻す側しか知らないので、そうした書式を持つ内容は受けない。R12 の DXF は MTEXT を持たないので、足すと `change.edit.unsupported` になる。
    - 続く PR で、ブロックの記号（INSERT）も形の値にした（小版 14）。定義（ブロック）の名前・置く点・X と Y の尺度・回転（度）と、格子に並べるなら列と行の数と間隔を持つ。切り抜きは形の値に含めない。
      - `replace` は、定義・格子の列と行の数・属性・切り抜きを変えない（属性の値は、小版 21 から変えられる）。属性は続くレコードにあり、置く点などに合わせて動かせないので、属性を持つ記号の置く点・尺度・回転を変えると `call.value.invalid` で `/edits/0/geometry` を指して失敗する。属性ごと動かすときは `transform` を使う。
      - `add` は、図面にある定義の名前を指し、切り抜きを持たない記号を足す。図面にない定義は `change.edit.unsupported` になる。1×1 の格子は、読み直すと格子なしになるので受けない。
    - 続く PR で、制御点で決まるスプライン（NURBS）も形の値にした（小版 15）。次数・節点・制御点と、有理なら制御点ごとの重み、閉じているか・周期的かを持つ。DXF と DWG の SPLINE の置き換えと追加も、ここで作った。
      - 置き換えは、印（70）の閉じている・周期的・有理と、次数・節点・制御点・重みを書き直し、ほかの印と許容差（42〜44）は元のままにする。足す SPLINE は平面の印を立て、節点と制御点の許容差を DXF の既定の 1e-7 とする。DWG の制御点のスプラインは、どちらの許容差も持つため。
      - R12 の DXF は SPLINE を持たないので、足すと `change.edit.unsupported` になる。当てはめる点か接線を持つスプラインは、小版 18 で扱う。
    - 続く PR で、記号の形の値に属性（`attributes`。タグと値の並び）を足した（小版 16）。`entities` は、記号が持つ属性のタグと値を返す。
      - `add` は、AutoCAD が挿入するときと同じく、定義の属性の定義のうち値が決まっていないもの（一定の印を持たないもの）から属性を作る。属性の定義の文字を、記号の置く点・尺度・回転で写し、渡したタグの値で既定の値を替える。渡さないタグは既定の値のままにする。
      - 属性を作るのは、実寸の空間に、X と Y の尺度の大きさが同じで置く記号だけとする。用紙では定義の長さを mm に直す倍率を書き戻す側しか知らず、尺度の大きさが違えば文字の形を保って写せないため。書式つきの属性の定義を持つ定義も作らない。作る必要のある属性を作れないときは `/edits/0/geometry/attributes` を指して失敗する。読めない属性の定義が図面内にあるときも、どの記号の定義に属するか境界では確かめられないため、記号の追加を受けない。
      - 定義にないタグと重複するタグは `/edits/0/geometry/attributes/{i}/tag` を、改行を含む値は `/edits/0/geometry/attributes/{i}/value` を指して失敗する。
      - `replace` は属性の値を変えない。元と違う属性を渡すと `/edits/0/geometry/attributes` を指して失敗する。
    - 続く PR で、`replace` が属性の値を変えられるようにした（小版 21）。表題欄の項目（図名・日付など）を書き換えるためである（対応表の E10 の表題欄）。
      - 属性の数・順・タグは変えない。違えば、`/edits/0/geometry/attributes` か、その属性のタグを指して失敗する。
      - 値は 1 行に限る。書式つきの値（複数行の属性）を持つ属性の値は変えず、その属性の値を指して失敗する。2007 より前の DXF では、ASCII でない値を書けないので、`change.edit.unsupported` になる。
      - 値を変えた属性は、続く ATTRIB の値（1）だけを書き直す。置く点・高さなどのほかの欄は変えない。DWG も同じ。
      - 試料の DXF と DWG の属性を持つ記号で、値を変えて書き戻し、読み直した形の値が変えたものと同じで、ほかの要素が変わらないことを確かめた。
    - 続く PR で、2 点の間に合わせる文字（TEXT の水平の位置合わせが 3・5）も形の値にした（小版 17）。文字の形の値に、2 点目（`end`）と合わせ方（`fit`。縦横の比を保つ `aligned` か、高さを保つ `fit`）を足した。基点（`position`）が 1 点目になる。
      - AutoCAD は回転を 2 点から決め直すので、回転は 1 点目から 2 点目への向きと同じでなければならない（1e-6 度まで）。違えば `/edits/0/geometry/rotation` を指して失敗する。2 点目と合わせ方は一緒に書き、片方だけなら書かなかった欄を、2 点が同じなら `end` を指して失敗する。
      - `replace` は、合わせ方を変えず（`/edits/0/geometry/fit`）、1 点に置く文字と入れ替えない（`/edits/0/geometry/end`）。
    - 続く PR で、当てはめる点で決まるスプラインも形の値にした（小版 18）。スプラインの形の値に、当てはめる点（`fit`）と両端の接線（`start_tangent`・`end_tangent`）を足した。
      - 当てはめる点で決まるものは、節点と制御点を空にし、重みを持たない。元の図形が制御点や節点も持つときは、当てはめる点から元の形を再現できると限らないので、形の値を返さず、置き換えない。
      - DWG の場合（scenario）が変わらないよう、置き換えでは、制御点で決まるものと当てはめる点で決まるものを入れ替えない（`/edits/0/geometry/fit` か `control`）。R2013 から後の DWG の、制御点を書かないスプライン（場合が 1 で、印の 1 が立つ）は、当てはめる点の欄のまま書き直す。
      - DWG の当てはめる点のスプラインは、閉じている・周期的の印を書かないので、変えると `dwg.change.unsupported` になる。0 の接線は DWG で接線なしと同じに書かれるので受けず、元の図形に 0 の接線があるときも形の値を返さず、置き換えない。
      - 足すのは、R12 より後の DXF と、R2013 より前の DWG だけとする。R2013 から後の DWG では、当てはめる点のスプラインの印と節点の取り方の値を試料で確かめていないので、`dwg.change.unsupported` になる。AutoCAD が当てはめる点だけの DXF の SPLINE を開けるかは、AutoCAD を持つ環境で確かめる必要がある。
    - 続く PR で、R2004 から後の DWG にも格子を持つ記号（MINSERT）を足し、変換できるようにした（決定 0161）。読む側は、属性を持つ MINSERT が列と行の欄の前に持つオブジェクトの数を読み分ける。AutoCAD で作った MINSERT の試料がないので、AutoCAD との行き来は確かめていない。
    - 続く PR で、寸法も形の値にした（小版 19）。`entities` が返すだけで、`replace` と `add` は `change.edit.unsupported` で断り、ファイルを変えない。寸法を書き戻すには、寸法を描いた記号の定義（`*D` の部品）を作り直す必要があるため。
      - 種類（`kind`。長さ・平行・角度・2 線の角度・弧の長さ・半径・直径・座標）ごとに、定義点（`first`・`second`・`line`・`vertex`・`center`・`chord` など）と、文字の出し方（`label`。測った値・上書きした文字・出さない）、上書きした文字（`content`）、測った値とその出所（`measurement`・`measurement_key`）、文字の位置と回転、寸法スタイルの名前を持つ。
      - 受ける値の検査（種類にない欄・足りない欄、上書きの文字の生の改行、測った値と寸法スタイルを変えないこと）は、書き戻しを作るときのために先に入れた。
    - ほかの形（引出線・ハッチングなど）は、まだ形の値を持たない。`entities` は、その要素の `geometry` を返さない。
    - 線形の印を持つスプラインは、変更後も線形かを確かめられないため置き換えない。
    - DWG は角度をラジアンで持つので、度で送った角度は、書いて読み直すと末の桁がずれうる。apply は、DWG では書き戻したファイルから表を作り直してハッシュを求めるので、返すハッシュは読み直したときと同じになる。
  - `capabilities` は、DXF と DWG を書ける形式（`write`）として返す。SXF と JWW の文書への `apply` は、`change.format.unsupported` にして何も変えない。
- 対応表の E1・E4・E10（[対応表](../formats/drawing2d-mapping.md)）の書く向きは、次のとおりとする。
  - E1 の非等方のビュー（X と Y で倍率の違うビュー）は、DXF・DWG のビューポートが等方の縮尺しか持たないので、形式の限界として書かない。ビューの変更は、まだ変更の一覧にない。
  - E4 の寸法は、`entities` が形の値を返す（小版 19）。書き戻しは、寸法を描いた部品（`*D` のブロック）を寸法スタイルから作り直す必要がある。AutoCAD が同じに描くかを確かめられないので、AutoCAD を持つ環境か、AutoCAD で寸法を変えた前後の試料が要る。
  - E10 の表題欄は、属性の値を `replace` で書き換えられる（小版 21）。表（ACAD_TABLE）のセルの変更は、表を描いた部品（`*T` のブロック）を作り直す必要があるので、寸法と同じ条件で待つ。E5 は、0154 と `Transform` で扱う。形式固有の情報（[決定 0115](0115-drawing-format-extensions.md)）は、書き戻しが L1 の値を残すので、図面モデルから書かない。
- SXF の apply は、インスタンスの番号を保って書く（0156）。
- 変更の診断の code が変わるので、診断で分岐する使い手は、`change` の code に合わせる。
- `dwg.change.unsupported` は、DWG の L1 の書き戻し（表のオブジェクトの変更）でも使う。図面モデルの変更の診断は `change.*` に移し、L1 の診断としては残す。
- `change.element.missing` と `change.element.stale` は、ID ごとに分けて数える（値 `id` でまとめる）。足す要素の出所は使わないので、足す変更の診断は場所を持たない。
- apply が返す ID とハッシュは、書き戻した表から図面モデルを作り直して求める。図面モデルへの変換は、確かめるときと合わせて 1 回の apply で 2 回になる。返すハッシュが読み直したときと同じになることを優先した。
- 同じ要素を 1 回の変更の一覧で複数回指すと、`change.edit.unsupported` にして一覧全体を当てない。各変更は読んだときの要素に対して計画するため、後の変更が前の変更を消さないようにする。
- 2 つ以上の要素を作ったレコード（ID の終わりに `/1` などを持つもの）の要素は、1 つだけを書き戻せないので、`change.edit.unsupported` にする。
- ハンドルが重複する DXF・DWG は、参照先が一意に決まらないため、変更を当てず `change.edit.unsupported` を返す。
- `Restyle` と `Transform` は、要素の並びでなく 1 つの要素を指す。並びは、変更を並べて表す。apply が変更ごとに 1 つの新しい ID とハッシュを返す形と合わせるためで、手間は同じ。
- 書式つき文字の内容に絶対高さか解釈できない書式がある場合、尺度を変える `Transform` は当てない。元の符号を直さずに拡大すると、文字の高さが変わらないことがあるため。

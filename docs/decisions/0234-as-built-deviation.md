# 0234: 出来形は、設計の TIN と点群の標高の差を、プロファイルの規格値の区分ごとに集計して返す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-01 |
| 状態 | 採用 |

## 背景

段階 3（[#304](https://github.com/zumen-jp/zumen/issues/304)）は、設計の地表面（TIN）と計測した点群の差を計算し、出来形の確認に使えるようにする（#372）。点群は決定 0232 の領域モデルで、TIN は J-LandXML の土木の領域モデル（#367）で持つ。規格値は「土木工事施工管理基準及び規格値（案）」の面管理の表が決め、平場・天端・法面ごとに、標高較差の平均値と個々の計測値の幅を持つ。表は、法肩・法尻から水平に 5 cm 以内の点を評価から除き、計測の密度を 1 点／m² 以上とする。

決めることは、次のとおり。

- 規格値をどこに持つか。
- 点を平場・法面のどれで評価するか。TIN は面の区分を持たない。
- 結果を何で返すか。

## 選択肢

1. 規格値をコードに持ち、区分を利用者が要求で名指す。
2. 規格値をプロファイル（決定 0138）の規則に持ち、区分を設計面の三角形の勾配で決める。勾配の幅も規則に書く。
3. 規格値をプロファイルに持ち、区分を別の入力（面の区分の多角形）で受ける。

## 決定

選択肢 2 を採る。1 は、要領の版が上がるたびにコードを変える。3 は、区分の多角形を作る手段が利用者にない。2 は、要領が勾配で区分を分ける盛土の法面（4 割）と同じ形で書け、利用者のプロファイルで勾配の幅を置き換えられる。

- **照合の種類。** プロファイルに `surface-elevation` を足す（決定 0173 の `CHECKS`）。欄は次のとおり。
  - `work`: 工種の名前。要求で選ぶ
  - `part`: 区分の名前（`flat`・`crest`・`slope` など）
  - `slope`: 区分に入る三角形の勾配の幅（`min`・`max`、割。鉛直 1 に対する水平の長さ）。書かない端は限りがない
  - `mean`・`each`: 平均値と個々の計測値の幅（`min`・`max`、mm）。書かない端は比べない
  - `density`: 計測の密度の下限（点／m²、平面に投影した面積あたり）
  - `exclude`: 区分の境から除く水平の距離（メートル）
- **区分。** 点の真下の三角形を探し、同じ工種の規則を順に見て、勾配の幅に入る最初の規則で評価する。平場と法面の境の勾配は、要領が数で決めないので、プロファイルで `basis = "chosen"` とする。区分の違う三角形から `exclude` の内にある点は除く。TIN の外の点と、どの規則にも入らない点は評価しない。どれも数を返す。
- **差。** 点の標高から、同じ平面の位置の設計面の標高（三角形の中の一次の補間）を引く。水平較差は求めない。
- **op。** `deviation` を足す。点群の文書・TIN を持つ土木の文書と TIN の ID・プロファイル・工種を受ける。点群のモジュールができるまでは、`pointcloud` と同じく図面のモジュールに置く（#380）。点群と TIN の座標系がどちらも分かって違えば、計算しない。
- **結果。** 規則ごとに、評価した点の数・面積・密度・平均・最小・最大を返す。規格値を外れれば `profile.surface-elevation.invalid`、点がないか密度が足りなければ `profile.surface-elevation.unsupported` の指摘にする（決定 0173 と同じ形）。合格・適合とは言わない（`docs/style.md`）。点ごとの差は、`offset`・`limit` の範囲で返す。
- **色分け。** 差の色分けは、3D のシーンの点の区画（#475）で返す。

## 影響

- `zumen-asbuilt` を足し、点群・TIN・解いた規則から結果を作る。`zumen-profile` は、解いた規則を返す関数を出す。図面の `check` は、`surface-elevation` の規則を照合しない（`profile.rule.unsupported`）。
- 国土交通省の基準を `profiles/mlit-earthwork/2026-03/` に置く。軟岩の法面の規格値は、地質を点群が持たないので、まだ持たない。
- 点群のモジュールを分けるとき（#380）、`deviation` も移す。

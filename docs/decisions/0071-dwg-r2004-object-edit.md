# 0071: R2004 の DWG の変更は、オブジェクトのセクションの後ろに足し、マップのセクションを作り直して、コンテナーのセクションを置き換える

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

R2000 の DWG は、変えたオブジェクトをファイルの後ろに足し、オブジェクトのマップを作り直して書く（[決定 0028](0028-dwg-object-data-edit.md)）。R2004 から後は、オブジェクトとマップがそれぞれコンテナーのセクション（`AcDb:AcDbObjects`・`AcDb:Handles`）にあり、マップの位置はセクションの初めから数える。コンテナーは、置き換えたセクションから組み直して書ける（[決定 0070](0070-dwg-r2004-container-write.md)）。

R2004 のオブジェクトは、大きさ（MS）・データ・CRC の並びが R2000 と同じで、マップのセクションの形も同じだった。R2010 から後は、大きさの後にハンドルのストリームの大きさ（MC）が加わる。ヘッダーの変数は、R2004 で変数が増えて並びが違う。

## 選択肢

1. 展開した `AcDb:AcDbObjects` の後ろに変えたオブジェクトと足したオブジェクトを足し、`AcDb:Handles` を作り直して、2 つのセクションを置き換える。
2. `AcDb:AcDbObjects` を、マップの順にオブジェクトを並べ直して作り直す。
3. 変えたオブジェクトを元の位置で書き換え、大きさが変わるときだけ後ろに足す。

## 決定

選択肢 1 を採る。R2000 と同じ考え方で、元のオブジェクトのバイトを動かさない。選択肢 2 は、マップが指さないバイト（セクションの初めの RL など）の扱いを決める必要がある。選択肢 3 は、大きさで扱いが分かれる。

- `DwgTxn` のオブジェクトの置き換え・削除・追加を、R2000 と R2004 で受け付ける。R2010 から後は、これまでどおり `dwg.edit.unsupported` を返す。
- R2004 は、展開した `AcDb:AcDbObjects` の後ろに、R2000 と同じ形（MS・データ・CRC）でオブジェクトを足す。マップは、セクションの初めからの位置で、R2000 と同じ形で作り直す。
- マップのセクションは、変更があれば必ず置き換える。オブジェクトのセクションは、置き換えか足しがあるときだけ置き換える。除くだけなら、元のバイトが残る。
- ヘッダーの変数の変更（HANDSEED・INSUNITS・PLIMMIN・PLIMMAX）と、共有の表からの書き戻しは、R2000 だけで受け付ける。
- 変えた後のオブジェクトのデータを渡せるよう、`DwgFile::object_data` で、オブジェクトのデータ（MS の後から CRC の前まで）を返す。

## 影響

- 合成の R2004 のコンテナーで、置き換え・削除・追加を確定して書き、読み直したオブジェクトと表が確定の後と同じになった。
- サンプルの R2004 の 2 つの図面で、すべてのオブジェクトを同じデータで置き換え、最後のオブジェクトを除いて書き、読み直した表が、除いたものを除いて元と同じになった。
- `AcDb:ObjFreeSpace` のセクション（オブジェクトの数やマップの位置を持つ）は直さない。書いた図面を AutoCAD で開いて確かめてはいない。
- R2004 の図形の型ごとのフィールドの符号化（共有の表からの書き戻し）と、R2010 から後のオブジェクトの変更は、後の作業に残る。

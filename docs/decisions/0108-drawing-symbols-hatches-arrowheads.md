# 0108: 図面モデルの記号・ハッチング・寸法の端部記号を、定義のキーと元の値で持つ

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

[決定 0022](0022-drawing2d-semantics-and-format-mapping.md) は、記号を定義の ID か名前空間付きのキー・配置・属性値で持つことを決めた。ハッチングは、境界と穴、塗り・線の組・パターン・既定義の区別、原点・間隔・角度・尺度、境界との参照で持つ。[決定 0107](0107-drawing-dimensions-and-leaders.md) は、寸法と引出線の端部記号を寸法スタイルの値として後で足すとした。図面モデルには、まだ記号・ハッチング・寸法スタイルがなかった。部品の定義（ブロックの中身）と曲線の要素も、まだない。

## 選択肢

1. 記号は定義を名前空間付きのキーで指し、配置・尺度・回転・格子・属性を持つ。ハッチングは、境界の輪を元の形（膨らみのある折れ線か、辺の並び）のまま持ち、塗り・パターン・グラデーションを分ける。端部記号は、図面の寸法スタイルの表に置く。
2. 記号を定義の中身に展開し、線と文字の要素として持つ。ハッチングはパターンの線に展開する。
3. 1 に加えて、ハッチングの境界を、曲線の要素（#28 で足す）に直して持つ。

## 決定

選択肢 1 を採る。展開すると、記号とハッチングの意味と、元の値が分からなくなる（決定 0022）。曲線の要素はまだないので、境界は輪の形のまま持ち、曲線の要素ができたら対応づける。

- `Shape::Symbol` は `Symbol` を持つ。定義は `SymbolKey`（名前空間と元の名前）で指す。DXF のブロックは名前空間 `dxf.block` にする。配置は、基点を置く点・X と Y の尺度・回転、格子に並べるなら列と行と間隔（`Grid`）。属性（`Attribute`）は、タグ・文字・表示しないか・レイヤ・色と線種・出所を持つ。
- `Shape::Hatch` は `Hatch` を持つ。輪（`HatchLoop`）は、形（`Boundary`）と、外側・いちばん外・境界を探して作った・文字の枠の印と、輪を作った要素の出所を持つ。形は、膨らみのある頂点の折れ線か、線分・円弧・楕円弧の辺の並びとする。島の埋め方（`Islands`）・境界に合わせて作り直すか・境界を探した点も持つ。
- 中を埋めるもの（`Fill`）は、塗り・パターン・グラデーションを分ける。パターン（`Pattern`）は、名前・定義の出どころ・回転・尺度・重ねるか・線の組を持つ。線の組は、回転と尺度を当てた後の値を、要素の空間の長さで持つ。用紙に置くときは、ビューの縮尺で換算する（決定 0022）。グラデーションは、名前・回転・ずれ・色の RGB・1 色のときの濃さを持つ。
- 寸法スタイル（`DimensionStyle`）は、図面の表に置き、寸法と引出線は名前で指す。いまは、両端と引出線の端部記号（`Arrowhead`: 既定の矢印か記号のキー）・大きさ・斜線の大きさ・倍率だけを持つ。両端を別にしないスタイルは、両端に同じ記号を置く。
- DXF・DWG の INSERT（MINSERT を含む）と、それに従う ATTRIB・SEQEND、HATCH、DIMSTYLE の表を移す。SPLINE の辺を持つ HATCH は移さず、`dxf.hatch-spline.unsupported` を返す。複数行の属性は、MTEXT をまだ移さないので、その属性だけを移さず `dxf.lift.invalid`（101）を返す。
- 境界（`drawing` の op）の要約は、記号とハッチングを数えず、範囲にも入れない。要約の欄は、要素の一覧の op（#66）と合わせて決める。

## 影響

- 記号の定義の中身（ブロック）は、まだ移さない。定義と配置を分けて持つ仕組みは、部分図・グループ・部品とあわせて #28 で足す。
- ハッチングの SPLINE の辺は、曲線の要素を足すときに移す。DXF の辺の当てはめる点（97）は、境界を作った要素の数（97）と同じコードで続くので、読み分けを試料で確かめる。
- DWG の読み手は HATCH の境界の図形のハンドルを表に置かないので、DWG のハッチングの輪は、作った要素の出所を持たない。
- 寸法の拡張データで上書きした寸法スタイルの値（DXF の ACAD の DSTYLE）は、まだ移さない。
- SOLID・POINT などの塗りと点の記号は、まだ移さない。

## 背景

段階 3（[#304](https://github.com/zumen-jp/zumen/issues/304)）は、LAS・LAZ・E57・PLY・XYZ の点群を読み、設計の TIN と比べる。点群は数億点・数十 GB になり、入力の全体を 1 つのバイト列で受けられない。これまでの決定は、次を宿題にしていた。

- 入りきらない入力は、コアが要る範囲を応答で求め、ホストが `zm_push` で渡す。呼び返し（コールバック）は使わない（[決定 0012](0012-boundary-functions-and-messages.md)）。
- 巨大な入力は、全体を読まず、索引と範囲の読み出しで扱ってよい（[決定 0008](0008-model-layers-and-codecs.md)）。
- wasm のメモリは 4 GiB まで（[決定 0013](0013-boundary-in-four-forms.md)）。
- 3D のシーンの点の区画と八分木の段は、点群の系統で決める（[決定 0213](0213-scene3d-sections-and-op.md)）。

いまの SDK の `Codec::read` は入力の全体（`&[u8]`）を受け、セッションは名前つきの入力をバイト列の全体で持つ。範囲で読む仕組みはない。

## 選択肢

範囲の読み出しの選択肢は、次の 3 つ。

1. 呼び返しで、コアがホストからバイトを読む。
2. コアが応答で要る範囲を返し、ホストがその範囲を新しい名前の入力として渡し、同じ要求をもう一度呼ぶ。
3. 点群の入力も、全体を `zm_push` で渡させる。

点の持ち方の選択肢は、次の 2 つ。

1. 点ごとの構造体の列。
2. 属性ごとの列（列指向）。

## 決定

範囲の読み出しは選択肢 2、点の持ち方は選択肢 2 にする。

### 範囲の読み出し

- `open` に、入力の全体の大きさ `size` を書ける欄を足す。`size` が、渡した入力の長さより大きければ、その入力を「全体の初めの部分」とみなす。ホストは、初めの部分（既定の目安は 64 KiB）だけを渡せばよい。
- コアは、読むのに足りない範囲があれば、結果に `needs` を返す。`needs` は、範囲（`start`・`end`）と、その範囲を渡す入力の名前の組の列で、名前はコアが決める（`<入力の名前>:<start>-<end>`）。状態は失敗ではなく、`needs` を返したことを示す。
- ホストは、`needs` の範囲を、その名前で `zm_push` してから、同じ要求をもう一度呼ぶ。`zm_push` と境界の関数は変えない。
- 範囲の入力は、`close` の `inputs` で捨てられる。コアは、渡された範囲を読み終えたら、`needs` と同じ形の `done` で、捨ててよい範囲を返す。
- 1 回の応答で求める範囲の合計は、予算の `input-bytes` の内にする。
- SDK には、範囲で読む trait（`Ranged`）を足す。入力は `Source`（全体の大きさと、渡された範囲の表）で受け、足りなければ `Need`（範囲の列）を返す。全体を渡された入力も、範囲が 1 つの `Source` として同じ trait で読む。`Codec::read` は変えない。
- 全体を渡しても読める。小さい点群の試験と、ホストが範囲を扱えない場合のためにする。

### 点群の L2

- 点群のモデル（`zumen-pointcloud` の `PointCloud`）は、座標系・高さの基準と成果（[決定 0019](0019-coordinate-systems-and-gsi-data.md)）、全体の範囲、点の数、持つ属性の表、八分木の索引を持つ。
- 点は、地図の空間（`northing`・`easting`、メートル）と標高に置く。LAS の倍率とずれは、読むときに当てて f64 にする。座標系の分からない点群は、座標系を不明にして診断する。
- 点の属性は列で持つ。位置（f64 の 3 つ）を必ず持ち、強度・分類・色・反射の番号・時刻は、形式が持つものだけを持つ。持たない属性を既定の値で埋めない。
- 楕円体高の点群（GNSS）は、ジオイドの格子がなければ標高に直さず、`assumed` で知らせる（決定 0019）。

### 八分木の LOD とタイル

- 索引は八分木にする。根は全体の範囲を囲む立方体で、節は（段と 3 つの軸の位置）の番号で名指す。節は、その段の点の間隔に間引いた点を持ち、間隔は段が 1 つ深くなるごとに半分にする。
- 形式が索引を持つ場合（COPC の階層）は、その索引をそのまま節にする。索引を持たない LAS・LAZ などは、読むときに八分木を作る。作るには全体を読むので、予算の `work` で数える。
- タイルは八分木の節にする。3D Tiles などのタイルの形式への書き出しは、L3 の派生として別の作業にする。
- 点を求める要求は、範囲（箱）・許容差（点の間隔）・点の数の上限 `limit` を受け、許容差より細かい段を読まない。上限を超えるなら、浅い段から読める所までにし、`exceeded` で知らせる。

### 予算

- LAZ などの展開で作ったバイトは `decoded-bytes` で数える（[決定 0010](0010-budget-by-work.md)）。返した点は `elements` で数える。
- ファイルに書かれた点の数で、先に確保しない。
- wasm では、1 回の要求で持つ点を `limit` と予算の内にする。

### シーン

- 点群は、3D のシーン（`ZMS3`、決定 0213）の区画で返す。チャンクは八分木の節にし、チャンクの区画に、点の始まりの番号と節の番号（段と 3 つの軸の位置）を足す。
- 点の区画は、チャンクの原点（f64）からの f32 の位置と、持つ属性の列（色は RGBA の u8、強度は u16、分類は u8）を持つ。色を持たない点群の色は、描く側が強度か分類で決める。
- op は `scene3d` を使い、`doc` に点群の文書を渡す。`box`・`tolerance` に `limit` を足す。区画の定義は、決定 0213 の `schema/scene3d.toml` に足す。

### wasm のモジュール

- 点群のモジュール（`pointcloud`）を、feature と表の行で足す（[決定 0221](0221-wasm-modules.md)）。LAS・LAZ・E57・PLY・XYZ を入れる。LAZ の展開の依存は、このモジュールにだけ入れる。
- 設計の TIN と点群の差（#372）は、点群のモジュールで計算する。TIN を読むために、点群のモジュールに土木の領域モデルと J-LandXML の読み取りも入れる。モジュールの間で L2 を渡す仕組みは作らない。
- XYZ には見分ける印がないので、判定の規則に入れない。`open` で形式を名指したときだけ XYZ として読む（#373）。

## 影響

- `open` の要求と結果、`scene3d` の要求、3D のシーンの区画に欄が増える。どれも小版の追加で済む。
- 範囲の読み出しの往復は、ホストの言語の包み（JS・Python など）で隠す。包みは、ファイルか URL の範囲の読み出しで `needs` に答える。
- 点群の差の結果の言い方は、決定 0138 に従い、合否を言わない。

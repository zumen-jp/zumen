# 0106: 図面モデルの色・線種・線幅を、指定値か継承元と元の符号で持つ

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

[決定 0022](0022-drawing2d-semantics-and-format-mapping.md) は、色・線種・線幅について、指定値か継承元・解決した値・元の符号を区別すること、ACI と Jw_cad のペン番号を混同しないこと、符号表と新規作成の既定値はプロファイル（[#9](https://github.com/zumen-jp/zumen/issues/9)）に置くことを決めた。図面モデルには、まだ色・線種・線幅の欄がなかった。プロファイルの形式は #9 で決めるので、まだ符号表を使えない。

## 選択肢

1. 要素は指定値か継承元（レイヤ・部品の配置）を持ち、色は元の符号とファイルが持つ RGB を分けて持つ。符号から RGB への表は使わない。レイヤからの継承は、問い合わせの関数で解く。
2. 1 に加えて、ACI の 1〜255 の RGB の表を核に持ち、RGB を埋める。
3. 読み込むときに、レイヤからの継承を解いた値だけを要素に置く。

## 決定

選択肢 1 を採る。符号表はプロファイルに置くと決めているので、核に表を持たない。継承を読み込むときに解くと、レイヤを編集したときに要素の値が古くなるので、継承元のまま持つ。

- `Style` は、色（`Inherit<Color>`）・線種（`Inherit<LineTypeId>`）・要素の線種の倍率・線幅（`Option<Inherit<LineWeight>>`）を持つ。`Inherit` は、レイヤから・部品の配置から・要素が持つ値のどれかとする。
- `Color` は、元の符号（`ColorCode`。系統と値）と、ファイルが持つ RGB を分けて持つ。系統は、いまは ACI だけ。符号表から引いた RGB は置かない。
- 線種は図面の一覧（`LineType`）に置き、名前・定義・出所を持つ。同じ形でも、名前と定義が別なら統合しない。定義は線と間の長さの列と、その長さの空間（`PatternBasis`）を持つ。DXF の LTYPE の長さは、要素の空間の文書の単位とする。要素が名前で指すだけで、ファイルに定義がない線種の定義は `None` とする。
- 線幅は、用紙の長さか、文書の既定の線幅（`LineWeight::Default`）とする。文書の既定の線幅と、文書全体の線種の倍率は `Drawing2D` に置く。
- レイヤは、色・線種・線幅（`LayerStyle`）を持つ。`Drawing2D::color_of` などは、レイヤからの継承だけを解く。部品の配置からの継承と、定義のないレイヤからの継承は、継承のまま返す。
- DXF の LTYPE の、形か文字を持つ要素は、線と間の長さだけを移し、`dxf.line-type-element.dropped` を返す。形と文字は、形式固有の情報の置き場（#28）ができたら移す。

## 影響

- ACI の色を描くには、使い手がプロファイルか自分の表で RGB を引く。プロファイルができたら、解決に使った表と版を残す（#9）。
- DWG の読み手は図形の線幅を表に置かないので、DWG の図形の線幅は `None`（読めていない）とする。表に置くと、書き戻しが扱う欄も広げる必要がある。
- DXF の色の名前（430）と、DWG の色の本のハンドルは、まだ移さない。

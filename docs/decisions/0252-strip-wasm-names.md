# 0252: 配る wasm のモジュールから名前のセクションを除き、LTO と大きさ優先の最適化はまだ使わない

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-03 |
| 状態 | 採用 |

## 背景

図面のプラグインの wasm のモジュール（[決定 0247](0247-drawing-model-binary.md)）は約 0.96 MB で、図面のモジュールの約 13% になった。配る側の転送量をさらに減らせるかを調べる（#485）。決定 0247 の時点で、名前のセクション（関数の名前、約 190 KB）・すべての op の要求を読む部分・describe のカタログなどが大きかった。

`wasm32-unknown-unknown` の release（`zumen-abi`、2026-11-03 の main）で、設定ごとの大きさを測った。brotli は Node.js の `zlib.brotliCompressSync` の既定の水準。

| 設定 | プラグイン（バイト） | プラグイン（brotli） | 図面（バイト） | 図面（brotli） |
| --- | --- | --- | --- | --- |
| 今の release | 961,482 | 170,636 | 7,579,735 | 1,412,099 |
| 名前のセクションを除く（`strip = "symbols"`） | 772,747 | 152,112 | 6,532,639 | 1,318,045 |
| LTO（`lto = "fat"`・`codegen-units = 1`） | 807,602 | 170,471 | 6,604,333 | 1,412,836 |
| LTO と名前のセクションを除く | 699,470 | 157,753 | 5,965,498 | 1,346,399 |
| LTO・名前のセクションを除く・`opt-level = "s"` | 616,481 | 132,230 | 4,891,230 | 1,077,204 |
| LTO・名前のセクションを除く・`opt-level = "z"` | 578,113 | 126,207 | 4,423,236 | 986,669 |

プラグインのモジュールの関数の大きさを名前のセクションから数えると、要求を読む部分（`zumen_abi::messages`）が約 119 KB、図面モデルのバイナリの読み書きが約 133 KB、プラグインの形式では使わない建物のハッシュ（約 30 KB）とレビューの文書の読み書き（約 22 KB）が入っていた。

## 選択肢

1. 名前のセクションを除く。
2. LTO を使う。
3. 大きさ優先の最適化（`opt-level = "s"`・`"z"`）を使う。
4. モジュールが持たない op の要求を読まないよう、要求の型をモジュールごとに分けて生成する。

## 決定

選択肢 1 を採る。2〜4 は、まだ採らない。

- **名前のセクションを除く。** `.cargo/config.toml` で、`wasm32-unknown-unknown` を `-C strip=symbols` で作る。プラグインのひな形（`templates/plugin/.cargo/config.toml`）にも同じ設定を置き、ひな形を写したリポジトリでも効くようにする。転送量（brotli）は、プラグインで約 11%、図面で約 7% 減る。
  - 名前のセクションは、ブラウザーの開発のツールでのスタックの読みやすさのためにある。コアは API でパニックを捕まえて `panicked` と診断を返す（[決定 0012](0012-boundary-functions-and-messages.md)）ので、利用者の手元では名前を使わない。関数の名前が要る調べものは、環境変数 `RUSTFLAGS` を空の文字列にして作る（`RUSTFLAGS` は `.cargo/config.toml` の設定より先に使われる）。
  - ネイティブのライブラリと CLI の release は変えない。スタックトレースと、各言語のラッパーのデバッグで名前を使う。
- **LTO は採らない。** 展開した大きさは減るが、brotli の大きさはほとんど変わらない（プラグインで 0.1%）。名前のセクションを除いたものと合わせると、かえって brotli が大きくなった。作る時間が延びる。
- **大きさ優先の最適化は、まだ採らない。** 名前のセクションを除いたものより、転送量はさらに約 13〜25% 減るが、図面を読む速さへの影響を測っていない。シーンの組み立てなどの重い処理の速さを、ネイティブと wasm の手元の測り方で比べてから決める。決定性（[決定 0007](0007-single-rust-implementation.md)）は、最適化の水準で変わらない（浮動小数点の縮約をしない）。
- **要求の型をモジュールごとに分けるのは、まだしない。** 生成器（`cargo xtask codegen`）と API のメッセージの型を feature ごとに分ける大きな変更で、減るのは要求を読む部分の一部に限られる。建物のハッシュとレビューの読み書きがプラグインのモジュールに入るのも、同じく、セッションが持つ文書の型を feature で分けるときに一緒に直す。

## 影響

- `wasm32-unknown-unknown` で作るものは、どれも名前のセクションを持たない（テストで作る wasm も同じ）。
- リリースのモジュールの大きさは、CI の分けたモジュールのテストの表（`bindings/js/test/modules.mjs`）で確かめる。

# 0107: 図面モデルの寸法と引出線を、定義点・保存された測定値・文字の上書きを分けて持つ

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

[決定 0022](0022-drawing2d-semantics-and-format-mapping.md) は、寸法の種類・定義点・測る空間・文字とスタイルを持つこと、寸法の測定値・保存された文字・文字の上書き・表示を省く指定を別に持つこと、線と文字から寸法の意味を捏造しないことを決めた。引出線は、経路・端部記号・注記の参照を持つとした。図面モデルには、まだ寸法と引出線の要素がなかった。寸法の体裁（DIMSTYLE）の解決と、寸法を描いた部品（匿名のブロック）の展開は、まだできない。

## 選択肢

1. 寸法は、種類ごとの定義点・元の形式が保存した測定値・寸法値の文字の指定・文字の位置・寸法スタイルの名前・部品の名前を持つ。測定値は、形式と欄を指すキーと組にする。引出線は、経路と、注記の要素の出所を持つ。
2. 1 に加えて、定義点から測定値を計算して持つ。
3. 寸法を描いた部品を展開し、線と文字の要素として持つ。

## 決定

選択肢 1 を採る。定義点から計算した値で保存された値を置き換えると、文字と測定値の違いが分からなくなる。測り直しは明示的な操作にする。部品の展開は、表示用の構成要素を親と対応づける仕組みができてからにする。

- `Shape::Dimension` は `Dimension` を持つ。種類（`DimensionKind`）は、線形・平行・3 点の角度・2 線の角度・半径・直径・座標を分け、それぞれの定義点を持つ。測る空間は、定義点の型（実寸か用紙か）で決まる。半径と直径の引出線の長さは、要素の空間の長さにする。
- 保存された測定値は `Measured`（値と、形式と欄を指すキー）にする。単位と、寸法の倍率を掛けた値かどうかは形式ごとに違い、DXF Reference の文からは決まらないため。
- 寸法値の文字（`Label`）は、測定値を書く・利用者の文字・書かないを分ける。利用者の文字は元のまま持ち、測定値に置き換える符号（DXF の `<>`）も残す。
- 寸法値の文字の位置（`DimensionText`）は、中央の点・利用者が動かしたか・回転・位置合わせを持つ。
- 寸法スタイルと、寸法を描いた部品は名前で持つ。両端の矢印などの寸法スタイルの値は、記号とスタイルの解決（#28）で足す。
- `Shape::Leader` は `Leader` を持つ。経路の頂点・曲線か折れ線か・矢印を付けるか・注記の要素の出所・寸法スタイルの名前を持つ。矢印を元の形式が決めなければ `None` とし、寸法スタイルに従うとする。注記はほかの要素なので、出所（`Ref`）で指す。
- DXF の DIMENSION・LEADER は、どちらの空間でも移す。種類の値がない・頂点の数が合わない・指すオブジェクトがないなどは `dxf.lift.invalid` を返し、Z のある点は `dxf.non-planar.dropped` を返す。診断の code は足さない。
- 境界（`drawing` の op）の要約は、寸法と引出線を数えず、範囲にも入れない。要約の欄を足すのは、要素の一覧の op（#66）と合わせて決める。

## 影響

- DWG の読み手は LEADER の頂点を表に置かないので、DWG の引出線は `dxf.lift.invalid`（76）を返して移さない。頂点を表に置くと、書き戻しが扱う欄も広げる必要がある。
- MULTILEADER・ARC_DIMENSION・バルーンは、まだ移さない（`dxf.lift.dropped`）。ARC_DIMENSION は、対応表のとおり対象版の最小のファイルで確かめてから加える。
- 寸法の測定値の単位（角度のラジアンなど）を決めるには、試料の図面で確かめる。

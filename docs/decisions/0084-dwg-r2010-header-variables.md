# 0084: R2010 から後の DWG のヘッダーの変数は、主のデータの中で、ビットの数を変えずに書き換える

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

R2000 と R2004 の DWG は、ヘッダーの変数の HANDSEED・INSUNITS・PLIMMIN・PLIMMAX を、セクションの大きさ（バイト）を変えずに書き換え、CRC を直す（[決定 0078](0078-dwg-r2004-header-variables.md)）。R2010 から後のヘッダーの変数のセクションは、データの初めに文字列のストリームの終わりまでのビットの数（RL）を持ち、主のデータの後に文字列のストリームとハンドルのストリームが続く。HANDSEED は主のデータにあり、ほかのハンドルはハンドルのストリームにある。読む側は、R2004 と同じ並びの変数を、ハンドルだけハンドルのストリームから読んでいる。

## 選択肢

1. 主のデータの中の変数の位置を R2004 と同じ並びで求め、ビットの数が変わらない値だけを書き換える。
2. ビットの数が変わる値も受け付け、文字列のストリームの終わりの位置（RL）を直して、後ろのストリームをずらす。
3. R2010 から後は、まだ変えない。

## 決定

選択肢 1 を採る。PLIMMIN・PLIMMAX（RD）と、同じ大きさの HANDSEED は、ビットの数が変わらない。INSUNITS（BS）は、BS の幅が同じ値だけを受け付ける。ビットの数が変わると、文字列のストリームの終わりの位置と、文字列があるかのフラグの位置が動き、それを直す形をサンプルで確かめていないので、選択肢 2 は採らない。

- `DwgTxn::set_handle_seed`・`set_units`・`set_paper_limits` を、R2010 から後でも受け付ける。ビットの数が変わる値は、確定のときに失敗する。
- 共有の表からの書き戻しは、これまでどおり R2004 までとする。

## 影響

- サンプルの R2010・R2013・R2018 の図面で、INSUNITS を BS の幅を変えない値に、PLIMMIN・PLIMMAX を変えて書き、読み直した表が変えた表と同じになり、CRC の診断が出なかった。HANDSEED を 1 進めて書くと、読み直した値が進めた値になった。
- 書いた図面を AutoCAD で開いて確かめてはいない。

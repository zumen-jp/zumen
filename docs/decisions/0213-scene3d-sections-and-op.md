## 背景

[決定 0207](0207-building-model-components.md) は、建物モデルから作る 3D のシーンを L3 にし、2D のシーン（[決定 0137](0137-columnar-scene-transfer.md)・[決定 0172](0172-scene-sections-and-op.md)）にならって、区画と op を決めるとした。シーンの要素の ID は建物モデルの ID にし、2D の図面と 3D の選択を ID で連動させる。旧版の zumen-jp/zumen-legacy#126 は、メッシュを JSON で渡すか、バイナリで渡すかを残していた。#219 は、3D のインスタンスと LOD の持ち方をこの issue（#417）に移した。

決めることは次のとおり。

- 2D のシーンと同じ blob にするか、別の種類にするか。
- 区画の中身。要素・メッシュ・インスタンス・色・塊。
- LOD と塊の分け方。
- op と、その引数（絞り込み・断面の箱・許容差）。
- 各言語の読み手の足し方と、点群のシーン（#370）と揃える所。

関わる決定は、次のとおり。

- 形状表現は L2 では評価せず、L3 でカーネルが評価する。曲面を三角形にする許容差を付け、作った点の数は `segments` で数える（[決定 0018](0018-geometry-layers-and-tolerances.md)・[決定 0010](0010-budget-by-work.md)）。
- 写像（`IfcMappedItem`）は、写像の元と変換で持ち、L3 では同じ形のインスタンスにつなぐ（0207）。
- プロジェクトの空間は、文書の長さの単位で Z を上にする。大きな座標は、塊ごとの f64 の原点と f32 の相対座標で持つ（[決定 0019](0019-coordinate-systems-and-gsi-data.md)・0137）。
- IFC と建物モデルと 3D のカーネルは、wasm の BIM のモジュールに入る（[決定 0013](0013-boundary-in-four-forms.md)）。

## 選択肢

1. 2D のシーンの blob に、3D の区画を足す。
2. 2D と同じ見出し・区画の表・境界の規則を持つ、別の種類の blob にする。区画の定義は別のファイルに置く。
3. glTF（バイナリの GLB）で返す。

選択肢 1 は、2D の読み手が 3D の区画を読み飛ばすだけで済むが、塊の原点が 2D（X・Y）と 3D（X・Y・Z）で合わず、1 つの塊に 2D と 3D が混ざる。図面のモジュールにない 3D の区画の番号も、2D の表に並ぶ。

選択肢 3 は、three.js などがそのまま読める。ただし、要素の ID・クラス・階は glTF の拡張か `extras` の JSON に置くことになり、型付き配列のビューで引けない。glTF の座標は f32 で、塊の原点の規則（0019）を拡張で足すことになる。glTF に書き出すことは、変換の出力として別に足せる。

## 決定

選択肢 2 を採る。

### 入れ物

- 見出しは `ZMS3`、大版（u16）、小版（u16）、塊の数（u32）、区画の数（u32）。続けて区画ごとの始まりと長さ（u32）を置き、各区画を 8 バイトの境界に置く。数はリトルエンディアン。版と互換、知らない区画を読み飛ばすこと、「始まり」の列と「なし」の値（u32 の最大）は、0137 と `schema/scene.toml` と同じにする。
- 区画の定義は `schema/scene3d.toml` に置き、`cargo xtask codegen` で、2D のシーンと同じ言語の定数と型を作る。
- 座標は、プロジェクトの空間の、文書の長さの単位にする。地図への変換は掛けず、結果の JSON に文書の地図への変換（0019）を書く。

### 区画の中身

- **メッシュ。** 形の 1 つ。頂点（f32 の X・Y・Z）、三角形（頂点の番号の 3 つ組、u32）、稜線（頂点の番号の組、u32）の始まりを持つ。頂点の座標は、メッシュの局所の座標にする。法線は持たず、読み手が面から求める。稜線は、カーネルが返す形の稜線（面の境の線）で、三角形の分け目の線は含めない。
- **インスタンス。** メッシュを置く 1 つ。メッシュの番号、要素の番号、色の番号、塊の原点からの変換（f32 の 3 行 4 列）を持つ。写像（`IfcMappedItem`）と型の形状表現の写像は、同じメッシュを引くインスタンスにする。写像でない形も、変換が平行移動だけのインスタンスにする。
- **要素。** 建物モデルの要素の 1 つ。ID・クラスの名前（`class` の成分）・名前を `strings` で引き、所属する階を要素の番号で持つ（階に属さなければ「なし」）。階の要素も、要素の行に入れる。
- **色。** 表示する RGBA（f32、0〜1）と、未解決の印。`style` の成分に面の色があればその色と透明度にする。なければ未解決の印を立て、色を決めるのは読み手に任せる。コアはクラスごとの色の表を持たない（[決定 0106](0106-drawing-color-line-type-weight.md) と同じ考え方）。
- **塊。** インスタンスの続きを、塊に分ける。塊ごとに、f64 の原点（X・Y・Z）、相対座標の範囲（f32 の最小と最大の X・Y・Z）、インスタンスの始まりを持つ。塊は、要素ごとにまとめ、1 つの要素のインスタンスを複数の塊に分けない。塊の大きさは、試料で測るまで、1 つの塊に 4096 のインスタンスまでの仮の値にする（#412、#421）。
- **文字列。** ID・クラス・名前を 1 つの UTF-8 の区画にまとめ、始まりと長さで引く。

### LOD

- 1 つのシーンには、1 つの細かさだけを持つ。粗いシーンは、許容差を大きくして別に作る。写像をインスタンスにするので、同じ形の繰り返しは大きさが増えない。
- 細かさを塊ごとに持つ区画（LOD の段）は、試料で、許容差を変えたときの大きさと作る時間を測り、要ると分かったら後ろに足す（#421）。閾値はそのときに決める。

### op

- `scene3d` の op を足す。引数は、文書（`doc`）、絞り込み（`storeys`・`classes`・`ids`。どれも省けば全部）、断面の箱（`box`。プロジェクトの空間の最小と最大）、許容差（`tolerance`）とする。
- 絞り込みは、条件のすべてに合う要素を返す。`storeys` は階の要素の ID の並び、`classes` は `class` の成分の名前の並び、`ids` は要素の ID の並び。
- 断面の箱は、箱と重なる要素だけを返し、箱を結果の JSON に書く。コアはメッシュを切らず、読み手が切り抜きの面（WebGL の clipping plane など）で切る（0172 の切り抜きと同じ）。
- 許容差は、プロジェクトの空間の長さで指す。既定は、0172 の空間の既定と同じく、対象の要素の範囲の対角線の 1/50000 にする。使った許容差を、結果の JSON と `approximated` の診断に書く。作った点は `segments`、評価した要素は `work` で数える。
- 形を評価できなかった要素は、メッシュを持たない要素の行として残し、0018 の診断を返す。
- 結果の JSON は、単位・地図への変換・使った許容差・断面の箱・メッシュとインスタンスと要素の数・範囲と、シーンの blob の番号を持つ。シーンは、`blobs` の `scene3d` で返し、`zm_take` で取り出す。

### 2D との連動

- 建物から切り出した 2D の図面の要素（0207 の「建物から 2D を切り出す」）と、3D のシーンの要素は、どちらも建物モデルの要素の ID を持つ。連動は、読み手が ID の文字列で引く。2D と 3D をつなぐ表は、シーンに持たない。

### 読み手

- 2D のシーンの読み手（`scene.js`・`Scene.cs` など）にならい、同じ言語に `scene3d` の読み手を足す。区画を型付き配列のビューにし、インスタンスからメッシュ・要素・色を引く関数を置く。
- 適合試験の組は、2D のシーンと同じく、試験の中で作る建物モデルから作る（#421）。

### 点群と揃える所

- 点群のシーン（#370）は、`ZMS3` の区画として後ろに足す。塊の原点（f64 の X・Y・Z）と相対座標（f32）、塊の区画は、ここで決めたものを使う。点の区画（位置・色・強度・分類）と八分木の段は、#370 で決める。

### 置き場所

- シーンを作る処理は、新しい crate `zumen-scene3d`（L3）に置く。`zumen-building` と 3D のカーネル（#414）に依り、2D の `zumen-scene` には依らない。wasm の BIM のモジュールに入る（0013）。
- 表示のエンジン（旧版の zumen-jp/zumen-legacy#132）は、この決定の範囲の外にする。作るかは利用者が決め、作るなら別の issue にする。2D のシーンにもエンジンはない。

## 影響

- 新しい診断の code（`scene3d.*`）と、`scene3d` の op・区画のスキーマを足すので、境界の小版を上げる（#421）。
- 塊の大きさと LOD の段は、試料（#412）で測ってから決め直す。
- glTF への書き出しは、要るときに変換の出力として別に足す。

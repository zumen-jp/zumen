# 0115: 図面モデルの形式固有の情報を、系統と版と読んだときの付く先の値で持つ

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

[決定 0022](0022-drawing2d-semantics-and-format-mapping.md) は、共通の要素にできない情報を、名前空間・系統・スキーマの版・型付きの値・出所を持つ拡張にすると決めた。拡張ごとに、どの共通の欄への変更に依存するかを定める。位置・文字・寸法などを編集したら、影響する拡張を更新するか、失効したと記録する。古い原本から編集前の値を復活させない。対応表の E5 は、文字と、その位置に依存する同じ系統の拡張を置き、文字を動かしてから書く。

DXF の XDATA（1001 の登録アプリケーション名に続く 1000〜1071）は、アプリケーションが図形に付ける値で、意味はアプリケーションが決める。いまの変換は、これを移していない。

## 選択肢

1. 図面に拡張の一覧を持つ。拡張は付く先（図面・空間の要素・用紙の要素）と、読んだときの付く先の値を持つ。いまの値と比べて、違えば失効したとする。
2. 要素に拡張の欄を足し、編集の op が拡張を更新するか外す。
3. 拡張に、依存する欄の名前の一覧を持たせ、欄ごとに比べる。

## 決定

選択肢 1 を採る。図面モデルは値の集まりで、編集は値を書き換えるだけなので、編集の op を通らない変更でも失効を見分けられる。要素に欄を足すと、要素を作るすべての所を変えることになる。欄ごとの依存は、意味の分かる拡張を足すときに付く先の値を絞ればよい。XDATA の意味はアプリケーションが決めるので、要素のどの欄に依存するかは分からない。

- `Drawing2D::extensions` に `Extension` を並べる。`Extension` は次を持つ。
  - 名前空間（`dxf.xdata` など）と、その中の元の名前（登録アプリケーション名など）。
  - 元の形式の版（DXF の `$ACADVER`）と、名前空間の値の型の契約の版。
  - 付く先（`Target`: 図面、実寸の空間か記号の定義の空間の要素、用紙の要素）。
  - 読んだときの付く先の値（`Basis`: 要素のレイヤ・スタイル・形と意味・出所）。
  - 型付きの値（`Field`: 名前空間の中の値の名前と、文字列・整数・実数・点・元のオブジェクトを指す値・バイト列）と、出所。後に[決定 0157](0157-drawing-model-fields-and-extensions.md) で、`Field` に元のグループ・コードを足すことにした。
- `Drawing2D::current_extensions` は、付く先が読んだときのままの拡張を返す。元の系統へ書き戻せるのは、これだけとする。`stale_extensions` は、付く先が変わったか、なくなった拡張を返す。書き戻す側は、これを更新するか、損失として診断する。読んだときの値を、いまの値の代わりに使わない。
- DXF と DWG の表の図形（記号の定義の中身も含む）の XDATA を、登録アプリケーション名ごとの拡張にする。値の名前は、グループ・コードの意味（1000 は文字列、1011 は位置、1041 は距離など）とする。点（1010〜1013）は続く Y と Z と合わせる。最初の 1001 より前の XDATA の値と、読めない値は `dxf.lift.invalid` を返し、その名前の分を移さない。

## 影響

- 書き戻し（lower・apply）は、まだない。作るときは、`current_extensions` だけを書き、`stale_extensions` を診断する。
- XDATA の位置・変位・向き（1011〜1013）や距離・尺度（1041・1042）を、要素の変換に合わせて動かすことはしない。付く先の要素が変われば、失効したとする。
- 拡張辞書（102 の `{ACAD_XDICTIONARY`）と、OBJECTS の独自のオブジェクト、図面全体に付く拡張は、まだ移さない。
- DWG の読み手は拡張データ（EED）を表に置かないので、DWG の XDATA は移らない。
- 付く先を要素の添字で指すので、要素を並べ替えたり消したりすると、別の要素を指すことがある。そのときも付く先の値が違うので、失効したとする。後に[決定 0156](0156-drawing-stable-ids-and-preconditions.md) で、付く先を ID で指し、読んだときの値をハッシュで持つことにした。
- 境界（`drawing` の op）の要約は、拡張を数えない。

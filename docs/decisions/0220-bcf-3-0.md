# 0220: BCF 3.0 の bcfzip をレビューの文書に写して読み、元の bcfzip の知らない要素を保って書き戻す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-31 |
| 状態 | 採用 |

## 背景

#429 は、BCF の bcfzip を読み書きし、レビューの文書（[決定 0214](0214-review-model-and-bcf.md)）と互いに写す。BCF は buildingSMART の形式で、topic・comment・viewpoint を持つ。作るにあたり、次のことが決まっていなかった。

- どの版から作るか。
- レビューの文書に写せない要素（ヘッダー・参照のリンク・BimSnippet・知らない要素や属性・スナップショット）を、書き戻すときにどうするか。
- BCF に要る値（Guid・TopicType・作者・日時）がレビューの文書にないとき、どうするか。
- ZIP をどう書くか。`zumen-zip` は読むだけだった。

BCF 2.1 は XSD の使用の条件が決まっていないので、#440（待ち: 判断）の後の #454 に分けた。3.0 の構造は、公開された仕様の文書から、事実だけを自分の言葉で写して作り、XSD は持たない。

## 選択肢

書き戻し方は 2 つある。

1. レビューの文書だけから、bcfzip を作り直す。
2. 元の bcfzip を渡せば、変えていない topic は元のバイト列のまま書き、変えた topic でも、写さない要素を元から写す。

選択肢 1 は、ほかのツールが書いた拡張や、スナップショットを、往復のたびに失う。

## 決定

選択肢 2 を採る。3.0 だけを読み書きし、`bcf.version` が 3.0 でなければ `bcf.version.unsupported` で失敗する。

### 読む（`zumen_bcf::review`、op `bcf_read`）

- topic は指摘に、comment はコメントに、viewpoint は 3D の場所に写す。Guid は小文字にする。
- 状態は、TopicStatus の文字列と状態の対応の表で写す。表は呼ぶ側が渡し、渡さなければ `Open`・`Resolved`・`Closed`。表にない文字列は `open` にし、元の文字列を `status_label` に残す。
- viewpoint の部品は、IfcGuid を持つものだけを要素の参照にし、ハッシュは開いた建物モデルの要素のハッシュで埋める。色は `#` と大文字の 16 進にする。
- op は、開いた IFC の文書（[決定 0219](0219-ifc-at-the-boundary.md)）を対象にし、文書を blob で返す。

### 書く（`zumen_bcf::write`、op `bcf_write`）

- 対象の 3D の場所を viewpoint にする。2D の場所・ほかの対象の場所・カメラのない場所は書かず、`bcf.location.unsupported` を報告する。図形は `bcf.markup.unsupported`、22 字の IfcGuid でない要素の ID は `bcf.element.unsupported`、照合の由来は `bcf.origin.dropped` を報告する。
- 指摘の ID が Guid でなければ、ID の blake3 から Guid を作る。同じ ID からは同じ Guid になる。
- 元の bcfzip に同じ Guid の topic があり、写した指摘が同じなら、フォルダーを元のバイト列のまま書く。変えた topic でも、ヘッダー・参照のリンク・Index・Stage・BimSnippet・文書の参照・知らない要素と属性は元から写し、変えていないコメントと viewpoint は元のまま書く。変えた viewpoint は新しいファイルにし、元のスナップショットは、絵が合わなくなるので書かない。
- 状態は、表の文字列で書く。状態が `open` で、`status_label` が表にない文字列なら、その文字列を書く。
- TopicType・作者・日時がない指摘とコメントには、呼ぶ側が渡した値を書いて `bcf.value.assumed` を報告する。値がなければ `bcf.value.missing` で失敗する。仕様が求める値を空にしない。
- カメラの縦横比はレビューの文書に持たないので、新しい viewpoint には 1 を書く。
- 元の bcfzip のルートのファイル（extensions.xml・project.bcfp・documents.xml など）は、元のまま書く。元がなければ extensions.xml を、書いた種類・状態・優先度・ラベル・利用者で作る。

### ZIP を書く

`zumen-zip` に、圧縮しない（stored）項目を書く `write` を足す。名前は UTF-8 の印を立て、日時は 1980-01-01 に固める。同じ入力から同じバイト列になる。ZIP64 が要る大きさなら書かず、`bcf.size.unsupported` で失敗する。圧縮は、使う側が要ると分かってから足す。

## 影響

- 境界に `bcf_read`・`bcf_write` を足し、スキーマの小版を 45 にする。
- BCF 2.1 は #454 で、#440 の判断の後に足す。読む側の違いは、版ごとに markup の読み方を分ければ足せる。
- 試験の bcfzip は、試験の中で書く。

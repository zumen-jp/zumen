# 0266: PDF の ObjStm の単独 Flate は、既存の展開と同じリーダーで出力量を先に数える

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-06 |
| 状態 | 採用 |

## 背景

[0256](0256-pdf-with-hayro.md) の読み込み前の確認は、オブジェクトのストリーム（ObjStm）を展開してから、そのバイト数を予算に数える。hayro-syntax 0.9.0 の展開には出力量の上限がないため、小さい圧縮入力でも、確認自身が予算を確かめる前に大きな出力を確保する。#521 の最初の実装として、#579 で単独の Flate フィルターの経路を直す。

## 選択肢

1. 上流に上限を渡す API が入るまで、展開後の確認を続ける。変更は小さいが、すでにある依存で減らせる確保も止められない。
2. hayro-syntax をフォークするか、展開をすべて自前にする。中で予算を数えられるが、依存の配布と更新、壊れた入力の読み方も維持する必要がある。
3. 既存の flate2 で出力を保持せずに展開量を数え、予算内なら hayro-syntax に渡す。読む量は増えるが、出力と ID を決める依存を替えずに、確保前の確認を加えられる。

## 決定

選択肢 3 を採る。ObjStm の単独 Flate に限定して、hayro-syntax 0.9.0 が使う flate2 の zlib、raw deflate のリーダーを同じ順で試す。固定長のバッファーだけに出力し、入力を読む量と出力を作る手間を `Work` に、展開したバイト数を `DecodedBytes` に数え、中断も確かめる。予算内で終わったら、元のストリームを hayro-syntax に渡す。

厳しい展開に失敗した場合も、寛容な展開の出力の上限を入力から求めて先に数える。失敗した試みの分も戻さない。予測子を当てる前のバイト数を使う。具体的な倍率、単位と対象の見分け方は [PDF の上限](../formats/pdf.md#上限) に記す。

依存の追加と更新はしない。flate2 1.1.10 と zlib-rs は 0256 で採った寛容なライセンスの依存で、ネイティブと wasm の双方で同じ処理を使う。時計・環境・ポインターの幅で予算を変えず、[0007](0007-single-rust-implementation.md) と [0010](0010-budget-by-work.md) に従う。描画、元のバイト列と ID の作り方は変えない。

## 影響

- 予算が足りない入力は、出力全体の確保前に止まる。新しく数える事前の展開と、失敗時の上限の見積もりにより、以前より早く止まる場合がある。
- 成功する入力でも事前の展開が 1 回増える。依存に展開途中の予算を渡せるようになったら、この重複を見直す。
- PDF 全体の予算制限を保証する変更ではない。ほかのフィルターと組み合わせ、ほかのストリーム、hayro 内部の読み込みと解釈などは #521 に残る。API につなぐ #518 の開始条件は緩めない。
- リポジトリ外への報告は #580 で利用者の判断を待ち、実装とは分ける。

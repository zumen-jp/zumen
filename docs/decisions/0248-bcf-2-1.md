# 0248: BCF 2.1 も 3.0 と同じ道で読み書きし、元の bcfzip と違うバージョンでは書き戻さない

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-03 |
| 状態 | 採用 |

## 背景

[決定 0214](0214-review-model-and-bcf.md) は、BCF の 2.1 と 3.0 を読み、既定で 3.0、引数で 2.1 を書くとした。[決定 0220](0220-bcf-3-0.md) は、権利の判断を待つ間、3.0 だけを読み書きし、2.1 を #454 に分けた。#440 で、2.1 を 3.0 と同じ扱いで実装してよいと決まった。

2.1 と 3.0 では、同じ中身を次のように違う形で書く。

| 中身 | 2.1 | 3.0 |
| --- | --- | --- |
| コメントと viewpoint の参照 | Markup の直下の `Comment` と `Viewpoints` | Topic の `Comments`・`Viewpoints` の中の `Comment`・`ViewPoint` |
| ラベル・関連する topic・参照のリンク・文書の参照 | 包まずに並べる（`Labels`・`RelatedTopic`・`ReferenceLink`・`DocumentReference`） | 一覧の要素で包む |
| ヘッダーのファイル | `Header` の直下の `File` | `Header` の `Files` の中の `File` |
| 色を付ける部品 | `Color` の直下の `Component` | `Color` の `Components` の中の `Component` |
| カメラ | 縦横比がない | `AspectRatio` がある |
| 拡張 | `project.bcfp` が指す XSD（任意） | `extensions.xml` |

決まっていなかったのは、次の 2 つ。

- 元の bcfzip と違うバージョンで書くよう求められたとき、どうするか。
- 元の bcfzip がないとき、2.1 で拡張を書くか。

## 選択肢

元の bcfzip と違うバージョンで書くときの扱いは 3 つある。

1. 写さない要素（ヘッダー・参照のリンク・文書の参照など）を、もう一方のバージョンの形に直して保つ。
2. 写さない要素を落とし、診断して書く。
3. 書かずに失敗する。

選択肢 1 は、文書の参照の形がバージョンで違う（2.1 はパスか URL、3.0 は文書の Guid か URL）ので、直せないものが残る。選択肢 2 は、元の bcfzip を渡した目的（写さないものを保つこと）に反する。

## 決定

選択肢 3 を採る。

- 読むのは 2.1 と 3.0。`bcf.version` の `VersionId` でバージョンを決め、バージョンごとに一覧の要素の置き場所を変えて読む。どちらのバージョンから読んでも、同じ中身なら同じレビューの文書になる。
- 書くバージョンは引数で選ぶ。引数がなければ、元の bcfzip のバージョンか 3.0 にする。元の bcfzip と違うバージョンでは書かず、`bcf.conversion.unsupported` で失敗する。バージョンを変えたいときは、元の bcfzip を渡さずに書く。
- 2.1 で書くとき、写さない要素と知らない要素・属性は、3.0 と同じく元の topic から写す。包まずに並ぶ要素は、すべてを写す。
- 2.1 で書くとき、コメントの本文は空でも書く（2.1 では本文が必須）。カメラに縦横比は書かない。
- 元の bcfzip がないとき、2.1 では拡張を書かない。2.1 の拡張は任意の XSD で、種類と状態の値を縛るためのものなので、書かなくてもリーダーは読める。
- API の `bcf_write` に `version`（`2.1` か `3.0` の文字列）を足し、スキーマのマイナーバージョンを 61 にする。ほかの値は `call.value.invalid` にする。`bcf_read` は読んだバージョンを返す。

## 影響

- 決定 0220 の「3.0 だけを読み書きする」を、この記録で置き換える。ほかの決定 0220 の内容は変えない。
- 2.1 と 3.0 の間で、元の bcfzip を保ったままバージョンを変えることはできない。要る使い方が出たら、文書の参照の写し方を決めてから足す。

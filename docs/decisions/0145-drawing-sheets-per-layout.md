# 0145: DXF・DWG のレイアウトごとに用紙を作り、用紙に元の名前を持たせる

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-28 |
| 状態 | 提案 |

## 背景

DXF・DWG の図面は、複数のレイアウト（印刷用の用紙空間）を持てる。これまでの変換は、今のレイアウトの図形だけを 1 枚の用紙に置いた。ほかのレイアウトの図形は、診断も返さずに落としていた（[決定 0112](0112-drawing-symbol-definitions.md) の「まだ移さない」、#174）。

手元の試料には、ほかのレイアウトを持つ図面がある。

- `sample_AC1015`〜`sample_AC1032`: 3 つのレイアウトを持つ。
- `farmhouse.dwg`: 26 のレイアウトを持つ。

図面モデルの `Drawing2D` は、もともと複数の用紙（`sheets`）を持てる。ただし、用紙には名前がない。どの用紙がどのレイアウトか、使い手には分からない。

ほかのレイアウトの図形は、BLOCKS のペーパー空間のブロックにある。

- DXF では、ブロックの名前は `*Paper_Space0` などで、番号が付く。
- 試料の DWG では、どのレイアウトのブロックのレコードも、番号のない `*Paper_Space` だった。

## 選択肢

1. レイアウトごとに用紙を作る。図面モデルの `Sheet` に、元の名前を持つ欄を足す。
2. レイアウトごとに用紙を作るが、名前は拡張として持つ。
3. 今のレイアウトだけを移し、ほかのレイアウトは診断で知らせる。

## 決定

選択肢 1 を採る。

- 名前は、用紙を選ぶ使い手（人も AI も）がまず要る値である。拡張（選択肢 2）では、形式ごとに読み方が違ってしまう。
- 選択肢 3 は、図面の大半を落とす図面がある（`farmhouse.dwg`）。

内容は次のとおり。

- **名前**: `Sheet.name: Option<String>` を足す。元の形式の用紙の名前で、翻訳しない。DXF・DWG では LAYOUT のレイアウトの名前（2 つ目の 1）とする。JWW・SXF は、まだ `None` とする。
- **ほかのレイアウトの見分け方**: BLOCKS にあるペーパー空間のブロック（名前が `*Paper_Space` で始まる）の中身を、ほかのレイアウトの図形とする。今のレイアウトの図形は ENTITIES にあるので、名前の番号に頼らずに見分けられる。
- **LAYOUT の探し方**: そのブロックのレコードを、レイアウトの欄の 330 で指す LAYOUT とする。今のレイアウトの LAYOUT は、ペーパー空間の図形の所有者から探す。
- **並び**: 用紙は、今のレイアウトを ID 0 で先に置く。ほかのレイアウトは、LAYOUT のタブの順（71）で後に並べる。ID は 1 から、ブロックの順に付ける。
- **原点と大きさ**: ほかのレイアウトの用紙の点は、LAYOUT の範囲の左下（10・20）を原点にした mm とする。大きさは範囲（10・20 から 11・21）で決める。今のレイアウトは、これまでどおり `$PLIMMIN`・`$PLIMMAX` で決める。
- **ビュー**: ビューポートの扱いは、今のレイアウトと同じとする。69 が 1 のものは用紙そのものなので、ビューにしない。
- **描く順**: ブロックのレコードを指す SORTENTSTABLE で決める。
- **今のレイアウトの MULTILEADER と POLYLINE**: これまでは、ペーパー空間にあっても実寸の空間に置いていた。これも用紙に置くように直す。

## 影響

- 図面モデルの `Sheet` に欄が増えるので、`Sheet` を作る使い手は欄を足す必要がある。
- ABI の図面の要約（`SheetSummary`）は、用紙の名前をまだ渡さない。用紙の数は増える。
- 図形のない空のレイアウトは、用紙を作らない。名前もまだ移さない。
- 試料の `sample_AC1015`〜`sample_AC1032` の DXF と DWG で、どの版でも同じ名前・大きさ・ビューの数の 3 枚の用紙になることを確かめた。

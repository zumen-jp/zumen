# 0145: DXF・DWG のレイアウトごとに用紙を作り、用紙の大きさと単位は LAYOUT の印刷の設定で決める

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-28 |
| 状態 | 提案 |

## 背景

DXF・DWG の図面は、複数のレイアウト（印刷用の用紙空間）を持てる。これまでの変換は、今のレイアウトの図形だけを 1 枚の用紙に置いた。ほかのレイアウトの図形は、診断も返さずに落としていた（[決定 0112](0112-drawing-symbol-definitions.md) の「まだ移さない」、#174）。

手元の試料には、ほかのレイアウトを持つ図面がある。

- `sample_AC1015`〜`sample_AC1032`: 3 つのレイアウトを持つ。
- `farmhouse.dwg`: 26 のレイアウトを持つ。

図面モデルの `Drawing2D` は、もともと複数の用紙（`sheets`）を持てる。ただし、用紙には名前がない。どの用紙がどのレイアウトか、使い手には分からない。

ほかのレイアウトの図形は、BLOCKS のペーパー空間のブロックにある。

- DXF では、ブロックの名前は `*Paper_Space0` などで、番号が付く。
- 試料の DWG では、どのレイアウトのブロックのレコードも、番号のない `*Paper_Space` だった。

用紙の点の単位は、レイアウトの印刷の設定（LAYOUT が持つ PLOTSETTINGS の値）が決める。72 は用紙の単位（0 は inch、1 は mm）、142 と 143 は印刷の尺度（142 の用紙の単位が、143 の図面の単位に当たる）、44 と 45 は用紙の大きさ（mm）である（DXF Reference「PLOTSETTINGS」）。レイアウトの範囲（LAYOUT の 10・20 から 11・21）は、用紙の端を、余白の分だけ原点からずらした図面の単位で持つ。これまでの変換は、用紙の点を文書の単位（`$INSUNITS`）で mm にしていた。

- `sample_AC1024`（`$INSUNITS` は inch）: どのレイアウトも 72 が 0 で、範囲を 25.4 倍すると用紙の大きさになる。Layout1 は 11 × 8.5 inch で、Letter（215.9 × 279.4 mm）を 90° 回したもの、MyLayout は A4 を回したものに合う。
- `features-r2018`（mm）: 72 が 1 で、範囲が A3 の 420 × 297 mm に合う。
- 横須賀市の 3 つの図面（`jp-yokosuka-minami-survey-*`、`$INSUNITS` は mm）: Layout1 と Layout2 は用紙を設定していない（44・45 が 0、印刷機は `none_device`）。Layout1 の範囲は AutoCAD の inch の既定の 12 × 9 で、これまでの変換は 12 × 9 mm の用紙にしていた。
- 文書の単位で換算すると、実寸を m で描いて mm の用紙を設定した図面では、用紙が 1000 倍になる。
- 文書の単位が分からない図面は、ペーパー空間の図形を落としていた（`dxf.paper-space.dropped`）。表題欄を失う。

また、用紙の ID は、今のレイアウトを 0、ほかを 1 からのブロックの順にしていた。レイアウトを足すとずれる（[決定 0156](0156-drawing-stable-ids-and-preconditions.md)）。

## 選択肢

1. レイアウトごとに用紙を作り、元の名前を持たせる。ID は LAYOUT のハンドル、大きさと単位はレイアウトごとの印刷の設定で決める。
2. レイアウトごとに用紙を作り、元の名前を持たせる。ID はブロックの順、単位は文書の単位、今のレイアウトの大きさは `$PLIMMIN`・`$PLIMMAX` で決める（この決定の最初の案）。
3. 今のレイアウトだけを移し、ほかのレイアウトは診断で知らせる。

2 は、上の試料のとおり、用紙の大きさを誤る。3 は、図面の大半を落とす図面がある（`farmhouse.dwg`）。名前を拡張として持つことも考えたが、名前は用紙を選ぶ使い手（人も AI も）がまず要る値で、形式ごとに読み方が違ってしまう。

## 決定

選択肢 1 を提案する。

- **名前。** `Sheet.name: Option<String>` を足す。元の形式の用紙の名前で、翻訳しない。DXF・DWG では LAYOUT のレイアウトの名前（2 つ目の 1）とする。JWW・SXF は、まだ `None` とする。
- **ID と並び。** 用紙の ID は LAYOUT のハンドルとする（0156）。用紙は、LAYOUT のタブの順（71）に並べる。
- **今の用紙。** `Drawing2D` に、開いたときに見せる用紙を指す `current_sheet: Option<SheetId>` を足す。今のレイアウト（ENTITIES のペーパー空間の図形が属するもの。図形のないときは 0153）の用紙を指す。モデルのタブを開いた状態で保存した図面（`$TILEMODE` が 1）は、`None` とする。
- **ほかのレイアウトの見分け方。** BLOCKS にあるペーパー空間のブロック（名前が `*Paper_Space` で始まる）の中身を、ほかのレイアウトの図形とする。今のレイアウトの図形は ENTITIES にあるので、名前の番号に頼らずに見分けられる。
- **LAYOUT の探し方。** そのブロックのレコードを、レイアウトの欄の 330 で指す LAYOUT とする。今のレイアウトの LAYOUT は、ペーパー空間の図形の所有者から探す。
- **単位と原点。** 用紙の点は、どのレイアウトも、範囲の左下（10・20）を原点にした mm とする。図面の単位から mm への倍率は、用紙の単位（72）の mm と、印刷の尺度（142 ÷ 143）を掛けたものとする。文書の単位は使わない。
- **大きさ。** 範囲（10・20 から 11・21）を同じ倍率で換算して決める。用紙を設定していないレイアウト（44 か 45 が 0）は、大きさを持たない（`None`）。
- **単位が分からないとき。** 72 が 0 と 1 のほか（2 の画素など）か、142・143 が正でなければ、図面の単位を mm とみなして用紙を作り、`dxf.paper-unit.assumed` を返す。ペーパー空間の図形は落とさない。`dxf.paper-space.dropped` は、台帳で廃止にする。
- **LAYOUT を持たない版（R14 まで）。** 1 枚の用紙を作り、大きさは `$PLIMMIN`・`$PLIMMAX` で決める。単位は文書の単位とし、分からなければ mm とみなして `dxf.paper-unit.assumed` を返す。
- **ビュー。** ビューポートの扱いは、今のレイアウトと同じとする。69 が 1 のものは用紙そのものなので、ビューにしない。
- **描く順。** ブロックのレコードを指す SORTENTSTABLE で決める。
- **今のレイアウトの MULTILEADER と POLYLINE。** これまでは、ペーパー空間にあっても実寸の空間に置いていた。これも用紙に置くように直す。

## 影響

- 図面モデルの `Sheet` と `Drawing2D` に欄が増えるので、それらを作る使い手は欄を足す必要がある。
- `sample_AC1015`〜`sample_AC1032` の DXF と DWG で、どの版でも同じ名前・大きさ・ビューの数の 3 枚の用紙になることを確かめた（単位は inch で、文書の単位と同じ）。横須賀市の図面のレイアウトは、大きさのない用紙になる。
- 印刷の尺度が 1:1 でないレイアウト（142 と 143 が違う）は、試料にない。AutoCAD で作った試料で確かめる。
- ABI の図面の要約（`SheetSummary`）は、名前を渡す（[決定 0153](0153-drawing-empty-layout-sheets.md)）。用紙の ID は、0156 の文字列で渡す。
- 図形のない空のレイアウトも、同じ規則で用紙にする（0153）。
- 単位の分からない図面の扱いは、対応表の E9（[対応表](../formats/drawing2d-mapping.md)）の、止めずに診断する規則に合う。

# 0157: 表示・印刷・寸法・意味を変える値は図面モデルの欄にし、アプリケーションの値だけを形式固有の情報にする

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-29 |
| 状態 | 提案 |

## 背景

図面モデル（Drawing2D）は、形式によらない図面の意味を持つ（[決定 0022](0022-drawing2d-semantics-and-format-mapping.md)）。形式固有の情報（`Extension`、[決定 0115](0115-drawing-format-extensions.md)）は、図形の XDATA を、登録アプリケーション名ごとに型付きの値で持つ。

その後の提案の最初の案と、それに沿った main の実装は、次の値を形式固有の情報にした。

- 図形の厚さ・線種の生成・スプラインの許容差（`dxf.entity`、[決定 0142](0142-dxf-entity-extension.md)）
- 図形の拡張辞書の XRECORD（`dxf.xrecord`、[決定 0148](0148-drawing-extension-dictionary-xrecords.md)）。AutoCAD が自分の版の往復のために置く XRECORD（`ACAD_XREC_ROUNDTRIP`・`ACAD_MTEXT_RT`）も含む
- 画層と線種の拡張辞書の XRECORD（[決定 0152](0152-drawing-layer-line-type-xrecords.md)）

どの値をモデルの欄にし、どの値を形式固有の情報にするかの規則は、まだない。形式固有の情報は、形式の系統ごとの名前空間で持つので、表示する側・別の形式への変換・分析は読まない。線種の生成のように表示を変える値を形式固有の情報に置くと、それらの使い手には失われたのと同じになる。

また、`Field` はグループ・コードを持たない。XRECORD のコードは決まった意味を持たないので、0148 の最初の案は、値の前に `code` の欄を置いて並べた。

## 選択肢

1. 値の働きで分ける。表示・印刷・寸法・意味を変える値はモデルの欄、アプリケーションが意味を決める値は形式固有の情報、形式が自分のために持つ値は L1 だけに置く。
2. 形式固有の値は、すべて形式固有の情報に置く。使い手が、要る名前空間を読む。
3. 形式固有の値も、要素の汎用の欄（名前と値の組）として、モデルに置く。

2 は、表示する側と変換が、形式の系統ごとの名前空間をすべて知る必要があり、図面モデルを置いた意味がなくなる。3 は、意味の分からない値を型なしでモデルに混ぜ、形式固有の情報と同じものを別の所に作る。

## 決定

選択肢 1 を提案する。

- **モデルの欄。** 表示・印刷・寸法の値・図面の意味（何を表すか、何に関連づくか）を変える値は、図面モデルの型付きの欄にする。形式が違っても同じ意味の値は、同じ欄に移す。欄がまだない値は、形式固有の情報に仮に置かず、欄を足すまで移さずに診断する。
- **形式固有の情報。** 意味をアプリケーションが決める値（登録アプリケーションの XDATA、アプリケーションの XRECORD）と、平面の図面モデルの範囲の外の値（厚さ）は、形式固有の情報にする。zumen は、アプリケーションの値の意味を推定しない。
- **L1 だけの値。** 形式が自分の版の往復や計算の控えのために持つ値（AutoCAD の版の往復の XRECORD、図形の範囲の控えなど）は、図面モデルへ写さず、L1 に残す。書き戻しは L1 の値を残す（[決定 0154](0154-drawing-apply-keeps-format-data.md)）。往復の値のうち、図形の値で表せない内容（新しい版の表の書式など）は、意味を読んでモデルの欄にする。読めない間は、移さずに診断する。
- **値の形。** `Field` に、元のグループ・コード（`code`）を足す。XDATA と XRECORD の値は、すべてコードを持つ。値の前に `code` の欄を置く並べ方（0148）はやめる。XRECORD の点も、XDATA と同じく X・Y・Z を合わせる。
- **付く先と依存。** 付く先は ID で、依存は付く先のハッシュで持つ（[決定 0156](0156-drawing-stable-ids-and-preconditions.md)）。
- **今の提案の振り分け。** 次のとおりにする。各決定も、この振り分けに合わせた。

| 値 | 置き場所 | 決定 |
| --- | --- | --- |
| 厚さ（39） | 形式固有の情報 `dxf.entity` | 0142 |
| スプラインの節点・制御点の許容差（42・43） | 形式固有の情報 `dxf.entity` | 0142 |
| 線種の生成（70 の 128） | モデル（`Polyline`） | 0142 |
| スプラインの当てはめの許容差（44）と節点の取り方 | モデル（`Spline`） | 0142 |
| アプリケーションの XDATA・XRECORD | 形式固有の情報 `dxf.xdata`・`dxf.xrecord` | 0115・0148・0152 |
| AutoCAD の版の往復の XRECORD | L1 だけ | 0148 |
| 記号の切り抜き（`ACAD_FILTER`） | モデル（`Symbol` の切り抜き） | 0149 |
| 画層の透過性（`AcCmTransparency`）・説明（`AcAecLayerStandard`） | モデル（`Layer`） | 0152 |
| 図形の透過性（440） | モデル（`Style`） | 0152 |
| 注釈の尺度（`AcDbContextDataManager`・`ASDK_XREC_ANNO_SCALE_INFO`）・寸法の関連づけ（`ACAD_DIMASSOC`）・動的ブロックの表し方（`AcDbBlockRepresentation`） | モデル（欄を足すまで診断） | 0148・0152 |

## 影響

- #250 で書き直した決定 0140〜0153 は、main の実装に合わせて、書き直す前の文で採用した。#250 でこの決定に合わせて書き直した内容は、この決定を採るときに、値ごとの決定として出し直す。
- 表示する側と変換は、モデルの欄だけを読めばよい。`dxf.*` の名前空間を読まなくても、図面を正しく描ける。
- 形式から値を移すときは、まずこの規則で置き場所を決め、対応表（[対応表](../formats/drawing2d-mapping.md)）に書く。
- AutoCAD が意味を決める値（注釈の尺度など）は、欄を足すまで図面モデルにない。書き戻しは L1 の値を残すので、元の形式へ戻すときは失われない。
- `Field` の形が変わるので、0115 の値の型の契約の版を上げる。
- 採用するときに、0115 からこの決定へリンクする。

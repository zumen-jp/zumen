# 0078: R2004 の DWG のヘッダーの変数は、展開したヘッダーのセクションの中で書き直し、セクションを置き換える

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

R2000 の DWG のヘッダーの変数の HANDSEED（[決定 0052](0052-dwg-write-back-entity-addition.md)）と、INSUNITS・PLIMMIN・PLIMMAX（[決定 0069](0069-dwg-write-back-header-variables.md)）は、ヘッダーの変数のセクションの中でその場で書き直す。R2004 では、ヘッダーの変数はコンテナーの `AcDb:Header` のセクションにあり、セクションの中の形（始まりのマーカー・大きさ・データ・CRC・終わりのマーカー）は R2000 と同じで、変数の並びが一部違う。読む側は、R2004 の並びで HANDSEED から INSUNITS までを読む。R2004 の DWG に図形を足すには、HANDSEED を進める必要がある。

## 選択肢

1. 展開した `AcDb:Header` のセクションを、R2000 と同じ方法で R2004 の変数の順に沿って書き直し、コンテナーのセクションを置き換える（[決定 0070](0070-dwg-r2004-container-write.md)）。
2. R2004 のヘッダーの変数は書き戻さない。

## 決定

選択肢 1 を採る。

- HANDSEED・INSUNITS・PLIMMIN・PLIMMAX の位置は、読む側と同じ R2004 の変数の並びで求める。
- 書き直すときは、R2000 と同じくセクションのデータの大きさ（バイト）を変えず、CRC を計算し直す。
- ヘッダーの変数が変わったときだけ、コンテナーの `AcDb:Header` を置き換える。
- R2010 から後は、ハンドルが別のストリームにあるので、まだ書き換えない。

## 影響

- サンプルの R2004 の 2 つの図面で、INSUNITS・PLIMMIN・PLIMMAX を変えて書き戻し、読み直した表が変えた表と同じになり、CRC の診断も出なかった。HANDSEED を 1 進めて書き、読み直した値が進めた値になった。
- R2004 の DWG に図形を足す準備ができた。
- 書いた図面を AutoCAD で開いて確かめてはいない。

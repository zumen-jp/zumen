# 0287: エージェントは公開の資料を読み、同意して手に入れた資料は条件が AI を禁じていなければ読む

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-09 |
| 状態 | 採用 |

## 背景

- エージェントは、仕様・販売のページ・公開の実装を読んで形式を実装し、形式の台帳（[0017](0017-format-rights-ledger-and-plugin-sdk.md)）に書誌の事実と権利の根拠を書く。外部の実装のソースは寛容なライセンスのものだけを読むと決めていたが、仕様と販売のページを読んでよいかの決まりはなく、AI での利用を禁じる注記には、そのつど当たってきた。台帳の `e57` は、ASTM の販売のページが規格を AI で扱うことを禁じるので、本文を読まないとした。
- 2026-11-09、`express` を台帳に足す PR（#666）の確かめる側が、ISO のサイトの注記を見つけた（#669）。作った側は、ページの本文だけを読んで見落とし、台帳に「AI で扱うことについての記述はない」と書いていた。注記は、ページの下の折りたたまれた部分（`<details>` の「© All Rights Reserved」）の中にあり、ページの本文を読むツールでは出てこない。
- 2026-11-09 に確かめた ISO の条件は、次のとおり。
  - **サイトの注記**（www.iso.org と committee.iso.org のページの下）。ISO の出版物と資料は著作権で守られ、使う者が ISO の著作権の条件を受け入れることを前提とする（subject to the user's acceptance）。複製を含む使用には、書面の許諾が要るとする。ISO Open data のものを除き、ISO の内容を機械学習・AI に使うことを禁じる。例として、大規模言語モデルの学習と、AI のツールに応答を作らせるためにアクセスし使うことを挙げる。
  - **利用許諾**（[Licence Agreement](https://www.iso.org/terms-conditions-licence-agreement.html)、2026-05-29 の改定）。出版物の使用は、End Customer Licence Agreement（ECLA）に従う。
    - 前文は、注文するか、出版物にアクセス・ダウンロード・インストール・使用すれば、同意したとする。1 節は、出版物に、その一部を含めるとする。
    - 4 節は、許す使い方に、出版物を読み・参照することと、その中身を社内の業務・仕組み・製品・サービスで理解・評価・適用することを含めるとする（使い方の範囲は、ライセンスの種類で縛る）。別の許諾がなければ、複製・配布・翻案・組み込み・デジタルの統合・派生物を作る権利は含まないとする。
    - 6(b) は、出版物をデジタルやソフトウェアの環境に統合・埋め込み・符号化・構造化・変換・運用化（integration・embedding・encoding・structuring・transformation・operationalization）することに、別の許諾を求める。例に、ソフトウェアのアプリケーション、ルールエンジン、データベース・データモデル・構造化したデータセット、AI のツールを挙げ、社内で使うものと第三者に出すものの両方を含める。
    - 7(b) は、ISO・ISO の会員団体・認められた配布者が別に許諾しなければ、出版物を AI・機械学習のために読み・使い・処理することを禁じる。禁じる使い方には、AI に出版物を取り込ませ、要約・言い換え・生成させるための入力や問い合わせが入る。法定のテキスト・データマイニングの例外（EU の指令 2019/790 の 4 条など）にも頼れないとする。
  - **PDF Association が配る ISO 32000-2 の無償版。** 店（pdfa-inc.org）の 0 ドルの手続きで受け取る。店の [EULA](https://www.pdfa-inc.org/eula/) は、ANSI の推奨の文に基づき、ダウンロードかアクセスで同意したとする。個人の、非独占の、譲渡できないライセンスで、1 台のコンピューターでだけ使え、複数のコンピューターやネットワークでの使用を許さない。製品の結合・翻案・翻訳・改変を禁じ、権利は表紙に書かれた著作権者が持つとする。AI・機械学習を名指しする条項と、実装を制限する条項はない。手続きの画面のほかの条件と、PDF の表紙の注記は確かめていない（#674）。
- 利用者は 2026-11-09 に、会話で「知識は消せないし、あなたは私の代わりとしてふるまうのだから全部読んでよい。権利上問題が起きることがなければよい。理想のツールを作るために柔軟なルールを設計したい」と答えた。そのあと下の方針を示されて、「この方針で進めて」と答えた（#669）。

## 選択肢

1. **AI での利用を禁じる持ち主のページと資料は、開かない。** 持ち主の意向にいちばん沿う。ただ、書誌の事実を得るのにも利用者の手が要り、持ち主ごとに禁止を足していくことになる。
2. **書誌の事実を読むためだけなら、ページを開いてよい。本文は読まない。** ページを読むこと自体が、注記の「AI のツールに応答を作らせる」に当たるので、注記の読み方としては弱い。
3. **仕様・ページ・資料を読めるかは、同意した条件で決める。** その資料の持ち主（著作権者）か、持ち主がその版の公開を許した配布者が誰でも見られるようにしている公開のページと資料は、注記によらず読む。購入・登録・会員・NDA などで、条件に同意して手に入れた資料は、その条件が AI での利用を禁じていなければ読む。何を書けるかは、著作権と今の決まりで縛る。

## 決定

3 を選ぶ。権利の問題が実際に起きるのは、同意した条件に反すること、その資料の持ち主が許さずに上げた写しを手に入れること、書くものに仕様の本文や寛容でないライセンスのコードが混ざること、受け取った図面や秘密を出すことの 4 つである。決まりはこの 4 つを避けることに絞る。新しい資料に当たったら、その資料の持ち主か、持ち主が許した配布者が出したものかと、手に入れるときに条件に同意したかと、その条件が AI での利用を禁じているかの 3 つを確かめる。

- **読む**
  - 公開のページと資料は、読んでよい。公開のページと資料とは、その資料の持ち主（著作権者）か、持ち主がその版の公開を許した配布者が、誰でも見られるようにしているもの（ログインも、条件への同意も要らないもの）をいう。この記録で「持ち主が許した配布者」というときは、その版の公開を許された配布者をいう。第三者の解説・論文・実装の文書にも、その文書の版ごとに同じ条件を当てる。サイトの注記が AI での利用を禁じていても、事実を得るために読む。注記の中身は台帳に書く。
  - 持ち主が許さずに上げた写し（売られている規格の本文が、持ち主でも、持ち主が許した配布者でもない所に置かれたものなど）は、公開の資料に含めず、開かない。著作権を侵害して上げられたものと知りながらダウンロードすることは、軽微なものなどを除き、私的使用のための複製の例外に入らない（著作権法 30 条 1 項 4 号。2026-11-09 に e-Gov の法令 API で確かめた）。持ち主の条件が写して配ることを許している資料（CC BY のもの、政府標準利用規約に従うものなど）の写しは、持ち主が許した写しとして扱う。ウェブ・アーカイブ（web.archive.org など）の写しも、持ち主の条件が写すことを許していなければ開かない。許しがあるか分からない写しも開かず、持ち主か、持ち主が許した配布者から入手する。持ち主のページが自動の取得を拒むときは、下のとおり利用者のブラウザーで開く。そこでも入手できなければ、利用者に頼む。
  - 自動の取得を拒む公開のページは、利用者のブラウザー（ブラウザーの拡張）で開いてよい。ログイン・CAPTCHA・支払いは越えない。利用者のブラウザーは、利用者がログインしているサイトでは、ログインしないと見られない所も開けてしまうので、ログインした状態でしか見られないものは開かない。
  - 購入・登録・会員・NDA などで、条件に同意して手に入れた資料は、その条件が AI での利用を禁じていなければ読む。禁じているか、確かめていなければ読まない。条件の文はエージェントが読んでまとめてよいが、読むと決めるのは利用者にする（利用規約の読みで採否が決まる権利の判断。[0254](0254-parallel-agents-and-cross-review.md)）。同じ条件と用途についての利用者の判断（日付と言葉の記録があるもの）は、そのまま使う。読まないと決めるのは、エージェントでよい。
  - ページ以外の資料（出版物の一部を見せるプレビューや、ファイルなど）は、その資料に当てる条件が、アクセス・ダウンロード・使用で同意したとするなら、条件に同意して手に入れた資料として扱う。その資料に当てる条件とは、資料の中の注記、その資料を配るページの条件、出版物の利用許諾（ISO の ECLA、店の EULA など）をいう。サイト全体の利用規約は含めず、サイトのページと同じく扱う。その資料の版に適用される許諾を確かめる。読むこと・AI での利用・使う場所や台数・秘密の保持を縛らず、写す・配る・作り変えることを許し、その際の条件がないか、出所の表示などに限られるものを「許すだけの許諾」とする。「許すだけの許諾」は、アクセス・ダウンロード・使用で同意したとする文があっても、読むために利用者の判断を待つ条件に含めない。写す・配る・作り変えるときは、その版の許諾と今の決まりに従う。NC・ND のように使い方や作り変えを制限する許諾は、条件として扱う。ISO の OBP のプレビューは、ECLA が出版物の一部へのアクセスでも同意したとし、7(b) が AI での利用を禁じるので、読まない。サイトのページそのものは、注記が条件の受け入れを前提としていても、上のとおり公開のページとして読む（#669 の判断）。
  - 配るページかライセンスのページから、その資料に当てる利用許諾があると分かる資料（規格の出版物とその一部、店の EULA で配るものなど）は、開く（アクセス・ダウンロードする）前に、その条件を確かめる。条件の中身を開かずに確かめられないものは、開かずに利用者に頼む。確かめる手順で、エージェントが利用者の代わりに条件に同意しないようにするためである。
  - そのほかの公開のファイルは、開いて読んでよい。本文より先に、表紙・著作権のページ・奥付・メタデータを見る。中の注記がアクセス・ダウンロード・使用で同意したとする場合、「許すだけの許諾」に当たると確かめた資料は公開の資料として読む。それ以外は本文を読むのをやめ、それまでに読んだ中身も使わない。注記がその資料に当たるか分からないときも、本文を読むのをやめ、その判断を利用者に頼む。台帳には資料の名前・入手先と注記だけを書き、利用者に知らせる。その資料に当たる条件を確かめ、AI での利用が禁じられておらず、利用者がその条件で今回の用途に使うことを認めた場合にだけ、本文を読める。同じ条件と用途についての利用者の判断（日付と言葉の記録があるもの）は、そのまま使う。
  - 学習済みの知識は使ってよい。
  - 外部の実装のソースは、今の決まりのまま、寛容なライセンスのものだけを読み、GPL の実装のソースは読まない。書くコードに混ざるのを防ぐための決まりで、同意した条件によらない。
- **書く**（今の決まりのまま）
  - 仕様の本文・表・図は写さない。節の番号・名前・値などの事実は書いてよい。
  - 読んだものを同梱するかは、今の決まり（ライセンス）で決める。
- **記録する**
  - 台帳の仕様の項の `note` に、入手に条件への同意が要るかと、その条件が AI での利用を禁じるかを書く。確かめていなければ、そう書く。項目は足さない。当てはまる仕様が少なく、文で足りるため。
  - 注記と条件は、ページの本文だけでなく、折りたたまれた部分とページの下まで読む。

エージェントは利用者の代わりに読むので、公開のページを読むことは、利用者が読むことと同じに扱う。同意した条件が AI を名指しで禁じる資料は、エージェントが読めば、同意した利用者が条件に反するので、分けて扱う。

今の仕様には、次のように当てる。

| 仕様 | 扱い |
| --- | --- |
| `iso_10303_11_2004`（EXPRESS） | 本文は ISO から買うもので、利用許諾が AI での利用を禁じるので読まない。この台帳の作業（#529・#666・#677）では、本文を買わず、プレビューも読んでいない（読み取りを足した #450 が何を読んだかの記録はない）。学習済みの知識・公開された EXPRESS のスキーマ・寛容なライセンスの実装で読む |
| `iso_32000_2_2020`（PDF 2.0） | 無償版は、店の EULA（1 台・ネットワークでの使用と改変の禁止）のもとで配られる。手続きの画面のほかの条件と表紙の注記を確かめていないので、利用者が確かめて決めるまで読まない（#674）。それまでは、学習済みの知識・Arlington PDF Model（Apache-2.0）・pdf-issues（CC BY 4.0）・寛容なライセンスの実装で進める |
| `e57_astm_e2807`（E57） | 本文は買うもので、販売のページが AI で扱うことを禁じるので読まない（今のまま） |
| `cedxm`・`jpeg_t81`・`kokuban_jcomsia` | 入手の条件が AI での利用を禁じるかを確かめていないので、読まない（#675 で確かめる） |

## 影響

- エージェントは、ISO・ASTM などのサイトのページを、ほかの公開のページと同じく読める。#669 で決めるまで ISO のページを開かないとした扱いは終わる。確かめる側も、同じ決まりで読む。
- ISO のサイトの注記は、使う者が条件を受け入れることを前提とし、AI のツールに応答を作らせるためのアクセスも禁じる。注記を知ったうえでページを使い続けると、注記の条件に同意したと見られる余地は残る。#669 では、読むのは書誌の事実で ISO に損害は生じないので、問題になる見込みは低いと見た。ページ全体を読んでも、書くものは事実に限り、本文・表・図を写さない。
- ほかの公開のファイルの中の注記は、開く前には知れない。注記がアクセス・ダウンロード・使用で同意したとするなら、開いたことで同意したと見られる余地は残る。ファイルの全体を一度に取り出すツールでは、注記を見つけたときには、注記が禁じる処理がもう済んでいることもある。そのため、本文より先に表紙・著作権のページ・奥付・メタデータを見て、同意を求める注記が「許すだけの許諾」に当たると確かめられなければ、本文を読むのをやめ、それまでに読んだ中身も使わない。
- ISO の ECLA は、出版物を買うか使う者（Licensee）について、4 節で、組み込み・デジタルの統合・派生物を作る権利を許す使い方に含めず、6(b) で、出版物をソフトウェアなどに統合・符号化・運用化することに別の許諾を求める。言葉の範囲は広く、仕様に従って形式を実装して公開することが当たるかは、文からは分からない。このリポジトリは ISO の出版物を同梱せず、本文・表・図を写さないが、当たるかの判断は利用者がする。
- `pdf` の権利は、[0017](0017-format-rights-ledger-and-plugin-sdk.md) の定義どおりなら、条件を確かめられていないので `unknown`（`core` に置けない）になりうる。#674 で無償版の条件（ECLA が当たるか）が分かるまで `public` のままにするのは、利用者の判断による。分かったら、0017 に照らして `rights` を見直す。それまで、エージェントは本文を読まない。
- 本文を読めない仕様は、学習済みの知識・公開の資料・寛容なライセンスの実装と、テストで確かめた結果で実装する。台帳の実装の根拠（`basis`）は、今の決まりのとおりに書く。
- 入手に同意が要るかは、`access` だけでは分からない。`iso_32000_2_2020` は `public`（無償）だが、店の手続きと EULA のもとで受け取る。そのため `note` に書く。

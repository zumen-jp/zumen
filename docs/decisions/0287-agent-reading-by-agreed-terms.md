# 0287: エージェントは公開の資料を読み、同意して手に入れた資料は条件が AI を禁じていなければ読む

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-09 |
| 状態 | 採用 |

## 背景

- エージェントは、仕様・販売のページ・公開の実装を読んで形式を実装し、形式の台帳（[0017](0017-format-rights-ledger-and-plugin-sdk.md)）に書誌の事実と権利の根拠を書く。外部の実装のソースは寛容なライセンスのものだけを読むと決めていたが、仕様と販売のページを読んでよいかの決まりはなく、AI での利用を禁じる注記には、そのつど当たってきた。台帳の `e57` は、ASTM の販売のページが規格を AI で扱うことを禁じるので、本文を読まないとした。
- 2026-11-09、`express` を台帳に足す PR（#666）の確かめる側が、ISO のサイトの注記を見つけた（#669）。作った側は、ページの本文だけを読んで見落とし、台帳に「AI で扱うことについての記述はない」と書いていた。注記は、ページの下の折りたたまれた部分（`<details>` の「© All Rights Reserved」）の中にあり、ページの本文を読むツールでは出てこない。
- 2026-11-09 に確かめた ISO の条件は、次のとおり。
  - **サイトの注記**（www.iso.org と committee.iso.org のページの下）。ISO の出版物と資料は著作権で守られ、使う者が ISO の著作権の条件を受け入れることを前提とする（subject to the user's acceptance）。複製を含む使用には、書面の許諾が要るとする。ISO Open data のものを除き、ISO の内容を機械学習・AI に使うことを禁じる。例として、大規模言語モデルの学習と、AI のツールに応答を作らせるためにアクセスし使うことを挙げる。
  - **利用許諾**（[Licence Agreement](https://www.iso.org/terms-conditions-licence-agreement.html)、2026-05-29 の改定）。出版物の使用は、End Customer Licence Agreement（ECLA）に従う。
    - 前文は、注文するか、出版物にアクセス・ダウンロード・インストール・使用すれば、同意したとする。1 節は、出版物に、その一部を含めるとする。
    - 4 節は、許す使い方に、出版物を読み・参照することと、その中身を社内の業務・仕組み・製品・サービスで理解・評価・適用することを含めるとする（使い方の範囲は、ライセンスの種類で縛る）。別の許諾がなければ、複製・配布・翻案・組み込み・デジタルの統合・派生物を作る権利は含まないとする。
    - 6(b) は、出版物をデジタルやソフトウェアの環境に統合・埋め込み・符号化・構造化・変換・運用化（integration・embedding・encoding・structuring・transformation・operationalization）することに、別の許諾を求める。例に、ソフトウェアのアプリケーション、ルールエンジン、データベース・データモデル・構造化したデータセット、AI のツールを挙げ、社内で使うものと第三者に出すものの両方を含める。
    - 7(b) は、ISO・ISO の会員団体・認められた配布者が別に許諾しなければ、出版物を AI・機械学習のために読み・使い・処理することを禁じる。禁じる使い方には、AI に出版物を取り込ませ、要約・言い換え・生成させるための入力や問い合わせが入る。法定のテキスト・データマイニングの例外（EU の指令 2019/790 の 4 条など）にも頼れないとする。
  - **PDF Association が配る ISO 32000-2 の無償版。** 店（pdfa-inc.org）の 0 ドルの手続きで受け取る。店の [EULA](https://www.pdfa-inc.org/eula/) は、ANSI の推奨の文に基づき、ダウンロードかアクセスで同意したとする。個人の、非独占の、譲渡できないライセンスで、1 台のコンピューターでだけ使え、複数のコンピューターやネットワークでの使用を許さない。製品の結合・翻案・翻訳・改変を禁じ、権利は表紙に書かれた著作権者が持つとする。AI・機械学習を名指しする条項と、実装を制限する条項はない。手続きの画面のほかの条件と、PDF の表紙の注記は確かめていない（#674）。
- 利用者は 2026-11-09 に、会話で「知識は消せないし、あなたは私の代わりとしてふるまうのだから全部読んでよい。権利上問題が起きることがなければよい。理想のツールを作るために柔軟なルールを設計したい」と答えた。そのあと、示された方針（#669 の判断の記録にある）に、「この方針で進めて」と答えた。
- 同じ日、利用者は会話で、ND・NC の資料（IFC・IDS・BCF のスキーマと文書の CC BY-ND 4.0、IFC2x3・IFC4 の文書の CC BY-NC-ND 4.0）を、資料ごとに利用者の判断を待たずに読むことを選んだ（「待たずに読む」、#677）。示した理由は、CC の 4.0 の許諾が 8(a) で、許しなしにできる使い方（読む・事実を使う）を縛らないとすることと、#440 もこの読みで IFC・BCF を実装したことだった。ただし、8(a) が守るのは許しなしに法でできる使い方で、読むために作る写しが法の例外に当たるかは、国と、写しを残すかによる。#440 の読みは、文書を写さずに事実だけを使うことを前提にする（台帳の `ifc` の `rights-note`）。そのため、写しを残すときは、そのときに許諾を確かめる（下の「写す・書く」）。
- 2026-11-09、PR #677 の Codex のレビュー（全 PR のマージ前のレビュー）が、利用者が Codex に、読むことを厳しくせず、いちばん緩い条件にし、決まりも小さく少なくするよう伝えたと書いた（言葉は PR #677 のそのレビューにある）。そのころ PR の決まりは、確かめを 9 回重ねて、手順が細かくなっていた（ファイルの中の注記を見つけたら止める、ISO のプレビューは読まない、許諾の種類の定義など）。2026-11-10、利用者は会話で、決まりを短く作り直すことを選んだ（「短く作り直す」）。示した中身は、次の 6 つである。
  - 公開資料はそのまま読む。
  - 購入・登録・会員・NDA・同意のボタンで同意した資料だけ、その条件に従う。
  - 無断の写しは開かない。
  - 写す・配る・写しを残すときは、そのときに許諾を確かめる。
  - 注記や許諾の種類では止めない。
  - ISO のプレビューも読む。
- 2026-11-10、PR #677 の 10 回目の確かめが、OBP のプレビューを読むと、ISO の利用許諾（ECLA）に同意したと見られうると指摘した。ECLA は出版物の一部へのアクセスでも同意したとし、6(b) はソフトウェアへの統合・符号化に別の許諾を求め、7(b) は AI で読むことを禁じる。台帳の `express` と `pdf` の権利の根拠は、ECLA に同意していないことに拠る。利用者は会話で、同意すると困ることと、プレビューから実装に得るものが少ないことを示されて、ISO の出版物は OBP のプレビューも読まないことを選んだ（「読まない形に直す」）。

## 選択肢

1. **AI での利用を禁じる持ち主のページと資料は、開かない。** 持ち主の意向にいちばん沿う。ただ、書誌の事実を得るのにも利用者の手が要り、持ち主ごとに禁止を足していくことになる。
2. **書誌の事実を読むためだけなら、ページを開いてよい。本文は読まない。** ページを読むこと自体が、注記の「AI のツールに応答を作らせる」に当たるので、注記の読み方としては弱い。
3. **仕様・ページ・資料を読めるかは、利用者が同意の操作をした条件で決める。** 公開の資料は、注記と許諾の種類によらず読む。購入・登録・会員・NDA・同意のボタンなどで同意して手に入れた資料は、その条件が AI での利用を禁じていなければ読む。何を書けるかは、著作権と今の決まりで縛る。

## 決定

3 を選ぶ。決まりは小さく少なくし、権利の問題が実際に起きる次のものだけを避ける。

- 利用者が同意の操作をした条件に反すること
- 形式の実装を縛る利用許諾に、同意したと見られること（ISO の出版物）
- 持ち主が許さずに上げた写しを、そうと知って手に入れること
- 書くものに、仕様の本文や、寛容でないライセンスのコードが混ざること
- 受け取った図面や秘密を出すこと

決まりは次のとおり。

- **読む**
  - 公開の資料は、そのまま読む。公開の資料とは、その資料の持ち主（著作権者）か、持ち主がその版の公開を許した配布者が、ログインも同意の操作もなしに誰でも見られるようにしているページとファイル（出版物の一部を見せるプレビューを含む）をいう。中の注記（AI での利用を禁じるものや、アクセス・使用で同意したとするもの）と、許諾の種類（CC の NC・ND など）では止めない。読むためにページを開き、ファイルを取得することは、写すことに数えない。
  - ISO の出版物（規格と、その一部。OBP のプレビューを含む。規格の一部として配るファイルも、ECLA が当たるかを確かめていないので、用心のために含める）は、同意の操作なしに見られるものも読まない。ECLA は、出版物の一部へのアクセスでも同意したとする。同意したと見られると、7(b) で AI で読むことが禁じられ、6(b) で形式の実装と公開が縛られうる。ISO のサイトのページ（販売のページ・書誌など）は、出版物ではないので読む。ほかの持ち主が自分で公開する同じ内容（buildingSMART の IFC など）は、その持ち主の資料として読む。ほかの持ち主の出版物に同じ形の条件が見つかっても、利用者が ISO と同じく扱うと決めるまでは、上の決まりのとおり読み、台帳の `note` に書いて利用者に知らせる。
  - 購入・登録・会員・NDA・同意のボタンなど、同意の操作をして手に入れた資料は、その条件に従う。条件が AI での利用を禁じていれば読まない。確かめていなければ、確かめるまで読まない。条件の文はエージェントが読んでまとめてよいが、読むと決めるのは利用者にする（利用規約の読みで採否が決まる権利の判断。[0254](0254-parallel-agents-and-cross-review.md)）。同意の操作は、エージェントが利用者の代わりにしない。
  - 持ち主が許さずに上げたと分かる写しは開かない。持ち主の条件が写すことを許していないウェブ・アーカイブの写しも、これに当たる。著作権を侵害して上げられたものと知りながらダウンロードすることは、軽微なものなどを除き、私的使用のための複製の例外に入らない（著作権法 30 条 1 項 4 号。2026-11-09 に e-Gov の法令 API で確かめた）。疑わしければ、持ち主の所から入手する。
  - 自動の取得を拒むページは、利用者のブラウザー（ブラウザーの拡張）で開いてよい。ログイン・CAPTCHA・支払いは越えない。利用者がログインしているサイトでは、ログインしないと見られない所も開けてしまうので、ログインした状態でしか見られないものは開かない。
  - 学習済みの知識は使ってよい。外部の実装のソースは、今の決まりのまま、寛容なライセンスのものだけを読み、GPL の実装のソースは読まない。書くコードに混ざるのを防ぐための決まりで、同意した条件によらない。
- **写す・書く**
  - 仕様の本文・表・図は写さない（今のまま）。節の番号・名前・値などの事実は書いてよい。
  - 写す・配る・作り変える・写しを残すときは、そのときにその版の許諾を確かめ、今の決まりに従う。NC・ND の読みで採否が決まるものは人を待つ（AGENTS.md）。写しを残すとは、使い続けるために置いておくこと（リポジトリ・共有のフォルダー・手元の資料の置き場など）をいう。読むためにツールが作る一時の写し（取得した出力の保存・一時フォルダー・clone など）は、使い続けなければ入らない。
- **記録する**
  - 台帳の仕様の項の `note` に、入手に同意の操作が要るかと、その条件が AI での利用を禁じるかを書く。確かめていなければ、そう書く。公開の資料の注記が AI での利用を禁じるときも、その中身を書く。注記は、折りたたまれた部分とページの下まで読む。項目は足さない。当てはまる仕様が少なく、文で足りるため。

エージェントは利用者の代わりに読むので、公開の資料を読むことは、利用者が読むことと同じに扱う。利用者が同意の操作をした条件は、エージェントが読んでも利用者を縛るので、分けて扱う。

今の仕様には、次のように当てる。

| 仕様 | 扱い |
| --- | --- |
| `iso_10303_11_2004`（EXPRESS） | 本文は ISO から買うもので、買えば利用許諾（ECLA）に同意し、7(b) が AI での利用を禁じるので、買わず、読まない。ISO の出版物なので、OBP のプレビューも読まない。この台帳の作業（#529・#666・#677）では、プレビューも読んでいない（読み取りを足した #450 が何を読んだかの記録はない）。学習済みの知識・公開された EXPRESS のスキーマ（IFC など）・寛容なライセンスの実装で読む |

## 影響

- エージェントは、ISO・ASTM などのサイトのページと、同意の操作なしに見られるファイルを、ほかの公開の資料と同じく読める。ISO の出版物は、プレビューも読まない。#669 で決めるまで ISO のページを開かないとした扱いは終わる。確かめる側も、同じ決まりで読む。
- ISO のサイトの注記は、使う者が ISO の著作権の条件を受け入れることを前提とし、ISO の内容を AI に使うことを禁じる。ほかの持ち主のページやファイルの注記にも、同じ書き方のものがある。注記を知ったうえで読み続けると、条件に同意したと見られる余地は残る。利用者は 2026-11-10 に、注記では止めないことを選んだ（背景）。読むのは事実で、本文・表・図は写さない。
- ISO の出版物を、プレビューも読まないのは、ECLA が、出版物の一部へのアクセスでも同意したとするからである（前文と 1 節）。同意したと見られると、7(b) で AI で読むことが禁じられ、6(b) で形式の実装と公開が縛られうる。台帳の `express` と `pdf` の権利の根拠は、ECLA に同意していないことに拠る。プレビューは、序文・適用範囲・引用規格・用語が主で、実装に要る中身はほとんどないと見た（学習済みの知識による。この作業ではプレビューを読んでいない）。ほかの持ち主の出版物に同じ形の条件が見つかったときは、利用者が決めるまで読み続けるので、そのあいだに同意したと見られる状態ができうる。止めると、やめた「注記で止める」手順に戻るので、知らせて利用者に決めてもらう形にした。
- 読むためにファイルを取得することは写すことに数えないが、写しを残して使い続けると、許諾の範囲の外になることがある。たとえば CC BY-NC の許諾は、営利の目的での複製を許さない。そのため、写しを残すときは、そのときに許諾を確かめる。
- ISO の ECLA は、出版物を買うか使う者（Licensee）について、4 節で、組み込み・デジタルの統合・派生物を作る権利を許す使い方に含めず、6(b) で、出版物をソフトウェアなどに統合・符号化・運用化することに別の許諾を求める。言葉の範囲は広く、仕様に従って形式を実装して公開することが当たるかは、文からは分からない。このリポジトリは ISO の出版物を同梱せず、本文・表・図を写さないが、当たるかの判断は利用者がする。
- `pdf` の権利は、[0017](0017-format-rights-ledger-and-plugin-sdk.md) の定義どおりなら、条件を確かめられていないので `unknown`（`core` に置けない）になりうる。#674 で無償版の条件（ECLA が当たるか）が分かるまで `public` のままにするのは、利用者の判断による。分かったら、0017 に照らして `rights` を見直す。それまで、エージェントは本文を読まない。
- 本文を読めない仕様は、学習済みの知識・公開の資料・寛容なライセンスの実装と、テストで確かめた結果で実装する。台帳の実装の根拠（`basis`）は、今の決まりのとおりに書く。
- 入手に同意の操作が要るかは、`access` だけでは分からない。`iso_32000_2_2020` は `public`（無償）だが、店の手続きと EULA のもとで受け取る。そのため `note` に書く。

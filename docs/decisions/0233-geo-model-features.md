# 0233: 地理の領域モデルは、地物を元の型の名前と属性と LOD ごとの形で持ち、座標は元の座標系の空間のまま持つ

## 背景

段階 3（[#304](https://github.com/zumen-jp/zumen/issues/304)）は、基盤地図情報（GML）・拡張 DM・CityGML（PLATEAU・i-UR）を読む。3 つの形式を受ける地理の領域モデル（L2、[決定 0008](0008-model-layers-and-codecs.md)）の中身を決める（#377）。

3 つの形式は、次のように書く。

- 基盤地図情報（台帳の `fgd_dl_4_1`）: JPGIS の GML で、地物（道路縁・建築物の外周線・等高線など）を、型と属性と、点・線・面で書く。座標は JGD2011 の経緯度か平面直角座標系。
- 拡張 DM（台帳の `extdm_a1_291`）: 固定の長さのレコードで、図形を分類コードと座標の列で書く。旧測地系（日本測地系）のデータもある。
- CityGML（台帳の `citygml_2_0`・`plateau_5_1`）: 地物（建築物・道路・土地利用など）を、型・属性・LOD ごとの形で書く。PLATEAU は i-UR の拡張の属性と、コードリストの値を使う。座標は JGD2011 の経緯度と標高（EPSG:6697）が多い。

どの形式も、地物の型の数が多く、版ごとに増える。CityGML の LOD2 以上は、立体を面の集まりで書く。

## 選択肢

地物の型の持ち方の選択肢は、次の 3 つ。

1. 地物の型を、Rust の型（列挙）にする。
2. 地物の型を、元の名前の文字のまま持ち、型の語彙（表示の名前・分類）をプロファイルに置く。
3. 地物の型ごとに、型付きの拡張（[決定 0022](0022-drawing2d-semantics-and-format-mapping.md)）にする。

座標の持ち方の選択肢は、次の 2 つ。

1. 読むときに、平面直角座標系に直す。
2. 元の座標系の空間のまま持ち、使うときに直す。

## 決定

地物の型は選択肢 2、座標は選択肢 2 にする。

### crate と依存

- 地理の領域モデルは、新しい crate `zumen-geo` に置く。依存は `zumen-base`・`zumen-crs`・`zumen-geom3d` だけにする。形式の crate が、このモデルに移す。

### 地物

- モデル（`GeoModel`）は、地物の列・座標系・高さの基準と成果を持つ。
- 地物（`Feature`）は、ID・型・分類コード・名前・属性・形の列・親の地物・出所を持つ。
  - 型は、名前空間の接頭辞をつけた元の名前の文字（`bldg:Building`・`fgd:RdEdg` など）で持つ。
  - 分類コードは、元の値の文字のまま持つ（拡張 DM の分類コード、PLATEAU のコードリストの値）。
  - 属性は、接頭辞をつけた元の名前と、型つきの値（文字・整数・実数・真偽・日付・コード・単位つきの量）の組の列にする。i-UR の拡張の属性も、同じ列に持つ。持たない属性を既定の値で埋めない。
- 型とコードの語彙（表示の名前、図面のレイヤ・色への対応）は、プロファイルの語彙（[決定 0138](0138-profiles-as-versioned-data.md)）に置く。モデルは語彙を知らない。
- 地物の入れ子（建築物と、その部分・付属物）は、親の地物の番号で持つ。

### 形

- 形（`Geometry`）は、LOD（0〜4、2D の地物は `None`）と、点・線・面・立体のどれかを持つ。1 つの地物は、LOD の違う形をいくつも持てる。
- 点・線・面は、点の列（面は外周と穴）で持つ。
- 立体と面の集まり（CityGML の `gml:Solid`・`gml:MultiSurface`）は、`zumen-geom3d` の `Shape` の面の集まり（`FaceSet`）にし、評価しないで持つ（[決定 0222](0222-geom3d-types-and-kernel-trait.md)）。暗黙の形（`ImplicitGeometry`）は `Mapped` にする。

### 座標

- 座標は、元の座標系の空間（[決定 0019](0019-coordinate-systems-and-gsi-data.md)）のまま持つ。経緯度の座標系なら地理の点（緯度・経度）、平面直角座標系なら地図の点（`northing`・`easting`）にし、標高は別に持つ。軸の順は、読むときに形式の順から直す。
- 3D の形の点（`[f64; 3]`）は、地理の空間なら（緯度・経度・標高）、地図の空間なら（`easting`・`northing`・標高）の順にする。
- 図面やシーンに出すときに、要求で名指した平面直角座標系の系へ直す。系の指定がなければ、モデルの範囲の中心の系にして `assumed` で知らせる。
- 旧測地系と JGD2000 の座標系は、座標系の名前として受ける（`zumen-crs` の `Crs` に足す）。JGD2011 との変換（TKY2JGD・PatchJGD）は、拡張 DM の旧測地系のデータを読むときに作り、変換のパラメーターの格子は利用者が渡す（ジオイドと同じ、決定 0019）。変換がなければ、座標系の違う地物を比べず、診断する。

### ID と出所

- ID は `gml:id` から作る（#1）。`gml:id` がなければ、親の地物の ID と型と、親の中の順の番号から作る。拡張 DM は、レコードの順の番号から作る。
- 出所は、元の要素かレコードのバイトの範囲にする。

### 図面と 3D のシーン

- 地図を図面の下敷きにするときは、地物を図面モデルの要素にする（`lower`）。点・線・面は、平面図の空間（x を東、y を北、[決定 0231](0231-civil-drawings.md) と同じ）の点・折れ線・閉じた折れ線にし、レイヤは型の語彙から決める。下敷き（`Underlay`）の種類は足さない。
- 3D の形は、3D のシーン（[決定 0213](0213-scene3d-sections-and-op.md)）の要素の行に、地物の ID・型・名前を入れて返す。階の欄は空にする。いまのシーンの作り方は建物モデルに結びついているので、地理の領域モデルから作る道は、別の作業で足す。

### wasm のモジュール

- 地理の領域モデルと 3 つの形式は、土木・地理のモジュール（#380、決定 0013）に入れる。

## 影響

- 地物の型の語彙は、形式の版ごとにプロファイルの版を足して増やす。モデルの型は変えない。
- 平面直角座標系の系をまたぐ地物（全国の基盤地図情報など）は、1 つの系に直すと歪む。系をまたぐ図は、まだ作らない。

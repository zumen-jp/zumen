# 0251: 基盤地図情報の配布のアーカイブは中の項目の名前で見分け、地物の ID を項目の名前と gml:id の組にする

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-03 |
| 状態 | 採用 |

## 背景

国土地理院の基盤地図情報は、ダウンロードサービスから ZIP のアーカイブで配られる（ファイル仕様書 4.1 節）。アーカイブは提供クラスごと（`FG-GML-ppppqq-ss-YYYYMMDD.zip`）か全項目（`FG-GML-ppppqq-ALL-YYYYMMDD.zip`）で、中に `FG-GML-ppppqq-提供クラス-YYYYMMDD-0001.xml` の GML を入れる（「基盤地図情報データのファイル名について」、2025-07-31）。数値標高モデルのアーカイブも `FG-GML-` で始まる名前の GML を入れる。#378 は GML を 1 つずつ開くところまで作った（[決定 0233](0233-geo-model-features.md)、`docs/formats/fgd.md`）。

決めることは 2 つ。

- アーカイブの判定。ZIP の署名は SFZ・P2Z・ifcZIP・xlsx などと重なり、中の `.xml` という終わりだけでは見分けられない。判定の規則（`zumen-sdk` の `Signature`）は、項目の名前の終わり（`ZipEntry`）しか持たない。
- 地物の ID。`gml:id` は GML の文書の中でしか一意でなく、同じアーカイブの別の GML に同じ `gml:id`（`K1_1` など）がある。決定 0233 は、ID を `gml:id` から作るとした。ID は契約なので、アーカイブの中の ID の作り方を先に決める。

## 選択肢

### 判定

1. 判定の規則に、項目のフォルダーを除いた名前の始まりと終わりで比べる形（`ZipName`）を足し、`FG-GML-` で始まる `.xml`・`.zip` の項目を持つアーカイブを基盤地図情報とする。
2. 中の `.xml` の項目の XML の根（`Dataset` と名前空間）で比べる。判定に展開が要る。
3. 判定せず、形式を名指して開く。

### ID

1. 項目の名前と `#` と GML の中の ID（`FG-GML-533945-RdEdg-20250801-0001.xml#K1_1`）。
2. 基盤地図情報レコード ID（`fid`）。
3. アーカイブの中の順の番号。

## 決定

判定は選択肢 1、ID は選択肢 1 を採る。

- 判定に展開を要すると、判定の手間がアーカイブの大きさで決まり、JavaScript のラッパーの判定（[決定 0221](0221-wasm-modules.md)）も展開を持つことになる。名前の規則は国土地理院が公開していて、ダウンロードのアーカイブの名前を利用者が変えても、中の項目の名前は残る。
- ID の `gml:id` の部分は、GML を 1 つずつ開いたときと同じにする。`fid` は地物の型ごとに付くとは限らず（DEM の構成点など）、決定 0233 と揃わない。順の番号は、アーカイブの項目を足すと変わる。

### 判定の規則

- `Signature::ZipName { prefixes, suffixes }` を足す。ディレクトリでない項目の、フォルダーを除いた名前のどれかが、ASCII の大文字と小文字を区別せずに `prefixes` のどれかで始まり、`suffixes` のどれかで終わるなら合う。`schema/boundary.toml` では、`zip-entry` に `zip-prefix` を添えて書く。JavaScript のラッパーの判定も同じ読み方にする（規則の種類 `zip_name`）。
- 基盤地図情報のアーカイブの規則は、始まり `FG-GML-`・終わり `.xml` と `.zip`。open は、SFZ・P2Z の後、ifcZIP の前に試す。

### 読み方

- アーカイブの中の、`FG-GML-` で始まる `.xml` の項目を、アーカイブの順に GML として読む。`FG-GML-` で始まる `.zip` の項目（全項目のアーカイブが提供クラスごとのアーカイブを入れる場合）は、1 段だけ開く。ほかの項目は `fgd.entry.unsupported` を返して読まない。
- 地物の ID は、項目の名前と `#` と、GML を 1 つで開いたときの ID。入れ子のアーカイブの項目は、外の項目の名前と `/` でつなぐ。親の地物の番号は、まとめたモデルの中の番号に直す。
- 出所のバイトの範囲は、項目を展開したバイト列の中の範囲。どの項目かは ID で分かる。
- 文書の座標系と高さの基準は、初めの形を持つ項目のもの。違う座標系か高さの基準の項目は、`fgd.crs.unsupported`（値は項目の名前）を返し、その項目の形を移さない。地物と属性は移す。
- 読めない GML の項目は、XML の読み取りの診断を返し、ほかの項目を読み進める。

## 影響

- `zumen-sdk` の `Signature` に `ZipName` が増えた。`Signature` を網羅して照らすプラグインは、この形を足す必要がある。
- 判定の規則の表に、基盤地図情報のアーカイブの行が増えた。capabilities の形式の一覧は変わらない（形式は `fgd` のまま）。

# 0286: TKY2JGD・PatchJGD の格子は、間隔を格子点の並びから見分けて補間し、地震などごとの PatchJGD のファイルを古い順に当てる

## 背景

[0237](0237-datum-transformations.md) は、TKY2JGD・PatchJGD の格子を、点を囲む四隅の格子点（緯度 30 秒・経度 45 秒の間隔）で双一次に補間するとし、PatchJGD の格子を 1 つだけ受けるとした。#670 で、次のことが分かった。

- **間隔。** TKY2JGD の論文（飛田、国土地理院時報 No.97、2001）は、格子点を 3 次メッシュの南西の隅とし、間隔を緯度 30 秒・経度 45 秒とする。国土地理院が載せる tokachi2003.par のヘッダー情報の例も、隣り合う 3 次メッシュのコードの行を並べる。一方、公共測量成果改定マニュアル（国土地理院技術資料 A1-No.337、令和 7 年 4 月）の第 3 条の解説は、補正パラメーターの格子を、3 次メッシュのコードの末位 2 桁が 00・05・50・55 のメッシュの南西の隅とし、緯度・経度で 150 秒・225 秒の整数倍とする。3 次メッシュの 5 倍の間隔である。0237 の補間は、この間隔の格子では、多くの点で四隅の格子点を見つけないので、PatchJGD の補正量を黙って 0 にする。ファイルのヘッダーは、間隔を書かない（2026-11-09 に、国土地理院の座標補正パラメータファイルの一覧のヘッダー情報で確かめた）。
- **複数のファイル。** 同じ解説は、同じ地区に地震ごとのパラメーターのファイルが複数あれば、成果を得た時期より後のものを古い年代順に当てるとし、どのファイルを当てるかは、利用者が成果を得た時期で選ぶとする。国土地理院は、地震などごとに PatchJGD のファイルを配る。JGD2000 から JGD2011 にするファイルのほかに、2011 年より前の地震などで JGD2000 の成果を改定するファイルと、2011 年より後の地震などで JGD2011 の成果を改定するファイルがある。
- **照合。** jgdtrans 0.3.1（MIT OR Apache-2.0、[0019](0019-coordinate-systems-and-gsi-data.md) の表）は、同じ形のファイルを読み、補間する。0237 は、実行時の依存にしないとした。照合に使う外部の実装は、寛容なライセンスの crate なら dev の依存にできる（[0254](0254-parallel-agents-and-cross-review.md)）。

## 選択肢

### 間隔

1. **3 次メッシュの間隔だけで補間する（今のまま）。** 5 倍の間隔の格子で、補正量を黙って 0 にする。
2. **5 倍の間隔だけで補間する。** マニュアルの解説には合うが、TKY2JGD と、3 次メッシュの間隔の PatchJGD のファイルを補間できない。
3. **呼ぶ側が間隔を渡す。** ファイルが間隔を書かないので、呼ぶ側も決められない。誤った間隔を渡すと、1 と同じく黙って 0 にする。
4. **格子点の並びから見分ける。** 格子点がすべて 5 倍の間隔の所にあれば、その間隔にする。そうでなく、3 次メッシュの間隔で隣り合う格子点があれば、3 次メッシュの間隔にする。どちらでもなければ読まない。

### 複数のファイル

1. **呼ぶ側が順に当てる。** 経緯度で格子を当てる関数を出し、呼ぶ側が、平面直角座標と経緯度の換算を挟んで順に呼ぶ。手順が長く、楕円体や系を取り違えやすい。
2. **変換に、PatchJGD の格子を並べて渡す。** 渡した順に当て、後のファイルは、前のファイルで直した経緯度で補間する。

## 決定

間隔は 4、複数のファイルは 2 にする。

- **間隔。** `ShiftGrid` は、読んだ格子点の並びから間隔を決める。
  - 格子点がすべて、3 次メッシュのコードの末位 2 桁が 00・05・50・55 の所にあれば、緯度 150 秒・経度 225 秒の間隔とし、点を囲むその四隅の格子点で双一次に補間する。
  - そうでなく、3 次メッシュの間隔で南北か東西に隣り合う格子点が 1 組でもあれば、0237 のとおり、緯度 30 秒・経度 45 秒の間隔で補間する。
  - どちらでもない並び（3 次メッシュの 1 つおきなど）は、補間の間隔が決まらないので、`crs.datum-grid.unsupported` で読まない。
  - 間隔は、ファイルの中で一様とする。3 次メッシュの間隔で隣り合う格子点と、5 倍の間隔だけの所が混ざったファイルは、全体を 3 次メッシュの間隔とみなすので、5 倍の間隔だけの所の点は、補正量を 0 にするか直さない。国土地理院のファイルが一様かは、#664 で確かめる。
  - 決めた間隔は、`ShiftGrid::spacing` で返す。
- **複数のファイル。** `Shifts::patch` で、PatchJGD の格子を並べて渡す。
  - 呼ぶ側は、直したい座標を得た時期より後のファイルを、古い順に並べる。
  - `to_jgd2011` は並びの順に当て、後のファイルは、前のファイルで直した経緯度で補間する。
  - 点を囲む格子点が 1 つもないファイルは、0237 のとおり補正量を 0 とする。一部だけがあるファイルでは、`crs.datum-shift.missing` を返して直さない。ファイルが複数なら、診断の `grid` に、渡した順の番号を付ける（`PatchJGD 2` など）。
  - 並びが空なら、0237 のとおり `crs.datum-grid.missing` を返す。
  - ファイルは、日本測地系と JGD2000 の座標にだけ当てる。上の並べ方では、並びは、2011 年より前の改定（JGD2000 の成果を改定するもの）、JGD2000 から JGD2011 にするファイル、その後の改定の順になる。JGD2011 の平面直角座標は、0237 の順で変換の行き先なので、そのまま返し、ファイルを当てない。そのため、2011 年より後の地震などによる改定のファイルは、地震などの前に得た JGD2011 の座標に当てられない。JGD2011 の座標に当てる扱いは、#678 で決める。
- **照合。** jgdtrans 0.3.1 を `zumen-crs` の dev の依存にし、テストの中で作った格子で、読んだ格子点と補間の値を照らす。実行時の読み取りと補間は、0237 のとおり自前で持つ。依存を足す理由は、次のとおり。
  - ライセンスは MIT OR Apache-2.0 で、`deny.toml` の一覧の中にある。既定の feature では、依存を持たない。
  - std の HashMap（反復の順が実行ごとに変わる）と、target の FMA の有無で変わる積和と、std の `f64::hypot`（水平の補正量の大きさと、統計の計算）を使う（0237 の選択肢 2）。テストは `hypot` を使う関数を呼ばず、格子点をコードで引き、補間の値を差の上限つきで比べるので、テストの結果は変わらない。
  - 配る成果物には入らない（[0269](0269-license-texts-per-artifact.md)・[0279](0279-sbom-per-artifact.md) は dev の依存を除く）。wasm32-unknown-unknown でも組み立てられる（2026-11-09 に `cargo check -p zumen-crs --tests --target wasm32-unknown-unknown` で確かめた）が、wasm32 の適合テストには使わない。
  - jgdtrans は、データの行を桁の位置で読み、ヘッダーの行数を形で決める（TKY2JGD は 2 行、PatchJGD は 16 行）。5 倍の間隔で補間する形は、SemiDynaEXE などに限る。テストの格子は、その桁と行数と形で書く。

## 影響

- 5 倍の間隔の PatchJGD のファイルで、補正量を黙って 0 にしない（間隔がファイルの中で一様なとき）。3 次メッシュの間隔の格子の補間は、0237 と同じ計算で、値もビット単位で変わらない。
- `Shifts::patch` の型が、`Option<&ShiftGrid>` からスライス（`&[&ShiftGrid]`）に変わる。`zumen-crs` はまだ公開していない（#317）。API のメッセージには出ていない。
- 3 次メッシュのコードで表せない所（緯度 0 度未満・66 度 40 分以上、経度 100 度未満・200 度以上）の点は、格子点がないものとして扱う。補正量の極端な TKY2JGD の格子で直した点で、格子点の番号があふれる（debug の build でパニックする）ことも、これで防ぐ。そうした点は平面直角座標に換算できず、まだ診断せずに直さない。これは #679 で直す。
- 国土地理院のパラメーターのファイルの間隔とヘッダーは、#664 で確かめる。テストの中で作った格子を外部の実装と照らしても、段は `synthetic` のまま（[0255](0255-verification-levels-in-the-ledger.md)）。
- 0237 は元の記録を残し、この決定へのリンクを足す。

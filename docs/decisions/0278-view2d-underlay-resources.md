# 0278: 表示部品のアンダーレイは内容と画素を利用側で解決し、中断した結果も解放する

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-06 |
| 状態 | 採用 |

## 背景

[決定 0267](0267-view2d-on-scene-columns.md) は、画像・PDF を利用側の解決関数から得て、表示部品自身は取得・送信しないとした。シーンには、元の参照名・ページ名、左下の基点と 2 つの辺、内容全体を収める `corners` と 1 単位を表す `unit` がある（決定 0114・0125・0172・0178）。#587 では、この契約に従って表示し、表示範囲・上限・中断と資源の寿命を具体化する。

## 選択肢

1. 利用側へ表示先の Canvas を渡し、その場で非同期に描いてもらう。
2. 利用側から全体の画像を 1 回受け取り、拡大して表示する。
3. 内容の寸法を解決してから、表示範囲に必要な画素を要求し、結果を表示部品が合成する。

1 は、差し替え後の古い処理が表示先へ描いてしまう。2 は大きな画像や PDF の全体を高解像度で持つことになる。3 を採る。内容の寸法を先に受け取るため、`unit` の辺に掛ける寸法を推測せず、画素の確保前に要求を止められる。

## 決定

### 解決と配置

- `underlayRenderer` または `setUnderlayRenderer` で関数を明示する。画像と PDF に、文書識別、要素 ID と配置の道筋、列の画像番号、元の参照名・ページ名、AbortSignal と上限を渡す。名前を URL として取得せず、ページ名を番号へ変換しない。DWF・DGN と未知の種類は未対応と報告する。
- 関数は、内容の幅・高さ、`render` と `dispose` を返す。内容の原点は左下、Y は上とする。`corners` は内容全体を 2 つの辺へ収め、`unit` は内容の寸法を辺に掛ける。PDF の内容の単位やページ回転の扱いは利用側が明示する。
- `render` には内容の単位での長方形と、画素比を反映した整数の幅・高さを渡す。利用側は、その長方形を表す左上原点の ImageBitmap・Canvas・OffscreenCanvas と、その `dispose` を返す。寸法が要求と違う結果は描かない。表示先の Canvas は渡さない。
- 要求する範囲は、画像の枠と画面の交差を内容へ戻した長方形とする。内側を残す切り抜きの外形でも絞る。多角形の正確な共通部分と反転した切り抜きは、既存の Canvas の切り抜きで処理する。このため、要求する長方形の中に最後には描かない部分が残ることはある。
- シーンの塊・単位・種類の描画順に合成し、画像を最背面へ移さない。大きい原点と相対座標、回転・反転・傾斜を保つ。画像は自身の画素と透明度で描き、図形の色・選択色で染めない。非表示レイヤは描かず、保持した資源を解放する。
- シーンの範囲を、解決した寸法で書き換えない。`fit` は引き続き SceneResult の範囲を使う。画像の画素を読む当たり判定や、画像・PDF 内の図形の吸着は足さない。既存の線・面・文字・点の判定を保つ。

### 中断と寿命

- 解決と描画の関数は、同期通知を抜けた後に呼ぶ。関数の同期部分・返却値のプロパティ取得・解放・中断の通知からの変更再入は拒否する。受領した画素は要求を出した資源に結び付けて解放する。表示部品の状態の通知も、決定 0274 の同期通知と再入禁止を保つ。
- 表示範囲や画素比が変わって、必要な範囲か画素数が変わったときは、以前の描画要求を中断する。同じ内容と画素数を別の位置・回転で使えるときは画素を再利用する。同じ資源で前の描画が未完了なら、完了してから次を始める。
- `refreshUnderlays` は失敗と中断を解除し、資源から解決し直す。`cancelUnderlays` は再読込か、関数・シーンの差し替えまで停止する。関数の変更、成功したシーンの差し替え、非表示や画面外、破棄では、その資源と未完了の要求を中断する。検査に失敗したシーンの差し替えは現在の資源を保つ。
- 返した資源と画像の所有権は、表示部品へ渡す。渡した画像を変更・転送・close しない。古い要求や破棄後に届いた結果も描かずに `dispose` を 1 回呼ぶ。利用側が同じ内容を共有する場合は、所有権を渡す単位ごとに包み、参照数を利用側で管理する。
- 画像の解放が終わり、未完了の描画も終わってから、その資源を解放する。`dispose` は Promise を返せる。中断した処理や解放が未完了なら、資源と画素の上限からまだ除かない。利用側が中断後も完了しなければ、新しい要求が上限で止まることがある。
- 解決・描画・結果の検査・解放の失敗を理由で区別し、要素参照を付けて報告する。例外の本文は報告へ写さない。現行の資源と画素はそれぞれの要求で識別する。解放が失敗しても残りの解放を続ける。再表示・再読込・範囲変更・シーン差し替えで次の要求に移った後や、破棄後に届く旧要求の失敗は、新しい状態へ混ぜない。失敗は自動で無限に試し直さず、再読込を待つ。
- `getState().underlays` と `underlay` イベントで、画像ごとの未解決・処理中・描画可能・中断・画面外・上限・失敗を返す。シーン・レイヤ・カメラの操作で画像の状態も変わった場合、その操作と `underlay` の各購読に同じ状態を渡し、全体の購読には 1 回だけ通知する。`getReport` にも未描画の理由を反映する。非同期の完了後は描画と状態を更新してから通知する。通知の例外はホストへ伝わるが、残りの購読への通知は完了する。

### 上限と依存

- `underlayJobs` は未完了の解決と描画、`underlayResources` は解決中・保持中・解放中の資源、`underlayPixels` は保持した画像と未完了の描画要求の総画素数を制限する。`underlaySide` は画像の一辺を制限する。表示の列を読む長さ・画像の件数・範囲を絞る作業も既存の上限に数える。
- `underlayBytes` は利用側へ渡す 1 資源の入力・復号の上限とする。利用側の取得・デコーダー内部の確保や実行を、表示部品は監視・強制停止できない。利用側は上限を確保前に数え、中断に応じる。返った画像の寸法を調べることだけで、復号前の上限を守れたとはしない。
- 表示部品の実行時の依存は増やさない。画像のアダプターと、pdf.js を注入するアダプターを利用側の例に置く。PDF の検査は、既存の外部の検証用 pdf.js 6.5.438（Apache-2.0）を使う。これは表示部品の依存・配布物には入れない。pdf.js 自身のブラウザーの下限を、表示部品の下限と混ぜない。

## 影響

利用側は、参照名と自分が持つ入力を明示して結ぶ。解決関数を渡さなくても、従来の `resource-unresolved` と要素 ID が得られる。React の #588 は、資源を二重に管理せず、この状態と破棄を使う。PDF の例は入力バイト数と出力 Canvas の上限を示すもので、pdf.js 内部の全確保量の保証ではない。

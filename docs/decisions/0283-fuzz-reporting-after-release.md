# 0283: 初回リリース後に見つけた入力と詳細は修正版を公開するまで非公開にする

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-07 |
| 状態 | 採用 |

## 背景

[0261](0261-fuzz-outside-required-checks.md) は、fuzz が見つけた失敗を issue にして早めに直す。初回リリース後に同じ手順で入力や実行の詳細を貼ると、影響を受ける版を利用者が使っている間に、その入力が公開される。

## 選択肢

1. 公開の issue に対象と失敗の種類を記録し、入力と詳細は非公開のセキュリティアドバイザリで扱う。
2. 修正版を公開するまで、対象と失敗の種類も含めて非公開のセキュリティアドバイザリで扱う。

## 決定

利用者は 2026-11-07 に「公開 issue に対象と失敗の種類を記録し、入力と詳細は修正版の公開まで非公開にする」と決めた。選択肢 1 では、利用者は未修正の問題があることを公開の計画から知ることができる。初回リリース以降、パニック・時間切れ・メモリの使い過ぎなど、入力によって起きる不具合に適用する。

報告者は [非公開の報告窓口](https://github.com/zumen-jp/zumen/security/advisories/new) を使う。担当者は、公開の issue には対象（fuzz なら target）と失敗の種類だけを書く。入力、誤りの文、実行の ID、調べた結果、同じ失敗かを見分ける情報は、非公開のアドバイザリに公開 issue の番号と一緒に記録する。入力を添えるときは [0258](0258-fuzz-seeds-and-runs.md) に従って出所とライセンスを示す。受け取った図面と秘密は添えない。

## 影響

- 0261 の補ったことの 3〜5 の記録先を、初回リリース後はこの決定に合わせる。PR との関係の判定、修正を確かめるテスト、マージの条件、利用者が認める失敗の範囲は 0261 に従う。承認時の実行の ID と詳しい比較は非公開で照合する。
- PR・毎晩・手動の実行の記録、ログ、artifact、キャッシュ、回帰テストにも同じ公開時期を適用する。修正とテストは非公開で確かめ、修正版が利用者に届く形で公開されたあとに、詳細と公開できる合成のテストを出し、公開 issue と結ぶ。
- 初回リリース前にリポジトリの fuzz が見つけた入力の扱いは 0258・0261 に従う。外部からの脆弱性の報告窓口は初回リリース前から非公開である。

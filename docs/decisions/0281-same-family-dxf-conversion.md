# 0281: 対応する同系統の図面は共有オブジェクト表から DXF に書く

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-07 |
| 状態 | 採用 |

## 背景

決定 0008 は同系統の再符号化をファイルモデル（L1）の責任とした。DXF と DWG は決定 0023 のオブジェクト表を共有する。一方、決定 0206 の `convert` は図面モデル（L2）から要素を追加して新しい DXF を作る。公開 R2004 DWG の弧長寸法は DXF がそのまま持てるが、この経路では寸法と描画ブロックの中身が落ちる。

## 選択肢

1. 図面モデルと公開 API の形に、DWG の弧長寸法と AutoCAD の描画ブロックを再現するためのフィールドを足す。
2. L2 で作った DXF に寸法だけを追加し直す。ハンドルの付け替え、ブロックとスタイルの二重登録、すでに返した欠落の診断との照合が要る。
3. 同じ符号化の系統で共有するオブジェクト表から DXF を書く。参照を含めて扱える図面を対象とし、それ以外は従来の経路を使う。

## 決定

3 を選ぶ。同系統の図面で必要な情報を、形式に依存しない L2 や各言語の API に持ち込まずに済む。

- 経路を選ぶ単位は文書とする。最初に扱うのは、R2004 DWG の弧長寸法とその描画ブロックを含む図面。図形・所有者・表・ブロック・用紙の参照を確認し、同じ共有表から DXF の各セクションを組み立てる。範囲とフィールドの扱いは [DXF の文書](../formats/dxf.md#r2004-dwg-の弧長寸法)に置く。
- 対応する図形・参照の組み合わせから外れたら、同じ表から L2 を作り、決定 0206 の経路で変換する。選ばなかった経路の途中のファイルや欠落の診断は返さない。予算と中断は両方の経路を通して効かせる。
- 書いたオブジェクトには元のハンドルを使う。出力対象外のデータは種類・件数と元の場所を診断する。診断順、予算による失敗、出力先名の扱いは既存の `convert` とそろえる。
- 対応を広げるときは、対象の公開 DWG と比較先の DXF を外部のリーダーで読み、保存した値と参照を照合する。ネイティブと wasm では同じ応答と出力バイト列を確認する。

## 影響

呼び出しは従来の `convert` と同じで、同じ形式に編集を書き戻す `apply` は元の L1 を使う。新しい経路の対象では、出力ファイル・要素数・診断が変わる。元のファイルの要素 ID の規則は決定 0156 に従う。

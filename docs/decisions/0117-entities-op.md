# 0117: 要素の一覧を返す entities の op は、空間と出所で作る ID と、offset と limit で続きを読む

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-28 |
| 状態 | 採用 |

## 背景

[決定 0012](0012-boundary-functions-and-messages.md) は、要素の一覧を返す `entities` の op の例と、一覧を返す op が件数の上限と続きの位置（`limit`・`next_offset`）を持つことを決めた。続きを要求する欄の名前と、要素の ID の形は決めていない。図面モデルの要素（[決定 0022](0022-drawing2d-semantics-and-format-mapping.md)）は専用の ID を持たず、出所（L1 のレコードの番号かバイト範囲）を持つ。ID は契約で、同じバイト列には、どの版でも同じ ID を返す。

## 選択肢

ID の形は、次の 3 つを比べた。

1. 空間か用紙の ID と、要素列の中の番号で作る。
2. 空間か用紙の ID と、要素の出所で作る。
3. 出所だけで作る。

続きを要求する欄は、次の 2 つを比べた。

1. `offset`（整数）。応答の `next_offset` を、そのまま次の要求に渡す。
2. 中身を見せない文字列の `cursor`。

## 決定

ID は選択肢 2、続きの欄は選択肢 1 を採る。番号で作ると、後の版で移す図形が増えたとき、後ろの要素の ID がずれる。出所だけで作ると、どの空間の要素かが ID から分からず、同じレコードから別の空間に移す要素を分けられない。`cursor` は中身を後で変えられるが、決定 0012 の `next_offset`（整数）と形が合わない。

- **要求。** `doc`（`open` で作った文書の名前）、`offset`（書かなければ 0）、`limit`（1 以上 10000 以下。書かなければ 1000）を持つ。
- **順。** 実寸の空間をモデルの順に並べ、それぞれの要素を要素列の順（入力の順）に並べる。その後に、用紙を同じように並べる。描く順は使わない。記号の定義の中の要素は、まだ返さない。
- **応答。** `items`（`offset` から `limit` 個まで）、`total`（全体の要素の数）、`next_offset`（続きがあるときだけ。次の要素の位置）を返す。`offset` が `total` 以上なら、`items` を空にする。
- **ID。** `space/<空間の ID>/` か `sheet/<用紙の ID>/` の後に、出所を続ける。後に[決定 0156](0156-drawing-stable-ids-and-preconditions.md) で、用紙の ID と、形式が鍵を持つ要素の出所の部分を、鍵（ハンドルかインスタンスの番号）で作ることにした。
  - DXF のレコードは `r<番号>`、DWG のバイト範囲は `b<先頭の位置>`。
  - 同じ空間の中で、同じ出所の要素が 2 つ以上あれば、2 つ目から `/1`・`/2` と出てきた順の番号を足す。
  - 出所のない要素は、要素列の中の番号で `e<番号>` とする。ファイルから読んだ要素は、出所を持つ。
- **項目の欄。** `id`、`kind`（形の種類。図面モデルの `Shape` の種類ごとに 1 つ。書式つきの文字は `formatted_text`）、`layer`（レイヤの元の名前。図面モデルにレイヤがなければ持たない）、`source`（出所のレコードの番号かバイト範囲）を持つ。
- **予算。** 返す項目 1 つごとに、`work` を 1 と数える。図面モデルへの変換の分は、`drawing` と同じに数える。

## 影響

- 範囲（`bbox`）・欄の選び方（`fields`）・場所での絞り込み（`view`・`region`）は、後で欄を足す。
- 1 つのレコードから 2 つ以上の要素を作る変換で、後の版がその間に要素を足すと、`/1` などの番号はずれる。
- 呼ぶたびに図面モデルへ変換し直す。続きを読む呼び出しも、変換の手間を同じに数える。

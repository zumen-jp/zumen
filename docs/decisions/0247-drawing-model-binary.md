# 0247: 図面モデルのバイナリを型の契約から作り、図面のプラグインの wasm のモジュールをプラグインの形式だけにする

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-02 |
| 状態 | 採用 |

## 背景

[決定 0243](0243-plugin-bundling.md) では、図面のプラグインの wasm のモジュールを、当面、コアの図面のモジュールにプラグインを足したものにした。[決定 0017](0017-format-rights-ledger-and-plugin-sdk.md) の形（プラグインの形式だけを持ち、公式のモジュールと図面モデル（L2）のバイナリでやり取りする）は、配置がなかったので見送った。この形では、プラグインのモジュールがコアの図面のモジュールと同じ大きさ（約 7 MB）になる。

[#481](https://github.com/zumen-jp/zumen/issues/481) で、決定 0017 の形に移す。決めることは、次のとおり。

- 図面モデル（`Drawing2D`）のバイナリの配置と、版と互換の規則。各言語の包みとプラグインが長く頼る、公開の契約になる。
- 約 130 の型の読み書きを、手で書き写さずに保つ方法。
- プラグインのモジュールから公式のモジュールへの渡し方と、受け取った図面の文書の扱い。

## 選択肢

渡し方の選択肢は、次の 3 つ。

1. **図面モデルのバイナリの配置を新しく決める。** 図面モデルのすべての欄を渡せる。決める仕事が大きい。
2. **プラグインのモジュールが、`drawing`・`entities` の応答と同じ JSON を返す。** 新しい配置は要らないが、JSON に出ない欄が落ちる。
3. **決定 0243 の形のままにする。** プラグインのモジュールが約 7 MB のまま。

読み書きの作り方の選択肢は、次の 3 つ。

1. **型ごとに手で書く。** 型を変えるたびに書き写し、漏れても気づきにくい。
2. **派生のマクロ（serde と、その上の形式など）を使う。** 依存が増える。配置が型の定義に埋もれ、欄を並べ替えるだけで配置が変わる。
3. **`cargo xtask codegen` が、型の定義から型の契約を書き足し、契約から読み書きを作る。** 配置が `schema/` の契約に残り、壊す変更を生成のときに止められる。

## 決定

渡し方は 1、作り方は 3 を選ぶ。

### 配置

- 入れ物は、決定 0137 の 2D のシーン（`ZMSC`）と同じ形にする。見出しは `ZMDR`、大版（u16）、小版（u16）、要素の数（u32）、区画の数（u32）。続けて区画ごとに始まりと長さ（u32）を置き、各区画を 8 バイトの境界に置く。数はリトルエンディアン。
- 区画 0 は元の文書（形式・系統・ハッシュ）、区画 1 は図面モデル。
- 区画の中は、列に分けず、値を型の契約の順に並べる。図面モデルは列挙の木で、描くために読むものではないため。
  - 符号のない整数は最短の LEB128、符号のある整数は zigzag の LEB128、`u8` は 1 バイト、`f64` はビットの 8 バイト。`char` は符号位置。
  - `bool` と `Option` の有無は、0 か 1 の 1 バイト。文字列は UTF-8 のバイト数と中身。一覧は項目の数と項目。配列と組は項目だけ。
  - 名前のある欄の構造体と、列挙の値の欄は、中身のバイト数を前に置く。欄に名前のない構造体（`LayerId(u32)` など）は、中の値だけを置く。
  - 列挙は、値の番号（契約の順）と中身。
- 同じ値からは、同じバイト列を書く。NaN と −0 も、ビットのまま書く。読み手は最短の形だけを受け付けるので、読んだものを書き直すと同じバイト列になる。
- 区画の長さは u32 なので、4 GiB を超える区画は書けない。書き手は u32 の最大にし、読み手は、区画が入力の外に出るので壊れているとみなす（2D のシーンと同じ）。

### 版と互換

- 決定 0137 と同じく、読み手は、同じ大版で小版が新しいものを読む。
  - 小版では、構造体の欄・列挙の値・区画を、後ろに足すだけにする。
  - 書き手の小版が読み手より新しいときだけ、知らない欄と区画を読み飛ばし、警告（`drawing.binary-field.dropped`・`drawing.binary-section.dropped`）を足す。同じか古い小版で余りがあれば、壊れているとみなす。
  - 古いバイナリにない欄は、既定の値にする。
  - 知らない列挙の値は、意味を推し量らずに `drawing.binary-value.unsupported` で断る。
- 欄と値を消す・名前や型を変える・区画の意味を変えるときは、大版を上げる。違う大版は `drawing.binary-version.unsupported`、壊れたものは `drawing.binary.invalid` で断る。
- 読むときは、入力のバイト数（`input-bytes`）、作る値の大きさ（`decoded-bytes`、一覧を作る前に数える）、要素の数（`elements`、見出しの数と合うかも確かめる）の予算で止める。

### 型の契約と生成

- `schema/drawing.toml` に、`Drawing2D` と `Source` からたどれる型（126）の欄と値の並びを、版と一緒に置く。後の小版で足した欄と値には、その小版を書く。
- `cargo xtask codegen` は、`crates/zumen-drawing/src` の型の定義を読み、契約と突き合わせる。足した型・欄・値を後ろに足して小版を上げ、読み書き（`crates/zumen-drawing/src/binary/generated.rs`）を作る。消した欄と値、型を変えた欄は、大版を上げないと書けないので誤りにする。CI の `codegen --check` が、型に追いついていない契約を見つける。
- 欄を外に見せない出所（`Ref`、`zumen-base`）は、手で書く。欄の順が契約と合うかは、xtask が確かめる。
- `usize` の欄（ビューの番号など）は、64 ビットの整数として書く。32 ビットの wasm で収まらない値は、読めない。
- 図面モデルの名前空間とキー（`&'static str`）を、`Cow<'static, str>` にした。形式の読み込みは今までどおり静的な文字列を借り、バイナリから読んだときだけ持つ。
- 読み書きは、`zumen-drawing` の `binary` の feature にする。乱数の図面モデル（`random` の feature）で、往復して同じ値・同じバイト列になること、壊したバイト列でも止まることを確かめる。

### 境界

- op `lift` を足す（スキーマの小版 60）。開いた図面の文書を図面モデルに変換し、図面モデルのバイナリを blob（種類 `drawing`）で返す。区画 0 には、元の文書の形式・系統・ハッシュを書く。
- 図面のモジュールの open は、`ZMDR` で始まる入力を図面モデルのバイナリとして読み、読むだけの文書にする。
  - 形式・系統・ハッシュは、区画 0 の値を返す。ハッシュは書いた側が付けたもので、読む側では確かめられない。
  - 図面を読む op（drawing・entities・tables・scene・convert など）は、元の文書と同じ答えを返す。apply は `call.document.unsupported` を返す。
  - lift のときの診断は、バイナリに持たない。
- `schema/boundary.toml` にモジュール `plugin` を足す。op は capabilities・open・close・describe・lift で、コアの形式を持たない。`zumen-abi` の `plugin` の feature で作り、コアの形式の文書と、それを読み書きする op を入れない。図面のモジュールの op にも lift を足す。プラグインの土台のモジュールは、プラグインの crate と一緒に作るものなので、リリースの wasm には入れない。
- `ZMDR` の判定の規則は、まだ `schema/boundary.toml` に足さない。JavaScript の包みの `loadModules` は、プラグインのモジュールで開いた図面を、図面のモジュールへ自動では渡さない（[#483](https://github.com/zumen-jp/zumen/issues/483)）。

### ひな形

- `templates/plugin` の wasm のモジュールは、`zumen-abi` を `plugin` の feature だけで使う。`plugin.json` の `module` は `plugin`。ネイティブのライブラリと CLI は、今までどおりコアの形式も持つ。
- 決定 0243 の wasm のモジュールの中身は、図面の形式について、当面の 2 から 1 に替える。建物の形式（[決定 0245](0245-building-format-plugins.md)）は、建物モデルのバイナリがないので、コアの建物のモジュールに足す形のまま（[#484](https://github.com/zumen-jp/zumen/issues/484)）。

## 影響

- wasm のモジュールの大きさは、次のとおり（`wasm32-unknown-unknown` の release、名前の区画を含む）。ひな形のプラグインは、図面のモジュールの約 14% になる。

| モジュール | バイト | brotli で |
| --- | --- | --- |
| 図面（`drawing`） | 7,424,864 | 1,383,563 |
| 建物（`bim`） | 1,742,455 | 433,912 |
| プラグインの土台（`plugin`、プラグインなし） | 998,988 | 185,251 |
| ひな形のプラグイン（`templates/plugin`） | 1,004,984 | 187,626 |

- プラグインのモジュールに残る大きいものは、名前の区画（約 190 KB）、すべての op の要求を読む部分、describe のカタログなど。さらに小さくするかは、[#485](https://github.com/zumen-jp/zumen/issues/485) で扱う。
- バイナリは誰でも作れるので、op は、コーデックが作らない形の図面モデルでも止まる必要がある。乱数の図面モデルを開いて図面を読む op を流す試験で、次の止まらない処理を見つけて直した。どの処理も形式によらないので、コアの形式から作った図面モデルでも、値しだいで同じ所を通る。
  - クロソイドの外接の箱と、シーンのハッチの線の行。大きな値に 1 を足しても変わらず、繰り返しが終わらなかった。回数で数える。
  - 配置の格子の升。升をすべて集めてから歩いていたので、行と列の数が大きいと記憶を食った。集めずに歩き、升ごとに `work` を数える。

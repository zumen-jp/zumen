# 0171: 再配布を認めるライセンスの公開サンプルは、出所とライセンスを台帳に書いて Git に入れる

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-30 |
| 状態 | 採用 |

## 背景

`AGENTS.md` は、受け取った図面も公開サンプルも Git に入れないとしている。実際の図面で確かめる試験は、`ZUMEN_SAMPLES` に指定したリポジトリの外のフォルダーを読み、指定がなければ何も確かめない。

そのため、次の問題があった。

- CI は、実際の図面での振る舞いを一度も確かめない。試料での確認は、試験を書いた人の手元でしか再現できない。
- 適合試験（#66）の完了の条件は、合成でない入力 1 つ以上で、ネイティブと wasm32 の出力の一致を確かめることである。入れられる入力がなく、条件を満たせなかった。
- 公開されている図面には、パブリックドメインや CC BY のように、再配布を認めるものがある。それでも一律に外に置いていた。

Git に入れてはいけない理由は、2 つある。権利（再配布の許諾がないもの・顧客の図面）と、リポジトリの大きさである。ライセンスで再配布を認めた公開の図面なら、前者は当てはまらない。

## 選択肢

1. 今のまま、公開サンプルも Git に入れない。
2. 再配布を認めるライセンスの公開サンプルだけを、リポジトリの `samples/` に入れる。出所とライセンスとハッシュを台帳に書き、CI で確かめる。
3. 公開サンプルを、別のリポジトリに置く。試験のときに版を固定して取得する。
4. 公開サンプルを、Git に入れず、CI が試験のときに出所の URL から取得する。

1 は、#66 の条件を満たせず、CI が実際の図面を確かめない今の形のままである。3 は、リポジトリを分けるほどの量がまだなく、版を合わせる手間が増える（[決定 0004](0004-repositories.md) は、権利と配布の都合があるときだけ分ける）。4 は、出所の URL が変わるか消えると試験が壊れ、取得したものが同じかを毎回確かめる必要がある。

## 決定

選択肢 2 を選ぶ。

- **入れてよいライセンス。** 目的を問わず、再配布・改変・商用の利用を、条件なしか表示だけを条件に認めるもの。
  - パブリックドメイン、CC0
  - CC BY（2.0〜4.0）
  - 公共データ利用規約（PDL1.0）、政府標準利用規約（第 2.0 版）。日本の官公庁の公開データの多くがこれに当たる
  - MIT・BSD・Apache-2.0・ISC・Zlib などの寛容なライセンス
- **入れないもの。**
  - ライセンスや利用条件が書かれていないもの。ダウンロードできることは、再配布の許諾ではない。
  - 非営利に限るもの（NC）、改変を禁じるもの（ND）、同じ条件での公開を求めるもの（SA）。SA は、依存に GPL などを入れない方針（[決定 0011](0011-bindings-through-ffi.md)）と同じく、扱いを分かりやすくするために入れない。
  - 利用規約で再配布を禁じるもの。ソフトウェアの製品に付く試料で、使用許諾が再配布を認めないものも含む。
  - 受け取った図面と、顧客の図面。公開されていても、個人の氏名・住所・連絡先が読めるもの。
- **置き場所。** `samples/<形式>/` に、取得したままのファイルを置く（例: `samples/dxf/`・`samples/jww/`・`samples/sxf/`）。手を加えたものは、変えた内容を台帳に書く（CC BY は変更の表示を求める）。
- **台帳。** `samples/ledger.toml` に、ファイルごとに次を書く。
  - 置き場所の道筋、SHA-256、バイト数
  - 題、公開した者、出所の URL、取得した日
  - ライセンス（SPDX の識別子か、規約の名前と版）と、その本文の URL、表示の文
  - 変えた内容（変えていなければ書かない）
- **大きさ。** 1 つのファイルを 5 MB まで、`samples/` の全体を 100 MB までにする。超えるものは、今までどおり `ZUMEN_SAMPLES` で扱う。全体の上限を上げるか、別のリポジトリに移すかは、新しい決定で決める。
- **確かめること。** `cargo xtask` に、台帳の検査を足し、CI で流す。`samples/` のファイルと台帳の項目が一対一であること、ハッシュとバイト数が合うこと、ライセンスが上の一覧にあること、大きさが上限の内であることを確かめる。
- **足すときの手順。** サンプルを足す PR に、ライセンスの本文の URL と、再配布を認める箇所を書く。ライセンスがはっきりしなければ、足さずに利用者に尋ねる。
- **試験。** 試料を読む試験は、`samples/` を読む。`ZUMEN_SAMPLES` も、今までどおり、Git に入れられない図面のために読む。CI の時間を大きく延ばす試験（すべての試料での書き戻しなど）は、今までどおり指定したときだけ流す。
- **ライセンスの表示。** `samples/` のファイルは、リポジトリのライセンス（MIT OR Apache-2.0）ではなく、台帳に書いたそれぞれのライセンスに従う。`samples/README.md` と `CONTRIBUTING.md` にそう書く。配る crate とパッケージには、`samples/` を入れない。

## 影響

- `AGENTS.md` の「公開サンプルを Git に入れない」を、この決定の条件に改める。受け取った図面を入れないことは変わらない。
- #66 の完了の条件（合成でない入力 1 つ以上）を、`samples/` の図面で満たせるようになる。台帳の検査と最初のサンプルは、#66 で作る。
- 試料を読む試験のコメントの「図面は Git に入れない」は、`samples/` を読むようにする PR で直す。
- リポジトリを複製する量が、最大で 100 MB 増える。
- 入れたサンプルの出所が後で消えても、台帳に出所・取得した日・ライセンスが残る。

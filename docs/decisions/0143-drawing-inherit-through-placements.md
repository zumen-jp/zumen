# 0143: 記号の定義の中の要素の継承は、配置の並びで解く

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-28 |
| 状態 | 採用 |

## 背景

[決定 0112](0112-drawing-symbol-definitions.md) は、記号の定義の中の要素の色・線種で、配置から継承するもの（DXF の BYBLOCK）を継承のまま持ち、「配置で解く処理は、まだない」とした（#174 の「BYBLOCK を配置で解くこと」）。図面モデルの `Drawing2D::color_of` などはレイヤからの継承だけを解き、配置からの継承（`Inherit::Block`）はそのまま返す。そのため、表示する使い手は、継承の解き方をそれぞれ書く必要があった。

AutoCAD の系統では、もう 1 つの規則がある。ブロックの中でレイヤ「0」にある図形は、配置（INSERT）のレイヤにあるものとして描く。レイヤからの継承（ByLayer）も、配置のレイヤの値で解く。この規則を知らない使い手は、ブロックの中の図形をレイヤ 0 の色で描いてしまう。手元の試料の DXF では、モデル空間に置いたブロックの中で、配置から色を継承する図形が 1108 件、レイヤ 0 でレイヤから色を継承する図形が 315 件あった。

## 選択肢

1. 図面モデルに、要素と配置を内側から外側へ並べた列で継承を解く関数を足す。レイヤには、配置のレイヤに従うかの印を足す。
2. 読み手が配置ごとに定義を展開し、継承を解いた値で要素を写す。
3. 解き方を文書にだけ書き、使い手に任せる。

## 決定

選択肢 1 を採る。

- 展開（選択肢 2）は、決定 0112 が採らなかった。配置の数だけ中身が増え、定義と配置の区別がなくなる。
- 文書だけ（選択肢 3）では、同じ解き方を使い手ごとに書くことになる。レイヤ 0 の規則は形式の知識なので、使い手が知らないまま誤る。
- 印は、形式の名前の規則（レイヤ「0」）を図面モデルの値に移したものである。解く関数は形式を知らずに済む。

内容は次のとおり。

- `Inheritor` は、継承を解くための色・線種・線幅（`Style`）とレイヤの組である。要素から作れる（`From<&Element<P>>`）。用紙の要素も、定義の中の要素も、同じ形で並べられる。
- `Drawing2D::color_placed`・`line_type_placed`・`line_weight_placed` は、要素とそれを置いた配置を内側から外側へ並べた列を受け取る。
  - 列の先頭から見て、値を持てばその値を返す。
  - 配置から継承するなら、次の配置へ進む。列が尽きれば `Inherit::Block` のまま返す。
  - レイヤから継承するなら、そのレイヤの値で解く。レイヤが値を持たなければ `Inherit::Layer` のまま返す。ただし、そのレイヤが配置のレイヤに従うなら、外側の配置のレイヤへ進み、従わないレイヤに着いたらそれで解く。列の最後まで従うレイヤなら、最後のもののレイヤで解く。
  - 線幅は、たどる途中で元の形式から読めていない線幅（`None`）に当たれば `None` を返す。
- `Layer.follows_placement` は、記号の定義の中の要素がこのレイヤにあれば、レイヤからの継承を配置のレイヤで解く印である。
  - DXF・DWG は、名前が「0」のレイヤで立てる。
  - JWW・SXF は立てない。JWW のブロックの中の要素は自分のレイヤを持ち、SXF の部分図・作図部品の中の要素の扱いには、レイヤ「0」に当たる規則がないため（推定）。

## 影響

- 表示する使い手は、配置をたどりながら列を作り、これらの関数で色・線種・線幅を得る。列の作り方（どの配置からたどるか）は、使い手が決める。後に[決定 0159](0159-drawing-walk-placements.md) で、配置をたどって要素ごとの値を返す関数を図面モデルに置くことにした。
- 配置のレイヤに従うのは、レイヤからの継承の解き方だけである。レイヤの表示・印刷の可否（`LayerState`）を配置のレイヤで決めることは、まだ扱わない。
- 引出線つきの注記の記号（`CalloutContent::Symbol`）の中身は、引出線の要素を配置として並べる。
- 既存の `color_of` などは変えない。列が要素 1 つなら、`color_of` などと同じ値を返す。
- 図面モデルの `Layer` に欄が増えるので、`Layer` を作る使い手は欄を足す必要がある。

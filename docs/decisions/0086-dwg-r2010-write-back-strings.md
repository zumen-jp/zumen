# 0086: R2010 から後の DWG の文字列を持つ図形は、型ごとのフィールドと一緒に文字列のストリームを書き直す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

R2010 から後の DWG への書き戻しは、文字列を持たない単純な図形のフィールドから始めた（[決定 0085](0085-dwg-r2010-write-back.md)）。R2007 からの図形は、文字列（T）を主のデータに置かず、主のデータの後の文字列のストリームに TU（BS の文字の数と UTF-16LE）で置く。ストリームの後には、ストリームのビットの数（RS。0x8000 に収まらなければ上位の RS が前に付く）と、ストリームがあるかのフラグ（B）が続き、その後にハンドルのストリームが始まる。

## 選択肢

1. 型ごとのフィールドを変えたときは、主のデータの型ごとのフィールドと文字列のストリームを一緒に符号化し直し、ストリームのビットの数とフラグを書き直す。
2. 文字列のストリームはそのまま写し、文字列の値の変更は受け付けない。
3. 文字列を持つ図形は、まだ書き戻さない。

## 決定

選択肢 1 を採る。符号化の書き手が文字列のストリームを持ち、T を UTF-8 から TU に直してそこに書く。図形の共通のフィールドは文字列を持たないので、型ごとのフィールドの文字列がストリームのすべてになる。

- 元の値を符号化したストリームが元のストリームのビットと同じで、主のデータの長さも元と同じときだけ、新しい値で書き直す。サンプルのストリームの TU は、終わりの NUL を持たなかった。
- TEXT と、R2010・R2013 の ATTRIB・ATTDEF を書き戻す。ATTRIB・ATTDEF は、名前の前のバージョン（RC）とフラグの後の位置を固定するか（B）を、表の 2 つの 280 から書く。ATTDEF の問いの前のバージョン（RC）は、元のビットを写す。
- R2004 と同じに符号化できる LWPOLYLINE・INSERT・MLINE と、R2010 の SPLINE も書き戻す。
- MTEXT・DIMENSION・HATCH・TOLERANCE・VIEWPORT・SHAPE・VERTEX、R2018 の ATTRIB・ATTDEF、R2013 からの SPLINE、MINSERT は、元の値を符号化しても元のデータと合わないか、サンプルで確かめていないので、`dwg.change.unsupported` で受け付けない。回転を持つ INSERT も、度から直した角度が元のビットと同じにならないと受け付けない。

## 影響

- サンプルの R2010・R2013・R2018 の図面で、TEXT・ATTRIB・ATTDEF の文字列に日本語を足し、LWPOLYLINE・INSERT・MLINE・SPLINE の点を動かして書き、読み直した表が変えた表と同じになった。
- 書いた図面を AutoCAD で開いて確かめてはいない。

# 0070: R2004 の入れ物は、置き換えた区切りだけを圧縮し直し、ページを並べ直して地図と見出しを作り直して書く

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

R2004 から後の DWG は、入れ物の区切りを展開して読む（[決定 0026](0026-dwg-r2004-container.md)・[決定 0027](0027-dwg-r2010-reading.md)）。書くときは元のバイト列をそのまま写すだけで、区切りを変えたファイルは書けなかった。R2004 から後のオブジェクトの書き換えには、展開した区切りから入れ物を組み直す書き手が要る。

試料の R2004・R2010・R2013・R2018 の図面では、次のようになっていた。

- ページは `0x100` から隙間なく並ぶ。データのページの大きさは、見出しとデータを `0x20` の倍数に切り上げたもので、見出しの 4 つめの欄と同じ。地図のページも `0x20` の倍数に切り上げる。
- ファイルの終わりは、ページの地図のページ、空のページの見出し（`0x14` バイト）、2 つめの見出しの順で、2 つめの見出しは暗号化した見出しと同じバイト列だった。
- 暗号化した見出しは、最後のページの番号、ページの地図の番号と位置、区切りの地図の番号、2 つめの見出しの位置、ページの数を持つ。
- データのページの見出しは位置を含まず、位置との排他的論理和で隠すだけだった。
- ファイルの見出しの `0x0D` と `0x20` は、プレビューと要約の区切りのページのデータの位置を指していた。
- `AcDb:FileDepList` は暗号化の欄が 2 で、読む側は読まない。

## 選択肢

1. 置き換えた区切りだけを圧縮し直し、ほかのページは元のバイト列を写す。ページの番号を振り直し、2 つの地図と見出しを作り直す。
2. すべての区切りを、展開したバイト列から圧縮し直す。
3. 置き換えた区切りのページを、ファイルの終わりに足す。

## 決定

選択肢 1 を採る。選択肢 2 は、読まない暗号化した区切りを書けない。選択肢 3 は、古いページが残り、ページの地図に空いたページの項目が要る。

- ページは元の位置の順に並べ、番号を 1 から振り直す。置き換えた区切りのページは、その区切りの元の初めのページの所に置く。区切りの地図とページの地図は、その後に、この順で置く。
- 置き換えていない区切りのページは、見出しを新しい位置で隠し直して写す。後ろは 0 で埋める。
- 置き換えた区切りは、ページの最大の大きさごとに分け、0 で埋めてから、圧縮する区切りは ODS の 4 の圧縮で縮める。圧縮は、距離 `0x4000` までの一致を 3 バイトのハッシュの鎖で探す。
- ページの地図の自分の大きさは、見出しと続く空のページの見出しを含めて `0x20` の倍数に切り上げる。試料の図面では、この大きさと合わないものもあった。
- 暗号化した見出しは、読んだものの番号・位置・数の欄を書き直し、CRC を計算し直す。2 つめの見出しにも同じバイト列を置く。
- ファイルの見出しの `0x0D` と `0x20` が元のページのデータを指していれば、動いた先に合わせる。
- 区切りを置き換えていなければ、これまでどおり元のバイト列を写す。

## 影響

- 手組みの入れ物で、区切りを置き換えて書き、読み直した区切りが置き換えた区切りと同じになった。圧縮は、乱れたバイト・繰り返し・0 の並びを、展開して元に戻ることを確かめた。
- 試料の R2004・R2010・R2013・R2018 の 7 つの図面で、そのまま組み直したものと、読めた区切りをすべて置き換えたものを読み直し、区切りが元と同じで、診断も出なかった。区切りをすべて置き換えると、ファイルは元より少し小さくなった。
- 書いた図面を、AutoCAD で開いて確かめてはいない。ページの地図の自分の大きさの決め方と、データのページの後ろの埋め方（試料には乱数の列で埋めたものもある）は、仕様の文からは決まらない。
- 区切りを置き換える口は、まだ R2004 から後のオブジェクトの書き換えにつないでいない。

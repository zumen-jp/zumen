# 0282: 旧版の赤入れは同じ図面を照合して移し、座標の写し方を利用側から受け、指摘の ID を入力から決める

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-08 |
| 状態 | 採用 |

## 背景

[旧版の決定 0021](https://github.com/zumen-jp/zumen-legacy/blob/7c1c400e9791bd60f4a5bba355ca90362ad607c2/docs/decisions/0021-drawing-markup.md) の赤入れは、対象を元の図面の SHA-256、項目を利用側が付けた ID で識別する。点は旧版のビューの座標にある。[決定 0214](0214-review-model-and-bcf.md) と [0218](0218-review-document-and-ops.md) のレビュー文書では、対象は文書内の ID と `v2:` のハッシュ、指摘は UUID を持つ。指摘のピンは指摘に属する 2D の場所になった。

旧版のビューと現行の用紙・空間は、座標系が同じとは限らない。

- DXF・DWG のモデル空間: 旧版は図面の単位を mm に直し、原点から遠い図面では、図形の代表点の中央値の近くへ 1 m 単位で原点を寄せた（[`origin_shift`](https://github.com/zumen-jp/zumen-legacy/blob/7c1c400e9791bd60f4a5bba355ca90362ad607c2/crates/zumen-dxf/src/scene.rs#L3456)）。現行の空間は図面の単位のままで、原点も寄せない（[0156](0156-drawing-stable-ids-and-preconditions.md)・[0267](0267-view2d-on-scene-columns.md)）。
- DXF・DWG のレイアウト: 旧版は紙空間の座標に用紙の単位を掛け、余白と印刷の原点を足した（[`layout_sheet`](https://github.com/zumen-jp/zumen-legacy/blob/7c1c400e9791bd60f4a5bba355ca90362ad607c2/crates/zumen-dxf/src/scene.rs#L3623)）。現行は LAYOUT の範囲の最小を原点にする（`crates/zumen-acad/src/drawing/layout.rs`）。
- JWW の用紙: 旧版（[`scene.rs`](https://github.com/zumen-jp/zumen-legacy/blob/7c1c400e9791bd60f4a5bba355ca90362ad607c2/crates/zumen-jww/src/scene.rs#L523)）も現行（`crates/zumen-jww/src/drawing.rs`）も、用紙の中心を原点とする座標を、用紙の左下を原点とする mm に直す。用紙の大きさの表も同じである。
- SXF・PDF: 旧版と現行の座標系を照らしていない。

## 選択肢

### 座標

- A. 点をそのまま使う。DXF・DWG では、単位と原点の差の分だけ黙ってずれる。
- B. 旧版の規則で図面から変換を求める。旧版の原点の寄せ方とレイアウトの規則を手元のツールに写し、図面を開くために形式の crate を足す。写し違えると、気付けないずれになる。
- C. 対応表にビューごとの縮尺と移動を書いてもらい、書いていないビューでは止める。点をそのまま使うのは、座標系が同じと確かめたビューだけにする。
- D. 座標系が違うビューへの対応を断る。DXF・DWG の赤入れを移せない。

### 指摘の ID

1. 各実行で新しい UUID を作る。移行を繰り返すと指摘の ID が変わる。
2. UUID 以外の ID を、対応表で UUID に結ぶ。対応表をなくしたときや、別の人が別の対応表で移したときに、同じ旧版の指摘が別の ID になる。
3. 旧版の図面の SHA-256 と項目の ID から UUID（バージョン 8）を決める。[0218](0218-review-document-and-ops.md) の照合の指摘と、[0220](0220-bcf-3-0.md) の Guid でない ID と同じく、同じ入力から同じ ID にする。対応表は上書きに使う。

## 決定

座標は C、指摘の ID は 3 を採る。

移行時に、同じバイト列の SHA-256 が旧版の記録と一致することを確認し、現行の図面のハッシュを決定 0156 の実装で計算する。対象の ID と、旧版のビューから現行の用紙・空間への対応は利用側が渡す。対応には、「現行の点 = 旧版の点 × 縮尺 + 移動」の正の縮尺と移動を書く。点をそのまま使う対応は JWW の図面の用紙（`sheet/`）にだけ許し、ほかのビューで縮尺と移動がなければ止める。写した点が有限の数にならないときも止め、その位置を返す。写した点の元の値は、`legacy.points`・`legacy.position` に保って報告する。

図形の ID はそのままにする。指摘の ID は、対応表にあればその UUID、旧版の ID が UUID ならその ID を使う。ほかは、旧版の図面の SHA-256 と項目の ID から決める。決め方は、`zumen-review/legacy-markup` と NUL のあとに、2 つの値の UTF-8 を、それぞれ長さ（8 バイトのリトルエンディアン）を前置して並べ、その SHA-256 の先頭 16 バイトをバージョン 8・RFC 9562 の変種にする。指摘の 2D の場所の ID には、旧版の項目の ID を使う。対応するビューが欠けた場合、ID が重なった場合、対応表に書いた指摘の ID が旧版にない場合は、作業を止める。

旧版の意味だけを持つ値は、元のキーに `legacy.` を付けた拡張フィールドに保ち、移行時に元の JSON Pointer を報告する。利用側が付けたデータもこの方法で持ち運ぶ。指摘の範囲は写した頂点を現行の長方形で囲み、元の多角形も保つ。図形と指摘が混在した場合は、元の描画順を文書の `legacy_item_order` に項目の ID で保つ。

## 影響

- 移行は手元のツールで 1 回行える。同じ旧版の文書・図面・対応表からは同じ文書になる。対応表の `topic_ids` がなくても、指摘の ID は変わらない。
- 同じ図面に対する別の旧版の文書が同じ項目の ID を使うと、指摘の ID が重なる。その文書をまとめるときは、対応表で別の UUID を指定する。
- ツールは図面を開かない。対応表の用紙・空間の ID が図面にあるかと、縮尺と移動が正しいかは、利用側が `drawing`・`entities` で確かめる（[旧版の赤入れの移行手順](../review-migration.md)）。
- 線の太さ・文字の高さなど、旧版が用紙の mm で持つ大きさは写さず、`legacy.` のキーに保つ。
- 各言語の通常の読み取り・保存には、移行結果を現行のレビュー文書として渡せる。旧版の要素参照・引き継ぎ元の SHA-256 は拡張フィールドに残り、対応を確かめてから現行の参照に結べる。

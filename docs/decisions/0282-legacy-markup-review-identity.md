# 0282: 旧版の赤入れを移すときは同じ図面を照合し、ビューと指摘の ID の対応を利用側から受ける

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-07 |
| 状態 | 採用 |

## 背景

[旧版の決定 0021](https://github.com/zumen-jp/zumen-legacy/blob/7c1c400e9791bd60f4a5bba355ca90362ad607c2/docs/decisions/0021-drawing-markup.md) の赤入れは、対象を元の図面の SHA-256、項目を利用側が付けた ID で識別する。図面上の位置は旧版のビューの用紙座標にある。[決定 0214](0214-review-model-and-bcf.md) と [0218](0218-review-document-and-ops.md) のレビュー文書では、対象は文書内の ID と `v2:` のハッシュ、指摘は UUID を持つ。指摘のピンは指摘に属する 2D の場所になった。

## 選択肢

1. ビューを名前で照合し、各実行で新しい UUID を作る。移行を繰り返すと指摘の ID が変わる。用紙の名前が重なる図面で、位置を特定できない。
2. 実際の図面を照合し、旧版のビューと、UUID 以外の指摘 ID は明示した対応表で移す。同じ入力と対応表からは同じ文書になる。利用側は最初に対応表を作る。

## 決定

選択肢 2 を採る。移行時に同じバイト列の SHA-256 が旧版の記録と一致することを確認し、現行の図面のハッシュを決定 0156 の実装で計算する。対象の ID と、旧版のビューから現行の用紙・ビューへの対応は利用側が渡す。用紙上の mm と座標の向きは共通なので、点は元の値を使う。

図形の ID はそのままにする。指摘の ID が UUID なら保ち、ほかは対応表で一意の UUID に結ぶ。指摘の 2D の場所の ID に旧版の項目の ID を使う。対応するビュー・UUID が欠けた場合や ID が重なった場合は、作業を止め、その位置を返す。

旧版の意味だけを持つ値は、元のキーに `legacy.` を付けた拡張フィールドに保ち、移行時に元の JSON Pointer を報告する。利用側が付けたデータもこの方法で持ち運ぶ。指摘の範囲は現行の長方形で囲み、元の多角形も保つ。図形と指摘が混在した場合は、元の描画順を文書の `legacy_item_order` に項目の ID で保つ。

## 影響

移行は手元のツールで 1 回行える。各言語の通常の読み取り・保存には、移行結果を現行のレビュー文書として渡せる。旧版の要素参照・引き継ぎ元の SHA-256 は拡張フィールドに残り、対応を確かめてから現行の参照に結べる。[旧版の赤入れの移行手順](../review-migration.md)

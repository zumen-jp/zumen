# 0258: fuzz の種に公開サンプルと合成の入力を使い、crate を変えた PR で短く、毎晩長く流す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-03 |
| 状態 | 採用 |

## 背景

[0010](0010-budget-by-work.md) の「fuzz」の節は、「PR ごとに短く、定期的に長く回す」「種には、テストキットで作る合成のファイルだけを使う」とする。#501 で、登録したすべての形式と L0 に fuzz の target を置き、CI で流す。種と、PR で流す条件と、見つけた入力を外に出すときの表示と、育てた種の引き継ぎ方と縮め方を決める。

- 0010 を決めたときは、公開サンプルを Git に入れる規則（[0171](0171-public-samples-in-git.md)）がなかった。合成のファイルだけとしたのは、受け取った図面を種にして、Git や CI に入れないためである。
- テストキットには、形式ごとに合成のファイルを作る仕組みがない。合成の入力は、適合試験の組（`bindings/conformance/cases`）と、各 crate の試験の中にある。
- fuzz の crate はワークスペースの外にあり、`cargo test --workspace` も `cargo clippy --workspace` も組み立てない。CI で組み立てて 28 の target を 20 秒ずつ流すと、6 分ほどかかる。

## 選択肢

### 種

1. テストキットで作る合成のファイルだけにする（0010 のまま）。形式ごとの生成器ができるまで、種のない target が多い。
2. 合成の入力に、公開サンプルを足す。
3. 受け取った図面も種にする。

### PR で流す条件

1. どの PR でも流す。
2. crate・種の元・fuzz の target・fuzz の workflow を変えた PR で流す。
3. fuzz の target と workflow を変えた PR でだけ流す。

### 見つけた入力を外に出すとき

見つけた入力は、種か種を変えたものである。公開サンプルには、表示を求めるライセンス（CC BY・MIT・公共データ利用規約）のものがある。

1. 公開サンプルの出所とライセンスを添えて出す。
2. 表示の要らない種（CC0 の公開サンプルと合成の入力）だけを使う。

### 育てた種と、外したサンプル

毎晩の実行は、育てた種を actions/cache で次の夜に引き継ぐ。公開サンプルを台帳から外しても、育てた種には、そのサンプルとそれを変えた入力が残る。

1. 外すときに、育てた種のキャッシュを手で消す。
2. キャッシュのキーに台帳のハッシュを入れ、台帳が変わったら前の種を戻さない。

### 育てた種の増え方

libFuzzer は、起動からの時間で止めるが、起動時に種をすべて流し終えるまでは止まらない。

1. 縮めない。種は夜ごとに増え、決まった時間のうち新しい入力を試す時間が減る。
2. 毎晩、残す前に、通る辺を変えずに縮める。
3. 縮めず、PR の実行では育てた種を戻さない。PR の実行の時間は保てるが、毎晩の実行は 1 と同じで、PR の実行が届く所も浅くなる。

## 決定

種は選択肢 2、PR で流す条件も選択肢 2、見つけた入力を外に出すときは選択肢 1、育てた種と外したサンプルは選択肢 2、育てた種の増え方も選択肢 2 にする。見つけた入力を外に出すときに選択肢 2 にすると、IFC の公開サンプルを 1 つも種にできない。IFC の公開サンプルの 12 件は、すべて表示を求める（CC BY 4.0・MIT・公共データ利用規約）。

- `cargo xtask fuzz-seeds` が、次の 4 つを、どの target にも種として書く。
  - `samples/ledger.toml` に載せた公開サンプル（0171）
  - 適合試験の組の、`push` で入れる合成の入力
  - L0 の攻撃の形（ZIP 爆弾・膨らむ deflate・書庫の入れ子・パスの走査・XML の外部実体と深い入れ子・ISO 10303-21 の深い入れ子）
  - 合成の格子（ISG・TKY2JGD・PatchJGD の形）。国土地理院のデータは使わない（[0019](0019-coordinate-systems-and-gsi-data.md)）
- 受け取った図面と、`ZUMEN_SAMPLES` のファイルは種にしない。種と見つけた入力は、Git に入れない。
- 見つけた入力を artifact に残すときは、公開サンプルの出所とライセンス（`samples/README.md`・`samples/ledger.toml`・`licenses/`）と、種か種を変えたものだという断りと、種を作ったコミット（`NOTICE.txt`）を添える。
- issue などに貼るときは、最小にした入力に、元の公開サンプルの出所とライセンスを添える。libFuzzer は元の種を記録しないので、元が分からなければ、台帳の全体を、種を作ったコミットに固定した URL で指す。サンプルを外した後も、指す先から表示が消えないようにするためである。
  - 毎晩の実行では、種を作ったコミットは、その夜の main のコミットである。
  - PR の実行では、PR と main を合わせた一時のコミットで種を作る。このコミットは、後でどの ref からも指されなくなり、残るとは限らないので、合わせた PR の head と main のコミットの台帳を並べて指す。
- 育てた種（actions/cache）のキーに、台帳（`samples/ledger.toml`）のハッシュを入れる。台帳が変わったら、前の種を戻さない。公開サンプルを台帳から外したときに、外したサンプルとそれを変えた入力を、種と artifact に残さないためである。手で消す決まりにすると、外す PR の実行と、マージまでに流れた毎晩の実行が、また残す。
- 毎晩の実行と手で流した実行は、育てた種を残す前に、target ごとに libFuzzer の `-merge=1` で、通る辺を変えずに縮める。縮めないと、種は夜ごとに増え、決まった時間のうち新しい入力を試す時間が減り、種を流すだけで決まった時間を超える target も出る。流す手順で通らなかった target は、見つけた入力の元を残すため、縮めない。縮めるときに落ちる入力・止まらない入力・メモリを使い過ぎる入力が出たときと、決まった時間で縮め終わらないときは、縮める前の種を残し、job を失敗させる。libFuzzer の縮める処理は、そうした入力を飛ばして通るので、黙って種から外さないためである。
- `crates/**`・`Cargo.toml`・`Cargo.lock`・種の元（`samples/**`・`bindings/conformance/cases/**`）・`fuzz/**`・`xtask/src/fuzz.rs`・`.github/workflows/fuzz.yml` を変えた PR で、target ごとに 20 秒流す。毎晩は target ごとに 180 秒流し、育てた種を次の夜に引き継ぐ。
- fuzz の crate の依存は、ワークスペースの `Cargo.lock` の版から解く。

## 影響

- 公開サンプルは実際のファイルの構造を持つので、合成の入力だけより深い所に届く。
- 公開サンプルはもう Git にあり、出所とライセンスを `samples/ledger.toml` と `licenses/` で示している。見つけた入力を外に出すときも、同じ表示を添える。
- 文書だけの PR では流さない。crate を変えた PR は、ほかの試験と並べて 6 分ほど流す。
- PR の実行も、台帳が同じなら main の育てた種を戻す。20 秒のうち新しい入力を試す時間が減り、種を流すのに 20 秒より長くかかる target は、その分長くかかる。
- 公開サンプルを足したとき・作り直したとき・台帳の項目を直したときも台帳が変わるので、育てた種を捨てて育て直す。
- 0010 の「fuzz」の節の 2 つの項目を、この記録で改める。

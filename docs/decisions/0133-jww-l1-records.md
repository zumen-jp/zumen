# 0133: JWW の L1 は、見出し・図形・ブロックの定義・画像を、元のバイト範囲のままレコードにする

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-28 |
| 状態 | 採用 |

## 背景

#172 で JWW（Jw_cad の図面）のコーデックを作る。[決定 0008](0008-model-layers-and-codecs.md) は、L1 を形式の構造をそのまま持つファイルモデルとし、変えずに書くと元のバイト列と一致することを求める。JWW は、`JwwData.` と版で始まり、見出しの欄（メモ・レイヤグループとレイヤ・表示と印刷の設定・SXF の色と線種・文字の設定）の後に、MFC の CArchive で書いた図形の一覧とブロックの定義の一覧を持つ。版 700 からは、その後に埋め込んだ画像の一覧が続く。見出しの欄は版で増え、公開の説明にない欄を持つファイルもある。図形の大きさは、クラスと版と一部の値（点の線種・ソリッドの色）で決まる。

## 選択肢

1. 見出しの欄をすべて解釈して持ち、図形の一覧の始まりは欄の大きさの和で決める。
2. 見出しを 1 つのレコードとして範囲で持ち、図形の一覧の始まりを、欄の大きさの和と、一覧の始まりの形を探した位置の候補から、終わりまで読めるもので決める。
3. 図形の一覧だけを読み、見出しと後ろは読まずに写す。

## 決定

選択肢 2 を採る。1 は、説明にない欄を持つファイルで一覧の始まりがずれて、全体を読めなくなる。3 は、画像を L1 で指せず、壊れた後ろと画像の一覧を区別できない。

- **レコード。** 見出し（始まりから図形の一覧の件数の前まで）、図形 1 つずつ、空のオブジェクト、ブロックの定義（中の図形の一覧の件数まで。中の図形は後ろに続くレコードで、定義の位置を持つ）、画像の件数、画像 1 つずつ。読めない後ろは 1 つのレコードにする。書くときは、レコードを元のバイトのまま並べるので、変えずに書くと元のバイト列と一致する。
- **種類。** 図形とブロックの定義はクラスの名前（`CDataSen` など）、ほかは `header`・`null`・`image-count`・`image`・`trailer` とする。図形は、オブジェクトの前の印の形（新しいクラス・2 バイトの番号・4 バイトの番号）と、クラスの位置を持つ。値は解釈しない。
- **一覧の始まり。** 版から欄の大きさを足した位置を最初の候補にする。次に、新しいクラスの印・名前の長さ（8〜32）・`CData` が続く所を探し、その前の件数（2 バイトと、`FF FF` に続く 4 バイト）と、図形がなくブロックの定義だけがあるときの 2 つ前の件数の位置を候補にする。探した候補は、見つけたクラスのオブジェクトを最初に読めたときだけ使う。
- **選び方。** 候補を順に、図形とブロックの定義の一覧を終わりまで読む。版 700 からは画像の一覧がファイルの終わりで終わり、版 700 より前は一覧がファイルの終わりで終わる最初の候補を使う。なければ、一覧を読めた最初の候補を使い、後ろを読めないバイト列として `jww.trailer.invalid` を報告する。
- **壊れた所。** `JwwData.` と版がなければ `jww.file.invalid`、どの候補でも一覧を読めなければ `jww.body.invalid` で読まない。読んだオブジェクトへの参照（Jw_cad は書かない）と、知らないクラスは読めないものとする。
- **予算。** 入力のバイト数と、レコード 1 つごとに `records` を数え、止めたら読んでいたオブジェクトの範囲を場所にする（[決定 0119](0119-budget-stop-place.md)）。書くときは、レコード 1 つごとに `work` を数える。

## 影響

- 編集（トランザクション）はまだ持たない。
- 図面モデルへの変換と、境界（`open`・`drawing`）へのつなぎは、#172 の続きで行う。
- 説明にない見出しの欄を持つファイルも、一覧の始まりを探して読める。見出しの中に一覧の始まりと同じ形があっても、終わりまで読めない候補は使わない。

# 0265: JWW の一覧の件数はレコードに分けず、最後のレコードの後ろを trailer に残す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-06 |
| 状態 | 採用 |

## 背景

[決定 0133](0133-jww-l1-records.md) は、JWW の読めない後ろを `trailer` にするとした。実装は、図形とブロックの定義の一覧の件数を独立したレコードにせず、最後のレコードの終わりから残りを `trailer` にする。このため、バージョン 700 より前で定義がないと、読めた定義の件数も `trailer` に入る。図形もないと、両方の一覧の件数が入る。診断は、一覧を終わりまで読めたかで決まる。

レコードの番号は、API のレコードの ID と図面モデルの出所に使う。区切りを変えると、同じバイト列の ID や参照先も変わりうる。

## 選択肢

1. 一覧の件数を独立したレコードにし、`trailer` は解釈できなかったバイトだけにする。
2. 読めた件数は前のレコードかヘッダーに含め、`trailer` は解釈できなかったバイトだけにする。
3. レコードの区切りと番号を保ち、`trailer` が読めた件数を含むことを明記する。

## 決定

選択肢 3 を採る。1 は後続するレコードの番号を変え、2 はレコードが指すバイト範囲を変える。件数は書き戻すときに読み直せるので、ID と参照先を変えてまで新しいレコードにする必要はない。

- 図形とブロックの定義の一覧の件数は、独立したレコードにしない。レコードの間にある件数は隙間として元のバイト列に持つ。
- 最後のレコードの終わりから残りがあれば、読めた件数も含めて `trailer` にする。バージョン 700 より前で定義がなければ定義の件数が入り、図形もなければ図形の件数も入る。バージョン 700 以降で定義がなく、画像の一覧を読めた場合は、定義の件数は `image-count` の前の隙間に残る。
- `trailer` があるだけでは壊れていると判断しない。一覧を終わりまで読めなかった場合に `jww.trailer.invalid` を返す規則は保つ。その場所は、読めた件数を含む `trailer` の全体になる。
- 一覧を書き直すときは、元の件数を読み飛ばし、書き直した件数を 1 度だけ書く。`trailer` を全体ごと追加して件数を重ねない。

## 影響

- パーサー・書き戻し・診断・レコードの区切り・ID の実装と出力を変えない。決定 0133 の `trailer` の説明を補う。
- 正常な空の定義一覧と、読めない後ろを持つ入力を、バージョン 700 の前後で確かめる。書き戻しでは、図形を追加・除去しても定義の件数が重ならないことを確かめる。

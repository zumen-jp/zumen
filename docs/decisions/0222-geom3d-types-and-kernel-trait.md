## 背景

[決定 0018](0018-geometry-layers-and-tolerances.md) は、3D のカーネルを trait の裏に置き、日本の BIM ソフトの書き出しで測って選ぶとした。試料がないので、カーネルの選定（#5、[決定 0207](0207-building-model-components.md) の「試料を得てから決めること」の 2）は止まっている。#414 は、試料がなくても決められる型と trait を作り、候補を合成の形で比べる。次のことが決まっていなかった。

- 型と trait の形。
- 建物モデルの形の項目（`zumen_building::ShapeItem`）と、geom3d の依存の向き。
- 候補のうち、試料で測るものをどれにするか。

## 決定

### 型と trait（`zumen-geom3d`）

- 点とベクトルは `[f64; 3]`（geom2d の `[f64; 2]` に合わせる）、配置は 3 行 4 列のアフィン変換 `Transform`、平面は点と法線の `Plane`。角度は度、三角関数は `libm`。
- メッシュ `Mesh` は、点・外向きの三角形・描く辺を持つ。要素の形 `Part<E>` は、使う側の要素の ID を型の引数に持つ。体積・面積・箱・同じ座標の点の統合・閉じているかの判定・変換を持つ。
- 評価する形 `Shape` は、形式を知らない形にする。押し出し・回転・円の断面の掃引・面の集合・三角形の集合・ブーリアン・半空間・写像・組。断面は、折れ線と円の輪にする。半空間は、平面の裏を中身とする。IFC の `AgreementFlag` などは、写す側が向きを揃える。
- `Kernel::evaluate(&Shape, Tolerance, &mut Cx) -> Result<Mesh, Failure>`。失敗は、評価しない種類・正しくない形・カーネルの失敗・予算と中断の 4 つの値で返し、パニックしない。作った三角形の数を予算の `segments` で数える（決定 0010）。
- `Section::section(&Mesh, &Plane, &mut Cx)` は、切り口を平面の局所の 2D の輪にし、中身を左に見る向きにする。どのカーネルのメッシュにも使える `MeshSection` を置く。点の符号は、平面の上を裏に寄せ、向きを点の符号だけで決め、交点を座標でつなぐ。頂点を通る切り口と、点の番号が分かれたメッシュでも輪になる。閉じていないメッシュは、開いた鎖にする。
- `zumen_geom3d::cases` に、候補を試料なしで比べる合成の形の組を置く。期待する体積と箱は、形から解析的に求める。

### 依存の向き

- `zumen-geom3d` は、`zumen-base`・`zumen-geom2d`・`libm` だけに依存し、建物モデルを知らない（決定 0008）。
- `zumen-building` は geom3d に依存しない。L2 の形状表現は評価せずに持つ（決定 0018・0207）。
- 建物モデルの形の項目を `Shape` に写し、カーネルで評価するのは、両方に依存する側（段階 2 の、建物モデルの形を評価する issue）に置く。今の `ShapeItem` は種類と子だけを持つので、写すのに要る値（断面・深さ・点など）は、試料で使う項目を数えてから、そのときに足す（決定 0207 の「試料を得てから決めること」の 1）。

### 候補の比較（`bench/kernels`）

結果は [bench/kernels/README.md](../../bench/kernels/README.md) にある。要点は次のとおり。

- manifold-rust（Apache-2.0、純粋な Rust）は、合成の立体 21 のすべてで、閉じたメッシュと期待する体積・切り口になった。パニックはなく、ネイティブ（arm64・x86_64）と wasm32 で出力のビットが一致した。BIM の wasm のモジュールへの増分は brotli で約 244 KB。
- csgrs（MIT）は、ブーリアンの出力が閉じず（BSP の T 字の継ぎ目）、切り口が輪にならない。依存の 1 つ（`core2`）は crates.io で取り下げられていて、そのままでは使えない。
- C++ の Manifold を呼ぶ manifold-csg は、作るのに cmake と C++ の道具が要り、決定 0018 の条件に合わない。
- 自前の、断面の 2D のブーリアン（i_overlay）は、扱える形では正しいが、壁の開口のように押し出しの向きが違う形・和・積・半空間を扱えない。メッシュのブーリアンは、別に要る。

そこで、#5 で試料を測る第一の候補を manifold-rust にする。選ぶのは #5 で、試料での失敗の割合・時間・メモリ・Linux と Windows での結果の一致を測ってから決める。manifold-rust には、パニックしうる所（約 650）と、std の三角関数・`HashMap` の使用があるので、#5 では、パニックを止める包み方（wasm はパニックで止まる）と、結果が環境で変わらないかも確かめる。自前の 2D のブーリアンは、押し出しの向きが同じ開口だけの速い道として、測ってから足すかを決める。

## 影響

- `zumen-geom3d` を足す（`publish = true`、公開の一覧にも入れる）。まだどの crate からも使わない。
- 候補は、選ぶまで workspace の依存に入れない。`bench/kernels` は、`bench/transfer` と同じく、独立したワークスペースにする。
- 3D の許容差の既定値（決定 0018）は、#5 で試料から決める。合成の組は、弦の誤差 0.001 で比べた。

# 0141: 図面モデルのレイヤは、オンと凍結を別の値で持ち、表示するかは 2 つから求める

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-28 |
| 状態 | 提案 |

## 背景

[決定 0105](0105-drawing-layers-and-order.md) は、DXF・DWG の画層の凍結（LAYER の 70 の 1）と非表示（色 62 が負）を、どちらも図面モデルの「表示しない」（`LayerState::visible` が偽）にまとめた。違いは、形式固有の情報の置き場ができるまで移さないとした。

しかし AutoCAD の表示では、凍結と非表示で、ブロックの中身の見え方が違う（AutoCAD の画層の説明による。DXF Reference には書かれておらず、試料の図面の表示では確かめていない）。

- 非表示の画層に置いた INSERT では、中の要素のうち、0 の画層のもの（INSERT の画層を継ぐもの）だけが見えなくなる。ほかの表示する画層にある中の要素は見える。
- 凍結した画層に置いた INSERT では、中の要素がどの画層にあっても、記号全体が見えなくなる。

2 つをまとめたままだと、図面モデルを表示する使い手は、凍結した画層の記号の中身を描いてしまうか、非表示の画層の記号の中身を消しすぎるかの、どちらかになる。この差は表示の結果を変えるので、形式固有の拡張ではなく、モデルの値として持つのがよい（[決定 0157](0157-drawing-model-fields-and-extensions.md)）。

また、画層は、凍結していて、しかも非表示であることがある。元の形式へ書き戻すには、2 つを別々に知る必要がある。

## 選択肢

1. `LayerState` に凍結の印（`frozen`）を足す。`visible` は今までどおり、凍結か非表示なら偽にする（この決定の最初の案）。
2. オン（`on`）と凍結（`frozen`）を別の値で持ち、表示するか（`visible`）は 2 つから求める関数にする。
3. 凍結を、レイヤを指せる拡張として持つ。

1 は、凍結した画層がオンかどうかを失うので、画層の状態を書き戻せない。`visible` の意味を保つ利点は、今の使い手との互換だけである。3 は、表示の結果を変える値を、拡張を読まない使い手から隠してしまう。

## 決定

選択肢 2 を提案する。

- `LayerState` は、オン（`on`）・凍結（`frozen`）・印刷する（`printable`）・編集できる（`editable`）を別の値で持つ。`LayerState::visible` は、オンで凍結していないときに真を返す関数にする。
- 凍結したレイヤに置いた記号は、中の要素がほかのレイヤにあっても表示しない。オフのレイヤに置いた記号は、配置のレイヤに従う中の要素だけを表示しない。配置をたどって表示を決めるのは、[決定 0159](0159-drawing-walk-placements.md) の関数である。
- DXF・DWG は、62 が負でないことを `on`、70 の 1 を `frozen` にする。新しいビューポートで凍結（70 の 2）は、これから作るビューのための値なので移さない。ビューポートで凍結した画層（341）は、今までどおりビューの `hidden_layers` にする。
- 凍結を持たない JWW・SXF は、`frozen` を偽にする。

## 影響

- `LayerState::visible` を値として読んでいた Rust の使い手は、関数に替える。境界（ABI）と SDK の応答は、`LayerState` を返さないので変わらない。
- 画層の状態を書き戻すときは、オンと凍結を別々に書ける。
- 凍結と非表示の見え方の違いは、AutoCAD で作った試料で確かめる。

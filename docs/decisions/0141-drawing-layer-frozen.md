# 0141: 図面モデルのレイヤは、凍結を表示しないことと分けて持つ

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-28 |
| 状態 | 採用 |

## 背景

[決定 0105](0105-drawing-layers-and-order.md) は、DXF・DWG の画層の凍結（LAYER の 70 の 1）と非表示（色 62 が負）を、どちらも図面モデルの「表示しない」（`LayerState::visible` が偽）にまとめた。違いは、形式固有の情報の置き場ができるまで移さないとした。

しかし AutoCAD の表示では、凍結と非表示で、ブロックの中身の見え方が違う（AutoCAD の画層の説明による。DXF Reference には書かれておらず、試料の図面の表示では確かめていない）。

- 非表示の画層に置いた INSERT では、中の要素のうち、0 の画層のもの（INSERT の画層を継ぐもの）だけが見えなくなる。ほかの表示する画層にある中の要素は見える。
- 凍結した画層に置いた INSERT では、中の要素がどの画層にあっても、記号全体が見えなくなる。

2 つをまとめたままだと、図面モデルを表示する使い手は、凍結した画層の記号の中身を描いてしまうか、非表示の画層の記号の中身を消しすぎるかの、どちらかになる。この差は表示の結果を変えるので、形式固有の拡張ではなく、モデルの値として持つのがよい。拡張の付く先（`Target`）も、レイヤを指せない（#174）。

## 選択肢

1. `LayerState` に凍結の印（`frozen`）を足す。`visible` は今までどおり、凍結か非表示なら偽にする。
2. `visible` を、凍結・非表示・表示の 3 つの値の列挙に替える。
3. 凍結を、レイヤを指せる拡張として持つ。

## 決定

選択肢 1 を採る。

- 今までの `visible` の意味（このレイヤの要素を表示するか）を変えないので、`visible` だけを見る使い手はそのまま動く。
- 3 つの値の列挙（選択肢 2）は、既存の使い手をすべて書き換えさせる。凍結は表示しないことを含むので、印を足すだけで表せる。
- 拡張（選択肢 3）は、表示の結果を変える値を、拡張を読まない使い手から隠してしまう。

内容は次のとおり。

- `LayerState::frozen` を足す。真なら、`visible` も偽にする。このレイヤに置いた記号は、中の要素がほかのレイヤにあっても表示しない。
- DXF・DWG は、70 の 1 を `frozen` にする。新しいビューポートで凍結（70 の 2）は、これから作るビューのための値なので移さない。ビューポートで凍結した画層（341）は、今までどおりビューの `hidden_layers` にする。
- 凍結を持たない JWW・SXF は、`frozen` を偽にする。

## 影響

- `LayerState` を作る Rust の使い手は、`frozen` を書き足す。境界（ABI）と SDK の応答は、`LayerState` を返さないので変わらない。
- 記号の中身をレイヤで隠す描き方は、表示する側の仕事として残す。この決定は、その判断に要る値を持たせるだけである。
- DXF・DWG への書き戻し（[決定 0139](0139-drawing-apply.md)）は、まだレイヤの状態を書き戻さない。

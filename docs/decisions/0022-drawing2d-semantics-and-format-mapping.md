# 0022: 図面を空間・配置・意味のある要素で持ち、形式ごとの違いを長さの型と拡張に残す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-25 |
| 状態 | 採用 |

## 背景

[#4](https://github.com/zumen-jp/zumen/issues/4) は、SXF・JWW・DXF の意味を受けられる Drawing2D を求めている。[0008](0008-model-layers-and-codecs.md) で層、[0018](0018-geometry-layers-and-tolerances.md) で幾何、[0019](0019-coordinate-systems-and-gsi-data.md) で座標の空間は決めた。ここでは図面の要素と、その間の関係を決める。

[形式の対応表](../formats/drawing2d-mapping.md) を作ると、共通の図形だけでは残せない違いがある。

- SXF の部分図には縦横で違う縮尺がある。DXF の平面のビューポートは、用紙上の高さと表示範囲の高さから 1 つの縮尺を決める。
- SXF の文字の大きさは配置先の座標系で解釈する。点マーカー・矢印の大きさ、線種のピッチとは空間の扱いが違う。文字高を一律に用紙の mm にしてはならない。
- DXF の TEXT は 9 点の位置合わせだけでなく、基準線や 2 点への位置合わせを持つ。文字高の数値だけでは字形の大きさも決まらない。
- 寸法の意味、寸法値として保存された文字、実際に描く線と矢印は別の情報である。線と文字だけから寸法の意味を復元できるとは限らない。
- 同じ RGB 値や線種の形でも、元の符号・名前・定義の区別に意味がある。

旧版の [決定 0008](https://github.com/zumen-jp/zumen-legacy/blob/main/docs/decisions/0008-sheets-and-scales-in-the-autocad-model.md)・[決定 0019](https://github.com/zumen-jp/zumen-legacy/blob/main/docs/decisions/0019-text-heights-between-formats.md)・[決定 0024](https://github.com/zumen-jp/zumen-legacy/blob/main/docs/decisions/0024-declared-text-height.md) の知見を引き継ぐ。表示用の Scene と AutoCAD のモデルを、Drawing2D の代わりにはしない。

## 選択肢

1. **AutoCAD のモデルを広げる。** DXF との対応は容易だが、部分図・文字枠・Jw_cad の設定を例外として扱い続ける。
2. **線・曲線・文字などの共通部分にそろえる。** 表示は容易だが、寸法・ハッチング・表題欄などの編集可能な意味が落ちる。
3. **意味の和集合を共通の要素にし、同じ意味にできない情報を拡張にする。** 空間と宣言値を保持し、出力先で表せるかを変換時に判定する。共通の要素と形式固有の情報の整合を管理する必要がある。

3 を選ぶ。対応表に根拠と変換の限界を置き、項目を足すときも同じ基準で判定する。

## 決定

### 文書・空間・配置

Drawing2D は、次の意味を持つ。名前は実装時の識別子の案であり、境界のスキーマを追加する決定ではない。

| 部品 | 持つもの |
| --- | --- |
| `Drawing2D` | 実寸の空間、用紙、要素、定義、スタイル、資源参照。順序のある一覧と ID による参照 |
| `ModelSpace` | 空間の ID、文書の長さの単位、座標系と精度、実寸の要素 |
| `Sheet` | 用紙の ID、名前、幅・高さ、用紙種別と向き、用紙上の要素とビュー |
| `View` | 参照する実寸の空間、対象要素、用紙への変換、切り抜き、レイヤの表示条件 |
| `SymbolDefinition`・`SymbolInstance` | 再利用する要素の定義と、基点・変換・属性値を持つ配置 |
| `Group` | 要素のまとまり。再利用する部品や実寸の空間とは区別する |

- すべての点と長さは、用紙か実寸かを型で区別する。同じ型の実寸でも空間の ID を検査し、別の部分図を混ぜて計測しない。用紙どうしも ID を検査する。
- 用紙の原点と軸は 0019 のとおりとする。元の原点・軸・単位からの変換を lift が行い、元の情報は出所と拡張に残す。単位不明を黙って mm とみなさない。換算が必要な操作には明示的な指定を求め、仮定した場合は診断する。
- 異なる部分図や JWW のレイヤグループは、同じ座標値でも同じ実寸の場所とはみなさない。空間を分け、各ビューで用紙へ置く。縮尺が 1:1 というだけで図枠と判断しない。
- ビューは同じ実寸の空間を複数回参照できる。モデルの座標を、用紙上で重ならないように移動しない。元の形式が複数配置を許さなければ lower が定義を分け、その対応を記録する。
- 変換は空間の組を持つ f64 のアフィン変換とし、縦横の倍率・回転・反転・移動を表せる。合成で生じるせん断も失わない。単位の換算と縮尺は由来を分けて記録する。
- 切り抜きは用紙上の閉じた境界とし、元の要素を削除しない。切り抜きも描画の分割数も予算の対象にする。
- Drawing2D の対象は平面の意味である。DXF の任意の 3D 座標や透視投影を Z の削除で写さない。平面へ写せる条件がなければ L1 に残し、L2 で扱えないことを診断する。投影・切断は別の処理とする。

### 長さと表示の大きさ

`PaperLength` は用紙の mm、`ModelLength` は空間の ID と文書の単位を持つ実寸の長さとする。文字高など両方がありうる欄は、この 2 つの型を値として区別して持つ。倍率と長さを同じ数値の欄で兼用しない。

| 対象 | 持ち方 |
| --- | --- |
| 図形の座標、文字枠、ハッチングの配置間隔 | 所属する空間の点と長さ。用紙上にある場合は用紙の型 |
| 用紙上で固定する文字・矢印・点マーカー・線幅・線種のピッチ | 用紙の長さ。位置は実寸に置き、大きさだけ用紙で指定することもできる |
| DXF などの実寸に従う文字・記号・線種 | 実寸の長さと、定義・要素・配置に指定された倍率。ビューごとの評価で用紙の長さを得る |
| 画面上の点として扱う記号 | `device_dot` のような意味を持つ記号。画面の画素数を実寸の長さにしない |

形式ごとの欄を対応表で分類する。SXF の文字枠やハッチングの間隔まで、用紙上で固定する長さに変えない。非等方の変換では、方向によって長さの換算が変わる。1 つの平均縮尺で文字・線種・許容差を換算しない。

### 文字

- 元の内容、書式の区間、フォントの指定、縦書き・横書き、幅・間隔・行送り・斜体・回転を持つ。元の制御文字と、解釈できた書式を区別し、解釈できない書式を黙って削除しない。
- 宣言された高さは、値・空間・意味を組にする。意味は文字枠・大文字の高さ・em・形式の宣言値を区別する。意味を確定できない宣言値には、形式と欄を指すキーを付ける。
- SXF と JWW の文字枠と、DXF の TEXT・MTEXT の宣言値を同じ意味とみなさない。DXF Reference の code 40 だけから、漢字高・大文字高・em の比率は決められない。旧版の 0.88・0.72 は描画上の推定であり、モデルの換算定数として採用しない。
- 配置は 9 点の枠への位置合わせ、基準線への位置合わせ、2 点の間への配置を区別する。元の基点、2 点目、Fit と Aligned の違いも残す。幅と字形の拡大率は別に持つ。
- 非等方の配置で、字形までアフィン変換するか、変換した枠に直交する文字を置くかを区別する。SXF の文字枠の扱いは後者の規則として保持する。実寸に固定された枠と、用紙上で固定する注記も区別する。
- 字形の評価は `text` と L3 が、呼び出し側から渡された同じフォントで行う。フォントがない場合は未解決のまま保持し、代替表示は診断する。

lower は文字高の扱いを明示する。空間と単位を換算したうえで、既定では旧版と同じく宣言された高さの数値を優先するが、意味を変えるときは元と先の意味・値を診断し、同じ見た目を保証しない。字形や枠の大きさを優先する指定では、必要なフォントと配置から換算し、宣言値を変えたことを診断する。必要な情報がなければ失敗を返す。近似には許容差が必要で、無条件に `equivalent` としない。

### 意味のある要素

| 要素 | 保存する意味 |
| --- | --- |
| 点・線分・円弧・楕円の弧・NURBS・クロソイド・複合曲線 | 0018 の厳密な形、向き、区間、閉合、境界の表示状態 |
| 寸法 | 種類、定義点・対象の参照、測定する空間、寸法線・補助線・端部記号の配置、文字とスタイル |
| 引出線・バルーン | 経路、端部記号、注記の参照、バルーンの囲みと内容 |
| 表 | 行・列・結合範囲、セルの内容・書式・枠。値と表示文字の違い |
| 記号 | 定義の ID または名前空間付きのシンボルのキー、配置、属性値 |
| 表題欄 | 項目のキーと値、元の項目名、対応する表示要素。単なる罫線の表とは区別する |
| ハッチング | 境界と穴、塗り・線の組・パターン・既定義の区別、原点・間隔・角度・尺度、境界との参照 |

- 寸法の測定値、保存された文字、文字の上書き、表示を省く指定は別に持つ。文字が測定値と違っても勝手に書き換えない。幾何からの再計算は明示的な編集にする。
- 寸法・表・ハッチングなどの表示用の構成要素も必要なら保持するが、意味のある親要素と対応づける。L3 で親と構成要素を二重に描かない。
- 見た目が寸法・表題欄に似ていても、線と文字から読み取り時に意味を捏造しない。推定する解析は別の操作とし、根拠と診断を返す。
- 出力先の種類・版が持たない要素は、同じ意味の別表現、許容差つきの近似、見た目への分解、欠落を区別する。決定 0009 の忠実度と診断を返す。

### スタイル・レイヤ・順序

- 色・線種・線幅は、指定値または継承元、解決した値、元の符号を区別する。元の符号には系統・符号表・版・値を付け、ACI と Jw_cad のペン番号を混同しない。
- 符号表と新規作成の既定値はプロファイル（[#9](https://github.com/zumen-jp/zumen/issues/9)）に置く。ファイル内の定義は読み取った値を優先する。解決に使ったプロファイルの版を残す。
- レイヤ・部品からの継承を RGB などの現在値だけに置き換えない。未解決の継承は未解決として保持する。
- 名前と定義の ID を持ち、同じ形の線種や同じ色というだけで定義を統合しない。用紙の自由サイズも、幅・高さが定型サイズと同じという理由で種別を変えない。
- 表示・印刷・編集の可否を分け、ビューごとの表示条件を持つ。JWW の書込対象など、共通化しない編集状態は拡張にする。
- 要素とビューの描画順を明示的な一覧で持つ。下敷きを常に最背面へ移動しない。レイヤの表示順と局所の順序から確定できない場合は、入力順と未解決の指定を保持して診断する。

### 形式固有の情報と編集

共通の要素は L1 の型に依存しない。共通化できない情報は、文書・空間・定義・要素に付く拡張として持つ。

- 拡張は名前空間、対応する系統、スキーマの版、型付きの値、出所を持つ。型の契約は L1 と独立させる。単なる何でも入る JSON を共通の要素の代わりにはしない。
- 共通の意味が分かる欄は共通の要素に置く。元の符号・独自の編集設定・未対応の表現など、共通化できない残りを拡張にする。
- 未知の拡張と読めないレコードの原本は L1 に残す。L2 は base の出所参照と、扱えない種類・件数を持てる。保持できている原本と、L2 で意味を扱えることは区別する。
- 拡張を読むのは対応する系統の lower・apply とする。ほかの系統へ書くときは、書き出せない拡張を診断する。中間ファイルに拡張を自動で埋め込む約束はしない。
- 拡張ごとに、どの共通の欄への変更に依存するかを定める。位置・文字・寸法などを編集したら、影響する拡張を更新するか、失効したと記録する。古い原本から編集前の値を復活させない。
- 更新できない拡張がある場合、情報を保つ編集は失敗させてトランザクションを戻す。利用者が損失を許した操作だけ、診断を付けて拡張を外せる。

型付きの拡張を保持しても、別形式への往復が無損失になるとは限らない。出力先に記録されなかった意味は、出力ファイルを単独で読み直しても戻らない。同じ系統で原本を保つ編集は、0008 の L1 のトランザクションを使う。

### 下敷きの画像・PDF

- `Underlay` は資源参照、種類、ページ、内容の範囲、配置先の空間と変換、切り抜き、可視性・透明度・描画順を持つ。PDF のページを画像のファイル名へ置き換えない。
- 資源は、入力とともに渡された内容の ID か未解決の参照名で指す。URL・絶対パス・相対パスが図面にあっても、核が外部ファイルやネットワークを開かない。ホストが内容を渡して解決する。
- 画像の画素数、PDF のページの寸法と回転、内容の単位は、それぞれの資源から得る。画素数のない SXF・JWW では、用紙または実寸で指定された配置範囲を保持する。画素数や dpi を推測して埋めない。
- 読み取り器が画像の選択枠を作っても、同じ画像を 2 つの要素として描かない。元から図形として描く境界線は別に保持する。
- PDF 単独の入力は、ページを用紙に対応づけ、ページ全体を参照する下敷きから始められる。寸法や表の意味が元から存在したことにはしない。線と文字への抽出・解析は別の操作で出所を付ける。

### 出所・検査・安全性

- 要素の ID と出所は base の契約に従う。この決定では ID の算出規則を新設・変更しない。合成した要素から元の複数レコード、部品の配置から定義まで辿れるようにする。
- lift・lower・apply は 0009 の忠実度を要素ごとに返す。未対応、仮定、変形、欠落、表示しない情報を種類・件数・場所で知らせる。新しい診断 code は実装の PR で台帳とカタログに登録する。
- 往復の検査は、バイトの一致、意味の一致、見た目の近さを別に行う。対応表の最小の例を試験内で作る。中間ファイルから読み直す試験では、変換前のメモリや L1 を使って失われた意味を補わない。
- 定義・配置・寸法の参照・拡張に循環や欠落があれば診断する。再帰、要素の展開、文字の配置、曲線の分割は Cx の予算で数える。非有限の値、特異な変換、無効な切り抜きでパニックしない。

## 影響

- [#4](https://github.com/zumen-jp/zumen/issues/4) の成果物は、この決定と対応表でそろう。設計の完了を、各形式の実装済みという意味では使わない。
- [#3](https://github.com/zumen-jp/zumen/issues/3) は、小さな DXF の L1 と、用紙・実寸の空間・ビュー・線分・文字の最小のモデルおよび lift を試作する。型と変換の置き場所は 0008 の依存の向きを守って試作で選ぶ。
- それを超える Drawing2D の実装と試験は [#28](https://github.com/zumen-jp/zumen/issues/28) で追う。SXF・JWW のコーデック全体と L3 の描画は、この設計の PR に含めない。
- #6 の受け渡し形式と #9 のプロファイルは、このモデルの値・空間・意味の区別を保持する。図面全体の実装が済むまで、両方の試作を止める必要はない。
- 作業一覧から #4 を取り除き、#3 の開始条件を更新する。#28 は最小のコーデックと出力の一致を確かめる作業の後に置き、最初の読み書きの経路を優先する。

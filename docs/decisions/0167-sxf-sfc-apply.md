# 0167: 図面モデルの変更を SFC のフィーチャのコメントに書き戻す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-29 |
| 状態 | 採用 |

## 背景

[決定 0139](0139-drawing-apply.md) の apply は、図面モデルの変更を DXF と DWG に書き戻す。SXF は読めるが、境界の `apply` は `change.format.unsupported` で断り、`capabilities` も書けないと返す。電子納品の図面を直したい使い手と AI は、SXF を DXF に移してから直すしかなく、移すときの情報の損失を避けられない。

SFC は、フィーチャを 1 つずつ `/*SXF` から `SXF*/` までのコメントに書く。フィーチャは引数の 0〜3 にレイヤ・色・線種・線幅のコードを持ち、続きに図形の値を持つ。インスタンスの番号（`#n`）は、ほかのフィーチャから指されない。複合曲線と複合図形の定義は、その前に書いたフィーチャをまとめる。ハッチングは、複合曲線をファイルの中の順の番号で指す。

P21 は、実体が互いを番号で指す。1 つの要素が、見え方・レイヤへの割り当て・用紙の中の並びなど、複数の実体にまたがる。

## 選択肢

1. SFC のファイルモデルを図面モデルから書き直す。
2. 元のバイト列のうち、変える引数の値の範囲だけを書き直し、フィーチャのコメントを除くか足す。当てた後に読み直して確かめる。
3. P21 も同時に作る。

## 決定

選択肢 2 を採る。P21 は後に残す。

- **当てる変更。** どれも要素を ID と読んだときのハッシュで指す（[決定 0156](0156-drawing-stable-ids-and-preconditions.md)）。
  - スタイルの変更（`Restyle`）。線分・折線・円・円弧・楕円・楕円弧・スプライン・クロソイドの、レイヤ・色・線種・線幅のコード（引数の 0〜3）のうち、変わったものだけを書き直す。
  - 置き換え（`Replace`）と移動（`Transform`）。線分・折線・円・円弧の図形の値を書き直す。種類は変えない。置き換えは、変わったレイヤとスタイルも書き直す。
  - 除去（`Remove`）。線分・折線・円・円弧・楕円・楕円弧・スプライン・クロソイド・文字・点マーカー・既定義シンボル・寸法・引出線・バルーン・塗りつぶしとハッチングのフィーチャを、後の改行とともに除く。
  - 追加（`Add`）。用紙に、線分・折線・円・円弧のフィーチャを、用紙のフィーチャ（`drawing_sheet`）の前に足す。用紙のフィーチャがなければ、最後のフィーチャの後に足す。インスタンスの番号は、ファイルの最大の番号の次から付ける。印（`/*SXF`・`/*SXF3`・`/*SXF3.1`）と改行（CRLF か LF）は、ファイルに合わせる。
- **コード。** 図面モデルの値を、ファイルが定義するコードに戻す。
  - レイヤは、レイヤのフィーチャで定義したもの。
  - 色は、SXF の色のコード（`ColorSystem::Sxf`）の既定義色（1〜16）と利用者定義色。RGB だけなら、同じ RGB の利用者定義色。
  - 線種は、既定義線種（1〜15）と利用者定義線種。
  - 線幅は、既定義線幅（1〜9）と利用者定義線幅の太さに一致するもの。
  - レイヤに従う値・ブロックに従う値・線種の倍率（1 でないもの）は、SXF が持たないので書けない。
- **断るもの。** `change.edit.unsupported` で断り、何も変えない。
  - 複合曲線がまとめるフィーチャ。変えると、複合曲線とそれを指すハッチングの形が変わる。
  - 複合曲線・複合図形の定義と配置。ほかのフィーチャが順の番号か名前で指す。
  - 1 つのフィーチャから複数の要素ができたもの（作図グループを複数の所に置いたものなど）と、同じ要素を 2 度指す変更。
  - 表（レイヤ・文字フォント・利用者定義線種・寸法スタイル）の変更。
  - 部分図と作図部品の空間への追加。
- **確かめ方。** 書き直したバイト列を読み直して図面モデルに変換し、次を確かめる。合わなければ断る。
  - 変えた要素と足した要素が、求めた値（出所を除く）になる。
  - 除いた要素がなくなる。
  - ほかの要素が、ID も値も変わらない。
- **境界。**
  - `capabilities` は SXF を書けると返す。P21 の文書の `apply` は、`change.format.unsupported` で断る。
  - 新しい小版で、色の変更（`color_change`）に SXF の色のコード（`sxf`）を足す。`aci` と一緒には書かない。
  - 同じ小版で、`add` に色・線種・線幅を足す。書かなければ、今までどおりレイヤに従う。SFC はレイヤに従う色を書けないので、`add` で書く必要がある。

## 影響

- 使い手と AI は、SFC の図面を SFC のまま直せる。変えないフィーチャ・見出し・コメントは、元のバイトのまま残る。
- 数は、読み直すと同じ値になる最短の 10 進で書く。元のファイルの桁数（小数 6 桁など）には合わせない。
- 図面モデルは、使わない既定義線種を表に持たない。境界の `add` と `restyle` は、図面で使っていない既定義線種を名前で指せない。
- SFC の書き戻しを SXF の検証ツールで確かめることは、ツールを使う環境で行う必要がある。
- P21 の書き戻し、表の変更、文字・寸法などの図形の値の書き戻し、部分図と作図部品への追加は、まだない。

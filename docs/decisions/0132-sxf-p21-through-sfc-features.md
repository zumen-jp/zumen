# 0132: SXF の P21 は、実体を SFC と同じ形のフィーチャに組み直して、SFC と同じ変換に通す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-28 |
| 状態 | 採用 |

## 背景

SXF の P21 は、SFC と同じ図面を STEP AP202 の実体で書く。SFC のフィーチャ 1 つは、P21 では表記の実体（`ANNOTATION_CURVE_OCCURRENCE` など）と、それが参照する幾何・見え方・レイヤの実体の組になる。SFC の図面モデルへの変換は [決定 0121](0121-sxf-sfc-lift-to-drawing.md)〜[決定 0131](0131-sxf-attribute-mechanism.md) で決め、P21 は `sxf.p21.unsupported` を報告して空の図面を返していた（#171）。旧版（L-S）は、P21 を SFC と同じフィーチャに組み直して描き、同じ図面の SFC と P21 で確かめていた。

## 選択肢

1. P21 の実体を、SFC と同じ名前と引数の順のフィーチャのレコードに組み直し、SFC と同じ変換に通す。
2. P21 の実体から、図面モデルへ直接移す変換を別に書く。
3. P21 を SFC のバイト列に書き直してから読む。

## 決定

選択肢 1 を採る。SFC と P21 が同じ図面を表すので、意味の決定（コードの表・推定・診断）を 1 か所に置ける。2 は同じ規則を 2 度書くことになり、片方だけ直す誤りが起きる。3 は文字列の書き直しと出どころの付け直しが要り、P21 の実体の番号を保てない。

- 変換は、ファイルのバイトではなく、文字列を戻したフィーチャのレコード（名前・種類・引数）を読む。SFC はフィーチャのコメントから、P21 は実体から作る。
- P21 の表は番号の順に組み直す。利用者定義色（名前が `$$SXF_` で始まらない `COLOUR_RGB`）と利用者定義線種（`CURVE_STYLE_FONT`）と文字フォント（`EXTERNALLY_DEFINED_TEXT_FONT`）とレイヤ（`PRESENTATION_LAYER_ASSIGNMENT`）は、番号の順にコードを付ける。既定義の色と線種は名前からコードを引く。線幅は、既定義の太さならそのコード、ほかは最初に使った順に 11 から付ける。
- 名前が `$$SXF_` で始まる `COLOUR_RGB` は、続きの名前の既定義色にする。名前が `$$SXF_dummy` で始まるレイヤは、複合図形を入れる仮のレイヤとしてレイヤにしない（推定。旧版の扱いを引き継ぐ）。
- 用紙は最初の `DRAWING_SHEET_REVISION` とし、要素はその並びの順に置き、用紙のフィーチャを最後に置く。用紙の名前（`A3_horizontal` など）から種別と向きを読み、読めなければ自由サイズとして `PRESENTATION_SIZE` の `PLANAR_BOX` の大きさを使う。図面名は `DRAUGHTING_TITLE` から読む。
- 組み直したフィーチャの出どころは、表記の実体（表は、その実体）のレコードにする。診断の種類は、P21 の実体の名前にする。
- 曲線は `TRIMMED_CURVE`（線・円・楕円・クロソイド）・`POLYLINE`・`CIRCLE`・`ELLIPSE`・`BEZIER_CURVE` を移す。トリムは媒介変数（ラジアン・長さ）か点で読み、向きが合っていれば反時計回りとする。クロソイドの曲がる向きは、実体の名前に書いた 0・1 とする（推定）。
- 文字・寸法・引出線・バルーン・ハッチング・複合曲線・記号・複合図形は、組み直すまで `sxf.lift.dropped` で報告する。見え方を持たない要素（用紙の枠など）は図形にしない。
- 参照の先がない実体は `sxf.p21-reference.missing` で、用紙がない P21 は `sxf.p21-sheet.missing` で報告する。`sxf.p21.unsupported` は廃止する。

## 影響

- SFC の変換の規則を変えると、P21 にも同じく効く。P21 にしかない値は、組み直すときに SFC の値の形に直す。
- 試験は、同じ図面を SFC と P21 で書き、図面モデルが出どころを除いて一致することで確かめる。
- 残りの要素の組み直しは #193 で続ける。

# 0153: 図形のない DXF・DWG のレイアウトも、名前と大きさだけの用紙にする

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-29 |
| 状態 | 採用 |

## 背景

[決定 0145](0145-drawing-sheets-per-layout.md) は、DXF・DWG のレイアウトごとに用紙を作り、用紙に元の名前を持たせた。ただし、図形のない空のレイアウトは用紙を作らず、名前も移さなかった。ABI の図面の要約（`SheetSummary`）も、用紙の名前を渡さなかった（#174）。

手元の試料では、空のレイアウトを持つ図面が多い。

- AutoCAD の試料（`arc_2000.dwg` など）と、日本の公開の図面（`jp-yokosuka-minami-survey-plan` など）は、モデルのタブを今のレイアウトとし、図形のない Layout1・Layout2 を持つ。
- `features-r2018.dxf` は、図形のない Layout1 と、図形のある A3-PLAN を持つ。

空のレイアウトを落とすと、使い手は、図面がどんなレイアウトを持つかを知れない。用紙を選ぶ画面や、AI が図面の構成を説明するときに、元の図面とずれる。

## 選択肢

1. 空のレイアウトも、名前と大きさだけを持つ中身のない用紙にする。
2. 空のレイアウトの名前を、図面全体の形式固有の情報として持つ。
3. これまでどおり移さず、文書にだけ書く。

## 決定

選択肢 1 を採る。

- 用紙は、もともと要素とビューのない状態を表せる。拡張（選択肢 2）では、レイアウトの並びと名前を、使い手が形式ごとに読み分けることになる。
- 選択肢 3 では、レイアウトの構成が失われる。

内容は次のとおり。

- **作る条件**: ペーパー空間のブロックのレコードを指す LAYOUT があれば、図形がなくても用紙を作る。名前・大きさ・タブの順は、[決定 0145](0145-drawing-sheets-per-layout.md) と同じく LAYOUT から読む。LAYOUT がなければ、これまでどおり作らない。
- **今のレイアウト**: 今のレイアウトの図形は ENTITIES にあり、そのペーパー空間のブロックは中身を持たない。今のレイアウトに図形があるときは、ID 0 の用紙を作り、そのブロックからの空の用紙は作らない。今のレイアウトに図形がないときは、ほかのレイアウトと同じく、そのブロックから中身のない用紙を作る。
- **ID と並び**: 用紙は、決定 0145 と同じく、今のレイアウトの用紙を先に、ほかをタブの順に並べる。中身のある用紙の ID は、決定 0145 と同じく 1 からブロックの順に付ける。中身のない用紙の ID は、その後から、タブの順に付ける。そのため、用紙の並びと ID の順が合わないことがある。中身のある用紙の ID は、空の用紙を足しても変わらない。
- **ABI**: 図面の要約（`SheetSummary`）に、用紙の名前（`name`）を足す。名前がなければ持たない。スキーマに任意の欄を足すだけなので、これまでの読み手はそのまま読める。

## 影響

- モデルのタブだけに図形を描いた図面も、レイアウトの数だけ用紙を持つ。用紙の有無で、用紙を表示するかを決めていた使い手は、要素とビューがあるかも見る必要がある。
- 用紙の ID が、用紙の並びの位置と合わないことがある。使い手は、ID を位置として使わない。
- 試料では、`arc_2000.dwg`・`line_2000.dwg`・`jp-yokosuka-minami-survey-plan` の DWG と DXF が、Layout1・Layout2 の中身のない 2 枚の用紙になる。`features-r2018.dxf` は、中身のない Layout1（ID 2）と、図形のある A3-PLAN（ID 1）をタブの順に持つ。

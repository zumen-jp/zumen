# 0151: 表の書式は、表のスタイルのセルのスタイルと、表・行・列・セルの上書きで持ち、セルに効く書式は関数で解く

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-29 |
| 状態 | 提案 |

## 背景

[決定 0147](0147-drawing-table-cell-values.md) は、表のセルの書式と枠、表のスタイルの中身を移さず、表を描いたブロック（`Table.drawn`）が見た目を持つとした（#174 の「表のセルの書式」）。描いたブロックは線と文字なので、表を編集して描き直す使い手や、セルの寄せ方と背景の色で見出しを見分ける使い手は、書式を線と文字から推し量る必要がある。

DXF の ACAD_TABLE のセルは、表のスタイルからの上書きとして、文字の回転（145）・文字スタイル（7）・高さ（140）・寄せ方（170）・文字の色（64）・背景を塗るか（283）と色（63）・上下左右の枠の色・線の太さ・表示を持つ。表のスタイル（TABLESTYLE）は、表題と見出しの行を出すか（280・281）と、データ・表題・見出しの行の書式を持つ。手元の試料の `sample_AC10*` の図面の最初の表は、結合したセルで、寄せ方・文字の色・背景の色・高さと、左と上の枠（色 63、0.40 mm）を上書きする。

R2010 からの表は、名前の付いたセルのスタイル（`_TITLE`・`_HEADER`・`_DATA` と、使い手が作ったもの）を表のスタイルに持ち、行・列・セルがセルのスタイルを指して、さらに上書きする（ODS 5.4.1 の 20.4.96・20.4.101）。表全体の上書き（93 と値）もある。この決定の最初の案は、セルの上書きと、表のスタイルの行の種類ごとの書式だけを、表ごとに持った。表全体・行・列の上書きと、R2010 からの DWG の書式は、診断も出さずに読まなかった。

## 選択肢

1. 図面モデルに表のスタイルの表を足し、表のスタイルはセルのスタイルの並びを持つ。表は、表のスタイルを ID で指し、表・行・列・セルの上書きを持つ。セルに効く書式は、図面モデルの関数で解く。
2. セルの上書きと、表のスタイルの行の種類ごとの書式だけを、表ごとに持つ（この決定の最初の案）。
3. 形式固有の情報（拡張）にする。
4. 表を描いたブロックだけで見た目を持つ（今のまま）。

2 は、使い手が作ったセルのスタイルと、表全体・行・列の上書きを表せない。同じ表のスタイルの書式を表ごとに写し、セルに効く書式を使い手がそれぞれ解くことになる。拡張（選択肢 3）では、DXF の符号を知る必要がある。描いたブロック（選択肢 4）は、編集すると古くなる。書式と描いたブロックの両方を持てば、使い手は描き直すか、描いたものを使うかを選べる。

## 決定

選択肢 1 を提案する。上書きは欄ごとに `Option` で持ち、`None` を上書きしないとする。解いた値だけを持つと、どこで上書きしたかが分からなくなる。

- **書式。** `CellFormat` は、文字スタイル（[決定 0158](0158-drawing-text-styles.md) の ID）・文字の高さ・文字の回転（度）・寄せ方（横と縦）・文字の色・背景を塗るか・背景の色・枠（`Borders`）を、どれも `Option` で持つ。色は、ほかの要素と同じく、レイヤとブロックからの継承を持つ。今の `Cell.rotation` は、この欄にまとめる。
- `Borders` は、上・右・下・左と、中の横と縦の枠（`Border`）を持つ。`Border` は、色・線の太さ・表示を持つ。
- **表のスタイル。** `Drawing2D::table_styles` に `TableStyle` を並べる。`TableStyle` は、ID（`TableStyleId`。鍵は [決定 0156](0156-drawing-stable-ids-and-preconditions.md) のとおり）・元の名前・表題と見出しの行を出すか・セルのスタイルの並び・出所を持つ。セルのスタイルは、名前と書式を持つ。
- **上書き。** `Table` は、表のスタイルの ID と、表全体の上書きの書式を持つ。行と列は、大きさ・指すセルのスタイルの名前・上書きの書式を持つ（今の `row_heights`・`column_widths` をまとめる）。セルも、指すセルのスタイルの名前と上書きの書式を持つ。
- **効く書式を解く関数。** `Drawing2D::cell_format(table, row, column)` は、欄ごとに、セル・行・列・表全体の上書きの順に見て、最初の値を取る。どれも値を持たなければ、セル・行・列の順に最初に指されたセルのスタイルの値を取る。どれも指さなければ、行の種類のセルのスタイル（`_TITLE`・`_HEADER`・`_DATA`）の値を取る（この順は推定。AutoCAD で作った試料で確かめる）。どこにも値がない欄は、`None` のまま返す。
- **DXF・DWG。**
  - DXF の表のスタイルは、7 で始まる書式の組を、データ・表題・見出しの順に持つ（試料の表を描いたブロックの文字の高さと寄せ方で確かめた）。これを `_DATA`・`_TITLE`・`_HEADER` のセルのスタイルにする。
  - 行の種類は、表題と見出しの行を出すかで、先頭の行から表題・見出し・データの順に決める。
  - セルの枠は、上を 69・279・289、右を 65・275・285、下を 66・276・286、左を 68・278・288 とする（試料の描いたブロックの線の色と太さで、上・右・左を確かめた。下は推定）。表のスタイルの枠の番号は、DXF Reference の並びからの推定とする。
  - 表全体の上書き（93 と値）と、使い手が作ったセルのスタイルは、値の並びを AutoCAD で作った試料で確かめてから読む。それまでは読まずに、表ごとに `dxf.table-format.dropped` を返す。
  - DWG は、R2007 までの ACAD_TABLE のセルの上書きを DXF と同じ並びで置くので、DXF と同じく読む。R2004 までの TABLESTYLE も、DXF と同じ並びで置く（行はデータ・表題・見出しの順で、色は ACAD_TABLE と同じく R2004 の形の CMC。試料の DXF と同じ値になる）。
  - R2010 からの DWG のセルのスタイルと内容の書式（ODS 20.4.101）と TABLESTYLE は、まだ読まない。読まない書式を持つ表は、書式を空にし、表ごとに `dwg.table-format.unsupported` を返す。

## 影響

- 図面モデルの `Cell` と `Table` の欄が変わり、`Drawing2D` に表のスタイルの表が増える。作る使い手は、欄を足す必要がある。
- 今の main は、セルの回転と書式・表ごとの行の種類の書式（`Table.formats`）を持ち、文字スタイルを名前で、表のスタイルを出所で指す。R2010 からの DWG の書式は、診断せずに空にしている。この決定を採ったら、表のスタイルの表と ID に移し、診断を足す。
- R2010 からの DWG の表は、書式を読めないことを診断で知らせる。表を描いたブロックが見た目を持つので、表示は失われない。試料では、セルのスタイルの枠は DXF と同じ色と太さを持つが、寄せ方・色・高さの上書きは内容の書式の欄に見つからなかった。
- R2010 からの DWG の TABLESTYLE は、名前の後に表のセルのスタイルと、番号・種類・名前（`Table`・`_TITLE`・`_HEADER`・`_DATA`）を持つセルのスタイルの並びを持つ。試料では、表題と見出しの高さと位置合わせを DXF と同じ値で読めたが、`_DATA` の項目の並びが ODS と合わなかったので、読まない。
- 下の枠の番号（66・276・286）と表のスタイルの枠の番号も、AutoCAD で作った試料で確かめる。
- 書式の変更の書き戻しは、まだ扱わない。

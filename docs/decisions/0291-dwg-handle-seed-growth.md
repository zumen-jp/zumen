# 0291: DWG の HANDSEED の大きさ（バイト）が変わるときも、ヘッダーの変数のセクションを作り直して書き戻す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-10 |
| 状態 | 採用 |

## 背景

[決定 0052](0052-dwg-write-back-entity-addition.md) は、足した図形の後ろに HANDSEED（次に振るハンドル）を進めるとき、HANDSEED の大きさ（バイト）が変わるなら受け付けないとした。HANDSEED はヘッダーの変数のセクションの中にあり、大きさを変えると後ろの変数のビットがずれるためである。R2004 と R2010 から後も、同じ並びで書き換え、大きさの変わる値は受け付けない（[決定 0078](0078-dwg-r2004-header-variables.md)・[決定 0084](0084-dwg-r2010-header-variables.md)）。

そのため、HANDSEED が 0xFF・0xFFFF・0xFFFFFF の少し手前にある図面では、数件の図形を足すだけで書き戻せなくなる。公開サンプルの R2018 には、64,353 本の線を足すと断る。断ったときは、入力のファイルが壊れているという意味の `dwg.file.invalid` を返すので、利用者には理由が分からない（#701）。

その後、[決定 0193](0193-dwg-header-resize-and-point-style-read.md) で、PDMODE・PDSIZE のビットの数が変わるときに、ヘッダーの変数のセクションを作り直す書き方を決めた。セクションの中の後ろのビットをそのまま写し、大きさと CRC を計算し直し、R2010 からは文字列のストリームの終わりの位置をずらす。R2000 ではセクションをファイルの後ろに置き、R2004 からは展開したセクションを置き換える。

## 選択肢

1. 決定 0052 のまま断り、診断を `change` の名前空間の、理由（HANDSEED の大きさ）の分かるものにする。
2. 決定 0193 の書き方で、HANDSEED の大きさが変わるときもセクションを作り直す。
3. HANDSEED を進めず、足した図形のハンドルだけを書く。

3 は、AutoCAD などが次に振るハンドルが、足した図形と重なる。1 は、図形を足すたびに、いつか必ず書き戻せなくなる。

## 決定

選択肢 2 を採る。

- HANDSEED の大きさ（バイト）が変わる値は、HANDSEED のハンドルの後ろのビットをそのまま写したセクションを作る。大きさ（RL）・CRC・R2010 からの文字列のストリームの終わりの位置（RL）と、セクションの置き場所は、決定 0193 と同じにする。
- 同じ確定で INSUNITS・PLIMMIN・PLIMMAX・PDMODE・PDSIZE も変えるときは、作り直したセクションに続けて書く。
- 大きさが変わらない値は、これまでどおりその場で書き直す。
- 決定 0052・0078・0084 の、HANDSEED の大きさが変わる値を受け付けないことは、この決定で置き換える。INSUNITS の幅が変わる値は、決定 0193 のとおり、まだ断る。

## 影響

- `DwgTxn::set_handle_seed` と、表から図形を足す書き戻し（`DwgFile::write_back`・`apply` の `add`）は、HANDSEED の大きさが変わる値も受け付ける。
- 手で組んだ R2000 の DWG で、HANDSEED を 0xFE・0xFFFE・0xFFFFFE から足した図形の後ろに進めて書き戻した。読み直すと HANDSEED と足した図形が合い、書き直したレコードは、HANDSEED の大きさが変わらないときと同じだった。手で組んだ R2004 では、足したオブジェクトと HANDSEED が合い、元のオブジェクトのバイトは変わらなかった。手で組んだ R2004・R2010・R2013・R2018 のヘッダーの変数のセクションでも、ほかの変数が元のままで、CRC の診断が出なかった。HANDSEED を縮める値と、同じ確定で幅の変わる PDMODE と INSUNITS を書く値も確かめた。
- 公開サンプルの R2018 に 64,353 本の線を足して書き戻し、読み直すと、元の要素の ID と形が同じで、HANDSEED が 0x10000 になった。同じ要求で、ネイティブと wasm の書き戻したバイト列が一致した。
- 検証キットに、R2000・R2018 のサンプルに 65,536 本の線を足した組（`701/`）を足した。ACadSharp 3.8.0 で読むと、通知が増えず、ヘッダーだけを読んだ HANDSEED が足した最後の線のハンドルの次で、HANDSEED より後ろに書く INSUNITS・PLIMMIN・PLIMMAX・CLAYER が入力のままだった。AutoCAD で開く確認は、キットの手順に足したが、まだ流していない。R2000 で、ファイルの後ろに置いたヘッダーのセクションを AutoCAD が受け付けるかは、決定 0193 と同じく分からない。

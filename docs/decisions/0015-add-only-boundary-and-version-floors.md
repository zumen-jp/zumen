# 0015: 境界は足すだけにし、4 つの版を分け、古い環境への下限を表で約束する

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-24 |
| 状態 | 採用 |

## 背景

- 業務のマクロや社内ツールは、十年単位で使われる。一度書いた VBA やアドインが、コアを新しくしても動き続けることが求められる。
- Revit・AutoCAD・Excel は、複数のアドインを 1 つのプロセスに読み込む。違う版の DLL を持ち込んだアドインどうしが、ぶつかる。
- ホストアプリに埋め込まれた言語の版は、古いことがある（2026-10-24 に確かめた）。
  - Rhino 8 と、Revit 2025・2026 に付く Dynamo 3.x の既定の Python は 3.9。CPython 3.9 のサポートは、2025-10-31 に終わった。
  - Revit・AutoCAD は、2024 まで .NET Framework 4.8 を使う。2025・2026 は .NET 8 で出て、2026 年 8〜9 月の更新で .NET 10 に移った。2027 は .NET 10。Autodesk は、現行と過去 3 版をサポートする。
  - 業務システムには、Java 8 も残る。Oracle の延長サポートは、2030 年 12 月まで続く。
- [0012](0012-boundary-functions-and-messages.md) で、境界を、数個の関数と、版 `v` のあるメッセージにした。[0011](0011-bindings-through-ffi.md) で、ネイティブで呼ぶ言語は、同じ C ABI のライブラリを共有するとした。
- ID は契約で、ID を変える変更には、先に決定の記録が要る（AGENTS.md）。

## 選択肢

### 版の付け方

1. **1 つの版番号だけにする。** 境界を壊したかどうかが、番号から分からない。
2. **パッケージの版と、ABI・メッセージのスキーマ・ID の規則の版を分ける。**

### 境界の変え方

1. **大版を上げて壊すことを許す**（semver のふつうの使い方）。大版のたびに、利用者のマクロやアドインを直すことになる。
2. **足すだけにする。** 意味を変えたいときは新しい名前で足し、古いものを残す。

### 下限

1. **各言語の新しい版だけに対応する。** 業務の環境で使えない。
2. **古い環境に、期限なく対応する。** 保守が重くなり続ける。
3. **ホストアプリと言語のサポート期間に合わせて下限を決め、表にして公開し、上げる規則も決める。**

## 決定

版の付け方は 2、変え方は 2、下限は 3 を選ぶ。

### 4 つの版

| 版 | 形 | 上げるとき | 確かめ方 |
| --- | --- | --- | --- |
| パッケージ | semver（`1.4.2` など）。コアの crate・全言語のパッケージ・カタログで同じ番号 | リリースごと | 各パッケージの版 |
| ABI | 整数（1 から） | 関数の引数か意味を変えるとき。上げないことを目指す | `zm_abi_version`、ライブラリのファイル名 |
| メッセージのスキーマ | 大版と小版（`1.7` など） | 小版は、op・欄・列挙の値を足すたび。大版は、壊すとき（上げないことを目指す） | 要求と応答の `v`（大版）、`capabilities`（小版） |
| ID の規則 | 形式ごとの整数 | ID を変えるとき。先に決定の記録を書く | `capabilities` |

バイナリの配置（[#6](https://github.com/zumen-jp/zumen/issues/6)）とプロファイル（[#9](https://github.com/zumen-jp/zumen/issues/9)）の版は、それぞれの記録で決める。

### 境界は足すだけ

- **関数。** 足すだけにする。引数か意味を変えたいときは、新しい名前の関数を足す。
- **op と欄**
  - op と、要求・応答の欄は、足すだけにする。消さず、名前と意味を変えない。
  - 要求に足す欄は、書かなければ今までと同じ動きになるようにする。
  - 意味を変えたいときは、新しい op か欄を足し、古いものは「廃止」として残す。廃止したものも動かし続ける。
- **列挙の値。** 足すだけにする。生成した包みは、知らない値も受け取れる（[0012](0012-boundary-functions-and-messages.md)）。
- **古いものと新しいものの組み合わせ**
  - 古い包みと新しいコア: 包みは、知らない欄を無視し、知らない値を受け取るので、動き続ける。
  - 新しい包みと古いコア: 古いコアは、知らない op と欄を失敗にする（[0012](0012-boundary-functions-and-messages.md)）。包みは、`capabilities` で確かめてから新しい op を使い、古いコアでは分かる失敗にする。
- **検査。** CI で、前のリリースのスキーマと比べ、消したものや変えたものがあれば失敗にする。
- **大版。** メッセージのスキーマの大版は、足すだけでは済まないときにだけ上げ、決定の記録を書く。上げたあとも、`v` を見て前の大版を受け付け続け、いつまで受け付けるかを記録に書く。
- **1.0 より前。** パッケージの 1.0 より前は、境界も小版で壊すことがある。壊したことは、リリースノートに書く。この節の約束は、1.0 から守る。

### 同じプロセスに並べる

- ネイティブのライブラリのファイル名には、ABI の大版を入れる（`zumen_abi1.dll`・`libzumen_abi1.so`・`libzumen_abi1.dylib`）。ABI の大版が違うものは、同じプロセスに並べて読み込める。
- 同じ大版のライブラリは、新しいものほど多くを受け付ける。古いものが先に読み込まれていたら、包みが `capabilities` で確かめ、分かる失敗にする。
- .NET のアセンブリは、名前を `Zumen` のままにし、強い名前を付け、AssemblyVersion を ABI の大版（`1.0.0.0`）に固定する。
  - .NET Framework 4.8 のホストで、同じ大版のものを 1 つとして扱い、版ごとのリダイレクトを要らなくするため。
  - ABI の大版を上げるときは、アセンブリの名前にも大版を入れ、並べて読み込めるようにする。
- アドインどうしのぶつかりは、ホストの仕組みでも避ける。Revit は 2026 から、アドインごとに読み込みの文脈を分けられる。分ける仕組みがないホストでは、アドインが Zumen を自分のアセンブリに取り込む（ILRepack など）ことを、文書で勧める。

### パッケージの版

- コアの crate と全言語のパッケージは、同じリリースで、同じ版番号にする。カタログも同じにする（[0009](0009-diagnostics-and-catalog.md)）。
- 大版を上げるのは、どれかのパッケージの公開の API を壊すときにする。境界は足すだけなので、各言語のパッケージの API は壊れない。壊れうるのは、Rust の crate の API だけになる。
- Rust の crate の `rust-version` は、固定したツールチェーンの版（今は 1.99）にする。

### 下限

- 下限は、言語の実行環境・OS・ホストアプリごとに決め、表にして [docs/support.md](../support.md) に置く。この記録は規則を決め、表はこの規則で直す。最初の版は、この記録と同じ PR で置く。
- **決め方**
  - ホストアプリの中で使われる言語は、メーカーがサポートしている版のホストアプリが使う、いちばん古い実行環境まで下げる。
  - 言語そのもののサポートが切れていても、それを使うホストアプリのサポートが続く間は、表に残す。
  - ホストアプリの外だけで使う実行環境（Node.js など）は、その実行環境のサポートが続いている版に限る。
- **上げ方**
  - 下限を上げるのは、その環境を使うホストアプリと、その言語の、両方のサポートが切れてからにする。
  - 上げる 1 つ前のリリースの、リリースノートで知らせる。
  - 下限を上げるのは小版で行い、大版は上げない。古い環境の利用者は、前のリリースを使い続けられる。
- **確かめ方。** 表の下限の環境で、適合試験（[0012](0012-boundary-functions-and-messages.md)）を流す。CI で流せない環境（32 bit の Excel など）は、Windows の実機（[0004](0004-repositories.md) の案の `verify`）で確かめる。確かめていない環境は、表にそう書く。

## 影響

- 境界を変える PR ごとに、前のリリースとの差を CI が確かめる。
- 廃止した op と欄が、残り続ける。古い形を新しい形に直す処理を、境界の側に持つ。
- 下限の表を守るために、古い環境（.NET Framework 4.8、32 bit の Excel など）で試験を流し続ける。
- [#17](https://github.com/zumen-jp/zumen/issues/17) は、この記録と、表の最初の版で完了する。

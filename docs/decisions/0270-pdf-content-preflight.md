# 0270: PDF の内容とフォームも展開量を先に数え、連結と走査用の写しを確保前に数える

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-06 |
| 状態 | 採用 |

## 背景

[0266](0266-pdf-flate-preflight.md) は ObjStm の単独 Flate を、出力を保持せずに確かめる。ページの内容とフォームは、走査自身が全体を展開してから予算に数えていた。ページの内容の配列をつなぐ量と、終わりのマーカーを足す写しも、確保前には数えていなかった。

## 選択肢

1. 上流に予算の API が入るまで、展開後の確認を続ける。処理は増えないが、既存の依存で止められる確保も止められない。
2. ページの内容を自前で展開・連結して解釈へ渡す。重複を減らせるが、上流のページのキャッシュと、壊れた内容の読み方も保つ必要がある。
3. 0266 の確認をページの内容とフォームへ広げ、上流が再び展開・連結する分と、走査用の写しを先に数える。読む回数は増えるが、描画を決める処理とキャッシュを替えずに済む。

## 決定

選択肢 3 を採る。有効なフィルターが単独 Flate の内容とフォームは、0266 と同じリーダーと固定長のバッファーで、全出力を確保する前に展開量・手間・中断を確かめる。先頭 Crypt、予測子、壊れた入力の扱いも同じにする。

内容の配列は、参照と直接のストリームを上流と同じ順に読む。読めない項目の診断を保ち、読めた項目の連結と区切りの空白を、ページのキャッシュを作る前に数える。上流が各項目を再び展開する分も数える。予測子で出力が短くなる場合と、展開後に失敗する場合も、予測子を当てる前に数えた量を使う。

終わりのマーカーを足す Vec と Rc への写しは、それぞれ確保前にバイト数と写す手間を数える。フォームのキャッシュは引き続きページ内で使い、解釈が呼ぶたびに展開する分も保つ。単独 Flate では、この分にも予測子の前の量を使い、失敗した展開も呼ぶたびに数える。具体的な単位は [PDF の上限](../formats/pdf.md#上限) に記す。

依存・API・ID の規則は変えない。予算はネイティブと wasm で同じように数え、成功時の内容は引き続き hayro に読ませる。

## 影響

- 対象の展開と写しは、小さい予算で全体の確保前に止まる。新たに数える量のため、以前より早く止まる場合がある。
- 成功する入力は確認の展開が増える。上流に予算の API が入ったら、この重複を見直す。
- LZW・複数フィルター、フォント・画像・ICC・関数、Pdf::new 内部、解釈途中の中断は対象外で、#521 に残る。#518 の開始条件は変えない。

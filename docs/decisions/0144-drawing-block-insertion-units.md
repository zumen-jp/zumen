# 0144: 記号の定義の単位は、ブロックのレコードの挿す単位にする

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-28 |
| 状態 | 提案 |

## 背景

[決定 0112](0112-drawing-symbol-definitions.md) は、DXF・DWG のブロックを記号の定義にし、中身の空間の単位を文書の単位（`$INSUNITS`）とした。ブロックのレコードの単位（70）は「まだ移さない」とした（#174）。

AutoCAD の系統では、ブロックごとに挿す単位を持つ。手元の試料（`sample_AC1015` から `sample_AC1032` の DWG と DXF）は、図面が inch で、mm と m のブロックを持つ。ブロックの中身の座標は、そのブロックの単位で書かれている。文書の単位のままでは、使い手は中身の長さを誤った単位で読む。

単位は、版によって置く所が違う。

- R2007 からは、DXF の BLOCK_RECORD の 70 と、DWG の BLOCK_HEADER の絵の後の BS にある。
- R2004 までは、BLOCK_RECORD の拡張データの ACAD の `DesignCenter Data` の組（1002 の `{`、版の 1070、単位の 1070、1002 の `}`）にある。

DWG の読み手は、R2010 からの欄を読んでいなかった。

## 選択肢

1. 記号の定義の空間の単位を、ブロックのレコードの挿す単位にする。配置の尺度は、元の値のまま持つ。
2. 単位を文書の単位のままにし、挿す単位による倍率を配置の尺度に掛ける。
3. 単位を移さず、拡張として持つ。

## 決定

選択肢 1 を採る。

- 試料には、mm のブロック `my_block` を inch の図面へ尺度 1/25.4 で挿した配置があった。配置の尺度は、単位の換算をすでに含む（推定。試料で確かめた）。選択肢 2 では、換算を 2 度掛けてしまう。
- 選択肢 3 では、定義の単位が誤ったまま残る。

内容は次のとおり。

- ブロックのレコードの挿す単位が 0（単位なし）か、なければ、定義の単位は文書の単位とする。
- 挿す単位の番号は、`$INSUNITS` と同じ対応で `Unit` にする。長さの単位でない番号（ミルなど、図面モデルの `Unit` にない単位）は `Unit::Unknown` とする。
- 配置は、定義の点を尺度・回転で写す。単位の違いで、さらに換算はしない。
- DWG の読み手は、R2010 から BLOCK_HEADER の絵を読み飛ばし、挿す単位・分解できるか・尺度を揃えるかを、DXF と同じく BLOCK_RECORD の 70・280・281 に置く。
- DWG に足すブロックのレコードは、70・280・281 を持てば、その値を書く（[決定 0095](0095-dwg-r2010-write-back-more-record-addition.md) の既定の値を置き換える）。R2004 までは欄がないので、0 でない挿す単位は受け付けない。

## 影響

- 記号の定義の空間の単位が、文書の単位と違うことがある。単位の違いを確かめて換算する使い手は、配置の尺度がすでに換算を含むことに注意する。
- 既存のブロックのレコードの単位の変更は、DWG へは書き戻さない（ブロックのレコードの変更をまだ受け付けないため）。
- 試料の DWG と DXF の組で、どの版でも同じ単位になることを確かめた。

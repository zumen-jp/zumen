# 0244: IFC のその場の編集は、L1 で触れたインスタンスだけを書き直し、building_apply の op で当てる

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-02 |
| 状態 | 採用 |

## 背景

読んだ IFC に、プロパティや名前を足し・変えて書き戻す（[#393](https://github.com/zumen-jp/zumen/issues/393)、旧版の zumen-jp/zumen-legacy#134）。[決定 0207](0207-building-model-components.md) は、変更を要素の ID と読んだときのハッシュを前提条件に持つ一覧にし、IFC の L1 の触れたインスタンスにだけ書き戻すと決めた。共有されたプロパティのセットを 1 つの要素について変えるときは、写しを作って付け替える。図面の apply（[決定 0139](0139-drawing-apply.md)・[決定 0156](0156-drawing-stable-ids-and-preconditions.md)）と同じ考え方である。

決めることは、次のとおり。

- 境界の op の形。
- L1 での当て方と、書き直す範囲。
- 最初に扱う変更の種類。
- 足すインスタンスの番号と GlobalId。

## 選択肢

境界の op の選択肢は、次の 2 つ。

1. **図面の `apply` に、建物の変更の種類を足す。** op は 1 つで済むが、`edit` の種類が図面と建物で混ざり、どの種類がどの文書に使えるかを型で表せない。
2. **建物の文書の op `building_apply` を足す。** 要求と結果の形は `apply` に揃え、変更の種類は建物のものだけにする。

L1 での当て方の選択肢は、次の 2 つ。

1. **変更ごとに書き直し、読み直す。** 作りは小さいが、変更の数だけファイルを読み直す。
2. **触れたインスタンスの写しに変更を重ね、最後に 1 度だけ書く。** 逆向きの参照も重ねた変更に合わせて直し、後の変更が前の変更を見られるようにする。

## 決定

op は 2、L1 での当て方は 2 を選ぶ。

### op

- `building_apply` は、`doc`・`hash`（文書のハッシュ。書けば、今と同じときだけ当てる）・`edits` を受ける。要素は、`building_elements` が返す ID とハッシュで指す。
- 結果は `apply` と同じく、変更ごとの書き戻した後の ID とハッシュと、文書のハッシュを返し、書き戻したファイルを blobs の file で返す。ifcZIP で開いたものは、元の項目の名前で包み直す。
- どれか 1 つでも当てられなければ、何も変えない。値の形が合わなければ `call.value.invalid`、要素がなければ `change.element.missing`、ハッシュが違えば `change.element.stale`・`change.document.stale`、当てられない種類なら `change.edit.unsupported` を返す。
- 当てたら、書き戻したものを読み直して、文書を替える。読み直したときの診断は、開いたときに返したので捨てる。IFC4.3 の線形の土木の領域モデルも作り直す。

### 変更の種類

- **`property`。** 要素のプロパティのセット（名前で指す）の、`IfcPropertySingleValue` の値を変える。セットかプロパティがなければ足す。値は `building_value` の形で、`type_name` と、`real`・`integer`・`text`・`boolean`・`logical` のどれかを受ける。
  - 要素だけが使うセットとプロパティは、その場で書き直す。
  - ほかの要素や関係と共有するセットは写しを作り、関係からこの要素を外して、新しい `IfcRelDefinesByProperties` で写しに付ける。関係がこの要素だけを結ぶなら、関係の参照を写しに替える。共有するプロパティも写しを作る。
  - 型の要素（`IfcTypeObject`）は、関係でなく型の HasPropertySets のセットを変える。
- **`attribute`。** 要素（`IfcRoot`）の Name か Description を変えるか、なくす。
- 数量・分類・材料・形状表現の変更と、要素を足す・除く変更は、要るときに種類を足す。

### L1

- 変更は、触れたインスタンスの写し（名前と引数。参照と並びは中を見られる形、ほかは書いたバイト列）に重ねる。名前を挙げないインスタンスは、元のバイト列のまま写す。
- 足すインスタンスには、今の最大の番号の次から振り、データの節の終わりの前に書く。
- 足す GlobalId は、入力の文書のハッシュと足した数から BLAKE3 で決める。同じ入力と同じ変更なら、同じファイルになる。
- 新しいセットと関係の OwnerHistory は、変える要素のものを使う。IFC2X3 は OwnerHistory を要るものとするので、要素の値を写す。

## 影響

- 変えた要素の ID は変わらない。足したインスタンスは要素でないので、ほかの要素の ID もずれない。
- 書いた IFC を、IFC を読むソフトで開いて確かめることは、検証の環境を待つ（別の issue、ラベル「待ち: 検証環境」）。
- 建物モデルからの新しい書き出しは、[#394](https://github.com/zumen-jp/zumen/issues/394)・[#395](https://github.com/zumen-jp/zumen/issues/395) で決めて作る。

# 0050: DWG（R2000）への書き戻しは、XRECORD のデータを元の並びのまま書き直し、文字列のコード・ページは元の値のものを使う

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

[決定 0049](0049-dwg-write-back-layout.md) までで、OBJECTS のうち XRECORD のほかの読む種類の欄を R2000 の DWG に書き戻せるようにした。

XRECORD のデータは、グループ・コードとコードの型で決まる値の並びで、前にデータのバイト数を持つ。文字列の値は、長さと値のほかに、コード・ページのバイトを持つ。読む側はコード・ページを読み飛ばし、値をバイト列のまま置く。値を足すと、新しい文字列のコード・ページを決めなければならない。

## 選択肢

1. 値の番号の並びが元と同じときだけ受け付け、元のデータを読みながら値を書き直す。文字列のコード・ページは、元の値のものを写す。
2. 値の追加も受け付け、新しい文字列のコード・ページは見出しの `$DWGCODEPAGE` を使う。

2 は、見出しのコード・ページの値と、文字列のコード・ページのバイトの対応を、図面で確かめられていない。

## 決定

選択肢 1 を採る。

- 値の番号の並びが元と違う変更（値の追加と削除）は受け付けない。
- データの値を元の並びのまま書き直し、データのバイト数を数え直す。文字列のコード・ページのバイトは、元の値のものを写す。
- 型に収まらない値（RC・RS・RL に収まらない整数、255 バイトを超えるバイナリ、RS に収まらない長さの文字列）は受け付けない。
- 複製の扱い（280）は書き直し、ハンドル（5）と所有者（330）の変更は受け付けない。

## 影響

- 手で組んだ R2000 の XRECORD で、文字列・点・実数・整数・真偽・バイナリを変えて書き戻し、読み直した値と、データが組んだものと同じになることを確かめた。試料の図面の XRECORD の実数と文字列も変えて書き戻す。
- XRECORD への値の追加は、まだ書き戻せない。

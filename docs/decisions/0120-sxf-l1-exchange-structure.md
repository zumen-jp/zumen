# 0120: SXF の L1 は、ISO 10303-21 の文と SFC のフィーチャのコメントを、元のバイト範囲のままレコードにする

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-28 |
| 状態 | 採用 |

## 背景

#171 で SXF（SFC・P21）のコーデックを作る。[決定 0008](0008-model-layers-and-codecs.md) は、L1 を形式の構造をそのまま持つファイルモデルとし、変えずに書くと元のバイト列と一致することを求める。SFC と P21 は、どちらも ISO 10303-21 の交換構造（始まりの行・見出しの節・データの節・終わりの行）に入る。P21 は図形を STEP のインスタンス（`#n=名前(引数);`）で書き、SFC はフィーチャをデータの節のコメント（`/*SXF` から `SXF*/` まで）に書く。同じ始まりの行は IFC などほかの STEP のファイルも使う。文字列は、P21 は ISO 10303-21 のエスケープで、SFC は Shift_JIS の生のバイトで書く。

## 選択肢

1. SFC と P21 で別の L1 を作る。
2. 交換構造を共通の L1 にし、文と SFC のフィーチャのコメントを、同じ形のレコードにする。
3. L1 で値を解釈して（文字列を戻し、数を実数にして）持つ。

## 決定

選択肢 2 を採る。値は解釈せず、元のバイト列の範囲で持つ。SFC と P21 の差は、データの節の書き方と文字列の囲み方だけで、区切り方と往復の規則は同じにできる。値を解釈して持つと、変えずに書いたときに元のバイト列へ戻せない書き方（桁・空白・エスケープ）が出る。

- **レコード。** `;` で終わる文（`HEADER;` のような語、`FILE_NAME(…);` のような見出しの文、インスタンスと複合のインスタンス）と、データの節の SFC のフィーチャのコメント 1 つずつ。レコードの間の空白とコメントは、レコードにせず、書くときにそのまま写す。
- **レコードの種類。** 語と見出しの文とフィーチャはその名前、複合のインスタンスは最初の部分の名前とする。フィーチャのコメントは、印の版（`/*SXF`・`/*SXF3`・`/*SXF3.1`）を持つ。
- **値。** `$`・`*`・参照・列挙・文字列・数・16 進・型を付けた値・並び、SFC の囲まない値に分け、範囲で持つ。SFC の文字列は `'…'` と `\'…\'` を分ける。エスケープと文字コードは図面モデルへの変換で戻す。
- **判定。** 始まりの行 `ISO-10303-21;` で判定し、読んだ後に `FILE_SCHEMA` の最初のスキーマの名前を確かめる。`ASSOCIATIVE_DRAUGHTING` でなければ `sxf.schema.unsupported` を返して読まない。`FILE_SCHEMA` がなければ読む。SFC か P21 かは、`FILE_DESCRIPTION` の `feature_mode` か、フィーチャのコメントがあることで決める。`AP202` と書いた P21 では、`/*SXF` もただのコメントとする。
- **壊れた所。** 始まり・データの節・終わりのどれかがなければ `sxf.file.invalid` で読まない。形の読めない文は次の `;` まで、フィーチャのコメントは閉じまでを飛ばし、`sxf.record.invalid` に範囲を付けて、続きを読む。飛ばしたバイトもレコードの間として写すので、往復は変わらない。
- **予算。** 入力のバイト数、レコード 1 つごとに `records`、値 1 つごとに `work`、並びの入れ子 1 つごとに `depth` を数える。止めたら、読んでいた文かコメントの範囲を場所にする（[決定 0119](0119-budget-stop-place.md)）。

## 影響

- 編集（トランザクション）はまだ持たない。書くのは、読んだレコードとその間をそのまま並べることだけ。
- 境界（`open`・`drawing`）にはまだつながない。図面モデルへの変換と一緒につなぐ。
- 圧縮した SFZ・P2Z は、まだ扱わない。

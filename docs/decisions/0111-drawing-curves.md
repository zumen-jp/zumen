# 0111: 図面モデルの曲線を元の定義のまま持ち、線分に近似しない

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

[決定 0022](0022-drawing2d-semantics-and-format-mapping.md) は、L2 が厳密な曲線の定義を保ち、近似するときは許容差を付けることを決めた。対応表の E8 は、円弧とスプラインを元の定義のまま持つことを試す。これまでの図面モデルは、線分と、ハッチングの境界の線分・円弧・楕円弧の辺だけを持った。円・円弧・楕円・スプライン・LWPOLYLINE は移さず、SPLINE の辺を持つ HATCH は `dxf.hatch-spline.unsupported` で落とした（[決定 0108](0108-drawing-symbols-hatches-arrowheads.md)）。

## 選択肢

1. 円を `Shape::Circle`、円弧・楕円弧・スプラインをハッチングの辺と同じ `Edge` の `Shape::Curve`、膨らみのある折れ線を `Shape::Polyline` として、元の値のまま持つ。
2. 曲線を、決めた許容差で線分の折れ線に近似して持つ。
3. スプラインを、節点と制御点の形に正規化して持つ。

## 決定

選択肢 1 を採る。近似すると、元の定義に戻せず、許容差の選び方が表示側の事情に縛られる。当てはめる点だけのスプラインから制御点を作る方法は形式とソフトで違い、正規化すると元の値が分からなくなる。

- `Edge` に `Spline` を足す。`Spline` は、次数・節点・制御点・重み（空なら有理でない）・当てはめる点・始まりと終わりの接線・閉じているか・周期的かを持つ。元の形式が持つものだけを入れ、片方から他方を作らない。
- `Shape::Circle` は中心と半径、`Shape::Curve` は `Edge` を持つ。円弧と楕円弧の角度は度で持つ。DXF の ELLIPSE の始まりと終わりのパラメーター（ラジアン）は、度に直す。
- `Shape::Polyline` は、頂点と膨らみ・閉じているか・一様な幅・頂点ごとの始まりと終わりの幅を持つ。頂点ごとの幅は、どれかの頂点が幅を持つときだけ、頂点の数だけ持つ。
- 定義の数が合わないもの（節点の数が制御点の数・次数・1 の和でない、制御点が次数より多くない、重みが制御点と同じ数でないか正でない、数えた数の欄と合わない）は移さず、`dxf.lift.invalid` を返す。周期的なスプラインの節点の数は確かめない。
- HATCH の SPLINE の辺を移す。DXF の辺の当てはめる点（97）は、2010（AC1024）以降の版だけにあるとして読む。DWG の読み手は当てはめる点を置かないので、DWG から作った表では読まない。`dxf.hatch-spline.unsupported` は使わなくなったので、廃止にする。
- 境界（`drawing` の op）の要約は、曲線と折れ線を数えず、範囲にも入れない。範囲の求め方は、要素の一覧の op（#66）と合わせて決める。

## 影響

- LWPOLYLINE の線種の生成の印（70 の 128）・厚さ（39）と、SPLINE の許容差（42〜44）は、まだ移さない。
- 古い POLYLINE と VERTEX、SOLID・POINT・RAY・XLINE は、まだ移さない。クロソイドは、形式に専用の要素がないので扱わない。
- DWG の SPLINE は閉じている・周期的の印を表に置かないので、DWG から作った図面モデルでは、どちらも偽になる。
- 2010 より前の版で当てはめる点を持つ HATCH の SPLINE の辺があれば、境界を作った図形の数として読み違える。この版の区別は DXF Reference の記述による推定で、試料の図面で確かめていない。

# 0273: PDF の描画資源も展開前に数え、実際の長さと再展開の見積もりを分ける

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-06 |
| 状態 | 採用 |

## 背景

[0266](0266-pdf-flate-preflight.md)・[0270](0270-pdf-content-preflight.md) は、ObjStm・ページの内容・フォームの単独 Flate を確保前に数える。関数・シェーディング・Indexed の表・ソフトマスクのグループは、走査自身が全体を展開してから数えていた。展開後の長さを再利用時の予算にも使うので、予測子で短くなる分と、展開後に失敗した分を数えられなかった。

## 選択肢

1. 依存に展開途中の予算を渡せるようになるまで待つ。重複する展開を増やさずに済むが、既存の方法で減らせる確保も残る。
2. 0266 の確認を共通の資源の展開へ広げ、展開量の見積もりを実際の長さとしても使う。変更は小さいが、標本・メッシュ・手続きの数え方や受け入れ条件まで、圧縮や予測子によって変わる。
3. 同じ確認を広げ、実際の長さと再展開の手間・バイト数を別々に保つ。値は増えるが、形を確かめる契約を保って、再利用と失敗も数えられる。

## 決定

選択肢 3 を採る。走査が共通の処理で展開する資源のうち、有効な単独 Flate は、0266 と同じ固定長のバッファーで手間・展開量・中断を確かめる。予算内なら、引き続き hayro で展開する。

結果には、予測子の後の実際の長さと、事前確認で数えた手間・バイト数を保つ。前者は標本・メッシュ・手続きの検査に、後者は解釈が資源を再び作るときの予算に使う。失敗した試みと寛容な展開の見積もりも戻さず、予測子の後で失敗して長さが 0 になっても保つ。再利用時には、事前確認と同じ手間を解釈側の展開の上限の見積もりとして数える。

それ自身の間接オブジェクトはページの中で確認結果を再利用し、直接のストリームは使うたびに確かめる。対象の資源と単位は [PDF の上限](../formats/pdf.md#上限) に記す。依存・API・ID の規則は変更せず、[0007](0007-single-rust-implementation.md)・[0010](0010-budget-by-work.md) の同じ実装と決まった作業量を使う。

## 影響

- 対象の単独 Flate は、走査の全出力の確保前に小さい予算で止まる。新たに数える手間とバイト数のため、以前より早く止まる場合がある。
- 成功する入力でも展開量を数える処理が増える。依存に予算を渡す口が入れば、重複を見直す。
- フォント・ICC・画像、LZW・複数フィルター、Pdf::new 内部、解析と解釈途中の中断は #521 に残す。#518 の開始条件は変えない。上流への送信判断は #580 と分ける。

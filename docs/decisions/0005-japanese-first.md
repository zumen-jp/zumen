# 0005: 日本語を正にする

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-24 |
| 状態 | 採用 |

## 背景

- 主な利用者は、日本の設計・施工・維持管理と、そのためのソフトウェアの開発者。
- 旧版も、日本の実務と日本語を標準にすると決めた（[旧版の決定 0033](https://github.com/zumen-jp/zumen-legacy/blob/main/docs/decisions/0033-japanese-first.md)）。
- 一方、識別子は各言語のパッケージや AI の道具から読まれるので、変えにくく、英語のほうが扱いやすい。

## 選択肢

1. **英語を正にし、日本語の訳を付ける。** 海外の寄稿者には読みやすいが、主な利用者に遠い。
2. **日本語を正にし、識別子は英語にする。**
3. **日本語と英語を同じ重さで保つ。** 2 つを常にそろえる手間がかかる。

## 決定

2 を選ぶ。

- **日本語で書くもの**
  - README・文書・決定の記録
  - issue・PR・コミットの説明
  - CLI のヘルプ、MCP の道具の説明
  - 診断の文言（カタログ）
- **英語のままにするもの**
  - 識別子：関数名・型名・パッケージ名・コマンド・オプション・JSON のキー・診断の code
  - Conventional Commits の種別とスコープ
- **原文を保つもの**
  - 第三者のライセンスの本文、仕様の引用
  - 図面に記録された名前・文字・単位
- **核は人向けの文を返さない。** 文言は日本語と英語のカタログに置き、どの言語の結合からも同じ文を引けるようにする。
- **英語の補足は、要るときに足す。** たとえば各レジストリの頁の冒頭の数行。

## 影響

- 英語しか読まない寄稿者には入りにくい。識別子とスキーマが英語なので、コードは読める。
- 診断の文言のカタログは、日本語を先に書き、英語を足す。

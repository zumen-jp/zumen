# 0069: DWG（R2000）への書き戻しで変えた INSUNITS・PLIMMIN・PLIMMAX は、見出しの変数の区切りの長さを変えずにその場で書き直す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

R2000 の DWG を読む側は、見出しの変数の区切りから `$ACADVER` と、INSUNITS（70 の整数）と、用紙空間の PLIMMIN・PLIMMAX（10・20 の実数）を表の見出しの変数に置く。書き戻しは、オブジェクトの変更と追加と削除を扱えるようになったが（[決定 0029](0029-dwg-table-write-back.md)〜[0068](0068-dwg-write-back-block-record-addition.md)）、見出しの変数の変更はみな拒んでいた。

試料の R2000 の図面では、用紙空間の PLIMMIN と PLIMMAX は、固定の 64 ビットの RD が 4 つ並んだものだった。INSUNITS は BS で、値によって 2 ビット（0 と 256）・10 ビット（1〜255）・18 ビットと長さが変わり、その後のビットがずれる。区切りの終わりには、データを覆う CRC がある。

UCS のレコードの追加も、次の候補だった。ただ、試料の図面に UCS のレコードがなく、共通のハンドルの後のハンドルの流れを確かめられない。

## 選択肢

1. 変えた変数のビットを、区切りの中でその場で書き直す。データの長さが変わる変更は拒み、CRC を計算し直す。
2. 見出しの変数の区切りを、一から符号化する。
3. 見出しの変数の変更は、これまでどおり拒む。

## 決定

選択肢 1 を採る。UCS のレコードの追加は、試料が得られるまで後回しにする。

- 書き戻せるのは、このファイルの見出しの変数の区切りから読んだ INSUNITS・PLIMMIN・PLIMMAX の変更だけとする。ほかの変数の変更と、読めなかった変数を足すことは拒む。
- INSUNITS は、70 の整数 1 つだけを持ち、BS で書いたときのビットの数が元の値と同じものだけを受け付ける。
- PLIMMIN と PLIMMAX は、どちらも有限の 10 と 20 の実数だけを持たなければならない。片方だけを変えても、両方を書き直す。
- 書き直したデータのバイトの長さが元と違えば拒む。CRC は、HANDSEED の書き直しと同じく計算し直す。

## 影響

- 手組みのファイルで、INSUNITS を 4 から 6 に、用紙空間の範囲を (-5.5, 0)〜(420, 297) に変えて書き戻した。読み直した表は、変えた表と同じになった。BS の幅が変わる値・整数でない値・有限でない範囲・`$ACADVER` の変更は拒んだ。
- 試料の R2000 の図面でも、INSUNITS と用紙空間の範囲を変えて書き戻し、読み直した表が変えた表と同じになった。CRC の診断も出なかった。
- 書き戻した図面を、AutoCAD で開いて確かめてはいない。
- INSUNITS の BS の幅が変わる値（0 と 1〜255 の間の変更など）は、まだ書き戻せない。
- UCS のレコードの追加は、まだ書き戻せない。

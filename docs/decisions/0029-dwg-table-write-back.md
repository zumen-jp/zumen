# 0029: 共有の表の変更は、DWG（R2000）の型ごとのフィールドを符号化し直して書き戻す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-26 |
| 状態 | 採用 |

## 背景

R2000 の DWG は、オブジェクトのデータを置き換えて書ける（[決定 0028](0028-dwg-object-data-edit.md)）。DXF は、共有の表の変更を元の表と比べて書き戻す（[決定 0024](0024-acad-table-write-back.md)）。DWG にも同じ書き戻しが要る。

- DWG のオブジェクトはビット列で、フィールドの多くは値によって長さが変わる。読む側は、表に置かないフィールド（共通のフィールドのフラグ・リアクター・ハンドルの並びなど）も持つ。
- オブジェクトを丸ごと符号化し直すには、表に置かないフィールドも表から作れなければならない。

## 選択肢

1. オブジェクトを、表の値だけから丸ごと符号化し直す。
2. 型ごとのフィールドだけを表の値から符号化し直し、その前と、ハンドルのストリームから後ろのビットは元のまま写す。
3. 書き戻しはまだ作らず、データの置き換えだけを公開する。

1 は、表に置かないフィールドを作れないので、今は使えない。3 は、表の変更を DWG に戻せない。

## 決定

選択肢 2 を採る。

- `DwgFile::write_back` は、表と今のファイルから作り直した表を、元のオブジェクトごとに比べ、値の並びが違うオブジェクトだけを `DwgTxn` で置き換える。1 つでも書き戻せない変更があれば、何も反映しない。
- 今は、LINE・CIRCLE・ARC の型ごとのフィールド（点・半径・角度・厚さ・押し出しの向き）だけを符号化する。ハンドルのストリームの位置（RL）は、書き直したフィールドの長さに合わせて直す。
- ほかの値の変更、ほかの種類のオブジェクトの変更、オブジェクトの追加・削除・並べ替え、ヘッダーの変数の変更は、`dwg.change.unsupported` を返す。R2000 でないバージョンを変えれば `dwg.edit.unsupported` を返す。
- ハンドルのストリームの後ろの埋めのビットも写すので、書き直したデータは元より 1 バイト長くなることがある。

## 影響

- `zumen-acad` に `DwgFile::write_back` と、診断の符号 `dwg.change.unsupported` が加わる。
- サンプルの R2000 の図面のすべての LINE・CIRCLE・ARC の点を動かして書き戻し、読み直した表が変えた表と同じになることを確かめた。
- 符号化できる種類とフィールドは、後で広げる。変えた DWG を AutoCAD が読むかは、まだ確かめていない。

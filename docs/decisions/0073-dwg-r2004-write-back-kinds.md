# 0073: R2004 の DWG への書き戻しは、R2000 と同じ形の種類を広げ、後ろに増えた欄は元のビットを写す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

R2004 の DWG へは、共通の欄と、LINE などの単純な種類の型ごとの欄だけを書き戻す（[決定 0072](0072-dwg-r2004-write-back.md)）。R2000 は、ほかに ATTRIB・ATTDEF・MTEXT・LWPOLYLINE・SPLINE・HATCH・POLYLINE・VERTEX・DIMENSION・INSERT・MINSERT・TOLERANCE・LEADER・MLINE・VIEWPORT・SHAPE の型ごとの欄を書き戻す（決定 0030〜0042）。

試料の R2004 の図面で、元の値を R2000 の形で符号化した型ごとの欄と、元の型ごとの欄の長さを比べた。

- ほとんどの種類は、長さが同じだった。ATTDEF の 1 つは、文字列の符号化の違いで、符号化したほうが長かった。
- 属性を持つ INSERT は、元の欄が 10 ビット長く、R2000 の欄の後に持つオブジェクトの数（BL）があった。
- MTEXT は、元の欄が 2 ビット長く、R2000 の欄の後に背景の印（BL）があった。
- HATCH は、R2004 で初めにグラデーションの欄がある。POLYLINE も、R2004 で持つオブジェクトの数が後ろにある。MINSERT は、持つオブジェクトの数が列と行の欄の前に入る。

## 選択肢

1. 型ごとの欄が R2000 と同じ種類はそのまま符号化し、後ろに欄が増えた種類は、元の値の符号化が元のビットの初めと同じときだけ、増えた欄を元のまま写す。
2. 種類ごとに、R2004 で増えた欄を読み、値として扱って書く。

## 決定

選択肢 1 を採る。増えた欄（持つオブジェクトの数・背景）は表の値に置かないので、元のまま写せば足りる。

- R2004 で書き戻す種類に、ATTRIB・ATTDEF・LWPOLYLINE・SPLINE・DIMENSION・TOLERANCE・LEADER・MLINE・SHAPE・VERTEX・INSERT・MTEXT・VIEWPORT を足す。
- INSERT と MTEXT は、新しい値を R2000 の形で符号化し、元の値を R2000 の形で符号化した欄の後ろから、ハンドルの流れの前までの元のビットを続ける。元の値の符号化が元のビットの初めと同じでなければ、書き戻さない。
- MINSERT・HATCH・POLYLINE は、R2004 ではまだ書き戻さず、`dwg.change.unsupported` を返す。

## 影響

- 試料の R2004 の 2 つの図面で、足した種類の図形の点と線種の尺度を変えて書き戻し、読み直した表が変えた表と同じになった。HATCH と表のレコードの変更は `dwg.change.unsupported` を返した。
- 試料の POLYLINE は多面と網だけで、型ごとの欄の変更を確かめられないので、R2004 では書き戻さない。MINSERT は試料にない。
- 書いた図面を AutoCAD で開いて確かめてはいない。

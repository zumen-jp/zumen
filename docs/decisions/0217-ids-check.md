# 0217: IDS は照合の入力としてそのまま読み、建物モデルの成分で確かめ、確かめられない facet を指摘と分けて返す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-31 |
| 状態 | 採用 |

## 背景

[決定 0207](0207-building-model-components.md) は、IDS を建物モデルで照合すると決めた（#411）。照合を作るにあたり、次の 4 つが決まっていなかった。

- IDS をプロファイル（決定 0193）に写すか、そのまま読むか。
- 建物モデルの成分にない値（IFC の属性の全体、分類、単一の値でないプロパティ）に掛かる facet を、どう扱うか。
- IDS の値の制約の XSD の式（`xs:pattern`）を、どう確かめるか。
- IDS の XSD とそこから生成したコードを、リポジトリに入れるか。

## 選択肢

IDS の扱いの選択肢は 2 つある。

1. IDS をプロファイルの規則に写し、プロファイルの照合で確かめる。
2. IDS を `zumen-ids` で読み、IDS の照合を `zumen-ids` に置く。

選択肢 1 では、facet の出現の決まり（必須・任意・禁止）、仕様の出現の決まり、型からの値の受け継ぎを、プロファイルの規則に足すことになる。図面のプロファイルの規則と意味が重ならない。

成分にない値に掛かる facet の選択肢は 3 つある。

1. 値がないものとして、満たさないとする。
2. 確かめられないとし、指摘と分けて返す。
3. 照合の前に断る。

選択肢 1 では、建物モデルが値を落としたことと、ファイルに値がないことの区別がつかず、正しいファイルに誤った指摘が出る。

## 決定

- IDS 1.0 を `zumen-ids` で読む。`zumen-ids` は `zumen-building`・`zumen-xml` に依り、IFC と STEP を知らない（層の向きの検査に足す）。
- 読み方。
  - 名前空間 `http://standards.buildingsmart.org/IDS` の要素だけを読む。構造が合わなければ `ids.file.invalid` を出して `Error::Invalid` を返す。
  - 知らない facet は `ids.facet.unsupported`、読まない制約と読めない式は `ids.restriction.unsupported` を出し、その facet か制約を確かめられないものとして残す。
  - XSD もそこから生成したコードも入れない。構造は仕様の文書で確かめ、読み手に手で書く。
- 式（`xs:pattern`）は、XSD の正規表現を文字列の全体に当てる NFA で確かめる。`\p{..}` の文字の種類は読まない。`\d`・`\w`・`\i`・`\c` の、ASCII でない文字への当てはまりは確かめられないとする。
- 照合は、要素ごとに facet を満たす・満たさない・確かめられないの 3 つで決める。
  - 必須の facet は、値がなければ満たさない。任意の facet は、値がなければ満たす。禁止の facet は、必須の結果の逆にする。
  - 仕様が必須なら、適用の条件に合う要素が 1 つ以上要る（`ids.applicability.missing`）。禁止なら、合う要素があれば指摘する（`ids.applicability.exists`）。
  - 要件を満たさない要素は `ids.requirement.invalid` で指摘する。重さは、必須と禁止の要件で error、任意の要件で warning にする。
  - 確かめられない facet は、`ids.applicability.unsupported`・`ids.requirement.unsupported` の info で、指摘と分けて返す。仕様ごとの結果は、指摘があれば不合格、なく確かめられないものがあれば不明にする。
- 値の比べ方は IDS 1.0 に従う。
  - 文字は大文字と小文字を区別する。列挙どうし・式どうしはどれかに合えばよく、制約の種類の間はすべてに合う。
  - 実数の等しさは、IDS の値 v に対し `|v|·1e-6 + 1e-6` の幅の内側で比べる。範囲の制約は幅なしで比べる。
  - 量は SI の単位に直して比べる。単位の倍率が決まらないもの（摂氏の温度など）は確かめられないとする。
  - プロパティと材料と分類は、型の要素の値を受け継ぎ、要素の値が同じ名前の型の値に代わる。
  - 定義された種類は、型の種類を先に、なければ要素の種類で決める。`USERDEFINED` なら、利用者の付けた種類で比べる。
  - `partOf` は、集約・入れ子・空間への包含・グループ・開口と充填を、上へ繰り返したどる。関係を指定すれば、どの段もその関係だけをたどる。
- 建物モデルにない値は、呼び手が `Lookup` で示す。
  - `Lookup::missing` は、建物モデルの作り手が持たない値（分類、材料の分類と組の名前、単一の値でないプロパティ）を示す。それに掛かる facet で、モデルに値が見つからなければ、確かめられないとする。
  - `Lookup::attributes` は、要素のすべての明示の属性の名前と値を返す。`zumen-ifc` は L1 のインスタンスの属性を、渡した EXPRESS（決定 0216）の属性の名前で返す。
  - 渡さなければ、成分にある属性（`GlobalId`・`Name`・`Description`・`Tag`・`LongName`・`PredefinedType`）だけを確かめ、ほかの属性は確かめられないとする。
- IFC2X3 のモデルで、総称のクラス（`IfcFlow*`・`IfcDistribution*` など）が entity の facet に合わなければ、確かめられないとする。IFC4 のクラスへの対応の表は持たない。

## 理由

- IDS の意味は、要素ごとの適用と要件の組で、図面の規則と重ならない。そのまま読めば、IDS の結果を IDS の言葉で返せる。
- 確かめられないことを指摘と分ければ、建物モデルの作り手が値を足したときに、照合を変えずに確かめられるものが増える。
- IDS の XSD は CC BY-ND 4.0 で、改変したものを配れない。手で書いた読み手なら、XSD をリポジトリに入れずに済む。

## 守ること

- 確かめられない facet を、満たす・満たさないのどちらかに寄せない。
- 単一の値でないプロパティは、建物モデルに足すまで確かめられない（決定 0215）。足したら、`zumen-ifc` の `Lookup::missing` から外す。

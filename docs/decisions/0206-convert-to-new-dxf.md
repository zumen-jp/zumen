# 0206: 別の形式への変換（convert）は、ひな形の DXF に apply で表の項目と要素を足して書く

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-31 |
| 状態 | 採用 |

## 背景

- [0139](0139-drawing-apply.md) は、L2 から L1 への向きを `lower`（別の形式への変換と新規作成）と `apply`（その場の編集）に分けた。`apply` はできたが、`lower` はなかった（#359）。
- `apply` は、DXF に画層・線種・文字スタイル・寸法スタイルを足し、空間・用紙・記号の定義に要素を足せる（[0155](0155-drawing-apply-additions.md)・[0162](0162-drawing-layer-changes.md)）。足せない値は、変更を当てずに失敗する。
- DXF の書き手は、読んだ表を書き戻す形で、空の表から文書を作る口はない。

## 選択肢

1. 表の既定の項目と記号の定義の空の部品だけを持つ、ひな形の DXF を作り、`apply` で表の項目と要素を足す。
2. 図面モデルから DXF の表を直に組み立てる、新しい書き手を作る。
   - 足すときの値の検査（画層の色・線種・文字の高さの意味など）を、`apply` と別に持つことになる。

## 決定

- 選択肢 1 を採る。op を `convert` にし、`doc`・`format`・`to` を受ける。スキーマの小版を 41 にする。
- 書けるのは DXF（R2004）だけにする。ほかの形式は `convert.format.unsupported` で失敗する。
- 手順:
  1. ひな形を作る。見出しの `$INSUNITS` は最初の実寸の空間の単位（空間がなければ mm）、`$PLIMMIN`・`$PLIMMAX` は最初の用紙の大きさにする。用紙に要素があれば、用紙を作るための点をペーパー空間に置き、要素を足した後に除く。
  2. 線種・文字スタイル・寸法スタイルを足し、次に画層を足す。状態とスタイルを持たない画層は、表示・印刷・編集でき、白（ACI 7）と Continuous で足す。
  3. 記号の定義の要素、実寸の空間の要素、最初の用紙の要素の順に足す。形は、形の値（geometry）を通して書いた先の空間と用紙の座標に置き直す。
  4. 足せない変更は、変更の一覧を半分に分けて探し、その要素だけを落とす。
- 形式の違いは次のように寄せる。
  - 実寸の空間が複数ある図面（JWW のレイヤグループ）は、1 つのモデル空間にまとめる。
  - 用紙は最初の 1 枚だけを書く。ビューは書かない。横と縦の尺度の違うビューは、用紙の要素に焼き込んで書く（[決定 0238](0238-bake-anisotropic-views.md)）。
  - 記号の属性は、記号から離した文字として書き、`convert.attribute.drawn` を返す。属性の定義は、一定で見えるものを文字にし、ほかは落とす。
  - ACI でない番号の色は、RGB があれば RGB で、なければ白で書く。
  - 書けない要素の種類（寸法・引出線・表・下絵・ハッチングなど、`apply` が足せないもの）は、種類ごとに `convert.element.unsupported` を返す。
  - 外部参照の記号の定義は書かない。
- 変換した文書は、開いた文書として `drawing`・`entities`・`apply` で続けて使える。

## 影響

- SXF・JWW・DWG への変換は、それぞれの書き手で新規作成を足すまでできない。
- `apply` で足せる要素が増えると、変換で落ちる要素が減る。

# 0024: AutoCAD の系統の表の変更は、元の表と比べて違うレコードだけを符号化に書き戻す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-26 |
| 状態 | 採用 |

## 背景

[0023](0023-acad-shared-object-table.md) は、DXF と DWG が共有するオブジェクトの表 `AcadDb` を置いた。表への変更と、変更を符号化に戻す方法は決めていない。[#64](https://github.com/zumen-jp/zumen/issues/64) は、共有の表の変更を DXF に書き戻すことを求めている。

- DXF のファイルモデル `DxfFile` は、レコードとタグの変更を `DxfTxn` で受け、確定するまで何も反映しない。変えていないレコードは元のバイトのまま書く（[0008](0008-model-layers-and-codecs.md)）。
- 表のオブジェクトは、元のレコードを `Origin` で指す。
- 表は、型付きの値（実数・整数・ハンドルなど）を持ち、元の値の行の書き方（桁、空白、指数の表記）を持たない。

## 選択肢

1. 表は自由に変えられるものとし、書き戻すときに、今のファイルから作り直した表と元のレコードごとに比べる。値の並びが違うレコードだけを、1 つのトランザクションで直す。
2. 表の変更を、操作（値の置き換え、タグの追加など）の記録として持ち、書き戻すときに操作を順に当てる。
3. 書き戻すときに、表からファイル全体を書き直す。

2 は、表を変える経路のすべてで記録を保たなければならず、DWG の表にも同じ仕組みが要る。3 は、変えていないレコードの元のバイトを失い、0008 の往復の約束に反する。

## 決定

選択肢 1 を採る。

- 表のオブジェクトは、`AcadDb::object_mut` で変えられる。見出しの変数は `set_variable` で置く。
- `DxfFile::write_back` は、今のファイルから表を作り直し、表のオブジェクトと元のレコード（`Origin::Dxf`）ごとに値の並びを比べる。違うレコードだけを `DxfTxn` で直し、最後にまとめて確定する。1 つでも書き戻せない変更があれば、何も反映しない。
- 値の並びの前と後ろで同じ値は、元のタグのまま残す。間の値は、グループ・コードの並びが同じなら値の行だけを差し替え、違えばタグを除いて足し直す。こうすると、触れていない値の書き方は元のバイトに残る。
- 差し替える値は、表を作るときの読み方の逆で書く（実数は読み直すと同じ値に戻る最短の表記、ハンドルとバイナリは大文字の 16 進）。
- 見出しの変数も、名前ごとに同じように比べる。表にあってファイルにない変数は、HEADER の最後に足す。
- 種類か元の場所が、このファイルの同じ種類のレコードと合わないオブジェクト（DWG から読んだものや、種類を変えたもの）は書き戻さず、`dxf.object.unsupported` を返す。
- オブジェクトの追加と削除、変数の削除はまだ扱わない。表に足したオブジェクトの元の場所の決め方とともに、後で決める（オブジェクトの追加と削除は [0025](0025-acad-object-add-remove-write-back.md) で決めた）。DWG への書き戻しも、DWG を書くときに決める。

## 影響

- `zumen-acad` に `DxfFile::write_back`、`AcadDb::object_mut`・`AcadDb::variables` と、診断の符号 `dxf.object.unsupported` が加わる。
- `AcadDb::get` は、足した後にハンドルを変えたオブジェクトも引けるように、索引が外れたら順に探す。
- 書き戻した後のファイルから作った表が、書き戻した表と同じになることを試験で確かめた。

# 0085: R2010 から後の DWG への書き戻しは、文字列を持たない単純な図形の共通のフィールドと型ごとのフィールドから始める

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-27 |
| 状態 | 採用 |

## 背景

R2010 から後の DWG は、オブジェクトのデータをハンドルのストリームの大きさ（MC）から受け渡して置き換えられる（[決定 0083](0083-dwg-r2010-object-edit.md)）。図形の共通のフィールドは、R2004 のフィールドの後、非表示の前に、材質（BB）・影（RC）・表示のスタイルの 3 つのフラグを持つ。主のデータの後に文字列のストリームとハンドルのストリームが続くので、主のデータのビットの数が変わると、ハンドルのストリームの始まり（MC）を直す必要がある。文字列のストリームを持つ図形（TEXT など）は、主のデータと文字列のストリームの両方を組み直す必要がある。

## 選択肢

1. 文字列を持たない単純な図形（LINE・CIRCLE・ARC・POINT・ELLIPSE・RAY・XLINE・SOLID・TRACE・3DFACE）の共通のフィールドと型ごとのフィールドから書き戻し、主のデータの終わりから後ろはそのまま写して MC を直す。
2. 文字列を持つ図形・表のレコード・図形でないオブジェクトまで一度に書き戻す。
3. R2010 から後は、まだ書き戻さない。

## 決定

選択肢 1 を採る。文字列のストリームを組み直す形は、種類ごとにサンプルで確かめてから広げる。

- 共通のフィールドは、R2004 と同じく色・線種の尺度・非表示を書き換え、R2010 で足された材質・影・表示のスタイルのフィールドはそのまま写す。
- 型ごとのフィールドは、変わらなければ元のビットを写す。変わったときは、元の値から作ったフィールドの長さが元のフィールドの長さと同じことを確かめてから、新しい値で作り直す。
- 主のデータの後ろ（文字列のストリームのフラグとハンドルのストリーム）はそのまま写し、MC を新しいバイトの数に合わせて書き直す。
- ほかの種類の図形・表のレコード・図形でないオブジェクトの変更と、図形の削除・追加は、`dwg.change.unsupported` で受け付けない。

## 影響

- サンプルの R2010・R2013・R2018 の図面で、単純な図形の座標・線種の尺度・色を変えて書き、読み直した表が変えた表と同じになった。TEXT と LAYER の変更は受け付けなかった。
- 書いた図面を AutoCAD で開いて確かめてはいない。

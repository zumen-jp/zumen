# 0004: 中心のリポジトリを 1 つにし、配布・権利・非公開の都合があるものだけを分ける

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-10-24 |
| 状態 | 採用 |

## 背景

- コア、各言語への境界、全言語の結合は、新しいメッセージを足すたびに一緒に変わる。
- 配る仕組みの側に制約がある。
  - SwiftPM・Packagist・Homebrew は、リポジトリの直下にある定義を読む。
  - Go のモジュールはソースで配る。
- 公開できないものがある。実図面の目録や、Windows の実機での検証がそれにあたる。
- 公開リポジトリに self-hosted runner をつなぐと、fork からの PR が手元の機械でコードを動かせてしまう。

## 選択肢

1. **すべてを 1 つのリポジトリに置く。** 配る仕組みの制約と、非公開のものを扱えない。
2. **層や言語ごとにリポジトリを分ける。** 新しいメッセージを全言語へ広げる変更が、いくつもの PR に分かれる。
3. **中心を 1 つにし、配る仕組み・権利・非公開の都合があるものだけを分ける。**

## 決定

3 を選ぶ。

| リポジトリ | 公開 | 中身 |
| --- | --- | --- |
| `zumen` | 公開 | コア、境界、全言語の結合と適合試験、表示エンジン、試用画面、文書と決定の記録、プロファイル（当面） |
| `.github` | 公開 | org の紹介、既定の寄稿の案内・行動規範・セキュリティの方針、issue のフォーム |
| `zumen-swift`・`zumen-go`・`zumen-php`・`homebrew-tap` | 公開・鏡 | `Package.swift`、wasm を埋め込んだ Go のモジュール、`composer.json`、CLI の Formula |
| `examples` | 公開 | 公開されたパッケージだけで書いた連携例（Revit・AutoCAD・Rhino・Excel・Jw_cad・SketchUp・Unity・Web・Python） |
| `zumen-legacy` | 公開 | 旧版 |
| `stbridge` など | 非公開 | 許諾を待つ形式のプラグイン |
| `corpus` | 非公開 | 実図面の目録と定期実行。図面そのものは Git に入れない |
| `verify` | 非公開 | Windows の実機での検証と self-hosted runner |

- **鏡のリポジトリ。** 書くのはリリースの CI（GitHub App）だけにする。issue は閉じ、README で中心のリポジトリへ案内する。
- **共有のリポジトリに定義を出す配布先。** conda-forge・vcpkg・winget がこれにあたる。
- **プロファイル。** 当面は `zumen/profiles/` に置く。次のどちらかになったら、別のリポジトリに分ける。
  - スキーマが 1.0 になったとき
  - 実務者からの寄稿が始まったとき
- **作る時期。** リポジトリは要るときに作る。最初は `zumen` だけ。

## 影響

- 新しいメッセージや形式を足す変更は、中心のリポジトリの 1 つの PR に収まる。
- 鏡のリポジトリは、リリースの CI に書き込みの権限が要る。
- 実機での検証と実図面の定期実行は、非公開のリポジトリから、公開リポジトリのコミットを取り出して走らせる。

## 背景

[決定 0247](0247-drawing-model-binary.md) は、図面の形式のプラグインの wasm のモジュールを、プラグインの形式だけを持つ小さなものにした。プラグインのモジュールは、読んだ図面を op `lift` で図面モデルのバイナリ（`ZMDR` で始まる、blob の種類 `drawing`）にし、図面のモジュールの `open` がそれを読むだけの文書にする。いまは、この受け渡し（プラグインのモジュールで open・lift し、blob を図面のモジュールのセッションに push して open する）を、利用者が書く（#483）。

JavaScript の包みの `detect` は、`schema/boundary.toml` の判定の規則（`DETECTION`）で入力を判定し、`Modules.forInput` は形式を持つモジュールを読み込む。決定 0247 は、`ZMDR` の判定の規則を足さなかった。`open` は図面モデルのバイナリの形式として元の文書の形式を返すので、判定の規則の表の `format` に何を書くかが決まっていなかった。

## 選択肢

### 図面モデルのバイナリの判定

1. 判定の規則の表に、形式 `drawing`（blob の種類の名前）・モジュール `drawing`・規則 `ZMDR` の行を足す。図面のモジュールの形式に `drawing` を足す。
2. 判定の規則の表には足さず、包みの中で `ZMDR` を特別に扱う。
3. バイナリの区画 0 の元の形式を包みで読み、その形式を返す。

### 受け渡しの口

1. `Modules` に `open` を足す。入力の形式を判定し、その形式を持つモジュールの新しいセッションで開く。図面の形式のプラグインなら、プラグインのモジュールで open と lift をし、図面のモジュールのセッションで開く。
2. `forInput` が、プラグインの入力に図面のモジュールを返し、受け渡しを隠したセッションを返す。
3. 利用者が書く手順のまま、例を README に書く。

## 決定

どちらも選択肢 1 を採る。

- 判定の規則の表は、コアと包みで同じ一覧を使う（[決定 0221](0221-wasm-modules.md)）。特別な扱いを包みに書くと、ほかの包みが同じ扱いを書き直すことになる。判定の形式は「どの形式の読み取りで開くか」を表すもので、図面モデルのバイナリは、元の形式によらず同じ読み取りで開く。区画 0 を包みで読むと、包みがバイナリの配置を知ることになる。
  - 判定の行は、E57 の後、DXF の前に置く。始まりの 4 バイトは、コアのどの形式とも重ならない。
  - `open` は今までどおり、元の文書の形式を返す。判定の形式 `drawing` と `open` の形式は違う。
- `Modules.open(name, bytes, request, inputs)` を足す。
  - `request` は open の要求の残りの欄（`doc`・`format` など）。`format` を書けば、判定せずに、その形式を持つモジュールで開く（xyz・extdm）。`inputs` は、open の前にセッションに足すほかの入力（`saf` で名指す属性ファイルなど）。
  - 判定したモジュールがプラグインで、op `lift` を持ち、図面のモジュールを読み込めるなら、プラグインのモジュールのセッションで open と lift をし、blob を図面のモジュールの新しいセッションで open する。プラグインのセッションは閉じる。図面のモジュールを読み込めなければ、プラグインのモジュールのセッションで開く。
  - 返すのは、開いたモジュール（`zumen`）・セッション（`session`）・open の応答（`response`）。セッションは呼び出し側が閉じる。どのモジュールの形式でもなければ `undefined`。open が失敗すれば、セッションを閉じて例外を投げ直す。
- ほかの言語の包みには、同じ口を足さない。C ABI の包み（Python・.NET・Java・Dart・Swift・C/C++）はネイティブのライブラリで、すべての形式とプラグインを同じライブラリで読む。Go の包みは、すべてを入れた wasm のモジュールを埋め込む（[決定 0226](0226-go-wrapper.md)）。分けたモジュールを使う包みを足すときに、同じ口を足す。

## 影響

- 判定の規則の表に行が 1 つ増えた（`DETECTION`、JavaScript の `constants.js`）。図面のモジュールの形式の一覧に `drawing` が増えた。capabilities の形式の一覧（形式の台帳の形式）は変わらない。
- `bindings/js/test/modules.mjs` は、図面モデルのバイナリを判定の検査から外さず、判定の形式 `drawing` を確かめる。組が足す入力を `Modules.open` でも開き、コアの open と同じ形式で開くことを確かめる。
- プラグインのひな形の試験（`templates/plugin/tests/wasm.mjs`）は、`Modules.open` で、プラグインの入力を図面のモジュールで開けることを確かめる。

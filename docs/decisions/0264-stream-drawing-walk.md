# 0264: 図面の配置を逐次処理し、継承と切り抜きは配置ごとに共有し、図面モデルのバイナリでは重複する空間 ID を拒否する

| 日付 | 2026-11-06 |

## 背景

[0262](0262-boundary-fuzz-targets.md) は、配置をたどるときに返す要素を `elements` でも数える。既定の上限は 1 億なので、699 バイトの格子の入力でも、走査の結果を全件集めると数十 GB になる（#563）。scene と check が使うのは、現在の要素と、作る結果だけである。

用紙の描く順・ビューの切り抜き・レイヤの検索・深い配置の継承・シーンの切り抜きの照合にも、入力や配置の数を掛け合わせた処理が残る（#566・#568・#569）。また、空間 ID が重なるバイナリでは、ID のキャッシュを別の空間と共有し、返さない要素ができる（#567）。記号の定義の空間 ID は、実寸の空間ともほかの定義とも重ならない契約である。

## 選択肢

1. 既定の `elements` を小さくする。正当な大図面の上限も下がり、要素数とレイヤ数などの積の処理は残る。
2. 全件を保持したまま、配置の道筋と切り抜きを共有する。1 要素の費用は減るが、描かない要素も総数に比例して保持する。
3. 借りた要素を逐次渡し、利用側は結果だけを保存する。入力に対応する索引と、配置ごとの継承・切り抜きを共有する。

空間 ID の重複については、別の ID を振り直す方法、重複を許して走査だけを直す方法、読み取りで拒否する方法がある。振り直すと安定 ID の契約に影響し、重複を許すと、起点を空間 ID で指定する API の意味が曖昧になる。

## 決定

選択肢 3 と、重複する空間 ID の読み取りでの拒否を採る。

- `WalkVisitor` と、道筋・ID・切り抜きを借りる `VisitRef`、`Drawing2D::walk_to` を足す。既存の `walk`・`walk_parts`・`Visit` は残す。全件を所有して返す関数は、複製する結果の見積もりを `decoded_bytes` で数えてから保存する。
- scene は、既定の許容差と描いた部品の有無を求める走査と、描く走査に分ける。診断は最初の走査だけで記録する。どちらの走査も同じ予算を使う。描く単位・道筋と、新しい切り抜きの組の見積もりも `decoded_bytes` で数える。
- check は、要素用の規則を走査前に一度選び、要素を受けるたびにその規則と照合する。用紙・レイヤ名・ファイル名の規則は、要素の走査が終わってから照合する。指摘だけを規則ごとに保存し、1 件の追加前に見積もりを `decoded_bytes` で数える。予算で止まったら、1 要素からの指摘や 1 用紙のビューの残りも処理せずに戻る。最後に規則の順で結び、応答の順を保つ。
- レイヤと実寸の空間は、ID をキーとする索引を走査ごとに作る。重複するレイヤ ID は、以前と同じく先の定義を使う。配置の継承値と、祖先による非表示は配置に入るときに求め、子に渡す。従来の `color_placed` などの関数も残す。
- 用紙の `order` は、範囲の外の添字も含めて項目ごとに `work` を数える。ビューの切り抜きと非表示レイヤはビューごとに一度作り、頂点とレイヤの数を `work` で数える。空間の `order` の範囲の外の添字は、0262 と同じく走査時に空間ごとに除き、数える。バイナリでの拒否は増やさない。
- 道筋は配置に入るときに複製し、切り抜きは新しい境界がある配置だけで複製する。要素ごとには複製しない。複製する道筋の段数と切り抜きの頂点数を `work` に数える。深さは従来の `depth` で制限する。
- シーンの切り抜きの組は、反転の有無と座標のビット列をキーとする `BTreeMap` で引く。正負のゼロは同じキー、NaN を含む組は再利用しない。以前の浮動小数の等値と同じ規則で、先に出た組の番号を使う。キーの頂点数と索引の高さから、比較の作業を `work` に数える。
- 図面モデルのバイナリは、実寸の空間と記号の定義を通して空間 ID の一意性を確かめる。重複すれば `drawing.binary.invalid`、理由 `duplicate-space-id` で拒否する。読むモデルの値と正常な ID の決め方は変えない。
- 既定の予算は変更しない。予算での停止位置は、追加で数える作業と保存量の分だけ変わりうる。時刻と実行環境のポインター幅で予算を変えない。

## 影響

0159 の走査の利用方法と部品、0262 の予算とメモリ、0247 のバイナリの検査を、この記録の範囲で改める。境界 API とバイナリの型の配置は変えない。

走査は、返した要素の総数を保持しない。必要な記憶は入力の索引と、現在の配置の道筋・境界で決まる。scene と check は、実際に作る結果を保持し、その量も予算で制限する。深い配置の道筋と追加の境界は各段が持つため、深さに対しては二乗になりうるが、要素ごとの継承の再走査をなくし、深さの上限は保つ。

正常な図面の描く順・ID・継承・切り抜き・指摘の順は保つ。既存の適合テストのハッシュで確かめる。巨大な格子の停止、空のビューの反復、深い配置、多数のレイヤと切り抜き、重複する空間 ID は合成の入力で確かめる。実測の条件と結果は PR に記録する。

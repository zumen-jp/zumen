# 0214: 赤入れと BIM の指摘は、指摘と図形と場所を持つ 1 つのレビューの文書にし、場所を ID とハッシュで新しい版へ移し、BCF とは指摘と 3D の場所を対応させる

## 背景

#1 は、図面の赤入れと BIM の指摘を同じモデルで扱うとした。旧版の決定 0021（提案）は、図面のバイト列の SHA-256 とビューを指す JSON に、赤入れ・変更雲・注記・指摘・写真の位置を用紙の mm で持ち、版の比較で新しい版へ移すとした。指摘の状態は `open`・`resolved`・`closed` の 3 つにし、担当・期限・返信はアプリケーションに任せた。3D の場所と BCF は扱っていない。

新しい版では、図面の要素は形式の鍵で作る ID と要素のハッシュを持ち（[決定 0156](0156-drawing-stable-ids-and-preconditions.md)）、建物モデルの要素は GlobalId の ID とハッシュを持つ（[決定 0207](0207-building-model-components.md)）。プロファイルの照合の指摘は、規則の id と診断の組で返す（[決定 0179](0179-profile-check-details.md)）。決定 0013 は、wasm の図面のモジュールに「レビュー」を入れた（[決定 0013](0013-boundary-in-four-forms.md)）。

BCF（BIM Collaboration Format）は、topic（指摘）・comment・viewpoint（カメラ・選んだ要素の GlobalId・表示・切断面・スナップショット）を ZIP の中の XML で持つ。2D の図面の上の場所は持たない。

## 選択肢

1. 旧版の 0021 の文書に、3D の場所を足す。指摘は図形の種類の 1 つ（`finding`）のまま。
2. 指摘（BCF の topic にあたる）と、図形（赤入れ・変更雲・注記・写真）を分け、指摘が 2D と 3D の場所をいくつも持てるようにする。
3. BCF をそのまま保存の形にし、2D の場所を BCF の拡張に置く。

選択肢 1 は、1 つの指摘が 2D の図面と 3D の両方の場所を持てず、コメントと担当を持たないので BCF の topic と対応しない。

選択肢 3 は、BCF の XSD が知らない要素を許さないので、2D の場所を置く所がない。ほかの道具が読めない BCF になる。

## 決定

選択肢 2 を採る。

### 文書

- JSON の文書にし、`format` は `"zumen-review"`、`version` は 1 にする。読み手は、ほかの形式と大きい版を断る。知らないキーは、読んで書き直しても保つ（旧版の 0021 と同じ）。
- 文書は、対象（`targets`）・指摘（`topics`）・図形（`markups`）を持つ。
- **対象。** 指摘と図形が指す文書。対象の ID（文書の中で一意）、形式、文書のハッシュ（0156 の `v2:` の元のバイト列のハッシュ）、名前を持つ。図面と建物モデルの、どちらの文書も対象にできる。

### 指摘

- ID（UUID。BCF の topic の Guid にそのまま使う）、題、説明、状態、種類、優先度、ラベル、担当、期限、作者と作った日時、直した人と日時、関係する指摘の ID、コメント、場所、出所を持つ。日時は RFC 3339 にする。
- **状態。** `open`（まだ扱っていない）・`resolved`（直したが確かめていない）・`closed`（確かめたか取り下げた）の 3 つ（旧版の 0021 と同じ）。アプリケーションの細かい状態は、別のキー（`status_label`）に文字列で持つ。
- **コメント。** ID・作者・日時・本文・場所の ID を持つ。
- **場所。** 指摘が持つ場所の列。場所は ID を持ち、2D か 3D のどちらかにする。
  - **2D の場所。** 対象の ID、用紙かビューの ID（0156）、ピンの位置と範囲（用紙の mm、Y が上）、要素の参照の列。
  - **3D の場所。** 対象の ID、カメラ（透視か平行、位置・向き・上の向き、視野角か見える幅。プロジェクトの空間の座標）、選んだ要素の参照の列、隠した要素と表示の既定、色を変えた要素と色、切断面の列（点と法線）。断面の箱（[決定 0213](0213-scene3d-sections-and-op.md)）は、6 つの切断面で表す。
  - **要素の参照。** 要素の ID と、場所を作ったときの要素のハッシュ（0156・0207）の組にする。
- **出所。** 照合から作った指摘は、規則の id と診断（0179 の指摘）を持つ。IDS の照合（#411）の結果も、同じ形で指摘にできる。照合の結果から指摘を作るのは、利用者が選んだ結果だけにし、照合のたびに自動で作らない。

### 図形

- 旧版の 0021 の `redline`・`cloud`・`text`・`photo` を引き継ぐ。どれも対象の ID と用紙かビューの ID と、用紙の mm の点を持つ。指摘のピンは、図形でなく指摘の 2D の場所にする。
- 図形は、指摘の ID を持てる（その指摘についての赤入れ）。持たなければ、指摘によらない赤入れにする。
- 図形の形（変更雲の円弧・矢じり・注記の枠）の作り方は、1 つの規則にし、コアが 2D のシーンの描くもの（[決定 0172](0172-scene-sections-and-op.md)）で返す。

### 新しい版へ移す

- 移す op は、レビューの文書と、対象の新しい版の文書を受け、新しい版を指す文書を返す。
- 要素の参照は、新しい版で ID を引き、ID がなければ `removed`、ハッシュが違えば `changed`、同じなら `unchanged` にする。場所の状態は、参照のどれかが `removed` か `changed` なら `changed`、すべてが `removed` なら `removed`、ほかは `unchanged` にする。移した後の参照のハッシュは、新しい版のハッシュにする。
- 移した場所と図形に、元の文書のハッシュと状態を書く（旧版の 0021 の `carried`）。
- 2D の点の位置は動かさない。図面の版の比較で位置のずれを求める op ができたら、ずれで動かすことを足す。変わった要素に合わせて点を動かすことは、推測になるのでしない（旧版の 0021 と同じ）。

### BCF との対応

- 読むのは BCF 2.1 と 3.0、書くのは既定で 3.0、引数で 2.1 にする。
- 指摘は topic に、コメントは comment に、3D の場所は viewpoint に写す。要素の参照は、GlobalId の ID を `IfcGuid` に写す。`i` と番号の ID の要素は BCF で指せないので、参照から除いて診断する。BCF から読むときは、要素のハッシュがないので、読んだ建物モデルのハッシュで埋めるか、なしにする。
- 状態は、BCF の `TopicStatus` の文字列との対応の表で写す。表は引数で受け、既定は `Open`・`Resolved`・`Closed` にする。表にない文字列は `open` にし、元の文字列を `status_label` に残す。
- 2D の場所と図形は、BCF に表せないので書かずに診断する。スナップショットの画像は、BCF から読んだものを保つ。コアは画像を作らない。
- BCF の topic は、変えていなければ元のバイト列のまま書き、知らない要素と属性も保つ（#429）。
- BCF API（サーバーとの通信）は範囲の外にする。

### 置き場所

- レビューの文書の型と、検査・移す処理は、新しい crate `zumen-review`（L2）に置く。図面モデルと建物モデルの ID とハッシュの型だけに依り、形式の crate に依らない。
- BCF の読み書きは、新しい crate `zumen-bcf` に置く。ZIP と XML の L0（[決定 0209](0209-xml-l0-without-dependency.md)・[決定 0210](0210-zip-l0-without-dependency.md)）に依る。
- どちらも wasm の図面のモジュールに入れる（0013 の「レビュー」）。3D の場所は座標と ID だけなので、3D のカーネルを要らない。

## 影響

- #428 は、この文書の型・検査・移す op を作る。#429 は、BCF の読み書きと対応の表を作る。
- 照合の指摘を指摘にする op は、#428 で足す。
- 新しい診断の code（`review.*`・`bcf.*`）と op を足すので、境界の小版を上げる。

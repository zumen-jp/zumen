# 0267: 2D の表示部品はシーンの列を Canvas 2D で描き、React と画面を別に置く

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-06 |
| 状態 | 採用 |

## 背景

[#507](https://github.com/zumen-jp/zumen/issues/507) は、旧版の表示部品とプレイグラウンドを、新しい領域モデルとシーンの上に作り直す作業である。[機能の比較](../view2d.md)に、旧版の公開 API と追跡先をまとめた。

シーンの配置と各言語のリーダーはすでにある（決定 0137・0172・0178・0188・0194）。曲線・線種・継承・文字の字形を、表示部品でもう一度評価すると、コアと異なる結果になる。旧版のマークアップも、決定 0214・0218 のレビューの文書とは形が異なる。

## 選択肢

### 表示部品が受け取るモデル

1. 旧版の `Scene` と表示部品を移し、新しいシーンから旧版のモデルへ変換する。
2. 既存の JS の `Scene` が持つ型付き配列の列を読む。

1 は、全要素を JS のオブジェクトへ写す経路と、旧版のモデルを保つ必要がある。2 は、Worker から移したバッファーの列をそのまま見られ、シーンの定義を一か所に保てる。

### 最初の描画

1. Canvas 2D を使う。
2. WebGL または WebGPU を使う。
3. SVG の DOM にする。

1 は、シーンの輪の塗りと切り抜き、文字の代替表示、画像を直接扱える。2 は、面の三角形分割や切り抜きの実装が先に要る。3 は、大きな図面で描くものごとの DOM を持つ。最初は 1 で機能と測定の基準を作り、測って不足した箇所に別の描画を検討する。

## 決定

モデルは 2、描画は 1 を採る。

### 配置と責務

| 場所 | 名前と責務 |
| --- | --- |
| `packages/view2d` | `@zumen-jp/view2d`。シーンの描画、表示範囲、選択、状態とイベント、操作ツール。React に依らない |
| `packages/react` | `@zumen-jp/react`。表示部品・Worker・購読の作成から破棄までを管理するフック |
| `playground/` | ファイルを開き、診断・レイヤ・選択・出所・レビューを操作する日本語のプレイグラウンド。文言と CSS を置く |
| `bindings/js` | 既存の wasm のラッパーと、シーンのリーダー。表示部品から形式の読み取りを増やさない |

名前と配置は、全体計画 #1 の 6 章と決定 0003 に沿う。名前の予約や公開は、実装とは別に利用者が判断する。

表示部品は、利用側が用意した Canvas と、`Scene`・その列を返した `SceneResult`・対象文書の識別情報を受け取る。識別情報は、開いた文書の名前・形式と、`drawing` が返す文書のハッシュを含む。レビューを重ねるときは、利用側がレビュー文書の対象 ID との対応も渡す。セッション内の文書の名前だけで、別の入力やバージョンを同じ対象とみなさない。

ボタン・パネル・CSS・人向けの既定の文言を同梱しない。アクセシブルな名前・操作の説明・診断の文は、利用側が用意する。色などの表示設定は引数で受け取り、CSS の値を使う場合も利用側で引いて渡す。

### シーンと座標

- バッファーの解析は、既存の `readScene` を使う。表示部品は列を読み、全要素の別モデルを作らない。索引など、表示と選択に必要な派生データだけを持つ。
- シーンの参照先・並びの範囲・座標・上限を、描画に使う前に確かめる。列は利用中に書き換えず、`SceneResult` と文書の識別情報を一組にして差し替える。起点（`from`）・ビュー（`view`）・単位（`unit`）・許容差（`tolerance`）は、列から推測せず、その結果から読む。別の要求や文書の結果と組み合わせない。
- 座標は、シーンの起点の座標と CSS ピクセルを分ける。用紙は mm、空間はその単位であり、単位不明を mm とみなさない。カメラと座標の変換は f64 の値で計算し、塊の原点からの相対座標を保つ。
- 色・線幅・切り抜き・描く単位と塊の順は、シーンの契約に従う。曲線の分割・線種・継承を JS で評価し直さない。
- 字形がある文字はその輪郭を描き、文字列を重ねない。字形のない文字はブラウザーの文字で代替できるが、寸法と形の一致を保証しない。代替や未描画は、理由と要素を利用側へ返す。
- 寸法値や精密な解析は L2 の API を使う。表示上の吸着・計測はシーンの許容差の影響を受ける。用紙から実寸を決められない場合は、実寸を未確定として返す。

### ID・状態・外部のデータ

- 選択は、シーンが持つ L2 の要素 ID と配置の道筋を保つ。格子の列・行も含め、同じ定義の複数の配置を区別する。表示部品は永続 ID を作り直さない。
- 出所は、選択した ID で `entities` を呼び、L1 のレコードとバイト範囲へたどる。形式ごとのレコードを表示部品で解釈しない。
- 表示範囲・レイヤ・選択・強調・ツールの状態を購読できるようにする。React はその状態を購読し、同じ状態を別に管理しない。破棄とシーンの差し替えで、購読・ポインター・古い非同期の処理を片づける。
- 図面の読み取りは Worker で行い、シーンのバッファーを移す。React のフックは、取り消された読み取りの結果を反映しない。
- 画像・PDF・フォントは、利用側が選んだ入力か、明示して渡した解決関数から得る。表示部品は参照名を URL として取得せず、図面や結果を送信しない。解決関数には中断と資源量の上限を伝え、失敗した要素を報告する。
- 赤入れは、決定 0214・0218 のレビューの文書と API を使う。対象・用紙・ビューを区別し、形の生成をコアと二重に実装しない。レビュー図形をシーンにするコアの処理と API は未実装であり、#589 で作る。保存・作者・時刻・文言は利用側が渡す。

## 影響

- 旧版とパッケージ名・入力モデルが変わる。API の綴りをそのまま保つことより、現在のシーン・ID・レビューの契約を優先し、移り方を機能の比較と各パッケージの README に書く。
- Canvas の画素と、ブラウザーが代替する文字の画素は、環境間でビット単位の一致を約束しない。コアのシーンと API の出力が同じになる約束は保ち、描画は形・座標・色・切り抜きと操作で検査する。
- 新しい実行時の描画の依存は要らない。React のフックで使う React と、追加する開発ツールは、その実装でバージョンとライセンスを確認する。
- ブラウザーの検査は、決定 0199 の Playwright と既存の固定したバージョンを使う。PR では Chromium、毎晩は Firefox と WebKit を使う。テストは合成のシーンと、再配布できる公開サンプルで行う。
- 実装は #584〜#589 で追う。この記録だけでは、表示部品が使えることや旧版を archive できることにはならない。

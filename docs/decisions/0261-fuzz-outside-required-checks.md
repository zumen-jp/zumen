# 0261: fuzz の job を main の必須の検査にせず、PR の変更と関係のない失敗ではマージを止めずに早めに直す

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-04 |
| 状態 | 採用 |

## 背景

[0258](0258-fuzz-seeds-and-runs.md) で、crate などを変えた PR でも fuzz を流す。ただ、fuzz の job は main の必須の検査ではない。main の必須の検査は、CI の 9 つの job のうち「サイト」を除く 8 つで、fuzz の crate はワークスペースの外にあるので、どれも fuzz の target を組み立てない。fuzz の結果を見ずにマージすれば、fuzz の組み立てを壊す変更や、パニックを足す変更も入る（#545）。

必須の検査にするかは、ルールセットを変えるので、利用者が決める（[0254](0254-parallel-agents-and-cross-review.md)）。fuzz は、PR の変更と関係のない、前からある誤りも見つける。その失敗の扱いもマージの条件に関わるので、利用者が決める。

## 選択肢

### fuzz の job

1. main の必須の検査にする。workflow は `paths` で PR を選ぶので、どの PR でも動かし、変えたファイルを見て中を飛ばす形に直す。
2. 必須の検査にしない。マージの手順で、PR で流れた fuzz の結果も見る。

### PR の変更と関係のない失敗

1. 直すまで、マージを止める。
2. issue にし、利用者に確かめてからマージする。
3. マージを止めず、issue にして早めに直す。

## 決定

利用者が 2026-11-04 に会話で、次のように決めた（言葉は #545 のコメントにある）。

- fuzz の job は、選択肢 2 にする。main の必須の検査にしない。理由は、CI を軽く保ちたいことである。
- PR の変更と関係のない失敗は、選択肢 3 にする。無視してよいが、早めに直す。

関係のない失敗について、利用者は理由を挙げていない。エージェントは、次の理由で、選択肢 3 が選択肢 1・2 より合うと考える。

- 選択肢 1 では、main に前からある失敗で PR が止まる。止めても main は安全にならず、直すまで、fuzz が流れる PR がすべて止まる。
- 選択肢 2 では、失敗のたびに利用者を待つ。

この判断をマージの手順にするため、エージェントが次を補った（#545 の範囲、[0174](0174-plan-in-issues.md)・0258 から）。PR #554 で利用者に示し、認めてもらってから採る。

1. PR で fuzz が流れたら、その結果も通ってからマージする。見つけた入力のある失敗は、流し直して通っても、通ったとしない。
2. PR の変更と関係のない失敗は、fuzz の失敗のうち、main の上でも同じように落ちるものとする。見つけた入力があれば、その入力が main の target でも落ちること。入力がなければ（組み立てや道具の失敗）、main の実行でも同じ所で落ちること。
3. 関係のない失敗では、マージを止めない。マージの前に issue にし（同じ失敗の issue があれば、それを使う）、PR の本文にその issue を書く。issue は、いちばん前の開いた段階の issue の子にし、開いた子 issue のいちばん上に並べる。入力を貼るなら、0258 のとおり最小にし、元の公開サンプルの出所とライセンスを添える。
4. 毎晩の実行で見つけた失敗も、同じく issue にして早めに直す。エージェントは、作業を選ぶ前に、main の最新の毎晩の fuzz を見る（`docs/work.md` の「選び方」）。

確かめ方は、`fuzz/README.md` の「落ちたとき」にある。

## 影響

- main の必須の検査は今の 8 つのままで、CI を軽く保てる。
- fuzz の組み立てを壊す変更とパニックを足す変更は、必須の検査では止まらない。マージの手順で、fuzz の結果を見て止める。PR のひな形の「確かめたこと」にも、fuzz の欄を足す。
- 関係のない失敗が直るまで、ほかの PR の実行でも、同じ失敗が出ることがある。その issue を PR の本文に書いて、マージしてよい。
- 見つけた入力は、版を出すまでは、公開の issue に書く（0258 と同じ）。`SECURITY.md` は、落ちる入力を公開の issue に書かないよう求めるので、版を出したあとの扱いは #557 で決める。
- 必須の検査にするかと、関係のない失敗の扱いを変えるには、利用者が決め直す（0254）。

# 0289: リリースを止めるものを 3 つに絞って main で区切り、決定 0283 の対象を配ったパッケージに入るコードにする

| 項目 | 内容 |
| --- | --- |
| 日付 | 2026-11-10 |
| 状態 | 採用 |

## 背景

- 開発は止めずに進む。0.2.0（#317）の前に、どこで区切り、何を待つかを決めていなかった。待つものを決めないと、issue が増えるたびに区切りが遠のく。
- [0283](0283-fuzz-reporting-after-release.md) の補ったこと 7 は、`v*` のタグの前に、タグを打つコミットで直っていない失敗のうち、入力か詳細を公開の所に置いたものを一覧で示し、直すか、扱いを利用者に決めてもらうとする。直さずにタグを打つなら、入力と詳細を非公開のアドバイザリに写してから、公開の所で伏せる。
- 2026-11-10 に一覧を調べると、すぐには直せない失敗が 2 系統あった。
  - LAZ（#510）: 展開を任せていた laz 0.13.0 が、壊れた入力でパニックする。直した版は、まだ crates.io にない。入力は #510 にある。LAZ は、各言語の `open` から届く。
  - PDF（#521 ほか）: ページの解釈を任せる hayro（[0256](0256-pdf-with-hayro.md)）の中で、時間やメモリを使いすぎる形が、issue・PR のレビュー・`docs/formats/pdf.md`・上流への報告にある。PDF は、どのパッケージの `open` からも使わないが、`zumen-pdf` は crates.io に単独で出す一覧にあった。
- 0283 の補ったこと 2 は、公開した最新のバージョンを最新の `v*` のタグとし、タグのコードで組み立てたすべての fuzz の target で確かめるとする。[0285](0285-release-push-requests.md) の 2 は、同じ確かめ方をタグを打つコミットに当てる。どちらも、パッケージに入らないコード（`zumen-pdf`）の失敗を含む。

## 選択肢

### 区切り

1. 機能がそろったかで区切る。
   - そろうのを待つ間にも issue が増え、区切りが決まらない。
2. 出してよい条件を満たした main のコミットで、push を頼むときに区切る。
   - 0283 の補ったこと 7 では、push を頼んでから見つけた失敗は非公開で扱うので、リリースを止めない。頼む前に見つけた失敗は公開の issue に書かれ、タグの前に直すか伏せるかが要る。頼むのが遅いほど、止めるものが増える。

### 0.2.0 の LAZ と PDF

1. 直るまで待つ。laz と hayro がいつ直るかは分からない。
2. 直さずに出す。入力と詳細を非公開のアドバイザリに写し、公開の所で伏せる。PDF の詳細は main の文書と上流の issue にもあり、伏せきれない。
3. 配るパッケージから外して出し、0283 の対象を、配るパッケージに入るコードに狭める。

## 決定

2026-11-10 に、利用者が会話で決めた。

- 区切りと周期（下の 1〜5）は、エージェントが示した案に「これで決める」と答えた（[#317 の記録](https://github.com/zumen-jp/zumen/issues/317#issuecomment-6743840325)）。
- LAZ と PDF は、選択肢 3 を示した問いに「外して出す」と答えた（[#317 の記録](https://github.com/zumen-jp/zumen/issues/317#issuecomment-6744714798)）。問いで示したのは、`zumen-pdf` を crates.io に出さないこと、0283 の「公開した最新のバージョン」を「配ったパッケージに入るコード」と決めること、LAZ の展開を止めて診断を返すことである（下の 6 の初めの文と 7）。

エージェントが次を補った。補ったことも、利用者が会話で認めてから採用する（認めた日・head・言葉は PR #711 に書く）。

- 6 の初めの文のほかの所
  - 配ったパッケージの範囲
  - 入力を渡した入口と、落ちた所で決めること（落ちる失敗と、落ちた所の決め方を含む）
  - その決め方を当てる所: 初回リリース後の判定、0283 の補ったこと 7 の一覧、push を頼んでから push まで、0285 の 2
  - 公開で扱うときの断り
- 2 の、0.2.0 のあとのタグを打つコミット。3 の後半。5 の、下限を上げるとき
- 7 の、`zumen-pdf` を配るのを #521 などを直してからにすること

決めたことは、次の 1〜7 である。

1. **止めるもの。** リリースを止めるのは、次の 3 つだけにする。作りかけの機能、速さの改善、1.0 より前に許している API の変更（[0015](0015-add-only-boundary-and-version-floors.md)）では止めない。
   1. 落ちる・終わらない・メモリや CPU を使いすぎる失敗のうち、0283 の補ったこと 7 の一覧に載るもの
   2. 公開の手順が通らないこと（`release.yml` の試運転が落ちる）と、権利・ライセンスの問題
   3. ID の契約を破る変更
2. **区切り。** 区切りの選択肢 2 を採る。push を頼むときの main のコミット（CI と `release.yml` の試運転が通ったもの）にタグを打ち、同じ日に push する。0.2.0 のあとは、このコミットを、5 のバージョンを上げる PR をマージしたコミットにする。頼んでから push までに見つけた失敗は、0283 の補ったこと 7 のとおり非公開で扱い、そのリリースを止めずに、あとのパッチで直す。
3. **0.2.0。** 止めるものを、#661・#668・#672 に固定する。このあとに見つけたものは、止めるものに足さず、push の前に、0283 の補ったこと 7 の一覧で扱う。ただし、一覧に載る失敗は 1 の 1 に当たるので、push の前に直すか、扱いを利用者に決めてもらう。
4. **周期。** 0.2.0 のあとは、2 週間ごとに、その時点の main から出す。間に合わないものは次の回に入れる。0283 の対象の失敗を直したら、2 週間を待たずにパッチを出す。
5. **バージョン。** 壊す変更があるときと、対応する環境の下限を上げるときは、マイナーを上げる（[0015](0015-add-only-boundary-and-version-floors.md)）。ほかはパッチを上げる。バージョンを上げる PR をマージしたコミットにタグを打つ。リリースのブランチは作らず、いつも main から出す。
6. **0283 の対象とするコード。** 0283 の「公開した最新のバージョン」は、そのバージョンで配ったパッケージに入るコードとする。0283 の範囲を、この分だけ狭める。
   - 配ったパッケージは、crates.io・npm・PyPI・NuGet に出したものと、`release.yml` が GitHub の Release に置く配布物（[0205](0205-release-and-publishing.md) の一覧）である。GitHub がどの Release にも添えるソースコードの圧縮は含めない。crates.io の crate では、既定で使わない機能のコードも入る。配る crate が使う依存のコードも入る。
   - 失敗が対象かは、入力を渡した入口と、落ちた所で決める。配るパッケージの入口は、crates.io に出す crate の公開の関数と、各言語のパッケージと CLI が呼ぶ op である。ほかの入口（0.2.0 では `zumen-pdf` の API と、fuzz の `pdf` の target）を、配らない入口と呼ぶ。
     - 配るパッケージの入口に入力を渡して起きる失敗は、対象にする。
     - 配らない入口で見つけた落ちる失敗（パニックと、スタックのあふれ）は、落ちた所が配ったパッケージに入るコードにあれば、対象にする。落ちた所は、落ちたときに動いていた関数とし、標準ライブラリの中なら、標準ライブラリの外の最初の呼び出し元とする。手元で再現しなくても、ログなどで落ちた所が分かれば、これで決める。落ちた所が分からなければ、対象にする。
     - 配らない入口で見つけたほかの失敗（落ちた所が配らないコードにある落ちる失敗と、時間切れ・メモリの使い過ぎ）は、対象にしない。ただし、同じ入力を配るパッケージの入口（その入口の fuzz の target）に流して失敗すれば、対象にする。
   - 初回リリース後の判定と、0283 の補ったこと 7 の一覧と、push を頼んでから push までに対象として扱う入力と、0285 の 2 の確かめは、どれもこの決め方による。タグを打つコミットで決めるときは、そのコミットから作るパッケージを、配ったパッケージと読む。
   - 対象にしない失敗は、[0258](0258-fuzz-seeds-and-runs.md)・[0261](0261-fuzz-outside-required-checks.md) のとおり公開で扱う。ただし、0285 のとおり、出所と再配布を認めるライセンスを示せない入力は、公開の所に貼らない。
7. **0.2.0 で外すもの。** LAZ と PDF を、配るパッケージから外す。
   - `zumen-pdf` を `publish = false` にし、`release.yml` の `CRATES` から外す。配るのは、#521 などを直してからにする。
   - `zumen-las` で LAZ の展開を止め、依存の `laz` を外す。LAZ と分かったら、点の範囲を求めずに `las.laz.unsupported` を返して止まる。laz の直した版が出たら、パッチで展開を戻す（#510）。

## 影響

- 0.2.0 の `open` は、LAZ を `las.laz.unsupported` で断る。リリースノートに書く。README・API の説明・`docs/formats/las.md`・形式の台帳を合わせる。`las.laz.invalid` は、展開を戻したときにまた返すので、`active` のまま残す。
- `laz` を外したので、`about.toml` の laz のライセンスの補いも外す。展開を戻すときに、直した版に合わせて足し直す。
- fuzz の `las` と `open` の target は、LAZ を飛ばさずに流す。展開を戻したら、LAZ の展開も fuzz で流れる。
- 配っていないコードを配るパッケージに入れたら、そのコードの失敗も、次のタグの前の 0283 の補ったこと 7 の一覧に入る。`zumen-pdf` は、#521 などを直してから配る。それまで、PDF の失敗の入力と詳細は、6 で対象にならないものに限り、6 の最後の断りのとおり公開で扱ってよい。
- `zumen-pdf` を初めて crates.io に出すときは、名前がまだないので、利用者のトークンで出すか、名前を取る（0205 の影響。人を待つもの）。
- `SECURITY.md`・`AGENTS.md`・`docs/work.md`・fuzz の手順の「公開した最新のバージョン」と「タグを打つコミット」の失敗は、上の 6 で読む。

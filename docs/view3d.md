# 3D の表示部品

利用側の Canvas に 3D のシーンを描く表示部品の設計です。設計は [#819](https://github.com/zumen-jp/zumen/pull/819) で採用しました。実装の開始条件と進み具合は [#681 の子 issue](https://github.com/zumen-jp/zumen/issues/681) で確認できます。

## 既存の契約と責務

| 契約 | 表示部品で守ること |
| --- | --- |
| [コアの設計](architecture.md) | 読み取り・形状の評価・シーン生成は Rust に置きます。表示部品で IFC をもう一度読まず、GPU の表示と入力を受け持ちます |
| [3D のシーンの採用済みの配置](https://github.com/zumen-jp/zumen/issues/417)・[#421](https://github.com/zumen-jp/zumen/issues/421) | 別の種類の blob `ZMS3`、メッシュ・インスタンス・要素・色・塊、Z が上、文書の長さの単位、f64 の原点と f32 の局所の値を使います。LOD はシーンごとに 1 段。塊と LOD の仮値は表示部品で決め直しません |
| [2D の表示部品](view2d.md)・[組み込みの案内](../packages/view2d/README.md) | 利用側の Canvas、文言・CSS・保存先を利用側に置くこと、明示した入力接続、購読・一時描画の解除をそろえます。2D の実装は変更しません |

| [座標系](formats/crs.md) | 地図への変換は文書のメタデータから受け取ります。座標系・単位・対応が分からない層を推測で重ねません |

`schema/scene3d.toml` と `scene3d` の op は #421 の成果物です。表示部品のために列・ID・コアの型を新設しません。採用済みの配置の詳細は [移行前の記録](https://github.com/zumen-jp/zumen/blob/86192aa34daad415a33dc07f92969aef9a3a1c5e/docs/decisions/0213-scene3d-sections-and-op.md) で確認でき、実装時には #421 が作ったスキーマと読み手を正とします。

## 描画基盤と依存

初期の描画は three.js の `WebGLRenderer`、WebGL2 とします。2026-11-11 に確認した公開リリース [r187](https://github.com/mrdoob/three.js/releases/tag/r187) の [0.187.0](https://github.com/mrdoob/three.js/blob/r187/package.json) と [MIT License](https://github.com/mrdoob/three.js/blob/r187/LICENSE) を比較の基準にしました。この設計の PR では依存を追加しません。

| 候補 | 公式の根拠と判断 |
| --- | --- |
| three.js | MIT。型付き配列の属性・インスタンス・当たり判定・複数の表示枠・資源の解放を持ち、利用側の three.js の物も受けられるため採ります |
| WebGL2 を直接扱う | 外部の描画の依存は減りますが、材質・インスタンス・選択・資源管理を別に実装し、利用側の Object3D を変換する必要があるため採りません |
| APS Viewer | [公式の説明](https://aps.autodesk.com/en/docs/viewer/v7/developers_guide/viewer_basics/)は取得できても本文を確認できませんでした。r71 は [過去の公式記事](https://aps.autodesk.com/blog/using-pointcloud-forge-viewer)の記録であり、現行版の確定値とは扱いません。現在の three.js を利用側と共用する契約を確かめておらず、独自のモデルの経路も必要になるので採りません。SDK の利用条件への同意や契約の判断は行っていません |
| xeokit | [公開ライセンス](https://github.com/xeokit/xeokit-sdk/blob/master/LICENSE)は AGPL-3.0。実行時の依存の規則に合わないため採りません。実装のソースは比較に使っていません |
| That Open Components | [本体は MIT](https://github.com/ThatOpen/engine_components/blob/main/LICENSE.md)ですが、[パッケージ](https://github.com/ThatOpen/engine_components/blob/main/packages/core/package.json)が要求する web-ifc は [MPL-2.0](https://github.com/ThatOpen/engine_web-ifc/blob/main/LICENSE.md)。別の IFC 読み取りとそのモデルを持ち込む経路になるので採りません |
| React Three Fiber | [MIT](https://github.com/pmndrs/react-three-fiber/blob/master/LICENSE)ですが、表示部品を React の描画の寿命に結び付けるため必須にしません。既存の React のフックと同様に、命令型の表示部品を任意の UI から使います |

`packages/view3d`、パッケージ名 `@zumen-jp/view3d` は #1 の置き場所に従います。`three` は必須の peer dependency とし、初期の許容範囲は `>=0.187.0 <0.188.0`、開発と検査は `0.187.0` を lockfile で固定します。ライブラリへ three.js を同梱せず、利用側と同じ ESM の実体を使います。複数の実体や範囲外の版では、互換性を推測して続けません。許容する r 版を増やすときは、Object3D・材質・選択・破棄の検査を通して範囲を更新します。

React は表示部品の依存にしません。React の任意のフックは `@zumen-jp/react` に置き、three.js の別の実体を読みません。three.js の内部パスや非公開 API に依存せず、一般の `three` と公開の addons のみを使います。three.js のライセンス表示は実装・配布を始める PR で第三者表示に加えます。

[WebGPURenderer](https://threejs.org/manual/pages/webgpurenderer) は WebGL2 へフォールバックできますが、ShaderMaterial・既存の材質の変更方法との互換は同じではありません。利用側が足す Object3D を同じように扱えると確かめるまでは、自動切り替えや初期の依存にしません。WebGL2 がない環境は利用側へ未対応を返します。この設計だけで[対応するブラウザー](support.md)の下限を上げず、実装時に構文・API・GPU の必要機能と下限での未確認を分けて記録します。

## シーンの受け取りと GPU の資源

シーンの blob・同じ要求の応答・同じ版の文書識別を一組で受け取ります。文書名だけで同一性を決めず、形式・ハッシュ・シーンの世代を選択と非同期処理に結び付けます。シーンの読みは `@zumen-jp/zumen` の #421 のリーダーを使います。呼び出し側は、表示が参照している列を変更・転送しません。

全列の長さ・型・参照範囲・有限の値、塊とメッシュの範囲、変換、件数を検査してから GPU へ渡します。新しいシーンの検査・資源作成に失敗したら、前のシーンを差し替えません。配列と索引、GPU バッファー、画素、反復の作業量には明示した上限を付け、入力に比例する確保は確保前に数えます。表示の上限や利用側の要求の中断をコアの予算と混同しません。

頂点と面の列は、型・配置が合うときは `BufferAttribute` のビューとして共有します。GPU への転送、法線の導出、3×4 から 4×4 への行列の展開、要素を引く索引は別の確保です。全経路をコピーなしとは呼びません。メッシュを共有し、塊・材質・表示状態が合うインスタンスをまとめます。反転や非一様な尺度などをまとめ描きで表せないときは、個別の Mesh の変換で保ち、表示と選択の双方を確かめます。未対応の形や変換を黙って省きません。

解決済みの RGBA と未解決の色を区別し、未解決の色は利用側が渡す代替色と報告を使います。色の解釈は #421 の契約に合わせ、照明やトーンマッピングによる表示と元の値を区別します。透明度 0・非表示・切断面の外の形は選択からも除きます。半透明の表示の合成と前後関係の限界は、GPU の画像が要素の意味やコアの結果であるかのようには扱いません。

## 座標と ID

公開する位置とカメラはプロジェクトの空間、文書の長さの単位、Z が上のままです。three.js の `Object3D.DEFAULT_UP` のような共有の既定値は変えず、作ったカメラの上方向を個別に設定します。

メッシュの点 `p`、塊の f64 原点 `c`、塊に対するアフィン変換 `(A, t)`、ビューの近くの f64 原点 `o` に対し、GPU へ渡す座標は `(c - o) + t + A p` とします。先に絶対座標を f32 にしてから原点を引きません。カメラ、切断面、利用側の物も同じ `o` に移します。ビューごとに表示原点を選び、移動や表示枠の切り替えで更新しても、文書の値・ID・保存したカメラは変えません。

地図上の層と重ねるときは、利用側が座標系・単位・プロジェクトから地図への対応を明示します。メートルかミリメートルか、緯度経度か平面座標かを値の大きさで推測しません。非線形の投影を単一の行列に見せず、対応できない変換は理由を返します。

要素の参照は文書識別と L2 の要素 ID です。インスタンスは元のシーンの行へ対応させ、GPU 内の並べ替えた番号や Object3D の `uuid` を永続 ID にしません。メッシュのない要素もメタデータから消しません。同じ建物から切り出した 2D は、#417 に従い同じ建物の要素 ID で連動します。任意の DXF と IFC の同名 ID を自動で結びません。

## ビューと状態

1 つの Canvas・1 つの WebGLRenderer に、ID のある複数の表示枠を置きます。枠は Canvas 左上からの CSS px の四角で、重ならないものに限定します。各枠に透視か平行投影のカメラ、切断面、表示・選択・色の状態を持たせます。viewport と scissor へ渡す向きと pixel ratio の変換は表示部品が受け持ち、CSS の大きさは利用側が設定します。

状態は three.js のオブジェクトそのものではなく、文書識別、ビュー ID、位置・方向・上方向、縦の視野角または平行投影の幅と縦横比、切断面、要素の参照による表示・選択・色を持ちます。入力値は有限で、方向・上方向が 0 でなく平行でもなく、投影の範囲と縦横比が有効であることを検査します。状態の取得・差し替え・購読は View2D と同じく明示し、保存先・自動送信・文言を持ちません。

次は表示部品の操作の設計で、まだ呼べる API ではありません。Rust の API の op やメッセージを追加するものでもありません。

| 操作 | 入力・返すもの・寿命 |
| --- | --- |
| `new View3D(canvas, options)` | 利用側の Canvas と表示・上限の設定。WebGL2 を使えないときは理由を返す |
| `setScene(input)` | blob・応答・文書識別の組か `null`。成功時だけシーンを差し替える |
| `setViews(views)` | ID・CSS px の枠・カメラ・切断面を一括で検査し、成功時だけ置き換える |
| `getState()`・`subscribe()`・`on()` | 状態が変わるまで同じ読み取り専用の snapshot。購読は解除関数を返す |
| `select()`・表示と色の設定 | 文書・ビュー・要素の参照で指定し、別文書の参照や未知の値を黙って読み替えない |
| `getRay(viewId, point)`・`hitTest(viewId, point)` | CSS px から、f64 原点と相対位置の光線、種類を区別した当たりの一覧を返す |
| `addOverlay(definition)` | 利用側の ID・原点・変換・単位・scope と幾何の記述か Object3D を登録し、`{ remove, signal }` を返す |
| レビューの場所への変換・適用 | 変換した値と調整・未対応の報告を返す。元のレビュー文書や保存先へ直接書かない |
| `attachInput()`・`handleInput()` | DOM の明示した接続と解除、DOM を使わない正規化した入力 |
| `invalidate()`・`render()`・`destroy()` | 更新を要求し、必要なときだけ描画する。破棄で予約した描画・購読・接続と部品所有の資源を終える |

切断面はレビュー文書と同じく、面の点 `p0` と法線 `n` で、法線の向きの半空間を取り除きます。相対座標 `q` では `n · (q + o - p0) > 0` を除き、描画と選択で同じ条件を使います。three.js の切り抜きの符号に合わせるときは法線を反転させます。断面の箱は #421 と同じく、要素を絞る箱と画面で切る 6 面を区別し、コアのメッシュを切り直した結果とは扱いません。

## レビュー文書と BCF

表示状態全体の保存と、レビュー文書の 3D の場所の保存を分けます。既存の `Place::Space` が持つ camera・selected・visible・exceptions・colored・clips を、対象と要素のハッシュを確認して受け渡します。見つからない要素は件数と参照を報告し、別の文書の同じ ID を採用しません。

現行のレビューの Camera は縦横比を持たず、平行投影は `width` を持ちます。BCF の読みでは `ViewToWorldScale` がその値へ写り、3.0 の書き出しは `AspectRatio = 1` です。[BCF 3.0 の説明](https://github.com/buildingSMART/BCF-XML/blob/release_3_0/Documentation/README.md#camera)と[スキーマ](https://github.com/buildingSMART/BCF-XML/blob/release_3_0/Schemas/visinfo.xsd)は縦の視野角・縦の尺度を使います。この設計で既存の Camera の意味や BCF の読み書きを変えません。

初期の厳密な BCF 往復は、単位が既知の m、地図への追加変換をしないプロジェクトの空間、1:1 のカメラ枠に限定します。この枠では平行投影の幅と高さが等しく、透視の視野角は縦の値で対応できます。通常の表示枠とは別に正方形の互換枠を保持し、表示上は余白を設けてその内容を保ちます。

任意の縦横比から正方形へ見える範囲を広げる変換は、明示した操作だけで行い、調整した値と理由を返します。元の縦横比とビュー全体は表示状態に保ち、BCF だけで完全に戻るとはしません。単位不明・mm など別の単位・既存の BCF で元の縦横比を復元できない場合は、厳密な往復の対象外と報告します。必要な単位と縦横比の引き渡しは、後続の BCF 接続の issue で契約・ネイティブ/wasm・外部との比較をそろえてから広げます。

カメラ・切断面・選択・可視性・色だけを変換し、一時の Object3D・操作ツール・ブラウザーの画素・保存先は BCF に混ぜません。スナップショットは利用側の明示した要求で作り、保存する画像の寸法と描画範囲を返します。外部サービスへのアップロードは別の許可を要する利用側の操作です。

## 追加描画と所有権

利用側が重機・車両などを足す経路は、幾何の記述と、利用側が作った Object3D の登録に分けます。登録に利用側の ID、f64 の原点、局所の変換、単位、`scene` か `viewer` の scope を明示します。ID の重複は拒み、コアの要素 ID とは種類で区別します。

幾何の記述は線・範囲・円・寸法線と、利用側が字形か描画済みの画像を渡す文字を対象にします。寸法の長さは文書単位、線とラベルの画面上の寸法は CSS px と区別します。新しいフォントや URL を自動で取りに行きません。表示のための近似の許容差と、当たり判定する部分を登録に結び付けます。

| 資源 | 所有する側・後始末 |
| --- | --- |
| 部品が blob から作る geometry・material・行列・索引 | 表示部品。シーン差し替えか破棄で解放 |
| 幾何の記述から部品が作る資源 | 表示部品。登録解除・scope の終了・破棄で解放 |
| 利用側が渡す Object3D と geometry・material・texture | 利用側。部品は借用し、登録解除で接続と購読を外します。共有資源を勝手に dispose しません |
| Canvas・利用側の CSS・渡した画像の元データ | 利用側。部品は DOM から取り除きません |
| 部品が作る描画用 texture・render target・renderer | 表示部品。個別に解放。material の解放だけで texture が解放されたとは扱いません |

Object3D の登録は、親のない root だけを受け、部品が持つ wrapper に接続します。既存の親から自動で奪ったり、利用側の位置・材質・`userData`・共有の既定値を書き換えたりしません。wrapper に原点と変換を置き、利用側は root の局所の座標を使います。更新は利用側が明示して `invalidate` を呼ぶ形にし、部品と利用側が同じ資源を同時に解放しません。

登録は `{ remove, signal }` を返します。`remove` は何回呼んでも後始末を重ねず、`signal` は解除を通知します。`scene` は成功したシーン差し替えで解除し、`viewer` は残しますが、古い文書の要素の参照を暗黙に引き継ぎません。破棄では両方を解除します。後始末の 1 つが失敗しても残りを実行し、最初の例外を返す規則を View2D にそろえます。利用側の資源を解放する callback を渡した場合も、部品側の解放との二重実行をしない契約にします。

## 当たり判定と入力

画面の点は Canvas 左上からの CSS px とビュー ID で受けます。光線をビューの相対座標へ移し、メッシュの当たりをインスタンスから元の要素へ戻します。利用側の Object3D は Raycaster と登録した対応で利用側の ID へ戻し、geometry の幾何の記述も同じ列に並べます。結果の種類は要素・追加描画・地面の 2D・点群を区別し、位置は f64 原点と相対座標、距離は文書単位を返します。

非表示・透明度 0・切断面の外を落としてから、距離が近い順に返します。同じ距離なら明示した登録の優先度、種類、元の行または利用側の ID で順を固定します。追加描画を常に手前とは扱いません。重なった候補を利用側が選べるよう一覧を返し、同じ要素の面の境界で重複した当たりはまとめます。

独自の shader や raycast を持つ利用側の物は、切り抜き・可視性・材質の対応を登録時に宣言させます。対応できないときは描画と選択の理由を返し、既存の要素と同じ精度を保証しません。利用側の callback は信頼されたアプリのコードで、コアの予算で中断できるとはしません。部品が扱う物の数・走査・結果の数には上限を設けます。

入力は `attachInput` と解除関数で明示して接続し、正規化した入力の入口も用意します。初期の標準割り当ては、クリックで選択、中ボタンで移動、Shift と中ボタンで注視点の周りの回転、Ctrl・Command とホイールで拡大、2 本指で移動・拡大です。個別に無効化でき、処理しない操作は DOM の既定の動作へ残します。特定の CAD 製品と同じ動作を保証せず、別の割り当ては利用側が渡します。

操作中のビューを固定してポインターを捕捉します。Escape、中断、捕捉の喪失、入力設定・ツール・シーンの変更と破棄で操作と購読を解除します。独自ツールの有効期間・重ね描き・再入の禁止も View2D にそろえ、操作やカメラの変更を利用側が購読できます。

## 地面の 2D・地物・点群

地面の 2D は、既存の View2D に描かせた Canvas を texture にする任意のアダプターから始めます。線・字形・切り抜きの描画を JS で作り直す案は採りません。平面の原点・2 軸・単位と、2D の文書・起点を利用側が明示します。texture の画素・寸法・更新に上限を付け、解像度による近似と元の 2D の報告を保ちます。2D を使わない入口は View2D を読み込みません。

地面での当たりは光線と平面の交点を元の 2D の座標・CSS px に戻し、既存の当たり判定へ渡します。紙の mm と実寸の対応が不明なら重ねません。建物から切り出した図面だけが同じ建物 ID で連動し、別の図面との対応は利用側が渡します。

地物と点群の描画は #472・#475 の列と参照を待つ別のアダプターです。八分木の既存の階層を使い、予算と表示範囲に従って読みます。表示だけのためにコアの点 ID・LOD や列の配置を作り直しません。点ごとの永続 ID を仮定せず、選べる単位はコアが返す参照に限ります。

## 検査と実装の分割

実装の検査には次の入力と比較先を使います。

- #421 が作る合成の既知の mesh・instance・ID と native/wasm の列の一致。表示は原点から遠い小さな図形、反転・非一様な尺度、複数の配置、透明度と未解決の色を含めます。
- 座標の数値・切断面の向き・既知の光線と当たりの集合を、独立した期待値と比較します。画像の差だけで ID や値の正しさを判定しません。
- ビューの保存・復元と 1:1・m の BCF の往復。縦横比の調整、単位不明、別文書、存在しない要素は制約や報告を確認します。BCF 2.1 と 3.0、外部の読み手と製品で確認した範囲を分けます。
- Chromium・Firefox・WebKit の固定した Playwright と、pixel ratio・複数のビュー・実ポインター・キーボード・タッチ・context loss。GPU に依存する画素をコアのビット一致の保証に含めません。
- 登録・解除・シーン差し替え・例外・破棄、React StrictMode・中断で、購読・Worker・RAF・GPU の資源が増え続けないこと。利用側の共有資源の再利用を確認します。
- 外部への通信を遮断し、公開サンプルかテスト内で作った最小の入力だけで、保存を要求するまで書き込みや送信がないこと。
- シーンのバイト、GPU 向けに展開した byte 数、CPU の処理、フレーム、GPU の完了を区別した時間と、メモリの観測。大規模な実物と表示の上限は、測る前に確認済みとしません。

API や BCF の単位・縦横比の拡張が必要な場合は、先に対応する契約・スキーマ・テストを確認します。

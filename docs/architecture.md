# コアの設計

## モデルと依存

読み書き・変換・解析は Rust に実装します。各言語のバインディングは同じコアを呼び、形式の判定もコアのデータから生成します。

実装は [`crates/`](../crates/) にあります。表では crate 名の `zumen-` を省きます。

| 層 | crate | ほかの層との関係 |
| --- | --- | --- |
| L0 字句・コンテナー | `step`・`xml`・`zip` | 形式の意味に依存しない部品を共有する |
| L1 ファイルモデル | `acad`（DXF・DWG）・`sxf`・`jww`・`ifc`・`pdf` | 異なる系統同士は依存しない。系統内でモデルを共有し、未知のレコードも元のバイト範囲と結び付ける |
| L2 領域モデル | `drawing`・`building`・`civil`・`geo`・`pointcloud` | L1 の型に依存しない。系統と領域をつなぐ処理が双方の型を扱う |
| L3 派生と照合 | `geom2d`・`scene`・`render`・`civil-drawing`・`profile`・`review`・`ids`・`bcf`・`asbuilt` | 領域モデルから作り直せる。元の要素とレコードまで出所をたどれるようにする |

形式別のリーダーは `zumen-landxml` など各形式の crate、納品・写真・表・ボーリングは `zumen-delivery`・`zumen-photo`・`zumen-sheet`・`zumen-geology` にあります。共通部品は `zumen-base`・`zumen-json`・`zumen-crs`・`zumen-geom3d`、入口は `zumen`（Rust）・`zumen-abi`（C ABI・wasm）・`zumen-sdk`（形式・プラグインの開発）です。

XML の原本位置・文字コード・名前の比較と予算は、[XML の原本と文字コード](formats/xml.md)にあります。

表示部品はコアのシーンを受け取り、利用側の Canvas・入力・状態と資源を管理します。[2D の表示部品](view2d.md) と [3D の表示部品の設計](view3d.md) に、読み取りと描画の責務、文書と ID、利用側の描画と破棄の契約があります。3D のシーンと表示本体の実装は #421 と #681 で追います。

## 書き出しの経路

| 場面 | 経路 |
| --- | --- |
| 低水準の編集 | L1 のトランザクションで、レコードと生の値を直接書き換える |
| 同じ形式の編集 | L2 の変更セット → `apply` → L1 の触れたレコードだけを書き換える |
| バージョンの変更、同じ系統の別の符号化 | L1 の系統の中で書き分ける |
| 別の形式への変換 | L1(A) → `lift` → L2 → `lower` → L1(B) → B のコーデック |
| 新規作成・作図 | L2 → `lower` → L1(B) → B のコーデック |

- どの経路でも、L1 への書き込みはトランザクションで行う。
- 書き出す前に、忠実度の見積もり（dry-run）を返せるようにする。

図面から新しい DXF を作る前には、`convert_estimate` で忠実度と既存の損失の診断を確認します。同系統の共有 L1 と、図面モデルからの lower は、それぞれ実変換と同じ書き手で一時的にファイルを作ります。見積もりは予定のハッシュ・要素数、種類と忠実度ごとの総数、上限付きの明細を返し、文書名と配布する blob は登録しません。同じ入力・設定・予算なら、直後の `convert` が書くハッシュ・要素数と診断が一致します。明細の上限は集計や書くファイルを変えません。数える対象と忠実度の範囲は、[DXF の見積もり](formats/dxf.md#変換前の見積もり)にあります。

同じ符号化・版・文字コードへの編集では、変更と、それに伴って更新する参照や件数だけを書き戻します。未知のレコードを含むほかの部分は元のバイトを保ちます。出力先で表せない値は、出所・種類・件数・忠実度を診断で返します。

図面モデルから新しい DXF を作る lower は、`zumen-acad` の `drawing` の feature に置きます。別の形式への `convert` は L1 → `lift` → L2 → lower、新規作図の `civil_drawing` は L2 → lower を通り、`lower_to_dxf_with` を共用します。既存の API は形の値を通す移し方を渡し、Rust の `lower_to_dxf` は元の形の値を保つ移し方を使います。文字の位置合わせなどの違いと保持・損失の範囲は、[DXF への変換](formats/dxf.md#新しい-dxf-への変換)にあります。同系統の L1 の再符号化は、この lower と分けます。

DXF の編集では、[DXF の編集](formats/dxf.md#編集) と [図面モデルの対応表](formats/drawing2d-mapping.md) で、残す値と診断を確認します。API の操作と期待する結果は [適合テストの `apply`](../bindings/conformance/cases/apply.json) と [`convert`](../bindings/conformance/cases/convert.json) にあります。外部の実装との照合は [検証キット](../xtask/verify/README.md) に従います。

## 幾何と許容差

領域モデルには曲線の定義を残します。表示・位相の計算や、出力形式で曲線を表せない場合に折れ線にし、作った点を `segments` の予算で数えます。別の形式への近似では弦の誤差を忠実度とともに記録します。用紙・実寸・プロジェクト・地図の座標と許容差を区別し、長さと面積は可能な限り元の形から求めます。2D の位相は許容差より細かな整数の格子で求め、使った間隔を記録します。

実寸の図形を持たない紙上の計測は、領域と ID を明示した[距離校正](calibration.md)で扱います。紙上の座標・要素の ID は保ちます。

## 決定性

同じ版・入力・設定・予算なら、書き出すバイト列、領域モデル、シーン、診断の順と停止位置までネイティブと wasm で一致させます。コアが描く画像も含みます。各端末の表示、外からの中断、環境の資源が先に尽きた場合は区別します。版をまたいで保証するのは ID です。

- IEEE 754 で結果が決まる演算を使い、精度が環境に依存する関数は `libm` を通す。出力の NaN は同じビット列にそろえる。32 bit の x86 は SSE2 を使い、wasm の relaxed SIMD は使わない。
- 位置・長さ・個数は `u64` で扱い、あふれを検査する。ハッシュ表の反復順や番地に頼らず、比較は全順序にする。同順位は ID か元の位置で決める。
- 並列の結果は入力順に集め、浮動小数の総和も分割によらず同じ順で計算する。時計・乱数・環境変数・ロケール・OS のフォントやファイルを結果に使う場合、値は呼び出し側から受け取る。
- 依存にも同じ条件を適用する。[適合テスト](../bindings/conformance/README.md) は、各環境から同じ入力を処理したハッシュをコミット済みの一覧と比べる。形式の正しさは仕様から求めた期待値と、独立した実装の出力で確かめる。

## 予算と中断

呼び出しの文脈に予算、診断の収集先と中断の合図を持たせ、入れ子の読み取りでも予算を共有します。依存の処理中に作業量を数えられない場合は、呼び出す前に入力の大きさを制限します。確保前に残りの入力と予算を確かめ、バイト・レコード・要素・深さ・分割数・繰り返しを作業量で数えます。並列でも入力順に予算を使います。停止位置を診断に残し、読み取りで部分結果を返すのは明示して求められた場合だけです。書き出しはすべての変更を確かめてから反映し、失敗時には何も書きません。中断や trap の後の wasm インスタンスの扱いは [JavaScript のバインディング](../bindings/js/README.md) にあります。

## 設計を変更するとき

契約・制限・手順は既存の節を書き換え、古い説明を削ります。同じ説明が要る箇所からはその節にリンクします。新しい文書は既存の節で扱えない用途があるときに作ります。

API と ID は[スキーマ](../schema/README.md)、診断は[カタログ](../catalog/README.md)、形式ごとの規則は[形式の文書](formats/README.md)、権利と検証の根拠は[形式台帳](../formats/README.md)、作業手順は[開発の進め方](work.md)にあります。変えた規則とテストを一緒に更新し、選択肢と採用理由はコミットか PR、未実装の約束は担当 issue に残します。個々の検査結果は元の記録を参照します。

過去の PR・issue・ソースのコメントにある決定番号は、[移行前の記録](https://github.com/zumen-jp/zumen/tree/86192aa34daad415a33dc07f92969aef9a3a1c5e/docs/decisions) から引けます。

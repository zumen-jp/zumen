# EXPRESS

利用者が渡す EXPRESS のスキーマ（ISO 10303-11）を読む規則を記録します。読んだスキーマは、IFC をスキーマに照らしてチェックする `validate` の op で使います（[決定 0207](../decisions/0207-building-model-components.md)・[決定 0216](../decisions/0216-express-validate-op.md)）。実装は `crates/zumen-ifc` の `Express` です。

ISO の本文は買わず、読みません。公開された EXPRESS のスキーマ（IFC など）と、寛容なライセンスの実装から読みます。zumen は EXPRESS のスキーマを同梱しません（旧版の決定 0028）。権利の根拠は[形式と権利の一覧](README.md#format-express)にあります。

## 入手

- IFC の EXPRESS のスキーマは、buildingSMART International が IFC のバージョンごとに公開している。利用者が入手し、`zm_push` で渡す。
- IFC のスキーマは、Git・パッケージ・テストに入れない。テストは、テストの中で書いた小さなスキーマを使う。
- 決定 0171 の条件に合う、再配布できる EXPRESS の公開サンプルは、まだ探していない（#663）。ISO が出すスキーマ（STEP のアプリケーション・プロトコルなど）は、ISO のサイトの AI の注記の扱いを利用者が決めてから探す（#669）。

## 読むもの

- ファイルの初めの `SCHEMA` から `END_SCHEMA` までを構文として読み、後ろは構文として読まない。字句には入力の全体を分けるので、後ろに閉じない注釈か文字列があれば失敗する。スキーマの名前の後ろのバージョンの識別子は読み飛ばす。
- 注釈（入れ子のある `(* … *)` と、`--` から行の終わりまで）は読まない。名前は、大文字と小文字を区別しない。
- 読むもの、読み飛ばすもの、数だけを数えるものは、[決定 0216](../decisions/0216-express-validate-op.md) の「EXPRESS から読むもの」のとおり。`WHERE`・`UNIQUE`・大域の `RULE` は評価せず、その数を結果と `express.rule.unsupported` で返す。

## 壊れた所と上限

- 読めない書き方、閉じない注釈か文字列、宣言のない名前、同じ名前の宣言、上位の型か定義された型の循環は、`express.file.invalid` で失敗する。診断の `line` と `near` は次のとおり。
  - 読めない書き方: その字句の行の番号と、その字句（名前と数は大文字にしたもの）。`END_SCHEMA` がないなど、入力の終わりで読めなくなったときは、行の番号を 0 にし、`near` を空にする。
  - 閉じない注釈か文字列: 行の番号（注釈は始まりの行、文字列は入力の終わりの行）。`near` は空。
  - 同じ名前の宣言: 後の宣言の名前の行の番号と、その名前（大文字にしたもの）。`TYPE` 同士・`ENTITY` 同士のほか、`TYPE` と `ENTITY` の同じ名前も断る。どちらの宣言を使うかを決められないためである（#668）。読み飛ばす宣言（`FUNCTION`・`RULE` など）の名前とは比べない。
  - 宣言のない名前と循環: 行の番号を 0 にし、`near` にその名前（大文字にしたもの）を入れる。上位の型の循環では、循環の中にある実体のうち名前の順で最初のもの、定義された型の循環では、たどると循環に入る型のうち名前の順で最初のものを入れる。
- 入力のバイト数を、予算の `input-bytes` で数える。字句に分けるときは、読んだバイトを `work` で数える（決定 0216）。字句・空白・注釈・文字列のまとまりごとに、読み終えてから数え、上限を超えたら、そのまとまりの範囲を指して止める。
- 循環を調べる手順を `work` で数える。上位の型は、強連結成分を Tarjan の方法で求め、実体ごとに 1 度入り、上位の型ごとに 1 度たどる。定義された型の鎖は、たどり終えた型を覚えておき、型ごとに 1 度だけたどる。手間は、実体・上位の型・定義された型の数に比例する（#668）。
- 集まりの型（`LIST OF` など）の入れ子は、1 段ごとに予算の `depth` で数え、型を読み終えたら出る。上限（既定は 256）を超えたら、その段の `LIST` などの字句を指して `budget.depth.exceeded` で止める（#668）。
  - 入れ子を読むとき・診断の値に型を書くとき・宣言のない名前を探すときは、自分を呼ばずに段を順にたどる。
  - 読んだ型を写す・比べる・捨てるときは、入れ子の段の数だけ自分を呼ぶ。段の数は読むときの `depth` の上限までなので、`depth` を上限なしにした呼び出しでは、深い入れ子でスタックを使い果たしうる。上限なしは、呼び出し側が明示したときだけ使う（決定 0010）。

## 確かめた度合い

| 形式 | 向き | 段 |
| --- | --- | --- |
| `express` | 読み | `synthetic` |

段の意味は[決定 0254](../decisions/0254-parallel-agents-and-cross-review.md) に、根拠は[形式と権利の一覧](README.md#format-express)にあります。

- 読み: テストの中で書いた小さな EXPRESS（`crates/zumen-ifc/tests/express.rs`）だけで確かめた `synthetic` の段。型・実体・属性・集まりを読むこと、評価しない規則の数、読めない書き方・宣言のない名前・同じ名前の宣言・循環の失敗、予算（バイトごとの `work`、集まりの入れ子の `depth`、長い鎖と循環を調べる手順の `work`）、既定の深さまでの入れ子を 1 MiB のスタックで読んでチェックできること、切ったり変えたりした EXPRESS で落ちないことを確かめる。
- buildingSMART が公開する IFC の EXPRESS のスキーマを読むことと、読んだ値とチェックの結果を外部の実装（IfcOpenShell など）と照らすことは、まだしていない（#663）。

# 座標系と標高

crate `zumen-crs` が持つ、座標の空間の型・座標系の名指し・平面直角座標の換算・ジオイドの格子の補間を書きます。

## 空間の型

| 型 | 空間 | 成分 |
| --- | --- | --- |
| `MapPoint` | 地図（メートル） | `northing`・`easting`。平面直角座標系の X・Y に当たる |
| `GeoPoint` | 地理（度） | `latitude`・`longitude` |
| `ProjectPoint` | プロジェクト（文書の長さの単位） | `x`・`y`・`z`（Z が上） |
| `Height` | 高さ（メートル） | 値・基準（`HeightDatum`）・成果（`Realization`） |

- 形式が書く成分の順は、`Axes`（`EastNorth`・`NorthEast`）で読み書きの所で直す。
- プロジェクトから地図への変換は `MapConversion`（IFC の `IfcMapConversion`）で表す。IFC 4.3 の定義のとおり、3 つの軸に同じ尺度（`Scale`）を掛け、地図の上の X 軸の向き（`XAxisAbscissa`・`XAxisOrdinate`）で反時計回りに回し、`Eastings`・`Northings`・`OrthogonalHeight` だけ動かす。回す角は、向きのベクトルを長さで割って余弦と正弦にし、三角関数を使わない。`IfcMapConversionScaled`（軸ごとの尺度）は、まだ扱わない。

## 座標系の名指し

| 座標系 | EPSG | `zumen-crs` |
| --- | --- | --- |
| JGD2024（JGD2011）の経緯度 | 6668 | `Crs::Geographic` |
| JGD2024（JGD2011）の平面直角座標系 I〜XIX | 6669〜6687 | `Crs::Plane(Zone)` |
| JGD2011 (vertical) height | 6695 | `VerticalCrs::Jgd2011`（測地成果2011） |
| JGD2024 (vertical) height | 11317 | `VerticalCrs::Jgd2024`（測地成果2024） |
| JGD2000 の平面直角座標系 I〜XIX | 2443〜2461 | `Crs::Jgd2000(Zone)` |
| 日本測地系の平面直角座標系 I〜XIX | 30161〜30179 | `Crs::Tokyo(Zone)` |

- 名前は、`EPSG:6677`・`urn:ogc:def:crs:EPSG::6677`・`http://www.opengis.net/def/crs/EPSG/0/6677` と、EPSG の名前（`JGD2024 / Japan Plane Rectangular CS IX`）を読む。水平の座標系の `JGD2011` は `JGD2024` と同じに読む。高さの 2 つの名前は、別の成果を指す。
- JGD2000 と日本測地系の平面直角座標系は、EPSG の名前（`JGD2000 / Japan Plane Rectangular CS IX`・`Tokyo / Japan Plane Rectangular CS IX`）も読む。JGD2011 には、利用者が渡す TKY2JGD・PatchJGD のパラメーターのファイルで直す（下の「座標の補正量の格子」）。経緯度の座標系（EPSG:4612・4301）は、まだ読まない。
- 19 の系の原点は、平成 14 年国土交通省告示第 9 号の別表から書く。経度は分の整数で持ち、ラジアンにするときに π/10800 を掛ける。

## 経緯度と平面直角座標の換算

国土地理院の測量計算サイトの平面直角座標への換算と緯度・経度への換算の計算式を、そのまま書く（2026-10-31 に確かめた）。楕円体は GRS80（測量法施行令第 3 条）、X 軸上の縮尺係数は 0.9999 とする。

- 順の換算は河瀬（2011）の式。展開の項は 5 つまで。
- 逆の換算は、地心緯度を介する河瀬（2021）の式。正角緯度 χ から δ の級数で地心緯度を求め、楕円体の比 (1+n)/(1−n) を 2 回掛けて緯度にする。
- 子午線収差角は、計算式の γ を度で返す。測量計算サイトの出力（`gridConv`）は、同じ点で符号が逆になる（下の照合を参照）。
- 中央の子午線からの経度の差が ±90 度に届く点と、緯度が ±90 度の点は換算しない。

## ジオイドの格子

ISG format 2.0（ISG、2020-06-25）の格子を読み、国土地理院の「ジオイド2024日本とその周辺」の説明書（2026 年 4 月）の方法で補間する。ジオイド高・基準面補正量・その和のどれかは、渡した格子で決まる。

- 読むのは、`data format` が `grid`、`coord type` が `geodetic`、`coord units` が `deg` か `dms`、`data units` が `meters`、並びが北から南・西から東（`N-to-S, W-to-E`。仕様の例の `N-S, W-E` も読む）のもの。書かれていない項目は、ISG format 2.0 の既定とする。ほかの形は `crs.geoid.unsupported` にする。
- 格子の間隔は、範囲と行・列の数から求める。`deg` の間隔（`0.333333` など）は丸めて書かれるので、書かれた間隔が求めた間隔と半分より違うときだけ壊れているとする。
- 双一次の補間は、求める点を囲む四隅の格子点を使う。重みが 0 でない格子点のどれかが `nodata` なら、値を返さない。格子点の上や格子の線の上では、重みが 0 の点を見ない（説明書の注 6）。格子の範囲の外も返さない。
- 補間の結果は、使ったモデルの名前と年（`model name`・`model year`）を持つ。格子の範囲と行・列の数は、`Grid::extent` で返す。
- ヘッダーの前のコメントの行は読まない。値の数は、予算のレコードで数える。ヘッダーの行と列の数で場所を取らない。

国土地理院のジオイド・モデルは、Git・パッケージ・テストに入れない。テスト（`crates/zumen-crs/tests/grid.rs`）は、ISG format 2.0 の例と同じ形の合成の格子を使う。実際のモデルで、国土地理院のジオイド高計算サービスか内挿計算プログラム（geoidcalc）と比べる照合は、[#438](https://github.com/zumen-jp/zumen/issues/438) で行う。照合の点・コマンド・手順・期待する結果は、検証キット（[`xtask/verify/geoid/`](../../xtask/verify/geoid/README.md)）にある。

## 座標の補正量の格子

日本測地系と JGD2000 の平面直角座標は、国土地理院の TKY2JGD（日本測地系から JGD2000）と PatchJGD（JGD2000 から JGD2011 と、地震などの後の成果の改定）のパラメーターのファイルで経緯度を直し、JGD2011 にする。読み取りは `ShiftGrid` で、データの行の書式は TKY2JGD の論文（飛田、国土地理院時報 No.97、2001）の表 2 による。

- データの行は、3 次メッシュのコード（8 桁）と、緯度・経度の補正量（秒）。空白で区切って読み、桁の位置は見ない。4 つ目の列（高さの補正量）があっても読まない。行の終わりは LF でも CR+LF でもよい。
- 初めのデータの行の前は、ヘッダーとして読まない。TKY2JGD のヘッダーは 2 行。PatchJGD のヘッダーは、バージョンの行と説明の行を持ち、行数と文字コード（UTF-8・Shift_JIS）がファイルのバージョンで違う（国土地理院の[座標補正パラメータファイルの更新の履歴](https://www.gsi.go.jp/sokuchikijun/patchjgd_version_00001.html)。ファイルと各ファイルのヘッダーは[座標補正パラメータファイルの一覧](https://www.gsi.go.jp/sokuchikijun/sokuchikijun41012.html)にある）。
- 初めのデータの行の後に、空白だけの行のほかで、データの行の形でない行（UTF-8 として読めない行を含む）があれば、`crs.datum-grid.invalid` で読まない。同じ格子点が 2 度あるときと、格子点の数が上限を超えるときも、同じにする。
- 格子点の間隔は、格子点の並びから見分ける。ファイルのヘッダーは、間隔を書かない。
  - 格子点がすべて、3 次メッシュのコードの末位 2 桁が 00・05・50・55 の所（緯度 150 秒・経度 225 秒の倍数）にあり、この間隔で南北か東西に隣り合う格子点があれば、3 次メッシュの 5 倍の間隔とする。公共測量成果改定マニュアル（国土地理院技術資料 A1-No.337、令和 7 年 4 月）の第 3 条の解説は、補正パラメーターの格子点をこの所とする。
  - そうでなく、3 次メッシュの間隔で南北か東西に隣り合う格子点があれば、3 次メッシュの間隔（緯度 30 秒・経度 45 秒）とする。TKY2JGD の論文の表 2 の間隔で、国土地理院が載せる tokachi2003.par のヘッダー情報の例も、隣り合う 3 次メッシュのコードの行を並べる。
  - 格子点が 1 つしかないときや、3 次メッシュの 2 倍・15 倍の間隔など、どちらの間隔でも隣り合う格子点がないときは、`crs.datum-grid.unsupported` で読まない。
  - 間隔は、ファイルの中で一様とする。3 次メッシュの間隔で隣り合う格子点と、5 倍の間隔だけの所が混ざったファイルは、全体を 3 次メッシュの間隔とみなすので、5 倍の間隔だけの所の点は、補正量を 0 にするか直さない。
  - 見分けた間隔は `ShiftGrid::spacing` で返す。国土地理院のファイルの間隔と、それがファイルの中で一様かは [#664](https://github.com/zumen-jp/zumen/issues/664) で確かめる。
- 補間は、点を囲む、その間隔の四隅の格子点の双一次。PatchJGD の格子は地殻変動のあった地域だけを持つので、囲む格子点が 1 つもない点の補正量は 0 にする。国土地理院の PatchJGD は、補正パラメーターの範囲の外の点を補正せず、一括処理の出力の行末に「-9999.」を出す（マニュアルの第 15 条）。囲む格子点の一部だけがある点と、TKY2JGD の格子の外の点は、`crs.datum-shift.missing` で直さない。3 次メッシュのコードで表せない所（緯度 0 度未満・66 度 40 分以上、経度 100 度未満・200 度以上）には、格子点がないとする。
- PatchJGD のファイルは、`Shifts::patch` に並べて渡す。マニュアルの第 3 条の解説のとおり、同じ地区に地震ごとのファイルが複数あれば、直したい座標を得た時期より後のファイルを、古い順に並べる。たとえば、地震 A の前に得た座標には、地震 A と、その後の地震 B のファイルを、この順に並べる。どのファイルを並べるかは、呼ぶ側が決める。
  - `to_jgd2011` は並びの順に当て、後のファイルは、前のファイルで直した経緯度で補間する。ファイルを 1 つ当てる前に中断の合図を確かめ、予算の作業量（`work`）を 1 つ数える。途中で止まれば、理由を診断にし、座標は返さない。
  - ファイルが複数なら、`crs.datum-shift.missing` の `grid` は、渡した順の番号を付けた `PatchJGD 1`・`PatchJGD 2` などにする。
  - ファイルは、日本測地系と JGD2000 の座標にだけ当てる。上の並べ方では、並びは、2011 年より前の改定（`tokachi2003.par` など、JGD2000 の成果を改定するもの）、JGD2000 から JGD2011 にするファイル、その後の改定の順になる。
  - JGD2011 の平面直角座標は、ファイルを当てずにそのまま返す。そのため、2011 年より後の地震などによる改定のファイル（`noto2024_BL.par` など）は、地震などの前に得た JGD2011 の座標に当てられない。JGD2011 の座標に当てる扱いは [#678](https://github.com/zumen-jp/zumen/issues/678) で決める。
- 格子点の数は、予算の作業量（`work`）で数える。
- 平面直角座標と経緯度の換算ができない点（値が有限でないか、緯度が ±90 度に届くか外か、系の原点との経度の差が ±90 度に届く）は、`crs.projection.unsupported` で直さない（#679）。換算は、日本測地系と JGD2000 の点を経緯度にするときと、補正量で直した経緯度を JGD2011 の平面直角座標にするときにある。補正量の極端な格子で直した点などで起きる。JGD2011 の経緯度の点も、どの系の平面直角座標にするかが決まらないので、同じ診断で直さない。
- 補正量の大きさには、読むときに上限を設けず、診断もしない。TKY2JGD と PatchJGD の論文とマニュアルは、補正量の値の範囲を定めていない。線を引くと、仕様にない値で、利用者が渡したファイルを断ることになる。断らずに warning だけを返すとしても、仕様に根拠のない閾値では、どの値から警告するかが恣意的になる。極端な補正量で直した点は、上の `crs.projection.unsupported` か、有限の値の平面直角座標になる。桁を誤った格子（小数点の抜けなど）は、診断なしに遠くの座標になるので、格子の正しさは、渡す側が国土地理院のファイルであることで確かめる。

パラメーターのファイルは、Git・パッケージ・テストに入れない。テスト（`crates/zumen-crs/tests/datum.rs`）は、表 2 と同じ項目の並びの合成の格子（桁の幅と行の終わりは表 2 と違う）と、行の終わりが CR+LF で長いヘッダーに UTF-8 でない行を含む合成の格子を使う。5 倍の間隔の格子の南端と南西の隅の値、間隔を確認できない格子の診断、2 つの PatchJGD のファイルを当てる順と、作業量の上限や中断の合図で止まることも、合成の格子で確かめる。

### jgdtrans との照合

`crates/zumen-crs/tests/jgdtrans.rs` は、テストの中で作った格子を、jgdtrans 0.3.1（MIT OR Apache-2.0。`zumen-crs` の dev の依存）でも読み、値を照らす。

- 格子は、表 2 の桁の幅（コード 8 桁、補正量 9 桁ずつを半角の空白で区切る）で書く。jgdtrans は、データの行を桁の位置で読み、ヘッダーの行数を形で決める（TKY2JGD は 2 行、PatchJGD と SemiDynaEXE は 16 行）。5 倍の間隔で補間する形は SemiDynaEXE などに限るので、5 倍の間隔の格子は、高さの補正量の列を持つ SemiDynaEXE の形で書く。
- 格子は 3 つ。東京の辺りの TKY2JGD の形（3 次メッシュの 9 × 9 の格子点）、仙台の辺りの PatchJGD の形（3 次メッシュの 13 × 13 の格子点から 11 個に 1 個ほどを除いたもの）、5 倍の間隔の SemiDynaEXE の形（9 × 9 の格子点）。補正量は、格子点ごとに決まる −10〜10 秒の値で、一次の式にしない。
- 読み: 格子点の数と、格子点ごとの緯度・経度の補正量が同じ。
- 補間: 格子ごとに 1,517 の点で、補間するかしないかがすべて合い、補間した点（957・687・957）の値の差は最大 2.4 × 10⁻¹¹ 秒だった（2026-11-09。テストは 10⁻⁹ 秒を上限にする）。
- 照らした点は、格子の線に乗らないように置いた。格子の線の上の点で、重みが 0 の側の格子点だけが欠けているとき、zumen は補間し（重みが 0 の格子点は見ない）、jgdtrans は四隅の格子点がそろわないので補間しない。国土地理院の計算の扱いは #664 で確かめる。
- 変換: 東京の辺りの 4 つの点を、日本測地系から TKY2JGD と 2 つの PatchJGD のファイルで、JGD2000 から 2 つの PatchJGD のファイルで JGD2011 にした平面直角座標は、jgdtrans で経緯度を順に直してから平面直角座標にした点と同じだった（差は 0 m。テストは 10⁻⁶ m を上限にする）。
- jgdtrans がヘッダーとして読む行数（PatchJGD は 16 行）が国土地理院のファイルに合うかは、確かめていない。国土地理院のファイルで照らすときに、#664 で確かめる。

## 標高の成果と基準

- `Height::difference` は、基準の違う高さの差を求めず `crs.height-datum.unsupported` を返す。成果の違う高さの差は求め、`crs.height-realization.mixed` を返す。
- `Realization::or_assume` は、形式が成果を書いていなければ、渡された成果を仮定して `crs.height-realization.assumed` を返す。

## SXF の測地座標系の部分図

SXF の測地座標系の部分図（X が北、Y が東）は、図面モデルの実寸の空間の `axes` を `Axes::NorthEast` にして持つ。空間の点は、ファイルの X・Y のまま持つ。用紙へ置くビューの変換は、`Axes::to_east_north` で東・北の順にしてから、数学座標系の部分図と同じ尺度・回転・移動で写す（[sxf.md](sxf.md)）。

## 確かめた度合い

| 形式 | 向き | 段 |
| --- | --- | --- |
| `isg` | 読み | `synthetic` |
| `par` | 読み | `synthetic` |

段の意味は[形式台帳の書き方](../../formats/README.md#確かめた度合い)に、根拠は形式と権利の一覧の [`isg`](README.md#format-isg) と [`par`](README.md#format-par) にあります。台帳の形式は、ジオイドの格子（ISG 形式）と、座標の補正量の格子（TKY2JGD・PatchJGD のパラメーターのファイル）です。

- ジオイドの格子: ISG format 2.0 の例と同じ形の合成の格子（`crates/zumen-crs/tests/grid.rs`）だけで確かめた `synthetic` の段。国土地理院のジオイド・モデルで、ジオイド高計算サービスか内挿計算プログラムと比べる照合は、検証キット（`xtask/verify/geoid/`）を使って #438 で行う。
- 座標の補正量の格子: TKY2JGD の論文の表 2 と同じ項目の並びの合成の格子と、長いヘッダーに UTF-8 でない行を含む合成の格子と、間隔を変えた合成の格子（`crates/zumen-crs/tests/datum.rs`）で確かめた `synthetic` の段。5 倍の格子の南端の補間、孤立した格子点と 15 倍の間隔の診断、複数のファイルを当てる際の作業量と中断も確認した。極端な補正量で直した点と、経緯度に換算できない点の `crs.projection.unsupported` も確かめた。fuzz の target `par` は、読めた格子で、決まった点の補間と `to_jgd2011` まで通す（#679）。テストの中で作った格子を jgdtrans 0.3.1 にも読ませ、読んだ格子点・補間の値・変換した座標を照らした（`crates/zumen-crs/tests/jgdtrans.rs`、上の「jgdtrans との照合」）が、自前で作った格子なので段は上げない。国土地理院のパラメーターのファイルは読んでいない。国土地理院のファイルの間隔とヘッダーを確かめることと、測量計算サイトの TKY2JGD・PatchJGD で確かめることは #664 で行う。
- 経緯度と平面直角座標の換算は形式ではないので、段を持たない。測量計算サイトと比べた記録は「照合の記録」にある。

# 座標系と標高

crate `zumen-crs` が持つ、座標の空間の型・座標系の名指し・平面直角座標の換算・ジオイドの格子の補間を書きます。

## 空間の型

| 型 | 空間 | 成分 |
| --- | --- | --- |
| `MapPoint` | 地図（メートル） | `northing`・`easting`。平面直角座標系の X・Y に当たる |
| `GeoPoint` | 地理（度） | `latitude`・`longitude` |
| `ProjectPoint` | プロジェクト（文書の長さの単位） | `x`・`y`・`z`（Z が上） |
| `Height` | 高さ（メートル） | 値・基準（`HeightDatum`）・成果（`Realization`） |

- 形式が書く成分の順は、`Axes`（`EastNorth`・`NorthEast`）で読み書きの所で直す。
- プロジェクトから地図への変換は `MapConversion`（IFC の `IfcMapConversion`）で表す。IFC 4.3 の定義のとおり、3 つの軸に同じ尺度（`Scale`）を掛け、地図の上の X 軸の向き（`XAxisAbscissa`・`XAxisOrdinate`）で反時計回りに回し、`Eastings`・`Northings`・`OrthogonalHeight` だけ動かす。回す角は、向きのベクトルを長さで割って余弦と正弦にし、三角関数を使わない。`IfcMapConversionScaled`（軸ごとの尺度）は、まだ扱わない。

## 座標系の名指し

| 座標系 | EPSG | `zumen-crs` |
| --- | --- | --- |
| WGS 84 の経緯度 | 4326 | `Crs::Wgs84` |
| JGD2024（JGD2011）の経緯度 | 6668 | `Crs::Geographic` |
| JGD2024（JGD2011）の平面直角座標系 I〜XIX | 6669〜6687 | `Crs::Plane(Zone)` |
| JGD2011 (vertical) height | 6695 | `VerticalCrs::Jgd2011`（測地成果2011） |
| JGD2024 (vertical) height | 11317 | `VerticalCrs::Jgd2024`（測地成果2024） |
| JGD2000 の平面直角座標系 I〜XIX | 2443〜2461 | `Crs::Jgd2000(Zone)` |
| 日本測地系の平面直角座標系 I〜XIX | 30161〜30179 | `Crs::Tokyo(Zone)` |

- 名前は、`EPSG:6677`・`urn:ogc:def:crs:EPSG::6677`・`http://www.opengis.net/def/crs/EPSG/0/6677` と、EPSG の名前（`JGD2024 / Japan Plane Rectangular CS IX`）を読む。水平の座標系の `JGD2011` は `JGD2024` と同じに読む。高さの 2 つの名前は、別の成果を指す。
- JGD2000 と日本測地系の平面直角座標系は、EPSG の名前（`JGD2000 / Japan Plane Rectangular CS IX`・`Tokyo / Japan Plane Rectangular CS IX`）も読む。JGD2011 には、利用者が渡す TKY2JGD・PatchJGD のパラメーターのファイルで直す（下の「座標の補正量の格子」）。経緯度の座標系（EPSG:4612・4301）は、まだ読まない。
- 19 の系の原点は、平成 14 年国土交通省告示第 9 号の別表から書く。経度は分の整数で持ち、ラジアンにするときに π/10800 を掛ける。

## 経緯度と平面直角座標の換算

国土地理院の測量計算サイトの平面直角座標への換算と緯度・経度への換算の計算式を、そのまま書く（2026-10-31 に確かめた）。楕円体は GRS80（測量法施行令第 3 条）、X 軸上の縮尺係数は 0.9999 とする。

- 順の換算は河瀬（2011）の式。展開の項は 5 つまで。
- 逆の換算は、地心緯度を介する河瀬（2021）の式。正角緯度 χ から δ の級数で地心緯度を求め、楕円体の比 (1+n)/(1−n) を 2 回掛けて緯度にする。
- 子午線収差角は、計算式の γ を度で返す。測量計算サイトの出力（`gridConv`）は、同じ点で符号が逆になる（下の照合を参照）。
- 中央の子午線からの経度の差が ±90 度に届く点と、緯度が ±90 度の点は換算しない。

## ジオイドの格子

ISG format 2.0（ISG、2020-06-25）の格子を読み、国土地理院の「ジオイド2024日本とその周辺」の説明書（2026 年 4 月）の方法で補間する。ジオイド高・基準面補正量・その和のどれかは、渡した格子で決まる。

- 読むのは、`data format` が `grid`、`coord type` が `geodetic`、`coord units` が `deg` か `dms`、`data units` が `meters`、並びが北から南・西から東（`N-to-S, W-to-E`。仕様の例の `N-S, W-E` も読む）のもの。書かれていない項目は、ISG format 2.0 の既定とする。ほかの形は `crs.geoid.unsupported` にする。
- 格子の間隔は、範囲と行・列の数から求める。`deg` の間隔（`0.333333` など）は丸めて書かれるので、書かれた間隔が求めた間隔と半分より違うときだけ壊れているとする。
- 双一次の補間は、求める点を囲む四隅の格子点を使う。重みが 0 でない格子点のどれかが `nodata` なら、値を返さない。格子点の上や格子の線の上では、重みが 0 の点を見ない（説明書の注 6）。格子の範囲の外も返さない。
- 補間の結果は、使ったモデルの名前と年（`model name`・`model year`）を持つ。格子の範囲と行・列の数は、`Grid::extent` で返す。
- ヘッダーの前のコメントの行は読まない。値の数は、予算のレコードで数える。ヘッダーの行と列の数で場所を取らない。

国土地理院のジオイド・モデルは、Git・パッケージ・テストに入れない。テスト（`crates/zumen-crs/tests/grid.rs`）は、ISG format 2.0 の例と同じ形の合成の格子を使う。実際のモデルで、国土地理院のジオイド高計算サービスか内挿計算プログラム（geoidcalc）と比べる照合は、[#438](https://github.com/zumen-jp/zumen/issues/438) で行う。照合の点・コマンド・手順・期待する結果は、検証キット（[`xtask/verify/geoid/`](../../xtask/verify/geoid/README.md)）にある。

## 対応点から地図への変換

図面（配置図など）の実寸の空間を地図の上に置く変換を、図面の点と地図の点の組から求める（[#685](https://github.com/zumen-jp/zumen/issues/685)）。`fit_map_conversion` は、組を `ControlPoint` の並びで受け、変換と点ごとの残差を返す。

- 変換は、尺度・回転・平行移動の相似とし、IFC の `IfcMapConversion` と同じ形（`MapConversion`）で返す。図面の X・Y を、地図の東・北に写す。鏡映は含めない。高さは求めず、`orthogonal_height` を 0 にする。図面の点の Z は見ない。
- 未知数は 4 つで、最小二乗で求める。図面と地図の点の重心を引いてから和を取り、地図の座標の大きな値で桁を落とさない。離れた 2 点か、一直線に並ぶ 3 点以上で決まる。
- 残差は、地図の点から、求めた変換で写した図面の点を引いた値（メートル）を、渡した組の順に返す。1 点だけ誤った組では、その点の残差が大きくなる。どの残差から誤りとするかは、呼ぶ側が決める。
- 組が 2 つより少ないか、図面の点がすべて重なるか、求めた変換が有限でなければ `crs.control-points.failed`（`points` は渡した組の数）を返す。有限でない値の組は `crs.control-point.invalid`（`index` は 0 から数えた組の番号）にする。組の数は、予算の作業量（`work`）で数える。
- 地図の座標系は、呼ぶ側が決めて変換と一緒に持つ。DXF の GEODATA からの変換は、次の節で扱う。

テスト（`crates/zumen-crs/tests/control.rs`）は、既知の変換で写した組から元の変換に戻ること、1 点ずつずらした組でその点の残差がもっとも大きいこと、2 点と一直線に並ぶ 3 点で決まること、診断と予算を確かめる。

## GEODATA から地図への変換

AutoCAD で地理位置を付けた DXF の GEODATA（[DXF の地理位置](dxf.md#地理位置geodata)）の値から、図面から地図への変換と地図の座標系を作る（[#685](https://github.com/zumen-jp/zumen/issues/685)）。`GeoData::read` は、`AcDbGeoData` のグループ・コードと値の並び（`GeoValue`）を読み、`GeoData::georeference` は `MapConversion` と `Crs` の組（`Georeference`）を返す。DXF の読みは呼ぶ側が渡すので、`zumen-crs` は `zumen-acad` に依らない。

- 読む値は、版（90）・座標の種類（70）・設計の点（10・20・30）・基準の点（11・21・31）・水平と垂直の単位の倍率（40・41）・上の向き（210・220・230）・北の向き（12・22）・尺度の推定の方法と利用者の倍率（95・141）・海面補正（294・142）・座標系の定義（303 の続きと 301）・メッシュの点と面の数（13・97）。サブクラスの印（100 の `AcDbGeoData`）の後だけを読み、同じグループ・コードが何度もあれば最初の値を使う。書かれていない値は ezdxf 1.4.5 の既定の値にする（推定）。
- 変換は、ezdxf 1.4.5 の `GeoData.get_crs_transformation` と同じ式にする。図面の点から設計の点を引き、水平の単位の倍率を掛け、`π/2 − atan2(北の Y, 北の X)` だけ反時計回りに回し、基準の点を足す。`MapConversion` では、`scale` が水平の単位の倍率、X 軸の向き（`x_axis_abscissa`・`x_axis_ordinate`）が北の向きの単位ベクトルの（Y, X）、平行移動が基準の点から回した設計の点を引いた値になる。高さは、基準の点の高さに、設計の点からの差に倍率を掛けた値を足す（推定。ezdxf は高さを写さない）。
- 座標系は、定義（Autodesk の座標系の XML）の `Alias`（`type="CoordinateSystem"` で、`Namespace` が `EPSG Code`）の `id` を EPSG のコードとして引く。XML の宣言は文字コードを UTF-16 と書くことがあり、DXF の文字列の符号化と合わないので、宣言を除いて読む。最初の軸（`AxisOrder` が 1 の `AxisAbbreviation`）が東か西でなければ扱わない。名前空間は見ない。いずれも ezdxf 1.4.5 の `GeoData.get_crs` と同じ。
- ezdxf が確かめた設定のほかは、変換を作らずに `crs.geodata.unsupported`（`reason`）を返す。版 1（R2009 の DXF。グループ・コードの意味が違う）は `version` だけを返す。座標の種類が局所の格子（1）でないものは `coordinate-type`、尺度の推定があるか利用者の倍率が 1 でないものは `scale-estimation`、海面補正は `sea-level`、上の向きが Z でないものは `up-direction`、メッシュの面で対応を持つものは `mesh`、水平と垂直で単位の倍率が違うものは `vertical-scale`、最初の軸が北か南か決まらないものは `axis-order`。面のないメッシュの点は使わない（ezdxf と同じ）。
- 座標の種類 2（投影の格子）と 3（経緯度）は、照らす相手が見つからないので扱わない（2026-11-18）。ezdxf 1.4.5 は局所の格子のほかの変換を作らない。AutoCAD が座標系を付けて保存した公開サンプル（ACadSharp の `geoloc.dxf`）も、座標の種類は 1 で、基準の点に投影の座標を書く。AutoCAD 2027 の `accoreconsole` には位置の目印を置くコマンドがなく、`LATITUDE`・`LONGITUDE` はヘッダーの値で、座標の種類を 0・2・3 に変えても変わらないので、図面の点の地図の座標を取り出せなかった。
- 定義から扱う座標系（[座標系の名指し](#座標系の名指し)の EPSG のコード）を引けなければ `crs.geodata-crs.unsupported`（`name` は見つけた EPSG のコードか座標系の名前）を返す。値が数でないか有限でないか、単位の倍率か北の向きが 0 なら `crs.geodata.invalid`（`code` はグループ・コード）を返す。診断は呼ぶ側が渡す場所（DXF のレコードの番号など）を持つ。値の数は予算の作業量（`work`）で数える。

テスト（`crates/zumen-geo/tests/geodata.rs`）は、テストの中で作る GEODATA つきの DXF を `zumen-acad` で読み、GEODATA の値と、図面の 4 点を写した地図の点を、ezdxf 1.4.5 で読んで写した値（`tests/geodata_ezdxf.py`）と 1e-9 m の中で照らす。図面は mm、地図は EPSG:6677 で、北を 30 度回す。扱わない設定・座標系・壊れた値の診断と場所、予算、公開サンプル（[`samples/dxf/acadsharp-geoloc.dxf`](../../samples/dxf/acadsharp-geoloc.dxf)）の値と診断も確かめる。

## 座標の補正量の格子

日本測地系と JGD2000 の平面直角座標は、国土地理院の TKY2JGD（日本測地系から JGD2000）と PatchJGD（JGD2000 から JGD2011 と、地震などの後の成果の改定）のパラメーターのファイルで経緯度を直し、JGD2011 にする。JGD2011 の平面直角座標は、2011 年より後の改定のファイルで直す。読み取りは `ShiftGrid` で、データの行の書式は TKY2JGD の論文（飛田、国土地理院時報 No.97、2001）の表 2 による。

- データの行は、3 次メッシュのコード（8 桁）と、緯度・経度の補正量（秒）。空白で区切って読み、桁の位置は見ない。4 つ目の列（高さの補正量）があっても読まない。行の終わりは LF でも CR+LF でもよい。
- 初めのデータの行の前は、ヘッダーとして読まない。TKY2JGD のヘッダーは 2 行。PatchJGD のヘッダーは、バージョンの行と説明の行を持ち、行数と文字コード（UTF-8・Shift_JIS）がファイルのバージョンで違う（国土地理院の[座標補正パラメータファイルの更新の履歴](https://www.gsi.go.jp/sokuchikijun/patchjgd_version_00001.html)。ファイルと各ファイルのヘッダーは[座標補正パラメータファイルの一覧](https://www.gsi.go.jp/sokuchikijun/sokuchikijun41012.html)にある）。
- 初めのデータの行の後に、空白だけの行のほかで、データの行の形でない行（UTF-8 として読めない行を含む）があれば、`crs.datum-grid.invalid` で読まない。同じ格子点が 2 度あるときと、格子点の数が上限を超えるときも、同じにする。
- 格子点の間隔は、格子点の並びから見分ける。ファイルのヘッダーは、間隔を書かない。
  - 格子点がすべて、3 次メッシュのコードの末位 2 桁が 00・05・50・55 の所（緯度 150 秒・経度 225 秒の倍数）にあり、この間隔で南北か東西に隣り合う格子点があれば、3 次メッシュの 5 倍の間隔とする。公共測量成果改定マニュアル（国土地理院技術資料 A1-No.337、令和 7 年 4 月）の第 3 条の解説は、補正パラメーターの格子点をこの所とする。
  - そうでなく、3 次メッシュの間隔で南北か東西に隣り合う格子点があれば、3 次メッシュの間隔（緯度 30 秒・経度 45 秒）とする。TKY2JGD の論文の表 2 の間隔で、国土地理院が載せる tokachi2003.par のヘッダー情報の例も、隣り合う 3 次メッシュのコードの行を並べる。
  - 格子点が 1 つしかないときや、3 次メッシュの 2 倍・15 倍の間隔など、どちらの間隔でも隣り合う格子点がないときは、`crs.datum-grid.unsupported` で読まない。
  - 間隔は、ファイルの中で一様とする。3 次メッシュの間隔で隣り合う格子点と、5 倍の間隔だけの所が混ざったファイルは、全体を 3 次メッシュの間隔とみなすので、5 倍の間隔だけの所の点は、補正量を 0 にするか直さない。
  - 見分けた間隔は `ShiftGrid::spacing` で返す。国土地理院のファイルの間隔と、それがファイルの中で一様かは [#664](https://github.com/zumen-jp/zumen/issues/664) で確かめる。
- 補間は、点を囲む、その間隔の四隅の格子点の双一次。四隅は、点の南西の格子点と、その北・東・北東の格子点とする。格子点の上と格子の線の上の点も、重みが 0 の格子点を含む四隅がそろわなければ補間しない。国土地理院の測量計算サイトの TKY2JGD・PatchJGD と同じ扱いで（下の「測量計算サイトとの照合」）、jgdtrans とも同じ。度分秒で書いた線の上の点は、度への換算の丸めで線から少し外れるので、格子の線から 10⁻⁹ 格子（3 次メッシュの間隔で 0.00000003 秒）より近い点は線の上に寄せる。PatchJGD の格子は地殻変動のあった地域だけを持つので、囲む格子点が 1 つもない点の補正量は 0 にする。国土地理院の PatchJGD は、補正パラメーターの範囲の外の点を補正せず、一括処理の出力の行末に「-9999.」を出す（マニュアルの第 15 条）。囲む格子点の一部だけがある点と、TKY2JGD の格子の外の点は、`crs.datum-shift.missing` で直さない。測量計算サイトの PatchJGD は、囲む格子点の一部だけがある点も「対象地域でない」として補正しない（補正量 0 と同じ座標を返す）。zumen は、地殻変動のあった地域の際で黙って補正しない座標を返さないよう、診断して直さない。3 次メッシュのコードで表せない所（緯度 0 度未満・66 度 40 分以上、経度 100 度未満・200 度以上）には、格子点がないとする。
- PatchJGD のファイルは、当てる成果で 2 つの列に分けて渡す（[#678](https://github.com/zumen-jp/zumen/issues/678)）。
  - `Shifts::patch` は、JGD2000 の成果に当てるファイル。2011 年より前の改定（`tokachi2003.par` など）と、JGD2000 から JGD2011 にするファイル。
  - `Shifts::revision` は、JGD2011 の成果の改定のファイル。2011 年より後の地震などのファイル（`noto2024_BL.par` など）。
  - 日本測地系と JGD2000 の座標には `patch` を当て、続けて `revision` を当てる。JGD2011 の平面直角座標には `revision` だけを当て、`patch` は当てない。JGD2011 の座標に当てる改定のファイルがなければ、座標をそのまま返す。
  - 並びを分けるのは、1 つの並びでは、JGD2011 の座標に 2011 年より前の改定や JGD2000 から JGD2011 にするファイルを当ててしまう誤りを、呼ぶ側の並べ方でしか防げないため。座標を得た時期を受けてファイルを選ぶ方法は、ファイルの対象の時期を読むヘッダーの書式が定まっていない（上のヘッダーの項）ので採らない。
- それぞれの並びの中は、マニュアルの第 3 条の解説のとおり、同じ地区に地震ごとのファイルが複数あれば、直したい座標を得た時期より後のファイルを、古い順に並べる。たとえば、地震 A の前に得た座標には、地震 A と、その後の地震 B のファイルを、この順に並べる。どのファイルを並べるかは、呼ぶ側が決める。
  - `to_jgd2011` は並びの順に当て、後のファイルは、前のファイルで直した経緯度で補間する。ファイルを 1 つ当てる前に中断の合図を確かめ、予算の作業量（`work`）を 1 つ数える。途中で止まれば、理由を診断にし、座標は返さない。
  - `crs.datum-shift.missing` の `grid` は、`patch` のファイルを `PatchJGD`、`revision` のファイルを `PatchJGD (JGD2011)` とし、並びのファイルが複数なら、渡した順の番号を付けた `PatchJGD 1`・`PatchJGD (JGD2011) 2` などにする。
  - 日本測地系と JGD2000 の座標に `patch` がなければ、`revision` があっても `crs.datum-grid.missing`（`grid` は `PatchJGD`）で直さない。
- 返す座標系は、どの改定の後でも JGD2011 の平面直角座標（`Crs::Plane`）とし、改定の時期を持たない。どの改定まで直した座標かは、呼ぶ側が渡したファイルで決まるので、呼ぶ側が記録する。
- 格子点の数は、予算の作業量（`work`）で数える。
- 平面直角座標と経緯度の換算ができない点（値が有限でないか、緯度が ±90 度に届くか外か、系の原点との経度の差が ±90 度に届く）は、`crs.projection.unsupported` で直さない（#679）。換算は、日本測地系と JGD2000 の点を経緯度にするときと、補正量で直した経緯度を JGD2011 の平面直角座標にするときにある。補正量の極端な格子で直した点などで起きる。JGD2011 の経緯度の点も、どの系の平面直角座標にするかが決まらないので、同じ診断で直さない。
- 補正量の大きさには、読むときに上限を設けず、診断もしない。TKY2JGD と PatchJGD の論文とマニュアルは、補正量の値の範囲を定めていない。線を引くと、仕様にない値で、利用者が渡したファイルを断ることになる。断らずに warning だけを返すとしても、仕様に根拠のない閾値では、どの値から警告するかが恣意的になる。極端な補正量で直した点は、上の `crs.projection.unsupported` か、有限の値の平面直角座標になる。桁を誤った格子（小数点の抜けなど）は、診断なしに遠くの座標になるので、格子の正しさは、渡す側が国土地理院のファイルであることで確かめる。

パラメーターのファイルは、Git・パッケージ・テストに入れない。テスト（`crates/zumen-crs/tests/datum.rs`）は、表 2 と同じ項目の並びの合成の格子（桁の幅と行の終わりは表 2 と違う）と、行の終わりが CR+LF で長いヘッダーに UTF-8 でない行を含む合成の格子を使う。5 倍の間隔の格子の南端と南西の隅の値、間隔を確認できない格子の診断、2 つの PatchJGD のファイルを当てる順と、作業量の上限や中断の合図で止まること、JGD2011 の座標に改定のファイルだけを当て、日本測地系と JGD2000 の座標の結果を 1 つの並びで渡したときと変えないことも、合成の格子で確かめる。

### jgdtrans との照合

`crates/zumen-crs/tests/jgdtrans.rs` は、テストの中で作った格子を、jgdtrans 0.3.1（MIT OR Apache-2.0。`zumen-crs` の dev の依存）でも読み、値を照らす。

- 格子は、表 2 の桁の幅（コード 8 桁、補正量 9 桁ずつを半角の空白で区切る）で書く。jgdtrans は、データの行を桁の位置で読み、ヘッダーの行数を形で決める（TKY2JGD は 2 行、PatchJGD と SemiDynaEXE は 16 行）。5 倍の間隔で補間する形は SemiDynaEXE などに限るので、5 倍の間隔の格子は、高さの補正量の列を持つ SemiDynaEXE の形で書く。
- 格子は 3 つ。東京の辺りの TKY2JGD の形（3 次メッシュの 9 × 9 の格子点）、仙台の辺りの PatchJGD の形（3 次メッシュの 13 × 13 の格子点から 11 個に 1 個ほどを除いたもの）、5 倍の間隔の SemiDynaEXE の形（9 × 9 の格子点）。補正量は、格子点ごとに決まる −10〜10 秒の値で、一次の式にしない。
- 読み: 格子点の数と、格子点ごとの緯度・経度の補正量が同じ。
- 補間: 格子ごとに 1,517 の点で、補間するかしないかがすべて合い、補間した点（957・687・957）の値の差は最大 2.4 × 10⁻¹¹ 秒だった（2026-11-09。テストは 10⁻⁹ 秒を上限にする）。
- 照らした点は、格子の線に乗らないように置いた。格子の線の上の点で、重みが 0 の側の格子点だけが欠けているときは、zumen も jgdtrans も四隅の格子点がそろわないので補間しない（2026-11-19 に、測量計算サイトに合わせて、zumen を重みが 0 の格子点も見る扱いに直した。#664）。
- 変換: 東京の辺りの 4 つの点を、日本測地系から TKY2JGD と 2 つの PatchJGD のファイルで、JGD2000 から 2 つの PatchJGD のファイルで JGD2011 にした平面直角座標は、jgdtrans で経緯度を順に直してから平面直角座標にした点と同じだった（差は 0 m。テストは 10⁻⁶ m を上限にする）。
- jgdtrans がヘッダーとして読む行数（PatchJGD は 16 行）は、2026-11-18 に国土地理院の PatchJGD のファイル 2 件で合うことを確かめた（#664）。

### 測量計算サイトとの照合

2026-11-19 に、国土地理院の測量計算サイトの Web 版 TKY2JGD（Ver.1.3.80）と Web 版 PatchJGD（Ver.1.0.1）の 1 点ごとの計算に点を度分秒で入れ、結果の経緯度（秒の小数 5 桁）を、同じ点の zumen の `ShiftGrid::correction` で直した経緯度と比べた（#664）。パラメーターのファイルは、国土地理院から入手した `TKY2JGD.par`（Ver.2.1.2）・`tokachi2003.par`（Ver.1.0.0）・`kumamoto2026_BL.par`（Ver.1.0.0）で、リポジトリの外に置いた。サイトの結果は、使ったパラメーターとして同じファイルの名前とバージョンを示した（TKY2JGD は示さない）。

- 点は、ファイルごとに 19 点。四隅のそろった格子点の上・東西と南北の格子の線の上・格子の中を 3 か所ずつ（12 点）、際の点 6 つ（北東の隅が欠けた格子の中、北か東の側が欠けた線の上と格子点の上、南か西の側だけが欠けた線の上）、格子の外の点 1 つ。点は格子点の並びから選んだので、位置と値は書かない。
- 四隅のそろった 12 点と、南か西の側だけが欠けた線の上の 2 点は、3 つのファイルのどれも、緯度・経度の差が表示の桁（0.00001 秒）の中で 0 だった（値を比べた点は、ファイルごとに 14 点、合わせて 42 点）。
- 北東の隅が欠けた格子の中と、北か東の側が欠けた線の上と格子点の上の 4 点は、サイトの TKY2JGD が「海域のため、変換できませんでした」とし、PatchJGD が「対象地域でないため補正しません」とした。格子の外の点も同じだった。zumen は、どれも補間しない。PatchJGD で囲む格子点が 1 つもない格子の外の点は、どちらも補正量 0 になる。囲む格子点の一部だけがある際の点は、サイトが補正せず、zumen は `crs.datum-shift.missing` で直さない（上の「座標の補正量の格子」）。
- 照らす前の zumen は、重みが 0 の格子点を見ず、度への換算の丸めで線の上の点を隣の区画に移していた。北か東の側が欠けた線の上の点を補間し、南か西の側だけが欠けた線の上の点で値を返さない所があった。照合を受けて直し、合成の格子のテスト（`crates/zumen-crs/tests/datum.rs` の `points_on_grid_lines_use_the_cell_to_the_north_east`）で確かめる。
- サイトの一括計算と平面直角座標の入力、TKY2JGD と PatchJGD を続けて当てる変換（`to_jgd2011`）は照らしていない。

## 標高の成果と基準

- `Height::difference` は、基準の違う高さの差を求めず `crs.height-datum.unsupported` を返す。成果の違う高さの差は求め、`crs.height-realization.mixed` を返す。
- `Realization::or_assume` は、形式が成果を書いていなければ、渡された成果を仮定して `crs.height-realization.assumed` を返す。

## SXF の測地座標系の部分図

SXF の測地座標系の部分図（X が北、Y が東）は、図面モデルの実寸の空間の `axes` を `Axes::NorthEast` にして持つ。空間の点は、ファイルの X・Y のまま持つ。用紙へ置くビューの変換は、`Axes::to_east_north` で東・北の順にしてから、数学座標系の部分図と同じ尺度・回転・移動で写す（[sxf.md](sxf.md)）。

## 確かめた度合い

| 形式 | 向き | 段 |
| --- | --- | --- |
| `isg` | 読み | `synthetic` |
| `par` | 読み | `external` |

段の意味は[形式台帳の書き方](../../formats/README.md#確かめた度合い)に、根拠は形式と権利の一覧の [`isg`](README.md#format-isg) と [`par`](README.md#format-par) にあります。台帳の形式は、ジオイドの格子（ISG 形式）と、座標の補正量の格子（TKY2JGD・PatchJGD のパラメーターのファイル）です。

- ジオイドの格子: ISG format 2.0 の例と同じ形の合成の格子（`crates/zumen-crs/tests/grid.rs`）だけで確かめた `synthetic` の段。国土地理院のジオイド・モデルで、ジオイド高計算サービスか内挿計算プログラムと比べる照合は、検証キット（`xtask/verify/geoid/`）を使って #438 で行う。
- 座標の補正量の格子: 国土地理院の TKY2JGD.par と PatchJGD のファイル 2 件を読み、測量計算サイトの TKY2JGD・PatchJGD の結果と照らした `external` の段（上の「測量計算サイトとの照合」、#664）。ほかの規則は、TKY2JGD の論文の表 2 と同じ項目の並びの合成の格子と、長いヘッダーに UTF-8 でない行を含む合成の格子と、間隔を変えた合成の格子（`crates/zumen-crs/tests/datum.rs`）で確かめた `synthetic` の段。5 倍の格子の南端の補間、孤立した格子点と 15 倍の間隔の診断、複数のファイルを当てる際の作業量と中断も確認した。極端な補正量で直した点と、経緯度に換算できない点の `crs.projection.unsupported` も確かめた。fuzz の target `par` は、読めた格子で、決まった点の補間と `to_jgd2011` まで通す（#679）。テストの中で作った格子を jgdtrans 0.3.1 にも読ませ、読んだ格子点・補間の値・変換した座標を照らした（`crates/zumen-crs/tests/jgdtrans.rs`、上の「jgdtrans との照合」）が、自前で作った格子なので段の根拠にしない。国土地理院のファイルの間隔・ヘッダー・ファイルの終わりの形は、2026-11-18 に 3 件で確かめた（#664）。
- 経緯度と平面直角座標の換算は形式ではないので、段を持たない。測量計算サイトと比べた記録は「照合の記録」にある。

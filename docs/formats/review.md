# レビューの文書と 2D の図形

レビューの JSON 文書は、対象・指摘・場所・図形を持ちます。文書の規則は[決定 0214](../decisions/0214-review-model-and-bcf.md)・[0218](../decisions/0218-review-document-and-ops.md)、空間の上の座標は[0282](../decisions/0282-legacy-markup-review-identity.md)、シーンの生成入口と出所の ID は[0295](../decisions/0295-review-scene-generation.md)にあります。

文書の読み書きは `zumen-review`、2D のシーンは `zumen-scene` が扱います。この文書は #589 のシーンの生成で使う図形と検査の規則を示します。

## 対象と座標

生成時には、開いた図面に対応する対象の ID・形式・ハッシュを渡します。文書内の対象と一致し、図面に存在する起点を指定すると、その対象と起点を指す項目を描きます。

| 起点 | 文書の `view` の値 | 点・幾何の寸法・許容差の単位 |
| --- | --- | --- |
| 実寸の空間 | 既存の空間の ID。例: `space/0` | 空間の単位 |
| 記号の定義の空間 | `DefinitionNamer` が決めた ID。例: `space/h1F` | 定義の空間の単位 |
| 用紙 | `SheetNamer` が決めた ID。例: `sheet/h22` | mm |
| 用紙のビュー | 用紙の ID 全体に `/view/` と 0 からの番号を足した値。例: `sheet/h22/view/0` | 用紙の mm |

点は Y が上です。空間の単位が不明なら、結果も不明のまま返します。スタイルの寸法を mm とみなして拡大・縮小しません。用紙のビューの点は用紙の座標であり、空間から用紙への変換をもう一度当てません。

別の対象・起点の項目は、指定による絞り込みで描きません。`view` のない項目に点がある場合は、置く先を診断し、現在の起点へ自動で置きません。3D の場所から 2D への投影も推測しません。文書の読み書きでは、こうした値も元のまま保ちます。

## スタイルの入力

文書の正式な図形のフィールドは、種類・対象・ビュー・点・文字・指摘への参照です。色・線幅・矢じり・文字の高さ・雲の刻みを、未知のフィールドから推測しません。呼び手が `ReviewStyle` で、次を明示します。

| 値 | 意味・条件 |
| --- | --- |
| `color` | 線・面・文字の RGB。各成分は 0〜255 |
| `line_weight` | 用紙の mm の線幅。有限で 0 以上。0 はもっとも細い線 |
| `text_height` | 起点の単位での文字の高さ。有限で正 |
| `text_padding` | 起点の単位での注記の枠の余白。有限で 0 以上 |
| `arrow_length` | 起点の単位での矢じりの長さ。有限で正 |
| `arrows` | 赤線の矢じり。`none`・`start`・`end`・`both` |
| `cloud_pitch` | 雲の円弧の弦の長さの上限。起点の単位で、有限で正 |
| `marker_size` | 写真と指摘の位置の記号の大きさ。起点の単位で、有限で正 |
| `font` | 任意のフォントの名前。字形は、渡した `FontSet` と既存の文字の規則で作る |

スタイルは選んだ項目に共通で当てます。文書の値には保存しません。`legacy.arrows`・`legacy.closed`・`legacy.arcLength`・`legacy.fontSize` など、移行時に保った描画の値は自動で解釈せず、その値を使わなかったことを診断します。作者・時刻など、描画のための値でないメタデータも保ちます。

## 図形

| 種類 | 作る形 |
| --- | --- |
| `redline` | 2 点以上を入力の順に結ぶ開いた折れ線。`arrows` に従い、端の有限で長さのある区間へ矢じりを置く |
| `cloud` | 3 点以上の輪を閉じ、辺の外側へ膨らむ半円を並べる。円弧は既存の曲線の分割を使う |
| `text` | 1 つの基点に `text` の文字を置き、文字の範囲を `text_padding` だけ広げた枠を描く |
| `photo` | 1 つの位置に写真位置の記号を描く。`text` は写真の参照として保ち、内容を取得しない |

赤線と雲の `text` が空でなければ、点の範囲の左上に文字を添えます。注記の `text` は空でない文字を求めます。注記と写真は先頭の点を使い、余分な点は使わなかった件数とともに診断します。注記の改行は LF と CRLF を扱い、上から文字の高さの 1.2 倍ずつ下へ行を置きます。枠は、置いた字形の輪郭の範囲を余白で広げます。字形が得られなければ文字高と字数から範囲を概算し、枠の近似を診断します。写真の参照は表示する題に読み替えず、呼び手が元の図形の ID から引きます。文言・作者・時刻をコアで作りません。

矢じりは塗った三角形にします。長さは `arrow_length`、幅はその 1/3 とし、先端を端点へ置きます。端の区間より矢じりが長い場合も、勝手に寸法を変えません。長さのない区間には置かず、すべての区間が長さを持たなければ入力の不備を診断します。

雲の輪の向きは符号付き面積で決めます。面積が 0 か、演算で有限でなくなる輪は診断します。各辺の円弧の数は、辺の長さを `cloud_pitch` で割って切り上げ、1 以上の整数にします。その数で辺を等分し、輪の外側へ膨らむ半円を置きます。重なる隣の点は円弧を作らずに飛ばし、端点の繰り返しは閉じる指定として扱います。円弧の数と分割後の点は、確保前に予算へ数えます。

写真位置は、`marker_size` を直径とする円と中心の十字で表します。画像の取得と表示は呼び手が行います。写真の URL・名前を開いたり、外部へ送ったりしません。

## 指摘の場所

2D の場所の `pin` には、`marker_size` を直径とする円と中心の十字を置きます。`extent` には、入力の左下と右上で閉じた長方形を描きます。両方あれば両方を描き、同じ場所のシーンの ID を付けます。ピンと範囲がともになければ、形を作りません。

指摘の題・作者・状態の文言は、呼び手が元の指摘の ID から引きます。対象の要素の参照から、ピンや範囲を推定しません。3D のカメラ・切断面・選択した要素は、この 2D の入口では投影せず、形を作れなかったことを診断します。

## 出所と描く順

図形のシーンの ID は `review/markup/<hex(id)>`、指摘の場所は `review/location/<hex(topic)>/<hex(location)>` です。同じ図形・場所から作る線・面・文字には、同じ ID を付けます。`sources` で元の種類と ID へ戻せます。

描く順は、文書の `markups` の順、続いて `topics` と各指摘の `locations` の順です。各図形の部品は、線・面・文字の既存のシーンの規則で並べます。移行時の `legacy_item_order` は自動で当てず、使わなかったことを診断します。

## 入力の検査と診断

Rust の公開フィールドから組み立てた `Review` も検査します。文書内の ID と参照、対象・起点・引数の不備では、シーンを返しません。幾何の不備は選んだ対象・起点の項目で検査します。有限でない点・寸法、足りない点、注記の足りない文字、範囲の順序の誤りも、元の図形・場所を示して診断します。選ばなかった項目の座標と未知のビューは、選んだ項目を描くことの失敗理由にはしません。

実装では `review.scene-` から始まる診断の code を台帳へ登録します。対象の不一致、起点の不足、描けない場所、使わなかった描画の値、図形の不備を区別し、種類・件数・元の場所と、必要ならフィールドの JSON Pointer を返します。予算と中断の停止は、既存の停止の診断に元の図形・場所を付けます。新しい code の正と文言は `catalog/` に置きます。

検査と索引のための走査・比較を `Work`、中間の形・点・文字・ID・索引・シーンの列を `DecodedBytes`、生成する図形を `Elements`、生成する点を `Segments` に数えます。三角関数などは `libm` を使い、円弧や文字を作る前に、作る量と処理量を確かめます。

フォントの配置と輪郭の読み取りは、フォントの内部の上限を使って、処理前に保守的な量を予約します。同じ輪郭を再利用するときは、輪郭の予約を重ねません。実際に小さい字形でも予約は大きくなるため、短い注記から試し、必要な量は `Budget` の使用量で確認できます。通常の図面のシーンの予算の数え方は変えません。

## 確かめた度合い

### 合成入力（synthetic）

レビュー文書の読み書き・引き継ぎ・取り込みは、`crates/zumen-review/tests/review.rs` の合成入力で検査しています。シーンの生成は `crates/zumen-scene/tests/review_scene.rs` の 17 件で、図形・文字と字形・対象と起点・ID・診断・予算と中断を検査しています。元の文書と、通常の図面のシーンのバイトが変わらないことも確認しています。

Windows のネイティブと `wasm32-unknown-unknown` では、6 種の起点・4 種の図形・フォントの有無・5 種の予算と中断を組み合わせた 240 件で、シーンの全バイト・出所・診断・予算の使用量を比較しました。670,736 バイトが一致し、SHA-256 は `27b732a3d7b09a837974a82497f818db93044746bfb4010cd90852dbf479caa2` です。比較用の一時のプログラムで確かめた範囲であり、通常の適合テストの対象に加えたものではありません。

`fuzz/fuzz_targets/review_scene.rs` は、JSON と直接作った Rust の値からシーンを作り、結果・診断・使用量の再現、低い予算と中断を検査します。フォントの輪郭も対象にします。Windows ではコンパイルと lint を確認し、継続する fuzz は CI で動かします。

### 外部の実装・表示（external・application）

レビューの図形について、外部の実装との照合と、表示部品・プレイグラウンドで描いた結果の確認は未実施です。API と表示部品への接続とともに #589 で追跡します。

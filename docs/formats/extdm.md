# 拡張 DM

公共測量の数値地形図データ（拡張 DM。作業規程の準則の付録 7「公共測量標準図式」の数値地形図データファイル仕様、台帳の `extdm_furoku7`）を読み、地理の領域モデル（[決定 0233](../decisions/0233-geo-model-features.md)）に移す規則を記録します。実装は `crates/zumen-extdm`、モデルは `crates/zumen-geo` です。API では、`open` に `format: "extdm"` を書いて名指しで開き（見分けるマーカーがないので判定しない）、`geo` の op に `doc`（と、中身を見る地物の `id`）を渡して、地物の型ごとの数と地物の属性・形の要約を返します。仕様の本文は写しません（`formats/ledger.toml`）。条の番号は付録 7 のもの、(1)〜(12) はファイル仕様のレコードの番号です。

## 対象

- 数値地形図データファイル（インデックス・図郭・グループヘッダー・要素・グリッドヘッダー・不整三角網ヘッダーの各レコードと、その実データのレコード）。インデックスレコードが別のファイル（数値地形図データインデックス、第 85 条）にあるときは、データファイルの前につないで渡す。
- 文字コードは UTF-8（第 99 条）。ファイル全体が UTF-8 として正しくなければ、Shift_JIS として読む。先頭の UTF-8 の BOM は除く。
- 書き戻しはしない。書き出すと、読んだバイト列をそのまま書く。

## レコード

- レコードは 84 バイトの固定長で、CR LF で区切る（第 96 条）。LF だけの区切りも受け付ける。短いレコードは、足りないフィールドを空白とみなす。
- フィールドは、仕様の書式（FORTRAN の書式）の桁でバイトの位置から切り出す。整数型（I）は前後の空白を除いて読み、空白だけなら値なしとする。文字型（A）は前後の空白（全角の空白を含む）を除く。
- 初めの 2 文字（`I`・`M`・`H`・`E1`〜`E8`・`G`・`T` と空白）でヘッダーのレコードを見分け、ヘッダーが持つ数だけ後のレコードを実データのレコードにする（L1 の分け方）。
  - インデックスレコード (a) の後に、図郭識別番号レコード数の (b) と、使用分類コード数の (c)。
  - 図郭レコード (a) の後に、(b)・(c) と、修正回数より 1 つ多い (d)・(e)・(f) の組。(f) は (d) のレコード数だけ。
  - 要素レコードの後に、そのレコード数の実データのレコード。
  - グリッドヘッダーレコードの後に、行数×列数の数値を 12 個ずつ入れたレコード。不整三角網ヘッダーレコードの後に、三角形数×9 の数値を 12 個ずつ入れたレコード。
- ヘッダーの数よりレコードが足りなければ、`extdm.record.invalid`（フィールド「レコード数」）を返す。ヘッダーのない実データのレコードと、知らないレコードタイプは、続くものをまとめて `extdm.record.unsupported` を返す。

## 座標系

- 系は、インデックスレコード (a) の座標系（平面直角座標系の系の番号）。インデックスレコードがないか、系が 1〜19 でなければ、図郭ごとに `extdm.crs.unsupported` を返し、座標系を不明にして形を移さない。地物と属性は移す。
- 測地系は、図郭レコード (d) の測地成果識別コード（修正の組のいちばん新しいもの）で決める。
  - 0（日本測地系で作成）は、日本測地系の平面直角座標系（`Crs::Tokyo`）。
  - 1（世界測地系で作成）・2（日本測地系から変換）と、書いていないときは、JGD2011（JGD2024）の平面直角座標系（`Crs::Plane`）とし、`extdm.datum.assumed` を返す。JGD2000 で作ったデータと区別できないので、これは仮定。
- 文書の座標系は、初めの図郭の座標系。座標系の違う図郭は `extdm.crs.unsupported` を返し、その図郭の形を移さない。
- 高さの基準は書いていないので、不明にする。

## 座標

- 要素の座標値は、図郭の原点（左下隅）からの値（(8)）。図郭レコード (b) の座標値の単位（1 は mm 単位、10 は cm 単位、999 は m 単位）で m に直し、原点に足す。X は北、Y は東。
- 図郭の原点は、図郭レコード (b) の左下図郭座標（メートル）に、(e) の端数を足したもの。端数は、地図情報レベルが 1000 以下なら mm、2500 以上なら cm で、符号は図郭座標と同じ（第 90 条）。
- 3 次元座標レコードの Z は、座標値の単位で m に直す。座標値がないことを表す値（m は -999、cm は -99900、mm は -999000）なら、標高を持たない。
- 2 次元の座標は、要素レコードの属性数値（mm、第 94 条）があれば、それを標高にする（等高線と、標高が同じ 3 次元のデータ、第 93 条・第 95 条）。

## 地物

- ヘッダーのレコード（インデックス (a)・図郭 (a)・グループヘッダー・要素・グリッドヘッダー・不整三角網ヘッダー）を地物にする。型は `extdm:` とレコードタイプ（`extdm:I`・`extdm:M`・`extdm:H`・`extdm:E1`〜`extdm:E8`・`extdm:G`・`extdm:T`）。
- ID は、ファイルの中のレコードの順の番号（0 から、10 進の文字）。
- 出所は、ヘッダーのレコードから、その実データのレコードの終わりまでのバイトの範囲。
- 分類コード（レイヤと項目の 4 桁）は、元の文字のまま地物の分類コードにする。
- 親は次のように決める。
  - 図郭レコードは、後に続くレコードの親になる。インデックスレコードは親を持たない。
  - ほかのレコードは、階層レベルで入れ子にする。前にあるグループヘッダーレコードのうち、階層レベルが小さいいちばん近いものを親にし、なければ図郭を親にする（第 42 条）。階層レベルが読めなければ、グループヘッダーは 1、ほかは 2 とし、`extdm.record.invalid` を返す。

## 属性

属性の名前は、`extdm:` と仕様の項目の名前にする。整数のフィールドは、値が 0 か空白（入力値なし）なら足さない。年月（西暦の下 2 桁と月）は文字のままにし、"0000" か空白なら足さない。

- インデックスレコード: 計画機関名を名前にする。図郭数・転位処理フラグ・間断処理フラグ・西暦年号・バージョン（整数）、作業規程名（文字）。(b) の図郭識別番号は、1 つずつ `extdm:図郭識別番号` にする。(c) は、使用分類コードごとに `extdm:使用分類コード/<使用分類コード>/標準の分類コード` などの名前にする（標準の分類コード・使用データタイプフラグ・方向規定区分・座標次元区分・内容記述）。
- バージョンが 2 でなければ（旧 DM は 0）、`extdm.version.unsupported` を返し、同じ書式として読む。
- 図郭レコード: 図郭名称を名前にする。図郭識別番号・タイトル名（文字）、地図情報レベル・修正回数・バージョン・要素数（整数）、隣接図郭識別番号（`extdm:隣接図郭識別番号/1`〜`/8`、左上から右回りの位置）。(d)・(e)・(f) の組からは、作成年月・現地調査年月・入力機器名・公共測量承認番号・作業機関名・撮影コース（(f) のレコードの文字）と、図郭識別コード・変換手法識別コード・測地成果識別コード。形は、図郭の四隅（左下・右下・右上・左上）の面。
- グループヘッダー・要素・グリッドヘッダー・不整三角網ヘッダー: 地域分類・情報分類・要素識別番号（整数）。要素識別番号は、要素識別番号反復回数（要素レコード）で 10,000 ごとに数える。
- グループヘッダー: 取得年月・更新の取得年月・消去年月、数値化区分。要素の数は、子の地物から求まるので移さない。
- 要素: 図形区分・精度区分・注記区分・転位区分・間断区分・属性区分（整数）、属性データの書式・取得年月・更新の取得年月・消去年月（文字）、属性数値（m の単位つきの量）。

## 形

形は LOD を持たない（`None`）。点は平面直角座標（北・東）と標高。

| レコードタイプ | 形 |
| --- | --- |
| E1 面 | 面。始点と同じ終点は除く。点が 3 つに満たなければ `extdm.record.invalid` |
| E2 線 | 線 |
| E3 円 | 円周上の 3 点を通る円を、座標値の単位を許容差にした多角形の面にする。`extdm.curve.approximated` を返す |
| E4 円弧 | 始点・中間点・終点を通る円弧を、同じ許容差の線にする。中間点を通る向きに回る。`extdm.curve.approximated` を返す |
| E5 点 | データ数が 0 か実データがなければ、代表点の座標値の点（第 92 条）。座標があれば、座標ごとの点（標高点群） |
| E6 方向 | 2 点 1 組ごとに、2 点の線（1 点目が記号の位置、2 点目が向き） |
| E7 注記 | 代表点の座標値の点。注記データを名前にし、縦横区分・文字列の方向・線号（整数）と、字大・字隔（mm の単位つきの量。仕様は 0.1 mm 単位）を属性にする。注記データは、レコードの区切りで全角の文字が分かれることがあるので、つないでから読む |
| E8 属性 | 形を持たない。属性レコードの文字を 1 つずつ `extdm:属性データ` にする |

- 円と円弧の 3 点が一直線に並べば、`extdm.record.invalid` を返す。円・円弧の標高は、3 点が同じ標高のときだけ持たせる。
- 実データ区分が 2（2 次元座標）・3・6（3 次元座標）でない E1〜E4・E6 と、座標が数でないかデータ数に足りないものは、`extdm.record.invalid` を返して形を移さない。
- グリッド（(5)・(11)）: 格子点を結ぶ三角形の集まり（`Shape::Triangles`、閉じていない）にする。値は原点（左下）から、行（X、北の向き）ごとに列（Y、東の向き）の順。格子点の座標は、グリッド原点座標値に行・列の番号とグリッドセルサイズを掛けたものを足し、座標値の単位で m に直して図郭の原点に足す。原点とセルサイズの単位と基準は仕様に書いていないので、座標値と同じとみなす（推定）。値がない格子点は置かず、四角形を南西・南東・北西と、南東・北東・北西の 2 つの三角形にする。三角形の点は（東・北・標高）。
- 不整三角網（(6)・(12)）: 三角形ごとの 3 点の三角形の集まりにする。記録の向きは決まっていないので、上から見て反時計回りにそろえる。Z がない三角形は置かず、`extdm.record.invalid` を返す。

## 上限

- 読んだレコードの数は予算（`Records`）で、地物の数は `Elements` で、座標・格子点・三角形の点の数は `Segments` で数える。

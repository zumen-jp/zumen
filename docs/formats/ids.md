# IDS

IDS（Information Delivery Specification）1.0 を読み、建物モデルで照合します。実装は `crates/zumen-ids` です。XSD と、そこから生成したコードは同梱しません（`formats/ledger.toml`）。

## 照合

仕様ごとに対象を選び、指定された要件を各要素のコンポーネントと照らします。満たさない要件を指摘にし、入力の版やモデルが持つ情報では確かめられない facet を分けて返します。たとえば IFC2X3 の総称クラスを IFC4 の詳細なクラスに推定して判定しません。通常の属性はモデルを使い、それ以外の明示の属性は、利用者が渡した EXPRESS の属性名で L1 の値を参照します。

## 手間の上限

読み取りと照合の手間は、予算の作業（`work`）で数え、上限で止める（#732）。

- **式（`xs:pattern`）を読む。** 括弧と、文字の集まりの引き算（`[a-z-[aeiou]]`）の入れ子は 64 段まで、`{n,m}` を展開した後の状態は 10,000 個まで、展開する回数は 660,000 回（状態の上限の 66 倍）までにする。超えた式は読めない式とし、`ids.restriction.unsupported` を返して、確かめられない制約として扱う。読む手間（式の文字の数と、展開した回数）を数える。文字の集まりは、展開しても写さない。
- **式を当てる。** 1 つの文字列に式を当てる前に、（文字の数 + 1）×（状態の数と、文字の集まりの項目の数の和）を数える。
- **値の決まりを当てる。** 文字列ごとに、文字を読む手間（16 バイトで 1）と、制約ごとの 1（列挙は、その値を読む手間）を数える。
- **facet を集める。** 要素と型のプロパティ・数量のセットと項目、分類の参照は、名前を読む手間（16 バイトで 1）を数える。材料の部分、並びの値の項目、`partOf` でたどる全体は、数を数える。どれも照合の前に数える。プロパティのセットと項目は、名前で引く表で集め、項目の数の二乗の手間にしない。
- **値と指摘を写す。** コンポーネントにある属性の値を写す手間と、指摘ごとに仕様の名前を写す手間（名前を 2 回読む手間）を、写す前に数える。

## 確かめた度合い

自作の UTF-8・UTF-16LE・UTF-16BE で IDS を読み、名前の要件をモデルに照合します。[XML の規則](xml.md)を使います。公開 IFC2X3 と自作の名前の要件 6 仕様について、IfcTester 0.9.0 の対象・不適合の全 GlobalId とコアの判定が一致しました。手順・期待値・比較器の反例は [IDS 検証キット](../../xtask/verify/ids/README.md)にあります。自分で定めた要件なので、読みの段は `synthetic` のままです。

自作の Shift_JIS の日本語の根を不正な IDS として断り、診断の `near` に Unicode の名前を返すことを検査します。未知の facet と制約の日本語の名前も、診断の `kind` とモデルに返します。この確認は `synthetic` です。

buildingSMART Japan の令和 7 年度用（202510_01）「共同溝・プレキャスト躯体工」の原本は、IDS の名前空間を宣言していません。IFC2X3 の自作モデルと組み合わせると、IfcTester 0.9.0 と `ids_check` はどちらも根の `ids` で読み取りを終え、3 仕様の対象数・不適合数は得られません。

名前空間を補った参考入力では、3 仕様とも ObjectType と実数のプロパティで対象を選び、文字列の必須プロパティを判定できました。各仕様に 3 要素を作り、対象 2 要素・不適合 1 要素の GlobalId を IfcTester と照合しました。別に、原本と参考入力についてネイティブと wasm の状態と応答も照らしました。[原本の版・再現手順・照合した値](../../xtask/verify/ids/README.md#国内積算用の公開原本)

段の意味は[形式台帳の書き方](../../formats/README.md#確かめた度合い)に、根拠は[形式と権利の一覧](README.md#format-ids)にあります。読みの段は `synthetic` です。判定まで照合できた入力は、自作の名前の要件と、公開原本に名前空間を補った参考入力です。IFC4/4.3、分類・材料・部分の関係、実機での表示は未確認です。

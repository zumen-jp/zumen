# LAS・LAZ

LAS 1.0〜1.4 と LAZ（台帳の `las_1_4_r15`・`laz_1_4`）、COPC 1.0（`copc_1_0`）の点群を読み、点群の領域モデルに移す規則を記録します。実装は `crates/zumen-las`、領域モデルは `crates/zumen-pointcloud` です。仕様の本文は写しません（`formats/ledger.toml`）。

## API

- `open` は、入力の初めの `LASF` で見分ける。`size` に全体の大きさを書けば、入力を全体の初めの部分とみなし、足りない範囲を `needs` で求める。ホストは、範囲を `<入力の名前>#<start>-<end>` の名前で `zm_push` してから、同じ `open` をもう一度呼ぶ。読み終えると、使った範囲の入力を `done` で返す。
- 1 回目はヘッダー（375 バイトまで）を、2 回目は VLR・点のレコード・EVLR の範囲を求める。全体を渡せば、1 回で読む。
- `pointcloud` の op は、点の数・範囲・座標系・持つ属性・八分木の深さとノードの数を返す。`limit` を書けば、`region`（北・東・標高の箱）と `tolerance`（点の間隔）に合う点を、八分木の浅い段のノードから `limit` 個まで返す。
- `scene3d` の op は、同じ選び方の点を八分木の節ごとの点の区画で ZMS3 1.1 に返す（スキーマ 1.88 から、[点群の契約](../../schema/README.md#点群の-3d-のシーン)）。`box` は東・北・高さの順で、`region` と軸の順が違う。
- 書き出しはしない。

## ヘッダーと VLR

- ヘッダーは、バージョン・点の形式と長さ・点の数・倍率とずれ・範囲を読む。1.4 は、64 ビットの点の数と EVLR の位置を読む。点の形式の上の 2 ビットが立てば LAZ とする（下の「LAZ」）。
- 上の 2 ビットのうち、LAZ 1.4（OGC 24-070r1）の 6.2・6.3 が LAZ のフラグと定めるのは、ビット 7（128）だけである。ビット 6（64）も LAZ のフラグとするのは推定で、LASzip（Apache-2.0）の読み方に合わせた（#544）。
  - LASzip（[`src/laszip_dll.cpp`](https://github.com/LASzip/LASzip/blob/a446a0c01362ed1c642928cff30416217f0468c3/src/laszip_dll.cpp) の `laszip_read_header`）は、点の形式のビット 7 かビット 6 が立てば、LASzip の VLR を求め、なければ「実験版の LASzip で圧縮したファイル」として断る。VLR があれば、ビット 7 だけを落として読む。圧縮して読むかは、ビットではなく、LASzip の VLR があるかで決める。
  - laz-rs 0.13.0（Apache-2.0、`src/las/file.rs`）は、圧縮をビット 7 だけで見分け、点の形式は下の 6 ビット（`& 0x3f`）にする。
  - zumen は、点の形式を下の 6 ビットにする所は laz-rs と同じにする。ビット 6 かビット 7 が立つのに LASzip の VLR がないファイルを断る所（`las.laz.invalid` の `laszip-vlr-missing`）は、LASzip と同じになる。LASzip の VLR があってビットが立たないファイルは、LASzip は圧縮したものとして読み、zumen は LAS として読む。ビット 6 だけが立つファイルを LAS として読むと、点の形式が 64 以上になり、点のレコードを読み違えるので、ビット 7 だけを見るようには直さない。
- VLR と EVLR は、利用者の ID・レコードの ID・説明・中身を持ち、L1 のレコードにする。範囲から外れるレコードの残りは読まず、`las.vlr.invalid` を返す。
- 点のレコードが、ヘッダーの点の数より短ければ、読めた点だけを読んで `las.points.invalid` を返す。

## 点

- X を東（`easting`）、Y を北（`northing`）、Z を標高にし、倍率とずれを当てて f64 にする。
- 強度・分類・反射の番号と数は、どの形式でも持つ。形式 0〜5 は分類を下の 5 ビットで、形式 6〜10 は 1 バイトで読む。時刻は、時刻を持つ形式（1・3〜10）だけが持つ。色は、色を持つ形式（2・3・5・7・8・10）だけが持つ。
- 走査の角度・利用者のデータ・点の出所・フラグのビット・近赤外・波形・追加のバイトは移さず、属性ごとに `las.attribute.dropped` を返す。

## 座標系

- 全体の符号化の WKT のフラグが立てば WKT のレコード（`LASF_Projection` の 2112）、なければ GeoTIFF のキーのレコード（34735）を読む。
- WKT は `AUTHORITY["EPSG",…]`（WKT1）と `ID["EPSG",…]`（WKT2）のコードを読み、高さの座標系（`VERT_CS`・`VERTCRS`）の中のコードを高さの座標系にする。
- GeoTIFF のキーは、投影の座標系（3072）・経緯度の座標系（2048）・高さの座標系（4096）の、キーの中に値があるものを読む。
- 平面直角座標系（JGD2011、EPSG:6669〜6687）だけを水平の座標系にする。点は地図の空間に置くので、経緯度の座標系とほかの座標系は `las.crs.unsupported` を返して不明にする。座標系のレコードがなければ `las.crs.missing` を返す。高さは JGD2011・JGD2024 の標高（6695・11317）だけを受け、ほかは `las.vertical-crs.unsupported` を返す。

## LAZ

- LAZ 1.0〜1.4（OGC 24-070r1・LASzip 仕様）の点を、外部の crate に頼らず `crates/zumen-las/src/laz` で展開する（#510）。
  - 対象は、`Point10`・`GpsTime11`・`Rgb12`・`WavePacket13`・`Byte` の v1・v2（チャンクなしとチャンクごとの順序圧縮）と、`Point14`・`Rgb14`・`Nir14`・`WavePacket14`・`Byte14` の v3・v4（層別チャンク圧縮）、固定長と可変長（`chunk_size = 0xffff_ffff`）のチャンクである。塊の表（chunk table）の位置はファイルの先頭からのオフセットとして読む。
  - 予算と安全性: 展開後のバイト列は先に予算の `decoded-bytes` で数えてから確保する。`laszip encoded`（レコード 22204）の項目と可変長チャンクの点数表は `records` で、各点の展開は `work` で数える。層別チャンクの各レイヤは入力のスライスをそのまま借り、宣言された長さだけでは事前確保しない。算術復号器は区間（`value < length`）と表の添字を常に検査し、GPS 時刻の系列の切り替えは有界な繰り返しで解くため、壊れた入力でもパニックしない。VLR がない・合わない・展開できないときは `las.laz.invalid` を返す。
  - 決まった値: 展開は整数の算術符号と予測器だけで行い、浮動小数の計算と `HashMap` の順を使わないため、ネイティブと wasm でビット単位で同じ点レコードになる。

## 八分木

- 読むときに八分木を作る。根は全体の範囲を囲む立方体で、ノードは 1 辺を 64 に分けた格子を持ち、点を浅い段の空いた格子から順に入れる。作るのにすべての点を見るので、予算の `work` で数える。

## COPC

- COPC 1.0 は、LAZ 1.4（点の形式 6〜8、可変長のチャンク）に、八分木の情報の VLR（利用者の ID `copc`・レコードの ID 1、160 バイト）と、階層の EVLR（`copc`・1000）を足した形式である。Rust の `zumen_las::copc::read` が、範囲の入力（`zumen_sdk::ranged`）から、条件（`zumen_pointcloud::Query`）に掛かる節だけを読む（#473）。
- 読む順:
  1. 初めの 589 バイト（ヘッダーと情報の VLR）。
  2. VLR の範囲と根の頁。
  3. 条件に掛かる項が指す子の頁。浅い頁から順に読む。
  4. 条件に掛かる節のチャンク。
- 入力を全体で渡せば、1 回で読む。
- 階層の項（段・X・Y・Z・位置・大きさ・点の数）は、点の数が正なら節のチャンク、-1 なら子の頁、0 なら空の節とする。
- 節の番号は八分木の `Key` にそのまま移す。COPC の X は東、Y は北なので、領域モデルの番号（北・東・標高）では X と Y を入れ替える。
- 根の立方体は、情報の中心と辺の半分から作る。節の 1 辺を分ける数は、根の辺の長さを根の間隔（`spacing`）で割って丸めた値にする。こうすると、段ごとの点の間隔が COPC の間隔（根の間隔を段ごとに半分にしたもの）と合う。
- 節の選び方は `select` と同じにする。許容差より細かい段の節と、範囲の箱に掛からない節を読まない。そうした項が指す子の頁も読まない。
- 点の上限: 範囲の箱にすべて入る節の点で上限に届けば、その後の節を読まず、`truncated` を立てる。
- 点は、節の番号の順に、チャンクごとに LAZ を展開して並べる。座標系と属性は LAS と同じに読む。
- 次のときは `las.copc.invalid` を返して読まない。`reason` で理由を分ける。
  - LAS 1.4 でないか、情報の VLR が最初の VLR でない（`info-missing`）。
  - 点の形式が 6〜8 でない（`point-format`）。
  - 中心が有限の値でないか、辺の半分か間隔が有限の正の値でない（`info`）。
  - 頁が入力の外にある（`hierarchy-range`）。
  - 節の番号が段の外にある（`hierarchy-key`）。
  - 点の数が -1 より小さい（`hierarchy-count`）。
  - 同じ節が二度ある（`hierarchy-duplicate`）。
  - チャンクが点の範囲の外にある（`chunk-range`）。
- 同じ頁は二度読まないので、頁が自分を指しても終わる。項は予算の `records`、読むチャンクの大きさは `input-bytes`、展開は `decoded-bytes` と `work` で数える。
- 試験の入力は、lazrs 0.9.0 で節ごとにチャンクを書いた合成の COPC（`crates/zumen-las/tests/copc_make.py`）。全体を LAZ として読んだ点と同じ値になることも確かめる。

### op から読む

- `open` の `pointcloud` に条件（`region`・`tolerance`・`limit`）を渡すと、COPC を条件に掛かる節の範囲だけで読む（#899、マイナーバージョン 104 から）。`region` は北・東・標高の箱、`tolerance` は点の間隔の上限（メートル、正の値）、`limit` は点の数の上限。
- 足りない範囲は、ほかの範囲の読みと同じく `needs` に `<入力>#<始め>-<終わり>` で返す（決定 0232）。ラッパーの `openRanged`・`open_ranged` が範囲を足して同じ要求を出し直す。先頭の 589 バイト（ヘッダーと COPC の情報）がなければ、まずそれを求める。
- 開いた文書は点群（`Document::Cloud`）で、`pointcloud` の op がそのまま使える。`limit` で点を落としたら、`open` の結果の `truncated` を `true` にする。
- COPC でない入力（LAS・LAZ、点群でない形式）に条件を渡すと、`call.value.invalid`（`/pointcloud`）を返す。
- 適合テストは `bindings/conformance/cases/pointcloud_copc.json`（試験と同じ合成の COPC）。

## まだしないこと

- `scene3d` の op から COPC を範囲で読むこと。
- 実データ（5 MB 以上）での確かめ。

## 確かめた度合い

| 形式 | 向き | 段 |
| --- | --- | --- |
| `las` | 読み | `external` |

段の意味は[形式台帳の書き方](../../formats/README.md#確かめた度合い)に、根拠は[形式と権利の一覧](README.md#format-las)にあります。読みの `external` の根拠は、PDAL の 2 つの公開サンプルを laspy 2.7.0 で読んだ値との照合です。1 つは合成の 1 点の LAS 1.2（点形式 3、#804）、もう 1 つは LAZ の順序圧縮の 1065 点（LAS 1.2、点形式 3、#504）で、LAZ は lazrs 0.9.0 で展開します。ほかのバージョン・点形式、座標系・VLR と EVLR の内容・層別圧縮の LAZ・COPC と、下に挙げる未確認の範囲は、この段の根拠に含めません。

## 外部照合と実行環境の一致

手順と比較するフィールドは [LAS の外部照合](../../xtask/verify/laspy/README.md)にあります。

| 確かめ方 | 対象と範囲 |
| --- | --- |
| 公開サンプルの外部照合 | `samples/las/pdal-synthetic.las`（非圧縮 LAS 1.2、点形式 3、合成の 1 点）。ヘッダーのバージョン・点形式・レコードの長さ・点数・尺度・原点・範囲、座標・強度・分類・反射番号と反射数・GPS 時刻・RGB を照合。座標以外の属性は反射番号と反射数を除き 0 のサンプル |
| 合成入力の外部照合 | LAS 1.2 の点形式 0〜3、1.3 の 4・5、1.4 の 6〜10 を、同じフィールドで照合。各 4 点を既知値から作り、負の座標・軸ごとに違う尺度と原点・分類のフラグ・反射番号のビット幅を確認。合成入力だけでは読みを `external` に上げない |
| 範囲読み・予算 | 公開サンプルを全体と範囲で読み、L1・点群モデル・診断を比較。テストキットの契約と、入力バイト・要素・作業の予算による停止を確認。落とす属性はコアの診断を確認 |
| ネイティブ・wasm の一致 | 適合テストの `pointcloud_samples.json` が同じ公開サンプルを `open`・`pointcloud` で開き、全点を選んだ応答・診断のハッシュを比較。既存の `pointcloud.json` は合成入力の範囲読みと LAZ の展開も比較 |

外部の実装との照合はネイティブの Rust テストで行います。座標系の解釈・VLR と EVLR の内容・落とした属性の値・波形の外部データ・GPS 時刻の時刻系の換算は、外部の実装とは照合していません。LAS 1.0・1.1 と、LAS 1.4 の旧点形式、層別圧縮（v3/v4）の LAZ と COPC の公開サンプル、5 MB 超の実データ、基準になるアプリで開くことも未確認です。受け取った図面は使っていません。残る確認は #371・#504 で追います。

公開サンプルは、PDAL のテスト用に作られたものに絞りました。laz-rs の `tests/data` の LAS も調べましたが、コードの Apache-2.0 の表示のほかに、実測の原データの来歴と再配布条件を確認できなかったため、採用していません（2026-11-11、#804）。

- LAZ は、`lazrs` が圧縮した全点形式（0〜10、固定長・可変長チャンク、追加バイト・波形・RGB・近赤外・スキャナーチャネル・GPS 時刻の系列切り替え）を展開して元の非圧縮 LAS のバイト列と一致することと、#510 の壊れた入力でパニックせず `las.laz.invalid` を返すことを、単体テスト（`crates/zumen-las/tests/read.rs`）で確かめた。

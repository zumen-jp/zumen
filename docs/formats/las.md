# LAS・LAZ

LAS 1.0〜1.4 と LAZ（台帳の `las_1_4_r15`・`laz_1_4`）の点群を読み、点群の領域モデルに移す規則を記録します。LAZ は、いまは展開を止めています（下の「LAZ」）。実装は `crates/zumen-las`、領域モデルは `crates/zumen-pointcloud` です。仕様の本文は写しません（`formats/ledger.toml`）。

## API

- `open` は、入力の初めの `LASF` で見分ける。`size` に全体の大きさを書けば、入力を全体の初めの部分とみなし、足りない範囲を `needs` で求める。ホストは、範囲を `<入力の名前>#<start>-<end>` の名前で `zm_push` してから、同じ `open` をもう一度呼ぶ。読み終えると、使った範囲の入力を `done` で返す。
- 1 回目はヘッダー（375 バイトまで）を、2 回目は VLR・点のレコード・EVLR の範囲を求める。全体を渡せば、1 回で読む。
- `pointcloud` の op は、点の数・範囲・座標系・持つ属性・八分木の深さとノードの数を返す。`limit` を書けば、`region`（北・東・標高の箱）と `tolerance`（点の間隔）に合う点を、八分木の浅い段のノードから `limit` 個まで返す。
- 書き出しはしない。

## ヘッダーと VLR

- ヘッダーは、バージョン・点の形式と長さ・点の数・倍率とずれ・範囲を読む。1.4 は、64 ビットの点の数と EVLR の位置を読む。点の形式の上の 2 ビットが立てば LAZ とし、VLR と点の範囲を求めずに `las.laz.unsupported` を返して止まる（下の「LAZ」）。
- 上の 2 ビットのうち、LAZ 1.4（OGC 24-070r1）の 6.2・6.3 が LAZ のフラグと定めるのは、ビット 7（128）だけである。ビット 6（64）も LAZ のフラグとするのは推定で、LASzip（Apache-2.0）の読み方に合わせた（#544）。
  - LASzip（[`src/laszip_dll.cpp`](https://github.com/LASzip/LASzip/blob/a446a0c01362ed1c642928cff30416217f0468c3/src/laszip_dll.cpp) の `laszip_read_header`）は、点の形式のビット 7 かビット 6 が立てば、LASzip の VLR を求め、なければ「実験版の LASzip で圧縮したファイル」として断る。VLR があれば、ビット 7 だけを落として読む。圧縮して読むかは、ビットではなく、LASzip の VLR があるかで決める。
  - laz-rs 0.13.0（Apache-2.0、`src/las/file.rs`）は、圧縮をビット 7 だけで見分け、点の形式は下の 6 ビット（`& 0x3f`）にする。
  - zumen は、点の形式を下の 6 ビットにする所は laz-rs と同じにする。いまは、ビット 6 かビット 7 が立てば、LASzip の VLR を見ずに `las.laz.unsupported` で断る。展開を戻したら、ビット 6 かビット 7 が立つのに LASzip の VLR がないファイルを断る所（`las.laz.invalid` の `laszip-vlr-missing`）は、LASzip と同じになる。LASzip の VLR があってビットが立たないファイルは、LASzip は圧縮したものとして読み、zumen は LAS として読む。ビット 6 だけが立つファイルを LAS として読むと、点の形式が 64 以上になり、点のレコードを読み違えるので、ビット 7 だけを見るようには直さない。
- VLR と EVLR は、利用者の ID・レコードの ID・説明・中身を持ち、L1 のレコードにする。範囲から外れるレコードの残りは読まず、`las.vlr.invalid` を返す。
- 点のレコードが、ヘッダーの点の数より短ければ、読めた点だけを読んで `las.points.invalid` を返す。

## 点

- X を東（`easting`）、Y を北（`northing`）、Z を標高にし、倍率とずれを当てて f64 にする。
- 強度・分類・反射の番号と数は、どの形式でも持つ。形式 0〜5 は分類を下の 5 ビットで、形式 6〜10 は 1 バイトで読む。時刻は、時刻を持つ形式（1・3〜10）だけが持つ。色は、色を持つ形式（2・3・5・7・8・10）だけが持つ。
- 走査の角度・利用者のデータ・点の出所・フラグのビット・近赤外・波形・追加のバイトは移さず、属性ごとに `las.attribute.dropped` を返す。

## 座標系

- 全体の符号化の WKT のフラグが立てば WKT のレコード（`LASF_Projection` の 2112）、なければ GeoTIFF のキーのレコード（34735）を読む。
- WKT は `AUTHORITY["EPSG",…]`（WKT1）と `ID["EPSG",…]`（WKT2）のコードを読み、高さの座標系（`VERT_CS`・`VERTCRS`）の中のコードを高さの座標系にする。
- GeoTIFF のキーは、投影の座標系（3072）・経緯度の座標系（2048）・高さの座標系（4096）の、キーの中に値があるものを読む。
- 平面直角座標系（JGD2011、EPSG:6669〜6687）だけを水平の座標系にする。点は地図の空間に置くので、経緯度の座標系とほかの座標系は `las.crs.unsupported` を返して不明にする。座標系のレコードがなければ `las.crs.missing` を返す。高さは JGD2011・JGD2024 の標高（6695・11317）だけを受け、ほかは `las.vertical-crs.unsupported` を返す。

## LAZ

- 展開を止めている。展開を任せていた `laz` crate 0.13.0 が壊れた入力でパニックし、直した版がまだ crates.io にないためである（#510）。`laz` は依存から外した。
- laz の直した版が出たら、パッチのリリースで展開を戻す（#510）。戻すときは、0.2.0 の前と同じく、次の扱いにする。
  - LAZ の点は、`laz` crate（Apache-2.0）で展開する。展開したバイトは、先に予算の `decoded-bytes` で数えてから確保する。塊の表の位置はファイルの初めからなので、点のレコードの始まりからずらして読む。
  - 権利: `laz` は Apache-2.0 で、依存の `byteorder`・`num-traits` も MIT・Apache-2.0 にできる（`cargo deny`）。並列の展開（`rayon`）の機能は使わない。`about.toml` に、`laz` のライセンスの補いを足し直す。
  - wasm: 入出力は `std::io` の `Read`・`Seek` だけで、wasm で動く。
  - 決まった値: 展開は整数の算術符号で、浮動小数の計算と HashMap の順を使わない。

## 八分木

- 読むときに八分木を作る。根は全体の範囲を囲む立方体で、ノードは 1 辺を 64 に分けた格子を持ち、点を浅い段の空いた格子から順に入れる。作るのにすべての点を見るので、予算の `work` で数える。

## まだしないこと

- COPC の階層をそのままノードにすること、ホストの言語のラッパーで `needs` に答えること、3D のシーン（`ZMS3`）の点のセクションで返すこと。
- 点群のモジュール（`pointcloud`、#380）。いまは図面のモジュールに入れる。
- 実データ（5 MB 以上）での確かめ。

# ボーリング交換用データ（BED）

地質・土質調査の成果のボーリング交換用データ（BED0500.DTD の XML）を読む規則を記録します（#390）。実装は `crates/zumen-geology` です。API では、`boring` の op に入力の名前を渡し、ボーリング 1 本の位置・標高と、深さごとの記録を返します。要素の名前は、要領の付属資料の構造図によります。DTD と記入例は同梱も転載もしません（`formats/ledger.toml` の `boring`）。

## 判定

- `zumen-xml` で読む。UTF-8・Shift_JIS・UTF-16 を [XML の規則](xml.md)で受け付ける。DTD は処理しないので、`xml.dtd.dropped` は返さない。
- 日本語の要素名は Unicode で比べる。Shift_JIS の `ボーリング情報` とその子も、UTF-8 と同じ値へ読む。
- XML として読めないか、根の要素が `ボーリング情報` でなければ、`boring.file.invalid` を返して失敗する。

## 読む要素

- 基礎情報: 適用規格（複数）、公開フラグのコード。
- 標題情報: 事業工事名・調査名・ボーリング名・ボーリング総数・ボーリング連番、経度・緯度（度・分・秒）と測地系のコード、調査位置の住所、調査期間の始まりと終わりの日、孔口標高・総削孔長・角度・方位。
- コア情報: 工学的地質区分名・現場土質名（下端の深さ・名前・記号）、色調（下端の深さ・名前）、観察記事（上端と下端の深さ・記事）、標準貫入試験（開始の深さ・合計の打撃回数・合計の貫入量）、孔内水位（測定の日・削孔状況のコード・水位・水位種別と備考）。
- 深さは地表からの m（GL.-m）。記録は文書の順で返し、並べ替えない。孔内水位が空なら、水位を返さない。

## 位置と標高

- 経度・緯度は、度・分・秒を、度に分の 60 分の 1 と秒の 3600 分の 1 を足した値にする。度・分・秒のどれかがなければ、位置を返さない。
- 測地系のコードは、00 を `tokyo`、01 を `jgd2000`、02 を `jgd2011`、03 を `jgd2024` にする。換算はしない。ほかのコードは `boring.value.invalid` を返し、測地系を返さない。
- 孔口標高は、東京湾平均海面（`tokyo_bay`）からの標高とする。成果は、測地系が `jgd2024` なら `survey_2024`。そうでなければ、調査の終わりの日（なければ始まりの日）が 2025-04-01 以後なら `survey_2024`、前なら `survey_2011` と仮定し、`crs.height-realization.assumed` を返す。

## 読まない要素

- ほかの試験（ルジオン試験・孔内載荷試験・透水試験・検層など）、判定表と区分、試料採取、削孔の記録、コアの記録、調査会社などは、要素の名前ごとに `boring.element.unsupported` を返す。
- 調査会社の技術者の名前と登録番号は、返さない。

## 値

- 文字は前後の空白を除き、空なら返さない。
- 数として読めない値は、`boring.value.invalid`（要素の名前と値）を返して飛ばす。区間の深さか名前が読めなければ、その記録を返さない。

## 上限

- 入力の大きさを `InputBytes`、根とコア情報の子の要素の数を `Records` で数える。

## 確かめた度合い

自作の UTF-16LE・UTF-16BE で、日本語の根の要素・地層の値と診断の要素名を検査します。[XML の規則](xml.md)を使います。この追加の確認は `synthetic` で、ボーリング交換用データの外部照合はしていません。

自作の Shift_JIS（`Shift_JIS`・`windows-31j`・`ms932`）で、UTF-8 とボーリングの全値・診断が一致することを検査します。[API の適合テスト](../../bindings/conformance/cases/xml_shift_jis.json)でも位置・標高・地層・貫入試験・孔内水位を比較します。この確認も `synthetic` です。

| 形式 | 向き | 段 |
| --- | --- | --- |
| `boring` | 読み | `synthetic` |

段の意味は[形式台帳の書き方](../../formats/README.md#確かめた度合い)に、根拠は[形式と権利の一覧](README.md#format-boring)にあります。この文書の規則は、仕様と、テストの中で作ったファイルだけで確かめたものです。公開サンプル・受け取った図面・外部の実装・基準になるソフトとは、まだ照らしていません。実際のファイルでは、ここに書いた扱いと違うことがあります。

- 要領が配る DTD での検証と、KuniJiban の柱状図との照合は #505 で行う。

# DXF

AutoCAD の系統のファイルモデル（L1）として DXF を読み書きする規則と、仕様が決めない所の扱いを記録します。実装は `crates/zumen-acad` の `dxf` です。旧版の知見（[旧版の DXF の扱い](https://github.com/zumen-jp/zumen-legacy/blob/main/docs/formats/dxf.md)）は、扱う範囲を広げるときに移します。

## 対象

- ASCII の DXF。バージョンは問わず、タグの並びとして読む。
- バイナリの DXF（DXF Reference「Binary DXF Files」）。先頭のセンチネルで見分け、各タグを ASCII の DXF の表現にしてから、ASCII の DXF と同じに扱う（[バイナリの DXF](#バイナリの-dxf)）。

## バイナリの DXF

- 先頭の 22 バイト `AutoCAD Binary DXF` CR LF SUB NUL の後に、グループ・コードと値の組が続く。数はリトル・エンディアン。
- グループ・コードの幅は、最初のタグ（`0 SECTION`）で決める。センチネルの後が NUL・NUL・`S` なら 2 バイトの符号つき整数（R13 から）、NUL・`S` なら 1 バイト（R12）。1 バイトのとき、255 は続く 2 バイトがグループ・コードであることを表す（推定）。
- 値のバイト列は、グループ・コードの型（DXF Reference「Group Code Value Types」）で決める。文字列とハンドルは NUL で終わるバイト列、実数は 8 バイト、整数は 60〜79・170〜179・270〜289・370〜389・400〜409・1060〜1070 が 2 バイト、90〜99・420〜429・440〜459・1071 が 4 バイト、160〜169 が 8 バイト、真偽（290〜299）は 1 バイト、バイナリ（310〜319・1004）は長さの 1 バイトとその長さのバイト列。整数の幅の割り当てと、280〜289 を 2 バイトとすることは推定。サンプルの R12・2000・2004・2007・2010・2013・2018 のバイナリの DXF で、どのタグも途中で切れずに末尾ちょうどで終わることを確かめた。
- ASCII の表現は、グループ・コードを 3 桁に右寄せした行と値の行で、改行は LF。実数は読み直すと同じ値に戻る最短の 10 進の表記、整数と真偽は 10 進、バイナリは大文字の 16 進。文字列の制御文字は、同じ図面の ASCII の DXF と同じく `^J` のように `^` と文字で書き、`^` 自身は `^ ` と書く（推定。サンプルの MTEXT の改行で確かめた）。
- レコードの範囲（`RecordInfo` のバイト範囲）は、元のバイナリのバイト範囲。
- 途中で切れたタグと、有限でない実数の値は、`dxf.binary.invalid` を返し、読まない。
- 書くときは、変えていないレコードの元のバイトを並べ、変えたレコードのタグを元と同じ幅のグループ・コードで符号化し直す。どのレコードも同じ値で書き換えたものとして符号化し直すと、サンプルのすべてのバージョンで元のバイト列と一致する。
- 変更の値は、変更のときにグループ・コードの型のバイト列にできるかを確かめ、できなければ `dxf.binary-value.unsupported` を返す（数でない数の値、型の幅を超える整数、奇数の桁や 255 バイトを超えるバイナリ、NUL を含む文字列、読みが作らない `^` の並び）。
- 同じ図面のバイナリと ASCII の DXF の組（サンプルの 7 つのバージョン）で、図面モデルと出る診断の種類が一致することを確かめた。数は相対の誤差 1e-9 の中で一致する。R12 の組は、ASCII の DXF がポリラインの頂点を 6 桁に丸めて書くので、1e-5 の中で一致する。
- まだ扱わないもの: バイナリの DXF のバージョンの変更（`dxf.version.unsupported`）、ASCII の DXF との相互の変換。

## レコードの区切り

- グループ・コードの行と値の行の組を、タグとして読む（DXF Reference「About ASCII DXF Files」）。
- グループ・コード 0 のタグから、次のグループ・コード 0 のタグの前までを、1 つのレコードにする。`SECTION`・`ENDSEC`・未知の種類も同じに扱う。
- 先頭がグループ・コード 0 でないタグ（コメントの 999 など）は、最初のレコードにまとめる。
- 値が `EOF` のグループ・コード 0 のタグで読むのをやめる。その後のバイトは、読まずにそのまま持つ。
- レコードは、改行も含めた元のバイト範囲を持ち、隣のレコードと隙間なく並ぶ。変えずに書くと、元のバイト列と一致する。

## 編集

- 変更は `DxfTxn` にためて、確定のときにまとめて反映する。1 つでも受け付けない変更があるか、予算で止まったら、何も反映しない。確定しないで捨てても、何も反映しない。
- 生の値は、レコードとタグの位置で名指しして置き換える。型付きの値は、グループ・コードで名指しする（今は実数だけ）。
- レコードとタグは、位置で名指しして足し、除ける（`insert_record`・`remove_record`・`insert_tag`・`remove_tag`）。レコードの位置は、確定するまで元のファイルの位置で名指しする。足したレコードには、確定するまで値の変更もタグの追加もできない。除いたレコードは、同じトランザクションでは名指しできない。
- `SECTION`・`ENDSEC`・`EOF` のレコードは、足すことも除くこともできない（`dxf.record.unsafe`）。セクションの区切りが変わるため。足すレコードは、最初のタグがグループ・コード 0 で、ほかは 0 以外でなければならない。レコードの先頭のタグは除けない。
- `new_handle` は、ヘッダーの `$HANDSEED`（DXF Reference「HEADER Section Group Codes」）の値を新しいハンドルとして返し、`$HANDSEED` を 1 つ進める。足すレコードのハンドル（5）は、これで決めて呼び出し側が渡す。`$HANDSEED` がないか読めなければ `dxf.handle-seed.missing` を返す。
- 改行を含む値と、グループ・コード 0 の値の変更は受け付けない。読み直すと、タグとレコードの区切りが変わるため。
- 反映したレコードは、元のバイト範囲を持たなくなる。書くときは、そのレコードのタグを並べ直す。グループ・コードの行と改行は元のバイトを使い、値だけを差し替える。変えていないレコードは、元のバイトのまま書く。
- 共有のオブジェクトの表の変更は、`DxfFile::write_back` で書き戻す。今のファイルから作り直した表と元のレコードごとに比べ、値の並びが違うレコードだけを 1 つのトランザクションで直す。前と後ろの同じ値は元のタグのまま残し、間の値は、グループ・コードの並びが同じなら値だけを差し替え、違えばタグを除いて足し直す。ヘッダーの変数も名前ごとに比べ、ファイルにない変数は HEADER の最後に足す。表から除いたオブジェクトのレコードは除き、表に足したオブジェクト（`Origin::New`）は、同じ所の後ろで最初の残したオブジェクトの前に、なければその所の ENDSEC の前に足す。表のハンドルのどれかが `$HANDSEED` 以上なら、`$HANDSEED` を最大のハンドルの次に進める。値を変えたか足したモデル空間の図形が `$EXTMIN`・`$EXTMAX`（DXF Reference「HEADER Section Group Codes」）の外にあれば、図形を含むように範囲を広げる。変数の削除はまだ扱わない。この DXF の同じ種類・同じ所のレコードから読んでいないオブジェクト、同じレコードから読んだ 2 つ目のオブジェクト、ファイルにない所に足したオブジェクトは `dxf.object.unsupported` を返す。
- 図面モデルの変更（`zumen_drawing::Changes`）は、`Apply` の `apply` で書き戻す。変更は、要素を ID と読んだときの要素のハッシュで指し、あれば読んだときの文書のハッシュを持つ。今のファイルから表と図面モデルを作り、ID から要素を引いて、変更が指す図形に当ててから `write_back` で書く。記号の定義の中の要素は、BLOCK のハンドルで作る定義の空間の ID（`space/h1F/h2A`）で指し、BLOCKS の中の図形に当てる。名前のある定義の空間には要素を足せる。DWG も同じ当て方を使う。今は、実寸の空間と用紙の次の形の置き換え（`Edit::Replace`）と、続くレコード（VERTEX・ATTRIB・SEQEND）を持たない図形の除去（`Edit::Remove`）と、スタイルの変更（`Edit::Restyle`）と、アフィン変換での移動（`Edit::Transform`）と、追加（`Edit::Add`）を扱う。用紙の要素は、用紙の ID で指して置き換え、用紙の mm を、読むときと逆に、図面の単位に戻して用紙の原点を足して書く。ほかのレイアウトの用紙の図形は、BLOCKS のペーパー空間のブロックの中にあり、そこで直す。変えていない点は、元の値を写す（戻した値が最後の桁で違うことがあるため）。
  - LINE の端点（10・20・11・21）、CIRCLE の中心と半径（10・20・40）。
  - ARC の中心・半径・角度（10・20・40・50・51）。時計回りの弧は、始まりと終わりを入れ替えて反時計回りで書く。
  - ELLIPSE の中心・長軸の端・比・パラメーター（10・20・11・21・40・41・42）。比は 0 より大きく 1 以下に限る。読むときに度へ直したパラメーターと長軸の端は、変わったときだけ書き、変えていないフィールドの最後の桁を変えない。
  - LWPOLYLINE の頂点・膨らみ・閉じていること・幅（90・70 の 1・43・10・20・40・41・42）。頂点の前と後の値は写し、頂点のフィールドを並べ直す。膨らみは 0 でないものだけ、頂点ごとの幅は図面モデルが持つときだけ書く。頂点の ID（91）を持つのに頂点の数が変わるもの、頂点の間にほかの値があるもの、一定の幅と頂点ごとの幅の両方を持つものは扱わない。
  - TEXT の内容・高さ・回転・幅の倍率・斜体の角度・反転・置く点（1・40・50・41・51・71 の 2 と 4・10・20・11・21）。位置合わせ（72・73）、2 点の間への合わせ方、文字スタイル、高さの意味は変えられない。左の基準線に置く文字は 10 を、ほかの位置合わせの文字は 11 を動かし、10 も同じだけ動かす（10 は位置合わせから決まる点で、ほかのソフトが読むため）。2007 より前のバージョンには、ヘッダーのコード・ページで符号化して書く。改行は書かない。省いた回転・幅の倍率・斜体の角度・反転は、既定の値でないときだけ足す。
  - MTEXT の内容・置く点・高さ・回転・枠の幅と高さ・置き方・行の間隔（1・3・10・20・40・50 または 11・21・41・46・71・73・44）。内容は 250 バイトごとに文字の途中と `^` の表記の途中で切らずに 3 へ分け、残りを 1 に書く。2007 より前のバージョンは、コード・ページで符号化したバイトで数え、2 バイトの文字の途中で切らない。改行は書かない（改行は `\P` で書く）。区間（`spans`）は内容から決まるので、内容を読んで得る区間と違うものは扱わない。回転は、角度（50）と向き（11・21）のうち元と同じ持ち方でだけ変えられる。向きを変えるときは、角度（50）が残っていれば除く。行の間隔の倍率（44）は 0.25〜4 に限る。文字スタイル・流れの向き・背景・高さの意味は変えられない。
  - INSERT の置く点・尺度・回転（10・20・41・42・50）。省いた尺度と回転は、既定の値（1 と 0）でないときだけ足す。格子の間隔（44・45）も、変わったときだけ書く（変換で負になることもある）。定義（2）・格子の有無と列と行の数（70・71）・切り抜きは変えられない。属性は、値だけを変えられる。値を変えた属性は、続く ATTRIB の値（1）を書き直し、ほかのフィールドは変えない。書式つきの値（複数行の属性）を持つ属性の値は変えられない。属性を持つ INSERT も置き換えられるが、続く ATTRIB は動かさない（図面モデルの属性は、それぞれの置く点を持つ）。DWG は回転をラジアンで持つので、読み直した値（度）が最後の桁で違うことがある。
  - LEADER の経路・スプラインか・矢印（10・20・30・76・72・71）。経路が変われば頂点を並べ直し、Z は 0 で書く。寸法スタイル（3）と注記（340）は変えられない。DWG は R2010 以降も置き換え、矢印（71）を書く。DWG は矢印のフラグを必ず持つので、矢印を寸法スタイルに従わせる引出線は書かない。`Edit::Transform` は経路を写し、X 軸の向き（211）を同じ変換で直す。曲線の引出線は相似の変換だけを受ける。
  - MULTILEADER の枝の線の頂点（`LEADER_LINE{` の中の 10・20・30）・集まる点（`LEADER{` の中の 10・20）・折れ曲がりの向きと長さ（11・21・40）。ほかのフィールド（注記・線の引き方・端部記号・大きさ・色・スタイル）と、枝と線の数、集まる点と折れ曲がりの有無は変えられない。切れ目（線の 11・12、枝の 12・13）を持つ線か枝は変えない。DWG の MULTILEADER と追加は、まだ書き戻さない。
  - POINT の位置と X 軸の角度（10・20・50）。角度は、省けば 0 なので、0 でないときだけ足す。見え方は文書の点の表し方（`$PDMODE`・`$PDSIZE`）が決めるので、既定義のマーカーの点と作図の補助の点にはできない。文書の点の表し方の変更（`Edit::SetPointStyle`）は、ヘッダーの `$PDMODE`（70）と `$PDSIZE`（40）に書く。形は 0〜4 に、円で囲むなら 32、四角で囲むなら 64 を足し、大きさは長さなら正、画面の高さに対する百分率なら負の値にする。読んで同じ意味になる変数は書き直さず、変数がなければ足す。大きさが正で有限でないものは断る。
  - 置き換えた図形の XDATA と拡張辞書は、元のまま書き戻す。形を変える置き換えで、元の図形が図形とともに動く XDATA（1011〜1013・1041・1042）を持てば、変更をすべて反映せず `change.xdata.unsupported` を返す。
  - 当てる前に、すべての変更を確かめる。文書のハッシュが今のファイルを書いたバイト列のハッシュと違えば `change.document.stale`、ID の要素か足す先の空間・用紙がなければ `change.element.missing`、要素のハッシュが今と違えば `change.element.stale`、扱えない変更は `change.edit.unsupported`（変更の種類・要素の種類・形式を値に持つ）を返し、何も反映しない。最初の 1 つで止めない。変えていないファイルは元のバイトのまま書くので、文書のハッシュは読んだバイト列（バイナリの DXF も）のハッシュと同じになる。
  - `Edit::Restyle` は、レイヤ・色・線種・線種の倍率・線幅のうち、指したフィールドだけを変える。形は変えない。変わったフィールドの値（8・6・62 と 420 と 430・370・48）だけを、図形に共通の値（サブクラスマーカーを持てば AcDbEntity のサブクラスの中、持たなければ XDATA の前）から除き、追加と同じ書き方でレイヤ（8）の後に書く。ほかの値と XDATA は元のまま写す。レイヤと線種は表の定義を引いて定義の名前で書き、定義がなければ当てない。線幅は R2000 から、RGB の色は R2004 からの DXF に限る。DWG も、今ある図形のレイヤ・色・線種・線種の倍率・線幅を書き戻す。画層と線種はハンドルのストリームのハンドル（固い参照）で、線種の種類は共通のデータの BB（ByLayer 0・ByBlock 1・Continuous 2・ハンドル 3）で、線幅は共通のデータの RC で書く。RGB の色は R2004 からの ENC（フラグ 0x8000 と、上位のバイトが 0xC2 の BL）で書き、透明度は元のまま写す。DBCOLOR を指す色を持つ図形の色と、MULTILEADER の画層と線種は変えない。属性を持つ INSERT のスタイルを変えても、続く ATTRIB のスタイルは変えない。
  - `Edit::Transform` は、要素の形をアフィン変換で写し（`zumen_drawing::transform`）、置き換えと同じ書き方で書く。LINE と、膨らみと幅を持たない LWPOLYLINE は、どの変換（向きがつぶれないもの）でも写す。CIRCLE・ARC・ELLIPSE と、膨らみか幅を持つ LWPOLYLINE は、相似（等方の尺度・回転・鏡映・平行移動）でだけ写す。鏡映は、角度とたどる向き・膨らみの符号を逆にする。TEXT と INSERT と POINT は相似で写す。鏡映は、TEXT と ATTRIB では上下の反転のフラグ（71 の 4）を入れ替え、INSERT では Y の尺度（42）の符号を変え、回転を φ − θ にして表す。反転は、斜体と幅の倍率を当てた字形に、文字の基点のまわりで当てるものとして扱い、斜体の角度（51）は変えない（推定）。MTEXT は反転のフラグを持たないので、鏡映を含まない相似でだけ写し、MTEXT の属性を持つ INSERT も鏡映しない。格子の間隔（44・45）には尺度を掛け、鏡映では、記号の Y の向きに並ぶ行の間隔（45）の符号を変える。それ以外の変換は `change.edit.unsupported` にする。R2004 から後の DWG の MINSERT は、持つオブジェクトの数を列と行のフィールドの前に読み書きして書き戻す。決定時は AutoCAD で作った MINSERT のサンプルがなかったため、足した MINSERT を変換して確かめた。
    - 図形とともに動く XDATA は、AutoCAD と同じ規則で直す。位置（1011・1021）は変換で写し、変位（1012・1022）は平行移動を除いて写し、向き（1013・1023）は写してから元の長さにそろえる。距離（1041）と倍率（1042）は尺度を掛けるので、相似でない変換では当てない。用紙の図形の XDATA は、用紙の mm と図面の単位の違いを直せないので、動く XDATA を持つ用紙の図形は当てない。
    - 属性を持つ INSERT は、続く ATTRIB の置く点・高さ・回転も同じ変換で直す。MTEXT の形の属性を持つ INSERT は当てない。
  - 置き換えは、レイヤ・色・線種・線幅・透過性が元の要素と同じときだけ当てる。スタイルを変えるときは `Edit::Restyle` を使う。2 つ以上の要素を作ったレコードの要素（ID の終わりに `/1` などを持つものと、その最初の要素）は、置き換えも除去もしない。

  - 当てたら、書き戻した表から図面モデルを作り直し、変更ごとに新しい ID とハッシュを返す。置き換えた要素の ID は変わらず、足した要素の ID は振ったハンドル（`space/0/h20` など）で作るので、書き戻したファイルを読み直したときと同じになる。除いた要素と、ハンドルを持たない要素（読み直すと ID がずれうる）は、ID を返さない。ハンドルを持たない要素の ID はレコードの番号で決まるので、前の要素か、ENTITIES より前の表のレコードを除くか足すと、変えていない要素の ID もずれる。そのとき `apply` は `ids_shifted` を返す（#722）。ハンドルを持たない要素の ID を図面の順に並べ、`apply` の前の並びから除いた要素を抜いたものが、後の並びの頭と違えば、ずれたとする（変えた要素も含む）。動かす・スタイルを変える・終わりの要素を除く・表のレコードの値を変えるだけなら、ずれない。ずれないときも、変えた要素の ID とハッシュは返さない。置き換えで要素のレコードの数が変わると、その要素より後ろの番号が変わり、変えた要素どうしの位置は、読み直さないと決められないため。`entities` で読み直して得る。
  - `Edit::Add` は、足す先を空間か用紙の ID で指す。実寸の空間の要素はモデル空間（`space/0`）の新しい図形として、用紙の要素は足す先の用紙のほかの図形と同じ所（今のレイアウトは ENTITIES の所でペーパー空間のフラグ 67 = 1 を付け、ほかのレイアウトはペーパー空間のブロックの ENDBLK の前）に足す。図形を持たない用紙には、その LAYOUT のブロックのレコードを所有者として、今のレイアウトなら ENTITIES の所に、ほかのレイアウトならそのペーパー空間のブロックに足し、読み直すと用紙の ID が変わる。図面の単位が分からない用紙には足さない。足せる形は、LINE・CIRCLE・ARC・ELLIPSE・LWPOLYLINE・TEXT（高さの意味が TEXT の高さのもの）・MTEXT（高さの意味が MTEXT の高さで、背景を持たず、区間が内容と合うもの）・INSERT（名前のあるブロックを置き、切り抜きを持たないもの。格子を持てば、列と行の数（70・71）と間隔（44・45）を書き、DWG では MINSERT になる。属性は、1 行の値で高さの意味が属性の高さのものを、所有者を INSERT とする ATTRIB と SEQEND として続ける）。要素の出所は使わない。ハンドルは、表のどのハンドルよりも大きく HANDSEED より小さくない値から順に付け、モデル空間の所有者を `*Model_Space` にし、用紙の所有者を追加先の用紙のブロックにする。R13 以降の DXF には、最初の図形にもサブクラスマーカー（100）を書く。レイヤ・線種・文字スタイル・ブロックは、大文字と小文字を区別せずに表の定義を引いて定義の名前で書き、定義がなければ足さない。色は ACI を 62、RGB を 420（R2004 から）、線幅を 370（R2000 から）に書く。DWG には、線幅と RGB の色を持つ要素をまだ足さない。透過性はまだ書かないので、レイヤから継承する要素だけを足す。TEXT の位置合わせが左の基準線でなければ、置く点を 11 と 10 に書く。MTEXT の向きは、DXF には元の形（50 か 11・21）で、DWG には 11・21 の向きで書き（0 でない角度の MTEXT は DWG に足さない）、R2010 からの DWG には枠の高さ（46）を必ず書く。バージョンが分かる DXF への ELLIPSE・MTEXT の追加は R13 以降、LWPOLYLINE は R14 以降に限り、ブロックは BLOCK_RECORD の表がなくても定義の存在を確かめる。ATTRIB・SEQEND を含むハンドルと次の HANDSEED を増やせないときも、何も反映しない。文書の点の表し方に従う点は、POINT として足し、0 でない角度を 50 に書く。R13 以降の DXF と DWG には LEADER も足せる。注記は同じ空間か用紙（定義の中なら同じ定義）の MTEXT だけを指し、73 = 0 とその MTEXT の高さと幅（40・41）と 340 を書く。注記がなければ 73 = 3 とする。注記の MTEXT のリアクター（330）は書かない。DWG に足す LEADER は矢印のフラグを必ず書くので、矢印を寸法スタイルに従わせる引出線は足さない。足す先が記号の定義の空間なら、所有者をその BLOCK_RECORD にし、DXF では ENDBLK の前に、DWG ではブロックの図形の列に足す。名のない定義・外部参照の定義・BLOCK_RECORD のない定義には足さない。定義の中に INSERT を足すときは、足す記号の定義から中の INSERT をたどり（同じ変更の一覧で先に足したものを含む）、足す先の定義に着けば `change.symbol-cycle.invalid` で断る。
- 型付きのビューは、共有のオブジェクトの表の上にある（`Object::line`）。今は LINE（DXF Reference「LINE」）だけ。値を読めないときは、グループ・コードとともに理由を返す。DWG の表にも同じビューを使う。
- `AcadDb::remove` で除いたオブジェクトへの参照のうち、DICTIONARY の項目（3 と次の 350・360）と、102 の組（`{ACAD_REACTORS` など）の中の 330・360 は、ほかのオブジェクトからも除く（DXF Reference「Common Group Codes for Objects」「DICTIONARY」）。参照を除いて空になった組は、組ごと除く。書き戻すと、直したオブジェクトのレコードも直る。
- まだ扱わないもの: ほかの変更に伴って直すもの（範囲を狭めること、用紙空間の範囲 `$PEXTMIN`・`$PEXTMAX`、組の外の所有者の参照 330 と、所有していたオブジェクトをまとめて除くこと、ブロックのレコードなど）、型付きのビューを広げること。

## 新しい DXF への変換

`convert` は、図面モデルを新しい R2004 の DXF（AC1018）に書きます。ひな形は `zumen-acad` の `NewDxfTemplate`（`drawing` の feature）が作り、表の項目と要素を `apply` で足します。

図面モデルから書く処理は `zumen-acad` の `lower_to_dxf_with` にあり、`convert` と `civil_drawing` も、Rust から直接呼ぶ `lower_to_dxf` も、これを使います（#643）。違いは要素の形を書く先に移す方法だけです。API の経路は形を API の形の値（`add` が受けるもの）に写してから戻し、`lower_to_dxf` は値を変えずに点と長さの空間・用紙を移します。API の形の値は文字の位置合わせを持たないので、API の経路では文字が左・ベースラインになり、幅の係数・斜体の角度・裏返しも既定の値になります。この既存の損失と診断は #763 で扱います。 API の記号は、名前空間と格子間隔の座標の系を確かめ、部品の参照を引き、最後に尺度や格子の個数も含む形を戻します。最初の検査で拒む場合は `symbol`、書かない定義や欠けた参照なら形を戻せなくても `external_symbol` として報告し、従来の診断の種類を保ちます。`Relocate` の受理の検査は、Rust の既定ではすべて通します。

- ひな形の TABLE はハンドル（5）と `AcDbSymbolTable`、表の項目は所有者（330）と `AcDbSymbolTableRecord`・種類ごとのサブクラス（100）を持つ。DIMSTYLE のハンドルは 105 に書く（DXF Reference「TABLES Section」「Common Group Codes for Symbol Table Entries」）。BLOCK・ENDBLK と足した図形の所有者は、対応する BLOCK_RECORD にする。これにより、記号の定義の中身も足せる。表の項目を足した後で、各 TABLE の件数（70）を実際の項目数に直す（DXF Reference「Symbol Table Group Codes」）。
- OBJECTS にルートの DICTIONARY、`ACAD_LAYOUT` の辞書、モデルと用紙の LAYOUT を書く。LAYOUT と BLOCK_RECORD は互いを指す。用紙は最初の 1 枚を `Layout1` にし、入力に用紙がなくても空の `Layout1` を持つ。空の LAYOUT を追加先に使うので、用紙を作るための一時的な POINT は置かない（DXF Reference「DICTIONARY」「LAYOUT」「BLOCK_RECORD」）。
- 用紙の座標と限界は最初の実寸の空間の単位で書き、LAYOUT の印刷の単位を mm、印刷の尺度を 1 図面単位の mm とする。実寸の空間がなければ mm とする。VIEWPORT は `AcDbEntity`・`AcDbViewport` と、用紙の BLOCK_RECORD を指す所有者を持つ。`$HANDSEED` は、VIEWPORT を含むすべてのハンドルより大きくする（DXF Reference「PLOTSETTINGS」「VIEWPORT」「HEADER Section Group Codes」）。
- 文字のコード・ページは ANSI_932 とする。ひな形の記号名にも、書き戻しで使う `encoding_rs` の同じ表を使う。この依存は既存採用済みで、ライセンスは `(Apache-2.0 OR MIT) AND BSD-3-Clause`。OS やロケールに依らず、wasm でも同じ表で符号化する。記号名に使えない文字は `_` にし、空の名前・無名の定義・ANSI_932 で元に戻らない名前には `zumen_番号` を付ける。名前が重なれば連番を付ける。連番は、小文字にした基の名前ごとに次に試す番号を覚えて探すので、名前を決める手間は定義の数に比例する。使った名前が候補になる系列は、多くても 2 つ（それ自身を基の名前とするものと、末尾の `_数字` を除いた名前を基の名前とするもの）で、どの系列も番号を戻さないので、試す名前の数は定義の数の 3 倍と予約名 2 つの和を超えない（#655）。
- キー（名前空間と名前）が同じ記号の定義が重なると、キーごとに先の定義だけを部品にする。置いた記号の形は、図面モデルの `Drawing2D::symbol` と同じく、先の定義で決まるからである。先の定義が外部参照の定義なら、そのキーの部品は書かず、`convert.element.unsupported`（`external_symbol_definition`）を返し、それを置いた記号を `external_symbol` で落とす。あとの定義は、外部参照かによらず書かず、`duplicate_symbol_definition` を返す。部品の名前は重ならず、落とした定義の中身も書かない（#656）。変換はどの形式の図面モデルにも同じ扱いをする。DXF の lift は同じ名前の BLOCK を取り除かないので、同じ名前のブロックを持つ DXF を変換すると、この形になる。
- `NewDxfTemplate::new` は `Cx` を受けず、ひな形を作る手間をループごとには数えない。手間は記号の定義の数と名前の長さに比例し、どちらも図面モデルを作るときに読んだ入力の量で抑えられる（`convert`）。図面モデルを作る `civil_drawing` は、今は記号の定義を作らない。呼び出し側は、作ったひな形のバイト数を `Work` に数えてから、ひな形を読む。
- 足せなかった画層は、元の場所と `kind: layer` を付けて `convert.element.unsupported` で返す。その画層の要素も落とし、種類・件数・元の場所を同じ code で返す。画層 0 には移さない。たとえば、追加できない予約名の Defpoints と、その上の要素は、この扱いになる。既定の画層 0 はひな形の項目を使う。
- 図面モデルから新しい R2004 DXF を作るときは、画層 0 と追加できた画層の説明を XDATA の `AcAecLayerStandard`（空の 1000、説明の 1000）、透過性を `AcCmTransparency`（1071 の上位バイトが 2、下位バイトが不透明度）に書く。使う APPID を 1 回ずつ表に登録する。説明は ANSI_932 で元の文字に戻り、符号化後 255 バイト以内で、NUL と改行を含まないものを扱う。255 バイトは [DXF Reference の拡張データの上限](https://help.autodesk.com/cloudhelp/2020/ENU/AutoCAD-DXF/files/GUID-A2A628B0-3699-4740-A215-C560E7242F63.htm)による。
- 画層を作れなかったときや、説明を表せないときは、出力に移せなかった値だけを `convert.layer-field.dropped` で返す。`field` は `description` か `transparency` で、それぞれの件数と元の画層の場所を持つ。ひな形にある画層 0 も含む。図面モデルへの読み取りと DXF への書き出しを通して、診断は元のレコード番号の順（DWG のオブジェクトはバイト範囲の開始位置の順）に返す。場所の表示を 0 件にしてもその順を保つ。
- 書けない要素と、文字にした属性の診断にも、元の要素・属性の場所を付ける。診断ごとの件数を数え、場所の数は呼び出しの上限まで残す。`convert.attribute.drawn` は、属性の文字を実際に足せたときだけ返す。

R2004 の構成は、Autodesk の [DXF Reference](https://images.autodesk.com/adsk/files/acad_dxf.pdf) の各節に従います。実アプリでの確認範囲は、下の「確かめた度合い」に書きます。

### 変換前の見積もり

`convert_estimate` は、`convert` と同じ `doc`・`format`・`to` を受け取り、`estimate` を返します（#645）。今は DXF への変換を扱います。見積もりでは、実変換と同じ経路で一時的に最後まで書き、予定の文書名・形式・ハッシュ・要素数、種類と忠実度ごとの集計、元の場所を持つ明細を返します。元の文書・ID は変わらず、変換先の文書と配布する blob は登録しません。同じ名前の `to` で続けて `convert` できます。すでにある文書名や不正な名前・形式は、実変換と同じ規則で拒否します。

`limit` は返す明細の上限で、既定は 100 件、最大は 1000 件です。0 なら明細を返しません。`total` と `counts` は上限によらず書き手が扱う項目の全件を数え、明細が収まらなければ `truncated` が true になります。lower の集計は図面モデルへ移せた項目が対象で、元のファイルから lift するときに落としたものは含みません。その欠落は応答の `diagnostics` から確かめます。共有 L1 の経路では、再符号化の対象レコードを数えます。元のファイルの全項目の明細を返す機能ではありません。

場所を持たない項目も数えます。同じ元の場所を持つ別の項目は別々に数え、診断の数と項目の数は分けます。`output_elements` はその項目から実際に書いた図形数で、表の項目などは 0 です。集計の `output_elements` の合計は、実変換が返す `elements` と一致します。

明細の場所は診断の場所の上限（`max_places`）とは独立して返します。明細の確保も作業量と展開量の予算で数えるため、予算が少ないと、明細を返す見積もりは実変換より先に止まることがあります。成功した見積もりの予定値と、同じ元の文書・設定で実変換した値を比較します。

忠実度は `native`（値と参照を保持）・`equivalent`（別の表現で同じ意味）・`approximated`（近似）・`drawn`（見た目だけ）・`dropped`（欠落）です。書ける形でも、文字の位置合わせ・高さの意味や、スタイルの既定値への置き換えなどで元の意味を保持できない場合は、保持・等価と扱いません。明細の `reasons` は、`text_height_meaning`・`relocated_shape`・`style_default` など、変えた値や参照の種類を示すキーです。属性の文字への分離と、ビューの用紙への焼き込みも区別して数えます。既存の `convert` のバイト列と診断は維持するため、文字の位置合わせなどの欠落を個別の診断で知らせる #763 の残件は、この見積もりで完了したとは扱いません。

見積もりと実変換のネイティブ・wasm の応答は `bindings/conformance/cases/convert_estimate.json` で照合します。API のテストでは、明細の上限、出力名を確保しないこと、元の ID とハッシュ、予算超過・中断後の再試行、複数の診断と出力の件数も確かめます。外部照合では、検証キットを作る `xtask/verify/make.py` が見積もりのハッシュ・要素数・診断を実変換と比較し、書いたファイルを既存の ezdxf の検査へ渡します。R2004 DWG の弧長寸法・描画ブロックの値と参照を照合する範囲は、下の「確かめた度合い」にあります。AutoCAD での表示の確認は、この見積もりの検査には含めません。

### R2004 DWG の弧長寸法

R2004 DWG のモデル空間・ペーパー空間に弧長寸法があり、必要な図形と参照をすべて扱える場合、`convert` は共有のオブジェクト表から R2004 の ASCII DXF に書く。この経路では、元のハンドル・所有者・表の名前・コードページを使う。

- 弧長寸法は `AcDbDimension` と `AcDbArcDimension` のサブクラスに分ける。共通部と固有部それぞれの 70・71、定義点、部分の角度、引出線の点を区別する。使うクラスの宣言は元の DWG から移し、出力のインスタンス数を 91 に書く。13 から始まる固有部の配置は AutoCAD の公開 DXF と照合した推定。
- 描画ブロックは元の BLOCK_RECORD とその BLOCK・ENDBLK を使い、所有するハンドルの並びで図形を書く。選択されていない用紙の寸法もその用紙のブロックに置く。図形は LINE・ARC・CIRCLE・SOLID・TRACE・POINT・MTEXT に対応する。用紙の LAYOUT は対応するブロックと相互に結び、寸法からは描画ブロックと DIMSTYLE、DIMSTYLE からは文字スタイルを引けるようにする。
- 元のリアクターのうち、出力するオブジェクトへの参照は 102 の組と 330 に残す。図形のプロキシ画像は 92 にバイト数、310 に元のバイト列を書く。
- ヘッダーは共有の表に取り出した変数と、新しい `$HANDSEED` を書く。コンテナー固有の情報などの欠落は `dwg.dxf-header.dropped`、出力対象外のオブジェクトは `dwg.dxf-record.dropped`、拡張辞書の組・省いたリアクター・辞書項目・図形の明示的な印刷スタイルへの参照は `dwg.dxf-reference.dropped` で返す。関連付けの DIMASSOC や拡張辞書も診断する。
- 表の名前は、ASCII と `$DWGCODEPAGE` が `ANSI_932` のときの CP932 に対応する。禁止文字と 255 文字の上限は復号して調べ、同じバイト列に戻る名前を元のまま書く。参照を引くときは ASCII の英字の大小を区別せず、2 バイト文字の後続バイトは変えない。`zumen-acad` の `drawing` の feature は、CP932 の名前を復号・照合する `cp932` の feature を含む。L1 だけを使う場合は `cp932` を選べる。
- 名前を復号して元のバイト列に戻せない場合、対象外の図形・外部参照のブロック・解けない必須の参照などがある場合は、同じオブジェクト表を図面モデルに移し、出力用のひな形に要素と表の項目を追加する経路で書く。試行と変換には同じ予算を使う。

## バージョンの変更

- `Dxf::write_as` で、`$ACADVER` の値を名指しして書く。元と同じバージョンなら、そのまま書く。バイナリの DXF のバージョンは、まだ変えない。
- いまは AC1012〜AC1032（R13〜2018）から AC1009（R12）への変更だけを扱う。ほかの組は `dxf.version.unsupported` を返し、何も書かない。
- 残すのは HEADER・TABLES・BLOCKS・ENTITIES のセクションと、VPORT・LTYPE・LAYER・STYLE・VIEW・UCS・DIMSTYLE・APPID の表。ほかは書かず、セクションと表ごとに診断を返す。
- BLOCKS と ENTITIES では、R12 の種類の図形だけを書く。LWPOLYLINE・MTEXT・HATCH などは変換せずに書かず、`dxf.entity.dropped` を返す。
- サブクラスマーカー（100）、所有者への参照（330・360）、`{` と `}` で囲むアプリケーションの組（102）、表のハンドル（TABLES の中の 5 と 105）は、置き換える先のない構造として黙って除く。ほかの R12 にないグループ・コードのタグは書かず、`dxf.group-code.dropped` を返す。
- ヘッダーは、R12 にないグループ・コードの値を持つ変数を、変数ごと書かない。`$ACADVER` を AC1009 にし、図形のハンドルを残すので、`$HANDLING` がなければ 1 として足す。
- 2007 以降のバージョン（UTF-8）から書くときは、ASCII でない文字を `\U+XXXX`（UTF-16 の単位ごと）にして、`dxf.text.equivalent` を返す。UTF-8 として読めない値は、バイト列のまま書く。
- 残すタグは、グループ・コードの行と改行を元のバイトのまま書く。
- まだ扱わないもの: LWPOLYLINE・MTEXT などの R12 の図形への変換、`*Model_Space` などのレイアウトのブロックの扱い、ほかのバージョンの組、ezdxf や ODA の変換結果との比較。

## オブジェクトの表

- `DxfFile::objects` で、DXF と DWG が共有するオブジェクトの表（`AcadDb`）を作る。
- セクションの中のレコードを、1 つずつオブジェクトにする。`SECTION`・`ENDSEC`・`EOF` と、セクションの外のもの（先頭のコメントなど）はオブジェクトにしない。ヘッダーの変数は `SECTION` のレコードの中にあるので、オブジェクトにならない。
- 値は、グループ・コードの範囲で決めた型で読む（DXF Reference「Group Code Value Types」）。ハンドルとバイナリは 16 進として読む。
- 型どおりに読めない値は、元のバイト列のまま文字列として置き、`dxf.value.invalid` を返す。
- オブジェクトは、元のレコードの番号を持つ。予算の作業は、レコードごとに数える。
- 型付きのビューと図面モデルへの変換は、この表の上で行う。
- まだ扱わないもの: 表からの書き戻し。

## API から読む

- API の `open` は、入力の先頭が判定の規則に合えば DXF として読み、文書の名前と `dxf` を返す。`capabilities` では、系統 `acad` の読める形式として示す。
- 予算は、コーデックが確かめる。入力の大きさは読む前に、作業はタグごとに、レコードはレコードごとに数える。
- 開いた文書は、L1 のファイルモデルとして `close` まで持つ。中身を返す op と、図面モデルへの変換は、まだ API から呼べない。

## 図面モデルへの変換

- `DxfFile` の `Lift<Drawing2D>` で、図面モデル（L2、`crates/zumen-drawing`）を作る。変換は共有のオブジェクトの表の上で行い、DWG も同じ変換を使う（[DWG の扱い](dwg.md)）。`zumen-acad` の feature `drawing` にあり、外せば L1 だけを使える。
- 移す図形と値は、この節の各項に書く。移さない種類の図形は、種類ごとに `dxf.lift.dropped` を返す。
- モデル空間の図形は 1 つの実寸の空間に、ペーパー空間（67 = 1）の図形とビューポートは、レイアウトごとの用紙に置く。図形のないレイアウトも、LAYOUT があれば、名前と大きさだけの中身のない用紙にする。中身のない用紙の ID は、中身のある用紙の後から、タブの順に付ける。今のレイアウトに図形があれば、そのペーパー空間のブロックからは用紙を作らない。
  - 今のレイアウトの図形は ENTITIES にあり、ID 0 の用紙に置く。ほかのレイアウトの図形は、BLOCKS のペーパー空間のブロック（DXF では `*Paper_Space0` など、DWG では番号のない `*Paper_Space`）にあり、今のレイアウトの用紙の後に、LAYOUT のタブの順（71）で並べる。
  - 用紙の名前は、そのブロックのレコードを指す LAYOUT のレイアウトの名前（2 つ目の 1）とする。今のレイアウトの LAYOUT は、ペーパー空間の図形の所有者から探す。
  - ほかのレイアウトの用紙の点は、LAYOUT の範囲の左下（10・20）を原点にし、大きさは範囲（10・20 から 11・21）で決める（推定。サンプルの DXF と DWG で確かめた）。範囲がなければ原点を 0 とし、大きさを持たない。
  - ペーパー空間の MULTILEADER と POLYLINE も用紙に置く。これまでは実寸の空間に置いていた。
- 実寸の単位は `$INSUNITS` で決める。ないか長さの単位でなければ不明とし、`dxf.units.missing` を返す。mm とみなさない。
- 用紙の点は、`$PLIMMIN` を原点にして mm に直す。単位が不明なら直せないので、ペーパー空間の図形を移さず `dxf.paper-space.dropped` を返す。用紙の大きさは `$PLIMMIN` と `$PLIMMAX` から決め、なければ持たない。
- ビューポートは、縮尺 41 ÷ 45 の等方のビューと、中心 10・20 と幅 40・高さ 41 の矩形の切り抜きにする。69 = 1 のものは用紙そのものなので、ビューにしない。ねじれ（51）・視点の向き（16・26・36）・注視点（17・27・37）が既定でないものは、まだ移さず `dxf.viewport.unsupported` を返す。
- 画層は、表の LAYER のレコードを表の順に移す。凍結（70 の 1）か色（62）が負なら表示せず、290 が偽なら印刷せず、ロック（70 の 4）なら編集できないとする。凍結は、表示しないことと別にも持つ（`LayerState::frozen`、[図面モデルとの対応](drawing2d-mapping.md)）。新しいビューポートで凍結（70 の 2）は移さない。図形が表にない名前を指せば、定義のない画層として足す。ビューポートで凍結した画層（341）は、ビューで表示しない画層にする。341 が画層のレコードを指さなければ、その指定だけを除き `dxf.lift.invalid` を返す。
- 線種は、表の LTYPE のレコードを表の順に移し、線と間の長さ（49）の列を要素の空間の長さとして持つ。要素に添える形と文字（74 の 2 と 4）は、要素の番号・中身・倍率・回転・回転の基準・ずれとして線種の定義に持つ。形は文字スタイル（340）の形のファイル（3）と番号（75）、文字は文字列（9）と文字スタイルの名前（2）で持つ。74 の 1 は回転を文書の x 軸から測ること、8 は文字を逆さにしないこととする（8 は推定）。形の番号が 0 の形は添えない（推定）。形と文字を兼ねる要素など読めない要素は、長さだけを移し、`dxf.line-type-element.dropped` を返す。図形が表にない名前を指せば、定義のない線種として足す。
- 図形の色は、62 が 1〜255 なら ACI の符号、420 があれば RGB として持つ。62 が 0 なら部品の配置から、256 かないならレイヤから継承する。線種（6）は ByLayer・ByBlock を継承とし、ほかは名前で線種を指す。線幅（370）は、-1 と -2 を継承、-3 を文書の既定、0〜211 を 1/100 mm とする。範囲の外の値は `dxf.lift.invalid` を返す。透過性（440）は、上位のバイトが 0 ならレイヤから、1 なら配置から継承し、2 なら下位のバイトを不透明度とする。ほかの値は `dxf.lift.invalid` を返す。画層の色は 62 の絶対値と 420、線種は 6、線幅は 370 から移す。画層の透過性は XDATA の `AcCmTransparency` の 1071 から、説明は XDATA の `AcAecLayerStandard` の 2 つ目の 1000 から移し、継承の値の透過性と空の説明は持たない。名前が「0」の画層は、ブロックの中の図形のレイヤからの継承を配置のレイヤで解く画層（`Layer.follows_placement`）にする。配置からの継承は継承のまま持ち、`Drawing2D::color_placed` などで配置の並びから解く。`$LTSCALE` と `$LWDEFAULT` は、文書の線種の倍率と既定の線幅にする。起点まで配置から継承したままの色と線種は、色 7 と線種「Continuous」で解く（推定。`Drawing2D::walk`、[図面モデルとの対応](drawing2d-mapping.md)）。
- 描く順は、モデル空間・ペーパー空間・記号の定義のブロックのレコードを指す SORTENTSTABLE で決める。並べ替えのハンドル（5）の小さいものから描き、表にない図形は自分のハンドルで並べ、同じなら入力の順にする。表がなければ入力の順とする。表が壊れているか、ハンドルのない図形があれば、入力の順のままにして `dxf.lift.invalid` を返す。
- 文字の高さ（40）は、宣言値（`dxf.TEXT.40`）として、図形の空間の長さで持つ。AutoCAD 2027 と比べ、TrueType では `A` の字形の外形の上、SHX では `H` の上に当たることを確かめた。シーンは、決めなければ `A` の字形の上（`capital_a`）に当てる。位置合わせ（72・73）の 9 点・基準線・外形の中央・Fit・Aligned・斜体・反転・回転の置く点も AutoCAD 2027 と比べた（同じ決定）。
- 文字の配置は、72・73 が両方 0 なら 10 の点に左・基準線で置く。72 が 3 なら Aligned、5 なら Fit として 10 と 11 の 2 点の間に置く。ほかは 11 の点に、72 と 73 の位置合わせで置く。 第 1 点の入力の有限性と平面の検査は保ち、採用する点だけを用紙座標へ換算する。中央・右寄せなどで使わない第 1 点は、その換算が非有限になる値でも図形を落とす理由にしない（[Autodesk の TEXT 仕様](https://help.autodesk.com/cloudhelp/2026/JPN/AutoCAD-DXF/files/GUID-62E5383D-8A14-47B4-BFC4-35824CAE8363.htm)）。ATTRIB も同じ規則で、縦の位置合わせには 74 を使う。
- 書式つきの文字（MTEXT）は、内容を 3 の並びの後に 1 を続けたものとし、元の内容と、書式の符号で分けた区間を持つ。高さ（40）は `dxf.MTEXT.40` の宣言値にする。挿入点（10）・位置合わせ（71 の 1〜9 を上・中央・下の行の左・中央・右）・書き進める向き（72 の 1・3・5）・枠の幅（41）と高さ（46、どちらも 0 ならなし）・行送りの倍率（44）と種類（73 の 2 なら一定）・文字スタイル（7）を持つ。向きは X 軸の向き（11・21）があればそれを、なければ回転（50）をラジアンから度に直して持つ。背景（90）は、1 を色（63・421）、2 を表示の背景の色の塗り、16 を枠の線とし、倍率（45、既定 1.5）と透明度（441）を持つ。文字の範囲の大きさ（42・43）は内容から決まるので移さない。
- MTEXT の書式の符号は、AutoCAD のヘルプが示すもののうち、`{}`・`\P`・`\N`・`\~`・`\\`・`\{`・`\}`・`\L`・`\O`・`\K`（と小文字）・`\U+XXXX` と、`;` で閉じる `\H`・`\W`・`\T`（後ろの `x` は倍率）・`\Q`・`\A`・`\C`・`\f`・`\F`・`\S` を解釈する。対にならない `}`、ほかの符号、値を読めない符号は、元の符号のまま解釈しない区間にする。`\c` の値は 420 と同じバイト順か確かめていないので、`\p` は段落の書式なので、解釈しない（推定）。`%%d` などの TEXT の特殊な符号は、TEXT と同じく文字列のまま持つ。
- 段組み（75 が 0 でない）の MTEXT は移さず `dxf.mtext-columns.unsupported` を返す。R2018 からは段組みのフィールドを埋め込みのオブジェクト（101）に置くので、101 を持つ MTEXT も段組みとみなす（推定。AC1032 のサンプルの図面では、101 を持つ 4 つの MTEXT がどれも段組みの種類 71 = 2 を持つ）。
- 寸法（DIMENSION）は、70 の下の 5 ビットで種類を分け、種類ごとの定義点（10・13〜16）を持つ。測定値（42）は `dxf.DIMENSION.42` のキーと組にして持ち、定義点から測り直さない。利用者の文字（1）は、ないか空か `<>` なら測定値を書く、空白 1 つなら書かない、ほかは元のまま上書きとし、書式の符号で区間に分ける。上書きの文字の `<>` は測定値を書く所、`\X` は寸法線の下の文字の始まりとする。文字の中点（11）・回転（53）・位置合わせ（71）・利用者が動かしたフラグ（70 の 128）・寸法スタイル（3）・部品の名前（2）も持つ。半径と直径の引出線の長さ（40）は、図形の空間の長さにする。
- 弧長寸法（ARC_DIMENSION）は、弧長の寸法にする。100 の `AcDbArcDimension` の後の、円弧の中心（15）と両端（13・14）を読み、寸法の弧の点（10）と、測定値・文字・寸法スタイル・部品の名前は DIMENSION と同じく読む。測る弧は、両端の間で寸法の弧の点を通る側とする。部分のフラグ（70）・角度（40・41）・16・17 は移さず、引出線のフラグ（71）が 1 なら `dxf.arc-dimension-leader.dropped` を返す。
- 引出線（LEADER）は、頂点（10・20・30）を経路とし、数（76）と合わなければ移さない。曲線か（72）・矢印（71）・寸法スタイル（3）を持ち、注記（340）は指すオブジェクトの出所で指す。
- 引出線つきの注記（MULTILEADER）は、値を区切り（300 `CONTEXT_DATA{`・301、302 `LEADER{`・303、304 `LEADER_LINE{`・305）で、図形・注記の文脈・枝・線に分けてから読む。枝は、線ごとの頂点（10・20・30）・集まる点（290 が真なら 10）・折れ曲がり（291 が真なら向き 11・21 と長さ 40）を持つ。図形の 291 が偽なら、折れ曲がりを持たない。線の引き方（170）・端部記号（342 の指すブロックのレコード）・大きさ（42、なければ文脈の 140）・ランディング（290）・倍率（文脈の 40）・スタイル（340 の指すオブジェクトの出所）も持つ。

- 寸法スタイルは、表の DIMSTYLE のレコードを表の順に移し、端部記号と大きさを持つ。端部記号は、両端を別にする（173）なら 343・344、しなければ両端とも 342、引出線は 341 の指すブロックのレコードの名前にし、0 かなければ既定の矢印とする。大きさ（41）・斜線の大きさ（142）・倍率（40）も持つ。指すものがブロックのレコードでないか、負の値なら、そのスタイルを移さず `dxf.lift.invalid` を返す。

- 記号の定義は、BLOCKS の BLOCK から作る。中身は、所有者（330）をたどって着くブロックのレコードの BLOCK のもの、所有者が分からなければ、並びの中で前の BLOCK から ENDBLK までのものとし、図面の実寸の空間とは別の、定義ごとの空間に置く。名前は BLOCK の 2、なければブロックのレコードの 2。基点（10）・名前のない定義（70 の 1、または名前が `*` で始まる）・外部参照のパス（70 の 4 なら 1）を持つ。ATTDEF は、ATTRIB と同じフィールドと、値を尋ねる文（3）・フラグ（70 の 2・4・8 を、値が決まっている・確かめる・尋ねない）を持つ属性の定義にする。空間のブロック（`*Model_Space`・`*Paper_Space`）は移さない。定義の空間の単位は、ブロックのレコードの挿入単位（R2007 からは 70、R2004 までは拡張データの ACAD の `DesignCenter Data` の 2 つ目の 1070）とし、0 かなければ文書の単位とする。配置の尺度は単位の換算を含むので、配置で単位を換算し直さない（推定。[図面モデルとの対応](drawing2d-mapping.md)）。どの BLOCK のものか分からない図形と、名前のない BLOCK は、`dxf.lift.invalid` を返す。配置は展開しない。配置（INSERT）と、表・セル・寸法・引出線つきの注記・寸法スタイルが指す定義がなければ `dxf.block.missing` を、定義の中の配置をたどって自分に戻る定義には `dxf.block-cycle.invalid` を返し、どちらも配置と定義は移す。
- 表（ACAD_TABLE）は、AcDbTable（100）より前の挿入点（10）と、表を描いたブロック（2）を読む。後の値からは、行と列の数（91・92）・横の向き（11・21）・表のスタイル（342）・行の高さ（141）・列の幅（142）と、種類（171）で始まるセルを読む。セルは、覆われる（173）・広げる列と行の数（175・176）と、種類が 1 なら文字（2 の区切りと 1）、2 ならブロックのレコード（340）を内容に持つ。1 も 2 もなければ、2007 からの値（301 `CELL_VALUE` から 304 `ACVALUE_END` まで）の表示する文字（302）を内容にする。値は、フラグ（93）・型（90）・型ごとの値（文字なら 1 に元の文字）・単位（94）・書式（300）・表示する文字（302）の順に並ぶ。302 は書式を当てた後の文字（サンプルでは、1 が `cell format 1`、書式が `%tc1` のとき `CELL FORMAT 1`）なので、表示に合う。値の中のほかのコードは、セルのフィールドとして読まない。R2010・R2013・R2018 のサンプルの DXF で確かめた。数が合わなければ `dxf.lift.invalid` を返す。
- 表のセルの 2007 からの値は、型のある値と単位と表示の書式も持つ。フラグ（93）の 1 が立つか、型（90）が 0 なら、値を持たない。型は、1 を整数（91）、2 を実数（140）、4 を文字列（2 の並びと 1）、8 を日時（92 の大きさと 310 の SYSTEMTIME。年・月・曜日・日・時・分・秒・ミリ秒の 16 ビットの並び）、16・32 を点（11・21・31）とする。単位（94）は、0・1・2・4・8・16・32 をなし・長さ・角度・面積・体積・通貨・百分率とする。書式（300）は、空でなければ元の文字列のまま持つ。角度はラジアンで持つ（サンプルでは、1.0471… を `%au0` で 60 と表示する）。オブジェクトの参照（64）・バイト列（128）・結果の並び（256）・一般の値（512）は値を移さず、`dxf.cell-value.dropped` を返す。どれも表示する文字（302）は内容に移す。R2007〜R2018 のサンプルの DXF で、整数・実数・角度・点・日時・百分率・通貨の値を確かめた（日時の 310 は、表示の `11/15/2024` と曜日が合う）。表題欄の役割は DXF にないので、属性を持つ記号のまま持ち、表題欄と推定しない。

- アンダーレイは、IMAGE と PDFUNDERLAY・DWFUNDERLAY・DGNUNDERLAY を移す。定義（340 の指す IMAGEDEF・PDFDEFINITION など）の参照名（1）を資源とし、ファイルは開かない。IMAGE は、挿入点（10）と 1 画素の横と縦（11・12）、画素の数（13・23）から左下・右下・左上の角を持ち、70 の 1 を表示する、280 が 1 なら境界（71・91・14）で切り抜き、290 が真なら内側を隠す。アンダーレイは、定義のページなどの名前（2）・挿入点（10）・尺度（41・42）・回転（50）を持ち、280 の 2 を表示する、1 なら境界（11）で切り抜き、16 なら内側を隠す。描く順は、ほかの図形と同じく SORTENTSTABLE と入力の順で決める。
- 図形の XDATA は、登録アプリケーション名（1001）ごとに、名前空間 `dxf.xdata` の形式固有の情報にする。バージョンは `$ACADVER`、値の型の契約のバージョンは 3 とし、値は並びの順に、グループ・コード（1000・1002〜1005・1010〜1013・1040〜1042・1070・1071）の意味で名付け、元のグループ・コード（`Field::code`）を付ける。点は続く Y（+10）と Z（+20）と合わせ、X のコードを付ける。付く先の図形を要素の ID で指し、読んだときの図形のハッシュを持つ。図形を編集すれば失効したとする。最初の 1001 より前の XDATA の値と、読めない値を持つ名前の分は `dxf.lift.invalid` を返す。
- 図面モデルの値にない図形のフィールドは、名前空間 `dxf.entity`（バージョン 3）の形式固有の情報にし、値に元のグループ・コードを付ける。厚さ（39）は、LINE・CIRCLE・ARC・TEXT・LWPOLYLINE・POLYLINE・SOLID・TRACE・POINT・SHAPE で 0 でなければ `thickness`（実数）にする。SPLINE のノットと制御点の許容差（42・43）は、あれば `knot_tolerance`・`control_tolerance`（実数）にする。線種の生成（70 の 128）とフィット許容差（44）は、図面モデルの値に移す。サンプルの DWG と DXF の組で、どのフィールドも一致することを確かめた。どのフィールドもない図形は、この拡張を持たない。実数として読めないか有限でない値があれば、図形は残し、この拡張を移さず `dxf.lift.invalid` を返す。
- 図形の拡張辞書（102 の `{ACAD_XDICTIONARY` の組の 360 が指す DICTIONARY）の XRECORD の項目は、項目の名前ごとに、名前空間 `dxf.xrecord` の形式固有の情報にする。値の型の契約のバージョンは 3 とし、値は、複製の扱い（280）の後のデータを記録の順に、元のグループ・コードを付けた型付きの値（`text`・`integer`・`real`・`point`・`handle`・`binary`）で並べる。点（X が 10〜17・210・1010〜1013）は、続く Y（+10）と Z（+20）があれば合わせ、なければ実数のまま並べる。図面モデルのフィールドにする値でフィールドがまだない項目（注釈の尺度の `AcDbContextDataManager`・`ASDK_XREC_ANNO_SCALE_INFO`・`ASDK_XREC_ANNOTATION_SCALE_INFO`、寸法の関連づけの `ACAD_DIMASSOC`、動的ブロックの `AcDbBlockRepresentation`、ビューごとの画層の上書きの `ADSK_XREC_LAYER_*_OVR`）と、AutoCAD のバージョンの往復の XRECORD（`ACAD_XREC_ROUNDTRIP`・`ACAD_MTEXT_RT`・`ACAD_MTEXT_2008_RT`）は、図面モデルに移さず元のファイルに残し、`dxf.extension-dictionary.unsupported` を返す。往復の値は、図形の値で表せる内容と表せない内容をまだ読み分けないので、すべて返す。ほかの XRECORD でない項目は移さず、`dxf.extension-dictionary.dropped` を返す。
- 記号の切り抜き（XCLIP）は、INSERT の拡張辞書の `ACAD_FILTER` の辞書の `SPATIAL` が指す SPATIAL_FILTER から作る。境界の点（10・20）を、境界の変換と挿入の逆の変換（40 の 12 ずつ、3 行 4 列を行の順）で記号の定義の空間に写し、記号の切り抜きの頂点にする。2 つの点は、向かい合う角の長方形とする。境界の向き（210〜230）が Z でないもの、境界の原点（11〜31）が 0 でないもの、点が 2 つより少ないものは、切り抜かずに記号を移し、`dxf.clip.dropped` を返す。前と後ろで切るか（72・73）と、境界を表示するか（71）は移さない。反転した切り抜き（AutoCAD 2015 から）は、SPATIAL_FILTER の拡張辞書の `ACAD_XREC_ROUNDTRIP` の XRECORD にある元の境界（102 の `ACAD_INVERTEDCLIP_ROUNDTRIP` の後の 10・20・30）を、内側を隠す切り抜きにする。同じ XRECORD の `ACAD_INVERTEDCLIP_ROUNDTRIP_COMPARE` の後の多角形が SPATIAL_FILTER の境界と合わなければ、境界をそのまま使う。
- 画層（LAYER）と線種（LTYPE）の表のレコードの拡張辞書の XRECORD も、同じく `dxf.xrecord` の形式固有の情報にし、画層と線種に付ける。ほかの表のレコードとオブジェクトの拡張辞書は移さない。
- ハッチング（HATCH）は、境界の輪の数（91）から後の値を並びの順に読む。輪ごとに、フラグ（92）の 2 が立てば膨らみ（42）のある頂点の折れ線、立たなければ線分・円弧・楕円弧・SPLINE の辺の並びとし、フラグの 1・4・8・16 を外側・境界を探した・文字の枠・いちばん外とする。輪を作った図形（330）は出所で指す。島（75）・パターンの出どころ（76）・回転（52）・尺度（41）・重ねるか（77）・線の組（53・43〜46・49）・境界を探した点（98・10・20）を持つ。塗り（70 = 1）はパターンのフィールドを読み飛ばし、450 が 1 ならグラデーションにする。SPLINE の辺（72 = 4）は、次数（94）・有理（73）・周期的（74）・ノット（95・40）・制御点（96・10・20）と、有理なら重み（42）を読む。2010（AC1024）以降のバージョンの DXF では、続くフィット点（97・11・21）と、あれば接線（12・13）も読む。
- 曲線は元の定義のまま移す。CIRCLE は中心（10）と半径（40）、ARC はさらに始まりと終わりの角度（50・51、度）を持つ。ELLIPSE は中心（10）・中心からの長軸の端（11）・比（40）と、始まりと終わりのパラメーター（41・42、ラジアン）を度に直して持つ。LWPOLYLINE は、頂点（10・20）ごとに続く始まりと終わりの幅（40・41）と膨らみ（42）・閉じているか（70 の 1）・線種の生成（70 の 128）・一様な幅（43）を持ち、頂点の数（90）と合わなければ移さない。古い POLYLINE は、続く VERTEX（所有者が指すか、66 が 1 の POLYLINE から SEQEND まで）を頂点にし、VERTEX の点（10・20）・膨らみ（42）・始まりと終わりの幅（40・41、なければ 0）と、閉じているか（70 の 1）と線種の生成（70 の 128）を持つ。どの頂点の幅も同じなら一様な幅にする。POLYLINE の既定の幅（40・41）は新しい頂点のためのものなので使わない。3D の折れ線（70 の 8）は Z がどれも 0 なら移す。曲線かスプラインで当てはめたもの（70 の 2・4）と、網・多面（16・64）は移さず `dxf.lift.dropped` を返す。SPLINE は、フラグ（70 の 1・2・4 を閉じている・周期的・有理）・次数（71）・ノット（40）・制御点（10）・重み（41）・フィット点（11）・接線（12・13）・フィット許容差（44、0 以上）を持ち、数のフィールド（72〜74）や次数と合わなければ移さない。フィット点で決まるフラグ（70 の 1024）が立てば、32・64・128・256 をノットの取り方の弦の長さ・その平方根・一様・指定とする。どれか 1 つでなければ取り方を持たない。標高（LWPOLYLINE の 38、POLYLINE の 30）や Z が 0 でなければ平面に移さない。
- Z が 0 でない点と、押し出しの向き（210・220・230）が Z でない図形は、Z を捨てて移さず、`dxf.non-planar.dropped` を返す。

- 入力が有限でも、楕円の長軸の端、画像の角、ラジアンから度への換算、用紙の座標・長さ、ビューの縮尺・移動・切り抜きが非有限になれば、図形かビューを移さず `dxf.lift.invalid` を返す。属性の換算だけが失敗した場合は、その属性だけを移さず、INSERT とほかの属性を残す。計算した値を丸めたり 0 に置き換えたりしない。用紙への換算は X・Y を 10・20、長さを 40 として、元の図形か属性のレコードを診断する。
- `$PLIMMIN`・`$PLIMMAX` の値が非有限か読めなければ、変数名と座標のコードで `dxf.lift.invalid` を返す。ヘッダーの変数の表はレコードの場所を持たないため、場所は付けない。読めない原点は既定の (0, 0) とし、読めない最大の点からは用紙の大きさを作らない。有限の範囲から計算した用紙の大きさが非有限になった場合も、大きさを未指定にして診断する。LAYOUT の範囲からの計算では、その LAYOUT を指す。
- XDATA と XRECORD の実数と点の各座標も、非有限なら `dxf.lift.invalid` を返す。その名前の拡張だけを移さず、付く先の図形と正常な拡張を残す。診断は元のグループ・コードと付く先のレコードを指す。L1 の値とバイト列は変えない。
- MTEXT の高さ・幅・間隔の符号で倍率を掛けた値が非有限になれば、掛ける前の書式を保ち、その符号を `Piece::Unparsed` に残す。解釈できない符号の既存の扱いに従い、診断は返さない。
- 2007 以降のバージョンは、文字の値を UTF-8 として読む。それより前のバージョンは、`$DWGCODEPAGE` が `ANSI_932` なら、ASCII でない文字を WHATWG の Shift_JIS として戻す。戻せないバイト列を持つものは `dxf.lift.invalid` で落とす。ほかのコード・ページと、`$DWGCODEPAGE` がないものの ASCII でない文字は、その図形を移さず `dxf.code-page.unsupported` を返す。
- 図面モデルの変更を書き戻すときも、2007 より前のバージョンの文字と名前（画層・文字スタイル・線種・寸法スタイル・ブロックなど）は、同じ表を逆に引いて符号化する。表せない文字と、符号化して戻すと別の文字になる文字（ANSI_932 の ¥・‾・− など）があれば、変更をすべて反映せず `change.edit.unsupported` と `change.character.unsupported` を返す。`\U+XXXX` の符号には直さない。名前を大文字と小文字を区別せずに比べるときは、Shift_JIS の 2 バイト目を小文字にしない。DWG（R2000〜R2004）も同じ。
- SOLID と TRACE は、角（10〜13）を 1・2・4・3 の順に結んだ閉じた輪 1 つを塗るハッチングにする。3 つ目と 4 つ目の角が同じか、13 がなければ三角形とする。POINT は、文書の点の表し方に従う図面モデルの点にし、50 を回転にする。点の表し方（`point_style`）は、`$PDMODE` を形（0〜4 の基本の形に、32 の円と 64 の四角）、`$PDSIZE` を大きさ（正は長さ、負は画面の高さに対する百分率、0 は画面の高さの 5%）にして作る。どちらの変数もなければ `None` にする。知らない番号と、有限でない大きさは、`dxf.lift.invalid` を返し、小さな点と画面の高さの 5% にする。
- まだ扱わないもの: 当てはめた古いポリライン（POLYLINE）と網・多面、RAY・XLINE などほかの図形、文書の点の表し方の書き戻し、端部記号のほかの寸法スタイルの値と、拡張データで上書きした値の解釈、拡張辞書の XRECORD でない項目と、画層と線種以外のオブジェクトの拡張辞書、独自のオブジェクト、記号の内側を隠す切り抜きと切り抜きの書き戻し、寸法の部品の展開、ブロックの展開、段組みの MTEXT、表全体の上書きと行・列ごとの書式、公差、ねじれと 3D のビュー、多角形の切り抜き、ANSI_932 でないコード・ページの文字と、文字の中の `\M+` の符号。

## 推定した扱い

仕様の文からは決まらないため、次のように扱います。実際のファイルで確かめたら、ここを直します。

| 所 | 扱い | 理由 |
| --- | --- | --- |
| 改行 | LF と CR LF のどちらも行の終わりとする。最後の行に改行がなくてもよい | 改行の種類で読めなくならないように。元のバイトは書くときに残る |
| グループ・コードの行 | 前後の ASCII の空白を除いて、符号つきの整数として読む | 仕様の例は右寄せだが、桁の揃え方の違いで読めなくならないように |
| 値の行 | 改行を除いた生のバイト列として持つ。空白も文字コードも変えない | 文字コードは `$DWGCODEPAGE` とバージョンで決まるため、L1 では解釈しない |
| `EOF` がない | 最後のタグまでを読み、診断は出さない | 試作の範囲では、壊れた終わりの扱いを決めていない |
| 形式の判定 | 先頭の 2 行が、空白を除いて `0` と `SECTION` | 999 のコメントで始まるファイルは、まだ判定しない |
| 実数の値を読む | 前後の空白を除いて 10 進の実数として読む。指数の表記を許し、有限でないものは読めないとする | 仕様の例には指数の表記（`1.0E+20` など）がある |
| ハンドルの値 | 空のもの、符号の付いたもの、64 ビットを超えるものは読めないとする | ハンドルは 16 進の符号のない数のため |
| 真偽の値（290〜299） | 0 と 1 だけを読む | ほかの値の意味を仕様の文から決められないため |
| 足したタグの書き方 | グループ・コードを 3 桁に右寄せし、ファイルの最初の行と同じ改行（CR LF か LF）で書く。値はそのまま書く | 仕様の例と AutoCAD の出力が右寄せのため。1 つのファイルで改行を混ぜないため |
| `$HANDSEED` の書き方 | 次のハンドルを、0 で埋めない大文字の 16 進で書く | 仕様の例のハンドルが大文字の 16 進のため |
| 書き戻す値の書き方 | 整数は 10 進、真偽は 0 と 1、ハンドルとバイナリは 0 で埋めない大文字の 16 進（バイナリは 1 バイトを 2 桁）、文字列はそのまま書く | 表を作るときの読み方の逆で、読み直すと同じ値になるため。元の桁揃えは、値を変えたタグでは保たない |
| 実数の値を書く | 読み直すと同じ値に戻る最短の 10 進の表記にする。指数は使わず、整数の値にも小数点を付ける | どの環境でも同じバイト列にするため |
| 書き戻しで広げる図面の範囲 | 値を変えたか足したモデル空間の図形のうち、LINE・POINT と、押し出しの向きが既定の CIRCLE だけを囲む。範囲は狭めない。変数がないか、10・20・30 の実数を持たなければ直さない | 囲む箱を値だけから決められる図形に限るため。除いた図形の分を狭めるには、ほかの図形の範囲がすべて要るため |
| 画層と線種の名前を引く | ASCII の大文字と小文字を区別しない。同じ名前のレコードが 2 つあれば、先のものを指す | AutoCAD が画層の名前の大文字と小文字を区別しないため。仕様の文からは決まらない |
| DIMENSION の移さないフィールド | 複製の挿入点（12）・行間（41・72）・水平の向き（51）は移さない。70 の 8・16 のビットは見ない | どれも寸法の意味を変えず、描く形は部品が持つため。8・16 は仕様の文にない |
| DIMENSION の測定値（42） | `dxf.DIMENSION.42` のキーと組にして持つ。長さ（長さ・平行・半径・直径・座標の寸法）は図面の単位、角度はラジアンで、寸法の倍率（DIMLFAC）は掛けない値とする | 仕様の文は「実際の測定値」とだけ書く。R2000〜R2018 の同じ図面の DXF と DWG の 11 の寸法（角度の寸法 2 つを含む）は、どれも定義点から測った値と合う（テスト `dimension_samples`）。ただし保存された値は最後に描いたときの値で、定義点と違うことがある（ほかの 2 つのサンプルの図面を合わせた 508 の寸法のうち 34 が違う）。比べた DXF のヘッダーの `$DIMLFAC` は 1 で、倍率を掛けないことは確かめていない |
| ARC_DIMENSION のフィールド | 15 を円弧の中心、13・14 を測る弧の両端（順は決めない）、40・41 を両端の角度、70 を部分のフラグ、71 を引出線のフラグとする。16・17 は移さない | DXF Reference に節がない。AutoCAD で作った R2004・R2018 のサンプルで、半径と角度から両端と弧の長さ（42）が合い、部分の寸法では 13 が終わりの角度の点だった。16・17 はどの寸法でも 13・14 と同じだった |
| LEADER の移さないフィールド | 注記の種類と大きさ（73・40・41）・鉤の線（74・75）・ずれ（212・213）・X 軸の向き（211）は移さない。矢印（71）がなければ寸法スタイルに従うとする | 経路と注記の参照があれば、注記との組の意味は保てるため |
| DIMSTYLE の既定の値 | 値のないフィールドは、DIMSCALE（40）を 1、DIMASZ（41）を 0.18、DIMTSZ（142）を 0、DIMSAH（173）を偽とする。R12 の名前の端部記号（5〜7）は読まない | DWG のリーダーが、既定の値と同じフィールドを置かないため。値は DXF Reference のヘッダーの変数の既定の値（インチの図面）で、メートルの図面の既定の値とは違う |
| INSERT の Z の尺度（43） | 移さない | 平面の図形を置くかぎり、平面の形を変えないため。定義に Z のある図形があるかは、定義を移すときに確かめる |
| HATCH の移さないフィールド | 密度の画素の大きさ（47）、グラデーションの色の番号（63）と値（463）は移さない | 47 は表示のための値のため。グラデーションの色は RGB（421）で決まり、63 は仕様の文で役割が決まらないため |
| HATCH の境界の図形の数（97） | 輪の最後の 97 の数だけ 330 を読み、合わなければ移さない。DWG は 330 を置かないので空にする | 境界を作った図形を黙って落とさないため。SPLINE の辺のフィット点の数も 97 なので、2010（AC1024）以降のバージョンの SPLINE の辺だけがフィット点を持つとして読み分ける（[図面モデルとの対応](drawing2d-mapping.md)、サンプルで確かめていない） |
| アンダーレイの切り抜きの反転（280 の 16） | IMAGE の 290 と同じく、内側を隠すこととする | DXF Reference「UNDERLAY」は「Clip inside mode」とだけ書き、サンプルの図面に切り抜いたアンダーレイがない |
| アンダーレイの切り抜きの頂点（14・11） | 元の形式のアンダーレイの座標のまま持つ。画像では画素の座標、アンダーレイでは内容の座標とする | 座標の意味をサンプルで確かめていない |
| 記号の切り抜きの変換（SPATIAL_FILTER の 40） | 先の 12 を挿入の逆の変換、後の 12 を境界の変換とし、境界の変換を先に当てる | サンプルの図面では、先の 12 が挿入点と尺度の逆になり、後の 12 は単位の変換だった。反転した切り抜きは、AutoCAD で作ったサンプルで確かめた |
| R12 のグループ・コード | 0〜79、210〜239、999、1000〜1071 とする | ほかの値の型（90 台の 32 ビットの整数など）は R13 以降で足されたため。実際の R12 のリーダーでは確かめていない |
| R12 の図形の種類 | 3DFACE・ARC・ATTDEF・ATTRIB・BLOCK・CIRCLE・DIMENSION・ENDBLK・INSERT・LINE・POINT・POLYLINE・SEQEND・SHAPE・SOLID・TEXT・TRACE・VERTEX・VIEWPORT とする | バージョンごとの図形の一覧から。R12 で範囲内のコードの意味が変わったものは確かめていない |
| R12 のヘッダーの未知の変数 | 値のグループ・コードが R12 の範囲なら、残す | 知らない変数を落とさないため。R12 のリーダーが無視するかは確かめていない |
| バージョンの比べ方 | `$ACADVER` の値を、前後の空白を除いたバイト列として比べる | バージョンの名は `AC` と 4 桁の数字で、辞書順が新旧の順になる |
| LINE の Z がない | 0 とみなす | 2D の図面では Z を省いたファイルがあるため |
| 用紙の単位 | LAYOUT の印刷の尺度と単位で決め、読めないか画素なら実寸と同じ `$INSUNITS` とする | AutoCAD 2027 の R2000〜R2018 のサンプルの 3 つのレイアウトで、範囲が印刷する用紙の大きさに合うことを確かめた。印刷の設定のない LAYOUT と画素の単位はサンプルがない |
| 用紙の原点 | `$PLIMMIN` とし、なければ（0,0）とする | [座標系の扱い](crs.md) の用紙の左下に合わせるため。印刷の設定の余白は見ていない |
| 用紙そのもののビューポート | 69 = 1 のものとする | ビューポートの ID の 1 は、ペーパー空間そのものを表すため |
| ビューの中心 | 12・22 を、注視点を原点にした実寸の座標とする。注視点が既定でないものは移さない | 注視点を足す向きを、実際のファイルで確かめていない |
| 押し出しの向きがない | （0,0,1）とみなす | 既定の値のため |
| TEXT の既定の値 | 50・51 は 0、41 は 1、7 は STANDARD、71・72・73 は 0 とする | 省いたファイルがあるため |

## 確かめた度合い

| 形式 | 向き | 段 |
| --- | --- | --- |
| `dxf` | 読み | `application` |
| `dxf` | 書き | `application` |

段の意味は[形式台帳の書き方](../../formats/README.md#確かめた度合い)に、根拠は[形式と権利の一覧](README.md#format-dxf)にあります。段は確かめた方法のうちもっとも強いものを示します。AutoCAD で確かめたのは、次の範囲だけです。ezdxf とは、毎晩の CI で下の「ezdxf」の項に書いた範囲を照らします。

- 読み: AutoCAD 2027 で作った R2000〜R2018 の DXF（`samples/dwg`）で、レイアウトの用紙・弧長寸法・反転した切り抜きを、AutoCAD が書いた値と比べた。TEXT の高さと位置合わせは、AutoCAD 2027 が計算した置く点と比べた。
- 非有限値の境界: 楕円・ハッチング・画像・文字と引出線つきの注記の角度、用紙と属性の換算、TEXT・ATTRIB の位置合わせで採用する点、ビュー、用紙の大きさ、MTEXT の書式倍率を、小さい合成入力で確かめた（`synthetic`、`crates/zumen-acad/tests/finite.rs`・`drawing.rs`、#594）。診断のコード・件数・場所と、正常な要素の ID、L1 のバイト列も確かめている。この異常値の扱いは、AutoCAD では照らしていない。
- 同系統の再符号化（`synthetic`）。最小の共有オブジェクト表で、出力から除いた XRECORD と辞書項目の件数・元のバイト範囲、未対応の参照がある場合の経路の切り替え、予算と中断での停止を確かめた。CP932 の「ア」と「ヂ」を別々の画層に使い、「ソ」の後続バイトとバックスラッシュを区別して参照を引けた。不正な名前では試行中の出力を破棄した。
- 同系統の再符号化（`external`、#634・#641）。AutoCAD の公開 R2004 DWG をそのまま変換した場合と、`apply` で画層「Walls」または「外壁」を 1 件足してから変換した場合を ezdxf 1.4.5 で再読した。追加した名前と ACI 3 が一致した。3 通りとも対の公開 DXF と、弧長寸法 6 件の値・所有者・寸法スタイル、描画ブロックの図形 67 件の順序・参照、プロキシ画像 6 件の全バイト、リアクター 12 本が一致した。省いたリアクター 12 本の診断は元の図形のバイト範囲を指した。監査の誤り・修復はいずれも 0 件だった。変換結果を AutoCAD で開き直す実機照合は未実施。
- 画層の説明と透過性: ezdxf 1.4.5 で R2004 DXF の画層 0 と追加画層に「説明だけ」「透過性だけ」「両方」を設定し、公開 API で変換した。6 通りで再読した値・XDATA・APPID が一致し、監査の誤り・修復は 0 件だった。入力・出力それぞれへの変更なしの `apply` はバイト列が一致した（`external`、#635）。出力できない画層と、ANSI_932 で表せない説明については、フィールドごとの件数と入力位置を適合テストで確かめる（#633）。
- 書き: AutoCAD で作った R2000・R2004・R2010・R2018 の DXF に、引出線の置き換え・変換・追加と MULTILEADER の線の置き換えを当てて書き戻し、AutoCAD 2027 で開いた。監査の誤りは 0 で、形・矢印・注記が当てた値と合った（#345）。
- 「サンプルで確かめた」と書いた扱いには、`samples/` にない図面で確かめたものもある。「推定」と書いたものと、サンプルで確かめたと書いていないものは、仕様とテストの中で作ったファイルで確かめた。AutoCAD と照らしたのは上の範囲だけで、ezdxf と照らす値は下の項にある。
- DWG のスタイルとレイヤの変更（#723）: 公開サンプルの DWG（R2000・R2004・R2013・R2018）の要素と画層のレイヤ・色・線種・線種の倍率・線幅を変えて書き戻し、zumen で読み直して、変えた値が同じで、ほかの要素と画層が変わらないことを確かめた。検証キットの `723/` の組で、ACadSharp 3.8.0 と ezdxf 1.4.5 が書き戻したファイルを読み、変えた図形の画層と ACI の色が zumen の読みと同じだった（`external`。名前のある線種・線幅・RGB の色と、画層のレコードは照らしていない）。AutoCAD で開く確認は、まだしていない。
- 点・寸法・表と、引出線のほかの変更を書き戻した DXF と、convert で書いた DXF は、AutoCAD で開いていない（#342・#314・#503）。

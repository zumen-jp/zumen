# DXF

AutoCAD の系統のファイルモデル（L1）として DXF を読み書きする規則と、仕様が決めない所の扱いを記録します。実装は `crates/zumen-acad` の `dxf` です。旧版の知見（[旧版の DXF の扱い](https://github.com/zumen-jp/zumen-legacy/blob/main/docs/formats/dxf.md)）は、扱う範囲を広げるときに移します。

## 対象

- ASCII の DXF。版は問わず、タグの並びとして読む。
- バイナリの DXF は、まだ読まない。先頭が DXF Reference「Binary DXF Files」の印なら `dxf.binary.unsupported` を返す。

## レコードの区切り

- グループ・コードの行と値の行の組を、タグとして読む（DXF Reference「About ASCII DXF Files」）。
- グループ・コード 0 のタグから、次のグループ・コード 0 のタグの前までを、1 つのレコードにする。`SECTION`・`ENDSEC`・未知の種類も同じに扱う。
- 先頭がグループ・コード 0 でないタグ（コメントの 999 など）は、最初のレコードにまとめる。
- 値が `EOF` のグループ・コード 0 のタグで読むのをやめる。その後のバイトは、読まずにそのまま持つ。
- レコードは、改行も含めた元のバイト範囲を持ち、隣のレコードと隙間なく並ぶ。変えずに書くと、元のバイト列と一致する。

## 編集

- 変更は `DxfTxn` にためて、確定のときにまとめて反映する（[決定 0008](../decisions/0008-model-layers-and-codecs.md)）。1 つでも受け付けない変更があるか、予算で止まったら、何も反映しない。確定しないで捨てても、何も反映しない。
- 生の値は、レコードとタグの位置で名指しして置き換える。型付きの値は、グループ・コードで名指しする（今は実数だけ）。
- レコードとタグは、位置で名指しして足し、除ける（`insert_record`・`remove_record`・`insert_tag`・`remove_tag`）。レコードの位置は、確定するまで元のファイルの位置で名指しする。足したレコードには、確定するまで値の変更もタグの追加もできない。除いたレコードは、同じトランザクションでは名指しできない。
- `SECTION`・`ENDSEC`・`EOF` のレコードは、足すことも除くこともできない（`dxf.record.unsafe`）。セクションの区切りが変わるため。足すレコードは、最初のタグがグループ・コード 0 で、ほかは 0 以外でなければならない。レコードの先頭のタグは除けない。
- `new_handle` は、見出しの `$HANDSEED`（DXF Reference「HEADER Section Group Codes」）の値を新しいハンドルとして返し、`$HANDSEED` を 1 つ進める。足すレコードのハンドル（5）は、これで決めて呼び出し側が渡す。`$HANDSEED` がないか読めなければ `dxf.handle-seed.missing` を返す。
- 改行を含む値と、グループ・コード 0 の値の変更は受け付けない。読み直すと、タグとレコードの区切りが変わるため。
- 反映したレコードは、元のバイト範囲を持たなくなる。書くときは、そのレコードのタグを並べ直す。グループ・コードの行と改行は元のバイトを使い、値だけを差し替える。変えていないレコードは、元のバイトのまま書く。
- 共有のオブジェクトの表の変更は、`DxfFile::write_back` で書き戻す（[決定 0024](../decisions/0024-acad-table-write-back.md)）。今のファイルから作り直した表と元のレコードごとに比べ、値の並びが違うレコードだけを 1 つのトランザクションで直す。前と後ろの同じ値は元のタグのまま残し、間の値は、グループ・コードの並びが同じなら値だけを差し替え、違えばタグを除いて足し直す。見出しの変数も名前ごとに比べ、ファイルにない変数は HEADER の最後に足す。表から除いたオブジェクトのレコードは除き、表に足したオブジェクト（`Origin::New`）は、同じ所の後ろで最初の残したオブジェクトの前に、なければその所の ENDSEC の前に足す（[決定 0025](../decisions/0025-acad-object-add-remove-write-back.md)）。表のハンドルのどれかが `$HANDSEED` 以上なら、`$HANDSEED` を最大のハンドルの次に進める。値を変えたか足したモデル空間の図形が `$EXTMIN`・`$EXTMAX`（DXF Reference「HEADER Section Group Codes」）の外にあれば、図形を含むように範囲を広げる。変数の削除はまだ扱わない。この DXF の同じ種類・同じ所のレコードから読んでいないオブジェクト、同じレコードから読んだ 2 つ目のオブジェクト、ファイルにない所に足したオブジェクトは `dxf.object.unsupported` を返す。
- 図面モデルの変更（`zumen_drawing::Changes`）は、`Apply` の `apply` で書き戻す（[決定 0139](../decisions/0139-drawing-apply.md)）。今のファイルから表と図面モデルを作り、変更が指す出所の図形に当ててから `write_back` で書く。DWG も同じ当て方を使う。今は、実寸の空間の LINE の端点（10・20・11・21）と CIRCLE の中心と半径（10・20・40）の置き換えと、続くレコード（VERTEX・ATTRIB・SEQEND）を持たない図形の除去だけを扱う。置き換えは、レイヤ・色・線種・線幅が元の要素と同じときだけ当てる。出所の要素がなければ `dxf.element.missing`、扱えない変更は `dxf.change.unsupported` を返し、何も反映しない。
- 型付きの見方は、共有のオブジェクトの表の上にある（`Object::line`）。今は LINE（DXF Reference「LINE」）だけ。値を読めないときは、グループ・コードとともに理由を返す。DWG の表にも同じ見方を使う。
- `AcadDb::remove` で除いたオブジェクトへの参照のうち、DICTIONARY の項目（3 と次の 350・360）と、102 の組（`{ACAD_REACTORS` など）の中の 330・360 は、ほかのオブジェクトからも除く（DXF Reference「Common Group Codes for Objects」「DICTIONARY」）。参照を除いて空になった組は、組ごと除く。書き戻すと、直したオブジェクトのレコードも直る。
- まだ扱わないもの: ほかの変更に伴って直すもの（範囲を狭めること、用紙空間の範囲 `$PEXTMIN`・`$PEXTMAX`、組の外の所有者の参照 330 と、所有していたオブジェクトをまとめて除くこと、ブロックのレコードなど）、型付きの見方を広げること。

## 版の変更

- `Dxf::write_as` で、`$ACADVER` の値を名指しして書く（[決定 0008](../decisions/0008-model-layers-and-codecs.md)）。元と同じ版なら、そのまま書く。
- いまは AC1012〜AC1032（R13〜2018）から AC1009（R12）への変更だけを扱う。ほかの組は `dxf.version.unsupported` を返し、何も書かない。
- 残すのは HEADER・TABLES・BLOCKS・ENTITIES のセクションと、VPORT・LTYPE・LAYER・STYLE・VIEW・UCS・DIMSTYLE・APPID の表。ほかは書かず、セクションと表ごとに診断を返す。
- BLOCKS と ENTITIES では、R12 の種類の図形だけを書く。LWPOLYLINE・MTEXT・HATCH などは変換せずに書かず、`dxf.entity.dropped` を返す。
- サブクラスの印（100）、所有者への参照（330・360）、`{` と `}` で囲むアプリケーションの組（102）、表のハンドル（TABLES の中の 5 と 105）は、置き換える先のない構造として黙って除く。ほかの R12 にないグループ・コードのタグは書かず、`dxf.group-code.dropped` を返す。
- 見出しは、R12 にないグループ・コードの値を持つ変数を、変数ごと書かない。`$ACADVER` を AC1009 にし、図形のハンドルを残すので、`$HANDLING` がなければ 1 として足す。
- 2007 以降の版（UTF-8）から書くときは、ASCII でない文字を `\U+XXXX`（UTF-16 の単位ごと）にして、`dxf.text.equivalent` を返す。UTF-8 として読めない値は、バイト列のまま書く。
- 残すタグは、グループ・コードの行と改行を元のバイトのまま書く。
- まだ扱わないもの: LWPOLYLINE・MTEXT などの R12 の図形への変換、`*Model_Space` などのレイアウトのブロックの扱い、ほかの版の組、ezdxf や ODA の変換結果との比較。

## オブジェクトの表

- `DxfFile::objects` で、DXF と DWG が共有するオブジェクトの表（`AcadDb`）を作る（[決定 0023](../decisions/0023-acad-shared-object-table.md)）。
- セクションの中のレコードを、1 つずつオブジェクトにする。`SECTION`・`ENDSEC`・`EOF` と、セクションの外のもの（先頭のコメントなど）はオブジェクトにしない。見出しの変数は `SECTION` のレコードの中にあるので、オブジェクトにならない。
- 値は、グループ・コードの範囲で決めた型で読む（DXF Reference「Group Code Value Types」）。ハンドルとバイナリは 16 進として読む。
- 型どおりに読めない値は、元のバイト列のまま文字列として置き、`dxf.value.invalid` を返す。
- オブジェクトは、元のレコードの番号を持つ。予算の作業は、レコードごとに数える。
- 型付きの見方と図面モデルへの変換は、この表の上で行う。
- まだ扱わないもの: 表からの書き戻し。

## 境界から読む

- 境界の `open`（[決定 0016](../decisions/0016-boundary-message-details.md)）は、入力の先頭が判定の規則に合えば DXF として読み、文書の名前と `dxf` を返す。`capabilities` では、系統 `acad` の読める形式として示す。
- 予算は、コーデックが確かめる。入力の大きさは読む前に、作業はタグごとに、レコードはレコードごとに数える。
- 開いた文書は、L1 のファイルモデルとして `close` まで持つ。中身を返す op と、図面モデルへの変換は、まだ境界から呼べない。

## 図面モデルへの変換

- `DxfFile` の `Lift<Drawing2D>` で、図面モデル（L2、`crates/zumen-drawing`）を作る（[決定 0022](../decisions/0022-drawing2d-semantics-and-format-mapping.md)）。変換は共有のオブジェクトの表（[決定 0023](../decisions/0023-acad-shared-object-table.md)）の上で行い、DWG も同じ変換を使う（[DWG の扱い](dwg.md)）。`zumen-acad` の feature `drawing` にあり、外せば L1 だけを使える。
- 移す図形と値は、この節の各項に書く。移さない種類の図形は、種類ごとに `dxf.lift.dropped` を返す。
- モデル空間の図形は 1 つの実寸の空間に、ペーパー空間（67 = 1）の図形とビューポートは 1 枚の用紙に置く。用紙は、ペーパー空間に何かあるときだけ作る。
- 実寸の単位は `$INSUNITS` で決める。ないか長さの単位でなければ不明とし、`dxf.units.missing` を返す。mm とみなさない。
- 用紙の点は、`$PLIMMIN` を原点にして mm に直す。単位が不明なら直せないので、ペーパー空間の図形を移さず `dxf.paper-space.dropped` を返す。用紙の大きさは `$PLIMMIN` と `$PLIMMAX` から決め、なければ持たない。
- ビューポートは、縮尺 41 ÷ 45 の等方のビューと、中心 10・20 と幅 40・高さ 41 の矩形の切り抜きにする。69 = 1 のものは用紙そのものなので、ビューにしない。ねじれ（51）・視点の向き（16・26・36）・注視点（17・27・37）が既定でないものは、まだ移さず `dxf.viewport.unsupported` を返す。
- 画層は、表の LAYER のレコードを表の順に移す（[決定 0105](../decisions/0105-drawing-layers-and-order.md)）。凍結（70 の 1）か色（62）が負なら表示せず、290 が偽なら印刷せず、ロック（70 の 4）なら編集できないとする。凍結と非表示の違いは移さない。図形が表にない名前を指せば、定義のない画層として足す。ビューポートで凍結した画層（341）は、ビューで表示しない画層にする。341 が画層のレコードを指さなければ、その指定だけを除き `dxf.lift.invalid` を返す。
- 線種は、表の LTYPE のレコードを表の順に移し、線と間の長さ（49）の列を要素の空間の長さとして持つ（[決定 0106](../decisions/0106-drawing-color-line-type-weight.md)）。形か文字を持つ要素（74 が 0 でない）は長さだけを移し、`dxf.line-type-element.dropped` を返す。図形が表にない名前を指せば、定義のない線種として足す。
- 図形の色は、62 が 1〜255 なら ACI の符号、420 があれば RGB として持つ。62 が 0 なら部品の配置から、256 かないならレイヤから継承する。線種（6）は ByLayer・ByBlock を継承とし、ほかは名前で線種を指す。線幅（370）は、-1 と -2 を継承、-3 を文書の既定、0〜211 を 1/100 mm とする。範囲の外の値は `dxf.lift.invalid` を返す。画層の色は 62 の絶対値と 420、線種は 6、線幅は 370 から移す。`$LTSCALE` と `$LWDEFAULT` は、文書の線種の倍率と既定の線幅にする。
- 描く順は、モデル空間・ペーパー空間・記号の定義のブロックのレコードを指す SORTENTSTABLE で決める。並べ替えのハンドル（5）の小さいものから描き、表にない図形は自分のハンドルで並べ、同じなら入力の順にする。表がなければ入力の順とする。表が壊れているか、ハンドルのない図形があれば、入力の順のままにして `dxf.lift.invalid` を返す。
- 文字の高さ（40）は、宣言値（`dxf.TEXT.40`）として、図形の空間の長さで持つ。字形の高さとの関係は決めない。
- 文字の配置は、72・73 が両方 0 なら 10 の点に左・基準線で置く。72 が 3 なら Aligned、5 なら Fit として 10 と 11 の 2 点の間に置く。ほかは 11 の点に、72 と 73 の位置合わせで置く。
- 書式つきの文字（MTEXT）は、内容を 3 の並びの後に 1 を続けたものとし、元の内容と、書式の符号で分けた区間を持つ（[決定 0109](../decisions/0109-drawing-formatted-text.md)）。高さ（40）は `dxf.MTEXT.40` の宣言値にする。挿入点（10）・位置合わせ（71 の 1〜9 を上・中央・下の行の左・中央・右）・書き進める向き（72 の 1・3・5）・枠の幅（41）と高さ（46、どちらも 0 ならなし）・行送りの倍率（44）と種類（73 の 2 なら一定）・文字スタイル（7）を持つ。向きは X 軸の向き（11・21）があればそれを、なければ回転（50）をラジアンから度に直して持つ。背景（90）は、1 を色（63・421）、2 を表示の背景の色の塗り、16 を枠の線とし、倍率（45、既定 1.5）と透明度（441）を持つ。文字の範囲の大きさ（42・43）は内容から決まるので移さない。
- MTEXT の書式の符号は、AutoCAD のヘルプが示すもののうち、`{}`・`\P`・`\N`・`\~`・`\\`・`\{`・`\}`・`\L`・`\O`・`\K`（と小文字）・`\U+XXXX` と、`;` で閉じる `\H`・`\W`・`\T`（後ろの `x` は倍率）・`\Q`・`\A`・`\C`・`\f`・`\F`・`\S` を解釈する。対にならない `}`、ほかの符号、値を読めない符号は、元の符号のまま解釈しない区間にする。`\c` の値は 420 と同じバイト順か確かめていないので、`\p` は段落の書式なので、解釈しない（推定）。`%%d` などの TEXT の特殊な符号は、TEXT と同じく文字列のまま持つ。
- 段組み（75 が 0 でない）の MTEXT は移さず `dxf.mtext-columns.unsupported` を返す。R2018 からは段組みの欄を埋め込みのオブジェクト（101）に置くので、101 を持つ MTEXT も段組みとみなす（推定。試料の図面で確かめていない）。
- 寸法（DIMENSION）は、70 の下の 5 ビットで種類を分け、種類ごとの定義点（10・13〜16）を持つ（[決定 0107](../decisions/0107-drawing-dimensions-and-leaders.md)）。測定値（42）は `dxf.DIMENSION.42` のキーと組にして持ち、定義点から測り直さない。利用者の文字（1）は、ないか空か `<>` なら測定値を書く、空白 1 つなら書かない、ほかは元のまま上書きとし、書式の符号で区間に分ける。上書きの文字の `<>` は測定値を書く所、`\X` は寸法線の下の文字の始まりとする（[決定 0110](../decisions/0110-drawing-callouts-and-dimension-text.md)）。文字の中点（11）・回転（53）・位置合わせ（71）・利用者が動かした印（70 の 128）・寸法スタイル（3）・部品の名前（2）も持つ。半径と直径の引出線の長さ（40）は、図形の空間の長さにする。
- 引出線（LEADER）は、頂点（10・20・30）を経路とし、数（76）と合わなければ移さない。曲線か（72）・矢印（71）・寸法スタイル（3）を持ち、注記（340）は指すオブジェクトの出所で指す。
- 引出線つきの注記（MULTILEADER）は、値を区切り（300 `CONTEXT_DATA{`・301、302 `LEADER{`・303、304 `LEADER_LINE{`・305）で、図形・注記の文脈・枝・線に分けてから読む（[決定 0110](../decisions/0110-drawing-callouts-and-dimension-text.md)）。枝は、線ごとの頂点（10・20・30）・集まる点（290 が真なら 10）・折れ曲がり（291 が真なら向き 11・21 と長さ 40）を持つ。図形の 291 が偽なら、折れ曲がりを持たない。線の引き方（170）・端部記号（342 の指すブロックのレコード）・大きさ（42、なければ文脈の 140）・ランディング（290）・倍率（文脈の 40）・スタイル（340 の指すオブジェクトの出所）も持つ。
- MULTILEADER の注記は、文脈の 290 が真なら書式つきの文字、296 が真なら記号とする。文字は、内容（304）・高さ（41、`dxf.MULTILEADER.41`）・位置（12）・向き（13・23、なければ 42 のラジアン）・幅（43）と高さ（44）・行送り（45・170）・位置合わせ（171）・書き進める向き（172）・背景（292 が真なら、291 が真で表示の背景の色、偽で 91 の色、倍率 141、透明度 92）・文字スタイル（340 の指す STYLE）を持つ。記号は、ブロックのレコード（341）・位置（15）・尺度（16・26）・回転（46、ラジアン）と、図形の属性の定義（330 の指す ATTDEF）と値（302）の組を持つ。公差の注記（172 = 3）は移さず `dxf.lift.invalid` を、段組み（173）は `dxf.mtext-columns.unsupported` を返す。線ごとの端部記号（94・345）、線と注記の色・線種・線幅、寄せ方の欄、属性の番号（177）と幅（44）、変換の行列（47）は移さない。
- MULTILEADER の色（91 など）は、元の形式の色の値（AcCmColor）として、上の 1 バイトが 0xC2 なら下の 3 バイトを RGB、0xC3 なら下の 1 バイトを色の番号とする。ほかは読めないとする（推定。試料の図面で確かめていない）。
- 寸法スタイルは、表の DIMSTYLE のレコードを表の順に移し、端部記号と大きさを持つ（[決定 0108](../decisions/0108-drawing-symbols-hatches-arrowheads.md)）。端部記号は、両端を別にする（173）なら 343・344、しなければ両端とも 342、引出線は 341 の指すブロックのレコードの名前にし、0 かなければ既定の矢印とする。大きさ（41）・斜線の大きさ（142）・倍率（40）も持つ。指すものがブロックのレコードでないか、負の値なら、そのスタイルを移さず `dxf.lift.invalid` を返す。
- 記号（INSERT）は、ブロックの名前（2）を名前空間 `dxf.block` のキーにし、挿入点（10）・尺度（41・42）・回転（50）を持つ。列と行（70・71）が 1 より多ければ、間隔（44・45）とともに格子にする。属性（ATTRIB）は、所有者（330）が INSERT を指すもの、所有者がないものは属性が続く（66 = 1）INSERT の後から SEQEND までのものを、その記号のものとする。属性はタグ（2）・値（1）と TEXT と同じ欄を持ち、縦の位置合わせは 74 から読む。高さは `dxf.ATTRIB.40` の宣言値にする。70 の 1 は表示しない属性にする。複数行の属性は、埋め込みのオブジェクトの印（101）の後の値を MTEXT として読み、書式つきの値も持つ。印の直前の 71（属性の種類）と 72 は、1 行の値の欄から除く。埋め込みの値に文字スタイル（7）がなければ、属性のものとする。INSERT に従わない ATTRIB は、ほかの種類と同じく `dxf.lift.dropped` を返す。
- 記号の定義は、BLOCKS の BLOCK から作る（[決定 0112](../decisions/0112-drawing-symbol-definitions.md)）。中身は、所有者（330）をたどって着くブロックのレコードの BLOCK のもの、所有者が分からなければ、並びの中で前の BLOCK から ENDBLK までのものとし、図面の実寸の空間とは別の、定義ごとの空間に置く。名前は BLOCK の 2、なければブロックのレコードの 2。基点（10）・名前のない定義（70 の 1、または名前が `*` で始まる）・外部参照のパス（70 の 4 なら 1）を持つ。ATTDEF は、ATTRIB と同じ欄と、値を尋ねる文（3）・印（70 の 2・4・8 を、値が決まっている・確かめる・尋ねない）を持つ属性の定義にする。空間のブロック（`*Model_Space`・`*Paper_Space`）は移さない。どの BLOCK のものか分からない図形と、名前のない BLOCK は、`dxf.lift.invalid` を返す。配置は展開しない。配置（INSERT）と、表・セル・寸法・引出線つきの注記・寸法スタイルが指す定義がなければ `dxf.block.missing` を、定義の中の配置をたどって自分に戻る定義には `dxf.block-cycle.invalid` を返し、どちらも配置と定義は移す（[決定 0116](../decisions/0116-drawing-symbol-references.md)）。
- 表（ACAD_TABLE）は、AcDbTable（100）より前の挿入点（10）と、表を描いたブロック（2）を読む（[決定 0113](../decisions/0113-drawing-tables-and-title-blocks.md)）。後の値からは、行と列の数（91・92）・横の向き（11・21）・表のスタイル（342）・行の高さ（141）・列の幅（142）と、種類（171）で始まるセルを読む。セルは、覆われる（173）・広げる列と行の数（175・176）と、種類が 1 なら文字（2 の区切りと 1）、2 ならブロックのレコード（340）を内容に持つ。1 も 2 もなければ、2007 からの値（301 `CELL_VALUE` から 304 `ACVALUE_END` まで）の表示する文字（302）を内容にする。値は、印（93）・型（90）・型ごとの値（文字なら 1 に元の文字）・単位（94）・書式（300）・表示する文字（302）の順に並ぶ。302 は書式を当てた後の文字（試料では、1 が `cell format 1`、書式が `%tc1` のとき `CELL FORMAT 1`）なので、表示に合う。値の中のほかのコードは、セルの欄として読まない。R2010・R2013・R2018 の試料の DXF で確かめた。数が合わなければ `dxf.lift.invalid` を返す。表題欄の役割は DXF にないので、属性を持つ記号のまま持ち、表題欄と推定しない。
- 下敷きは、IMAGE と PDFUNDERLAY・DWFUNDERLAY・DGNUNDERLAY を移す（[決定 0114](../decisions/0114-drawing-underlays.md)）。定義（340 の指す IMAGEDEF・PDFDEFINITION など）の参照名（1）を資源とし、ファイルは開かない。IMAGE は、挿入点（10）と 1 画素の横と縦（11・12）、画素の数（13・23）から左下・右下・左上の角を持ち、70 の 1 を表示する、280 が 1 なら境界（71・91・14）で切り抜き、290 が真なら内側を隠す。下敷きは、定義のページなどの名前（2）・挿入点（10）・尺度（41・42）・回転（50）を持ち、280 の 2 を表示する、1 なら境界（11）で切り抜き、16 なら内側を隠す。描く順は、ほかの図形と同じく SORTENTSTABLE と入力の順で決める。
- 図形の XDATA は、登録アプリケーション名（1001）ごとに、名前空間 `dxf.xdata` の形式固有の情報にする（[決定 0115](../decisions/0115-drawing-format-extensions.md)）。版は `$ACADVER` とし、値は並びの順に、グループ・コード（1000・1002〜1005・1010〜1013・1040〜1042・1070・1071）の意味で名付ける。点は続く Y（+10）と Z（+20）と合わせる。読んだときの図形の値も持ち、図形を編集すれば失効したとする。最初の 1001 より前の XDATA の値と、読めない値を持つ名前の分は `dxf.lift.invalid` を返す。
- 図面モデルの値にない図形の欄は、名前空間 `dxf.entity`（版 1）の形式固有の情報にする（[決定 0142](../decisions/0142-dxf-entity-extension.md)）。厚さ（39）は、LINE・CIRCLE・ARC・TEXT・LWPOLYLINE・POLYLINE・SOLID・TRACE・POINT・SHAPE で 0 でなければ `thickness`（実数）に、LWPOLYLINE・POLYLINE の線種の生成（70 の 128）は立っていれば `line_type_generation`（整数の 1）にする。SPLINE の節点・制御点・当てはめの許容差（42・43・44）は、あれば `knot_tolerance`・`control_tolerance`・`fit_tolerance`（実数）にする。試料の DWG と DXF の組で、どの欄も一致することを確かめた。どの欄もない図形は、この拡張を持たない。
- ハッチング（HATCH）は、境界の輪の数（91）から後の値を並びの順に読む。輪ごとに、印（92）の 2 が立てば膨らみ（42）のある頂点の折れ線、立たなければ線分・円弧・楕円弧・SPLINE の辺の並びとし、印の 1・4・8・16 を外側・境界を探した・文字の枠・いちばん外とする。輪を作った図形（330）は出所で指す。島（75）・パターンの出どころ（76）・回転（52）・尺度（41）・重ねるか（77）・線の組（53・43〜46・49）・境界を探した点（98・10・20）を持つ。塗り（70 = 1）はパターンの欄を読み飛ばし、450 が 1 ならグラデーションにする。SPLINE の辺（72 = 4）は、次数（94）・有理（73）・周期的（74）・節点（95・40）・制御点（96・10・20）と、有理なら重み（42）を読む。2010（AC1024）以降の版の DXF では、続く当てはめる点（97・11・21）と、あれば接線（12・13）も読む（[決定 0111](../decisions/0111-drawing-curves.md)）。
- 曲線は元の定義のまま移す（[決定 0111](../decisions/0111-drawing-curves.md)）。CIRCLE は中心（10）と半径（40）、ARC はさらに始まりと終わりの角度（50・51、度）を持つ。ELLIPSE は中心（10）・中心からの長軸の端（11）・比（40）と、始まりと終わりのパラメーター（41・42、ラジアン）を度に直して持つ。LWPOLYLINE は、頂点（10・20）ごとに続く始まりと終わりの幅（40・41）と膨らみ（42）・閉じているか（70 の 1）・一様な幅（43）を持ち、頂点の数（90）と合わなければ移さない。古い POLYLINE は、続く VERTEX（所有者が指すか、66 が 1 の POLYLINE から SEQEND まで）を頂点にし、VERTEX の点（10・20）・膨らみ（42）・始まりと終わりの幅（40・41、なければ 0）と、閉じているか（70 の 1）を持つ。どの頂点の幅も同じなら一様な幅にする。POLYLINE の既定の幅（40・41）は新しい頂点のためのものなので使わない。3D の折れ線（70 の 8）は Z がどれも 0 なら移す。曲線かスプラインで当てはめたもの（70 の 2・4）と、網・多面（16・64）は移さず `dxf.lift.dropped` を返す。SPLINE は、印（70 の 1・2・4 を閉じている・周期的・有理）・次数（71）・節点（40）・制御点（10）・重み（41）・当てはめる点（11）・接線（12・13）を持ち、数の欄（72〜74）や次数と合わなければ移さない。標高（LWPOLYLINE の 38、POLYLINE の 30）や Z が 0 でなければ平面に移さない。
- Z が 0 でない点と、押し出しの向き（210・220・230）が Z でない図形は、Z を捨てて移さず、`dxf.non-planar.dropped` を返す。
- 要る値がないか読めないか範囲の外なら、その図形を移さず `dxf.lift.invalid` をグループ・コードとともに返す。どの診断も、元のレコードを指す。
- 2007 以降の版は、文字の値を UTF-8 として読む。それより前の版の ASCII でない文字は、コード・ページを読まないので、その図形を移さず `dxf.code-page.unsupported` を返す。
- まだ扱わないもの: 当てはめた古いポリライン（POLYLINE）と網・多面、SOLID・POINT などほかの図形、ARC_DIMENSION、端部記号のほかの寸法スタイルの値と、拡張データで上書きした値の解釈、拡張辞書と独自のオブジェクト、寸法の部品の展開、ブロックの展開とブロックのレコードの単位（70）、ほかのレイアウトの空間のブロック、段組みの MTEXT、表のセルの書式・枠と値の種類、公差、複数のレイアウト、ねじれと 3D のビュー、多角形の切り抜き、コード・ページの文字。

## 推定した扱い

仕様の文からは決まらないため、次のように扱います。実際のファイルで確かめたら、ここを直します。

| 所 | 扱い | 理由 |
| --- | --- | --- |
| 改行 | LF と CR LF のどちらも行の終わりとする。最後の行に改行がなくてもよい | 改行の種類で読めなくならないように。元のバイトは書くときに残る |
| グループ・コードの行 | 前後の ASCII の空白を除いて、符号つきの整数として読む | 仕様の例は右寄せだが、桁の揃え方の違いで読めなくならないように |
| 値の行 | 改行を除いた生のバイト列として持つ。空白も文字コードも変えない | 文字コードは `$DWGCODEPAGE` と版で決まるため、L1 では解釈しない |
| `EOF` がない | 最後のタグまでを読み、診断は出さない | 試作の範囲では、壊れた終わりの扱いを決めていない |
| 形式の判定 | 先頭の 2 行が、空白を除いて `0` と `SECTION` | 999 のコメントで始まるファイルは、まだ判定しない |
| 実数の値を読む | 前後の空白を除いて 10 進の実数として読む。指数の表記を許し、有限でないものは読めないとする | 仕様の例には指数の表記（`1.0E+20` など）がある |
| ハンドルの値 | 空のもの、符号の付いたもの、64 ビットを超えるものは読めないとする | ハンドルは 16 進の符号のない数のため |
| 真偽の値（290〜299） | 0 と 1 だけを読む | ほかの値の意味を仕様の文から決められないため |
| 足したタグの書き方 | グループ・コードを 3 桁に右寄せし、ファイルの最初の行と同じ改行（CR LF か LF）で書く。値はそのまま書く | 仕様の例と AutoCAD の出力が右寄せのため。1 つのファイルで改行を混ぜないため |
| `$HANDSEED` の書き方 | 次のハンドルを、0 で埋めない大文字の 16 進で書く | 仕様の例のハンドルが大文字の 16 進のため |
| 書き戻す値の書き方 | 整数は 10 進、真偽は 0 と 1、ハンドルとバイナリは 0 で埋めない大文字の 16 進（バイナリは 1 バイトを 2 桁）、文字列はそのまま書く | 表を作るときの読み方の逆で、読み直すと同じ値になるため。元の桁揃えは、値を変えたタグでは保たない |
| 実数の値を書く | 読み直すと同じ値に戻る最短の 10 進の表記にする。指数は使わず、整数の値にも小数点を付ける | どの環境でも同じバイト列にするため（決定 0007） |
| 書き戻しで広げる図面の範囲 | 値を変えたか足したモデル空間の図形のうち、LINE・POINT と、押し出しの向きが既定の CIRCLE だけを囲む。範囲は狭めない。変数がないか、10・20・30 の実数を持たなければ直さない | 囲む箱を値だけから決められる図形に限るため。除いた図形の分を狭めるには、ほかの図形の範囲がすべて要るため |
| 画層と線種の名前を引く | ASCII の大文字と小文字を区別しない。同じ名前のレコードが 2 つあれば、先のものを指す | AutoCAD が画層の名前の大文字と小文字を区別しないため。仕様の文からは決まらない |
| DIMENSION の移さない欄 | 複製の挿入点（12）・行間（41・72）・水平の向き（51）は移さない。70 の 8・16 のビットは見ない | どれも寸法の意味を変えず、描く形は部品が持つため。8・16 は仕様の文にない |
| DIMENSION の測定値（42） | 単位を決めず、`dxf.DIMENSION.42` のキーと組にして持つ | 仕様の文は「実際の測定値」とだけ書く。角度の寸法の値は、DWG の値（ODS ではラジアン）と DXF の値が合うので、ラジアンと見られるが、試料で確かめていない |
| LEADER の移さない欄 | 注記の種類と大きさ（73・40・41）・鉤の線（74・75）・ずれ（212・213）・X 軸の向き（211）は移さない。矢印（71）がなければ寸法スタイルに従うとする | 経路と注記の参照があれば、注記との組の意味は保てるため。DWG の R2000 以降は矢印の欄を持たない |
| DIMSTYLE の既定の値 | 値のない欄は、DIMSCALE（40）を 1、DIMASZ（41）を 0.18、DIMTSZ（142）を 0、DIMSAH（173）を偽とする。R12 の名前の端部記号（5〜7）は読まない | DWG の読み手が、既定の値と同じ欄を置かないため。値は DXF Reference の見出しの変数の既定の値（インチの図面）で、メートルの図面の既定の値とは違う |
| INSERT の Z の尺度（43） | 移さない | 平面の図形を置くかぎり、平面の形を変えないため。定義に Z のある図形があるかは、定義を移すときに確かめる |
| HATCH の移さない欄 | 密度の画素の大きさ（47）、グラデーションの色の番号（63）と値（463）は移さない | 47 は表示のための値のため。グラデーションの色は RGB（421）で決まり、63 は仕様の文で役割が決まらないため |
| HATCH の境界の図形の数（97） | 輪の最後の 97 の数だけ 330 を読み、合わなければ移さない。DWG は 330 を置かないので空にする | 境界を作った図形を黙って落とさないため。SPLINE の辺の当てはめる点の数も 97 なので、2010（AC1024）以降の版の SPLINE の辺だけが当てはめる点を持つとして読み分ける（決定 0111、試料で確かめていない） |
| 下敷きの切り抜きの反転（280 の 16） | IMAGE の 290 と同じく、内側を隠すこととする | DXF Reference「UNDERLAY」は「Clip inside mode」とだけ書き、試料の図面に切り抜いた下敷きがない |
| 下敷きの切り抜きの頂点（14・11） | 元の形式の下敷きの座標のまま持つ。画像では画素の座標、下敷きでは内容の座標とする | 座標の意味を試料で確かめていない（決定 0114） |
| R12 のグループ・コード | 0〜79、210〜239、999、1000〜1071 とする | ほかの値の型（90 台の 32 ビットの整数など）は R13 以降で足されたため。実際の R12 の読み手では確かめていない |
| R12 の図形の種類 | 3DFACE・ARC・ATTDEF・ATTRIB・BLOCK・CIRCLE・DIMENSION・ENDBLK・INSERT・LINE・POINT・POLYLINE・SEQEND・SHAPE・SOLID・TEXT・TRACE・VERTEX・VIEWPORT とする | 版ごとの図形の一覧から。R12 で範囲内のコードの意味が変わったものは確かめていない |
| R12 の見出しの未知の変数 | 値のグループ・コードが R12 の範囲なら、残す | 知らない変数を落とさないため。R12 の読み手が無視するかは確かめていない |
| 版の比べ方 | `$ACADVER` の値を、前後の空白を除いたバイト列として比べる | 版の名は `AC` と 4 桁の数字で、辞書順が新旧の順になる |
| LINE の Z がない | 0 とみなす | 2D の図面では Z を省いたファイルがあるため |
| 用紙の単位 | 実寸と同じ `$INSUNITS` とする | ペーパー空間の単位を別に決める変数を確かめていない |
| 用紙の原点 | `$PLIMMIN` とし、なければ（0,0）とする | 決定 0019 の用紙の左下に合わせるため。印刷の設定の余白は見ていない |
| 用紙そのもののビューポート | 69 = 1 のものとする | ビューポートの ID の 1 は、ペーパー空間そのものを表すため |
| ビューの中心 | 12・22 を、注視点を原点にした実寸の座標とする。注視点が既定でないものは移さない | 注視点を足す向きを、実際のファイルで確かめていない |
| 押し出しの向きがない | （0,0,1）とみなす | 既定の値のため |
| TEXT の既定の値 | 50・51 は 0、41 は 1、7 は STANDARD、71・72・73 は 0 とする | 省いたファイルがあるため |

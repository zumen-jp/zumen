# DXF

AutoCAD の系統のファイルモデル（L1）として DXF を読み書きする規則と、仕様が決めない所の扱いを記録します。実装は `crates/zumen-acad` の `dxf` です。旧版の知見（[旧版の DXF の扱い](https://github.com/zumen-jp/zumen-legacy/blob/main/docs/formats/dxf.md)）は、扱う範囲を広げるときに移します。

## 対象

- ASCII の DXF。版は問わず、タグの並びとして読む。
- バイナリの DXF（DXF Reference「Binary DXF Files」）。先頭の印で見分け、各タグを ASCII の DXF の表現にしてから、ASCII の DXF と同じに扱う（[バイナリの DXF](#バイナリの-dxf)）。

## バイナリの DXF

- 先頭の 22 バイト `AutoCAD Binary DXF` CR LF SUB NUL の後に、グループ・コードと値の組が続く。数はリトル・エンディアン。
- グループ・コードの幅は、最初のタグ（`0 SECTION`）で決める。印の後が NUL・NUL・`S` なら 2 バイトの符号つき整数（R13 から）、NUL・`S` なら 1 バイト（R12）。1 バイトのとき、255 は続く 2 バイトがグループ・コードであることを表す（推定）。
- 値のバイト列は、グループ・コードの型（DXF Reference「Group Code Value Types」）で決める。文字列とハンドルは NUL で終わるバイト列、実数は 8 バイト、整数は 60〜79・170〜179・270〜289・370〜389・400〜409・1060〜1070 が 2 バイト、90〜99・420〜429・440〜459・1071 が 4 バイト、160〜169 が 8 バイト、真偽（290〜299）は 1 バイト、バイナリ（310〜319・1004）は長さの 1 バイトとその長さのバイト列。整数の幅の割り当てと、280〜289 を 2 バイトとすることは推定。試料の R12・2000・2004・2007・2010・2013・2018 のバイナリの DXF で、どのタグも途中で切れずに末尾ちょうどで終わることを確かめた。
- ASCII の表現は、グループ・コードを 3 桁に右寄せした行と値の行で、改行は LF。実数は読み直すと同じ値に戻る最短の 10 進の表記、整数と真偽は 10 進、バイナリは大文字の 16 進。文字列の制御文字は、同じ図面の ASCII の DXF と同じく `^J` のように `^` と文字で書き、`^` 自身は `^ ` と書く（推定。試料の MTEXT の改行で確かめた）。
- レコードの範囲（`RecordInfo` のバイト範囲）は、元のバイナリのバイト範囲。
- 途中で切れたタグと、有限でない実数の値は、`dxf.binary.invalid` を返し、読まない。
- 書くときは、変えていないレコードの元のバイトを並べ、変えたレコードのタグを元と同じ幅のグループ・コードで符号化し直す。どのレコードも同じ値で書き換えたものとして符号化し直すと、試料のすべての版で元のバイト列と一致する。
- 変更の値は、変更のときにグループ・コードの型のバイト列にできるかを確かめ、できなければ `dxf.binary-value.unsupported` を返す（数でない数の値、型の幅を超える整数、奇数の桁や 255 バイトを超えるバイナリ、NUL を含む文字列、読みが作らない `^` の並び）。
- 同じ図面のバイナリと ASCII の DXF の組（試料の 7 つの版）で、図面モデルと出る診断の種類が一致することを確かめた。数は相対の誤差 1e-9 の中で一致する。R12 の組は、ASCII の DXF がポリラインの頂点を 6 桁に丸めて書くので、1e-5 の中で一致する。
- まだ扱わないもの: バイナリの DXF の版の変更（`dxf.version.unsupported`）、ASCII の DXF との相互の変換。

## レコードの区切り

- グループ・コードの行と値の行の組を、タグとして読む（DXF Reference「About ASCII DXF Files」）。
- グループ・コード 0 のタグから、次のグループ・コード 0 のタグの前までを、1 つのレコードにする。`SECTION`・`ENDSEC`・未知の種類も同じに扱う。
- 先頭がグループ・コード 0 でないタグ（コメントの 999 など）は、最初のレコードにまとめる。
- 値が `EOF` のグループ・コード 0 のタグで読むのをやめる。その後のバイトは、読まずにそのまま持つ。
- レコードは、改行も含めた元のバイト範囲を持ち、隣のレコードと隙間なく並ぶ。変えずに書くと、元のバイト列と一致する。

## 編集

- 変更は `DxfTxn` にためて、確定のときにまとめて反映する（[決定 0008](../decisions/0008-model-layers-and-codecs.md)）。1 つでも受け付けない変更があるか、予算で止まったら、何も反映しない。確定しないで捨てても、何も反映しない。
- 生の値は、レコードとタグの位置で名指しして置き換える。型付きの値は、グループ・コードで名指しする（今は実数だけ）。
- レコードとタグは、位置で名指しして足し、除ける（`insert_record`・`remove_record`・`insert_tag`・`remove_tag`）。レコードの位置は、確定するまで元のファイルの位置で名指しする。足したレコードには、確定するまで値の変更もタグの追加もできない。除いたレコードは、同じトランザクションでは名指しできない。
- `SECTION`・`ENDSEC`・`EOF` のレコードは、足すことも除くこともできない（`dxf.record.unsafe`）。セクションの区切りが変わるため。足すレコードは、最初のタグがグループ・コード 0 で、ほかは 0 以外でなければならない。レコードの先頭のタグは除けない。
- `new_handle` は、見出しの `$HANDSEED`（DXF Reference「HEADER Section Group Codes」）の値を新しいハンドルとして返し、`$HANDSEED` を 1 つ進める。足すレコードのハンドル（5）は、これで決めて呼び出し側が渡す。`$HANDSEED` がないか読めなければ `dxf.handle-seed.missing` を返す。
- 改行を含む値と、グループ・コード 0 の値の変更は受け付けない。読み直すと、タグとレコードの区切りが変わるため。
- 反映したレコードは、元のバイト範囲を持たなくなる。書くときは、そのレコードのタグを並べ直す。グループ・コードの行と改行は元のバイトを使い、値だけを差し替える。変えていないレコードは、元のバイトのまま書く。
- 共有のオブジェクトの表の変更は、`DxfFile::write_back` で書き戻す（[決定 0024](../decisions/0024-acad-table-write-back.md)）。今のファイルから作り直した表と元のレコードごとに比べ、値の並びが違うレコードだけを 1 つのトランザクションで直す。前と後ろの同じ値は元のタグのまま残し、間の値は、グループ・コードの並びが同じなら値だけを差し替え、違えばタグを除いて足し直す。見出しの変数も名前ごとに比べ、ファイルにない変数は HEADER の最後に足す。表から除いたオブジェクトのレコードは除き、表に足したオブジェクト（`Origin::New`）は、同じ所の後ろで最初の残したオブジェクトの前に、なければその所の ENDSEC の前に足す（[決定 0025](../decisions/0025-acad-object-add-remove-write-back.md)）。表のハンドルのどれかが `$HANDSEED` 以上なら、`$HANDSEED` を最大のハンドルの次に進める。値を変えたか足したモデル空間の図形が `$EXTMIN`・`$EXTMAX`（DXF Reference「HEADER Section Group Codes」）の外にあれば、図形を含むように範囲を広げる。変数の削除はまだ扱わない。この DXF の同じ種類・同じ所のレコードから読んでいないオブジェクト、同じレコードから読んだ 2 つ目のオブジェクト、ファイルにない所に足したオブジェクトは `dxf.object.unsupported` を返す。
- 図面モデルの変更（`zumen_drawing::Changes`）は、`Apply` の `apply` で書き戻す（[決定 0139](../decisions/0139-drawing-apply.md)）。変更は、要素を ID と読んだときの要素のハッシュで指し（[決定 0156](../decisions/0156-drawing-stable-ids-and-preconditions.md)）、あれば読んだときの文書のハッシュを持つ。今のファイルから表と図面モデルを作り、ID から要素を引いて、変更が指す図形に当ててから `write_back` で書く。記号の定義の中の要素は、BLOCK のハンドルで作る定義の空間の ID（`space/h1F/h2A`）で指し、BLOCKS の中の図形に当てる。名前のある定義の空間には要素を足せる（[決定 0177](../decisions/0177-drawing-apply-leaders-and-definitions.md)）。DWG も同じ当て方を使う。今は、実寸の空間と用紙の次の形の置き換え（`Edit::Replace`）と、続くレコード（VERTEX・ATTRIB・SEQEND）を持たない図形の除去（`Edit::Remove`）と、スタイルの変更（`Edit::Restyle`）と、アフィン変換での移動（`Edit::Transform`）と、追加（`Edit::Add`）を扱う。用紙の要素は、用紙の ID で指して置き換え、用紙の mm を、読むときと逆に、図面の単位に戻して用紙の原点を足して書く。ほかのレイアウトの用紙の図形は、BLOCKS のペーパー空間のブロックの中にあり、そこで直す。変えていない点は、元の値を写す（戻した値が最後の桁で違うことがあるため）。
  - LINE の端点（10・20・11・21）、CIRCLE の中心と半径（10・20・40）。
  - ARC の中心・半径・角度（10・20・40・50・51）。時計回りの弧は、始まりと終わりを入れ替えて反時計回りで書く。
  - ELLIPSE の中心・長軸の端・比・パラメーター（10・20・11・21・40・41・42）。比は 0 より大きく 1 以下に限る。読むときに度へ直したパラメーターと長軸の端は、変わったときだけ書き、変えていない欄の最後の桁を変えない。
  - LWPOLYLINE の頂点・膨らみ・閉じていること・幅（90・70 の 1・43・10・20・40・41・42）。頂点の前と後の値は写し、頂点の欄を並べ直す。膨らみは 0 でないものだけ、頂点ごとの幅は図面モデルが持つときだけ書く。頂点の ID（91）を持つのに頂点の数が変わるもの、頂点の間にほかの値があるもの、一定の幅と頂点ごとの幅の両方を持つものは扱わない。
  - TEXT の内容・高さ・回転・幅の倍率・斜体の角度・反転・置く点（1・40・50・41・51・71 の 2 と 4・10・20・11・21）。位置合わせ（72・73）、2 点の間への合わせ方、文字スタイル、高さの意味は変えられない。左の基準線に置く文字は 10 を、ほかの位置合わせの文字は 11 を動かし、10 も同じだけ動かす（10 は位置合わせから決まる点で、ほかのソフトが読むため）。2007 より前の版には ASCII の文字だけを書き、改行は書かない。省いた回転・幅の倍率・斜体の角度・反転は、既定の値でないときだけ足す。
  - MTEXT の内容・置く点・高さ・回転・枠の幅と高さ・置き方・行の間隔（1・3・10・20・40・50 または 11・21・41・46・71・73・44）。内容は 250 バイトごとに文字の途中と `^` の表記の途中で切らずに 3 へ分け、残りを 1 に書く。2007 より前の版には ASCII の文字だけを書き、改行は書かない（改行は `\P` で書く）。区間（`spans`）は内容から決まるので、内容を読んで得る区間と違うものは扱わない。回転は、角度（50）と向き（11・21）のうち元と同じ持ち方でだけ変えられる。向きを変えるときは、角度（50）が残っていれば除く。行の間隔の倍率（44）は 0.25〜4 に限る。文字スタイル・流れの向き・背景・高さの意味は変えられない。
  - INSERT の置く点・尺度・回転（10・20・41・42・50）。省いた尺度と回転は、既定の値（1 と 0）でないときだけ足す。格子の間隔（44・45）も、変わったときだけ書く（変換で負になることもある）。定義（2）・格子の有無と列と行の数（70・71）・切り抜きは変えられない。属性は、値だけを変えられる。値を変えた属性は、続く ATTRIB の値（1）を書き直し、ほかの欄は変えない。書式つきの値（複数行の属性）を持つ属性の値は変えられない。属性を持つ INSERT も置き換えられるが、続く ATTRIB は動かさない（図面モデルの属性は、それぞれの置く点を持つ）。DWG は回転をラジアンで持つので、読み直した値（度）が最後の桁で違うことがある。
  - LEADER の経路・スプラインか・矢印（10・20・30・76・72・71）。経路が変われば頂点を並べ直し、Z は 0 で書く。寸法スタイル（3）と注記（340）は変えられない。DWG は R2000〜R2004 だけで、矢印は書かない（[決定 0177](../decisions/0177-drawing-apply-leaders-and-definitions.md)）。
  - POINT の位置と X 軸の角度（10・20・50）。角度は、省けば 0 なので、0 でないときだけ足す。見え方は文書の点の表し方（`$PDMODE`・`$PDSIZE`）が決めるので、既定義の印の点と作図の補助の点にはできない。文書の点の表し方の変更は受け付けない（[決定 0183](../decisions/0183-drawing-apply-points.md)）。
  - 置き換えた図形の XDATA と拡張辞書は、元のまま書き戻す。形を変える置き換えで、元の図形が図形とともに動く XDATA（1011〜1013・1041・1042）を持てば、変更をすべて反映せず `change.xdata.unsupported` を返す（[決定 0154](../decisions/0154-drawing-apply-keeps-format-data.md)）。
  - 当てる前に、すべての変更を確かめる。文書のハッシュが今のファイルを書いたバイト列のハッシュと違えば `change.document.stale`、ID の要素か足す先の空間・用紙がなければ `change.element.missing`、要素のハッシュが今と違えば `change.element.stale`、扱えない変更は `change.edit.unsupported`（変更の種類・要素の種類・形式を値に持つ）を返し、何も反映しない。最初の 1 つで止めない。変えていないファイルは元のバイトのまま書くので、文書のハッシュは読んだバイト列（バイナリの DXF も）のハッシュと同じになる。
  - `Edit::Restyle` は、レイヤ・色・線種・線種の倍率・線幅のうち、指した欄だけを変える。形は変えない。変わった欄の値（8・6・62 と 420 と 430・370・48）だけを、図形に共通の値（区切りを持てば AcDbEntity の区切りの中、持たなければ XDATA の前）から除き、追加と同じ書き方でレイヤ（8）の後に書く。ほかの値と XDATA は元のまま写す。レイヤと線種は表の定義を引いて定義の名前で書き、定義がなければ当てない。線幅は R2000 から、RGB の色は R2004 からの DXF に限る。DWG は、今ある図形の色（ACI）と線種の倍率だけを書き戻せるので、レイヤ・線種・線幅・RGB の色を変える `Restyle` は `change.edit.unsupported` にする。属性を持つ INSERT のスタイルを変えても、続く ATTRIB のスタイルは変えない。
  - `Edit::Transform` は、要素の形をアフィン変換で写し（`zumen_drawing::transform`）、置き換えと同じ書き方で書く。LINE と、膨らみと幅を持たない LWPOLYLINE は、どの変換（向きがつぶれないもの）でも写す。CIRCLE・ARC・ELLIPSE と、膨らみか幅を持つ LWPOLYLINE は、相似（等方の尺度・回転・鏡映・平行移動）でだけ写す。鏡映は、角度とたどる向き・膨らみの符号を逆にする。TEXT と INSERT と POINT は相似で写す。鏡映は、TEXT と ATTRIB では上下の反転の印（71 の 4）を入れ替え、INSERT では Y の尺度（42）の符号を変え、回転を φ − θ にして表す。反転は、斜体と幅の倍率を当てた字形に、文字の基点のまわりで当てるものとして扱い、斜体の角度（51）は変えない（推定）。MTEXT は反転の印を持たないので、鏡映を含まない相似でだけ写し、MTEXT の属性を持つ INSERT も鏡映しない。格子の間隔（44・45）には尺度を掛け、鏡映では、記号の Y の向きに並ぶ行の間隔（45）の符号を変える。それ以外の変換は `change.edit.unsupported` にする。R2004 から後の DWG の MINSERT は、持つオブジェクトの数を列と行の欄の前に読み書きして書き戻す（[決定 0161](../decisions/0161-dwg-r2004-minsert.md)）。AutoCAD で作った MINSERT の試料がないので、足した MINSERT を変換して確かめた。
    - 図形とともに動く XDATA は、AutoCAD と同じ規則で直す。位置（1011・1021）は変換で写し、変位（1012・1022）は平行移動を除いて写し、向き（1013・1023）は写してから元の長さにそろえる。距離（1041）と倍率（1042）は尺度を掛けるので、相似でない変換では当てない。用紙の図形の XDATA は、用紙の mm と図面の単位の違いを直せないので、動く XDATA を持つ用紙の図形は当てない。
    - 属性を持つ INSERT は、続く ATTRIB の置く点・高さ・回転も同じ変換で直す。MTEXT の形の属性を持つ INSERT は当てない。
  - 置き換えは、レイヤ・色・線種・線幅・透過性が元の要素と同じときだけ当てる。スタイルを変えるときは `Edit::Restyle` を使う。2 つ以上の要素を作ったレコードの要素（ID の終わりに `/1` などを持つものと、その最初の要素）は、置き換えも除去もしない。
  - `Edit::ReplaceLayer` と `Edit::AddLayer` は、画層の表のレコードを置き換え、足す（[決定 0162](../decisions/0162-drawing-layer-changes.md)）。置き換えは、元のレコードの 2・70・62・420・6・290・370 だけを書き直す。表示しない画層は色の番号を負にし、凍結した画層の番号は負にしない。名前を変えたら、図形の 8、XDATA の 1003、`$CLAYER` も新しい名前にする。OBJECTS のオブジェクトが画層を名前（8）で指していれば当てない。足すときは、画層 0 のレコードを写し、ハンドル・拡張辞書と反応子の組・拡張データ・真の色を除いてから同じ欄を書き、新しいハンドルで画層の表の ENDTAB の前に置く。名前の重なり（大文字と小文字を区別しない）、使えない文字、画層 0 と Defpoints の名前の変更、凍結して表示する状態、番号のない色、版が持てない値は `change.edit.unsupported` にする。`Edit::RemoveLayer` は、画層の表のレコードを除く。ほかのオブジェクトかヘッダーの変数が、画層をハンドルか名前（8・1003）で指していれば除かない。後ろにハンドルのないレイヤがあれば、その ID が変わるので除かない。画層 0・Defpoints・外部参照に依る画層と、反応子を持つ画層も除かない。拡張辞書を持つ画層は、拡張辞書と、それが所有するオブジェクトも一緒に除く。一緒に除くものをほかが指すか、所有をたどれなければ除かない（[決定 0170](../decisions/0170-drawing-table-record-extension-dictionaries.md)）。DWG は、名前を変えてもレコードの名前だけを書き直し（図形はハンドルで指す）、今あるレコードの線種と真の色の変更は書き戻さない。画層の透過性と説明（XDATA）はまだ書かないので、変える置き換えと、持つ画層の追加は `change.edit.unsupported` にする。

  - `Edit::ReplaceLineType`・`Edit::AddLineType`・`Edit::RemoveLineType` は、線種の表のレコードを置き換え、足し、除く（[決定 0164](../decisions/0164-drawing-line-type-changes.md)）。置き換えは、元のレコードの 2・3・73・40 と要素の値だけを書き直す。形も文字も添えない線種は要素の値を書き直し、形か文字を添える線種は、要素の数を変えずに長さ（49）だけを書き直す。添える形と文字は変えない。名前を変えたら、図形と画層のレコードの 6 と、ヘッダーの変数の 6（`$CELTYPE`）も新しい名前にする。図形と画層のレコードでないオブジェクト（多重線のスタイルなど）が名前（6）で指していれば当てない。足すときは、Continuous のレコードを写し、ハンドル・拡張辞書と反応子の組・拡張データ・要素の値を除いてから同じ欄を書く。ByLayer・ByBlock・Continuous の名前の変更と除去、名前の重なり、用紙の mm の列、有限でない長さは `change.edit.unsupported` にする。ほかのオブジェクトかヘッダーの変数が、ハンドルか名前で指す線種と、後ろにハンドルのない線種がある線種は除かない。
  - `Edit::ReplaceDimensionStyle`・`Edit::AddDimensionStyle`・`Edit::RemoveDimensionStyle` は、寸法スタイルの表のレコードを置き換え、足し、除く（[決定 0165](../decisions/0165-drawing-dimension-style-changes.md)）。置き換えは、元のレコードの 2・40・41・142 と、端部記号が変わったときの 173・341〜344 だけを書き直す。端部記号は R2000 から、ブロックのレコードがあるものだけを書く。名前を変えたら、寸法・引出線・公差の 3 と、ヘッダーの変数の 2（`$DIMSTYLE`）も新しい名前にする。それら・寸法スタイルのレコード・辞書でないオブジェクトが名前と同じ 3 を持てば当てない。足すときは、Standard（なければ表の初めの子でない寸法スタイル）のレコードを写し、ハンドル・拡張辞書と反応子の組・拡張データ・端部記号を除いてから同じ欄を書き、ハンドルを 105 に置く。Standard・子の寸法スタイル（名前に `$` を持つもの）・子を持つ寸法スタイルの名前の変更と除去、名前の重なり、負か有限でない大きさは `change.edit.unsupported` にする。ほかのオブジェクトかヘッダーの変数が、ハンドルか名前で指す寸法スタイルと、後ろにハンドルのない寸法スタイルがある寸法スタイルは除かない。
  - 文字スタイル・線種・寸法スタイルの除去も、拡張辞書を持つレコードを、拡張辞書と、それが所有するオブジェクトごと除く（[決定 0170](../decisions/0170-drawing-table-record-extension-dictionaries.md)）。DWG は、一緒に除くオブジェクトをオブジェクトの地図から除く。
  - 当てたら、書き戻した表から図面モデルを作り直し、変更ごとに新しい ID とハッシュを返す。置き換えた要素の ID は変わらず、足した要素の ID は振ったハンドル（`space/0/h20` など）で作るので、書き戻したファイルを読み直したときと同じになる。除いた要素と、ハンドルを持たない要素（読み直すと ID がずれうる）は、ID を返さない。
  - `Edit::Add` は、足す先を空間か用紙の ID で指す。実寸の空間の要素はモデル空間（`space/0`）の新しい図形として、用紙の要素は足す先の用紙のほかの図形と同じ所（今のレイアウトは ENTITIES の所でペーパー空間の印 67 = 1 を付け、ほかのレイアウトはペーパー空間のブロックの ENDBLK の前）に足す。図形を持たない用紙には、その LAYOUT のブロックのレコードを所有者として、今のレイアウトなら ENTITIES の所に、ほかのレイアウトならそのペーパー空間のブロックに足し、読み直すと用紙の ID が変わる。図面の単位が分からない用紙には足さない（[決定 0155](../decisions/0155-drawing-apply-additions.md)）。足せる形は、LINE・CIRCLE・ARC・ELLIPSE・LWPOLYLINE・TEXT（高さの意味が TEXT の高さのもの）・MTEXT（高さの意味が MTEXT の高さで、背景を持たず、区間が内容と合うもの）・INSERT（名前のあるブロックを置き、切り抜きを持たないもの。格子を持てば、列と行の数（70・71）と間隔（44・45）を書き、DWG では MINSERT になる。属性は、1 行の値で高さの意味が属性の高さのものを、所有者を INSERT とする ATTRIB と SEQEND として続ける）。要素の出所は使わない。ハンドルは、表のどのハンドルよりも大きく HANDSEED より小さくない値から順に付け、モデル空間の所有者を `*Model_Space` にし、用紙の所有者を追加先の用紙のブロックにする。R13 以降の DXF には、最初の図形にも区切り（100）を書く。レイヤ・線種・文字の体裁・ブロックは、大文字と小文字を区別せずに表の定義を引いて定義の名前で書き、定義がなければ足さない。色は ACI を 62、RGB を 420（R2004 から）、線幅を 370（R2000 から）に書く。DWG には、線幅と RGB の色を持つ要素をまだ足さない。透過性はまだ書かないので、レイヤから継承する要素だけを足す。TEXT の位置合わせが左の基準線でなければ、置く点を 11 と 10 に書く。MTEXT の向きは、DXF には元の形（50 か 11・21）で、DWG には 11・21 の向きで書き（0 でない角度の MTEXT は DWG に足さない）、R2010 からの DWG には枠の高さ（46）を必ず書く。版が分かる DXF への ELLIPSE・MTEXT の追加は R13 以降、LWPOLYLINE は R14 以降に限り、ブロックは BLOCK_RECORD の表がなくても定義の存在を確かめる。ATTRIB・SEQEND を含むハンドルと次の HANDSEED を増やせないときも、何も反映しない。文書の点の表し方に従う点は、POINT として足し、0 でない角度を 50 に書く（[決定 0183](../decisions/0183-drawing-apply-points.md)）。R13 以降の DXF には、注記のない LEADER（73 = 3）も足せる。DWG には LEADER をまだ足さない。足す先が記号の定義の空間なら、所有者をその BLOCK_RECORD にし、DXF では ENDBLK の前に、DWG ではブロックの図形の列に足す。名のない定義・外部参照の定義・BLOCK_RECORD のない定義には足さない（決定 0177）。定義の中に INSERT を足すときは、足す記号の定義から中の INSERT をたどり（同じ変更の一覧で先に足したものを含む）、足す先の定義に着けば `change.symbol-cycle.invalid` で断る（[決定 0182](../decisions/0182-drawing-apply-symbols-in-definitions.md)）。
- 型付きの見方は、共有のオブジェクトの表の上にある（`Object::line`）。今は LINE（DXF Reference「LINE」）だけ。値を読めないときは、グループ・コードとともに理由を返す。DWG の表にも同じ見方を使う。
- `AcadDb::remove` で除いたオブジェクトへの参照のうち、DICTIONARY の項目（3 と次の 350・360）と、102 の組（`{ACAD_REACTORS` など）の中の 330・360 は、ほかのオブジェクトからも除く（DXF Reference「Common Group Codes for Objects」「DICTIONARY」）。参照を除いて空になった組は、組ごと除く。書き戻すと、直したオブジェクトのレコードも直る。
- まだ扱わないもの: ほかの変更に伴って直すもの（範囲を狭めること、用紙空間の範囲 `$PEXTMIN`・`$PEXTMAX`、組の外の所有者の参照 330 と、所有していたオブジェクトをまとめて除くこと、ブロックのレコードなど）、型付きの見方を広げること。

## 版の変更

- `Dxf::write_as` で、`$ACADVER` の値を名指しして書く（[決定 0008](../decisions/0008-model-layers-and-codecs.md)）。元と同じ版なら、そのまま書く。バイナリの DXF の版は、まだ変えない。
- いまは AC1012〜AC1032（R13〜2018）から AC1009（R12）への変更だけを扱う。ほかの組は `dxf.version.unsupported` を返し、何も書かない。
- 残すのは HEADER・TABLES・BLOCKS・ENTITIES のセクションと、VPORT・LTYPE・LAYER・STYLE・VIEW・UCS・DIMSTYLE・APPID の表。ほかは書かず、セクションと表ごとに診断を返す。
- BLOCKS と ENTITIES では、R12 の種類の図形だけを書く。LWPOLYLINE・MTEXT・HATCH などは変換せずに書かず、`dxf.entity.dropped` を返す。
- サブクラスの印（100）、所有者への参照（330・360）、`{` と `}` で囲むアプリケーションの組（102）、表のハンドル（TABLES の中の 5 と 105）は、置き換える先のない構造として黙って除く。ほかの R12 にないグループ・コードのタグは書かず、`dxf.group-code.dropped` を返す。
- 見出しは、R12 にないグループ・コードの値を持つ変数を、変数ごと書かない。`$ACADVER` を AC1009 にし、図形のハンドルを残すので、`$HANDLING` がなければ 1 として足す。
- 2007 以降の版（UTF-8）から書くときは、ASCII でない文字を `\U+XXXX`（UTF-16 の単位ごと）にして、`dxf.text.equivalent` を返す。UTF-8 として読めない値は、バイト列のまま書く。
- 残すタグは、グループ・コードの行と改行を元のバイトのまま書く。
- まだ扱わないもの: LWPOLYLINE・MTEXT などの R12 の図形への変換、`*Model_Space` などのレイアウトのブロックの扱い、ほかの版の組、ezdxf や ODA の変換結果との比較。

## オブジェクトの表

- `DxfFile::objects` で、DXF と DWG が共有するオブジェクトの表（`AcadDb`）を作る（[決定 0023](../decisions/0023-acad-shared-object-table.md)）。
- セクションの中のレコードを、1 つずつオブジェクトにする。`SECTION`・`ENDSEC`・`EOF` と、セクションの外のもの（先頭のコメントなど）はオブジェクトにしない。見出しの変数は `SECTION` のレコードの中にあるので、オブジェクトにならない。
- 値は、グループ・コードの範囲で決めた型で読む（DXF Reference「Group Code Value Types」）。ハンドルとバイナリは 16 進として読む。
- 型どおりに読めない値は、元のバイト列のまま文字列として置き、`dxf.value.invalid` を返す。
- オブジェクトは、元のレコードの番号を持つ。予算の作業は、レコードごとに数える。
- 型付きの見方と図面モデルへの変換は、この表の上で行う。
- まだ扱わないもの: 表からの書き戻し。

## 境界から読む

- 境界の `open`（[決定 0016](../decisions/0016-boundary-message-details.md)）は、入力の先頭が判定の規則に合えば DXF として読み、文書の名前と `dxf` を返す。`capabilities` では、系統 `acad` の読める形式として示す。
- 予算は、コーデックが確かめる。入力の大きさは読む前に、作業はタグごとに、レコードはレコードごとに数える。
- 開いた文書は、L1 のファイルモデルとして `close` まで持つ。中身を返す op と、図面モデルへの変換は、まだ境界から呼べない。

## 図面モデルへの変換

- `DxfFile` の `Lift<Drawing2D>` で、図面モデル（L2、`crates/zumen-drawing`）を作る（[決定 0022](../decisions/0022-drawing2d-semantics-and-format-mapping.md)）。変換は共有のオブジェクトの表（[決定 0023](../decisions/0023-acad-shared-object-table.md)）の上で行い、DWG も同じ変換を使う（[DWG の扱い](dwg.md)）。`zumen-acad` の feature `drawing` にあり、外せば L1 だけを使える。
- 移す図形と値は、この節の各項に書く。移さない種類の図形は、種類ごとに `dxf.lift.dropped` を返す。
- モデル空間の図形は 1 つの実寸の空間に、ペーパー空間（67 = 1）の図形とビューポートは、レイアウトごとの用紙に置く（[決定 0145](../decisions/0145-drawing-sheets-per-layout.md)）。図形のないレイアウトも、LAYOUT があれば、名前と大きさだけの中身のない用紙にする（[決定 0153](../decisions/0153-drawing-empty-layout-sheets.md)）。中身のない用紙の ID は、中身のある用紙の後から、タブの順に付ける。今のレイアウトに図形があれば、そのペーパー空間のブロックからは用紙を作らない。
  - 今のレイアウトの図形は ENTITIES にあり、ID 0 の用紙に置く。ほかのレイアウトの図形は、BLOCKS のペーパー空間のブロック（DXF では `*Paper_Space0` など、DWG では番号のない `*Paper_Space`）にあり、今のレイアウトの用紙の後に、LAYOUT のタブの順（71）で並べる。
  - 用紙の名前は、そのブロックのレコードを指す LAYOUT のレイアウトの名前（2 つ目の 1）とする。今のレイアウトの LAYOUT は、ペーパー空間の図形の所有者から探す。
  - ほかのレイアウトの用紙の点は、LAYOUT の範囲の左下（10・20）を原点にし、大きさは範囲（10・20 から 11・21）で決める（推定。試料の DXF と DWG で確かめた）。範囲がなければ原点を 0 とし、大きさを持たない。
  - ペーパー空間の MULTILEADER と POLYLINE も用紙に置く。これまでは実寸の空間に置いていた。
- 実寸の単位は `$INSUNITS` で決める。ないか長さの単位でなければ不明とし、`dxf.units.missing` を返す。mm とみなさない。
- 用紙の点は、`$PLIMMIN` を原点にして mm に直す。単位が不明なら直せないので、ペーパー空間の図形を移さず `dxf.paper-space.dropped` を返す。用紙の大きさは `$PLIMMIN` と `$PLIMMAX` から決め、なければ持たない。
- ビューポートは、縮尺 41 ÷ 45 の等方のビューと、中心 10・20 と幅 40・高さ 41 の矩形の切り抜きにする。69 = 1 のものは用紙そのものなので、ビューにしない。ねじれ（51）・視点の向き（16・26・36）・注視点（17・27・37）が既定でないものは、まだ移さず `dxf.viewport.unsupported` を返す。
- 画層は、表の LAYER のレコードを表の順に移す（[決定 0105](../decisions/0105-drawing-layers-and-order.md)）。凍結（70 の 1）か色（62）が負なら表示せず、290 が偽なら印刷せず、ロック（70 の 4）なら編集できないとする。凍結は、表示しないことと別にも持つ（`LayerState::frozen`、[決定 0141](../decisions/0141-drawing-layer-frozen.md)）。新しいビューポートで凍結（70 の 2）は移さない。図形が表にない名前を指せば、定義のない画層として足す。ビューポートで凍結した画層（341）は、ビューで表示しない画層にする。341 が画層のレコードを指さなければ、その指定だけを除き `dxf.lift.invalid` を返す。
- 線種は、表の LTYPE のレコードを表の順に移し、線と間の長さ（49）の列を要素の空間の長さとして持つ（[決定 0106](../decisions/0106-drawing-color-line-type-weight.md)）。要素に添える形と文字（74 の 2 と 4）は、要素の番号・中身・倍率・回転・回転の基準・ずれとして線種の定義に持つ（[決定 0150](../decisions/0150-drawing-line-type-marks.md)）。形は文字スタイル（340）の形のファイル（3）と番号（75）、文字は文字列（9）と文字スタイルの名前（2）で持つ。74 の 1 は回転を文書の x 軸から測ること、8 は文字を逆さにしないこととする（8 は推定）。形の番号が 0 の形は添えない（推定）。形と文字を兼ねる要素など読めない要素は、長さだけを移し、`dxf.line-type-element.dropped` を返す。図形が表にない名前を指せば、定義のない線種として足す。

- MULTILEADER の線の色（91）・線種（341 の指す LTYPE。名前が ByLayer・ByBlock なら継承）・線幅（171。-1 はレイヤ、-2 は配置、-3 は文書の既定）と、注記の色（文字は 92、記号は 93）を持つ（[決定 0146](../decisions/0146-drawing-callout-line-style.md)）。配置から継承する値（ByBlock）は、注記の要素に従う。値がなければ、配置から継承する（推定）。これらの欄は、最後の区切り（100）の後から読む。AcDbEntity の 92 は代わりの図形の大きさなので読まない。線ごとの上書き（線の 93 が 0 でないか、線の色 92 が ByBlock でない）は移さず、`dxf.leader-line-style.dropped` を返す。作った試料の DXF（R2000・R2018）と、AutoCAD の試料の R2000〜R2018 の DXF・DWG で確かめた。上書きした線の試料はない。

- 下敷きは、IMAGE と PDFUNDERLAY・DWFUNDERLAY・DGNUNDERLAY を移す（[決定 0114](../decisions/0114-drawing-underlays.md)）。定義（340 の指す IMAGEDEF・PDFDEFINITION など）の参照名（1）を資源とし、ファイルは開かない。IMAGE は、挿入点（10）と 1 画素の横と縦（11・12）、画素の数（13・23）から左下・右下・左上の角を持ち、70 の 1 を表示する、280 が 1 なら境界（71・91・14）で切り抜き、290 が真なら内側を隠す。下敷きは、定義のページなどの名前（2）・挿入点（10）・尺度（41・42）・回転（50）を持ち、280 の 2 を表示する、1 なら境界（11）で切り抜き、16 なら内側を隠す。描く順は、ほかの図形と同じく SORTENTSTABLE と入力の順で決める。
- 図形の XDATA は、登録アプリケーション名（1001）ごとに、名前空間 `dxf.xdata` の形式固有の情報にする（[決定 0115](../decisions/0115-drawing-format-extensions.md)）。版は `$ACADVER`、値の型の契約の版は 3 とし、値は並びの順に、グループ・コード（1000・1002〜1005・1010〜1013・1040〜1042・1070・1071）の意味で名付け、元のグループ・コード（`Field::code`）を付ける（[決定 0157](../decisions/0157-drawing-model-fields-and-extensions.md)）。点は続く Y（+10）と Z（+20）と合わせ、X のコードを付ける。付く先の図形を要素の ID で指し、読んだときの図形のハッシュを持つ。図形を編集すれば失効したとする（[決定 0156](../decisions/0156-drawing-stable-ids-and-preconditions.md)）。最初の 1001 より前の XDATA の値と、読めない値を持つ名前の分は `dxf.lift.invalid` を返す。
- 図面モデルの値にない図形の欄は、名前空間 `dxf.entity`（版 3）の形式固有の情報にし、値に元のグループ・コードを付ける（[決定 0142](../decisions/0142-dxf-entity-extension.md)）。厚さ（39）は、LINE・CIRCLE・ARC・TEXT・LWPOLYLINE・POLYLINE・SOLID・TRACE・POINT・SHAPE で 0 でなければ `thickness`（実数）にする。SPLINE の節点と制御点の許容差（42・43）は、あれば `knot_tolerance`・`control_tolerance`（実数）にする。線種の生成（70 の 128）と当てはめの許容差（44）は、図面モデルの値に移す（[決定 0157](../decisions/0157-drawing-model-fields-and-extensions.md)）。試料の DWG と DXF の組で、どの欄も一致することを確かめた。どの欄もない図形は、この拡張を持たない。実数として読めないか有限でない値があれば、図形は残し、この拡張を移さず `dxf.lift.invalid` を返す。
- 図形の拡張辞書（102 の `{ACAD_XDICTIONARY` の組の 360 が指す DICTIONARY）の XRECORD の項目は、項目の名前ごとに、名前空間 `dxf.xrecord` の形式固有の情報にする（[決定 0148](../decisions/0148-drawing-extension-dictionary-xrecords.md)）。値の型の契約の版は 3 とし、値は、複製の扱い（280）の後のデータを記録の順に、元のグループ・コードを付けた型付きの値（`text`・`integer`・`real`・`point`・`handle`・`binary`）で並べる（[決定 0157](../decisions/0157-drawing-model-fields-and-extensions.md)）。点（X が 10〜17・210・1010〜1013）は、続く Y（+10）と Z（+20）があれば合わせ、なければ実数のまま並べる。図面モデルの欄にする値で欄がまだない項目（注釈の尺度の `AcDbContextDataManager`・`ASDK_XREC_ANNO_SCALE_INFO`・`ASDK_XREC_ANNOTATION_SCALE_INFO`、寸法の関連づけの `ACAD_DIMASSOC`、動的ブロックの `AcDbBlockRepresentation`、ビューごとの画層の上書きの `ADSK_XREC_LAYER_*_OVR`）と、AutoCAD の版の往復の XRECORD（`ACAD_XREC_ROUNDTRIP`・`ACAD_MTEXT_RT`・`ACAD_MTEXT_2008_RT`）は、図面モデルに移さず元のファイルに残し、`dxf.extension-dictionary.unsupported` を返す。往復の値は、図形の値で表せる内容と表せない内容をまだ読み分けないので、すべて返す。ほかの XRECORD でない項目は移さず、`dxf.extension-dictionary.dropped` を返す。
- 記号の切り抜き（XCLIP）は、INSERT の拡張辞書の `ACAD_FILTER` の辞書の `SPATIAL` が指す SPATIAL_FILTER から作る（[決定 0149](../decisions/0149-drawing-symbol-clips.md)）。境界の点（10・20）を、境界の変換と挿入の逆の変換（40 の 12 ずつ、3 行 4 列を行の順）で記号の定義の空間に写し、記号の切り抜きの頂点にする。2 つの点は、向かい合う角の長方形とする。境界の向き（210〜230）が Z でないもの、境界の原点（11〜31）が 0 でないもの、点が 2 つより少ないものは、切り抜かずに記号を移し、`dxf.clip.dropped` を返す。前と後ろで切るか（72・73）と、境界を表示するか（71）は移さない。
- 画層（LAYER）と線種（LTYPE）の表のレコードの拡張辞書の XRECORD も、同じく `dxf.xrecord` の形式固有の情報にし、画層と線種に付ける（[決定 0152](../decisions/0152-drawing-layer-line-type-xrecords.md)）。ほかの表のレコードとオブジェクトの拡張辞書は移さない。
- ハッチング（HATCH）は、境界の輪の数（91）から後の値を並びの順に読む。輪ごとに、印（92）の 2 が立てば膨らみ（42）のある頂点の折れ線、立たなければ線分・円弧・楕円弧・SPLINE の辺の並びとし、印の 1・4・8・16 を外側・境界を探した・文字の枠・いちばん外とする。輪を作った図形（330）は出所で指す。島（75）・パターンの出どころ（76）・回転（52）・尺度（41）・重ねるか（77）・線の組（53・43〜46・49）・境界を探した点（98・10・20）を持つ。塗り（70 = 1）はパターンの欄を読み飛ばし、450 が 1 ならグラデーションにする。SPLINE の辺（72 = 4）は、次数（94）・有理（73）・周期的（74）・節点（95・40）・制御点（96・10・20）と、有理なら重み（42）を読む。2010（AC1024）以降の版の DXF では、続く当てはめる点（97・11・21）と、あれば接線（12・13）も読む（[決定 0111](../decisions/0111-drawing-curves.md)）。
- 曲線は元の定義のまま移す（[決定 0111](../decisions/0111-drawing-curves.md)）。CIRCLE は中心（10）と半径（40）、ARC はさらに始まりと終わりの角度（50・51、度）を持つ。ELLIPSE は中心（10）・中心からの長軸の端（11）・比（40）と、始まりと終わりのパラメーター（41・42、ラジアン）を度に直して持つ。LWPOLYLINE は、頂点（10・20）ごとに続く始まりと終わりの幅（40・41）と膨らみ（42）・閉じているか（70 の 1）・線種の生成（70 の 128）・一様な幅（43）を持ち、頂点の数（90）と合わなければ移さない。古い POLYLINE は、続く VERTEX（所有者が指すか、66 が 1 の POLYLINE から SEQEND まで）を頂点にし、VERTEX の点（10・20）・膨らみ（42）・始まりと終わりの幅（40・41、なければ 0）と、閉じているか（70 の 1）と線種の生成（70 の 128）を持つ。どの頂点の幅も同じなら一様な幅にする。POLYLINE の既定の幅（40・41）は新しい頂点のためのものなので使わない。3D の折れ線（70 の 8）は Z がどれも 0 なら移す。曲線かスプラインで当てはめたもの（70 の 2・4）と、網・多面（16・64）は移さず `dxf.lift.dropped` を返す。SPLINE は、印（70 の 1・2・4 を閉じている・周期的・有理）・次数（71）・節点（40）・制御点（10）・重み（41）・当てはめる点（11）・接線（12・13）・当てはめの許容差（44、0 以上）を持ち、数の欄（72〜74）や次数と合わなければ移さない。当てはめる点で決まる印（70 の 1024）が立てば、32・64・128・256 を節点の取り方の弦の長さ・その平方根・一様・指定とする。どれか 1 つでなければ取り方を持たない。標高（LWPOLYLINE の 38、POLYLINE の 30）や Z が 0 でなければ平面に移さない。
- Z が 0 でない点と、押し出しの向き（210・220・230）が Z でない図形は、Z を捨てて移さず、`dxf.non-planar.dropped` を返す。
- 要る値がないか読めないか範囲の外なら、その図形を移さず `dxf.lift.invalid` をグループ・コードとともに返す。どの診断も、元のレコードを指す。
- 2007 以降の版は、文字の値を UTF-8 として読む。それより前の版は、`$DWGCODEPAGE` が `ANSI_932` なら、ASCII でない文字を WHATWG の Shift_JIS として戻す。戻せないバイト列を持つものは `dxf.lift.invalid` で落とす。ほかのコード・ページと、`$DWGCODEPAGE` がないものの ASCII でない文字は、その図形を移さず `dxf.code-page.unsupported` を返す（[決定 0175](../decisions/0175-acad-code-page-shift-jis.md)）。
- SOLID と TRACE は、角（10〜13）を 1・2・4・3 の順に結んだ閉じた輪 1 つを塗るハッチングにする。3 つ目と 4 つ目の角が同じか、13 がなければ三角形とする。POINT は、文書の点の表し方に従う図面モデルの点にし、50 を回転にする。点の表し方（`point_style`）は、`$PDMODE` を形（0〜4 の基本の形に、32 の円と 64 の四角）、`$PDSIZE` を大きさ（正は長さ、負は画面の高さに対する百分率、0 は画面の高さの 5%）にして作る。どちらの変数もなければ `None` にする。知らない番号と、有限でない大きさは、`dxf.lift.invalid` を返し、小さな点と画面の高さの 5% にする（[決定 0160](../decisions/0160-drawing-points.md)）。
- まだ扱わないもの: 当てはめた古いポリライン（POLYLINE）と網・多面、RAY・XLINE などほかの図形、文書の点の表し方の書き戻し、ARC_DIMENSION、端部記号のほかの寸法スタイルの値と、拡張データで上書きした値の解釈、拡張辞書の XRECORD でない項目と、画層と線種以外のオブジェクトの拡張辞書、独自のオブジェクト、記号の内側を隠す切り抜きと切り抜きの書き戻し、寸法の部品の展開、ブロックの展開、段組みの MTEXT、表全体の上書きと行・列ごとの書式、公差、ねじれと 3D のビュー、多角形の切り抜き、ANSI_932 でないコード・ページの文字と、文字の中の `\M+` の符号。

## 推定した扱い

仕様の文からは決まらないため、次のように扱います。実際のファイルで確かめたら、ここを直します。

| 所 | 扱い | 理由 |
| --- | --- | --- |
| 改行 | LF と CR LF のどちらも行の終わりとする。最後の行に改行がなくてもよい | 改行の種類で読めなくならないように。元のバイトは書くときに残る |
| グループ・コードの行 | 前後の ASCII の空白を除いて、符号つきの整数として読む | 仕様の例は右寄せだが、桁の揃え方の違いで読めなくならないように |
| 値の行 | 改行を除いた生のバイト列として持つ。空白も文字コードも変えない | 文字コードは `$DWGCODEPAGE` と版で決まるため、L1 では解釈しない |
| `EOF` がない | 最後のタグまでを読み、診断は出さない | 試作の範囲では、壊れた終わりの扱いを決めていない |
| 形式の判定 | 先頭の 2 行が、空白を除いて `0` と `SECTION` | 999 のコメントで始まるファイルは、まだ判定しない |
| 実数の値を読む | 前後の空白を除いて 10 進の実数として読む。指数の表記を許し、有限でないものは読めないとする | 仕様の例には指数の表記（`1.0E+20` など）がある |
| ハンドルの値 | 空のもの、符号の付いたもの、64 ビットを超えるものは読めないとする | ハンドルは 16 進の符号のない数のため |
| 真偽の値（290〜299） | 0 と 1 だけを読む | ほかの値の意味を仕様の文から決められないため |
| 足したタグの書き方 | グループ・コードを 3 桁に右寄せし、ファイルの最初の行と同じ改行（CR LF か LF）で書く。値はそのまま書く | 仕様の例と AutoCAD の出力が右寄せのため。1 つのファイルで改行を混ぜないため |
| `$HANDSEED` の書き方 | 次のハンドルを、0 で埋めない大文字の 16 進で書く | 仕様の例のハンドルが大文字の 16 進のため |
| 書き戻す値の書き方 | 整数は 10 進、真偽は 0 と 1、ハンドルとバイナリは 0 で埋めない大文字の 16 進（バイナリは 1 バイトを 2 桁）、文字列はそのまま書く | 表を作るときの読み方の逆で、読み直すと同じ値になるため。元の桁揃えは、値を変えたタグでは保たない |
| 実数の値を書く | 読み直すと同じ値に戻る最短の 10 進の表記にする。指数は使わず、整数の値にも小数点を付ける | どの環境でも同じバイト列にするため（決定 0007） |
| 書き戻しで広げる図面の範囲 | 値を変えたか足したモデル空間の図形のうち、LINE・POINT と、押し出しの向きが既定の CIRCLE だけを囲む。範囲は狭めない。変数がないか、10・20・30 の実数を持たなければ直さない | 囲む箱を値だけから決められる図形に限るため。除いた図形の分を狭めるには、ほかの図形の範囲がすべて要るため |
| 画層と線種の名前を引く | ASCII の大文字と小文字を区別しない。同じ名前のレコードが 2 つあれば、先のものを指す | AutoCAD が画層の名前の大文字と小文字を区別しないため。仕様の文からは決まらない |
| DIMENSION の移さない欄 | 複製の挿入点（12）・行間（41・72）・水平の向き（51）は移さない。70 の 8・16 のビットは見ない | どれも寸法の意味を変えず、描く形は部品が持つため。8・16 は仕様の文にない |
| DIMENSION の測定値（42） | `dxf.DIMENSION.42` のキーと組にして持つ。長さ（長さ・平行・半径・直径・座標の寸法）は図面の単位、角度はラジアンで、寸法の倍率（DIMLFAC）は掛けない値とする | 仕様の文は「実際の測定値」とだけ書く。R2000〜R2018 の同じ図面の DXF と DWG の 11 の寸法（角度の寸法 2 つを含む）は、どれも定義点から測った値と合う（試験 `dimension_samples`）。ただし保存された値は最後に描いたときの値で、定義点と違うことがある（ほかの 2 つの試料の図面を合わせた 508 の寸法のうち 34 が違う）。比べた DXF の見出しの `$DIMLFAC` は 1 で、倍率を掛けないことは確かめていない |
| LEADER の移さない欄 | 注記の種類と大きさ（73・40・41）・鉤の線（74・75）・ずれ（212・213）・X 軸の向き（211）は移さない。矢印（71）がなければ寸法スタイルに従うとする | 経路と注記の参照があれば、注記との組の意味は保てるため。DWG の R2000 以降は矢印の欄を持たない |
| DIMSTYLE の既定の値 | 値のない欄は、DIMSCALE（40）を 1、DIMASZ（41）を 0.18、DIMTSZ（142）を 0、DIMSAH（173）を偽とする。R12 の名前の端部記号（5〜7）は読まない | DWG の読み手が、既定の値と同じ欄を置かないため。値は DXF Reference の見出しの変数の既定の値（インチの図面）で、メートルの図面の既定の値とは違う |
| INSERT の Z の尺度（43） | 移さない | 平面の図形を置くかぎり、平面の形を変えないため。定義に Z のある図形があるかは、定義を移すときに確かめる |
| HATCH の移さない欄 | 密度の画素の大きさ（47）、グラデーションの色の番号（63）と値（463）は移さない | 47 は表示のための値のため。グラデーションの色は RGB（421）で決まり、63 は仕様の文で役割が決まらないため |
| HATCH の境界の図形の数（97） | 輪の最後の 97 の数だけ 330 を読み、合わなければ移さない。DWG は 330 を置かないので空にする | 境界を作った図形を黙って落とさないため。SPLINE の辺の当てはめる点の数も 97 なので、2010（AC1024）以降の版の SPLINE の辺だけが当てはめる点を持つとして読み分ける（決定 0111、試料で確かめていない） |
| 下敷きの切り抜きの反転（280 の 16） | IMAGE の 290 と同じく、内側を隠すこととする | DXF Reference「UNDERLAY」は「Clip inside mode」とだけ書き、試料の図面に切り抜いた下敷きがない |
| 下敷きの切り抜きの頂点（14・11） | 元の形式の下敷きの座標のまま持つ。画像では画素の座標、下敷きでは内容の座標とする | 座標の意味を試料で確かめていない（決定 0114） |
| 記号の切り抜きの変換（SPATIAL_FILTER の 40） | 先の 12 を挿入の逆の変換、後の 12 を境界の変換とし、境界の変換を先に当てる。内側を隠す切り抜きはないものとする | 試料の図面では、先の 12 が挿入点と尺度の逆になり、後の 12 は単位の変換だった。反転した切り抜きの試料はない |
| R12 のグループ・コード | 0〜79、210〜239、999、1000〜1071 とする | ほかの値の型（90 台の 32 ビットの整数など）は R13 以降で足されたため。実際の R12 の読み手では確かめていない |
| R12 の図形の種類 | 3DFACE・ARC・ATTDEF・ATTRIB・BLOCK・CIRCLE・DIMENSION・ENDBLK・INSERT・LINE・POINT・POLYLINE・SEQEND・SHAPE・SOLID・TEXT・TRACE・VERTEX・VIEWPORT とする | 版ごとの図形の一覧から。R12 で範囲内のコードの意味が変わったものは確かめていない |
| R12 の見出しの未知の変数 | 値のグループ・コードが R12 の範囲なら、残す | 知らない変数を落とさないため。R12 の読み手が無視するかは確かめていない |
| 版の比べ方 | `$ACADVER` の値を、前後の空白を除いたバイト列として比べる | 版の名は `AC` と 4 桁の数字で、辞書順が新旧の順になる |
| LINE の Z がない | 0 とみなす | 2D の図面では Z を省いたファイルがあるため |
| 用紙の単位 | 実寸と同じ `$INSUNITS` とする | ペーパー空間の単位を別に決める変数を確かめていない |
| 用紙の原点 | `$PLIMMIN` とし、なければ（0,0）とする | 決定 0019 の用紙の左下に合わせるため。印刷の設定の余白は見ていない |
| 用紙そのもののビューポート | 69 = 1 のものとする | ビューポートの ID の 1 は、ペーパー空間そのものを表すため |
| ビューの中心 | 12・22 を、注視点を原点にした実寸の座標とする。注視点が既定でないものは移さない | 注視点を足す向きを、実際のファイルで確かめていない |
| 押し出しの向きがない | （0,0,1）とみなす | 既定の値のため |
| TEXT の既定の値 | 50・51 は 0、41 は 1、7 は STANDARD、71・72・73 は 0 とする | 省いたファイルがあるため |

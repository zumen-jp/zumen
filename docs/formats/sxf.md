# SXF

SXF Ver.3.1 の SFC と P21 を、ファイルモデル（L1）として読み書きする規則と、仕様が決めない所の扱いを記録します。実装は `crates/zumen-sxf` です。旧版の知見（[旧版の SXF の扱い](https://github.com/zumen-jp/zumen-legacy/blob/main/docs/formats/sxf.md)）は、扱う範囲を広げるときに移します。仕様の本文は写しません（`formats/ledger.toml`）。

## 対象

- SFC と P21。どちらも ISO 10303-21 の交換構造に入る（[決定 0120](../decisions/0120-sxf-l1-exchange-structure.md)）交換構造の読み取りと文字列のエスケープの戻し方は、IFC と共有する crate `zumen-step` が行う。SFC のフィーチャのコメントのマーカー（`/*SXF`・`/*SXF3`・`/*SXF3.1`）と、AP202 と書いた P21 でそれを読まないことは、`zumen-sxf` が読み方として渡す（[決定 0207](../decisions/0207-building-model-components.md)）。
- SFZ・P2Z（SFC・P21 を ZIP に入れたアーカイブ）は、アーカイブの最初の `.sfc`・`.p21` の項目（大文字と小文字を問わない）を SXF として読む（#385）。図面と同じ名前の属性ファイル（下の「属性ファイル」）のほかの項目（画像など）は読まず、`open` の結果の `entries` に、属性ファイルを含むアーカイブの中の名前をアーカイブの順で返す。`.sfc`・`.p21` の項目のない ZIP は SXF にせず、ifcZIP などとして試す。
- SFZ・P2Z への `apply` は、SXF の項目だけを書き直したバイト列に置き換え、ほかの項目は展開したバイト列のまま写したアーカイブを書く。アーカイブは `zumen-zip` で、項目を stored で、日時を 1980-01-01 に固定して書く（決定性、[決定 0220](../decisions/0220-bcf-3-0.md)）。元のアーカイブの圧縮と日時は保たない。ZIP64 が要る大きさなら `sxf.archive.unsupported` を返して書かない（適合テストの `cases/open_sxf_zip.json`）。
- SFC は図面モデルへ移す（[決定 0121](../decisions/0121-sxf-sfc-lift-to-drawing.md)）。API の `open` は SXF の判定の規則で SFC と P21 を読み、`drawing` は SFC と P21 を図面モデルへ移す（適合テストの `cases/open_sxf.json`）。P21 は、実体を SFC と同じ形のフィーチャに組み直して、同じ変換に通す（[決定 0132](../decisions/0132-sxf-p21-through-sfc-features.md)）。P21 の組み直しは、下の「P21 の組み直し」に記録する。

## 判定

- 先頭の行が `ISO-10303-21;` なら SXF の候補とする。`FILE_SCHEMA` の最初の名前が `IFC` で始まるものは、先に IFC の判定の規則で分ける（[ifc.md](ifc.md)）。
- `FILE_SCHEMA` の最初の文字列の、最初の語（空白か `{` の前まで）を、大文字と小文字を区別せずに `ASSOCIATIVE_DRAUGHTING` と比べる。違えば `sxf.schema.unsupported` を返す。IFC などを空の図面として読まないため。`FILE_SCHEMA` がない古い SXF は読む（推定。旧版の扱いを引き継ぐ）。
- `FILE_DESCRIPTION` の最初の文字列に `feature_mode` があるか、データのセクションにフィーチャのコメントがあれば SFC、ほかは P21 とする。`AP202` とある P21 では、`/*SXF` で始まるコメントもただのコメントとする（推定）。

## レコードの区切り

- `;` で終わる文を 1 つのレコードにする。語（`HEADER;`）、ヘッダーの文（`FILE_NAME(…);`）、インスタンス（`#n=名前(…);`）、複合のインスタンス（`#n=(A(…) B(…));`）。
- データのセクションの `/*SXF` から `SXF*/` までを、SFC のフィーチャのレコードにする。マーカーは長いものから比べ、`/*SXF3.1` は `SXF3.1*/`、`/*SXF3` は `SXF3*/`、`/*SXF` は `SXF*/` で閉じる。中は `#n = 名前(…)` 1 つで、`;` を付けない（推定。旧版の扱いを引き継ぐ）。
- レコードの間の空白とコメント、読めなかった文は、レコードにしない。書くときは、レコードとその間を元のバイトのまま並べるので、変えずに書くと元のバイト列と一致する。
- `END-ISO-10303-21;` の後のバイトは、読まずにそのまま持つ。

## 値

- P21 の値は ISO 10303-21 の形で読む。文字列は `''` で閉じず、`\X2\` などのエスケープは戻さずに範囲で持つ。文の中のコメントは飛ばす。
- SFC の値は、`'…'`（次の `'` で閉じる）、`\'…\'`、並び `(…)`、囲まない値に分ける。囲まない値は、`,` か `)` の前までで、前後の空白を除く。
- SFC の `\'…\'` は、Shift_JIS の 2 バイトの文字の 1 バイト目（0x81〜0x9F・0xE0〜0xFC）の次のバイトと、`\\` を飛ばし、後に空白を挟んで `,` か `)` が続く `\'` で閉じる（推定。「表」のように 2 バイト目が `\` の文字があるため）。文字列の中の改行も範囲に含める。

## 壊れた所

- 始まりの行・`DATA` の節・`END-ISO-10303-21;` のどれかがなければ、`sxf.file.invalid` で読まない。
- 形の読めない文は次の `;` まで、閉じのあるフィーチャのコメントは閉じまでを飛ばし、`sxf.record.invalid` にその範囲を付ける。閉じのないコメントは、終わりまでを飛ばす。

## 上限

- 入力のバイト数、レコードの数、値の数（`work`）、並びの入れ子の深さ（`depth`）を予算で数える。止めたら、読んでいた文かコメントの範囲を場所にする（[決定 0119](../decisions/0119-budget-stop-place.md)）。

## 図面モデルへの変換

- フィーチャの引数は、0 から 3 番目がレイヤ・色・線種・線幅のコードで、続きが図形の値。値は `'…'` で囲んだ数でも、囲まない数でも読む。折れ線の座標の並びは、`(…)` でも、`'(…)'` と囲んだものでも読む。
- 要素の出所は、フィーチャのレコードの番号と、そのインスタンスの番号（`#n`）を持つ。要素の ID は、インスタンスの番号で `sheet/0/i20` のように作る（[決定 0156](../decisions/0156-drawing-stable-ids-and-preconditions.md)）。前にフィーチャを足しても、ほかの要素の ID は変わらない。P21 は、要素の出所にした実体（表記の実体など）の番号で作る。同じ図面の SFC と P21 は番号の振り方が違うので、ID は同じにならない。API の `entities` は、出所の `instance` にこの番号を 10 進の文字列で返す。
- 文字列は Shift_JIS で戻し、`\'…\'` の中の `\\` を `\` に戻す。改行は除く。
- 用紙のフィーチャは仕様では最後に書くが、後に要素があっても落とさず用紙に入れる（推定）。
- レイヤの状態は、表示の可否から、印刷を表示に合わせ、編集はできるとする（推定）。
- 楕円弧の角度は、媒介変数の角度とする（推定）。
- スプラインは制御点が 3n + 1 個の 3 次のベジェ曲線をつないだものとし、開閉のフラグは 0 を閉じているとする（推定。[決定 0126](../decisions/0126-sxf-splines-and-point-markers.md)）。
- 画像は、作図グループの名前の `$$RASTER$$` か、属性の `$$ATRU$$番号$$名称$$画像$$` の後をファイルの名前とし、グループの中の最初の 4 点以上の折れ線を範囲とする（推定。[決定 0125](../decisions/0125-sxf-raster-underlays.md)）。
- 図面表題欄の 12 の項目の順は、事業名・工事名・契約区分・図面名・図面番号・図面種別・尺度・作成年・作成月・作成日・受注会社名・発注事業者名とする（推定。[決定 0124](../decisions/0124-drawing-title-blocks.md)）。
- 点マーカーは、名前空間 `sxf.marker` とマーカーのコードを既定義のマーカーのキーにした点にし、回転と尺度を移す。記号にはしない（[決定 0160](../decisions/0160-drawing-points.md)）。
- クロソイドは値のまま移し、曲がる向きのフラグは 0 を反時計回りとする（推定。[決定 0123](../decisions/0123-drawing-clothoid-edge.md)）。
- 文字の 9 点の配置は、1 を左下とし、右へ 1 つずつ、上へ 3 つずつ数える（推定）。文字範囲の幅と字の間隔は `sxf.text` の拡張に残す（[決定 0122](../decisions/0122-sxf-text-to-formatted-text.md)）。
- 寸法は、定義点と寸法値の文字を図面モデルの寸法に、寸法線と補助線の端・矢印・文字範囲の幅と字の間隔を `sxf.dimension` の拡張に移す。弧長と角度の寸法の弧は、始めの角度から反時計回りとし、半径の寸法は、矢印がなければ終点を円の上の点とする（推定。[決定 0127](../decisions/0127-sxf-dimensions.md)）。
- 引出線とバルーンは、引出線つきの注記にする。頂点は矢印の側から並び、矢印は名前空間 `sxf.arrow` のコードのキーで指し、大きさはコードの表で決まるとする（推定）。バルーンの円は `sxf.callout` の拡張に残す（[決定 0128](../decisions/0128-sxf-labels-and-balloons.md)）。
- ハッチングは、指す複合曲線の曲線の辺を並べた輪にする。表示する複合曲線は、曲線を複合曲線の色・線種・線幅で置き、線のハッチングの要素の色は 1 本目の線の色にする（推定。[決定 0129](../decisions/0129-sxf-hatches-and-composite-curves.md)）。
- 現在の複合曲線のまとめ方では、前に書いた文字・点マーカー・ハッチング・複合図形の配置なども取り込む。これらは曲線にはせず、表示の有無によらず `sxf.lift.dropped` で元のレコードを報告する。表示フラグが不正な場合も、複合曲線の `sxf.lift.invalid` に加えて報告する。同じインスタンス番号の文字と後続の円がある場合、文字を要素に戻すと既存の円の ID が変わるため、この修正では要素に戻さない。復元は #611 で扱う。このようなフィーチャを含むハッチングの境界は、従来どおり `sxf.lift.invalid` で断る。
- 作図部品は名前空間 `sxf.sfig` の記号の定義に、既定義シンボルは名前空間 `sxf.symbol` の名前のキーにする。色を指定しない既定義シンボルの色はレイヤに従う（推定）。部分図の中の部分図は、外の部分図のビューに重ねたビューにする（[決定 0130](../decisions/0130-sxf-parts-symbols-and-nested-views.md)）。
- 名前が `$$ATR` で始まる複合図形の要素に、名前と `$$` で区切った値を `sxf.attribute` の拡張で付ける。背景色などの値は解かない（[決定 0131](../decisions/0131-sxf-attribute-mechanism.md)）。
- 測地座標系の部分図は、実寸の空間の `axes` を `Axes::NorthEast`（X が北、Y が東）にし、点はファイルの X・Y のまま持つ。ビューの変換が、東・北の順に直してから用紙へ置く（[決定 0019](../decisions/0019-coordinate-systems-and-gsi-data.md)、[crs.md](crs.md)）。
- まだ移さない種類と、読めない値は、`sxf.lift.dropped`・`sxf.lift.invalid` で報告する。
- 読んだ値が有限でも、計算した値が無限大か NaN になるものは、図形・ビューにせず、元のフィーチャ（P21 は表記の実体）を場所にした `sxf.lift.invalid` で報告する（#595）。対象は次の 3 つである。
  - 楕円・楕円弧の長軸の端の点（中心と半径の和があふれる）
  - 円弧寸法・角度寸法の点（角度の差か、中心と半径の和があふれる）
  - 部分図の中の部分図のビュー（内と外の尺度の積があふれる）。そのビューの中身も置かない。診断の場所は内の配置のフィーチャで、作らないビューごとに 1 件なので、外の部分図を何度も置くと、同じ場所の診断が置いた数だけ出る
- SFC の診断は、表と図形の変換段階によって入力順から外れる場合がある。図面・ID・書き戻しを保ったまま入力順にそろえる作業は #624 で扱う。

## 属性ファイル

属性ファイル（SAF、附属書の属性付加機構編の 3 章）を読み、属性ファイル用の属性付加機構の要素に結ぶ（[決定 0249](../decisions/0249-sxf-attribute-files.md)、`crates/zumen-sxf/src/saf.rs`）。

- `open` の `saf` に名指した入力か、なければ P2Z・SFZ の中の、図面と同じ名前の SAF（拡張子を `.SAF` にしたものか、図面の項目の名前に `.SAF` を足したもの。大文字と小文字を問わない）を読む。ほかの名前の SAF は結ばない。
- 根の `SxfAttributeXML` の `version`・`date`・`sxfFile`・`application`、`AttributeSet`（内容が属性セット識別番号）、`Figure` の `AttrSetRef` の `Attr` と `AttrGroup` を読む。文書型宣言（`SXFV31.DTD`）は解決せず、診断もしない。
- 省略できないタグ属性がないものと、重なる図形識別番号は `sxf.saf-value.invalid` を、知らない要素は `sxf.saf-element.unsupported` を返す。根が `SxfAttributeXML` でなければ、属性ファイルなしで図面を開く。
- 名前が `$$ATRF$$図形識別番号$$属性ファイル名` の作図グループを置いた要素（`sxf.attribute` の拡張の値が `ATRF` で始まるもの）に、同じ図形識別番号の図形の属性を、属性ごとに `sxf.saf` の拡張で付ける。拡張の名前は属性名で、フィールドは `figure`・`figure_name`・`set`・（属性セットがあれば）`set_name`・`set_version`・`designed_by`・（グループの中なら）`group`・（書いてあれば）`type`・`unit`・`value` の順。値は文字のまま持ち、`$$$`（文字列の内容を属性値にする）も解かない。
- 図面の図形識別番号の図形が属性ファイルになければ `sxf.saf-figure.missing` を、属性ファイルの図形の要素が図面になければ `sxf.saf-figure.dropped` を返す。
- 属性ファイルは書き直さない。P2Z・SFZ への `apply` は、SAF の項目をそのまま写す。

## P21 の組み直し

- 表は実体の番号の順に組み直し、利用者定義の色・線種・文字フォントとレイヤに、その順でコードを付ける。線幅は、既定義の太さでなければ、最初に使った順に 11 から付ける。
- 名前が `$$SXF_` で始まる `COLOUR_RGB` は既定義色に、名前が `$$SXF_dummy` で始まるレイヤは複合図形の仮のレイヤとしてレイヤにしない（推定。旧版の扱いを引き継ぐ）。
- 文字列は ISO 10303-21 のエスケープを戻し、規格の外の 8 ビットのバイトは Shift_JIS として読む（推定）。
- 同じ番号の実体は、ファイルの順で最初だけを使う。後の実体は `sxf.p21-instance.dropped` で、番号と元のレコードを報告する。L1 には元のバイト列を残す。
- 用紙は、番号がもっとも小さい `DRAWING_SHEET_REVISION` で、要素はその並びの順に置く。ほかの用紙は `sxf.p21-sheet.dropped` で、番号と元のレコードを報告する。用紙の名前が `A0`〜`A4` と向き（`horizontal`・`vertical`）でなければ、自由サイズとして `PLANAR_BOX` の大きさを使う。
- 1 つの要素が複数のレイヤに属すれば、名前が `$$SXF_dummy` で始まる仮のレイヤを除き、番号がもっとも小さい `PRESENTATION_LAYER_ASSIGNMENT` を使う。ほかのレイヤへの参照ごとに、要素の番号と割り当ての元のレコードを `sxf.p21-layer-member.dropped` で報告する。採用したレイヤの中で繰り返した参照は、この診断に数えない。レイヤの定義と、L1 の元のバイト列は残す。
- 診断は、表や用紙を組み直す順によらず、参照切れや図形の変換時の診断も含めて、元のレコードの入力順に並べる。同じレコードでは報告順を保ち、レコードを持たない診断は最後にする。集約する場所は収集中も設定の件数までに抑え、入力の先頭を残す。場所を 0 件にしても診断の順を保つ。収集・場所の移動・整列と転送を Work に数え、途中で止まっても、収集済みの診断と停止の場所を返す（[決定 0009](../decisions/0009-diagnostics-and-catalog.md)）。
- 呼び出し側がすでに診断を入力順で収集中なら、同じ収集先を使う。入れ子で場所の先頭位置を失わず、転送の Work を二重に数えない。内側の呼び出しも停止を返し、収集済みの診断はもっとも外側の呼び出しが届ける。
- 文字の配置基点は、書き手が下・中・上の行ごとに高さの 1/2・-1/2・-1 だけ文字の上の向きへずらして書くので、戻して SFC の基点にする（推定。旧版が同じ図面の SFC と P21 で確かめた）。9 点の配置は、`TEXT_LITERAL_WITH_EXTENT` の名前の `$$SXF_` の後の行（`baseline`・`middleline`・`topline`）と列（`left`・`centre`・`right`）から読む。斜体の角度と字の間隔は、文字の見え方から読む。
- 点マーカーは `PRE_DEFINED_POINT_MARKER_SYMBOL` の名前から、既定義シンボルは `EXTERNALLY_DEFINED_SYMBOL` の名前から作る。記号の見え方に色がなければ、点マーカーは白、既定義シンボルはレイヤに従う（推定）。
- 寸法は `DRAUGHTING_CALLOUT` の中の寸法線（`DIMENSION_CURVE`）の線の見え方とレイヤを使う。寸法補助線（`PROJECTION_CURVE`）は名前（`$$SXF_prj_1`・`$$SXF_prj_2`）の順に読み、基点は `LINE` の点とする。矢印の向きは、端末記号の X 軸が寸法線の外向きなら 1、内向きなら 2 とする。円弧の寸法の外向きは、始めの側を時計回り、終わりの側を反時計回りの接線とする（推定。旧版の書き手と同じ向き）。寸法値だけの `STRUCTURED_DIMENSION_CALLOUT` は要素にしない。
- 引出線とバルーンは `LEADER_DIRECTED_CALLOUT` で、引出線（`LEADER_CURVE`）の折れ線と、引出線でない円の要素をバルーンの円とする。矢印の名前は `PRE_DEFINED_TERMINATOR_SYMBOL` の名前から矢印のコードにし、名前が表にない矢印は open arrow とする（推定）。
- トリムした曲線は、向きが合っていれば反時計回りとし、クロソイドの曲がる向きは実体の名前に書いた 0・1 とする（推定）。
- 複合曲線は、ハッチングの外形と中抜きから引く。線の見え方とレイヤと表示の可否は、複合曲線を指す `ANNOTATION_CURVE_OCCURRENCE` から読む。SFC の変換は複合曲線にその前の要素をまとめるので、複合曲線は図形の並びの先に置く（推定。P21 は複合曲線を置く所を持たない）。
- 複合図形の定義（`DRAUGHTING_SUBFIGURE_REPRESENTATION`）は、名前の接頭語（`$$SXF_FM_`・`$$SXF_FG_`・`$$SXF_G_`・`$$SXF_P_`）から種類を決め、接頭語がなければ作図グループとする（推定。旧版の扱いを引き継ぐ）。定義は、中の定義から先に、用紙の要素より前に置く。属性付加機構の名前は、接頭語を除いた名前のまま SFC と同じに扱う。
- タイルのハッチングは、最初の `FILL_AREA_STYLE_TILE_SYMBOL_WITH_STYLE` の外部定義の記号から、名前・色・基点・倍率・角度を読む。
- 参照の先がない実体は `sxf.p21-reference.missing`、用紙がなければ `sxf.p21-sheet.missing` で報告する。

## 書き戻し

[決定 0167](../decisions/0167-sxf-sfc-apply.md) の apply は、図面モデルの変更を SFC に書き戻す。P21 には、[決定 0169](../decisions/0169-sxf-p21-apply.md) が同じ変更を書き戻す（下の「P21 への書き戻し」）。

- 変える引数の値の範囲だけを書き直し、フィーチャのコメントを除くか足す。ほかのバイトは写す。
- スタイルの変更は、線分・折線・円・円弧・楕円・楕円弧・スプライン・クロソイドの、引数の 0〜3 のコードのうち変わったものを書き直す。
- 置き換えと移動は、線分・折線・円・円弧の図形の値を書き直す。数は、読み直すと同じ値になる最短の 10 進で書く。
- 除去は、要素を作るフィーチャ（図形・文字・点マーカー・既定義シンボル・寸法・引出線・バルーン・塗りつぶし・ハッチング）を後の改行とともに除く。
- 点マーカーは、レイヤと色（引数の 0〜1）と、点・マーカーのコード・回転・尺度を書き直す。名前空間 `sxf.marker` の既定義のマーカーの点だけを書き、線種と線幅は持たない。鏡映は表せないので断る（[決定 0183](../decisions/0183-drawing-apply-points.md)）。
- 追加は、用紙に線分・折線・円・円弧・点マーカーを、用紙のフィーチャの前に足す。インスタンスの番号は、ファイルの最大の番号の次から付ける。SXF のフィーチャは色・線種・線幅を自分で持ち、レイヤかブロックに従う値を持たない。色（点マーカーと線分・折線・円・円弧）か、線種か線幅（線分・折線・円・円弧）を書かない（レイヤかブロックに従う）追加は、`change.style.unsupported`（`field` は `color`・`line_type`・`line_weight`、`format` は `SFC` か `P21`）で断る。書いた値を受けられないとき（定義のない色など）は、`change.edit.unsupported` で断る（[決定 0292](../decisions/0292-sxf-add-inherited-style.md)）。
- スタイルの変更と置き換えで、コードに戻せない値（レイヤに従う値・定義のないコード・1 でない線種の倍率・レイヤに従わない透過性）、複合曲線がまとめるフィーチャ、複合曲線と複合図形の定義と配置、複数の要素を作るフィーチャ、表の変更は、`change.edit.unsupported` で断る。
- 当てた後に読み直し、変えた要素が求めた値になり、ほかの要素の ID と値が変わらないことを確かめる。

### P21 への書き戻し

[決定 0169](../decisions/0169-sxf-p21-apply.md) の apply は、SFC と同じ変更を受け、同じものを断る。書き方だけが違う。

- 要素は表記の実体である。スタイルの変更は、曲線の見え方と見え方の割り当てを足して指し替える。置き換えと移動は、幾何の実体を足して指し替える。共有しうる元の実体は書き換えない。
- 点マーカーは記号の表記の実体である。形の変更（置き換えと移動）は、点・向き（`DIRECTION`）・配置・尺度を X と Y に書いた `SYMBOL_TARGET`・マーカーの名前の `PRE_DEFINED_POINT_MARKER_SYMBOL`・`DEFINED_SYMBOL` を足して指し替える。色の変更は、`SYMBOL_COLOUR`・`SYMBOL_STYLE`・見え方の割り当てを足し、元の記号の見え方の割り当てと置き換える（なければ並びの終わりへ足す）。元の割り当てがほかの見え方も持てば、それらを同じ順に写し、記号の見え方だけを付け替えた割り当てを足す（[決定 0193](../decisions/0193-dwg-header-resize-and-point-style-read.md)）。追加は、これらと `ANNOTATION_SYMBOL_OCCURRENCE` を足す。マーカーの名前は、読むときと同じ名前の表（コード 1〜7）から引く。回転は向きの成分で書いて角度で読むので、読み直した回転は最後の桁が違いうる（[決定 0190](../decisions/0190-drawing-apply-p21-markers-and-point-styles.md)）。
- 色と線種は、コードを持つ実体を指し、既定義のものがなければ名前で足す。線幅は、同じ太さの `LENGTH_MEASURE_WITH_UNIT` を指し、なければ型を付けた数で書く。
- 除去は、表記の実体と、用紙・レイヤ・非表示・複合図形の定義の並びの中の参照を除く。ほかの所から指される要素は断る。並びを空にする除去とレイヤの変更は断る。空になった非表示は、実体ごと除く。
- 追加は、用紙の並びの終わりとレイヤの並びへ、足した表記の実体を加える。足す実体は、最大の番号の次から番号を付け、最後の実体の後に書く。
- どこからも指されなくなった幾何と見え方の実体は除く。
- 書き直す実体と、複製する `CURVE_STYLE` の変更しない値は、文字列・列挙・数・バイナリの中身と型の名前を元のバイトのまま写す。Shift_JIS の文字列と ISO 10303-21 のエスケープを、いったん文字に戻して書き直すことはしない。並びの区切りと参照番号は書き直す。
- 書き直した実体は、元の改行と空白を保たない。円弧の角度はラジアンで書くので、読み直すと最後の桁が違いうる。確かめるときは、角度だけ相対誤差 1e-9 まで同じとみなす。
- サンプルの P21 で、用紙と部分図の線分・円・円弧・折線を動かし、文字を除き、線分を足して書き戻した。1,043 件のうち、レイヤの最後の文字を除く 3 件は断り、ほかは当たった。

## 確かめた度合い

| 形式 | 向き | 段 |
| --- | --- | --- |
| `sxf` | 読み | `synthetic` |
| `sxf` | 書き | `external` |
| `saf` | 読み | `synthetic` |

段の意味は[決定 0254](../decisions/0254-parallel-agents-and-cross-review.md) に、根拠は[形式と権利の一覧](README.md#format-sxf)（属性ファイルは[こちら](README.md#format-saf)）にあります。段は確かめた方法のうちもっとも強いものを示します。この文書の規則のうち、外部の実装と照らしたのは下の書きの範囲だけで、基準になるソフトとは、まだ照らしていません。実際のファイルでは、ここに書いた扱いと違うことがあります。

- 読み: 受け取った図面（SFC 1 件・P21 1 件）を読み、要素の ID がインスタンスの番号で重ならないことと、書き戻して読み直せることを、テスト（`crates/zumen-sxf/tests/samples.rs`）で確かめた（#288・#290）。読んだ値を外部の実装や SXF ブラウザの表示と照らしていないので、段は `synthetic` にした。ほかの規則は、仕様と、テストの中で作ったファイルだけで確かめた。毎晩の CI で、テストの中で作った SFC・P21 を ezsxf 0.3.7 でも読んで照らす（`xtask/verify`、#528）が、自前で作ったファイルなので、読みの段には数えない。
- 書き: 毎晩の CI で、テストの中で作った SFC・P21 に点を足して書き戻したファイルを ezsxf 0.3.7 で読み、変更で決めた形・レイヤと、SFC の色（既定義色の番号）が ezsxf の読んだ値と合うことを確かめる（`xtask/verify`、#528）。P21 では、点マーカーの種類を比べない。ezsxf は P21 の文字列のエスケープを戻さないので、P21 のレイヤの名前は、照合がファイルのバイトから戻す。ほかの変更を書き戻した SFC・P21 は、自前の読み取りで読み直しただけ。SFZ・P2Z に書き戻したアーカイブは、外部の実装と照らしていない。書き戻した SFC・P21 は、SXF ブラウザなどでは開いていない（#342）。
- 属性ファイル: 仕様と、テストの中で作った SAF とアーカイブだけで確かめた。属性ファイルを結んだアーカイブを SXF ブラウザで開く確認は #494・#505 で行う。
- 複合曲線の前の曲線以外のフィーチャは、合成 SFC で、表示・非表示・表示フラグなし・不正なフラグと、用紙・部分図・作図グループ・作図部品での診断の種類・件数・場所を確かめた。元の要素の配置・出所・ID・順序と、インスタンス番号が重複する文字と後続の円の ID、予算・中断、合成 P21 の未対応の曲線を含むハッチングを断ることも確かめた。検証キットには、非表示の複合曲線の前の文字・点マーカー・ハッチング・作図部品と作図グループの配置を持つ SFC を加え、黙って捨てない照合で診断と元のレコードを結ぶ。ezsxf 0.3.7 はこの複合曲線を読めないと報告するので、外部の実装とは用紙の中にあることを比べず、要素として残る形を照合する（#549）。
- P21 の同番号の後続実体・複数の用紙・複数のレイヤへの所属は、合成 P21 で診断の種類・件数・場所を確かめた。ファイルの順と番号の順が異なるとき、仮のレイヤと同じレイヤ内の重複、空の先頭の用紙、元の図面・ID・書き戻し、Work と中断も確かめた。新規 3 種と参照切れ・図形の変換時の診断を混ぜ、場所の上限が 0 件・1 件のときも入力順で集約すること、同一レコードでは報告順を保つこと、SFC の診断と Work が変わらないことも確かめた。検証キットの P21 にも 3 種類の診断の対象を加え、診断の場所の数と、採用した形・レイヤ・用紙内の所属を ezsxf 0.3.7 との照合で確かめた。照合側も zumen と同じ選び方をするので、仕様の解釈が独立に確かめられたとは扱わない（#550）。
- 診断の収集を 3 段に入れ子にした場合と、収集中の文脈から実際の P21 を lift する場合も、場所の上限 0 件・1 件で入力順・先頭の値・Work・中断と予算停止・収集済みの診断の保持を確かめた。P21 の直接の呼び出しと、図面・診断・停止結果・作業量が一致する。
- Shift_JIS のレイヤ「図枠」を持つ合成 P21 に点を 2 つ足し、元の線と点のレイヤ名と ID、書き戻したファイルのバイトを確かめた。検証キットでは、点の形と所属するレイヤを ezsxf 0.3.7 で照らした。レイヤの所属一覧だけから 2 点を外した対照例は、各点の欠けた所属を検出した。ezsxf は 8 ビットの文字を置き換えるので、照合する名前はファイルのバイトから戻している。レイヤとスタイルを変える回帰では、書き直す実体と複製した `CURVE_STYLE` の元のバイト、入れ子の型と値、変更しない要素の ID と値、Work と中断時に元のファイルを保つことも確かめた。スタイルの名前に引用符と `#` に続く数字があるときも、実際の参照をたどって使い終えた実体を除くことを確かめた（#552）。
- 同じ番号のフィーチャを持つ合成 SFC で、ezsxf 0.3.7 と、各レコードの線・円の形・種類・レイヤを照らした。同じ種類の線を含め、型で読めなかった先頭の線と後の線を区別し、要素の欠落と診断の場所も検査した。用紙と作図グループの所属は、ezsxf が返す元のフィーチャ番号までの照合になる（#553）。
- 計算で有限でなくなる値（#595）は、合成 SFC の楕円・円弧寸法・入れ子の部分図と、合成 P21 の楕円で、`sxf.lift.invalid` の場所、ほかの要素の値と ID が正常な値の組と同じこと、ファイルのバイト列を変えないことを確かめた。P21 の寸法と入れ子の部分図は、SFC と同じ計算を通るので、個別には確かめていない。
- 「旧版が確かめた」「旧版の扱いを引き継ぐ」と書いた扱いは、この版では確かめ直していない。
- 公開サンプルと受け取った図面を外部の実装と照らすことと、SXF ブラウザでの照合は #503 で行う。

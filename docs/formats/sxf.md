# SXF

SXF Ver.3.1 の SFC と P21 を、ファイルモデル（L1）として読み書きする規則と、仕様が決めない所の扱いを記録します。実装は `crates/zumen-sxf` です。仕様の本文は写しません（`formats/ledger.toml`）。

## 対象

- SFC と P21。どちらも ISO 10303-21 の交換構造に入る交換構造の読み取りと文字列のエスケープの戻し方は、IFC と共有する crate `zumen-step` が行う。SFC のフィーチャのコメントのマーカー（`/*SXF`・`/*SXF3`・`/*SXF3.1`）と、AP202 と書いた P21 でそれを読まないことは、`zumen-sxf` が読み方として渡す。
- SFZ・P2Z（SFC・P21 を ZIP に入れたアーカイブ）は、アーカイブの最初の `.sfc`・`.p21` の項目（大文字と小文字を問わない）を SXF として読む（#385）。図面と同じ名前の属性ファイル（下の「属性ファイル」）のほかの項目（画像など）は読まず、`open` の結果の `entries` に、属性ファイルを含むアーカイブの中の名前をアーカイブの順で返す。`.sfc`・`.p21` の項目のない ZIP は SXF にせず、ifcZIP などとして試す。
- SFZ・P2Z への `apply` は、SXF の項目だけを書き直したバイト列に置き換え、ほかの項目は展開したバイト列のまま写したアーカイブを書く。アーカイブは `zumen-zip` で、項目を stored で、日時を 1980-01-01 に固定して書く（決定性、[BCF の読み書き](bcf.md)）。元のアーカイブの圧縮と日時は保たない。ZIP64 が要る大きさなら `sxf.archive.unsupported` を返して書かない（適合テストの `cases/open_sxf_zip.json`）。
- SFC は図面モデルへ移す。API の `open` は SXF の判定の規則で SFC と P21 を読み、`drawing` は SFC と P21 を図面モデルへ移す（適合テストの `cases/open_sxf.json`）。P21 は、実体を SFC と同じ形のフィーチャに組み直して、同じ変換に通す。P21 の組み直しは、下の「P21 の組み直し」に記録する。

## 判定

- 先頭の行が `ISO-10303-21;` なら SXF の候補とする。`FILE_SCHEMA` の最初の名前が `IFC` で始まるものは、先に IFC の判定の規則で分ける（[ifc.md](ifc.md)）。
- `FILE_SCHEMA` の最初の文字列の、最初の語（空白か `{` の前まで）を、大文字と小文字を区別せずに `ASSOCIATIVE_DRAUGHTING` と比べる。違えば `sxf.schema.unsupported` を返す。IFC などを空の図面として読まないため。`FILE_SCHEMA` がない古い SXF は読む（推定）。
- `FILE_DESCRIPTION` の最初の文字列に `feature_mode` があるか、データのセクションにフィーチャのコメントがあれば SFC、ほかは P21 とする。`AP202` とある P21 では、`/*SXF` で始まるコメントもただのコメントとする（推定）。

## レコードの区切り

- `;` で終わる文を 1 つのレコードにする。語（`HEADER;`）、ヘッダーの文（`FILE_NAME(…);`）、インスタンス（`#n=名前(…);`）、複合のインスタンス（`#n=(A(…) B(…));`）。
- データのセクションの `/*SXF` から `SXF*/` までを、SFC のフィーチャのレコードにする。マーカーは長いものから比べ、`/*SXF3.1` は `SXF3.1*/`、`/*SXF3` は `SXF3*/`、`/*SXF` は `SXF*/` で閉じる。中は `#n = 名前(…)` 1 つで、`;` を付けない（推定）。
- レコードの間の空白とコメント、読めなかった文は、レコードにしない。書くときは、レコードとその間を元のバイトのまま並べるので、変えずに書くと元のバイト列と一致する。
- `END-ISO-10303-21;` の後のバイトは、読まずにそのまま持つ。

## 値

- P21 の値は ISO 10303-21 の形で読む。文字列は `''` で閉じず、`\X2\` などのエスケープは戻さずに範囲で持つ。文の中のコメントは飛ばす。
- SFC の値は、`'…'`（次の `'` で閉じる）、`\'…\'`、並び `(…)`、囲まない値に分ける。囲まない値は、`,` か `)` の前までで、前後の空白を除く。
- SFC の `\'…\'` は、Shift_JIS の 2 バイトの文字の 1 バイト目（0x81〜0x9F・0xE0〜0xFC）の次のバイトと、`\\` を飛ばし、後に空白を挟んで `,` か `)` が続く `\'` で閉じる（推定。「表」のように 2 バイト目が `\` の文字があるため）。文字列の中の改行も範囲に含める。

## 壊れた所

- 始まりの行・`DATA` の節・`END-ISO-10303-21;` のどれかがなければ、`sxf.file.invalid` で読まない。
- 形の読めない文は次の `;` まで、閉じのあるフィーチャのコメントは閉じまでを飛ばし、`sxf.record.invalid` にその範囲を付ける。閉じのないコメントは、終わりまでを飛ばす。

## 上限

- 入力のバイト数、レコードの数、値の数（`work`）、並びの入れ子の深さ（`depth`）を予算で数える。止めたら、読んでいた文かコメントの範囲を場所にする。

## 図面モデルへの変換

- フィーチャの引数は、0 から 3 番目がレイヤ・色・線種・線幅のコードで、続きが図形の値。値は `'…'` で囲んだ数でも、囲まない数でも読む。折れ線の座標の並びは、`(…)` でも、`'(…)'` と囲んだものでも読む。
- 要素の出所は、フィーチャのレコードの番号と、そのインスタンスの番号（`#n`）を持つ。要素の ID は、インスタンスの番号で `sheet/0/i20` のように作る。前にフィーチャを足しても、ほかの要素の ID は変わらない。P21 は、要素の出所にした実体（表記の実体など）の番号で作る。同じ図面の SFC と P21 は番号の振り方が違うので、ID は同じにならない。API の `entities` は、出所の `instance` にこの番号を 10 進の文字列で返す。
- 文字列は Shift_JIS で戻し、`\'…\'` の中の `\\` を `\` に戻す。改行は除く。
- 用紙のフィーチャは仕様では最後に書くが、後に要素があっても落とさず用紙に入れる（推定）。
- レイヤの状態は、表示の可否から、印刷を表示に合わせ、編集はできるとする（推定）。
- 楕円弧の角度は、媒介変数の角度とする（推定）。
- スプラインは制御点が 3n + 1 個の 3 次のベジェ曲線をつないだものとし、開閉のフラグは 0 を閉じているとする（推定）。
- 画像は、作図グループの名前の `$$RASTER$$` か、属性の `$$ATRU$$番号$$名称$$画像$$` の後をファイルの名前とし、グループの中の最初の 4 点以上の折れ線を範囲とする（推定）。どれかの点の座標を読めない折れ線（数として読めない値がある、x と y の数が違う）は、角に使わない点であっても範囲にせず、次の折れ線を探す（推定）。ふつうの折れ線として読めない折れ線は範囲にもしない、という読み方で、「最初の 4 点以上の折れ線」を、ふつうの折れ線として読める折れ線の中で数える。決定は変えない。飛ばした折れ線は、ほかの読めない折れ線と同じく `sxf.lift.invalid` で知らせる。P21 の照合（`xtask/verify/check_ezsxf.py` の `raster_outline`）も同じ選び方をするので、この所は外部の実装で独立に確かめていない。SFC の画像の範囲は、照合で比べていない（#651）。
- 図面表題欄の 12 の項目の順は、事業名・工事名・契約区分・図面名・図面番号・図面種別・尺度・作成年・作成月・作成日・受注会社名・発注事業者名とする（推定。[図面モデルとの対応](drawing2d-mapping.md)）。
- 点マーカーは、名前空間 `sxf.marker` とマーカーのコードを既定義のマーカーのキーにした点にし、回転と尺度を移す。記号にはしない。
- クロソイドは値のまま移し、曲がる向きのフラグは 0 を反時計回りとする（推定。[図面モデルとの対応](drawing2d-mapping.md)）。
- 文字の 9 点の配置は、1 を左下とし、右へ 1 つずつ、上へ 3 つずつ数える（推定）。文字範囲の幅と字の間隔は `sxf.text` の拡張に残す。
- 寸法は、定義点と寸法値の文字を図面モデルの寸法に、寸法線と補助線の端・矢印・文字範囲の幅と字の間隔を `sxf.dimension` の拡張に移す。弧長と角度の寸法の弧は、始めの角度から反時計回りとし、半径の寸法は、矢印がなければ終点を円の上の点とする（推定）。
- 引出線とバルーンは、引出線つきの注記にする。頂点は矢印の側から並び、矢印は名前空間 `sxf.arrow` のコードのキーで指し、大きさはコードの表で決まるとする（推定）。バルーンの円は `sxf.callout` の拡張に残す。
- ハッチングは、指す複合曲線の曲線の辺を並べた輪にする。表示する複合曲線は、曲線を複合曲線の色・線種・線幅で置き、線のハッチングの要素の色は 1 本目の線の色にする（推定）。
- 現在の複合曲線のまとめ方では、前に書いた文字・点マーカー・ハッチング・複合図形の配置なども取り込む。これらは曲線にはせず、表示の有無によらず `sxf.lift.dropped` で元のレコードを報告する。表示フラグが不正な場合も、複合曲線の `sxf.lift.invalid` に加えて報告する。同じインスタンス番号の文字と後続の円がある場合、文字を要素に戻すと既存の円の ID が変わるため、この修正では要素に戻さない。復元は #611 で扱う。このようなフィーチャを含むハッチングの境界は、従来どおり `sxf.lift.invalid` で断る。
- 作図部品は名前空間 `sxf.sfig` の記号の定義に、既定義シンボルは名前空間 `sxf.symbol` の名前のキーにする。色を指定しない既定義シンボルの色はレイヤに従う（推定）。部分図の中の部分図は、外の部分図のビューに重ねたビューにする。
- 名前が `$$ATR` で始まる複合図形の要素に、名前と `$$` で区切った値を `sxf.attribute` の拡張で付ける。背景色などの値は解かない。
- 測地座標系の部分図は、実寸の空間の `axes` を `Axes::NorthEast`（X が北、Y が東）にし、点はファイルの X・Y のまま持つ。ビューの変換が、東・北の順に直してから用紙へ置く（[座標系の扱い](crs.md)、[crs.md](crs.md)）。
- まだ移さない種類と、読めない値は、`sxf.lift.dropped`・`sxf.lift.invalid` で報告する。
- 読んだ値が有限でも、計算した値が無限大か NaN になるものは、図形・ビューにせず、元のフィーチャ（P21 は表記の実体）を場所にした `sxf.lift.invalid` で報告する（#595）。対象は次の 3 つである。
  - 楕円・楕円弧の長軸の端の点（中心と半径の和があふれる）
  - 円弧寸法・角度寸法の点（角度の差か、中心と半径の和があふれる）
  - 部分図の中の部分図のビュー（内と外の尺度の積があふれる）。そのビューの中身も置かない。診断の場所は内の配置のフィーチャで、作らないビューごとに 1 件なので、外の部分図を何度も置くと、同じ場所の診断が置いた数だけ出る
- 計算した値が有限のまま極端な値で変わるものは、次のように扱う（#728）。
  - 長さ寸法の補助線の傾きは、寸法線と補助線の向きの内積と、比べる値（長さの積の 1e-9 倍）があふれも潰れもしなければ、前と同じ式で求める。そうでなければ、向きを大きいほうの成分の指数で 2 の冪に割ってから比べる（端の差があふれれば、半分どうしの差から求める）。寸法線の端の差があふれる値（`-1e308` と `1e308` など）と、内積と長さの積があふれるか潰れる値（`1e200` や `1e-200` の大きさの座標）でも、傾きを正しく求める。
  - 楕円・楕円弧の半径の比（小さいほうを大きいほうで割る）が 0 に丸められるもの（`1e300` と `1e-300` など）は、潰れた楕円にせず、元のフィーチャを場所にした `sxf.lift.invalid` で報告する。0 にならない比は、小さくてもそのまま楕円にする。
- SFC の診断も、表・複合曲線・複合図形・用紙の変換段階によらず、P21 と同じく元のレコードの入力順に並べ、集約する場所は入力の先頭を残す（#624）。図面・ID・書き戻しは変えない。集める手間を Work に数えるので、SFC の図面モデルへの変換の Work は、診断の数と残す場所の数の分だけ増える。`apply` の中で行う変換も、同じだけ増える。

## 属性ファイル

属性ファイル（SAF、附属書の属性付加機構編の 3 章）を読み、属性ファイル用の属性付加機構の要素に結ぶ（`crates/zumen-sxf/src/saf.rs`）。

- `open` の `saf` に名指した入力か、なければ P2Z・SFZ の中の、図面と同じ名前の SAF（拡張子を `.SAF` にしたものか、図面の項目の名前に `.SAF` を足したもの。大文字と小文字を問わない）を読む。ほかの名前の SAF は結ばない。
- 根の `SxfAttributeXML` の `version`・`date`・`sxfFile`・`application`、`AttributeSet`（内容が属性セット識別番号）、`Figure` の `AttrSetRef` の `Attr` と `AttrGroup` を読む。文書型宣言（`SXFV31.DTD`）は解決せず、診断もしない。
- 省略できないタグ属性がないものと、重なる図形識別番号は `sxf.saf-value.invalid` を、知らない要素は `sxf.saf-element.unsupported` を返す。根が `SxfAttributeXML` でなければ、属性ファイルなしで図面を開く。
- 作図グループの名前は `$$ATRF$$図形識別番号$$属性ファイル名` と、ファイル名を省いた `$$ATRF$$図形識別番号` を読む。グループを置いた要素に、読み込んだ SAF の同じ図形識別番号の属性を、属性ごとに `sxf.saf` の拡張で付ける。拡張の名前は属性名で、フィールドは `figure`・`figure_name`・`set`・（属性セットがあれば）`set_name`・`set_version`・`designed_by`・（グループの中なら）`group`・（書いてあれば）`type`・`unit`・`value` の順。値は文字のまま持ち、`$$$`（文字列の内容を属性値にする）も解かない。
- 図面の図形識別番号の図形が属性ファイルになければ `sxf.saf-figure.missing` を、属性ファイルの図形の要素が図面になければ `sxf.saf-figure.dropped` を返す。
- 属性ファイルは書き直さない。P2Z・SFZ への `apply` は、SAF の項目をそのまま写す。

## P21 の組み直し

- 表は実体の番号の順に組み直し、利用者定義の色・線種・文字フォントとレイヤに、その順でコードを付ける。線幅は、既定義の太さでなければ、最初に使った順に 11 から付ける。
- 名前が `$$SXF_` で始まる `COLOUR_RGB` は既定義色に、名前が `$$SXF_dummy` で始まるレイヤは複合図形の仮のレイヤとしてレイヤにしない（推定）。
- 文字列は ISO 10303-21 のエスケープを戻し、規格の外の 8 ビットのバイトは Shift_JIS として読む（推定）。
- 同じ番号の実体は、ファイルの順で最初だけを使う。後の実体は `sxf.p21-instance.dropped` で、番号と元のレコードを報告する。L1 には元のバイト列を残す。
- 用紙は、番号がもっとも小さい `DRAWING_SHEET_REVISION` で、要素はその並びの順に置く。ほかの用紙は `sxf.p21-sheet.dropped` で、番号と元のレコードを報告する。用紙の名前が `A0`〜`A4` と向き（`horizontal`・`vertical`）でなければ、自由サイズとして `PLANAR_BOX` の大きさを使う。
- 1 つの要素が複数のレイヤに属すれば、名前が `$$SXF_dummy` で始まる仮のレイヤを除き、番号がもっとも小さい `PRESENTATION_LAYER_ASSIGNMENT` を使う。ほかのレイヤへの参照ごとに、要素の番号と割り当ての元のレコードを `sxf.p21-layer-member.dropped` で報告する。採用したレイヤの中で繰り返した参照は、この診断に数えない。レイヤの定義と、L1 の元のバイト列は残す。
- 診断は、表や用紙を組み直す順によらず、参照切れや図形の変換時の診断も含めて、元のレコードの入力順に並べる。同じレコードでは報告順を保ち、レコードを持たない診断は最後にする。集約する場所は収集中も設定の件数までに抑え、入力の先頭を残す。場所を 0 件にしても診断の順を保つ。収集・場所の移動・整列と転送を Work に数え、途中で止まっても、収集済みの診断と停止の場所を返す。
- 呼び出し側がすでに診断を入力順で収集中なら、同じ収集先を使う。入れ子で場所の先頭位置を失わず、転送の Work を二重に数えない。内側の呼び出しも停止を返し、収集済みの診断はもっとも外側の呼び出しが届ける。
- 文字の配置基点は、書き手が下・中・上の行ごとに高さの 1/2・-1/2・-1 だけ文字の上の向きへずらして書くので、戻して SFC の基点にする（推定）。9 点の配置は、`TEXT_LITERAL_WITH_EXTENT` の名前の `$$SXF_` の後の行（`baseline`・`middleline`・`topline`）と列（`left`・`centre`・`right`）から読む。斜体の角度と字の間隔は、文字の見え方から読む。
- 点マーカーは `PRE_DEFINED_POINT_MARKER_SYMBOL` の名前から、既定義シンボルは `EXTERNALLY_DEFINED_SYMBOL` の名前から作る。記号の見え方に色がなければ、点マーカーは白、既定義シンボルはレイヤに従う（推定）。
- 寸法は `DRAUGHTING_CALLOUT` の中の寸法線（`DIMENSION_CURVE`）の線の見え方とレイヤを使う。寸法補助線（`PROJECTION_CURVE`）は名前（`$$SXF_prj_1`・`$$SXF_prj_2`）の順に読み、基点は `LINE` の点とする。矢印の向きは、端末記号の X 軸が寸法線の外向きなら 1、内向きなら 2 とする。円弧の寸法の外向きは、始めの側を時計回り、終わりの側を反時計回りの接線とする（推定）。寸法値だけの `STRUCTURED_DIMENSION_CALLOUT` は要素にしない。
- 引出線とバルーンは `LEADER_DIRECTED_CALLOUT` で、引出線（`LEADER_CURVE`）の折れ線と、引出線でない円の要素をバルーンの円とする。矢印の名前は `PRE_DEFINED_TERMINATOR_SYMBOL` の名前から矢印のコードにし、名前が表にない矢印は open arrow とする（推定）。
- トリムした曲線は、向きが合っていれば反時計回りとし、クロソイドの曲がる向きは実体の名前に書いた 0・1 とする（推定）。
- 複合曲線は、ハッチングの外形と中抜きから引く。線の見え方とレイヤと表示の可否は、複合曲線を指す `ANNOTATION_CURVE_OCCURRENCE` から読む。SFC の変換は複合曲線にその前の要素をまとめるので、複合曲線は図形の並びの先に置く（推定。P21 は複合曲線を置く所を持たない）。
- 複合図形の定義（`DRAUGHTING_SUBFIGURE_REPRESENTATION`）は、名前の接頭語（`$$SXF_FM_`・`$$SXF_FG_`・`$$SXF_G_`・`$$SXF_P_`）から種類を決め、接頭語がなければ作図グループとする（推定）。定義は、中の定義から先に、用紙の要素より前に置く。属性付加機構の名前は、接頭語を除いた名前のまま SFC と同じに扱う。
- タイルのハッチングは、最初の `FILL_AREA_STYLE_TILE_SYMBOL_WITH_STYLE` の外部定義の記号から、名前・色・基点・倍率・角度を読む。
- 参照の先がない実体は `sxf.p21-reference.missing`、用紙がなければ `sxf.p21-sheet.missing` で報告する。

## 書き戻し

SXF の apply は、図面モデルの変更を SFC に書き戻す。P21 には、同じ変更を書き戻せる（下の「P21 への書き戻し」）。

文字は `text_string` の内容・位置・高さ・角度・傾斜・位置合わせ・書体と、色・レイヤを書き戻す。書式が均一な 1 区間の文字を受け、改行・鏡映・背景・折り返し・個別の書式は断る。元の文字の幅と字間は高さの変更に合わせて伸縮する。追加時は半角を高さの半分、それ以外を高さとして幅を見積もり、`sxf.text-width.approximated` で場所と件数を返す。書体がなければ `text_font` を足す。

レイヤは名前と表示を変更でき、末尾のコードに追加する。表示と印刷は同じにし、編集可能・凍結なしとする。色・線種・線幅・説明の指定、既存の未定義参照と衝突する追加は断る。SFC の新しい文字列は Shift_JIS で往復できるものに限り、表せない文字・制御文字・コメントの終端は変更全体を断る。

公開 API では、文字の `add` に `text`、読み取った文字の `replace` に `formatted_text` を渡し、移動は `transform`、色・レイヤの変更は `restyle` を使う。追加する文字には色を指定し、線種と線幅は指定しない。レイヤは `add_layer`・`layer` で編集する。同じ操作を SFZ・P2Z にも使い、図面以外の添付を保つ。同じ `apply` で追加するレイヤを要素から指すことは、まだできない。

- 変える引数の値の範囲だけを書き直し、フィーチャのコメントを除くか足す。ほかのバイトは写す。
- スタイルの変更は、線分・折線・円・円弧・楕円・楕円弧・スプライン・クロソイドの、引数の 0〜3 のコードのうち変わったものを書き直す。
- 置き換えと移動は、線分・折線・円・円弧の図形の値を書き直す。数は、読み直すと同じ値になる最短の 10 進で書く。
- 除去は、要素を作るフィーチャ（図形・文字・点マーカー・既定義シンボル・寸法・引出線・バルーン・塗りつぶし・ハッチング）を後の改行とともに除く。
- 点マーカーは、レイヤと色（引数の 0〜1）と、点・マーカーのコード・回転・尺度を書き直す。名前空間 `sxf.marker` の既定義のマーカーの点だけを書き、線種と線幅は持たない。鏡映は表せないので断る。
- 追加は、用紙に線分・折線・円・円弧・点マーカー・文字を、用紙のフィーチャの前に足す。インスタンスの番号は、ファイルの最大の番号の次から付ける。SXF のフィーチャは色・線種・線幅を自分で持ち、レイヤかブロックに従う値を持たない。色（点マーカー・文字と線分・折線・円・円弧）か、線種か線幅（線分・折線・円・円弧）を書かない（レイヤかブロックに従う）追加は、`change.style.unsupported`（`field` は `color`・`line_type`・`line_weight`、`format` は `SFC` か `P21`）で断る。SFC で書き込む既定義色（コード 1〜16）の宣言がなければ、対応する名前の `pre_defined_colour` を 1 件足す。書いた値を受けられないとき（定義のない利用者定義色など）は、`change.edit.unsupported` で断る。
- 複写（`Edit::Copy` と `SxfFile::applied_with_copies`、#889）は、SFC と P21 の用紙上の線分・折線・円・円弧・点マーカー・文字・複合図形配置を、スタイルと文字範囲の幅・字間（`sxf.text`）を保ったまま足す。複合曲線（`composite_curve_org`）の要素、属性付加機構（`$$ATR*`・SAF の `$$ATRF$$`）が付いた要素、用紙以外の場所は `change.copy.unsupported` で全体を拒む。
- コードに戻せない値（スタイルの変更と置き換えのレイヤに従う値・定義のないコード・1 でない線種の倍率・レイヤに従わない透過性）と、複合曲線がまとめるフィーチャ、複合曲線と複合図形の定義と配置、複数の要素を作るフィーチャ、レイヤ以外の表の変更は、`change.edit.unsupported` で断る。
- 当てた後に読み直し、変えた要素が求めた値になり、ほかの要素の ID と値が変わらないことを確かめる。

### P21 への書き戻し

SXF の apply は、SFC と同じ変更を受け、同じものを断る。書き方だけが違う。

文字は `ANNOTATION_TEXT_OCCURRENCE` の参照先に、文字列・配置・範囲・書式を追加して付け替える。共有する元の文字と書式は変更しない。新しい文字列は ASCII と UTF-16 の X2 エスケープを使う。文字の位置・回転・傾斜は、読み直しでの相対誤差 1e-9 までを同じとみなす。レイヤの追加と最後の要素のレイヤ変更では、所属一覧を空にしないため、用紙に置かない補助点を使う。非表示は `INVISIBILITY` で切り替える。

- 要素は表記の実体である。スタイルの変更は、曲線の見え方と見え方の割り当てを足して指し替える。置き換えと移動は、幾何の実体を足して指し替える。共有しうる元の実体は書き換えない。
- 点マーカーは記号の表記の実体である。形の変更（置き換えと移動）は、点・向き（`DIRECTION`）・配置・尺度を X と Y に書いた `SYMBOL_TARGET`・マーカーの名前の `PRE_DEFINED_POINT_MARKER_SYMBOL`・`DEFINED_SYMBOL` を足して指し替える。色の変更は、`SYMBOL_COLOUR`・`SYMBOL_STYLE`・見え方の割り当てを足し、元の記号の見え方の割り当てと置き換える（なければ並びの終わりへ足す）。元の割り当てがほかの見え方も持てば、それらを同じ順に写し、記号の見え方だけを付け替えた割り当てを足す。追加は `ANNOTATION_SYMBOL_OCCURRENCE`・`DRAUGHTING_ANNOTATION_OCCURRENCE` を含む複合の実体を作る。`STYLED_ITEM` が見え方の割り当てと記号を指し、用紙とレイヤの所属一覧がこの複合の実体を指す（#342）。マーカーの名前は、読むときと同じ名前の表（コード 1〜7）から引く。回転は向きの成分で書いて角度で読むので、読み直した回転は最後の桁が違いうる。
- 色と線種は、コードを持つ実体を指し、既定義のものがなければ名前で足す。線幅は、同じ太さの `LENGTH_MEASURE_WITH_UNIT` を指し、なければ型を付けた数で書く。
- 除去は、表記の実体と、用紙・レイヤ・非表示・複合図形の定義の並びの中の参照を除く。ほかの所から指される要素は断る。並びを空にする除去は断る。空になった非表示は、実体ごと除く。
- 追加は、用紙の並びの終わりとレイヤの並びへ、足した表記の実体を加える。足す実体は、最大の番号の次から番号を付け、最後の実体の後に書く。
- どこからも指されなくなった幾何と見え方の実体は除く。
- 書き直す実体と、複製する `CURVE_STYLE` の変更しない値は、文字列・列挙・数・バイナリの中身と型の名前を元のバイトのまま写す。Shift_JIS の文字列と ISO 10303-21 のエスケープを、いったん文字に戻して書き直すことはしない。並びの区切りと参照番号は書き直す。
- 書き直した実体は、元の改行と空白を保たない。円弧の角度はラジアンで書くので、読み直すと最後の桁が違いうる。確かめるときは、角度だけ相対誤差 1e-9 まで同じとみなす。
- サンプルの P21 で、用紙と部分図の線分・円・円弧・折線を動かし、文字を除き、線分を足して書き戻した。1,043 件のうち、レイヤの最後の文字を除く 3 件は断り、ほかは当たった。

## 確かめた度合い

自作の UTF-16LE・UTF-16BE の SAF で、線への属性の結合を検査します。[XML の規則](xml.md)を使います。この文字コードの追加の確認は `synthetic` で、既存の SFC・P21 の外部照合の範囲には含めません。

文字とレイヤは、合成の適合テスト `apply_text_sfc`・`apply_text_p21`・`apply_text_sfz`・`apply_text_p2z` と [`check_text_apply.py`](../../xtask/verify/check_text_apply.py) で確認します。内容・位置・高さ・幅・角度・書体・色・レイヤと追加・改名したレイヤを ezsxf 0.3.7 と照らします。P21 は ezsxf の実体解析結果の参照をたどる照合で、表示ソフトでの確認は含みません。圧縮形式は図面を取り出して照合し、添付が保たれることも確かめます。日本語・Unicode の符号化、共有した文字と書式、拒否時の原子的な扱いは crate の合成テストで確かめます。

自作の Shift_JIS の SAF で、日本語の未知の要素名を診断に返し、図形識別番号を保つことを検査します。この確認も `synthetic` です。

| 形式 | 向き | 段 |
| --- | --- | --- |
| `sxf` | 読み | `application` |
| `sxf` | 書き | `application` |
| `saf` | 読み | `application` |

段の意味は[形式台帳の書き方](../../formats/README.md#確かめた度合い)に、根拠は[形式と権利の一覧](README.md#format-sxf)（属性ファイルは[こちら](README.md#format-saf)）にあります。段は確かめた方法のうちもっとも強いものを示します。実際のソフトで開いて照合した図形・属性と、外部の読み取りで比べた値を以下に示します。

- 読み: 公開サンプル（`samples/sxf/ezsxf-writer-all-features.sfc`）を毎晩の CI で ezsxf 0.3.7 と照らし、レイヤ・用紙の所属・図形の種類・線分と折線と円と円弧の形・黙って捨てていないことを確かめる（`xtask/verify`、#874）。受け取った図面（SFC 1 件・P21 1 件）を読み、要素の ID がインスタンスの番号で重ならないことと、書き戻して読み直せることも、テスト（`crates/zumen-sxf/tests/samples.rs`）で確かめた（#288・#290）。ほかの規則は、仕様と、テストの中で作ったファイルだけで確かめた。
- 書き: 毎晩の CI で、テストの中で作った SFC・P21 に点を足して書き戻したファイルを ezsxf 0.3.7 で読み、変更で決めた形・レイヤと、SFC の色（既定義色の番号）が ezsxf の読んだ値と合うことを確かめる（`xtask/verify`、#528）。P21 では、点マーカーの種類を比べない。ezsxf は P21 の文字列のエスケープを戻さないので、P21 のレイヤの名前は、照合がファイルのバイトから戻す。文字とレイヤは、上記の合成テストでも照合する。ほかの変更を書き戻した SFC・P21 は、自前の読み取りで読み直しただけ。属性付き SFZ・P2Z の 8 組は [SAF 検証キット](../../xtask/verify/saf/)で ZIP の非対象の項目・図形・属性を照合した。
- 型付き SFC に書き戻した 2 点を DynaCAD ビューアー 9.00.00 で赤いポイントとして選択した。Jw_cad 10.3.6.0 で開いて SFC に書き出し、位置 (50, 60)・(80, 60)、印 1・3、回転 30°・0°、倍率 1、色番号 2（赤）が一致した。[2 点の実測と対象範囲](https://github.com/zumen-jp/zumen/issues/342#issuecomment-7045359046)。
- Jw_cad 10.3.6.0 が保存した SFC と P21 を公開 `apply` で編集し、点を 1 個移動して 1 個追加した。書き戻した両方を Jw_cad で開き、別名保存した SFC を ezsxf 0.3.7 で再読した。移動した点は (55, 67)・印 1・30°・倍率 1、追加した点は (65, 43)・印 1・45°・倍率 2、残した点は (80, 60)・印 3・0°・倍率 1 で、すべて赤だった。元の線分と円の座標・半径も一致した。旧い最小入力の照合範囲は[点の検証キット](../../xtask/verify/points/)に記す。
- 属性ファイル: 電子納品では拡張子を除いた名前を図面とそろえる。DynaCAD（ビューアー 9.00.00）で、同名幹の SAF を持つ SFZ 2 組は編集前後とも線分の属性値が一致した。図面の拡張子にさらに `.SAF` を足す名前は zumen が互換のために読む。SFZ 2 組でこの名前の属性は同ビューアーに表示されなかった。自作 P21 は、線分の作図グループの配置を用紙の要素に加えた場合に同ビューアーで開けなかった。[P21 の対照と残る実機照合](../../xtask/verify/saf/kit-readme.md#p21-の用紙に属性付きの線分を置く照合)。[農林水産省「測量成果電子納品要領（案）」付属資料 4](https://www.maff.go.jp/j/nousin/seko/nouhin_youryou/pdf/survey_youryob_h2603.pdf)・[実測結果](https://github.com/zumen-jp/zumen/issues/494#issuecomment-6969769269)。
- この実測後に、自作 P21 では属性付き作図グループの定義原点で参照方向を省き、配置では X 軸の向きを指定した。画層 L に置いた配置からグループ内の線分までを、円の編集前後とも ezsxf でたどる。修正後の P2Z の実機照合は未完了。[国土交通省 SXF Ver.3.1 第 2 版、STEP AP202 サブセット編 2-1-20・2-1-21](https://www.cals-ed.go.jp/sxf_ver3-1_specification_draft/)
- 国土技術政策総合研究所の完成平面図サンプル 1（SXF Ver.3.1）は、同名幹の P21 と SAF を持つ。SAF の属性セットは 1 件、図形は 126 件、属性は 534 件。P21 の作図グループの定義と配置はいずれも SAF 名を省き、126 個の図形識別番号が SAF と一致した。公開 API の `open` に SAF を指定し、既定予算で `lift` した。グループ内の各要素に属性が付くため、図面モデルには 265 要素に 812 件の `sxf.saf` 拡張がある。全要素の属性名・値・型・単位・グループ・属性セット情報が元の XML と一致した。`open` に診断はなく、`lift` には `sxf.code.missing` の診断があった。DynaCAD ビューアー 9.00.00 で同じ原本を開き、画層一覧と、連続線 1 件の図形識別番号・属性セット・グループ・文字列属性 2 件を確認した。値のある属性と空欄の属性はいずれも元の SAF と一致した。[国土技術政策総合研究所のサンプル配布案内](https://www.nilim-cdrw.go.jp/dl_sample.html)
- 複合曲線の前の曲線以外のフィーチャは、合成 SFC で、表示・非表示・表示フラグなし・不正なフラグと、用紙・部分図・作図グループ・作図部品での診断の種類・件数・場所を確かめた。元の要素の配置・出所・ID・順序と、インスタンス番号が重複する文字と後続の円の ID、予算・中断、合成 P21 の未対応の曲線を含むハッチングを断ることも確かめた。検証キットには、非表示の複合曲線の前の文字・点マーカー・ハッチング・作図部品と作図グループの配置を持つ SFC を加え、黙って捨てない照合で診断と元のレコードを結ぶ。ezsxf 0.3.7 はこの複合曲線を読めないと報告するので、外部の実装とは用紙の中にあることを比べず、要素として残る形を照合する（#549）。
- P21 の同番号の後続実体・複数の用紙・複数のレイヤへの所属は、合成 P21 で診断の種類・件数・場所を確かめた。ファイルの順と番号の順が異なるとき、仮のレイヤと同じレイヤ内の重複、空の先頭の用紙、元の図面・ID・書き戻し、Work と中断も確かめた。新規 3 種と参照切れ・図形の変換時の診断を混ぜ、場所の上限が 0 件・1 件のときも入力順で集約すること、同一レコードでは報告順を保つこと、SFC の診断と Work が変わらないことも確かめた（#624 で SFC も入力順にし、この確かめは置き換えた）。検証キットの P21 にも 3 種類の診断の対象を加え、診断の場所の数と、採用した形・レイヤ・用紙内の所属を ezsxf 0.3.7 との照合で確かめた。照合側も zumen と同じ選び方をするので、仕様の解釈が独立に確かめられたとは扱わない（#550）。
- 診断の収集を 3 段に入れ子にした場合と、収集中の文脈から実際の P21 を lift する場合も、場所の上限 0 件・1 件で入力順・先頭の値・Work・中断と予算停止・収集済みの診断の保持を確かめた。P21 の直接の呼び出しと、図面・診断・停止結果・作業量が一致する。
- SFC の診断の順（#624）: 表の段階の診断（`sxf.lift.invalid`）と図形の段階の診断（`sxf.lift.dropped`）が混ざる合成 SFC で、入力順に並ぶこと、同じ診断の場所が入力の先頭から残ること、場所の上限 0 件・1 件で順・件数・値が変わらないこと、Work の上限ちょうどで通り 1 少ないと止まること、中断で止まることを確かめた。1 つのレコード（引数の足りない複合曲線）が続けて報告する 3 つの `sxf.code.missing` が、報告した順のまま、後ろのレコードを表の段階で報告した `sxf.lift.invalid` より前に並ぶことも確かめた。表の段階で `sxf.member.assumed`、図形の段階で `sxf.lift.dropped` を報告するレコードでも、その順を保つ。作図グループの要素を配置した所で変換する SFC と、部分図の要素を前に書いた用紙の要素より先に変換する SFC では、同じ診断の場所が後ろのレコードから先に届くが、場所は入力順に並び、場所の上限 0 件・1 件でも入力の先頭を残すことを確かめた。複合曲線の走査が予算で止まる場所の試験は、集める手間の分だけ予算を上げて同じ場所を確かめる。適合テストの `composite_sxf` の SFC でも、図形の段階の診断のあとに表の段階の診断が来ていた順を、入力順に直した。
- Shift_JIS のレイヤ「図枠」を持つ合成 P21 に点を 2 つ足し、元の線と点のレイヤ名と ID、書き戻したファイルのバイトを確かめた。検証キットでは、点の形と所属するレイヤを ezsxf 0.3.7 で照らした。レイヤの所属一覧だけから 2 点を外した対照例は、各点の欠けた所属を検出した。ezsxf は 8 ビットの文字を置き換えるので、照合する名前はファイルのバイトから戻している。レイヤとスタイルを変える回帰では、書き直す実体と複製した `CURVE_STYLE` の元のバイト、入れ子の型と値、変更しない要素の ID と値、Work と中断時に元のファイルを保つことも確かめた。スタイルの名前に引用符と `#` に続く数字があるときも、実際の参照をたどって使い終えた実体を除くことを確かめた（#552）。
- 同じ番号のフィーチャを持つ合成 SFC で、ezsxf 0.3.7 と、各レコードの線・円の形・種類・レイヤを照らした。同じ種類の線を含め、型で読めなかった先頭の線と後の線を区別し、要素の欠落と診断の場所も検査した。用紙と作図グループの所属は、ezsxf が返す元のフィーチャ番号までの照合になる（#553）。
- 計算で有限でなくなる値（#595）は、合成 SFC の楕円・円弧寸法・入れ子の部分図と、合成 P21 の楕円で、`sxf.lift.invalid` の場所、ほかの要素の値と ID が正常な値の組と同じこと、ファイルのバイト列を変えないことを確かめた。P21 の寸法と入れ子の部分図は、SFC と同じ計算を通るので、個別には確かめていない。
- 有限のまま極端な値で変わる値（#728）は、合成 SFC の長さ寸法（寸法線の端の差があふれるもの、内積と長さの積があふれるものと潰れるもの）と楕円（半径の比が 0 に丸められるもの）で、補助線の傾きと、`sxf.lift.invalid` の場所、ほかの要素の ID が正常な値の組と同じことを確かめた（`synthetic`）。
- 公開サンプルと受け取った図面を外部の実装と照らすことと、SXF ブラウザでの照合は #503 で行う。

## 記号定義からの配置

`tables` の `sxf.sfig` の名前から、既存の作図部品（種類 4）を用紙へ `add` で配置できます。SFC は `sfig_locate`、P21 は既存の `DRAUGHTING_SUBFIGURE_REPRESENTATION` を指す `SYMBOL_REPRESENTATION_MAP`・`MAPPED_ITEM` と配置・表記の実体を書きます。P21 は用紙とレイヤの所属一覧に追加します。部品の定義は変更しません。配置の色・線種はレイヤに従い、線幅は持ちません。固有のスタイル・格子・属性・切り抜きは断ります。P21 の回転は向きで書くため、円弧と点マーカーと同じ相対誤差 1e-9 で再読を確かめます。

P21 の未配置の作図部品も、配置から読んだ既存定義の後に実体番号の順で読みます。従来から読み取る空間の ID は変えません。追加後にほかの要素の ID か値が変われば、書き戻しの従来の検査で断ります。`drawing_metadata_formats` の合成 SFC・P21 で、一覧の名前から配置し、位置・倍率・定義の参照と再読後の応答を確かめます。[外部照合](../../xtask/verify/README.md#記号定義の配置を照らす)では ezsxf 0.3.7 の定義参照・位置・倍率・回転・所属と未変更の実体を比べます。この配置の追加は、SXF ブラウザでは確認していません。

## 新しい P21 への変換

農林水産省の電気通信設備編（平成 25 年 3 月）は、1-3-1 で SXF（P21）Ver.2.0 レベル 2 以上を対象とする。1-3-11（2）は、補助線の移動で値を更新するような CAD の寸法機能を使い、対象物に合う種類の寸法で受け渡すことを求める。富山県も、寸法線の属性を失うと図面の再利用が難しくなると説明している。[農林水産省の作成要領](https://www.maff.go.jp/j/nousin/seko/nouhin_youryou/pdf/cad_elec_youryoa_h2503.pdf)・[富山県の電子納品 Q&A](https://www.pref.toyama.jp/1510/kendodukuri/doboku/faq.html)。

スキーマ 1.85 の `convert`・`convert_estimate` で `format: "sxf"` を指定すると、L2 の図面から新しい P21 を作る（#360）。Rust では `zumen_sxf::lower_to_p21` を呼ぶ。既存の P21/SFC の書き戻しとは別の経路で、受け取ったファイルの未解釈のレコードはコピーしない。自作の表と用紙に既存の `apply` で図形を追加し、表の組み立てに使う仮の円を除いてから返す。用紙の枠と空レイヤの補助点は図形に数えない。

- 線・円・円弧・幅と膨らみのない折れ線・1 行の文字・点マーカーを追加できる。通常の点は既定義の dot にし、文書の点スタイルは保持しない。追加処理が受け入れない形・文字の配置は、ほかの図形と分けて落とす。
- 水平な直線寸法は、両端の定義点、寸法線、2 本の補助線、表示文字を 1 件の寸法にまとめる（#920）。実寸の空間では既知の単位を mm に直し、部分図に実寸を書いてビューの正の等方尺度と平行移動で配置する。最初の用紙の対象空間の最初のビューを使う。矩形の切り抜きがある場合は、定義点・寸法線・文字位置がその中にある寸法を扱う。回転、傾いた補助線、非表示レイヤを伴うビューは対象外とする。
- 寸法値は表示時の文字に固定する（`dimension_label_fixed`）。定義点から測れる距離と、元の上書き文字は別々に残る。DXF のグループ 42 の値を P21 に独立して保存できない場合は `stored_measurement`、文字や線の見え方の変更は `dimension_appearance` を元の寸法の場所に報告する。両端の記号は省き、元の寸法に `dimension_terminators` を付ける。端ごとの欠落は `dimension_terminator` に 2 件を数え、`first`・`second` で位置を区別する。書式を含む上書きや対象外の寸法は、出所付きで欠落に数える。
- 実寸の各空間は、最初の用紙の、正の等方尺度・軸平行・切り抜きと非表示レイヤのない最初のビューに置く。それがなければ、既知の単位を mm に直して 1:1 で置く。単位不明は数値を使い、`unit_unspecified` で知らせる。X/Y が東/北の順でない空間は、図形ごとに落とす。モデル空間への参照は残らず、`model_to_paper` の `drawn` になる。
- 実寸の空間ごとの描画順で書き、その後に最初の用紙の要素を書く。ビューと用紙要素を混ぜた順序、追加の用紙、ビューの参照は保持しない。最初の用紙の寸法は枠に書き、寸法が不明なら A3 横にする。用紙名は保持しない。
- レイヤ名と表示を写し、色・線種・線幅の継承を要素の値に解く。図面内の RGB を優先し、色の符号は CAD 色表 v1 で解く。解けない色は黒、線幅は 0.25 mm、複合・不正な線種は実線にして、代替した項目を診断する。単純な線と間の交互の列は利用者定義線種にし、用紙の長さに直す。
- 文字は元の文字スタイルのフォント名を使い、宣言された高さを枠の高さとして扱う。基線の配置は下揃えにする。字幅と間隔は #861 の追加処理で見積もるため、近似として知らせる。字形の輪郭が一致するという契約は持たない。

記号の定義・寸法スタイル・文字スタイルの定義・元の線種の定義・表題欄・形式固有の拡張・文書の点スタイルは、その項目を出所付きで落としたと報告する。記号の配置、ハッチング、水平な直線寸法以外の寸法、表、下絵、スプラインなどの未対応図形は `convert.element.unsupported` に種類・件数・場所を持たせる。値の変更は `convert.item.drawn`・`convert.item.approximated` と見積もりの `reasons` に残す。

見積もりも同じ書き手を最後まで実行する。明細の上限はバイト列・ハッシュ・全件集計を変えない。予算停止・中断では、新しい文書も blob も公開しない。再読・ネイティブと wasm の一致と、ezsxf 0.3.7 の参照・数値との照合は別々に検査する。`xtask/verify/check_convert_cad.py` は自作 DXF の線・円・円弧・折れ線・文字・点、色・線種・線幅・レイヤを照らす。P21 の文字列のエスケープは検証キットの補助関数で戻すので、独立した文字コードの検証には数えない。これらの基本図形は SXF ブラウザでの表示を確かめていない。

[直線寸法の検証キット](../../xtask/verify/README.md#dxf-の水平な直線寸法を-p21-で確かめる)は、自作 DXF 2 件を変換し、公開 API の全応答と P21 のバイト列がネイティブと wasm で一致することを検査する。ezsxf 0.3.7 で各 P21 を読み、寸法が 1 件、定義点間の実寸が 1,000 mm、A3 の 1:10 のビューで用紙上の間隔が 100 mm、表示が「1000」「995」であることを確かめた。

Jw_cad 10.3.6.0 で両方の P21 を開き、2 本の補助線、水平な寸法線、元どおりの寸法値と上書き文字が同じ位置に表示された。文字の中央に寸法線が重なる。両方を JWW に別名保存し、部分図内に寸法が各 1 件あり、文字が「1000」「995」、配置の倍率が 0.1 であることを ezjww 0.7.6 で確かめた。どちらも定義点は (0, 0) と (1,000, 0)、寸法線は (0, 100) から (1,000, 100) だった。DynaCAD ビューアー 9.0.0.0 でも両方を開き、寸法線・補助線と文字、寸法線と文字の重なりを確認した。`SXF属性閲覧` で「1000」の水平線を選ぶと、図形一覧には「寸法線」が 1 件表示された。

見積もりの項目全体は、近似だけなら `approximated`、モデルの用紙化や継承の解消なども含めば `drawn` とする。複数の変更理由はすべて残す。

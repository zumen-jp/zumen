# SXF

SXF Ver.3.1 の SFC と P21 を、ファイルモデル（L1）として読み書きする規則と、仕様が決めない所の扱いを記録します。実装は `crates/zumen-sxf` です。旧版の知見（[旧版の SXF の扱い](https://github.com/zumen-jp/zumen-legacy/blob/main/docs/formats/sxf.md)）は、扱う範囲を広げるときに移します。仕様の本文は写しません（`formats/ledger.toml`）。

## 対象

- SFC と P21。どちらも ISO 10303-21 の交換構造に入る（[決定 0120](../decisions/0120-sxf-l1-exchange-structure.md)）。
- 圧縮した SFZ・P2Z は、まだ読まない。
- SFC は図面モデルへ移す（[決定 0121](../decisions/0121-sxf-sfc-lift-to-drawing.md)）。境界の `open` は SXF の判定の規則で SFC と P21 を読み、`drawing` は SFC を図面モデルへ移す（適合試験の `cases/open_sxf.json`）。P21 の変換は、まだない（#171）。

## 判定

- 先頭の行が `ISO-10303-21;` なら SXF の候補とする。
- `FILE_SCHEMA` の最初の文字列の、最初の語（空白か `{` の前まで）を、大文字と小文字を区別せずに `ASSOCIATIVE_DRAUGHTING` と比べる。違えば `sxf.schema.unsupported` を返す。IFC などを空の図面として読まないため。`FILE_SCHEMA` がない古い SXF は読む（推定。旧版の扱いを引き継ぐ）。
- `FILE_DESCRIPTION` の最初の文字列に `feature_mode` があるか、データの節にフィーチャのコメントがあれば SFC、ほかは P21 とする。`AP202` とある P21 では、`/*SXF` で始まるコメントもただのコメントとする（推定）。

## レコードの区切り

- `;` で終わる文を 1 つのレコードにする。語（`HEADER;`）、見出しの文（`FILE_NAME(…);`）、インスタンス（`#n=名前(…);`）、複合のインスタンス（`#n=(A(…) B(…));`）。
- データの節の `/*SXF` から `SXF*/` までを、SFC のフィーチャのレコードにする。印は長いものから比べ、`/*SXF3.1` は `SXF3.1*/`、`/*SXF3` は `SXF3*/`、`/*SXF` は `SXF*/` で閉じる。中は `#n = 名前(…)` 1 つで、`;` を付けない（推定。旧版の扱いを引き継ぐ）。
- レコードの間の空白とコメント、読めなかった文は、レコードにしない。書くときは、レコードとその間を元のバイトのまま並べるので、変えずに書くと元のバイト列と一致する。
- `END-ISO-10303-21;` の後のバイトは、読まずにそのまま持つ。

## 値

- P21 の値は ISO 10303-21 の形で読む。文字列は `''` で閉じず、`\X2\` などのエスケープは戻さずに範囲で持つ。文の中のコメントは飛ばす。
- SFC の値は、`'…'`（次の `'` で閉じる）、`\'…\'`、並び `(…)`、囲まない値に分ける。囲まない値は、`,` か `)` の前までで、前後の空白を除く。
- SFC の `\'…\'` は、Shift_JIS の 2 バイトの文字の 1 バイト目（0x81〜0x9F・0xE0〜0xFC）の次のバイトと、`\\` を飛ばし、後に空白を挟んで `,` か `)` が続く `\'` で閉じる（推定。「表」のように 2 バイト目が `\` の文字があるため）。文字列の中の改行も範囲に含める。

## 壊れた所

- 始まりの行・`DATA` の節・`END-ISO-10303-21;` のどれかがなければ、`sxf.file.invalid` で読まない。
- 形の読めない文は次の `;` まで、閉じのあるフィーチャのコメントは閉じまでを飛ばし、`sxf.record.invalid` にその範囲を付ける。閉じのないコメントは、終わりまでを飛ばす。

## 上限

- 入力のバイト数、レコードの数、値の数（`work`）、並びの入れ子の深さ（`depth`）を予算で数える。止めたら、読んでいた文かコメントの範囲を場所にする（[決定 0119](../decisions/0119-budget-stop-place.md)）。

## 図面モデルへの変換

- フィーチャの引数は、0 から 3 番目がレイヤ・色・線種・線幅のコードで、続きが図形の値。値は `'…'` で囲んだ数でも、囲まない数でも読む。折れ線の座標の並びは、`(…)` でも、`'(…)'` と囲んだものでも読む。
- 文字列は Shift_JIS で戻し、`\'…\'` の中の `\\` を `\` に戻す。改行は除く。
- 用紙のフィーチャは仕様では最後に書くが、後に要素があっても落とさず用紙に入れる（推定）。
- レイヤの状態は、表示の可否から、印刷を表示に合わせ、編集はできるとする（推定）。
- 楕円弧の角度は、媒介変数の角度とする（推定）。
- スプラインは制御点が 3n + 1 個の 3 次のベジェ曲線をつないだものとし、開閉のフラグは 0 を閉じているとする（推定。[決定 0126](../decisions/0126-sxf-splines-and-point-markers.md)）。
- 画像は、作図グループの名前の `$$RASTER$$` か、属性の `$$ATRU$$番号$$名称$$画像$$` の後をファイルの名前とし、グループの中の最初の 4 点以上の折れ線を範囲とする（推定。[決定 0125](../decisions/0125-sxf-raster-underlays.md)）。
- 図面表題欄の 12 の項目の順は、事業名・工事名・契約区分・図面名・図面番号・図面種別・尺度・作成年・作成月・作成日・受注会社名・発注事業者名とする（推定。[決定 0124](../decisions/0124-drawing-title-blocks.md)）。
- クロソイドは値のまま移し、曲がる向きのフラグは 0 を反時計回りとする（推定。[決定 0123](../decisions/0123-drawing-clothoid-edge.md)）。
- 文字の 9 点の配置は、1 を左下とし、右へ 1 つずつ、上へ 3 つずつ数える（推定）。文字範囲の幅と字の間隔は `sxf.text` の拡張に残す（[決定 0122](../decisions/0122-sxf-text-to-formatted-text.md)）。
- 寸法は、定義点と寸法値の文字を図面モデルの寸法に、寸法線と補助線の端・矢印・文字範囲の幅と字の間隔を `sxf.dimension` の拡張に移す。弧長と角度の寸法の弧は、始めの角度から反時計回りとし、半径の寸法は、矢印がなければ終点を円の上の点とする（推定。[決定 0127](../decisions/0127-sxf-dimensions.md)）。
- 引出線とバルーンは、引出線つきの注記にする。頂点は矢印の側から並び、矢印は名前空間 `sxf.arrow` のコードのキーで指し、大きさはコードの表で決まるとする（推定）。バルーンの円は `sxf.callout` の拡張に残す（[決定 0128](../decisions/0128-sxf-labels-and-balloons.md)）。
- ハッチングは、指す複合曲線の曲線の辺を並べた輪にする。表示する複合曲線は、曲線を複合曲線の色・線種・線幅で置き、線のハッチングの要素の色は 1 本目の線の色にする（推定。[決定 0129](../decisions/0129-sxf-hatches-and-composite-curves.md)）。
- 測地座標系の部分図は、X と Y を入れ替えて用紙へ置く。
- まだ移さない種類と、読めない値は、`sxf.lift.dropped`・`sxf.lift.invalid` で報告する。

# API のスキーマ

各言語への API の定義です。ここを元に、`cargo xtask codegen` が各言語の型と C のヘッダーを作ります。

| ファイル | 中身 | 生成するもの |
| --- | --- | --- |
| `boundary.toml` | バージョン（ABI・メッセージのスキーマ）、状態コード、関数とその引数 | `bindings/c/include/zumen.h`、`crates/zumen-abi/src/abi.rs`、`bindings/js/src/constants.js`・`constants.d.ts`、`bindings/python/zumen/constants.py`、`bindings/dotnet/Zumen/Constants.g.cs` |
| `messages.json` | 要求・応答・op ごとのフィールド・診断・セッションの設定・カタログの形（JSON Schema 2020-12） | `crates/zumen-abi/src/messages.rs`、`bindings/js/src/messages.d.ts`、`bindings/python/zumen/messages.py`、`bindings/dotnet/Zumen/Messages.g.cs`、`bindings/cli/src/tools.json`（MCP のツール） |
| `scene.toml` | シーンの blob の配置（セクションと値の組） | `crates/zumen-scene/src/layout.rs`、`bindings/c/include/zumen_scene.h`、`bindings/js/src/constants.js`・`constants.d.ts`、`bindings/python/zumen/constants.py`、`bindings/dotnet/Zumen/Constants.g.cs` |
| `drawing.toml` | 図面モデル（L2）のバイナリの型の契約（型ごとのフィールドと値の並びと、バージョン）。生成器が図面モデルの型から書き足す | `crates/zumen-drawing/src/binary/generated.rs`、`crates/zumen-drawing/src/model_size/generated.rs` |

生成したファイルもコミットします。CI の `cargo xtask codegen --check` が、元と合わないものを見つけます。

VBA7 向けには、`boundary.toml` と `scene.toml` から `bindings/vba/ZumenNative.bas` にネイティブの宣言・ABI の型・バージョン・状態コード・シーンの配置を生成します。メッセージは UTF-8 の JSON のまま受け渡します。所有権と型の対応は [VBA のバインディング](../bindings/vba/README.md) にあります。

## 図面モデルのメモリ予算

スキーマ 1.114 の `building_drawing` は、指定した階を基準に IFC を水平に切ります。階に配置があればプロジェクト空間での Z 座標を使い、配置がなければ単位付きの階の標高を使います。図の XY 原点はプロジェクトの原点です。`height`・`depth`・`tolerance`・`chord` は `unit` の単位で渡し、`scale` は用紙の縮尺の分母です。階や長さの単位が解決できないとき、予算停止・中断のときは、図面と blob を登録しません。

成功時には `to` の名前の読み取り用図面と、元の IFC の形式・系統・入力ハッシュを持つ `drawing` の blob（ZMDR）を返します。各線の `zumen.building.drawing` 拡張は元の要素・形の項目と切断線などの役割を保ちます。ネイティブではその図面を `entities` や `convert` に渡せます。分割した wasm では BIM モジュールの blob を図面モジュールに渡して開きます。[切り出して DXF に書く例](../docs/formats/ifc.md#建物を図面へ切り出す)

スキーマ 1.113 から、要求の `budget` とセッション既定の予算で `model_bytes` を指定できます（#559）。

```json
{"v":1,"op":"drawing","doc":"plan.dxf","budget":{"model_bytes":67108864}}
```

図面モデル（L2）が保持する要素・頂点・輪・文字列・表・拡張を、ポインター幅によらない 64 ビット相当の論理バイト数で数えます。圧縮や符号化を展開した `decoded_bytes`、要素の件数だけを数える `elements` とは別の予算です。既定は 512 MiB です。上限を超えたときは元のレコードや要素の出所を添えた `budget.model-bytes.exceeded` を返して失敗し、途中の部分結果は返しません。開いていた文書は変更されません。

## 部品を持たない寸法の表示設定

図面モデルのバイナリ 1.2 では、`Drawing2D` の末尾に `dimension_display` を書きます。1.0・1.1 の図面を読むと、この一覧は空になります。既存の要素の ID と、編集の前提条件に使う要素・寸法スタイルのハッシュは同じです。[バイナリの型](drawing.toml)

基本の設定は寸法スタイルの名前で、個別の上書きは要素の ID と読み取り時のハッシュで結びます。スタイル名は ASCII の大文字と小文字を区別せず、同じ対象が複数あれば先の設定を使います。個別の値は要素のハッシュが一致するときだけ使い、省いた項目はスタイルから継承します。長さは、倍率を掛ける前の図面の単位です。倍率・矢印・目盛りの共通値は既存の寸法スタイルにあり、表示設定はその 3 項目の個別の値を持ちます。たとえば目盛りの大きさを 0 にすると、スタイルが指定する斜線を取り消せます。

表示設定だけの変更も編集時に検出するには、元の文書のハッシュを指定します。DXF の寸法を同じ文書内で複写すると、個別の上書きは写しにも付きます。別文書へ引出線や記号を複写するときは、参照する寸法スタイルの表示設定と文字スタイルの定義も照合します。記号に含まれる寸法では個別の上書きも照合し、異なれば複写全体を拒みます。

寸法文字の垂直配置（`text_vertical_placement`）は 0〜4 を使います。寸法文字と線のすき間（`text_gap`）は図面の単位で、負の値は文字の囲みを含む指定として符号も保存します。[DIMTAD](https://help.autodesk.com/cloudhelp/2022/ENU/AutoCAD-Core/files/GUID-60D1241D-CEA7-4493-BD6A-4EF433F3C946.htm)・[DIMGAP](https://help.autodesk.com/cloudhelp/2025/ENG/AutoCAD-Core/files/GUID-EB367187-A5D6-404A-8121-A6D1D25B626A.htm)

## 図面から地図への変換

スキーマ 1.112 から、`drawing` の応答は文書が地理位置（DXF・DWG の `GEODATA`）を持ち変換を作れたときに `result.georeference`（EPSG コードの `crs` と IFC の `IfcMapConversion` と同じ形の `conversion`）を返します。合わせて、図面と土木・地理のモジュールで `georeference` を使えます（#685）。

```json
{"v":1,"op":"georeference","doc":"plan.dwg","points":[{"x":1200,"y":3400}]}
{"v":1,"op":"georeference","crs":6677,"control_points":[{"drawing":{"x":0,"y":0},"map":{"easting":1000,"northing":2000}},{"drawing":{"x":10000,"y":0},"map":{"easting":1010,"northing":2000}}],"points":[{"x":5000,"y":0}]}
```

`doc` を渡すと開いた図面から変換を取り出し、任意の `expected_hash` で元の文書ハッシュを確かめます。変換を作れない設定・座標系の文書では診断を添えて成功し、`georeference` と `mapped` を省きます。`crs`（平面直角座標系の EPSG コード）と `control_points`（2 組以上の図面座標と地図投影座標）を渡すと、尺度・回転・平行移動の相似の変換を最小二乗で求め、組ごとの残差（`residuals`）とともに返します。どちらの形でも `points` を渡せば地図の東・北の座標（メートル）に写して `mapped` に返します。式と診断は[座標系と標高](../docs/formats/crs.md#対応点から地図への変換)にあります。

## レビューのシーン

スキーマ 1.95 から、図面のモジュールの `review_scene` で、レビューの文書の 1 つの対象の図形と指摘の場所を、開いた図面の起点で 2D のシーンにできます。図面のシーンとは別の blob で、配置は `scene` と同じです。`zm_push` した文書の名前を `review`、描く対象の ID を `target` に渡します。対象の形式とハッシュは開いた文書から作り、文書の対象と合わなければ `review.target.stale` で描きません。

```json
{"v":1,"op":"review_scene","doc":"plan.dxf","review":"review.json","target":"plan","from":"space/0","tolerance":0.01,"style":{"color":"#ff0000","line_weight":0.35,"text_height":2.5,"text_padding":0.5,"arrow_length":2,"arrows":"end","cloud_pitch":3,"marker_size":2}}
```

`tolerance` と `style` は必須です。色・線幅・寸法を文書の値から推測しないためです。`from`・`view`・`region`・`fonts` は `scene` と同じ意味で、`print`・`palette`・`heights` は受け付けません。文書の図形・場所の `view` が起点と合う項目だけを描き、別の対象・起点の項目は混ぜません。

結果の `sources` は描いた図形・場所ごとに、シーンの ID（シーンの `entity_ids`）から元の図形の `markup`、または指摘の `topic` と場所の `location` へ戻す対応です。描く順に並びます。題・作者・写真などの文言はシーンに入れず、呼び手が元の ID から引きます。図形の規則と診断は[レビューの文書と 2D の図形](../docs/formats/review.md)にあります。

`scene` に `review` を足さず op を分けたのは、`scene` の `print`・`palette`・`heights` が意味を持たず、必須のスタイルと `sources` で結果と検査の形が変わるためです。`review_carry`・`review_adopt` と同じレビューの領域の op にしています。

## 用紙の長さの文字の高さ

スキーマ 1.93 から、`entities` は、実寸の空間の文字が用紙の長さで高さを持つとき（JWW）、`geometry` の `height` を用紙の mm で返し、`height_on_paper` を `true` にします。前は `geometry` を省いていました。返した形をそのまま `apply` の `replace` に渡せます。`add` と `replace` で `height_on_paper` を省くと、従来どおり高さを点と同じ単位として受け取ります。

## 土木モデルの保持値

スキーマ 1.87 から、`civil` に `doc` と `details: true` を渡すと、座標点セット・元の高さの基準と、選んだ線形の IP・地盤縦断・片勾配・横断の線と点を `result.details` で取得できます。線形が複数ある場合は `id` が必要です。`alignment` に直接書いた線形では `details: true` を受け付けません。省略または `false` の場合は従来の要約と位置だけを返します。

```json
{"v":1,"op":"civil","doc":"road.xml","id":"road","details":true,"distances":[25]}
```

距離・北と東・高さはメートルです。片勾配の `kind` が `superelevation` なら左右の値は %、`rail` なら左右の高さの差と `gauge` は mm です。横断の点の `height` は `height_reference` が `elevation` なら文書の標高、`formation_offset` なら計画高からの差です。`side` で離れの符号を変えません。文書の `tokyo_bay_offset` を高さへ自動で足さず、名前・出所・省略された高さを保持します。点の名前を永続 ID と同一視しません。

返す値の複写前に、行ごとに作業量 1 と確保量 512 バイト、文字列の長さを追加の確保量として数えます。予算停止では部分結果を返さず、文書を変更しません。読み取りの対応範囲、参照の評価と Rust の移行は [J-LandXML の規則](../docs/formats/landxml.md)にあります。

## 空の図面を作る

スキーマ 1.83 から、入力のファイルを渡さずに `create` で空の文書を作れます。`format` は `capabilities.formats` の `create` が `true` の形式、`to` はまだ登録していない文書名です。今は図面のモジュールで `dxf` を指定できます。`write` は既存の文書の書き戻し、`create` は入力なしの作成を示します。

```json
{"v":1,"op":"create","format":"dxf","to":"new.dxf","unit":"millimeter"}
```

`unit` は `millimeter`・`centimeter`・`meter`・`inch`・`foot`・`unknown` です。省略すると `millimeter`、`unknown` は単位なしにします。結果は `doc`・`format`・`hash`・`elements`（0）と、空のファイルの `file` blob を返します。作った文書には、すぐに `apply` で図形や表を追加できます。`hash` は通常の編集の前提条件に使えます。名前はファイルシステムのパスではなく、セッション内の名前です。

DXF のバージョン・既定の表・空間と用紙は、[新規作成の規則](../docs/formats/dxf.md#空の-dxf-を作る)に従います。既存の文書は上書きしません。未対応形式は `create.format.unsupported`、不正な名前は `call.value.invalid`、既存の名前は `call.document.exists` で拒否します。予算停止・中断・失敗で文書や blob は残りません。入力を登録してある同名の名前は変更せず、文書名とは別に扱います。

## P21・JWW への変換

スキーマ 1.85 から、図面のモジュールの `convert` と `convert_estimate` に `sxf`（出力は P21）と `jww` を指定できます。元の文書を `doc`、新しく登録する文書名を `to` に渡します。

```json
{"v":1,"op":"convert_estimate","doc":"source.dxf","format":"sxf","to":"out.p21","limit":100}
{"v":1,"op":"convert","doc":"source.dxf","format":"sxf","to":"out.p21"}
```

見積もりは出力予定のハッシュ・要素数・忠実度の集計と明細を返し、文書と blob は登録しません。実変換は同じ書き手を使い、新しい文書と `file` blob を返します。書けない情報は種類・件数・出所で診断します。対応する図形、用紙・縮尺・レイヤと属性の扱いは、[P21](../docs/formats/sxf.md#新しい-p21-への変換)・[JWW](../docs/formats/jww.md#新しい-jww-への変換)の契約を確認してください。

## 管理 XML の変更

スキーマ 1.84 から、図面のモジュールで `delivery_apply` を使えます。`zm_push` した管理 XML の `input` と `edits` を渡すと、変更後の XML を 1 個の `file` blob で返します。結果は `input`・変更後の `hash`・変更数の `applied` です。入力の登録内容は変えません。blob を取り出し、`close` の `inputs` で元の登録を捨ててから同じ名前で `zm_push` し、`delivery_check` で成果品全体を照らせます。

```json
{"v":1,"op":"delivery_apply","input":"納品/INDEX_C.XML","edits":[{"kind":"set_text","path":[{"name":"基礎情報"},{"name":"工事名称"}],"value":"道路改良工事"},{"kind":"append","path":[{"name":"基礎情報"}],"child":{"name":"備考","value":"確認済み"}}]}
```

`path` は根からたどる子の列で、空なら根を指します。`name` は接頭辞を含む元の名前、`index` は同名の兄弟の中の 0 始まりの位置（省略時は 0）です。すべての経路を変更前の XML で解きます。同じ要求で追加した項目は経路で指さず、`child.children` にまとめます。同じ親への `append` は指定した順に書きます。

`set_text` は子要素を持たない項目に使い、注記と処理命令を保ちます。`append.child` は `name`・任意の `value`・任意の `children` を持つ木です。属性や名前空間宣言は追加せず、親で宣言済みの接頭辞を使います。`value` は文字参照にする前の文字で、`children` があればその前に書きます。

任意の `hash` は元の XML の文書ハッシュです。`edits: []` で元のバイト列とハッシュを得られます。古いハッシュ、存在しない経路、同じ項目への複数の更新、更新と追加の重複、表せない文字・名前は拒否します。予算停止・中断・失敗では結果も blob も返さず、`partial: true` でも一部だけは適用しません。保持する書式・診断・未対応範囲は[管理 XML の書き戻し](../docs/formats/delivery.md#管理-xml-の書き戻し)にあります。

## 図面の詳細

スキーマ 1.81 から `tables.symbols` は記号の定義を元の順で返します。未配置の定義も含め、`id` は `entities.place` と同じです。`namespace` と `name` は定義を識別するキーで、JWW の `name` はブロック番号の文字列です。基点・属性のタグと既定値・入力の指定・無名の区別・外部参照名・出所も返します。外部の参照先は開きません。属性の配置と書式は元の定義に保ち、一覧には含めません。複数行の属性の元の文字列は `formatted_value` で読むために返します。

返された名前を `add` の記号の `name` に使えます。DXF・DWG は従来どおり大文字と小文字を区別せず、JWW と SXF は区別します。JWW と SXF の同名の別定義は推測しません。JWW はレイヤグループの空間へ、SXF の作図部品は用紙へ足せます。JWW では未指定のスタイルを定義に従わせ、SXF ではレイヤに従う色・線種と線幅なしにします。配置に固有の色・線種・線幅、格子・属性・切り抜きは、この 2 形式では書けません。定義自体は変更しません。JWW の追加で出所のレコード番号が動く場合は、従来どおり `ids_shifted` を返します。

`drawing` の空間と用紙の `elements` は全 14 種類を数えます。`curves` は円弧・楕円・スプラインなどをまとめ、記号の中身やビューの参照先は展開しません。従来の `lines`・`texts` の意味と、線分と文字だけから求める `extent` は保ちます。

`sheets[].views` は従来の件数です。`view_details` に元の順で対象の空間・アフィン行列・切り抜き・出所を返します。`scale` はモデルの各軸の 1 単位に対応する用紙の mm、`ratio` はモデルの単位を mm に直した縮尺です。単位不明なら `ratio` は持ちません。`rotation` は X 軸の向き、`mirrored` は向きの反転で、せん断は元の行列で確認します。`model_clip` は切り抜きを逆変換した点、`extent` はその点を囲むモデル座標の範囲です。切り抜きが空なら範囲は持ちません。数値や参照を表せない場合は `drawing.metadata.failed` で場所と理由を返し、部分結果を出しません。複製と計算は作業量と確保量の予算へ数えます。

## バージョン

- **ABI**（`versions.abi`）は、関数の引数か意味を変えるときに上げます。上げないことを目指します。
- **メッセージのスキーマ**は、メジャーバージョン（`schema-major`、要求と応答の `v`）とマイナーバージョン（`schema-minor`、`capabilities` が返す）に分けます。op・フィールド・列挙の値を足すたびに、マイナーバージョンを上げます。
  並行して作業するときは、push の直前に fetch した `origin/main` の値に 1 を足します。上げたら `cargo xtask codegen` で定数を作り直し、`cargo run -p zumen-conformance -- --write` で `capabilities` の応答のハッシュを書き直します。Rust の `capabilities` の試験は、生成した定数で照らします。
- 関数・状態コード・op・フィールド・列挙の値は、足すだけにします。消さず、名前と意味を変えません。パッケージの 1.0 より前は、壊したことをリリースノートに書いたうえで、マイナーバージョンで壊すことがあります。

要求に足すフィールドは、省略すれば従来の動きになるようにします。意味を変えるには新しい名前を足し、廃止した名前も動かし続けます。ラッパーは未知の応答フィールドを無視し、未知の列挙値も受け取ります。新しい op を古いコアで使う前に `capabilities` を確認します。追加で表せずメジャーバージョンを上げる場合、要求の `v` で以前のメジャーバージョンも受け付け、いつまで受け付けるかをこの節に明記します。パッケージが 1.0 より前の破壊的変更では、上の例外に従い、理由・移行方法・バージョンをリリースノートと、コミットまたは PR に残します。

## ID と編集の前提条件

同じバイト列からは、どのバージョンでも同じ ID を返します。浮動小数の計算結果や並び替え後の添字から ID を作りません。図面の要素は出所のキーを使い、AutoCAD のハンドルは `h` と大文字の 16 進、SXF のインスタンス番号は `i` と 10 進で表します。キーがなければレコード・バイト位置・要素の位置を使い、同じ出所の 2 つ目以降は `/1`、`/2` と区別します。実寸の空間は `space/0` です。

編集の前提条件には ID と読んだときのハッシュを使います。文書のハッシュは元のバイト列の BLAKE3 の先頭 128 ビットです。要素のハッシュは出所の位置を含めず、決まった順で符号化した意味の値を使います。すべての変更を適用前に検査し、要素がなければ `change.element.missing`、値が変わっていれば `change.element.stale` を返します。ID の規則を変える場合は、実装に先立って契約と移行方法を文書にし、その差分を別の担当者が確認します。1.0 より前の API の例外も ID には適用しません。

建物の形を含む成分と Hash v1 の追加の符号化は、[IFC の所有する形とハッシュ](../docs/formats/ifc.md#所有する形とハッシュを建物に保持する)にあります。属性だけの取得と形を含む取得は明示的に選び、前提条件の検査でも同じ経路を使います。

## 同じ apply 内の表の参照

`add_layer`・`add_line_type`・`add_text_style`・`add_dimension_style` で先に足した項目を、後ろの変更から名前で指せます。線種を足し、それを指すレイヤを足し、そのレイヤ上に線を足す操作も 1 回にまとめられます。新しい文字スタイルは文字の追加・置き換え、寸法スタイルは寸法と引出線の追加に使えます。既存の公開 ID は従来どおり使い、新しく足した項目の ID を推測して指定する方法は提供しません。

名前の比較・同名の拒否・書ける形と形式は各変更の規則に従います。前方参照は受け付けません。すべての変更と書き出しが成功してから、文書と 1 つのファイル blob を更新します。同じ要素への二重変更、古いハッシュ、不正な参照、予算停止、中断では表の追加も残しません。番号を使う要素の ID が動く場合も、元の ID とハッシュで対象を検査し、応答の `ids_shifted` で再取得を求めます。

マイナーバージョン 99 からは、`add_symbol` で記号の定義（ブロック）を足せます。名前・基点・中の要素（`add` と同じ `geometry` と画層・色・線種・線の太さ）を渡し、後ろの `add` の `geometry.shape = symbol` から名前で置けます。足した定義は `apply` の結果に ID とハッシュを持たないので、`tables` の `symbols` から引きます。書ける形式は DXF と DWG で、JWW・SXF は `change.symbol.unsupported` で断ります。同じ名前（大文字と小文字は区別しない）・名前のない定義・外部参照・属性の定義も同じ code で断ります。

## 要素の複写

マイナーバージョン 100 からは、`copy` で要素を複写できます（#889）。要素の ID とハッシュ、写しを動かすアフィン変換（`matrix`、元の位置なら `[1, 0, 0, 0, 1, 0]`）を渡し、マイナーバージョン 110 からは配置先の空間・用紙（`place`）と複写元の文書（`from_doc`）も指定できます。写しは元のレイヤ・色・線種・線種の倍率・線幅・透過性と形式固有の値（DXF・DWG の XDATA、JWW のフラグ・文字種・字間、SXF の文字範囲の幅・字間など）を保ち、図形とともに動く XDATA と記号の属性を同じ変換で直します。DXF の寸法・表は、写しごとに新しい匿名ブロックを作ります。`apply` の結果は写しの ID とハッシュを返し、元の要素と複写元の文書は変えません。同じ要素を同じ一覧で何度も写せます。

別の空間・用紙・文書へ貼り付けるときの規則は次のとおりです。

- **形式と配置先**: `place` を省けば元の要素と同じ場所 ID を使い、同じ形式の間（DXF 同士、DWG 同士、JWW 同士、SFC 同士、P21 同士）だけを受け付けます。ない `place` は `change.element.missing`、形式の不一致は `change.copy.unsupported`（`field = format`・`value = mismatch`）にします。
- **単位**: 配置元と配置先の長さの単位がともに決まっていて一致するときだけ写します（用紙は mm）。単位が不明または異なるとき（JWW のレイヤグループの縮尺違いを含む）は、`field = unit`・`value = mismatch` で拒みます。ワールド座標に結ばれた動く XDATA（1011〜1013・1041・1042）は、モデル空間（`space/0`）以外の配置では `field = xdata`・`value = world_space` で拒みます。
- **レイヤ**: DXF・DWG は大文字と小文字を区別しない名前、SXF は完全一致の名前で貼り付け先のレイヤに結び、なければ `field = layer`・`value = missing` で拒みます。JWW はレイヤ番号がレイヤグループを決めるため同じグループ番号の空間に限り、貼り付け先の枠に異なる非空のレイヤ名があれば `field = layer`・`value = conflict` で拒みます。
- **線種・文字スタイル・寸法スタイル・APPID**: 要素が指す定義が貼り付け先になければ `missing`、同じ名前で定義の内容が異なれば名前衝突として `conflict`（`field` は `line_type`・`text_style`・`dimension_style`・`appid`）で拒み、異なる定義へ黙って差し替えません。SXF の利用者定義色や JWW のペン色が異なる RGB になる場合も `field = style` で拒みます。
- **記号定義**: 要素が指すブロックや複合図形が貼り付け先になければ `field = symbol`・`value = missing`、同名の定義の基点や中身が異なれば `field = symbol`・`value = conflict` で拒みます。定義の空間へ記号を写して入れ子が輪になるときは `change.symbol-cycle.invalid` で拒みます。

写せない要素は、`change.copy.unsupported` で変更の添字・種類・フィールド・理由を返して全体を拒みます。リアクター・拡張辞書・XDATA のハンドル・ほかの図形を指す参照を持つ要素、JWW の曲線属性番号（`curve != 0`）、SXF の複合曲線や属性付加機構（`$$ATR*`・SAF の `$$ATRF$$`）が付いた要素、同じ一覧の先の変更が変えた要素が、それにあたります。

DXF・DWG は 4 種類の表、JWW・SXF は各形式が追加できるレイヤを扱います。TEXT・MTEXT の置き換えは、既存または先に追加した文字スタイルへ指し替えられます。文字の位置合わせや高さの意味は保ちます。寸法・引出線の置き換えで別の寸法スタイルへ移す操作は対象に含めません。

参照を解く途中で要素の位置・元のキー・値の対応を確認できなければ `change.references.failed` に理由を返し、文書を保ちます。名前の索引と比較、表を準備する書き戻し、読み直し、元の対象との照合を作業量と展開量の予算へ数えます。[適合テスト](../bindings/conformance/README.md#同じ-apply-内の表の参照)で、再読とネイティブ・wasm の一致を確認します。

## 要素の絞り込み

メッセージのスキーマ 1.80 から、`entities` に `ids`・`layers`・`kinds`・`source` を指定できます。同じ一覧内の値は OR、異なる条件と従来の `place`・`region` は AND で照らします。`ids` は要素の公開 ID、`layers` は `tables.layers` の公開 ID です。レイヤ名が同じでも選び分けられます。`kinds` は応答の `kind` と同じ種類です。一覧の重複は要素を増やさず、空の一覧や、ない ID だけの一覧なら結果は空です。

元の要素の順に ID を決めてから絞ります。入力順と、同じ出所を持つ要素の重複の番号を保ち、`total`・`offset`・`next_offset` はすべての条件で絞った後の位置を使います。記号定義の中は従来どおり `place` を明示したときだけ対象です。`ids` にその要素を書くだけでは検索対象を広げません。

`source.record` はレコード番号との完全一致、`source.bytes` は空でない半開区間 `[start,end)` の重なりです。バイト範囲の端が接するだけでは一致しません。`source.handle` は接頭辞なしの 1〜16 桁の 16 進文字列、`source.instance` は 1〜20 桁の符号なし 64 bit 整数の 10 進文字列です。どちらも数値で比べ、ハンドルの大文字・小文字や先頭の 0 は区別しません。この 2 つは同時に指定できません。出所の複数の項目も AND で照らし、必要な項目がない要素を除きます。空の `source` は制限を加えません。不正な範囲とキーは `call.value.invalid` に要求の場所を返します。

条件を省略したときは、応答と予算の消費を保ちます。条件の複製・索引・並べ替え・要素ごとの比較を予算へ数えます。絞り込みを、属性や形を複製する前に行い、選ばれない要素の属性を返すための処理を省きます。停止時には部分結果を返さず、その後も文書を使えます。値と順序は[絞り込みの適合テスト](../bindings/conformance/README.md#要素の絞り込み)で確かめます。

## 要素のスタイルと拡張

メッセージのスキーマ 1.79 から、`entities.fields` に `style` と `extensions` を指定できます。指定したフィールドだけを返し、省略した既存の応答・ID・ハッシュを保ちます。ページと場所の指定はほかのフィールドと共通です。

`style` は要素自身の値です。色の符号と図面内の RGB、レイヤやブロックからの継承、線種、線種の倍率、線幅、透過性を返します。継承を解かず、色表から RGB を補いません。線種の参照は `tables.line_types` と同じ公開 ID で、重複した出所の番号もそろえます。色・線種・倍率・線幅の形は `restyle` に対応します。元の色が未解決で符号も RGB もなければ空のオブジェクト、線幅が未取得ならフィールドを省きます。この未取得の値は変更の指定に使えません。透過性は `inherit` か不透明度 `alpha`（0〜255）で返す、読むためのフィールドです。

`extensions` はその要素を対象にする拡張だけを返します。名前空間・名前・形式とスキーマのバージョン・出所を保ち、拡張とフィールドの元の順序、同じキーの重複を保ちます。`basis` は依存する要素のハッシュで、現在のハッシュと一致するときだけ `current` が真です。失効した値も返し、要素に依存するハッシュがなければ `basis` を省いて `current` を偽にします。取得は拡張を書き戻す操作ではありません。

拡張の `value` は `kind` と値を持ちます。`text` は文字列、`integer` は符号付き 64 bit 整数の 10 進文字列、`real` は有限の実数、`point` は有限の 3 成分です。`handle` は接頭辞なしの大文字の 16 進文字列、`bytes` は 1 バイトを小文字の 16 進 2 桁にした文字列です。整数・ハンドル・空のバイト列を丸めずに保ちます。

参照の索引、並べ替えと検索の比較量、文字列と配列の複製を作業量・展開量の予算へ数えます。不正な参照や返せない数値は、要素の ID・出所・理由を持つ `drawing.entity-details.failed` で失敗し、部分結果を返しません。予算停止や失敗後も文書を使えます。4 形式の編集後の再読と環境間の一致は[属性の適合テスト](../bindings/conformance/README.md#要素のスタイルと拡張)で確かめます。

## モデル空間の計測

`measure` は、`doc` と実寸の空間の ID `from` を選び、`quantity` に `length`・`perimeter`・`area`・`distance` を指定します。`first` は `{"kind":"element","id":"space/0/h10"}` のように公開 ID で要素を指します。距離のときだけ `second` が必要で、両方の対象に `{"kind":"point","position":{"x":0,"y":0}}` も使えます。用紙、記号定義の中、異なる空間をまたぐ計測は対象にしません。`expected_hash` があれば文書のハッシュと照合します。文書・要素・ID・ハッシュは変わりません。

結果の `value` は空間の単位、面積ならその 2 乗です。`unit` と `unit_power` に単位と次数を返し、単位不明なら `unknown` を保ちます。距離は経路の境界間で求め、距離を作る点を `nearest_first` と `nearest_second` に返します。閉じた経路の内部や線幅、表示変換は含めません。周長と面積には閉じた経路を求めます。面積は向き付き線積分の絶対値で、自己交差を塗り規則で統合した面積ではありません。

線分・折れ線の直線と円弧・円・円弧は元の定義を使います。楕円の全面積とクロソイドの長さも解析的に求めます。ほかの楕円、スプライン、クロソイドの距離は折れ線で近似し、`approximate: true` と、要素の ID・計測の種類・出所・件数を持つ `drawing.element-measurement.approximated` を返します。`tolerance` は正の有限値で、既定は空間の単位で `0.001` です。曲線を分割する弦の誤差の目標であり、計測値の誤差上限の保証ではありません。要求に使った値を結果にも返します。

折れ線と分割数の上限は 65,536、スプラインの制御点・フィット点は各 4,096、次数は 32 です。作業量と確保量を先に数え、作った点は `segments`、距離の組み合わせは `work` で数えます。近似の上限、未対応の形、閉じていない経路、数値の範囲外などは `drawing.element-measurement.failed` に理由と元の要素を残し、計測の部分結果を返しません。予算停止後も文書を再利用できます。期待値と環境間の応答の一致は[計測の適合テスト](../bindings/conformance/README.md#計測)で確認します。

スキーマ 1.102 から、距離の対象に `{"kind":"split_point","position":{"origin":{"x":1e16,"y":1e16},"offset":{"x":3,"y":4}}}` のように原点と相対座標を分けた点を使えます。両方の対象が点（`point` か `split_point`）のときだけ使え、要素との組み合わせは `split-point-with-element` で拒みます。原点と相対座標を先に足さず、X・Y の差を 4 項の正確な和から一度だけ丸めてから長さを求めるので、大きな原点と小さな差も、原点の違う 2 点も桁を落としません。差か長さが有限に収まらなければ `overflow`、有限でない成分は `invalid-point` で拒み、部分結果を返しません。`nearest_first` と `nearest_second` は原点と相対座標の和を丸めた点で、位置を正確には表しません。

同じ版から、`distance` で両方の対象が点なら、`from` に公開用紙の ID（`drawing` の `sheets` の `id`）も指定できます。校正を使わずに用紙の座標の距離を返し、`unit` は用紙の `millimeter`、`sheet` は `true` です。これは実寸ではありません。校正した実寸は、校正を明示的に選ぶ `measure_distance` で求めます。校正がないことを実寸の推定で埋めません。用紙の要素は `sheet-element` で拒み、距離のほかの計測は `/from` の値の誤りです。実寸の空間の結果には `sheet` を返しません。`expected_hash`・診断・予算の扱いはほかの計測と同じです。期待値と環境間の一致は[点の計測の適合テスト](../bindings/conformance/README.md#計測)で確認します。

## 色の表とレイヤの非表示

メッセージのスキーマ 1.78 から、`scene`・`render`・`check`・`review_adopt` の `palette` に `"builtin:cad-v1"` を指定できます。別の入力を `push` せず、組み込みの固定の色表を選びます。省略時は従来どおり空の表、入力名を指定したときはその JSON の表だけを使います。未知の組み込み名は `/palette` の不正な値です。

| 系統 | 対応する符号と出所 |
| --- | --- |
| ACI | 1〜255。ezdxf 1.4.5 のモデル空間の色表 |
| SXF | 1〜16。ezsxf 0.3.7 の既定義色 |
| JWW | 1〜9 は ezjww 0.7.6 の新しい文書の画面色。100 は黒、101〜116 は SXF の既定義色 |

図面内の RGB が最優先です。JWW の利用者設定を変えず、表にない利用者定義色も推測しません。ACI の継承を表す 0・256 と、JWW の背景色 0 は表の対象外です。ACI 7 はシーンの背景依存のフラグを保ち、画像では指定した `foreground` を使います。背景に応じて表全体を自動で変えません。`cad-v1` の対応は固定し、色を変えるときは別の名前にします。MIT の許諾と出所は [`zumen-drawing/NOTICE`](../crates/zumen-drawing/NOTICE) に置き、配布物の第三者ライセンスにも含めます。

`render.hidden_layers` は、シーンの `layer_ids` と同じ公開 ID の一覧です。view2d と同じく `unit_layers` に対応する描画単位だけを除き、親の配置から追加の除外を伝播させません。重複した指定は画像を変えず、未知の ID は `render.options.invalid` で失敗します。省略と空の一覧は、画像・診断・予算消費とも従来の応答を保ちます。図面・公開 ID・シーンの配置は変えません。

非表示の単位の描画診断は出しませんが、先に行う図面の読み取りとシーン生成の診断は残ります。照合する ID の文字列と行数、指定数の積を作業量へ数え、行ごとの非表示状態を確保する前に展開量を数えます。停止と不正な指定では部分画像を返しません。SVG と PNG の具体例と制限は[画像の書き出し](../docs/render.md)にあります。

## モデル空間の交わり

スキーマ 1.90 から、`intersect` で同じ実寸の空間の 2 要素の交点・接点・重なりを求められます。`first` と `second` は `measure` と同じ形で公開 ID を指し、異なる要素にします。文書・要素・ID・ハッシュは変わりません。

```json
{"v":1,"op":"intersect","doc":"plan.dxf","from":"space/0","first":{"kind":"element","id":"space/0/h10"},"second":{"kind":"element","id":"space/0/h11"}}
```

要素は計測と同じ経路にします。線分・折れ線の直線・点と、円・円弧・膨らみを持つ辺は元の定義を使い、楕円・スプライン・クロソイドは折れ線に近似して `approximate: true` と `drawing.element-intersection.approximated` を返します。`tolerance` は正の有限値で、既定は空間の単位で `0.001` です。その 1/4 を間隔とする[整数格子](../docs/geometry2d.md)へ入力を移し、交わりを整数式で判定します。格子の原点は両要素の最初の点のうち X、Y の辞書順で小さいほうを整数に丸めた点で、`first` と `second` を入れ替えても同じ結果になります。入力の移動が許容差を超える座標は `numeric-range` で失敗します。

返す点は、格子へ移した曲線どうしの交点です。点の移動と交点の丸めは各座標で格子の間隔の半分まで、半径の丸めは間隔の半分までなので、点は両方の元の曲線から許容差の半分ほどの距離に収まります。浅い角度で交わる組や接するに近い組では、元の曲線どうしの正確な交点の位置が入力の小さな差で大きく動くため、その位置から許容差より離れることがあります。

`points` は交点と接点を格子点の X、Y の辞書順に返します。区間の組から出た同じ格子点は 1 つにまとめ、すべてが接するときだけ `tangent`、すべてが格子点でない交点を丸めたときだけ `rounded` を真にします。`overlaps` は長さを持つ重なりで、`segment`（端点を辞書順）、`arc`（反時計回りの始点・終点と中心・半径）、`circle`（中心・半径）の順に並べます。区間の組ごとに返し、つながる区間をつなぎません。重なりの端点と同じ格子点は `points` に含めません。

経路の区間数は計測と同じ上限で、全組の数を作業量へ先に数えます。交点の判定と丸め、格子への移動、並べ替えも作業量へ、作った点を `segments` へ、配列を確保量へ数えます。未対応の形・範囲外の座標・ない ID は `drawing.element-intersection.failed` に理由と元の要素を残し、部分結果を返しません。区間の組の計算で失敗した場合は `first` を指します。予算停止後も文書を再利用できます。期待値と環境間の応答の一致は[交わりの適合テスト](../bindings/conformance/README.md#交わり)で確かめます。

## モデル空間の閉領域

スキーマ 1.91 から、`regions` で同じ実寸の空間の要素から閉領域を求められます。`operation: "detect"` は `subject` の要素の線が囲むすべての有限の面を返し、穴の内側の面も別の領域にします。`union`・`intersection`・`difference`・`xor` は、閉じた要素の `subject` と `clip` の和・積・差（`subject` から `clip` を除く）・排他的論理和です。`clip` を書かなければ空とし、`fill` は内部を決める規則で、既定は `even_odd` です。要素は `measure` と同じ形で公開 ID を指し、同じ一覧で同じ ID を繰り返しません。文書・要素・ID・ハッシュは変わりません。

```json
{"v":1,"op":"regions","doc":"plan.dxf","from":"space/0","operation":"difference","subject":[{"kind":"element","id":"space/0/h20"}],"clip":[{"kind":"element","id":"space/0/h21"}]}
```

要素は計測と同じ経路にし、すべてを折れ線にします。円・円弧・膨らみを持つ辺は弦と円弧の距離が許容差の半分以下になるよう分け、楕円・スプライン・クロソイドは計測と同じく近似します。曲線を分けた要素は `approximate: true` と `drawing.element-region.approximated` を返します。`tolerance` と[整数格子](../docs/geometry2d.md)は `intersect` と同じで、格子の原点は全要素の最初の点のうち X、Y の辞書順で最小の点を整数に丸めた点です。集合演算では閉じていない要素を `not-closed` で失敗にします。

`regions` は外周を反時計回り、穴を時計回りにし、各輪郭を辞書順で最小の点から始め、外周、穴の順の辞書順に並べます。`area` は格子点の座標で求めた、外周から穴を除いた面積です。要素の順序や `subject` と `clip` の中の順序を入れ替えても同じ領域を返します。交点を格子点へ丸めて元の線を曲げた点は `rounded` に要素の ID と格子点で返し、元の線からの距離は格子の 1 間隔以内です。点や一直線に縮んだ要素・長さ 0 の線は `discarded` の `degenerate`、閉領域の境界に使わなかった線の部分（橋や開いた枝）は `open` と始点・終点で返します。

分割後の辺は合わせて 4096 本までで、超えると `input-limit` で失敗します。経路と弦の点を `segments` へ、分割・走査・抽出の二乗の上限を作業量へ、配列を確保量へ先に数えます。未対応の形・範囲外の座標・ない ID・丸めが収束しない入力（`precision`）は `drawing.element-region.failed` に理由と元の要素を残し、部分結果を返しません。要素の集合の計算で失敗した場合は `subject` の最初の要素を指します。予算停止後も文書を再利用できます。期待値と環境間の応答の一致は[閉領域の適合テスト](../bindings/conformance/README.md#閉領域)で確かめます。

## モデル空間の作図

スキーマ 1.92 から、`construct` で同じ実寸の空間の要素からオフセット・トリム・延長・面取り・フィレットの形の値を求められます。文書・要素・ID・ハッシュは変わりません。返した値を `apply` の `replace` と `add` に渡すと、図面に反映できます。`replace` の `geometries` が空なら `remove`、2 つなら 1 つ目で置き換えて 2 つ目を `add` にします。`replace` は形の種類を変えないので、円をトリムした円弧のように種類が変わる形は `remove` と `add` にします。

```json
{"v":1,"op":"construct","doc":"plan.dxf","from":"space/0","operation":"trim","target":{"kind":"element","id":"space/0/h10"},"boundaries":[{"kind":"element","id":"space/0/h11"}],"pick":{"x":12.5,"y":3}}
```

`operation` ごとに使うフィールドが決まり、それ以外のフィールドは書けません。

- `offset`: `target` を `distance` だけ離した形を `add` に返します。線分は進む向きの左、円と円弧は外側を正とします。半径が 0 以下になる値は `no-solution` で失敗します
- `trim`: `target` を `boundaries` との交点で切り、`pick` の点を含む部分を除いた残りを `replace` に返します。円は切ると円弧になります。`pick` が要素の外なら `pick-outside`、交点の上なら `ambiguous-pick`、交点がなければ `no-intersection` で失敗します
- `extend`: 線分か円弧の `end`（`start` か `end`）を、延ばした先で最初に当たる `boundaries` まで延ばします。円は延ばせず `unsupported-shape` になります
- `chamfer`: 端点を共有する 2 本の線分 `target` と `second` の角を、角から `distances` の 2 つの距離で結ぶ線分を `add` に、残りを `replace` に返します
- `fillet`: 同じ角を半径 `radius` の円弧で丸めます。端点を共有しない組は `no-corner` で失敗します

距離と半径は正の有限値で、`offset` の `distance` だけは 0 でない負の値も書けます。`boundaries` は 1 本以上、`target` や `second` と同じ ID や重複を含めません。`tolerance` と[整数格子](../docs/geometry2d.md)は `intersect` と同じです。作った点・交点・切断点は格子で求めた値、変えない端点・中心・半径・角度は元の値を返し、`replace` の形は元の要素の向きを保ちます。時計回りの円弧は反時計回りの値にします。`cuts` は切断点ごとに境界の ID と点と、交点を格子点へ丸めたか（`rounded`）、端の判定で点を寄せたか（`adjusted`）を返します。境界に楕円・スプライン・クロソイドを使うと `approximate: true` と `drawing.element-construction.approximated` を返します。

経路・交点・作図の計算を作業量・`segments`・確保量へ数えます。未対応の形・範囲外の座標・ない ID・解がない入力は `drawing.element-construction.failed` に理由と元の要素を残し、部分結果を返しません。計算での失敗は `target` を指します。予算停止後も文書を再利用できます。期待値と環境間の応答の一致は[作図の適合テスト](../bindings/conformance/README.md#作図)で確かめます。

## 3D のシーンの契約

建物のシーンは `zumen-scene3d` と共通 API の `scene3d` で作ります（メッセージのスキーマ 1.82 から）。地物も同じ列と op を使います（1.86 から）。[scene3d.toml](scene3d.toml) から各言語の定数と型を生成します。以下の生成条件は建物を対象とし、地物の座標と選択は[地物の図面とシーン](#地物の図面とシーン)、点群は[点群の 3D のシーン](#点群の-3d-のシーン)に従います（1.88 から）。

- ヘッダーは `ZMS3`、メジャー・マイナーバージョン（各 u16）、塊の数・セクションの数（各 u32）。セクション表は開始位置と長さ（各 u32）を持つ。リトルエンディアンで、セクションは 8 バイト境界に置く。未知のセクションは読み飛ばす。開始位置の列と「なし」（u32 の最大値）の扱いは [2D の配置](scene.toml) と同じ。
- メッシュの頂点は局所座標 f32、三角形と稜線は頂点番号 u32。法線は面から求め、稜線には三角形の分け目を入れない。配置はメッシュ・要素・色の番号と、塊の原点からの変換（f32 の 3 行 4 列）を持つ。写像では同じメッシュを使い回す。
- 要素は ID・クラス・名前を UTF-8 の文字列の開始位置と長さで参照し、階を要素番号で持つ。色は f32 の RGBA と未解決のフラグ。各塊は f64 の原点、f32 の相対座標の範囲、インスタンスの開始位置を持つ。同じ要素を複数の塊に分けない。[公開 IFC 12 件での測定](../crates/zumen-scene3d/README.md#公開-ifc-での計測)から、4096 インスタンスを目安に採用した。配置の f32 化の誤差が許容差の 1/4 を超える場合は、より早く塊の原点を区切る。
- `scene3d` は文書に対して `storeys`・`classes`・`ids` のすべてに合う要素を選ぶ。断面の `box` は重なりで絞り、切り抜きは読み手が行う。座標はプロジェクト空間の文書単位。許容差の既定は対象範囲の対角線の 1/50000 とし、使った許容差は応答と `approximated` の診断に残す。応答には文書の単位と地図への変換、指定された断面の箱、範囲、メッシュ・インスタンス・要素の数、blob の番号を記録する。作った点は `segments`、評価した要素は `work` で数える。blob は `blobs` の `scene3d` で返し、`zm_take` で受け取る。
- シーンごとに細かさを決め、粗いシーンは許容差を変えて作る。評価できない要素も ID と診断を残す。建物から切り出した 2D の図面とは同じ建物要素の ID で照合する。許容差 1・4・16 倍を試した公開サンプルでは、三角形とバイト数の削減が小さかったため、固定の LOD の段と自動切り替えは設けない。既定の 1 倍と、利用側の明示した許容差を使う。

実装では次の条件も検査します。

- blob は 512 MiB 以内です。点のないシーンは ZMS3 1.0 の 20 セクション、点を持つシーンは 1.1 の 26 セクションを持ち、その間の数を断ります。セクション表の後に列を順に置き、重複・逆順・範囲外・行の途中で終わる列を断ります。変換の 3 行 4 列は行優先です。メッシュの頂点番号は各メッシュの中の番号で、開始位置の列の末尾は参照先の行数です。
- ID は建物モデルの値をそのまま使い、選択された要素が参照する所属階も要素表に含めます。階の選択は主の親をたどります。各条件の中は OR、条件どうしは AND、空の配列は何も選びません。クラス名の大文字と小文字を区別します。
- 箱の重なりは要素全体で判定します。一部だけが重なった要素の全配置を残します。形を持たない要素は位置を判定できないため ID を残します。開口の切削形は表示せず、開口自身の ID は表に残します。開口と分解の参照を保つため形の評価は建物全体に行います。
- 軸は Z が上のプロジェクト空間です。地図への変換は元値として応答に添え、頂点へ適用しません。長さの単位を特定できなければ失敗します。色は建物の style 成分の RGB と透過性を使い、なければ未解決フラグを付けて診断します。未解決 RGB は 0、代替色は読み手が選びます。
- 許容差の省略時は実寸 1 mm で予備評価し、選択対象の範囲の対角線から求めます。空か点だけなら 1 mm にします。予備評価と本評価は同じ予算を使います。f32 化の変位は要素の場所と値を診断し、表せない形を落とすときも ID と診断を残します。
- IFC の通常の open は属性だけを取得します。scene3d は同じ L1 から形を含む建物を、その呼び出しの予算で取得します。形のキャッシュをセッションへ残さず、同じ要求の予算停止位置を保ちます。要素表は elements、頂点は segments、確保・走査・参照は decoded_bytes・work・depth で制限します。

Rust の read と JavaScript の readScene3D は、全列の有限値・参照・ID の重複まで検査します。JavaScript の検査用確保量は既定 256 MiB、作業量は 100,000,000 で、引数で下げられます。ほかの言語の読み手はヘッダーと列の範囲・幅を先に確認し、要素 ID とインスタンスの参照は取得時に確認します。列を借用する読み手の利用中は元の blob を変更しません。

### 地物の図面とシーン

`zumen-geo` の任意の feature `drawing`・`scene3d` が領域モデルから派生物を作ります。モデルの属性・形・ID は書き換えません。経緯度は JGD2011、平面座標は JGD2011 の平面直角座標を受け付け、X を東、Y を北、単位をメートルにそろえます。測地系が不明、WGS 84、日本測地系、JGD2000 の入力には、測地系の変換を推定しません。高さは元の数値と `height_crs` を保ち、楕円体高と標高を相互に読み替えません。

投影先は `zone`（1〜19）で指定します。省略時は元の平面座標の系を使います。経緯度では、有効な形の範囲の中心を各系へ投影し、原点からの距離が最小の系を計算用に仮定して `geo.zone.assumed` を返します。同距離なら番号の小さい系を選びます。これは行政界による適用地域の判定ではありません。明示した系へ合わせるときも、線・面は元の頂点を投影して直線で結び、辺を細分しないことを `geo.projection.approximated` で知らせます。許容差は投影後の辺全体の誤差を保証しません。

Rust の `drawing::build` は点を点、線を折れ線、面の外周と各穴を閉じた折れ線にします。単位が m、軸が東・北のモデル空間を 1 つ作り、用紙や縮尺は補いません。利用側のプロファイルが定めた型・分類コードとレイヤの対応を `LayerRule` で受け取り、コードの指定を型だけの規則より優先します。未登録の型は明示した代替レイヤに置くか、診断して除きます。立体は平面図へ投影しません。壊れた穴を持つ面は全体を除き、穴だけを省きません。図面 ID は既存の命名規則を使い、`sources` と要素の出所から元の地物 ID・形・輪・入力位置へ戻れます。

共通 API の `scene3d` は土木・地理のモジュールでも使えます。`ids` は元の地物 ID、`classes` は型を選び、条件の積と元の順を保ちます。`storeys` は受け付けません。`lod` は 0〜4 の 1 段を選び、省略時は選択した地物全体の最大の LOD を使います。別の段への代替はせず、LOD のない形は含めます。`box` は投影先の東・北・高さのメートルで地物全体を選び、切り抜きません。形を出せない地物も ID・型・名前の行を保ち、階は持ちません。

高さのある線と面、面集合・三角形・その組と写像を扱います。写像を元の座標で適用した後に投影し、面は既存の幾何カーネルで三角形に分けます。高さのない線・面、点の表示、曲面などの未対応の形は `geo.geometry.unsupported` に種類・理由・件数・地物の出所を残します。色は未解決として診断し、表示側が代替色を選びます。

同じ地物のすべてのメッシュを 1 つの塊へ置き、f64 の原点と f32 の局所座標に分けます。丸めのずれが `tolerance / 4` を超える地物はメッシュを返さず、行と診断を保ちます。許容差の既定は選択した範囲の対角線の 1/50000、空か点だけなら 1 mm です。応答の `unit` は m、`map` は投影先の EPSG 名と恒等変換です。座標は投影済みなので、表示側が再び投影しません。`height_crs` は元にあるときだけ返します。

要素・点・走査・確保・再帰は共有の予算と中断で制限し、停止時は派生物も blob も返しません。合成の同じ地物で図面とシーンの頂点・軸・単位・ID を照合し、10 億 m の原点、穴の面積 84 m²、19 系の投影原点、複数の形を持つ地物と停止の境界を確かめます。図面・ZMS3・診断・予算の記録は `crates/zumen-geo/tests/check_visual.py` でネイティブ各環境と wasm のハッシュを比べます。外部実装との照合を示すものではありません。

### 点群の 3D のシーン

点群の文書にも共通 API の `scene3d` を使います（スキーマ 1.88 から）。点群のモジュールと、すべてを入れた組み立てで使えます。メッシュの列は空のまま、ZMS3 1.1 で足した 6 列に点を入れます。メッシュだけのシーンは従来どおり 1.0 の 20 列で書き、既存の blob のバイト列を変えません。

- 塊は元の八分木の節ごとに 1 つです。`chunk_points` は点の開始行、`chunk_nodes` は段・北の位置・東の位置・高さの位置の 4 値で、元の `Key` を写します。節は元のキーの順に並べ、同じ節を 2 回置きません。点を持たない塊の 4 値は「なし」です。
- 点は `point_xyz` に、塊の原点（選んだ点の範囲の中心、f64）からの東・北・高さを f32 で持ちます。f32 に丸めたずれは `scene3d.coordinate.approximated` で最大値を知らせます。色は元の 16 ビットの赤・緑・青と不透明度 65535 の `point_rgba`（u16 × 4）、強度は `point_intensity`（u16）、分類は `point_classification`（u8）で、元が持たない属性は空の列にします。色がなければ読み手が強度か分類から選びます。点ごとの永続 ID は持たず、選べる単位は節のキーと区画の中の行です。
- 点は `pointcloud` の op と同じ規則で選びます。`box` は東・北・高さのメートル、`tolerance` は点の間隔で、これより細かい段の節を読みません。`limit` は点の数の上限で、省略時は選んだすべての点です。上限で返さなかった点があれば応答の `truncated` を true にします。`storeys`・`classes`・`ids`・`zone`・`lod` は受け付けません。座標系と高さ基準を変換せず、応答の `map` は元の水平座標系の EPSG 名と恒等変換、`height_crs` は元の高さの基準です。`tolerance` を省くと、返したもっとも深い段の点の間隔を応答に記録します。
- 走査は `work`、返す点は `elements`、確保は `decoded_bytes` で数えます。停止と失敗では blob を返しません。八分木の節が同じ点を 2 回指す、指さない点がある、属性の列の長さが点の数と違う入力を断ります。
- 読み手は、点の開始行の単調性と範囲、節の段（0〜20）と位置、節の重複、属性の列の行数、点が塊の範囲に入ることを検査します。Rust の `Reader::points` と JavaScript の `Scene3D.points` は塊の点を元の blob から借用して返します。ほかの言語は列を名前で取り出し、u16 の列を読む関数を持ちます。

合成の LAS（色・強度・分類を持つ 12 点、同じ位置を重ねた 3 段の節）を `scene3d_pointcloud.json` でネイティブと wasm に流し、全バイトのハッシュを比べます。`zumen-pointcloud` の試験は、同じ `Query` の `select` と点の順・数・`truncated`・段を比べ、座標・色・強度・分類を元の列へ戻して照らし、全予算の境界で途中の結果を返さないことを確かめます。外部実装との照合は含みません。

### 出来形の差の色分け

`deviation` は、J-LandXML の設計面に指定した `differTP` を設計高に足して、点群の標高と比べます。差は「点の高さ − 換算した設計高」（メートル）です。基準名があるのに T.P. へ換算できない場合や、点群の鉛直 EPSG コードを扱えない場合は `crs.height-datum.unsupported` で止めます。基準を省いた点群は元の設計高と同じ現場基準、基準を省いた設計面は点群と同じ現場基準と仮定し、`deviation.height-datum.assumed` を返します。標高の成果が片側だけ不明なら相手側の成果を仮定して `crs.height-realization.assumed` を返します。両方の成果が分かって異なる場合は `crs.height-realization.mixed` とともに差を返します。成果間の補正は行いません。規格値との比較と色分けも同じ差を使います。離島独自の平均海面への換算は、点の位置から推定しません。[国土地理院の離島の高さ](https://www.gsi.go.jp/sokuchikijun/ritohyokogenten.html)

`deviation` の要求に `scene3d`（`box`・`tolerance`・`limit`）を書くと、点群の `scene3d` と同じ点の区画のシーンと、色の段の表 `bands` を返します（スキーマ 1.89 から）。点の位置・強度・分類と点の選び方は点群のシーンと同じで、`point_rgba` だけを差の段の色に替えます。

- 段は規則の `each`（個々の計測値の規格値、mm）から決めます。差は規格値の判定と同じく mm にして比べ、下限より小さければ `below`、上限より大きければ `above` です。規格値ちょうどは内側に入れ、指摘（`profile.surface-elevation.invalid`）の最小・最大と同じ比べ方になります。
- 内側は 0 から規格値の半分まで（`low_inner`・`high_inner`）と、半分から規格値まで（`low_outer`・`high_outer`）に分けます。境の値は 0 に近い段に入れ、0 は `high_inner` です。規格値のない側は内側の 1 段だけにします。
- TIN の外・どの規則の勾配にも入らない三角形の上・区分の境の近くで除いた点は `not_evaluated` の灰色です。
- `bands` は規則の順に、その規則で起こりうる段を差の小さい順に並べ、最後に規則を持たない `not_evaluated` を置きます。各段は規格値から求めた端（mm）と 16 ビットの色を持ち、応答の `chain` が規格値のプロファイルの id と版を示します。色は表示のための既定で、規格値や判定を表しません。

`deviation_scene3d.json` は標高 0 の計画面に、道路掘削の平場の規格値 ±150 mm に対する 0・半分・ちょうど・外の差の 9 点と TIN の外の 1 点を置き、ネイティブと wasm で全バイトのハッシュを比べます。ABI の試験は、応答の差と段の表から文書の端の扱いで段を引き、シーンの点の色を座標で元の点に戻して比べます。外部実装との照合は含みません。

## op を足す

JSON のフィールド名はそのまま各言語へ渡します。Rust の予約語と重なる `box` だけは `r#box` に生成し、読み書きする JSON の名前は `box` に保ちます。

1. `messages.json` に、`<op>_request` と `<op>_result` を足します。
   - `<op>_request` は `allOf` で `request_common` を取り込み、`op` のフィールドを `const` にします。
   - `request` の `oneOf` に、`<op>_request` を足します。
2. `boundary.toml` の `schema-minor` を上げます。
3. `cargo xtask codegen` を実行し、`crates/zumen-abi` に op の処理を書きます。
4. `bindings/conformance/cases/` にテストの組を足し、ハッシュの一覧を作り直します（[bindings/conformance/README.md](../bindings/conformance/README.md)）。
5. 新しい診断の code を使うなら、`catalog/` も直します（[catalog/README.md](../catalog/README.md)）。

op とフィールドの説明（`description`）は日本語で書きます。この説明が、生成した型のコメントと、AI 向けのツールの説明になります。説明のない定義とフィールドは、生成器が受け付けません。

## 使える書き方

JSON Schema のうち、どの言語の型にも素直に写せる部分だけを使います。生成器は、これ以外の書き方と、知らないキーワードを受け付けません。

| 書き方 | 使う所 | Rust の型 |
| --- | --- | --- |
| `type: object`、`properties`、`required`、`additionalProperties: false` | `$defs` の定義 | 構造体。書かなくてよいフィールドは `Option` |
| 上と同じで `additionalProperties` を書かないもの | `allOf` で取り込まれるだけの定義（`request_common`） | 構造体。取り込む側のフィールドになる |
| `allOf: [{"$ref": …}]` と `unevaluatedProperties: false` | 共通のフィールドを取り込む定義（`<op>_request`） | 取り込んだ定義を、同じ名前のフィールドに持つ構造体 |
| `type: string` と `enum` | `$defs` の定義 | 列挙 |
| `oneOf` の中がすべて `{"$ref": …}` で、どれも同じ名前の `const` のフィールドを持つオブジェクト | タグつきの共用体（`request`） | 列挙。形ごとに 1 つ |
| `oneOf` の中が `integer`・`number`・`string`・文字列の `const` で、JSON の値から 1 つに決まるもの | スカラーの共用体（`limit`・`param_value`） | 列挙 |
| `type: string`・`boolean`・`number` | フィールド | `String`・`bool`・`f64` |
| `type: integer`、`minimum`・`maximum` | フィールド | 下限が 0 以上なら `u64`、そうでなければ `i64` |
| `type: array` と `items` | フィールド | `Vec` |
| `type: object` と、値の型を書いた `additionalProperties` | フィールド（名前から値への表） | `BTreeMap<String, …>` |
| `$ref: "#/$defs/<名前>"` | フィールド | 指した定義の型 |
| `const`（文字列） | 共用体の形のタグのフィールド | フィールドにはしない |

- 定義・フィールド・列挙の値の名前は、英小文字・数字・`_` にします。
- オブジェクト・列挙・共用体は、フィールドの中に直接書かず、`$defs` に名前をつけて `$ref` で指します。
- 整数は ±(2^53 − 1) の中に限ります。`maximum` を書かなければ、2^53 − 1 が上限になります。
- `response` は、コアが手で書きます（`result` の形が op ごとに違うため）。スキーマには、文書として書きます。

## メッセージの JSON

要求と応答の JSON は次の規則で読み書きします。

- **読む。** UTF-8 の JSON（RFC 8259）だけを読みます。先頭の BOM は読み飛ばします。キーが重なるもの、入れ子が 64 より深いもの、値のあとに空白以外が続くものは、`call.json.invalid` にします。
- **整数。** `1.0` のように小数部が 0 だけの表記も、整数として読みます。指数のある表記は、整数として読みません。
- **知らないフィールド。** 要求に知らないフィールドがあれば `call.field.unsupported`、必要なフィールドがなければ `call.field.missing`、型か範囲が合わなければ `call.value.invalid` にします。場所は JSON Pointer で返します。
- **書く。** キーはスキーマの順に並べ、空白を入れません。浮動小数は、ECMAScript の `Number::toString` と同じ表記で書きます。どの環境でも、同じバイト列になります。
